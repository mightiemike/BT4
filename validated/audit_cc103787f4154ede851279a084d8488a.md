### Title
Permanent loss of excess outbound gas fee when `applyGasRefund`'s on-chain refund call fails - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
`applyGasRefund` in `x/uexecutor/keeper/outbound.go` computes the excess gas fee (`gasFee - gasFeeUsed`) owed back to the user after every outbound (success or failure) and attempts to return it via `CallUniversalCoreRefundUnusedGas`. If both the swap-refund and no-swap fallback EVM calls fail, the code simply records `refundPcTx.Status = "FAILED"` on the outbound and returns — there is no retry path, no admin sweep/reclaim message, and no alternate ledger entry that preserves the user's claim to that value.

### Finding Description
`applyGasRefund` ( [1](#0-0) ) is invoked from both `handleFailedOutbound` and `handleSuccessfulOutbound` for every observed outbound once UVs vote in `gas_fee_used` via `MsgVoteOutbound`. When `gasFee > gasFeeUsed`, it computes `refundAmount` and tries two on-chain paths in order:

1. Swap-refund: `CallUniversalCoreRefundUnusedGas(..., withSwap=true, ...)`
2. No-swap fallback: `CallUniversalCoreRefundUnusedGas(..., withSwap=false, ...)`

If the fallback call also errors, the only effect is:
```go
if err != nil {
    refundPcTx.Status = "FAILED"
    refundPcTx.ErrorMsg = err.Error()
}
...
outbound.PcRefundExecution = refundPcTx
outbound.RefundSwapError = swapFallbackReason
``` [2](#0-1) 

This is persisted via `k.UpdateOutbound(ctx, utxId, outbound)` and the function returns `nil` — the outbound's terminal status (`OBSERVED` or `REVERTED`) is unaffected by refund failure, and `MsgVoteOutbound` finalization succeeds regardless. Once the outbound reaches its terminal state and is removed from `PendingOutbounds`, `applyGasRefund` is never invoked again for that outbound: the UTX/OutboundTx state model documented in `x/uexecutor/README.md` is strictly append-only per-outbound and has no "retry refund" trigger, and there is no message/keeper function anywhere in the codebase to re-attempt or manually reclaim a `FAILED` `PcRefundExecution` (grep for `RetryRefund`/`Sweep`/`retry` finds nothing in `x/uexecutor`). The excess gas amount that should have been returned to the user is thus permanently unaccounted for, mirroring the external bug class where an unprivileged user's entitled value is forfeited on an exceptional/failure path with no redistribution or reclaim mechanism.

This is directly analogous to the `MasterChef`/`MlumStaking` bug: a computed, owed value (there: forfeited staking rewards; here: forfeited excess gas fee) is dropped on a failure/edge path with no code path to redistribute or reclaim it, and the only observable artifact is a status string with no corrective action.

### Impact Explanation
Any external, unprivileged relayer/attacker who can cause the underlying `refundUnusedGas` EVM call to revert on both the swap and no-swap paths (e.g., by triggering conditions such as depleted PRC20 balance in `UniversalCore` for that gas token, quoter/slippage failure combined with a `UniversalCore`-side check that also fails the no-swap deposit path, or a malicious/blacklisted-recipient PRC20 that reverts transfers) can cause legitimate users' excess gas refunds to be permanently and silently lost. Because this triggers on the normal `MsgVoteOutbound` finalization path with honest validators reporting a real `gas_fee_used`, no privileged actor is required — a user (or an attacker crafting a payload with a token/recipient combination that reliably fails the refund transfer) can cause the loss. This falls in scope as "permanent loss ... of user or protocol-controlled funds" reachable via "ordinary user deposits, payloads, contracts, or default transaction submission paths alone."

### Likelihood Explanation
The refund failure path requires only that the on-chain `refundUnusedGas` call fails twice in a row on the destination `UniversalCore` contract — a condition plausibly triggerable via token behavior (fee-on-transfer/blacklist/paused tokens as `gasToken`), insufficient escrowed balance in `UniversalCore`, or transient issues that recur deterministically for a given gas token/recipient pair. Given every outbound (success or revert) calls `applyGasRefund` whenever there's excess gas, and there is no compensating retry/sweep, the likelihood of encountering and exploiting this is moderate-to-high for any token whose transfer/swap semantics can be made to revert reliably.

### Recommendation
When both refund attempts fail, do not just record a `FAILED` status and drop it:
- Persist the pending refund amount/recipient/gas token as first-class on-chain state (e.g., a `PendingGasRefunds` collection) so it can be retried in a later block or claimed via an explicit `MsgClaimGasRefund`/admin sweep message.
- Alternatively, expose an idempotent retry keeper method (analogous to `RevertStuckInbound`) that admin or automated jobs can invoke against `OutboundTx` entries whose `PcRefundExecution.Status == "FAILED"`, re-attempting `CallUniversalCoreRefundUnusedGas` until it succeeds or is explicitly written off with proper accounting (e.g., routed to a treasury/community pool rather than silently vanishing).

### Proof of Concept
1. Configure (or have UVs observe) an outbound whose `gas_fee` significantly exceeds the eventual `gas_fee_used` reported via `MsgVoteOutbound`, using a `gas_token` PRC20 that is deliberately made to revert on both the auto-swap deposit path and the plain deposit path in `UniversalCore` (e.g., a token contract that reverts `transfer`/`transferFrom` to specific addresses, or one for which the pool has zero liquidity so the swap quote/execution reverts and the no-swap `depositPRC20`-style call also reverts due to a paused/blacklisted state).
2. Drive the outbound to quorum via `MsgVoteOutbound` with `gas_fee_used` set low enough to produce a large `refundAmount`, as in `test/integration/uexecutor/gas_fee_refund_test.go`'s `"swap fallback reason stored when swap refund fails"` case [3](#0-2) , but arrange for the no-swap fallback to also fail.
3. Observe: `OutboundTx.PcRefundExecution.Status == "FAILED"`, `OutboundStatus` reaches its terminal state (`OBSERVED`/`REVERTED`) as normal, and the outbound is removed from `PendingOutbounds` — no further code path in the repository ever re-attempts or reclaims `refundAmount`, and no query/message exists to recover it, resulting in permanent loss of the user's excess gas fee.

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
