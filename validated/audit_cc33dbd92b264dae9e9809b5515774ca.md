**Analysis:**

The premise of the question already answers itself: `verify_events_against_root_hash` in `types/src/transaction/mod.rs` recomputes the event root hash from the events slice actually passed in and compares it against `transaction_info.event_root_hash()`. [1](#0-0) 

If an events vector is missing a `TransferEvent` that was included when the "true" `event_root_hash` was computed, the recomputed `InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash()` over the truncated set will differ from that true root hash (this relies on the accumulator hash being collision-resistant/second-preimage-resistant, which is the standard cryptographic assumption for Merkle/accumulator hashing used throughout Aptos). The `ensure!` check will therefore fail and return an `Err`, exactly as the question's own "proof idea" describes as the expected regression-test outcome.

This same check is applied consistently in the two callers that matter here:
- `TransactionOutputListWithProof::verify` invokes it per transaction output before accepting the list. [2](#0-1) 
- `TransactionListWithProof::verify` invokes it per event list when events are present. [3](#0-2) 

There is no code path shown (or found) where a "filtering bug upstream" could drop an event from the slice passed into `verify_events_against_root_hash` while somehow still supplying the *original* (non-recomputed) `event_root_hash` in a way that would bypass this check — the check unconditionally recomputes the root hash from whatever events slice it is given and compares against the `TransactionInfo`'s committed value, which itself is bound to the ledger via the transaction/accumulator proof (`self.proof.verify(ledger_info, ...)`). Any hypothetical "filtering bug" that drops an event before this function is called would be caught here, not bypass it — that's the entire purpose of this function. The scenario described is not an exploit; it is exactly the mechanism that prevents the described attack, and no code defect was found that would allow the mismatch to go undetected.

fn verify_events_against_root_hash(
    events: &[ContractEvent],
    transaction_info: &TransactionInfo,
) -> Result<()> {
    let event_hashes: Vec<_> = events.iter().map(CryptoHash::hash).collect();
    let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash();
    ensure!(
        event_root_hash == transaction_info.event_root_hash(),
        "The event root hash calculated doesn't match that carried on the \
                         transaction info! Calculated hash {:?}, transaction info hash {:?}",
        event_root_hash,
        transaction_info.event_root_hash()
    );
    Ok(())
}
