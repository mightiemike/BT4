### Title
App Proxy HMAC canonicalization uses undelimited/unescaped key-value concatenation, allowing parameter-boundary forgery of a Shopify-signed signature - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
`validateHmac()` in `hmac-validator.ts` builds two structurally different canonical strings depending on the `signator` — an "admin" path and an "appProxy" path — much like the referenced report's `increaseLock()`/`extendLock()` pair that computed logically equivalent state with two inconsistent formulas. The admin path (`stringifyQueryForAdmin`) canonicalizes safely through `ProcessedQuery`, which uses `URLSearchParams` and therefore delimits/encodes every key and value. The app-proxy path (`stringifyQueryForAppProxy`) instead concatenates raw, un-escaped `key=value` fragments with **no delimiter at all** between successive pairs. [1](#0-0) 

### Finding Description
`generateLocalHmac()` picks the canonicalizer based on `signator`: [2](#0-1) 

For `signator === 'admin'`, `stringifyQueryForAdmin` sorts keys and hands them to `ProcessedQuery`, which appends each pair to a `URLSearchParams` object (percent-encoding `=`, `&`, and other reserved characters), guaranteeing that the mapping from `{key: value}` pairs to canonical string is unambiguous. [3](#0-2) 

For `signator === 'appProxy'`, `stringifyQueryForAppProxy` instead does a raw `reduce` that emits `${key}=${value}` fragments back-to-back with **no separator character between pairs**: [4](#0-3) 

Because there is no delimiter (and no escaping of `=` inside values), the mapping from a set of `{key: value}` pairs to the canonical string is **not injective**: two structurally different query-parameter sets can serialize to the exact same byte string, and therefore produce the exact same valid HMAC once signed with the real secret. Concretely, a trailing `key=value` fragment can be "absorbed" into the value of an earlier (alphabetically-preceding) parameter without changing the canonical string at all, e.g.:
- Real Shopify-signed request: `{logged_in_customer_id: '111', path_prefix: '/apps/my_app', shop: 's.myshopify.com', timestamp: 'T'}` → canonical `"logged_in_customer_id=111path_prefix=/apps/my_appshop=s.myshopify.comtimestamp=T"`.
- A forged request with only `{logged_in_customer_id: '111path_prefix=/apps/my_app', shop: 's.myshopify.com', timestamp: 'T'}` (i.e. `path_prefix` is not a separate key any more but is spliced into the value of `logged_in_customer_id`) produces **the identical canonical string**, and hence passes `safeCompare(hmac, localHmac)` with the same signature. [5](#0-4) 

This is directly reachable by an anonymous app-proxy caller: `validateHmac` is exported on `shopify.utils` and is the mechanism apps are told to use to authenticate inbound App Proxy requests (`signator: 'appProxy'`) — a request path driven entirely by unauthenticated storefront traffic.

Note: `normalizeQuery`'s duplicate-key guard only rejects duplicates of `hmac`/`shop`/`signature`/`timestamp`, and does nothing to prevent the boundary-shifting collision above, since it operates on already-parsed key/value pairs, not on the ambiguous serialization step. [6](#0-5) 

### Impact Explanation
An app that trusts fields such as `logged_in_customer_id` or `path_prefix` from an app-proxy request validated by `shopify.utils.validateHmac(..., {signator: 'appProxy'})` can have those fields silently disappear or be merged into a sibling field's value while the signature still validates, because the underlying canonical-string construction is ambiguous. Any app logic that branches on the *presence* of a security-relevant parameter (e.g. treating "no `logged_in_customer_id` key" as anonymous vs. authenticated) is exposed to this ambiguity, letting an attacker craft a request whose true parameter set differs from what Shopify actually signed while still bearing a byte-identical, and therefore valid, signature.

### Likelihood Explanation
Reaching this code path requires no privileges: the App Proxy signature scheme is specifically designed for anonymous storefront/customer HTTP requests that Shopify forwards to the app, and `validateHmac` with `signator: 'appProxy'` is the documented entry point apps are meant to call on every inbound proxied request.

### Recommendation
Fix `stringifyQueryForAppProxy` so that it produces an injective encoding of the query, consistent with the admin path: percent-encode keys/values and insert an unambiguous delimiter (e.g. `&`) between pairs, or otherwise ensure the mapping from parsed query object to canonical string cannot collide for two different parameter sets.

### Proof of Concept
1. Compute `S = HMAC-SHA256(secret, "logged_in_customer_id=111path_prefix=/apps/my_appshop=s.myshopify.comtimestamp=T")` — this is exactly what Shopify itself would sign for a genuine app-proxy request with those four params (per `stringifyQueryForAppProxy`, `packages/apps/shopify-api/lib/utils/hmac-validator.ts:60-66`).
2. Send a request to the app with query `{logged_in_customer_id: '111path_prefix=/apps/my_app', shop: 's.myshopify.com', timestamp: 'T', signature: S}` (only 3 real keys instead of 4).
3. `stringifyQueryForAppProxy` on this parsed object emits the identical string `"logged_in_customer_id=111path_prefix=/apps/my_appshop=s.myshopify.comtimestamp=T"`, so `generateLocalHmac` returns `S`, and `safeCompare(S, S)` passes in `validateHmac` (`hmac-validator.ts:105-115`), even though the app never receives a `path_prefix` key at all.

function stringifyQueryForAdmin(query: AuthQuery): string {
  const processedQuery = new ProcessedQuery();
  Object.keys(query)
    .sort((val1, val2) => val1.localeCompare(val2))
    .forEach((key: string) => processedQuery.put(key, query[key]));

  return processedQuery.stringify(true);
}

function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

export function generateLocalHmac(config: ConfigInterface) {
  return async (
    params: AuthQuery,
    signator: HMACSignator = 'admin',
  ): Promise<string> => {
    const {hmac: _hmac, signature: _signature, ...query} = params;

    const queryString =
      signator === 'admin'
        ? stringifyQueryForAdmin(query)
        : stringifyQueryForAppProxy(query);

    return createSHA256HMAC(config.apiSecretKey, queryString, HashFormat.Hex);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

  put(key: string, value: any): void {
    if (Array.isArray(value)) {
      this.putArray(key, value);
    } else if (value?.constructor === Object) {
      this.putObject(key, value);
    } else {
      this.putSimple(key, value);
    }
  }

  putArray(key: string, value: (string | number)[]): void {
    value.forEach((arrayValue) =>
      this.processedQuery.append(`${key}[]`, `${arrayValue}`),
    );
  }

  putObject(key: string, value: object): void {
    Object.entries(value).forEach(
      ([entry, entryValue]: [string, string | number]) => {
        this.processedQuery.append(`${key}[${entry}]`, `${entryValue}`);
      },
    );
  }

  putSimple(key: string, value: string | number): void {
    this.processedQuery.append(key, `${value}`);
  }

  stringify(omitQuestionMark = false): string {
    const queryString = this.processedQuery.toString().replace(/\+/g, '%20');
    return omitQuestionMark ? queryString : `?${queryString}`;
  }
