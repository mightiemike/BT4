## Title
`ensure_match_transaction_info` skips verifying the state-checkpoint root, letting `replay_verify`/`replay_on_archive` accept a diverged/corrupted ledger state - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticity check used by the archive-replay tooling (`storage/db-tool/src/replay_on_archive.rs`) to confirm that locally re-executed transactions match the transaction infos that are anchored (via the accumulator) to a trusted `LedgerInfo`. The function checks status, gas, write-set hash and event-root hash, but it explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` against the locally recomputed state root. Since these are the only fields in `TransactionInfo` that authenticate the *full* world-state (as opposed to the per-transaction delta), replay-verify can report success even though the archived/replayed full ledger state has diverged from the authenticated one.

### Finding Description
`ensure_match_transaction_info` in [1](#0-0)  compares `status`, `gas_used`, the write-set hash (`state_change_hash`) and the event-root hash against the supplied `TransactionInfo`, then contains this explicit TODO instead of a check:

```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
``` [2](#0-1) 

This function is directly used by `storage/db-tool/src/replay_on_archive.rs::execute_and_verify`, which re-executes archived transactions against state read straight from the archive DB (`self.arc_db.state_view_at_version(...)`) and calls `ensure_match_transaction_info` per transaction as the sole correctness gate: [3](#0-2) 

The per-transaction write-set hash check only authenticates the *delta* a transaction claims to write, not the resulting cumulative state root. `state_checkpoint_hash` (and its hot-state/position-state variants) is the only field in `TransactionInfo` that is supposed to authenticate the full Sparse-Merkle-Tree/JMT state root at checkpoint boundaries — this is exactly the value `DoStateCheckpoint` computes and cross-checks in the normal chunk-executor commit path via `known_state_checkpoints`/`known_hot_state_checkpoints`/`known_position_state_checkpoints` (see `execution/executor/src/chunk_executor/mod.rs::update_ledger`, lines 373-413). Because `replay_on_archive`'s verification path bypasses `DoStateCheckpoint` entirely and instead relies solely on `ensure_match_transaction_info`, the state-root authentication step is silently skipped.

Consequently, if the archived KV state that `state_view_at_version` reads (the pre-state for replay) has been corrupted or has silently diverged from the value that produced the on-chain accumulator/`state_checkpoint_hash`, replay-verify will still report success as long as each individual transaction's write-set delta and events hash correctly against the recorded `TransactionInfo` — the aggregate state root divergence is never independently checked.

### Impact Explanation
Replay-verify (`db-tool replay-on-archive` / `replay-verify`) exists specifically to give a cryptographic guarantee that an archived history of transactions, when replayed, reproduces the exact ledger state that was actually accepted and signed by validators — this is the class of "authenticated ... state proof accepted as valid" and "hard-fork-only divergence during ... replay" impact called out by the state-integrity gate. Because the state-checkpoint root is never validated, a corrupted/tampered archive state (or a latent VM/executor bug that only manifests in the cumulative state root, not in any single write-set delta) is accepted as verified. This defeats the core integrity guarantee replay-verify is meant to provide for mainnet archive data and could mask a hard-fork-class divergence between the "verified" replay and the authentic chain state.

### Likelihood Explanation
No privileged access or malicious peer behavior is required — the gap is in local code executed by anyone running the replay-verify tool against archived data (which may itself be sourced from disk that has bit-rotted, been tampered with, or restored from a subtly buggy backup/restore path). The bug is deterministic and 100% reproducible: any of the three checkpoint hash fields is simply never compared.

### Recommendation
Extend `ensure_match_transaction_info` to independently recompute (or accept as a parameter) the state/hot-state/position-state checkpoint roots at checkpoint boundaries and assert them against `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, and `txn_info.position_state_checkpoint_hash()`, mirroring the checks already performed by `DoStateCheckpoint` in the normal execution path, before this code path is relied upon for any authenticated verification (and before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled, as the TODO itself states).

### Proof of Concept
1. Corrupt or replace a single state value in an archived AptosDB such that no individual transaction's declared write-set changes (and thus no `state_change_hash`) is affected, but the resulting full state root at the next checkpoint boundary differs from the authentic `state_checkpoint_hash` recorded on-chain.
2. Run `storage/db-tool/src/replay_on_archive.rs` (`replay-verify`) over the range containing that checkpoint.
3. Observe that `execute_and_verify` re-executes all transactions and calls `ensure_match_transaction_info`, which only checks status/gas/write-set-hash/event-root-hash — never `state_checkpoint_hash` — so the tool reports success despite the state root divergence.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
