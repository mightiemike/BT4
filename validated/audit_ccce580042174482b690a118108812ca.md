### Title
Starknet OS `execute_replace_class` omits declared-class-hash validation performed by the live Blockifier, enabling state/proof divergence via the `replace_class` syscall - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler in the Blockifier (the component that executes transactions live in the sequencer) enforces that the target `class_hash` corresponds to an actually-declared contract class before allowing a contract to swap its class hash. The corresponding handler inside the Starknet OS Cairo program (`execute_replace_class`), which is used to re-execute the same block for proving/verification, does **not** perform this check — the check is explicitly marked as an outstanding `TODO`. This mirrors the reported bug class: a privileged operation (installing/using an implementation) is performed by casting/trusting an address/hash without validating that it actually conforms to what the rest of the protocol assumes, breaking an invariant enforced elsewhere.

### Finding Description
Blockifier's `replace_class` syscall implementation validates that the class is declared before installing it on the contract's state entry: [1](#0-0) 

and the Cairo1/current syscall path delegates to `base.replace_class(...)`, whose test coverage confirms it rejects undeclared class hashes ("is not declared") and even enforces Cairo0/Cairo1 compatibility rules ("Cannot replace V1 class hash with V0 class hash"): [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of the same syscall (`execute_replace_class`, used both in the current and deprecated OS syscall dispatch paths) directly overwrites the contract's `class_hash` in `contract_state_changes` with **no check** that the hash corresponds to a declared class, and the code contains an explicit acknowledgment of the gap: [4](#0-3) 

The deprecated OS syscall path has the identical unchecked behavior: [5](#0-4) 

Additionally, the Rust-side SNOS syscall executor used for the OS hint processing (`snos_deprecated_syscall_executor.rs`) also implements `replace_class` as a complete no-op that returns success unconditionally, with no declared-class check at all: [6](#0-5) 

The OS is the component whose execution trace is turned into a STARK proof and is expected to be functionally equivalent to the Blockifier's live execution for the same block (OS re-execution is meant to attest that the sequencer computed the correct state transition). Any legitimate difference in accepted/rejected inputs between Blockifier and the OS is a soundness gap: it means the OS could "successfully" prove a state transition for inputs that the live sequencer would have rejected, or that the OS's `contract_class_changes`/state view is inconsistent with what Blockifier enforces, silently accepting an undeclared or type-mismatched (Cairo0 vs Cairo1) class hash into a contract's state entry.

### Impact Explanation
- Breaks the invariant, enforced by the live Blockifier, that any contract's class hash always refers to a declared (and version-compatible) `CompiledClass`. If the OS accepts a `replace_class` with an undeclared/incompatible hash that the Blockifier would have rejected, the OS-computed state root/committed contract state can diverge from the Blockifier-computed one for the same transaction sequence.
- This is a wrong-committed-root / honest-node-divergence class issue: two honest components of the same sequencer stack (Blockifier vs. the Starknet OS re-execution used for proof generation) can disagree on whether a transaction is valid and what state results, undermining the guarantee that the produced proof attests to the same state transition the sequencer actually committed.
- Because contract state (specifically the executable class pointer for an address) is corrupted with a value that the "real" definition of correctness (Blockifier's checks) forbids, a subsequently generated proof could misrepresent a rejected/invalid state change as valid, i.e., a wrong committed state root/block hash relative to what should have been produced.

### Likelihood Explanation
Reachable directly by any account/contract via a completely ordinary transaction: any contract can invoke the `replace_class` syscall with an attacker-chosen `class_hash` (as demonstrated by the Blockifier's own negative test cases using arbitrary/undeclared felt values). No privileged role, staking, or p2p condition is required — it's a single-transaction, single-syscall trigger. The only reason this hasn't caused visible incidents is that in the current pipeline the Blockifier's live execution filters out such transactions before they are included in a block; the risk materializes specifically in any code path that re-executes/validates a block via the OS without first requiring Blockifier-equivalent semantics (e.g., independent re-execution/verification tooling, proof generation for adversarially crafted execution traces, or future divergence introduced by other TODO-marked gaps in the OS).

### Recommendation
Implement the missing declared-class-hash check in the Starknet OS's `execute_replace_class` (and the corresponding deprecated path), mirroring the Blockifier's logic exactly:
1. Look up `class_hash` in the OS's `compiled_class_facts_bundle` / `contract_class_changes` structures and fail (mark as reverted, consistent with how other OS syscalls signal failure) if the class is not present.
2. Enforce the same Cairo0/Cairo1 compatibility rule that Blockifier enforces (reject replacing a Cairo1-class contract with a Cairo0 class hash, or vice versa per current semantics).
3. Remove the `Ok(ReplaceClassResponse {})` no-op stub in `snos_deprecated_syscall_executor.rs` and route it through the same validated logic, or explicitly assert that this path is unreachable/deprecated-only with a corresponding guarantee elsewhere.
4. Add a differential/consistency test that runs the same `replace_class`-invoking transaction through both the Blockifier and the OS re-execution and asserts identical accept/reject behavior and resulting state.

### Proof of Concept
1. Deploy a Cairo1 contract exposing `test_replace_class(class_hash)` that calls `syscalls::replace_class_syscall(class_hash)` (already present as a feature/test contract in the repo, see `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo:514-516`).
2. Submit an INVOKE transaction calling `test_replace_class` with an arbitrary, undeclared `class_hash` (e.g., `felt!(1234_u16)`).
3. Under Blockifier, this reverts with "is not declared" (as shown in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`), so the transaction is rejected/excluded from the block.
4. If the identical low-level syscall trace were instead fed to / re-executed by the Starknet OS's `execute_replace_class` (e.g., via any tooling that constructs OS execution input independent of Blockifier's pre-validation, or via a future code path that reuses the OS logic without going through Blockifier's gating), the OS would unconditionally overwrite `contract_state_changes[contract_address].class_hash = 1234` with no validation, producing a state/class assignment that Blockifier's own invariants forbid — demonstrating the semantic gap between the two "identical" execution engines.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
