### Title
Missing declared-class-hash validation in Starknet OS `execute_replace_class` causes state-root divergence from blockifier execution - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS's Cairo re-implementation of the `replace_class` syscall omits the validation that the blockifier (Rust) implementation performs — checking that the target `class_hash` is a declared, compatible class before writing it into the contract's state entry. This is directly analogous to the PhiFactory bug class: a caller can, via an ordinary syscall reachable from any transaction, unilaterally rewrite a critical, security-relevant setting (a contract's class hash) with no validation on the "receiving" side, causing the two independent execution paths of the system (blockifier vs. OS re-execution) to disagree on the resulting state.

### Finding Description
The blockifier's Rust implementation of `replace_class` explicitly validates the target class before mutating state: [1](#0-0) 
and the newer syscall path additionally rejects incompatible class-version replacements (evidenced by the test asserting `"Cannot replace V1 class hash with V0 class hash"`). [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall (`execute_replace_class`, used for proof generation / re-execution of the block) contains an explicit TODO marking that this validation is not implemented: [3](#0-2) 

Specifically, at line 902 the comment reads: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function proceeds directly to overwrite the contract's `StateEntry.class_hash` in `contract_state_changes` with whatever `class_hash` value was supplied, with no check that it corresponds to a declared class (unlike the deprecated-syscalls Rust handler which calls `state.get_compiled_class(request.class_hash)?` first, causing a state-read error/revert if undeclared).

This mirrors the PhiFactory root cause exactly: a settings-mutation entry point (`updateArtSettings` / `replace_class`) accepts attacker/caller-controlled input and commits it to persistent state without validating it against the required invariant (existing declared class / sane royalty bound), and this omission is reachable from an ordinary, unprivileged transaction (any contract can invoke the `replace_class` syscall on itself).

### Impact Explanation
If a transaction invokes `replace_class` with an undeclared (or otherwise invalid) class hash:
- Blockifier, which builds/validates the block during normal sequencing, will reject the syscall (returns `StateError`/`UndeclaredClassHash`), causing the transaction to revert or fail differently than in the OS.
- The Starknet OS re-execution (used to construct/verify the proof of the same block) lacks this check and will unconditionally commit the arbitrary class hash into `contract_state_changes`, producing a different final state diff/state root for the same transaction and block.

This is a direct **honest-node divergence** / **wrong committed root** scenario: the sequencer's blockifier and the OS's re-execution, which must agree bit-for-bit on state transitions for a block to be provable and honestly represented, disagree on the outcome of a transaction that replaces a contract's class with an undeclared hash. Depending on which path a node trusts, this can result in the OS/prover committing an unauthorized state change (writing a bogus class hash into a live contract's storage entry) that blockifier itself would never have permitted, or the network being unable to reconcile the sequencer-built block against the OS-proved block, threatening the ability to confirm new transactions built on top of that divergence.

### Likelihood Explanation
Reachability is trivial: any contract can invoke `replace_class(class_hash)` from ordinary execution (no special permissions), and merely needs to pass an undeclared or version-incompatible class hash — a value fully controlled by the calling contract/transaction. No malicious operator, prover, or node behavior is required; a single unprivileged transaction sender can trigger the divergent code paths. The TODO comment in the source confirms this is a known, currently-unimplemented check rather than a theoretical gap.

### Recommendation
Add the equivalent declared-class-hash (and class-version compatibility) check to `execute_replace_class` in the Starknet OS Cairo implementation, mirroring the blockifier's Rust validation (`get_compiled_class` lookup, and the V0/V1 compatibility check), before allowing the `StateEntry.class_hash` to be updated. This closes the TODO and guarantees agreement between blockifier and OS re-execution for this syscall.

### Proof of Concept
1. Deploy a contract that calls the `replace_class` syscall with an arbitrary, undeclared `class_hash` (e.g., as exercised by the existing blockifier unit test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit the transaction to a sequencer: blockifier's `get_compiled_class` lookup fails, and the syscall/transaction errors out (per `hint_processor.rs` and the negative-flow test asserting `"is not declared"`).
3. Feed the identical transaction/block trace into the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`): because the "TODO" validation is absent, the OS accepts the undeclared class hash and writes it into `contract_state_changes` unconditionally, producing a state diff/root that differs from what blockifier computed for the same block.
4. Compare committed state roots/hashes from both execution paths to observe the divergence.

Note: I was unable to fully trace how the OS's block-building/committer stage would ultimately treat this divergent contract_state_changes entry when computing the final committed root and whether any downstream check elsewhere in the OS pipeline (outside `syscall_impls.cairo`) might catch it before commitment; a Devin session with full-repo access would be needed to confirm there is no compensating validation elsewhere in the OS commitment/output stage.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
