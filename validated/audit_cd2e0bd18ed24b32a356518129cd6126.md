### Title
Unbounded stale gas-price consumption from ChainMeta oracle in outbound gas accounting - (File: `x/uexecutor/keeper/gas_fee.go`, `x/uexecutor/keeper/build_revert_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The `ChainMeta` oracle's write path (`VoteChainMeta`) filters out votes older than `chainMetaVoteStalenessSeconds` (300s) before computing the median that gets pushed on-chain via `setChainMeta` [1](#0-0) . However, every consumer of that stored price — `GetOutboundTxGasAndFees`, `GetGasFeeInfoForRevertOutbound`, `GetGasPriceByChain`, and `GetL1GasFeeByChain` — reads the last-applied value from the `UniversalCore` contract unconditionally, with no check against `timestampObservedAtByChainNamespace` (which exists in the ABI but is never called from Go) [2](#0-1) [3](#0-2) .

### Finding Description
This is the same bug class as Pyth's `getPriceUnsafe`: a price/rate value is fetched and used for accounting without verifying its freshness at the point of consumption, even though a `publishTime`/`stored_at` field exists specifically for that purpose.

`VoteChainMeta` only updates `ChainMeta` when there are fresh votes; if validators stop submitting fresh votes for a chain (RPC outage, disabled chain-meta oracle, validator downtime, or a chain being deprecated), the on-chain `gasPriceByChainNamespace`/`l1GasFeeByChainNamespace` values simply freeze at whatever was last written — potentially arbitrarily old [4](#0-3) . Every downstream unprivileged-triggered flow keeps consuming this frozen value as if it were current:

- `buildRevertOutbound` calls `GetGasFeeInfoForRevertOutbound` → `GetOutboundTxGasAndFees` to populate `GasPrice`/`GasFee`/`GasLimit` on every `INBOUND_REVERT` outbound, triggered whenever a user's inbound fails validation [5](#0-4) .
- `InitiateFundMigration` in `x/utss` uses the same stale `GetGasPriceByChain` value to size a fund migration's `GasPrice`/`GasLimit`/`L1GasFee` fields [6](#0-5) .
- `applyGasRefund` in `x/uexecutor/keeper/outbound.go` compares the outbound's stored `GasFee` (populated from this same stale oracle at creation time) against the observed `GasFeeUsed` to decide how much excess gas to refund via `CallUniversalCoreRefundUnusedGas` [7](#0-6) .

None of these call sites check chain-meta age before using the value for fund-affecting arithmetic, unlike the write-path staleness gate.

### Impact Explanation
If a stale (e.g., pre-spike or pre-crash) gas price sits in `ChainMeta` for an extended period (oracle degraded/disabled, all validators down for that chain's oracle interval, or a chain administratively re-enabled after inactivity), refund/revert/migration accounting silently uses an outdated price:
- Under-refunding gas to users on `INBOUND_REVERT` or failed outbounds if real gas prices spiked since the last fresh vote (user funds partially stuck relative to what they're owed).
- Over/under-sizing `FundMigration` gas allocations, potentially causing migration transactions to fail on the destination chain or over-allocate protocol funds.

This matches the "Registry and accounting path" and "Universal execution path" invariants: gas token/price use must not misroute value based on stale attacker-uncontrolled-but-unverified data.

### Likelihood Explanation
Low-to-moderate: requires the chain-meta oracle to stop receiving fresh votes for a specific chain (network partition to that RPC, misconfiguration, or a chain that is temporarily/administratively idle) while inbound reverts, outbound gas refunds, or fund migrations continue to be triggered by ordinary user activity or admin action on that chain. No malicious actor is required — an ordinary user's failed inbound or a normal outbound observation is enough to trigger consumption of the stale value.

### Recommendation
Add a staleness check at the point of consumption, mirroring the write-path guard: before using `gasPriceByChainNamespace`/`l1GasFeeByChainNamespace` in `GetOutboundTxGasAndFees`, `GetGasPriceByChain`, `GetL1GasFeeByChain`, or `InitiateFundMigration`, call `timestampObservedAtByChainNamespace` and compare against current block time using the same (or a configurable) `chainMetaVoteStalenessSeconds` threshold; reject or fall back gracefully (as `buildRevertOutbound` already does for other errors) when the value is stale, rather than silently proceeding with a frozen price.

### Proof of Concept
1. Chain X's Universal Validators stop submitting fresh `MsgVoteChainMeta` for chain X (e.g., RPC endpoint goes down for chain X only) while `LastAppliedChainHeight` remains at its last successfully-applied value.
2. Time passes well beyond `chainMetaVoteStalenessSeconds` — the on-chain `gasPriceByChainNamespace` value for chain X is now stale, but no code path rejects its use.
3. A user's inbound from chain X fails validation, triggering `buildRevertOutbound` → `GetGasFeeInfoForRevertOutbound` → `GetOutboundTxGasAndFees`, which reads and applies the frozen gas price to size the `INBOUND_REVERT` outbound's `GasFee`/`GasPrice` fields.
4. If real-world gas prices on chain X have since risen, the relayer's gas refund (via `applyGasRefund`) is computed against the stale (lower) `GasFee`, under-refunding the user relative to actual costs — with no on-chain signal that the price used was outdated.

// to get gasToken, gasFee, protocolFee, gasPrice, and chainNamespace.
// Pass gasLimitWithBaseLimit=0 to use the contract's baseLimit.
func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}
