## Analysis

The Derby bug is fundamentally about a **predictable, attacker-observable price used for a value conversion that executes with a time/state gap an attacker can exploit for risk-free profit**. The closest reachable analog in this Push Chain repo is not the `ChainMeta` gas-price oracle (that path requires validator votes — privileged/honest-validator actors, out of scope), but the **Uniswap V3 quote-then-swap flow used for `GAS` / `GAS_AND_PAYLOAD` inbound auto-swaps**, which converts a user's bridged PRC20 into native PC using a live AMM quote with only a fixed 5% slippage tolerance.

### Title
Inbound auto-swap deposit uses a manipulable single-block Uniswap V3 quote with fixed 5% slippage, letting an attacker sandwich depositors' PRC20→PC conversion - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
When a `GAS` or `GAS_AND_PAYLOAD` inbound is executed, the module fetches a live swap quote from the on-chain Uniswap V3 `QuoterV2` and immediately executes the PRC20→WPC swap against that same pool, tolerating up to 5% negative slippage [1](#0-0) . Because the quote and the swap both reference the pool's *current* price and the only protection is a static `quote * 95 / 100` floor [2](#0-1) , any unprivileged actor who can move the pool price before this module-originated swap lands can extract up to the full 5% slippage window from the depositing user's funds — the same "extract value from a soon-to-be-applied state change" pattern as the Derby exchange-rate front-running bug, just against an AMM quote instead of a vault NAV.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false` to obtain `amountOut` for the PRC20→WPC leg [3](#0-2) . Immediately afterward, `minPCOut` is derived as a flat 95% of that quote and passed into `CallPRC20DepositAutoSwap`, which performs the actual on-chain swap via `depositPRC20WithAutoSwap` [4](#0-3) . This sequence — quote, then execute against the same pool with a fixed percentage floor — is used on both the `GAS` inbound path [1](#0-0)  and the `GAS_AND_PAYLOAD` inbound path [5](#0-4) , and again for excess-gas refunds on outbound finalization [6](#0-5) .

The upgrade notes confirm this is a deliberate, documented design choice replacing a previous zero-slippage call: "GAS and GAS_AND_PAYLOAD inbound routes now call the Uniswap V3 QuoterV2 contract to obtain an on-chain swap quote and pass minPCOut (quote × 95%)... replacing the previous 0-slippage call" [7](#0-6) .

Because the pool used (WPC/PRC20 on the Uniswap V3 fork deployed as a system contract) is a public AMM, any unprivileged holder of the relevant tokens can trade against it. The inbound's presence becomes knowable in advance (it is voted on-chain via `MsgVoteInbound` before the ballot finalizes and the deposit/swap executes), giving an attacker a window to push the pool price up to 5% against the depositor immediately before the module's swap lands, then reverse the trade afterward — extracting the difference as guaranteed, risk-free profit funded entirely by the depositing user's converted funds. This mirrors the core Derby defect: a value-conversion using a rate that can be predicted/manipulated right before it is "locked in" on-chain, allowing risk-free extraction at another party's expense.

### Impact Explanation
This falls under the allowed impact "corruption of PRC20 or native asset accounting" and "stealing... of user... controlled funds": the depositing user's bridged PRC20 is converted to PC at a price manipulated up to 5% worse than fair market value, with the difference captured by the attacker sandwiching the module-originated swap. This is a direct, unprivileged, fund-draining MEV vector against every `GAS`/`GAS_AND_PAYLOAD` inbound and every outbound gas refund that goes through the swap-refund path.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: it requires the attacker to have capital to move the specific PRC20/WPC pool and to be able to order transactions around the block that processes the finalizing `MsgVoteInbound`/`MsgVoteOutbound`. On a permissionless mempool/proposer model this is a standard, well-understood MEV sandwich pattern, not a novel attack technique, and the 5% tolerance is a substantial, fixed extraction ceiling rather than a tightly-bounded one.

### Recommendation
Reduce or dynamically tighten the slippage tolerance (5% is large for typical liquidity depths), and/or use a TWAP-based reference price instead of an instantaneous `quoteExactInputSingle` call so a single-block price movement cannot be leveraged. Consider settling the swap in the same atomic step the quote is fetched with a much smaller allowed deviation, or route through a private/non-frontrunnable execution path (e.g., commit-reveal or batched execution) for module-originated swaps so depositors are not exposed to sandwichable single-block AMM pricing.

### Proof of Concept
1. Attacker observes an inbound `GAS`/`GAS_AND_PAYLOAD` event (or its corresponding `MsgVoteInbound` votes) targeting a known PRC20/WPC pool before the ballot finalizes.
2. Attacker submits a large swap against the same Uniswap V3 pool to push the PRC20→WPC price up by close to 5%, ordered to land before the ballot-finalizing transaction that triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`.
3. The module calls `GetSwapQuote` [3](#0-2)  against the now-skewed pool, computes `minPCOut = quote * 95/100` [8](#0-7) , and executes `depositPRC20WithAutoSwap`, delivering PC to the recipient at the manipulated (worse) rate — still within the accepted 5% band, so the transaction does not revert.
4. Attacker immediately reverses their position, realizing the price impact as profit extracted from the value the depositor should have received.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
