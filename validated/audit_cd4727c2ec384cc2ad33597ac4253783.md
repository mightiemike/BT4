I found a strong analog. The seed bug describes value extraction by manipulating a live counter that a price computation depends on, then reversing the manipulation to pocket the difference. In Push Chain's `x/uexecutor` module, several code paths convert protocol/user funds through a live Uniswap V3 pool spot price (`GetSwapQuote`) instead of a fixed, pre-agreed rate, with only a fixed 5% slippage buffer — this is directly analogous: an unprivileged attacker can move the pool price right before the protocol-driven swap executes and pocket the difference, exactly like buying/selling the "seat" around the victim's transaction.

### Title
Sandwichable on-chain quote lets attacker extract value from protocol-driven gas-refund and gas-deposit swaps - (File: x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
`applyGasRefund` (outbound finalization) and the `GAS`/`GAS_AND_PAYLOAD` inbound deposit-with-autoswap paths compute the minimum acceptable swap output (`minPCOut`) as `quote * 95 / 100`, where `quote` is a live spot-price read from the Uniswap V3 `QuoterV2.quoteExactInputSingle` at the moment the module-originated swap executes [1](#0-0) . Because the quote is read and the swap executed within the same flow, and the pool is a normal permissionless Uniswap V3 pool that any unprivileged user can trade against, an attacker can move the pool price immediately before the protocol's swap and back again immediately after (a sandwich), extracting up to the full 5% slippage tolerance from user/protocol-controlled gas-refund or gas-deposit funds — the same "manipulate the live price input, then reverse it to pocket the difference" pattern described in the seed report.

### Finding Description
Three call sites compute a live AMM quote and pass a 5%-tolerance `minPCOut` into a protocol-originated `DerivedEVMCall` swap:

- `GetSwapQuote` reads `QuoterV2.quoteExactInputSingle` for the `prc20 → WPC` pair at the current pool state [2](#0-1) .
- `ExecuteInboundGas` (inbound `GAS` flow) uses this quote to compute `minPCOut = quote * 95 / 100` before calling `CallPRC20DepositAutoSwap` [3](#0-2) .
- `gasAndPayloadDepositAutoSwap` (inbound `GAS_AND_PAYLOAD` flow) does the identical computation [4](#0-3) .
- `applyGasRefund` (outbound finalization, triggered once honest validators reach quorum on `MsgVoteOutbound`) does the identical computation for the excess-gas refund swap `gasToken → PC` [1](#0-0) .

All three swaps are executed via `k.evmKeeper.DerivedEVMCall(...)` as ordinary EVM transactions from the `uexecutor` module account, landing in the mempool/block like any other transaction [5](#0-4) [6](#0-5) . Because the underlying Uniswap V3 pool is a permissionless AMM reachable by any unprivileged account, and the module's swap tolerates up to 5% slippage from the just-read spot quote, an attacker can:
1. Submit a large swap in the same pool immediately before the protocol's deposit/refund transaction executes, moving the spot price against the protocol's swap direction.
2. Let the protocol's `depositPRC20WithAutoSwap` / `refundUnusedGas` execute at the manipulated price (still within the 5% band, so it doesn't revert).
3. Submit a reverse swap immediately after to restore the pool price, capturing the value that would otherwise have gone to the recipient (the bridging user in the `GAS`/`GAS_AND_PAYLOAD` case, or the outbound sender/fund_recipient in the refund case).

This mirrors the seed report's bonding-curve exploit: the "seat price" (here, the swap output) is derived from a manipulable live counter (the pool's spot price) at execution time rather than a value locked/agreed at intent time, and the attacker profits by moving the counter unfavorably for the victim and reversing it afterward.

### Impact Explanation
Each exploited swap silently reduces the PC (or PRC20) amount actually delivered to the bridging user or refund recipient by up to the 5% slippage margin, with the difference captured by the attacker via the sandwich. This is an unauthorized loss of user/protocol-controlled funds (PC native token from `depositPRC20WithAutoSwap`, or gas-token/PC from `refundUnusedGas`) reachable through ordinary unprivileged bridging/deposit transactions and normal DEX trading, without requiring any relayer, validator, or admin compromise.

### Likelihood Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound, and every successful/failed outbound with excess gas to refund, triggers one of these swaps, so the attack surface is exercised continuously and predictably (the attacker can watch the mempool/pending inbound votes and the deterministic finalization of outbound ballots to time the sandwich). The only defense is the 5% tolerance band, which is a wide margin for an AMM sandwich and does not require deep liquidity manipulation for pools with typical on-chain liquidity depths for newly bridged/long-tail tokens.

### Recommendation
Do not rely on a single just-in-time spot quote with a fixed percentage tolerance for protocol-driven swaps. Options: (1) use a TWAP-based quote from the Uniswap V3 pool (`observe`) instead of `quoteExactInputSingle`'s instantaneous price, (2) tighten and dynamically size slippage tolerance to pool liquidity/expected price impact instead of a flat 5%, or (3) route these swaps through a private/atomic execution path (e.g., compute quote and execute swap in the same atomic EVM call rather than a two-step off-chain-computed-then-submitted pattern) so there is no window for a front-run/back-run sandwich.

### Proof of Concept
1. Attacker identifies a bridging user submitting a `GAS_AND_PAYLOAD` inbound (or any pending outbound about to finalize with `gasFee > gasFeeUsed`) whose deposit/refund token trades against `WPC` in a Uniswap V3 pool with the `defaultFeeTier` configured in `UniversalCore`.
2. Immediately before the `uexecutor` module's `DerivedEVMCall` executing `depositPRC20WithAutoSwap`/`refundUnusedGas` lands (module transactions are ordinary EVM txs, timing is observable from pending inbound ballots reaching quorum or outbound ballots reaching quorum), attacker submits a large swap in the same pool/fee-tier that shifts the spot price unfavorably for the upcoming protocol swap direction.
3. `GetSwapQuote` at execution time returns a price already skewed by the attacker's trade; `minPCOut = quote * 95/100` still permits the module's swap to execute at this degraded price rather than reverting [7](#0-6) .
4. Attacker immediately submits the reverse swap to restore the pool price, net profiting the price impact they induced (bounded by the 5% band and pool depth), while the bridging user/refund recipient receives less PC than the true pre-manipulation price would have given them.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
