### Title
Public free-bandwidth pool exhaustion DoS via cheap repeated transactions - (File: chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java)

### Summary
The reported LevelMinting bug is a class of vulnerability where a shared, capped resource (deposit/redeem quota) can be atomically and cheaply exhausted by a malicious actor within the resource's reset window, causing legitimate/innocent users' transactions to revert. The closest unprivileged analog in java-tron is the shared `PublicNetLimit` free-bandwidth pool consumed by `BandwidthProcessor.useFreeNet`, which is drawn from by *any* account issuing ordinary broadcast transactions.

### Finding Description
`BandwidthProcessor.useFreeNet` checks and consumes bandwidth from a single global, shared bucket (`PublicNetLimit`/`PublicNetUsage`) before falling back to charging TRX fees: [1](#0-0) 

This pool is checked and incremented per transaction, independent of which account is transacting — any account (including a freshly created, low-balance account) can consume it via ordinary `TransferContract`/`TransferAssetContract` transactions: [2](#0-1) 

Because the free-net check-then-use logic is not gated by any per-user fairness mechanism (it is a global bucket shared by the whole network, replenished only slowly over the sliding window via `increase()`), a malicious actor can broadcast many cheap, self-directed, low-fee transactions in rapid succession (across blocks, or bursts within the propagation/packing window) to drive `PublicNetUsage` up to `PublicNetLimit`. Once exhausted, `useFreeNet` returns `false` for every other account, forcing `BandwidthProcessor.consume` to fall through to `useTransactionFee`, and ultimately to an `AccountResourceInsufficientException` for any account without sufficient TRX balance to pay bandwidth fees: [3](#0-2) 

This mirrors the LevelMinting pattern precisely: a shared per-window cap (`deposit/redemption cap` ≈ `PublicNetLimit`) that is check-then-consume, with no fee/anti-spam mechanism scaled to deter repeated cheap consumption, allowing one actor to monopolize the resource and block legitimate/innocent users from using it during that window.

### Impact Explanation
Exhausting `PublicNetLimit` denies free bandwidth to every zero/low-balance account attempting ordinary transfers network-wide until the sliding window recovers (`BandwidthProcessor.increase`), which can take hours given typical window sizes. Victims without spare TRX balance to cover the fallback fee are unable to transact at all, a direct availability/DoS impact reachable purely via broadcasting ordinary signed transactions — no privileged actor or contract call required.

### Likelihood Explanation
Likelihood is moderate: the attack requires only funding a handful of accounts with minimal TRX (for basic account/transfer fees) and rapidly broadcasting many self-transfers; the marginal cost per unit of consumed bandwidth quota is very low relative to the shared pool size, similar to the "cheap L2 gas" assumption in the original report. It is fully unprivileged and reachable by any external actor via ordinary broadcast transactions.

### Recommendation
- Rate-limit or fairly partition consumption of `PublicNetLimit` per account/time window (e.g., per-account sub-quota of the public pool) rather than a single first-come-first-served global bucket.
- Consider imposing a minimal fee or per-account throttle on free-bandwidth consumption to raise the cost of exhausting the shared pool, analogous to the LevelMinting report's recommendation to impose fees on deposit/redeem to deter cap-filling abuse.
- Monitor/alert on rapid depletion of `PublicNetUsage` and consider dynamically shrinking per-tx free-bandwidth grants when the pool is under contention.

### Proof of Concept
1. Attacker funds N throwaway accounts with minimal TRX.
2. Each account repeatedly issues zero/low-value `TransferContract` transactions to itself or another attacker-controlled address; each call flows through `BandwidthProcessor.consume` → `useAccountNet` (fails, no frozen balance) → `useFreeNet`.
3. Each successful `useFreeNet` call increments the shared `PublicNetUsage` counter until it reaches `PublicNetLimit` (`chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java:520-531`).
4. Once exhausted, any other account's ordinary transfer that relies on free bandwidth fails `useFreeNet`, falls through to fee payment, and if that account lacks TRX, `AccountResourceInsufficientException` is thrown (`chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java:172-177`), denying service to legitimate/innocent users until the pool window resets.

*Note: I could not fully verify the exact default value of `PublicNetLimit` (`chainbase/src/main/java/org/tron/core/store/DynamicPropertiesStore.java`) or the precise window-reset cadence within the available index; a full review of that configuration would require a live Devin session with complete file access to confirm exact economic feasibility of the attack.*

  private boolean useFreeNet(AccountCapsule accountCapsule, long bytes, long now) {

    long freeNetLimit = chainBaseManager.getDynamicPropertiesStore().getFreeNetLimit();
    long freeNetUsage = accountCapsule.getFreeNetUsage();
    long latestConsumeFreeTime = accountCapsule.getLatestConsumeFreeTime();
    long newFreeNetUsage = increase(freeNetUsage, 0, latestConsumeFreeTime, now);

    if (bytes > (freeNetLimit - newFreeNetUsage)) {
      logger.debug("Free net usage is running out."
              + " Bytes: {}, freeNetLimit: {}, newFreeNetUsage: {}.",
          bytes, freeNetLimit, newFreeNetUsage);
      return false;
    }

    long publicNetLimit = chainBaseManager.getDynamicPropertiesStore().getPublicNetLimit();
    long publicNetUsage = chainBaseManager.getDynamicPropertiesStore().getPublicNetUsage();
    long publicNetTime = chainBaseManager.getDynamicPropertiesStore().getPublicNetTime();

    long newPublicNetUsage = increase(publicNetUsage, 0, publicNetTime, now);

    if (bytes > (publicNetLimit - newPublicNetUsage)) {
      logger.debug("Free public net usage is running out."
              + " Bytes: {}, publicNetLimit: {}, newPublicNetUsage: {}.",
          bytes, publicNetLimit, newPublicNetUsage);
      return false;
    }
