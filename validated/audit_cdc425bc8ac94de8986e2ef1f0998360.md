Confirmed: `redirectFactory` (in both `shopify-app-remix` and `shopify-app-react-router`) correctly checks `parsedUrl.origin === new URL(config.appUrl).origin` before propagating request params, matching the documentation. The actual URL parsing/safety check itself, however, lives in `sanitizeRedirectUrl`/`isSafe` in `validate-redirect-url.ts`, and that function has an insufficient check that lets it accept protocol-relative URLs (`//attacker.com/...`) as "safe."

### Title
Open redirect via protocol-relative URL bypass in `sanitizeRedirectUrl` - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts` and `packages/apps/shopify-app-react-router/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
`sanitizeRedirectUrl`/`isSafe` is meant to prevent apps from redirecting merchants off-domain (only file URIs, whitespace, bad protocols, and "invalid relative URLs" are rejected). It fails to reject protocol-relative URLs such as `//evil.com/path`, which `new URL()` resolves to an absolute URL on an attacker-controlled host while still passing every check in `isSafe`.

### Finding Description
`isSafe()` runs four checks on a `redirectUrl` string before allowing it to be used: [1](#0-0) 

- `FILE_URI_MATCH = /\/\/\//` only matches **three** consecutive slashes, so a value like `//evil.com/path` (two slashes) passes.
- `WHITESPACE_CHARACTER` doesn't apply to `//evil.com/path`.
- `new URL('//evil.com/path', 'https://myapp.example.com')` follows the WHATWG URL "network-path reference" rule and resolves to `https://evil.com/path` — the host is silently replaced by the input's host, not the intended `domain` base.
- `INVALID_RELATIVE_URL = /[/\\][/\\]/` is tested against `url.pathname` (`"/path"`), which contains no double slash, so it passes.
- `VALID_PROTOCOLS.includes(url.protocol)` passes because the resolved protocol is `https:`.
- `requireSSL` passes because the resolved protocol is already `https:`.

As a result, `sanitizeRedirectUrl(domain, '//evil.com/path')` returns a `URL` object pointing to `https://evil.com/path` instead of throwing/rejecting it. This function is the shared redirect-safety primitive used across `shopify-app-remix` and `shopify-app-react-router`. [2](#0-1) 

This mirrors the reported bug class: a validation routine that is supposed to enforce a documented safety boundary ("Refusing to redirect" to unsafe locations) implements a check that is measurably weaker than intended, letting an out-of-scope value slip through the same code path that's trusted to gate it.

### Impact Explanation
`redirectFactory`'s origin check (`parsedUrl.origin === new URL(config.appUrl).origin`) does independently gate whether request query params (`id_token`, `shop`, `host`, `embedded`, etc.) get copied to the destination, and that logic is not driven by `sanitizeRedirectUrl` in the `redirectFactory` path shown. [3](#0-2)  This means the direct redirect-target consumer of `sanitizeRedirectUrl` in this codebase is limited to the code paths exercised by its own tests (e.g. login/OAuth flows or app-level `redirect(url, {options})` calls that use it directly), not the `redirectFactory`'s `parseURL`, which builds URLs itself via `new URL(url, base)` without calling `sanitizeRedirectUrl`.

### Likelihood Explanation
I could not find, within the indexed portion of the codebase, a call site that pipes untrusted/merchant-provided input directly into `sanitizeRedirectUrl` in a way that would leak session data to the resolved host — the two `redirect.ts` implementations reviewed build their target URL with `new URL(url, base)` directly rather than through `sanitizeRedirectUrl`, and gate param-forwarding on `origin` equality computed from that URL (which would correctly detect `https://evil.com` as cross-origin and refuse to forward params). Given index size limits, there may be additional call sites of `sanitizeRedirectUrl` (e.g. in `shopify-app-express` or other helper files) that I was not able to locate or fully verify.

### Recommendation
Harden `isSafe()` in `validate-redirect-url.ts` to reject protocol-relative URLs explicitly, e.g. by checking `redirectUrl.startsWith('//')` (or more robustly, by parsing `redirectUrl` on its own with no base and rejecting it if it yields a defined `protocol`/`host`, before re-resolving against `domain`), then re-verifying that the resolved `url.host` matches the parsed `domain`'s host.

### Proof of Concept
```ts
import {sanitizeRedirectUrl} from './validate-redirect-url';

// domain = the app's own origin
const result = sanitizeRedirectUrl('https://myapp.example.com', '//evil.com/steal');
console.log(result.href); // "https://evil.com/steal" -- should have thrown ShopifyError
```

Given the uncertainty about whether any call site actually forwards sensitive request parameters through `sanitizeRedirectUrl` without an additional origin check (I could not confirm one within the indexed code, and a Devin session with full repo access would be needed to exhaustively enumerate all call sites), I present this as a valid analog for the "insufficiently enforced validation boundary" bug class, but flag that its exploitability depends on an as-yet-unconfirmed call site.

const FILE_URI_MATCH = /\/\/\//;
const INVALID_RELATIVE_URL = /[/\\][/\\]/;
const WHITESPACE_CHARACTER = /\s/;
const VALID_PROTOCOLS = ['https:', 'http:'];

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}

export function sanitizeRedirectUrl<OptionsArg extends Options>(
  domain: string,
  redirectUrl: unknown,
  options: OptionsArg = {} as OptionsArg,
): SanitizedRedirectUrl<OptionsArg> {
  if (isSafe(domain, redirectUrl, options.requireSSL)) {
    return new URL(redirectUrl, domain) as SanitizedRedirectUrl<OptionsArg>;
  } else if (options.throwOnInvalid === false) {
    return undefined as SanitizedRedirectUrl<OptionsArg>;
  } else {
    throw new ShopifyError('Invalid URL. Refusing to redirect');
  }
}
