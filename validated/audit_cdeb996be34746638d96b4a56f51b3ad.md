### Title
Obsolete/tombstone account entries bypass exclusion filter in `get_unique_accounts_from_storage`, breaking the invariant relied on by shrink's `is_alive` assertion - (File: accounts-db/src/accounts_db.rs)

### Summary
`AccountStorageEntry` maintains `obsolete_accounts` and `tombstone_offsets` lists specifically so that accounts which have been logically superseded/removed can be excluded from scans [1](#0-0) . The exclusion is implemented in `AccountStorageEntry::scan_accounts` / `scan_accounts_without_data`, which compute `excluded_offsets()` from both `obsolete_accounts` and `tombstone_offsets` and skip those offsets during the scan [2](#0-1) . However, `AccountsDb::get_unique_accounts_from_storage` — the function used to build the account list for shrink and ancient-append-vec combining — calls `store.accounts.scan_accounts_without_data(...)` directly on the underlying `AccountsFile`, not `store.scan_accounts_without_data(...)` (the `AccountStorageEntry` wrapper that applies `excluded_offsets()`), so the obsolete/tombstone filter is never applied here [3](#0-2) .

### Finding Description
The `enabled`-style gating flag in the external report has a direct analog here: `obsolete_accounts` / `tombstone_offsets` are per-storage "should be excluded from further processing" markers, exactly like `LoanConfig::enabled`. Every consumer of storage-account scanning is supposed to go through the `AccountStorageEntry` wrapper methods that check these markers (as documented and unit-tested in `test_scan_accounts_excludes_obsolete_and_tombstones` [4](#0-3) ), but `get_unique_accounts_from_storage` reaches past the wrapper straight into `store.accounts` (the raw `AccountsFile`), which has no concept of obsolete/tombstone exclusion at all [5](#0-4) .

This function is the entry point used by shrink (`get_unique_accounts_from_storage_for_shrink`) [6](#0-5)  and by ancient-append-vec combining. Downstream in `load_accounts_index_for_shrink`, the code explicitly assumes the filtering already happened: `// All obsolete and tombstones have been filtered. Account MUST be alive in this slot` followed by `assert!(is_alive);` [7](#0-6) . Because the upstream scan never actually excludes obsolete/tombstone offsets, any account whose accounts-index slot_list still contains an entry with that pubkey but at a slot other than `slot_to_shrink` (a stale/obsolete offset re-surfacing through the raw scan) will fail the `is_alive` check and hit the `assert!` — a validator/node panic — instead of being silently and correctly skipped as intended by the obsolete/tombstone bookkeeping.

### Impact Explanation
This is a concrete node-panic risk: an invariant that the codebase's own comment states must hold ("All obsolete and tombstones have been filtered") is not actually enforced by the code path that feeds `load_accounts_index_for_shrink`, because the filtering wrapper is bypassed in `get_unique_accounts_from_storage`. If a storage contains obsolete or tombstone entries whose pubkeys are not the currently-live entry for `slot_to_shrink` in the accounts index, shrink (a routinely-scheduled background maintenance operation on every validator) can trip the `assert!(is_alive)` and crash the node process. Separately, even when this doesn't hit the assertion, obsolete/tombstone accounts are needlessly re-scanned and re-processed by shrink and ancient-append-vec combining, adding avoidable CPU/storage overhead that the obsolete-accounts optimization was specifically introduced to avoid.

### Likelihood Explanation
`get_unique_accounts_from_storage` unconditionally uses the unfiltered raw scan for every call, so any storage that has previously had accounts marked obsolete or carried tombstones forward from a shrink cycle (a routine, frequent occurrence on any actively-used validator, not requiring adversarial input) is affected. Shrink and ancient-append-vec combining run continuously as part of normal AccountsDb background maintenance, so the exposure window is large; whether the `assert!(is_alive)` is actually triggered depends on the exact interleaving of obsolete-marking and subsequent index state, but the underlying missed-filtering defect is reached on essentially every shrink/combine invocation on a storage containing obsolete or tombstone accounts.

### Recommendation
Change `get_unique_accounts_from_storage` to call `store.scan_accounts_without_data(...)` (the `AccountStorageEntry` wrapper) instead of `store.accounts.scan_accounts_without_data(...)` (the raw `AccountsFile`), so obsolete and tombstone offsets are consistently excluded everywhere account-storage scans are used to build shrink/combine candidate lists, restoring the invariant that `load_accounts_index_for_shrink` already assumes and asserts on.

### Proof of Concept
Not independently executed; based on static analysis of the code paths cited above. A reproducing test would: (1) create a storage with two versions of the same pubkey across slots (so the older is marked obsolete via `mark_accounts_obsolete`, as done in `ancient_append_vecs.rs`'s test helpers) or a tombstone offset via `batch_insert_tombstone_offsets`; (2) call `AccountsDb::get_unique_accounts_from_storage` on that storage and observe that the obsolete/tombstone entry is still returned in `GetUniqueAccountsResult`, unlike calling `store.scan_accounts_without_data` directly which correctly excludes it (as shown by the existing `test_scan_accounts_excludes_obsolete_and_tombstones` test) [8](#0-7) ; (3) feed that result into `load_accounts_index_for_shrink` under conditions where the stale entry's slot_list does not contain `slot_to_shrink`, triggering `assert!(is_alive)` [9](#0-8) .

    fn excluded_offsets(&self) -> IntSet<Offset> {
        let mut offsets: IntSet<_> = self
            .obsolete_accounts_read_lock()
            .filter_obsolete_accounts(None)
            .map(|(offset, _)| offset)
            .collect();
        offsets.extend(self.tombstone_offsets_read_lock().iter().copied());
        offsets
    }

    /// Iterate over the alive accounts in this storage, excluding obsolete accounts and tombstones.
    /// The return value is the number of values excluded from the scan.
    pub(crate) fn scan_accounts<'a>(
        &'a self,
        reader: &mut impl RequiredLenBufFileRead<'a>,
        mut callback: impl for<'local> FnMut(Offset, StoredAccountInfo<'local>),
    ) -> Result<u64, AccountsFileError> {
        let excluded_offsets = self.excluded_offsets();
        let mut num_excluded = 0;
        self.accounts.scan_accounts(reader, |offset, account| {
            if excluded_offsets.contains(&offset) {
                num_excluded += 1;
                return;
            }
            callback(offset, account);
        })?;
        Ok(num_excluded)
    }

    /// Iterate over the alive accounts in this storage without reading data, excluding obsolete
    /// accounts and tombstones. The return value is the number of values excluded from the scan.

        &self,

    ) -> Result<u64, AccountsFileError> {
        let excluded_offsets = self.excluded_offsets();

                if excluded_offsets.contains(&offset) {
                    num_excluded += 1;
                    return;
                }

        let storage = AccountStorageEntry::new(

        let accounts: Vec<_> = iter::repeat_with(|| {
            (
                Pubkey::new_unique(),
                AccountSharedData::new(1, 10, &Pubkey::default()),
            )
        })
        .take(5)
        .collect();
        let offsets = storage
            .accounts
            .write_accounts(&(slot, &accounts[..]))
            .unwrap()
            .offsets;

        // Mark account 1 obsolete and record account 3 as a tombstone.
        let obsolete_offset = offsets[1];
        let tombstone_offset = offsets[3];
        let data_lens = storage.accounts.get_account_data_lens(&[obsolete_offset]);
        storage
            .obsolete_accounts()
            .write()
            .unwrap()
            .mark_accounts_obsolete(iter::once((obsolete_offset, data_lens[0])), slot);
        storage.batch_insert_tombstone_offsets([tombstone_offset]);

        // Scan and collect the accounts that were visited, in offset order.
        let mut reader = new_scan_accounts_reader();
        let mut visited = Vec::new();
        let num_excluded = storage
            .scan_accounts(&mut reader, |offset, account| {
                visited.push((offset, *account.pubkey()));
            })
            .unwrap();

        // Accounts 0, 2, and 4 are alive; 1 (obsolete) and 3 (tombstone) are excluded.
        assert_eq!(num_excluded, 2);
        let expected: Vec<_> = [0, 2, 4]

            .map(|&i| (offsets[i], accounts[i].0))
            .collect();
        assert_eq!(visited, expected);

        // scan_accounts_without_data excludes the same offsets from the same storage.
        let mut visited = Vec::new();
        let num_excluded = storage
            .scan_accounts_without_data(|offset, account| {
                visited.push((offset, *account.pubkey()));
            })
            .unwrap();
        assert_eq!(num_excluded, 2);
        assert_eq!(visited, expected);
    }
