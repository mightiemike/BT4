## Analysis

The referenced bug class — using a block-count delta as a proxy for wall-clock time, when block/slot production rate is not actually constant — has a concrete analog in Agave's ancient-append-vec / shrink subsystem.

### Title
Ancient-append-vec slot-count threshold assumes fixed slot duration, but slot time is now feature-gated and variable - ([File: accounts-db/src/accounts_db.rs])

### Summary
`AccountsDb` decides which storages are "ancient" (and therefore subject to background packing/shrinking) using a fixed **slot-count** offset, `ANCIENT_APPEND_VEC_DEFAULT_OFFSET = 100_000`, combined with `epoch_schedule.slots_per_epoch` (also a fixed slot count) [1](#0-0) . This slot-count arithmetic implicitly assumes a constant slot duration, exactly the assumption the external report calls out as broken. `runtime/src/slot_params.rs` now defines multiple feature-gated slot-time regimes — legacy 400ms down to 350/300/250/200ms — that are activated progressively via `reduce_slot_time_to_350ms/300ms/250ms/200ms` [2](#0-1) , and `Bank::slot_range_duration_in_years`/`slot_range_duration_nanos` explicitly compute wall-clock duration per slot range because ns/slot is no longer constant across a bank's lifetime [3](#0-2) .

### Finding Description
`get_oldest_non_ancient_slot_from_slot` computes the ancient/modern boundary purely in slot units:
```
result = apply_offset_to_slot(max_root, ancient_append_vec_offset);   // -100_000 slots
result = apply_offset_to_slot(result, -(slots_per_epoch - 1));
``` [4](#0-3) 

This threshold, together with `combine_ancient_slots_packed`/`shrink_ancient_slots`, drives when storages get squashed into packed ancient AppendVecs [5](#0-4) . The 100,000-slot constant (and the epoch-length offset) was implicitly calibrated for the legacy ~400ms/slot cadence (`LEGACY_SLOT_PARAMS.ns_per_slot = 400_000_000`) [6](#0-5) . Once slot-time-reduction features activate (350/300/250/200ms), the same 100,000-slot / one-epoch offset represents proportionally less wall-clock time — as little as half at 200ms/slot. The runtime is fully aware slot duration is no longer fixed (hence the new `slot_params_at_slot`/`ns_per_slot_at_slot` machinery and `slot_range_duration_nanos` [7](#0-6) ), yet the ancient-append-vec subsystem in `accounts-db` never consults these per-slot durations — it only ever computes slot deltas.

### Impact Explanation
As slot cadence speeds up, storages cross the "ancient" boundary in far less real time than the offset was designed for, causing `combine_ancient_slots_packed`/`shrink_ancient_slots` to run substantially more often relative to actual wall-clock account "coldness." This produces disproportionate background CPU, I/O, and re-write costs for AccountsDb (the packing algorithm rewrites and merges storages) [8](#0-7) . Conversely, on validators that stay on the legacy/slower slot-time regime after peers have upgraded, storages take proportionally longer in real time to become eligible for ancient packing, causing them to accumulate more slots' worth of storage entries before being compacted — disproportionate storage growth. This matches the accepted "disproportionate storage and CPU cost" impact category for this scan.

### Likelihood Explanation
`reduce_slot_time_to_350ms/300ms/250ms/200ms` are real, sequenced feature gates already wired into `Bank`'s slot-params machinery and covered by tests such as `test_reduce_slot_time_range_duration` [9](#0-8) , confirming that once any of these features activate cluster-wide (which is the whole purpose of the feature), the constant-slot-duration assumption baked into `ANCIENT_APPEND_VEC_DEFAULT_OFFSET`/`get_oldest_non_ancient_slot_from_slot` no longer holds for every validator running that code. No attacker action is required — the divergence is triggered by ordinary feature activation, making this a design defect rather than a purely theoretical concern.

### Recommendation
Compute the ancient/modern boundary from wall-clock duration rather than raw slot count, using the same `slot_params`/`ns_per_slot_at_slot` machinery `Bank` already exposes (e.g., derive an effective slot offset from a target duration via `slot_range_duration_nanos`), so the ancient-append-vec threshold tracks real elapsed time across slot-time-regime transitions instead of a fixed slot delta.

### Proof of Concept
1. Activate `reduce_slot_time_to_200ms` on a running validator (or in a test bank as done in `test_reduce_slot_time_range_duration`).
2. Observe that `Bank::slot_range_duration_nanos(start, start + 100_000)` now returns roughly half the nanoseconds it would under `LEGACY_SLOT_PARAMS` [10](#0-9) .
3. Because `AccountsDb::get_oldest_non_ancient_slot_from_slot` never queries slot duration, the same `ANCIENT_APPEND_VEC_DEFAULT_OFFSET = 100_000` slot window now marks storages "ancient" after only half the real time, doubling the frequency of ancient-append-vec combine/shrink passes relative to design intent [4](#0-3) .

    /// get the oldest slot that is within one epoch of `max_root`.
    /// The slot will have been offset by `self.ancient_append_vec_offset`
    fn get_oldest_non_ancient_slot_from_slot(
        &self,
        epoch_schedule: &EpochSchedule,
        max_root: Slot,
    ) -> Slot {
        let mut result = max_root;
        if let Some(offset) = self.ancient_append_vec_offset {
            result = Self::apply_offset_to_slot(result, offset);
        }
        result = Self::apply_offset_to_slot(
            result,
            -((epoch_schedule.slots_per_epoch as i64).saturating_sub(1)),
        );
        result.min(max_root)
    }

    /// Returns the wall-clock duration in years for `[start_slot, end_slot)`.
    fn slot_range_duration_in_years(&self, start_slot: Slot, end_slot: Slot) -> f64 {
        if start_slot >= end_slot {
            return 0.0;
        }

        let mut cursor = start_slot;
        let mut params = self.slot_params.baseline_params();
        let mut duration = 0.0;

        for (effective_slot, effective_params) in self.slot_params.param_transitions() {
            if effective_slot <= start_slot {
                params = effective_params;
                continue;
            }
            if effective_slot >= end_slot {
                break;
            }

            duration += (effective_slot - cursor) as f64 / params.slots_per_year();
            cursor = effective_slot;
            params = effective_params;
        }

        duration + (end_slot - cursor) as f64 / params.slots_per_year()
    }

    /// Returns the exact wall-clock duration in nanoseconds for `start_slot..=end_slot`.
    pub fn slot_range_duration_nanos(&self, start_slot: Slot, end_slot: Slot) -> u128 {
        self.slot_params
            .slot_range_duration_nanos(start_slot, end_slot)
    }

impl AccountsDb {
    /// Combine account data from storages in 'sorted_slots' into packed storages.
    /// This keeps us from accumulating storages for each slot older than an epoch.
    /// After this function the number of alive roots is <= # alive roots when it was called.
    /// In practice, the # of alive roots after will be significantly less than # alive roots when called.
    /// Trying to reduce # roots and storages (one per root) required to store all the data in ancient slots
    pub(crate) fn combine_ancient_slots_packed(
        &self,
        sorted_slots: Vec<Slot>,
        can_randomly_shrink: bool,
    ) {
        let tuning = PackedAncientStorageTuning {
            // Slots old enough to be ancient.
            max_ancient_slots: self.max_ancient_storages,
            // Don't re-pack anything just to shrink.
            // shrink_candidate_slots will handle these old storages.
            percent_of_alive_shrunk_data: 0,
            ideal_storage_size: NonZeroU64::new(get_ancient_append_vec_capacity()).unwrap(),
            can_randomly_shrink,
            max_resulting_storages: NonZeroU64::new(10).unwrap(),
        };

        let _guard = self.active_stats.activate(ActiveStatItem::SquashAncient);

        let mut stats_sub = SquashStatsSub::default();

        let (_, total_us) = measure_us!(self.combine_ancient_slots_packed_internal(
            sorted_slots,
            tuning,
            &mut stats_sub
        ));

        self.shrink_ancient_stats.accumulate_sub_stats(stats_sub);
        self.shrink_ancient_stats
            .total_us
            .fetch_add(total_us, Ordering::Relaxed);

        self.shrink_ancient_stats.report();
    }

#[test]
fn test_reduce_slot_time_range_duration() {
    const SLOTS_PER_EPOCH: Slot = 32;
    let bank_for_activations = |activations: &[(Pubkey, Slot)]| {
        let (mut genesis_config, _) = create_genesis_config_with_legacy_hashes(1_000_000);
        genesis_config.epoch_schedule =
            EpochSchedule::custom(SLOTS_PER_EPOCH, SLOTS_PER_EPOCH, false);
        let mut bank = Bank::new_for_tests(&genesis_config);
        let mut feature_set = FeatureSet::default();
        for (feature_id, activation_slot) in activations {
            feature_set.activate(feature_id, *activation_slot);
        }
        bank.feature_set = Arc::new(feature_set);
        bank.refresh_slot_params();
        bank
    };

    let ordered_activations = slot_time_feature_gates()
        .into_iter()
        .zip([1, 33, 65, 97])
        .map(|((feature_id, _), activation_slot)| (feature_id, activation_slot))
        .collect::<Vec<_>>();
    let bank = bank_for_activations(&ordered_activations);

    let expected_duration = [
        (SLOTS_PER_EPOCH, LEGACY_SLOT_PARAMS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_350MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_300MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_250MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_200MS),
    ]
    .into_iter()
    .map(|(slots, params)| slots as f64 / params.slots_per_year())
    .sum::<f64>();

    assert_eq!(
        bank.slot_range_duration_in_years(0, SLOTS_PER_EPOCH * 5)
            .to_bits(),
        expected_duration.to_bits()
    );
    assert_eq!(
        bank.slot_range_duration_nanos(0, SLOTS_PER_EPOCH * 5 - 1),
        [
            (SLOTS_PER_EPOCH, LEGACY_SLOT_PARAMS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_350MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_300MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_250MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_200MS),
        ]
        .into_iter()
        .map(|(slots, params)| u128::from(slots) * params.ns_per_slot())
        .sum::<u128>()
    );

    let [reduce_to_350ms, _, _, reduce_to_200ms] = slot_time_feature_ids();
    let bank =
        bank_for_activations(&[(reduce_to_200ms, 1), (reduce_to_350ms, SLOTS_PER_EPOCH + 1)]);
    assert_eq!(
        bank.slot_params_at_slot(SLOTS_PER_EPOCH - 1),
        LEGACY_SLOT_PARAMS
    );
    assert_eq!(bank.slot_params_at_slot(SLOTS_PER_EPOCH), SLOT_PARAMS_200MS);
    assert_eq!(
        bank.slot_params_at_slot(SLOTS_PER_EPOCH * 2),
        SLOT_PARAMS_200MS
    );
    assert_eq!(
        bank.slot_range_duration_in_years(0, SLOTS_PER_EPOCH * 3)
            .to_bits(),
        (SLOTS_PER_EPOCH as f64 / LEGACY_SLOT_PARAMS.slots_per_year()
            + (SLOTS_PER_EPOCH * 2) as f64 / SLOT_PARAMS_200MS.slots_per_year())
        .to_bits()
    );
    assert_eq!(
        bank.slot_range_duration_nanos(0, SLOTS_PER_EPOCH * 3 - 1),
        u128::from(SLOTS_PER_EPOCH) * LEGACY_SLOT_PARAMS.ns_per_slot()
            + u128::from(SLOTS_PER_EPOCH * 2) * SLOT_PARAMS_200MS.ns_per_slot()
    );
}
