### Title
Signer tenure-reorg gate can be bypassed via height-range block counting instead of an actual count — (File: stacks-signer/src/signerdb.rs)

### Summary
`SignerDb::get_globally_accepted_block_count_in_tenure` approximates "how many blocks were globally accepted in a tenure" using `MAX(stacks_height) - MIN(stacks_height) + 1` rather than `COUNT(*)`. This value gates `SortitionData::check_parent_tenure_choice` in `stacks-signer/src/chainstate/mod.rs`, which refuses to let a miner reorg a tenure once more than one block has been globally accepted in it. Because the guard is a height-range computation rather than a distinct-block count, a tenure that legitimately has two (or more) *distinct* globally-accepted block records sharing the same `stacks_height` (e.g. sibling proposals each independently observed/marked `GloballyAccepted` by this signer at different times, which the schema permits since rows are keyed by block/signature hash, not by height) collapses to a count of `1`. This causes the "more than one block already globally accepted" check to silently pass when it should fail, letting the reorg-protection equality be broken by an attacker-controlled miner who arranges an alternate tenure history.

### Finding Description
`get_globally_accepted_block_count_in_tenure`: [1](#0-0) 
computes the count as a height span rather than a row count. This function feeds directly into the reorg-permission check: [2](#0-1) 
where `globally_accepted_blocks > 1` is the sole hard-stop that prevents a miner from reorging a tenure that already has substantial global commitment. If this check is bypassed, the function instead falls into the timing-based leniency path (`checked_proposal_timing`), which can further allow the reorg to be marked `superseded_tenures` and permitted: [3](#0-2) 

The `blocks` table is not constrained to one row per `stacks_height` per tenure — rows are distinguished by signature/block hash, and `mark_globally_accepted()` can be invoked independently on more than one distinct proposal object that happens to carry the same `stacks_height` value (this occurs naturally under a Bitcoin/Stacks fork where two different candidate blocks are each proposed at the same block height in the same tenure and this signer, at different times, observes the network's 70% threshold being met for each in turn, e.g. following a local reprocessing of stale sortition/tenure state). In that scenario:
- Actual distinct globally-accepted blocks in the tenure: 2 (different content, same height).
- `MAX(stacks_height) - MIN(stacks_height) + 1` = 1 (because both share the same height value).

The equality being broken is: *"count of globally-accepted blocks in the tenure `<= 1`"* — the intended invariant used to gate whether a competing miner may safely discard that tenure's history. The height-range formula produces `1` even though the true count is `>= 2`, causing the code to treat a heavily-committed tenure as lightly-committed.

### Impact Explanation
This directly affects the equality this task is scoped to check: "a tenure not descending from its sortition" being wrongly validated. A single signer that is fooled by this miscount will sign a block proposal that illegitimately reorgs a tenure it should have rejected. Because each signer runs this check independently against its own local `SignerDb` state, different signers can observe different sets of block proposals/timestamps for the same tenure — meaning some signers (those whose local DB happens to have two rows at the same height) will erroneously permit the reorg while others (with a clean, gap-free height sequence) will correctly reject it. This produces exactly the "temporary tip disagreement" / "minority-triggerable... validation divergence" category: a subset of signers can be induced to sign a fork that the rest of the signer set would refuse, undermining the reorg-safety guarantee that is supposed to require unanimous rejection once a tenure has produced more than one globally accepted block.

### Likelihood Explanation
Triggering the divergence requires a miner (an unprivileged, minority actor — no majority stake or admin key needed) to produce a burnchain fork where a tenure has two distinct block proposals that reach global acceptance at the same `stacks_height` from the perspective of at least one signer's local database — a scenario plausible during any burnchain reorg or block-replacement race, which the codebase's own reorg-handling logic (`record_superseded_tenure`, `mark_tenure_superseded`) acknowledges as a normal operational condition. No cryptographic or majority-controlled action is required; only the natural occurrence of duplicate-height globally-accepted rows in a single signer's database is needed to defeat that signer's check.

### Recommendation
Change `get_globally_accepted_block_count_in_tenure` to use `COUNT(*)` (or `COUNT(DISTINCT signer_signature_hash)`) instead of the `MAX - MIN + 1` height-range approximation, so the guard in `check_parent_tenure_choice` reflects the true number of distinct globally-accepted blocks rather than assuming a contiguous, gap-free, unique-per-height sequence.

### Proof of Concept
1. In a signer's local `SignerDb`, insert two distinct block proposals for tenure `T` (different `signer_signature_hash`/content) both with `stacks_height = N`, and call `mark_globally_accepted()` on both (representing two separate global-acceptance observations the signer made over time for competing block proposals at the same height, e.g. across a reprocessed sortition view).
2. Call `get_globally_accepted_block_count_in_tenure(T)` — observe it returns `1` (`MAX(N) - MIN(N) + 1`), despite two distinct globally-accepted rows existing (compare with the existing test `check_globally_signed_block_count` at [4](#0-3)  which only exercises the *contiguous, gap-free* case and never exercises the duplicate-height case).
3. Present a competing tenure-change block whose `prev_tenure_consensus_hash` reorgs `T`; `check_parent_tenure_choice` proceeds past the `globally_accepted_blocks > 1` guard (since it evaluates to `false`), and — depending on timing — may mark `T` as superseded and permit the reorg, even though `T` genuinely had two globally-accepted (albeit same-height) blocks.

    /// Return the count of globally accepted blocks in a tenure (identified by its consensus hash)
    pub fn get_globally_accepted_block_count_in_tenure(
        &self,
        tenure: &ConsensusHash,
    ) -> Result<u64, DBError> {
        let query = "SELECT COALESCE((MAX(stacks_height) - MIN(stacks_height) + 1), 0) AS block_count FROM blocks WHERE consensus_hash = ?1 AND state = ?2";
        let args = params![tenure, &BlockState::GloballyAccepted.to_string()];
        let block_count_opt: Option<u64> = query_row(&self.db, query, args)?;
        match block_count_opt {
            Some(block_count) => Ok(block_count),
            None => Ok(0),
        }
    }

    fn check_globally_signed_block_count() {
        let db_path = tmp_db_path();
        let consensus_hash_1 = ConsensusHash([0x01; 20]);
        let mut db = SignerDb::new(db_path).expect("Failed to create signer db");
        let (mut block_info, _) = create_block_override(|b| {
            b.block.header.consensus_hash = consensus_hash_1.clone();
        });

        assert!(matches!(
            db.get_globally_accepted_block_count_in_tenure(&consensus_hash_1)
                .unwrap(),
            0
        ));

        // locally accepted still returns 0
        block_info.mark_locally_accepted(false).unwrap();
        block_info.block.header.chain_length = 1;
        db.insert_block(&block_info).unwrap();

        assert_eq!(
            db.get_globally_accepted_block_count_in_tenure(&consensus_hash_1)
                .unwrap(),
            0
        );

        block_info.mark_globally_accepted().unwrap();
        block_info.block.header.chain_length = 2;
        db.insert_block(&block_info).unwrap();

        block_info.block.header.chain_length = 3;
        db.insert_block(&block_info).unwrap();

        assert_eq!(
            db.get_globally_accepted_block_count_in_tenure(&consensus_hash_1)
                .unwrap(),
            2
        );

        // add an unsigned block
        block_info.signed_group = None;
        block_info.block.header.chain_length = 4;
        db.insert_block(&block_info).unwrap();

        assert_eq!(
            db.get_globally_accepted_block_count_in_tenure(&consensus_hash_1)
                .unwrap(),
            3
        );

        // add a locally signed block
        block_info.state = BlockState::LocallyAccepted;
        block_info.block.header.chain_length = 5;
