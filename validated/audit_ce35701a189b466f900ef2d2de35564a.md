### Title
Module-driven PRC20→WPC auto-swaps use a single-block spot quote with fixed 5% slippage, enabling sandwich extraction of user gas-abstraction funds - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
Every path where `x/uexecutor` swaps a user's deposited PRC20 for WPC (native PC) — inbound GAS execution, inbound GAS_AND_PAYLOAD execution, and outbound gas-refund — derives `minPCOut` from `GetSwapQuote`, a single, un-TWAP'd `QuoterV2.quoteExactInputSingle` spot read taken in the same execution as the swap, discounted by a hardcoded 5%. Because the quote source is a live on-chain AMM pool that any unprivileged user can trade against, an attacker can push the pool price against the pending swap immediately before it lands and reverse it immediately after, capturing the difference between the true price and the artificially moved price within the 5% tolerance — a textbook sandwich, structurally identical to the reported `buy_P()`/`sell_P()` slippage bug.

### Finding Description
`GetSwapQuote` calls the Uniswap V3 `QuoterV2` contract for a fresh `amountOut` immediately before the swap executes: [1](#0-0) 

That quote is then discounted by a flat, non-configurable 5% to form `minPCOut`, in three independent call sites:
- Inbound `GAS` execution: [2](#0-1) 
- Inbound `GAS_AND_PAYLOAD` execution: [3](#0-2) 
- Outbound unused-gas refund (swap leg): [4](#0-3) 

The resulting `minPCOut` is passed straight into `DerivedEVMCall("depositPRC20WithAutoSwap", ...)` / `refundUnusedGas`, which execute the real on-chain swap as a module-signed transaction: [5](#0-4) 

None of these three call sites use a time-weighted average price, an external price oracle, or any manipulation-resistant reference value — the "protection" is purely a percentage of a number the attacker can move in the same block window the swap will land in. This is the same root cause the external report flags in `LiquidityFundsManage.sol`: computing a min-out from a spot AMM read and applying slippage to that manipulated read instead of to a manipulation-resistant reference.

Trigger timing is attacker-controllable because inbound execution is driven directly by the depositor's own action: a user (who may itself be, or collude with, the attacker) deposits on the source chain, Universal Validators vote the inbound to quorum, and `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` run inside the finalizing `MsgVoteInbound` transaction — the attacker knows exactly which block/mempool window the swap will execute in and can bracket it with buy/sell transactions against the same WPC/PRC20 pool on Push Chain's own EVM, no validator or TSS collusion required.

### Impact Explanation
A successful sandwich extracts value from the swap that would otherwise flow to (a) the depositing user, whose minted native PC balance from `depositPRC20WithAutoSwap` is reduced, or (b) the protocol/refund recipient in the gas-refund path. This is a real-fund loss for an unprivileged user's gas-abstraction deposit, reachable purely through ordinary token trading on the pool referenced by `UniversalCore`, matching "corruption of PRC20 or native asset accounting" / "refund accounting" and unauthorized value drain from user-controlled funds in the in-scope impact list.

### Likelihood Explanation
No privileged role is required: the attacker only needs (1) enough capital to move the WPC/PRC20 pool briefly, and (2) visibility into pending `MsgVoteInbound` transactions in the Push Chain mempool (or knowledge of their own deposit's execution timing if they are the depositor). Since Push Chain's finalizing inbound votes are ordinary user-reachable transactions and pool liquidity is expected to be modest for newly bridged PRC20 assets, this is practically exploitable, though bounded by the fixed 5% slippage ceiling per swap.

### Recommendation
Replace the single-block `QuoterV2` spot quote with a manipulation-resistant reference (e.g., a TWAP over several blocks, or an external price oracle) when computing `minPCOut`, and/or make the slippage tolerance configurable and tightened based on pool liquidity depth. Consider also capping the trade size relative to observed pool liquidity, and emitting an event so operators can detect abnormal execution prices and pause the swap route if manipulation is suspected.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` that will bring an inbound GAS/GAS_AND_PAYLOAD deposit for chain X to quorum (or triggers their own inbound deposit).
2. Immediately before/alongside that transaction, attacker submits a large trade against the WPC/`prc20AddressHex` Uniswap V3 pool that depresses the PRC20→WPC price.
3. The finalizing `MsgVoteInbound` executes `ExecuteInboundGas`, which calls `GetSwapQuote` (reflecting the manipulated price) and computes `minPCOut = quote * 95 / 100` at `x/uexecutor/keeper/execute_inbound_gas.go:142-146`, then `CallPRC20DepositAutoSwap` executes at the depressed rate — within the 5% band, so it does not revert.
4. Attacker immediately reverses their trade, restoring the pool price and capturing the extracted value, while the depositing user receives less native PC than the true market rate would have produced.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
