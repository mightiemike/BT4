### Title
Per-IP-only, in-memory, restart-volatile rate limiting on POST /sessions with no account-level lockout allows distributed credential-stuffing - (File: core/web/router.go)

### Summary
`sessionRoutes` protects `POST /sessions` only with a per-client-IP, in-process token-bucket built via `memory.NewStore()` [1](#0-0) , and the underlying account/password check in `orm.CreateSession` never tracks failed attempts or applies any account-level lockout [2](#0-1) . Because the limiter state is keyed purely by remote IP and lives only in process memory, an attacker who can vary source IPs (or trigger a node restart) can perform effectively unbounded login attempts against any target email.

### Finding Description
`NewRouter` explicitly disables trust of forwarded-IP headers (`engine.RemoteIPHeaders = nil`) so the limiter key is `gin`'s resolved `RemoteIP` (the real TCP peer address), which prevents header-spoofing bypass [3](#0-2) . `sessionRoutes` wraps `unauth.POST("/sessions", sc.Create)` with `rateLimiter(rl.UnauthenticatedPeriod(), rl.Unauthenticated())`, defaulting to 5 requests per 20 seconds per IP [1](#0-0) [4](#0-3) . The `rateLimiter` helper backs this with `memory.NewStore()`, an in-process map with no persistence [5](#0-4) .

Tracing the call path `POST /sessions` -> `rateLimiter` mgin middleware -> `SessionsController.Create` -> `AuthenticationProvider().CreateUser session (localauth.orm.CreateSession)` [2](#0-1) , there is no code anywhere that records failed attempts per account/email, no counter incremented on `AuthLoginFailedEmail`/`AuthLoginFailedPassword` audit events beyond logging, and no cross-request state keyed by email. The only throttling control is the per-IP bucket. Consequently:
- An attacker distributing requests across many source IPs (e.g., a botnet, cloud IP pool, or IPv6 rotation) faces only a 5-requests/20s cap *per IP*, giving effectively unbounded aggregate throughput against a fixed target account.
- A node restart/redeploy resets the in-memory `limiter.Rate` store entirely, instantly clearing any accumulated throttling state for every IP.

This is confirmed by the existing test `TestSessions_RateLimited`, which only asserts single-IP throttling (5 failed attempts from one client trigger a 429), and does not test or assert any account-level protection across IPs [6](#0-5) .

### Impact Explanation
No account-level or global brute-force protection exists beyond bcrypt's inherent slow-hash cost (`CheckPasswordHash`) and MFA (WebAuthn) if enabled per-user. For accounts without WebAuthn enrolled, an attacker with distributed IP resources can conduct high-volume, low-detection credential-stuffing/brute-force against the local-auth login endpoint, potentially leading to account/session takeover and subsequent API token or job/bridge configuration compromise on the node — matching a "credential compromise leading to session/API token theft" impact class.

### Likelihood Explanation
Feasibility is real but requires nontrivial attacker resources: many source IPs (botnet/proxy pool) or repeated ability to trigger app restarts. Given cheap access to IP pools (cloud instances, residential proxy services), the precondition is realistic for a motivated attacker targeting an internet-exposed Chainlink node with local auth and no MFA. It does not require any privilege, leaked keys, or insider access — it's reachable purely via the public unauthenticated `/sessions` endpoint.

### Recommendation
Add account-scoped (email-keyed) failed-login tracking and lockout/backoff in `core/sessions/localauth/orm.go`'s `CreateSession` (e.g., persisted failed-attempt counters with exponential backoff or temporary lockout after N failures within a window), independent of client IP. Additionally, consider backing the rate limiter with a persistent/shared store (e.g., database or Redis) instead of `memory.NewStore()` so state survives restarts, and consider stacking a global (not just per-IP) unauthenticated rate limit on `/sessions`.

### Proof of Concept
Integration test plan (extending `core/web/sessions_controller_test.go` / `core/web/router_test.go`):
1. Create a test user via `AuthenticationProvider().CreateUser`.
2. Simulate N (e.g., 50) distinct source IPs against `POST /sessions` with wrong passwords for that user's email, using `httptest.NewServer` and a custom `http.Client`/`net.Dialer` or `httptest` request with different `RemoteAddr` values (bypassing IP-based limiter since each IP has its own bucket).
3. Assert that despite exceeding `Unauthenticated` (5) attempts per IP cumulatively (e.g., 5 attempts × 50 IPs = 250 total attempts against one account), no 429/lockout is ever returned for the *account*, and login attempts keep returning `401` rather than being blocked — demonstrating the absence of account-level lockout.
4. Optionally simulate a limiter-store reset by restarting `web.Router`/re-instantiating `rateLimiter` mid-test and show the per-IP bucket resets to full allowance, enabling continued attempts from the same IP.

```go
func rateLimiter(period time.Duration, limit int64) gin.HandlerFunc {
	store := memory.NewStore()
	rate := limiter.Rate{
		Period: period,
		Limit:  limit,
	}
	return mgin.NewMiddleware(limiter.New(store, rate))
}
```

```go
func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}
```

```go
func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}
```

```go
func TestSessions_RateLimited(t *testing.T) {
	t.Parallel()

	ctx := t.Context()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(ctx))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	client := clhttptest.NewTestLocalOnlyHTTPClient()
	input := `{"email":"brute@force.com", "password": "wrongpassword"}`

	for range 5 {
		request, err := http.NewRequestWithContext(ctx, "POST", ts.URL+"/sessions", bytes.NewBufferString(input))
		require.NoError(t, err)

		resp, err := client.Do(request)
		require.NoError(t, err)
		assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
	}

	request, err := http.NewRequestWithContext(ctx, "POST", ts.URL+"/sessions", bytes.NewBufferString(input))
	require.NoError(t, err)

	resp, err := client.Do(request)
	require.NoError(t, err)
	assert.Equal(t, 429, resp.StatusCode)
}
```
