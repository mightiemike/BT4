### Title
Starknet OS `execute_replace_class` syscall omits declared-class validation present in the Blockifier equivalent, enabling divergence/replacement with an undeclared class hash - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall (`execute_replace_class`) writes an attacker/contract-controlled `class_hash` into `contract_state_changes` without first checking that the class is actually declared. The equivalent Rust `blockifier` execution path performs this check explicitly. This is directly analogous to the ImageMagick `-concatenate` bug class: an operation is missing an authorization/validity check that its sibling operations enforce, letting a caller perform a state mutation (writing to a resource — here, the class table entry for a contract address) that should have been disallowed.

### Finding Description
`execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo:881-920` contains: [1](#0-0) 

with the explicit marker comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` immediately before it unconditionally builds a new `StateEntry` with the caller-supplied `class_hash` and commits it into `contract_state_changes` via `dict_update`. No lookup against declared classes (Sierra/CASM/deprecated class tables) is performed anywhere in this function.

Contrast this with the reference (blockifier / native Rust) implementation of the same syscall: [2](#0-1) 
which explicitly comments "Ensure the class is declared (by reading it)" and calls `syscall_handler.state.get_compiled_class(request.class_hash)?` before `set_class_hash_at`. Blockifier's test suite confirms this is a hard requirement, rejecting undeclared hashes with `"is not declared"`: [3](#0-2) [4](#0-3) 

The `execute_replace_class` (deprecated Cairo0 syscall path) in `deprecated_execute_syscalls.cairo` dispatches to the same instrumented path via `REPLACE_CLASS_SELECTOR` at line 676-687, and both Cairo0 and Cairo1 syscall dispatch tables route to `execute_replace_class` in `syscall_impls.cairo`, meaning both syscall variants share this gap.

### Impact Explanation
The Starknet OS is the program whose execution trace is proven and is used to independently re-derive/verify the state transition (including in `starknet_transaction_prover` / re-execution flows referenced in `crates/starknet_os_flow_tests`). If the OS accepts a `replace_class` syscall with an undeclared class hash where the blockifier (the sequencer's actual execution engine used to build/order/execute the block) rejects it, this creates a root-cause discrepancy between what the sequencer executes/commits and what the OS proves as valid, or — if the OS is used for re-execution/validation of externally supplied blocks — allows a state transition to be accepted by the OS that should have been rejected as invalid (an unauthorized state mutation: setting a contract's class pointer to a hash with no corresponding declared class). This falls into the "wrong committed root / honest-node divergence" and "Starknet OS re-execution" categories explicitly in scope, since the artifact of `contract_state_changes` feeds directly into `compute_class_commitment`/`hash_class_changes` used for the class/contract Patricia tree commitment (`crates/apollo_starknet_os_program/.../state/commitment.cairo:255-292`), and ultimately into the state root computed by the OS.

### Likelihood Explanation
Any account/contract can trigger `replace_class_syscall(class_hash)` directly from a single transaction with an arbitrary (undeclared) `class_hash`, as demonstrated by the Cairo1 test contract's `test_replace_class` function: [5](#0-4) 
No special privileges are required — this is reachable by an unprivileged transaction sender.

### Recommendation
Add the missing declared-class check to `execute_replace_class` in `syscall_impls.cairo`, mirroring the blockifier's behavior: before constructing/committing the new `StateEntry`, verify (via a hint/lookup against the OS's declared classes/compiled-class facts, analogous to `get_compiled_class`) that `class_hash` corresponds to a declared class, and abort/fail the syscall (propagating a revert as blockifier does) if it is not declared.

### Proof of Concept
Not independently executable from the index alone (Cairo/STARK OS execution requires the full prover/runner harness), but the code-level PoC is:
1. Deploy a contract based on `TestContract` (Cairo1) as in `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo`.
2. Invoke `test_replace_class(class_hash)` with an arbitrary, never-declared `class_hash` (e.g., `felt!(1234_u16)` as used in blockifier's own negative test `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
3. In the blockifier execution path this reverts with `"is not declared"`. Running the same transaction through the Starknet OS program (`execute_replace_class` in `syscall_impls.cairo`) does not perform this check and would set `contract_state_changes[contract_address].class_hash = 1234` unconditionally, producing a divergent outcome between the two execution engines for the same transaction.

**Uncertainty note**: I was unable to fully trace whether some later stage of OS output validation (outside of what was retrieved, e.g. a final "all contract addresses have valid class hash" pass) implicitly rejects state diffs containing undeclared class hashes before the state root is finalized. The `compute_class_commitment`/`hash_class_changes` code reviewed only hashes class-hash entries for the class tree, not the *contract* tree, and I found no explicit undeclared-class check downstream of `execute_replace_class` for the *contract* state entry within the files inspected. A background engineer with access to the complete `commitment.cairo` and `os.cairo` main flow should confirm whether any late-stage check exists that would mitigate this before treating the finding as fully unmitigated.
