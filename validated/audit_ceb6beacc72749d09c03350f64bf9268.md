### Title
Global-rejected requests still consume the shared per-endpoint QPS token bucket, enabling cross-tenant DoS - ([File: framework/src/main/java/org/tron/core/services/http/RateLimiterServlet.java])

### Summary
`RateLimiterServlet.service` calls `rateLimiter.acquirePermit(runtimeData)` (per-endpoint limiter, shared across all callers of that servlet class) before calling `GlobalRateLimiter.acquirePermit(runtimeData)` (per-IP/global limiter). When the per-endpoint check succeeds but the global check subsequently fails, the request is rejected, but for `QpsRateLimiterAdapter`/`DefaultBaseQqsAdapter`-backed endpoints (Guava `RateLimiter`-based, non-releasable) the already-consumed per-endpoint token is never refunded. This lets a single attacker IP burn through the shared per-endpoint QPS budget for other legitimate IPs even while its own requests are being denied by the global per-IP limiter.

### Finding Description
In `RateLimiterServlet.service`:
```
boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);
``` [1](#0-0) 

The per-endpoint `IRateLimiter` for a servlet like `GetBurnTrxServlet` is registered once, keyed only by servlet class name in `RateLimiterContainer` — i.e. shared across *all* client IPs hitting that endpoint, not per-caller. [2](#0-1) 

For the default/QPS-based adapters (`QpsRateLimiterAdapter`, `DefaultBaseQqsAdapter`), `acquirePermit` delegates to a Guava `RateLimiter.tryAcquire()`/`acquire()` token bucket, which is not restorable — there is no "give back the token" API. [3](#0-2) [4](#0-3) 

The `finally` block only calls `release()` when `rateLimiter instanceof IPreemptibleRateLimiter`:
```
if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
  ((IPreemptibleRateLimiter) rateLimiter).release();
}
``` [5](#0-4) 
`QpsRateLimiterAdapter` does not implement `IPreemptibleRateLimiter`, so no release/refund happens for QPS-token-bucket-based endpoints when the global check subsequently rejects the request.

`GlobalRateLimiter` enforces a per-IP token bucket (`loadIpLimiter`) and a global token bucket, independent of the per-endpoint limiter's state. [6](#0-5) 

Exploit flow: an attacker sends a burst of requests to a QPS-limited public endpoint (e.g. `GetBurnTrxServlet`) from a single IP, fast enough to exceed their own per-IP QPS quota in `GlobalRateLimiter`. Each such request first successfully consumes a token from the shared per-endpoint bucket (`perEndpointAcquired = true`) and only then is rejected by `GlobalRateLimiter.acquirePermit` (`acquireResource = false`). The per-endpoint token is not refunded. Because the per-endpoint bucket is shared across all IPs, repeatedly triggering this path drains the shared endpoint budget, causing legitimate, low-rate callers from unrelated IPs to receive "lack of computing resources" (429-equivalent) errors on the same endpoint, at effectively free cost to the attacker (their own requests were going to be dropped anyway by their own IP quota).

### Impact Explanation
This is a cross-tenant denial-of-service: one unprivileged attacker IP can exhaust a rate-limited public HTTP endpoint's shared quota for all other callers, without needing to actually get any of its own requests processed, and while being throttled at the IP layer. Impact is limited to service availability degradation of specific rate-limited HTTP/gRPC endpoints (both `RateLimiterServlet` and `RateLimiterInterceptor` share this exact ordering/refund gap), not to consensus, funds, or state integrity.

### Likelihood Explanation
Highly feasible and repeatable: the attacker needs only network access to a public FullNode HTTP/gRPC endpoint that is configured with a `QpsRateLimiterAdapter`/`DefaultBaseQqsAdapter` (the default) or `IPQPSRateLimiterAdapter`, and the ability to send requests faster than their own per-IP `GlobalRateLimiter` quota. No authentication, special privileges, or races are required — a simple burst of concurrent requests suffices, and the effect is deterministic given Guava's non-refundable `RateLimiter` semantics.

### Recommendation
Reverse or decouple the check/consume ordering so shared, non-refundable per-endpoint quota is not spent for requests ultimately rejected by the global/IP limiter. Options: (1) check `GlobalRateLimiter.acquirePermit` first (before consuming per-endpoint quota) when the per-endpoint limiter is not preemptible/refundable; or (2) use a reservation-style API (e.g., `tryAcquire` peeking without committing) so the per-endpoint QPS bucket is only debited once both checks pass; or (3) make all per-endpoint adapters implement a refund/`release` capability and always release on any downstream rejection, not just for `IPreemptibleRateLimiter` instances.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/services/ratelimiter/RateLimiterOrderingLeakTest.java
public class RateLimiterOrderingLeakTest {

  @Test
  public void globallyRejectedRequestStillConsumesPerEndpointQuota() {
    // Configure a tight per-endpoint QPS bucket (e.g. qps=1) shared across all IPs.
    QpsRateLimiterAdapter perEndpoint = new QpsRateLimiterAdapter("qps=1");

    // Simulate GlobalRateLimiter per-IP bucket already exhausted for attacker IP
    // (e.g. via repeated GlobalRateLimiter.acquirePermit calls from "1.2.3.4"
    //  until GlobalRateLimiter.tryAcquire returns false for that IP).

    RuntimeData attackerReq = mockRuntimeData("1.2.3.4");

    // Step 1: attacker request passes per-endpoint check, consuming the single
    // available token from the SHARED bucket.
    boolean perEndpointAcquired = perEndpoint.acquirePermit(attackerReq);
    assertTrue(perEndpointAcquired);

    // Step 2: global limiter rejects (attacker IP already over its own quota).
    boolean globalAcquired = GlobalRateLimiter.tryAcquire(attackerReq); // assert false
    assertFalse(globalAcquired);

    // Step 3: a legitimate, different IP now tries the SAME endpoint and is
    // denied even though it never made a prior request — proving the shared
    // per-endpoint budget was consumed by a request that was ultimately rejected.
    RuntimeData legitimateReq = mockRuntimeData("9.9.9.9");
    boolean legitimatePerEndpointAcquired = perEndpoint.acquirePermit(legitimateReq);
    assertFalse(legitimatePerEndpointAcquired); // FAILS today, demonstrating the bug
  }
}
```
Expected assertion under a fix: the legitimate caller's per-endpoint acquisition should succeed (or at minimum, per-endpoint quota consumption should be conditioned on the global check also passing), proving quota accounting is consistent with acceptance.

  public static boolean tryAcquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null || !r.tryAcquire()) {
        return false;
      }
    }
    return rateLimiter.tryAcquire();
  }

  public static boolean acquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null) {
        return false;
      }
      r.acquire();
    }
    rateLimiter.acquire();
    return true;
  }

  public static boolean acquirePermit(RuntimeData runtimeData) {
    return Args.getInstance().isRateLimiterApiNonBlocking()
        ? tryAcquire(runtimeData)
        : acquire(runtimeData);
  }
