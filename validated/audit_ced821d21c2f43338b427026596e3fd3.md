### Title
`EthBlockAssembler` computes the first post-Cancun `excess_blob_gas` with hardcoded zero base fee and default `BlobParams::cancun()`, diverging from `validate_against_parent_4844` - (File: crates/ethereum/evm/src/build.rs)

### Summary
`EthBlockAssembler::assemble_block` computes the `excess_blob_gas` header field for the very first post-Cancun block using a hardcoded call with all-zero inputs and the default `alloy_eips::eip7840::BlobParams::cancun()`, instead of the chain's actual configured blob params and the parent's real `base_fee_per_gas`. The consensus validator `validate_against_parent_4844` computes the same "first post-fork" value using the *actual* parent base fee and the chain's configured `blob_params_at_timestamp`. These two computations can diverge, so a block reth builds itself can fail reth's own consensus check.

### Finding Description
In `crates/ethereum/evm/src/build.rs`: [1](#0-0) 

```rust
if self.chain_spec.is_cancun_active_at_timestamp(timestamp) {
    block_blob_gas_used = Some(*blob_gas_used);
    excess_blob_gas = if self.chain_spec.is_cancun_active_at_timestamp(parent.timestamp) {
        parent.maybe_next_block_excess_blob_gas(
            self.chain_spec.blob_params_at_timestamp(timestamp),
        )
    } else {
        // for the first post-fork block, both parent.blob_gas_used and
        // parent.excess_blob_gas are evaluated as 0
        Some(
            alloy_eips::eip7840::BlobParams::cancun()
                .next_block_excess_blob_gas_osaka(0, 0, 0),
        )
    };
}
```

For the first post-Cancun block, the assembler calls `next_block_excess_blob_gas_osaka(0, 0, 0)` on the *hardcoded default* `BlobParams::cancun()`, i.e. `excess=0`, `blob_gas_used=0`, and — critically — `base_fee_per_gas=0`, regardless of the chain's actual configured blob schedule (custom genesis chains can configure different cancun `target`/`max`/`update_fraction`, as shown by the `blob_params_from_genesis` test in `crates/chainspec/src/spec.rs`) and regardless of the parent block's real `base_fee_per_gas`.

Compare this to the canonical validator in `crates/consensus/common/src/validation.rs`: [2](#0-1) 

```rust
pub fn validate_against_parent_4844<H: BlockHeader>(
    header: &H,
    parent: &H,
    blob_params: BlobParams,
) -> Result<(), ConsensusError> {
    let parent_blob_gas_used = parent.blob_gas_used().unwrap_or(0);
    let parent_excess_blob_gas = parent.excess_blob_gas().unwrap_or(0);
    ...
    let parent_base_fee_per_gas = parent.base_fee_per_gas().unwrap_or(0);
    let expected_excess_blob_gas = blob_params.next_block_excess_blob_gas_osaka(
        parent_excess_blob_gas,
        parent_blob_gas_used,
        parent_base_fee_per_gas,
    );
    ...
}
```

Here `blob_params` is the chain's real params for the header's timestamp (passed in by the caller in `crates/ethereum/consensus/src/lib.rs`), and `parent_base_fee_per_gas` is the parent's **actual** base fee (which, on any real network, is non-zero since London activates before Cancun). The EIP-4844 spec text quoted in both files only says that `parent.blob_gas_used` and `parent.excess_blob_gas` are evaluated as `0` for the first post-fork block — it says nothing about zeroing the parent's base fee. The `_osaka` suffix on this function name indicates it also implements EIP-7918's blob-fee "reserve price" rule, which explicitly compares the blob base fee against a multiple of the execution base fee; feeding it `base_fee=0` versus the parent's real base fee can therefore produce a different result whenever that reserve-price clamp is active.

This is directly analogous to the reported `sYETIToken.buyBack` bug: a downstream value (there, `lastBuyBackPrice`; here, `excess_blob_gas`) is derived from a **hardcoded/assumed** input (there, positional array indices assuming a fixed swap path; here, hardcoded zero base fee and hardcoded default `BlobParams::cancun()`) instead of the actual runtime values used by the "correct" calculation path elsewhere in the same system, causing the two paths to silently diverge.

### Impact Explanation
This breaks the invariant that a block built by reth's own `EthBlockAssembler` must pass reth's own `validate_against_parent_4844` (and the equivalent check any spec-following client performs). If the assembler's hardcoded-zero-base-fee/default-params computation differs from the value `validate_against_parent_4844` (using the real parent base fee and configured blob params) expects, the locally built block would carry a wrong `excess_blob_gas`, causing that self-built block to be rejected by consensus validation (by reth's own node when re-validating, and by any other spec-compliant client), i.e. a valid-looking block that is actually invalid per spec — matching the "reth-built blocks rejected by other clients" / "valid chain marked invalid" impact class. This specifically manifests at Cancun-fork-activation-block assembly, and — because the underlying `next_block_excess_blob_gas_osaka` function folds in the base-fee reserve-price logic — potentially at every subsequent fork-activation boundary that this code path handles the same way.

### Likelihood Explanation
The divergence is deterministic and triggers on every chain's first post-Cancun block whenever (a) the reserve-price/base-fee-dependent branch of `next_block_excess_blob_gas_osaka` is exercised (base fee is non-zero, which is virtually always true since London predates Cancun on real chains), or (b) the chain uses custom genesis blob-schedule parameters for Cancun that differ from the hardcoded `alloy_eips::eip7840::BlobParams::cancun()` default (as demonstrated possible by the `blob_params_from_genesis` test). This requires no attacker action — it is a self-consistency bug in reth's block-building/validation pair, triggered purely by fork-timing and chain configuration.

### Recommendation
In `crates/ethereum/evm/src/build.rs`, replace the hardcoded branch with the same real inputs used by the validator: use `self.chain_spec.blob_params_at_timestamp(timestamp)` (not the default `BlobParams::cancun()`) and the parent's actual `base_fee_per_gas` (not `0`), keeping only `excess_blob_gas` and `blob_gas_used` zeroed as the spec text requires for the parent, e.g.:
```rust
self.chain_spec.blob_params_at_timestamp(timestamp)
    .next_block_excess_blob_gas_osaka(0, 0, parent.base_fee_per_gas.unwrap_or(0))
```

### Proof of Concept
1. Configure/observe a mainnet-like chain where London (base fee) is active well before Cancun, so the parent block immediately preceding the first Cancun block has a non-zero `base_fee_per_gas` (the normal case).
2. Have reth build the first post-Cancun block via `EthBlockAssembler::assemble_block`; per `build.rs:104-111` it computes `excess_blob_gas = BlobParams::cancun().next_block_excess_blob_gas_osaka(0, 0, 0)`, ignoring the parent's real base fee.
3. Run `validate_against_parent_4844` (as invoked from `crates/ethereum/consensus/src/lib.rs`) against this newly built header/parent pair; it independently recomputes the expected value as `blob_params.next_block_excess_blob_gas_osaka(0, 0, parent_base_fee_per_gas)` with the parent's real (non-zero) base fee.
4. If `next_block_excess_blob_gas_osaka`'s result depends on the `base_fee` argument (per its EIP-7918/"osaka" reserve-price semantics) or on `target`/`max`/`update_fraction` differing from the hardcoded default, the two computed values differ, and `validate_against_parent_4844` returns `ConsensusError::ExcessBlobGasDiff`, rejecting the block reth itself just built.

```rust
pub fn validate_against_parent_4844<H: BlockHeader>(
    header: &H,
    parent: &H,
    blob_params: BlobParams,
) -> Result<(), ConsensusError> {
    // From [EIP-4844](https://eips.ethereum.org/EIPS/eip-4844#header-extension):
    //
    // > For the first post-fork block, both parent.blob_gas_used and parent.excess_blob_gas
    // > are evaluated as 0.
    //
    // This means in the first post-fork block, calc_excess_blob_gas will return 0.
    let parent_blob_gas_used = parent.blob_gas_used().unwrap_or(0);
    let parent_excess_blob_gas = parent.excess_blob_gas().unwrap_or(0);

    if header.blob_gas_used().is_none() {
        return Err(ConsensusError::BlobGasUsedMissing)
    }
    let excess_blob_gas = header.excess_blob_gas().ok_or(ConsensusError::ExcessBlobGasMissing)?;

    let parent_base_fee_per_gas = parent.base_fee_per_gas().unwrap_or(0);
    let expected_excess_blob_gas = blob_params.next_block_excess_blob_gas_osaka(
        parent_excess_blob_gas,
        parent_blob_gas_used,
        parent_base_fee_per_gas,
    );
    if expected_excess_blob_gas != excess_blob_gas {
        return Err(ConsensusError::ExcessBlobGasDiff {
            diff: GotExpected { got: excess_blob_gas, expected: expected_excess_blob_gas },
            parent_excess_blob_gas,
            parent_blob_gas_used,
        })
    }
```
