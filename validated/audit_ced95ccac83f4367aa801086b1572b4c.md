### Title
Unbounded recursive bytecode-segment hashing during Sierra→CASM class hashing can stack-overflow the sequencer/gateway process - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
CVE-2017-11556 is a stack-consumption DoS caused by an unbounded-recursion function walking attacker-controlled nested input (`Parser::advanceToNextToken`). The Apollo sequencer contains an analogous unbounded-recursion function, `bytecode_hash_node`, which walks a `NestedIntList` describing the CASM bytecode's segment structure. This structure's nesting depth is derived from the shape of a user-submitted Sierra program (via `declare` transactions) and is not depth-limited anywhere before the recursive hash is computed in-process.

### Finding Description
`bytecode_hash_node` recurses once per nesting level of the `bytecode_segment_lengths: NestedIntList` field of a `CasmContractClass`: [1](#0-0) 

This is invoked from `HashableCompiledClass::hash` / `hash_inner` whenever a compiled class hash is computed: [2](#0-1) 

The entry point reachable from an untrusted, unprivileged contract declarer is `SierraCompiler::compile`, used by the gateway/class-manager flow for every `declare` transaction: the class is compiled to CASM in a resource-limited subprocess, but the resulting `CasmContractClass` is deserialized back into the main process and its recursive compiled-class hash is computed **in-process, with no recursion-depth bound**: [3](#0-2) 

The design comment in `apollo_gateway_config` explicitly notes that Sierra-to-CASM compilation is CPU/memory intensive and happens "before the transaction's signature and balance are verified," which is why a subprocess + resource limits + concurrency semaphore were added for the *compilation* step: [4](#0-3) 

However, that protection covers only the external compiler subprocess (bounded by `max_cpu_time`/`max_memory_usage`, applied via `ResourceLimits::apply`): [5](#0-4) 

The subsequent hash computation over the compiler's output (`executable_class.hash(&HashVersion::V2)`) runs back in the gateway/class-manager's own process/thread and is unbounded recursive Rust code — a sufficiently deeply nested `bytecode_segment_lengths` tree (driven by deeply/branchy Sierra control flow within the existing `max_bytecode_size` limit) can exhaust the thread's stack and crash the process with a hard stack overflow (not a catchable panic), unlike the subprocess CPU/memory limits which only bound the external compiler.

The same recursive hashing utility (`HashableCompiledClass::hash`) is reused elsewhere in the class-manager and blockifier state-reading code paths (e.g., `apollo_class_manager`, `blockifier/execution/contract_class.rs`), meaning any code path that (re)computes a compiled class hash from an attacker-supplied `NestedIntList` inherits the same risk.

### Impact Explanation
A stack overflow is a hard process abort (SIGSEGV/abort), not a recoverable Rust panic. If triggered inside the gateway process (which handles `add_tx` for all incoming transactions) or inside the batcher/class-manager during block building, it can crash the sequencer node handling the request, causing denial of service. If exploitable cheaply and repeatedly by any contract declarer, this can degrade or halt the node's ability to accept/process new transactions, satisfying the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
The path is reachable from a single, ordinary `declare` transaction submitted by any account — no special privileges required. The vulnerable hash computation runs after external-subprocess compilation succeeds and is not protected by any recursion-depth or stack-size safeguard, unlike sibling protections (`ResourceLimits`, `max_concurrent_declare_compilations`) that exist specifically because this stage was already identified as attacker-reachable and resource-sensitive. The likelihood is somewhat tempered by the fact that `bytecode_segment_lengths` nesting depth is a byproduct of Sierra-to-CASM lowering (function/branch structure), not a raw attacker-controlled field, so an attacker would need to craft a Sierra program whose compiled CASM segment tree is deep enough (within `max_bytecode_size` = 80K felts) to exhaust the thread's stack.

### Recommendation
- Convert `bytecode_hash_node` (and the equivalent OS/hint recursive segment-hash walkers) to an explicit iterative algorithm with an explicit stack/queue on the heap, removing native-stack recursion entirely.
- Alternatively, enforce and validate a maximum nesting depth for `bytecode_segment_lengths` immediately after deserializing the compiler's output, rejecting/erroring on classes whose segment tree exceeds a safe bound, mirroring the existing `max_bytecode_size` and `RecursionDepthGuard` patterns used elsewhere in the codebase.
- Ensure the hash computation for gateway/class-manager declare processing runs on a thread with a bounded, monitored stack (or is itself moved into the resource-limited subprocess) so a stack overflow cannot crash the parent sequencer process.

### Proof of Concept
1. Craft a Sierra program whose control-flow/function structure, once compiled to CASM by the (trusted) `cairo-lang-starknet-classes` compiler, produces a `bytecode_segment_lengths: NestedIntList` with very deep nesting (e.g., deeply chained nested scopes/branches), while keeping total bytecode size under `max_bytecode_size` (80 * 1024 felts, see `crates/apollo_sierra_compilation_config/src/config.rs`).
2. Submit this class via a `declare` transaction to the gateway (`GenericGateway::add_tx`), which triggers `ClassManager::add_class` → `SierraCompiler::compile`.
3. After the subprocess compiles the class (bounded by CPU/memory, unaffected by stack depth of the *hash* computation), the resulting `CasmContractClass` is hashed in-process via `executable_class.hash(&HashVersion::V2)`, invoking the recursive `bytecode_hash_node` over the deep `NestedIntList`, exhausting the calling thread's stack and crashing the process.

```rust
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
```

```rust
/// Computes the compiled class hash for a given hashable class using the specified hash algorithm.
fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}
```

```rust
pub fn compile_with_args(
    compiler_binary_path: &Path,
    contract_class: ContractClass,
    additional_args: &[&str],
    resource_limits: ResourceLimits,
) -> Result<Vec<u8>, CompilationUtilError> {
    // Create a temporary file to store the Sierra contract class.
    let serialized_contract_class = serde_json::to_string(&contract_class)?;

    let mut temp_file = NamedTempFile::new()?;
    temp_file.write_all(serialized_contract_class.as_bytes())?;
    let temp_file_path = temp_file.path().to_str().ok_or(CompilationUtilError::UnexpectedError(
        "Failed to get temporary file path".to_owned(),
    ))?;

    // Set the parameters for the compile process.
    let mut command = Command::new(compiler_binary_path.as_os_str());
    command.arg(temp_file_path).args(additional_args);

    // Apply the resource limits to the command.
    resource_limits.apply(&mut command);

    // Run the compile process.
    let compile_output = command.output()?;

    if !compile_output.status.success() {
        let stderr_output = String::from_utf8(compile_output.stderr)
            .unwrap_or_else(|_| "Failed to decode stderr output".to_string());

        let error_message = format_compiler_error(&stderr_output, &compile_output.status);
        return Err(CompilationUtilError::CompilationError(error_message));
    }
    Ok(compile_output.stdout)
}
```
