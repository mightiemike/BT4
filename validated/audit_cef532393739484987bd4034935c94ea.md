## Analog Found

This report's bug class — a "current provider" being used for an operation when the actual state has been split across multiple entities (leading to incorrect accounting) — maps directly onto how `nearcore`'s SPICE execution path handles congestion info across a dynamic-resharding boundary.

### Title
Spice congestion info is inherited unsplit by both child shards across a resharding boundary - ([File: chain/chain/src/spice/chunk_application.rs])

### Summary
In the SPICE (`protocol_feature_spice`) execution path, `build_block_congestion_info` assigns each new-epoch shard's `CongestionInfo` by looking up the *parent* shard's post-resharding `ChunkExtra`. When a shard splits into two children, **both children receive the identical, unsplit parent `CongestionInfo`** instead of a properly partitioned one. This mirrors the reported bug class: an operation (congestion/interest accounting) that assumes state lives entirely with one "current provider," when in fact it is split across multiple providers (the two child shards) after the split.

### Finding Description
`build_block_congestion_info` (`chain/chain/src/spice/chunk_application.rs:325-352`) resolves, for each shard in the *current* block's shard layout, the previous-block shard id via `get_prev_shard_id_from_prev_hash`, then copies that previous shard's `ChunkExtra::congestion_info()` verbatim: [1](#0-0) 

The code contains an explicit acknowledgment of the defect: [2](#0-1) 

This is in stark contrast to the non-spice resharding path, `ReshardingManager::get_child_congestion_info_not_finalized` (`chain/chain/src/resharding/manager.rs:327-365`), which correctly splits congestion accounting between children: the left child inherits the parent's info unchanged (it keeps all buffered/delayed receipts), while the right child's `buffered_receipts_gas`/`receipt_bytes` are explicitly reduced by the size/gas of every receipt group that stays with the left child, with an assertion that the right child ends with zero buffered gas: [3](#0-2) 

The SPICE path skips this split entirely, so `CongestionInfo.buffered_receipts_gas`/`receipt_bytes` for one or both children no longer reflects what is actually present in their respective outgoing-buffer tries.

### Impact Explanation
Downstream, this incorrect `CongestionInfo` is consumed by `ReceiptSink`/`ReceiptSinkV2` for both:
- **Transaction admission** — `CongestionControl::shard_accepts_transactions` (`core/primitives/src/congestion_info.rs:123`) decides whether to reject incoming transactions to a shard based on `congestion_level`, computed from `buffered_receipts_gas`/`receipt_bytes` (`core/primitives/src/congestion_info.rs:44`). A shard with an inflated (unsplit) congestion figure could wrongly reject valid transactions; a shard with an artificially low figure could accept transactions it should throttle.
- **Receipt forwarding/buffering invariants** — `ReceiptSinkV2WithInfo::forward_from_buffer` asserts `own_congestion_info.buffered_receipts_gas() == 0` once all buffers for a shard are drained: [4](#0-3) 
If a child shard's inherited `CongestionInfo.buffered_receipts_gas` does not match its actual (post-split) outgoing buffer contents, this invariant can be violated once the buffer that shard *actually* owns is fully drained while the (wrong) counter is still nonzero — or conversely go negative via `checked_sub` failing and surfacing `RuntimeError::UnexpectedIntegerOverflow` (`core/primitives/src/congestion_info.rs:245-321`), an inconsistent-state class of error. Either outcome is a transaction/receipt-triggered divergence between honest nodes tracking the same shard under SPICE, or a chunk-application failure (halt) for that shard.

### Likelihood Explanation
This requires (a) the `protocol_feature_spice` feature to be active and (b) a dynamic-resharding split event to occur while receipts are buffered/delayed for the splitting shard — exactly the scenario the existing non-spice resharding code was carefully written to handle (see `test-loop-tests/src/tests/resharding_v3.rs:1709-1747`, which tests analogous buffer-splitting correctness for the non-spice path). Any ordinary user submitting cross-shard receipts that land in the outgoing buffer of a shard scheduled to split can trigger the divergent accounting once resharding executes; no privileged validator action is required to *cause* the state to diverge, only for the split to occur while SPICE chunk execution assigns congestion info from an unsplit parent.

### Recommendation
- **Short term:** Either disable dynamic resharding under SPICE until congestion-info splitting is implemented for the SPICE execution path, or port `ReshardingManager::get_child_congestion_info_not_finalized`'s split logic (subtracting each child's non-retained receipt-group gas/bytes) into `build_block_congestion_info`.
- **Long term:** Add an invariant check (as already exists for the non-spice path's assertion) that fails loudly/rejects the chunk rather than silently propagating an unsplit `CongestionInfo`, and add resharding-boundary test coverage for the SPICE path analogous to `slow_test_resharding_v3_large_receipts_towards_splitted_shard`.

### Proof of Concept
1. Enable `protocol_feature_spice` and configure a shard scheduled for a dynamic-resharding split (`TrieSplit`/`ReshardingSplitShardParams`).
2. Prior to the split, submit cross-shard transactions/receipts from any account so that the parent shard accumulates non-trivial `buffered_receipts_gas`/`receipt_bytes` in its outgoing buffer destined for receivers that, post-split, are only reachable through the *left* child (i.e., receipts that should NOT be inherited by the right child).
3. Trigger the resharding boundary block. `build_block_congestion_info` (`chain/chain/src/spice/chunk_application.rs:325-352`) assigns the parent's full, unsplit `CongestionInfo` to the right child.
4. Continue applying chunks on the right child until its (empty) outgoing buffers are fully drained; observe the `assert_eq!(self.sink.own_congestion_info.buffered_receipts_gas(), 0)` in `ReceiptSinkV2WithInfo::forward_from_buffer` (`runtime/runtime/src/congestion_control.rs:281-284`) fail, or observe transaction-admission decisions (`shard_accepts_transactions`) on the right child based on gas/bytes that were never actually present in its buffers.
