### Title
Missing declared-class check in Starknet OS `execute_replace_class` allows state root divergence from Blockifier execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall does not verify that the target `class_hash` corresponds to a declared contract class before overwriting the calling contract's class hash in `contract_state_changes`. The Rust `blockifier` (the actual sequencer execution engine) enforces this check and reverts the call when the class is undeclared, but the OS re-execution path — which independently replays transactions to produce the committed state — omits it, as flagged by an explicit TODO in the code itself.

### Finding Description
In the OS's syscall handler, `execute_replace_class` reads the requested `class_hash` and immediately writes it into the contract's `StateEntry` with no verification that a compiled class exists for that hash: [1](#0-0) 

The comment on line 902, `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`, explicitly documents this gap.

By contrast, the Rust `blockifier` implementation that governs actual block production enforces the check by reading the compiled class (which errors if undeclared) before permitting the class-hash swap: [2](#0-1) 

This is exercised in tests that confirm blockifier rejects `replace_class` to an undeclared class hash with an `"is not declared"` error: [3](#0-2) 

The deprecated (Cairo0) syscall path in the OS has the analogous gap — `execute_replace_class` in `deprecated_execute_syscalls.cairo` also writes the new class hash without any declared-class check: [4](#0-3) 

while the corresponding Rust deprecated-syscall handler does perform the check: [5](#0-4) 

This is structurally the same bug class as the external report: a validation gate that is present at the "front door" (blockifier's live transaction execution / the report's `_canMintHoneyJar`-equivalent check) but missing in a downstream/parallel code path that trusts default/unchecked input (the OS's independent re-execution / the report's default-valued `slumberParties[0]`). The Starknet OS is required to be a faithful, syscall-for-syscall re-execution of what actually happened in the block during block production, per the "Starknet OS re-execution" attack surface. If the OS's semantics diverge from blockifier's for any reachable transaction path, the OS-computed state (and hence any commitment/root computed from OS execution, e.g. in `starknet_os_flow_tests` or SNOS-based proving flows) can differ from the state blockifier actually committed for the block.

### Impact Explanation
If a transaction invokes `replace_class_syscall` with an undeclared class hash, blockifier (governing the real, committed block) reverts the call — the account's class hash is left unchanged and any state changes from that call are rolled back. The OS's re-execution of the identical transaction, lacking the check, would not revert on this basis and would write the undeclared class hash into `contract_state_changes`, producing a different final state (and thus a different computed root/commitment) for the same transaction and same pre-state. This is a concrete correctness break between the two execution engines that are supposed to agree — a wrong committed root / honest-node divergence, which can block proof acceptance or corrupt the derived state commitment for the OS-driven proving pipeline (e.g., `starknet_transaction_prover`, `starknet_os_flow_tests`).

### Likelihood Explanation
Likelihood is high: `replace_class_syscall` is a standard, unprivileged syscall reachable by any contract executing an ordinary transaction; supplying an arbitrary/undeclared `class_hash` requires no special privileges, preconditions, or race — a single crafted transaction is sufficient to trigger divergent behavior between blockifier and the OS. The code explicitly acknowledges the missing check via a dated TODO, confirming it is a known, currently-unaddressed gap rather than a hypothetical.

### Recommendation
Add an explicit "declared contract class" check in the OS's `execute_replace_class` (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`), mirroring the `get_compiled_class`/`is_cairo1` checks already performed in `crates/blockifier/src/execution/syscalls/syscall_base.rs`, so that the OS reverts (or otherwise reproduces blockifier's exact failure behavior) whenever `class_hash` is not a declared class, keeping OS re-execution semantics identical to blockifier's live execution.

### Proof of Concept
1. Deploy or use an existing account/contract that can invoke `replace_class_syscall`.
2. Submit a transaction that calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared on-chain.
3. Observe blockifier's real execution: `syscall_base.rs::replace_class` calls `self.state.get_compiled_class(class_hash)?`, which returns `StateError::UndeclaredClassHash`, causing the call (and thus the class-hash write) to revert — confirmed by the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`.
4. Run the same transaction through the Starknet OS's Cairo re-execution (`execute_replace_class` in `syscall_impls.cairo`): because no declared-class check exists there, the function proceeds to `dict_update` the contract's `StateEntry.class_hash` to the undeclared hash unconditionally.
5. Compare the resulting `contract_state_changes` / state diff from steps 3 and 4: they differ for the same transaction and same pre-state, demonstrating the state-root divergence between blockifier's committed result and the OS's re-executed result.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
