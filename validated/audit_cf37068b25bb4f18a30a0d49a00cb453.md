## Title
Missing slippage protection in `ExchangeWithdrawContract` allows front-running/MEV against exchange liquidity withdrawals - (`File: actuator/src/main/java/org/tron/core/actuator/ExchangeWithdrawActuator.java`)

### Summary
Java-tron's Bancor-style token exchange (`Exchange`/`ExchangeV2` pools) exposes the same class of bug described in the Cork report: a redemption/withdrawal operation that pays out an amount computed from the *current* pool ratio, with no caller-supplied minimum-output guard, so it can be sandwiched by an unprivileged actor manipulating the pool immediately beforehand.

### Finding Description
`ExchangeTransactionContract` (a swap) is properly protected: it carries an `expected` field, and `ExchangeTransactionActuator.doValidate()` reverts if the computed `anotherTokenQuant` is less than `tokenExpected` [1](#0-0) .

`ExchangeWithdrawContract`, however, has no such field at all: `quant` is the only caller-supplied input, and `anotherTokenQuant` — the amount of the *other* pooled token the withdrawer receives — is derived purely from the current on-chain `firstTokenBalance`/`secondTokenBalance` ratio at execution time [2](#0-1) . The protobuf definition confirms there is no `expected`/minimum field on this message, unlike `ExchangeTransactionContract` which explicitly documents `expected: expected minimum number of tokens` [3](#0-2) .

Because any unprivileged account can submit an `ExchangeTransactionContract` (or `ExchangeInjectContract`) against the same `exchange_id` and have it ordered immediately before the victim's `ExchangeWithdrawContract` within the same block, the pool ratio can be pushed in a direction unfavorable to the withdrawer just before their withdrawal executes. Since `ExchangeWithdrawActuator` computes `anotherTokenQuant` strictly from the post-manipulation ratio and enforces no minimum, the withdrawer receives a manipulated, unfavorable split between the two tokens — the exact same "single-asset protected, other-asset unprotected" pattern as `redeemEarlyLv` in the Cork report (RA protected via `amountOutMin`, CT/DS not protected).

### Impact Explanation
A malicious, unprivileged actor can extract value from any account withdrawing liquidity from a `TokenID`/`TokenID` Bancor-style exchange pool by sandwiching the withdrawal with swaps that shift the balance ratio, causing the withdrawer to receive less of the "other" asset than the pool's steady-state ratio would imply — a direct asset/accounting-value-extraction impact within the "exchange/market math" component.

### Likelihood Explanation
Exploitation only requires submitting an ordinary `ExchangeTransactionContract`/`ExchangeInjectContract` transaction against a known, live exchange pool and getting it ordered ahead of a known pending `ExchangeWithdrawContract` in the same block — well within reach of any network participant able to observe the mempool, with no special privilege required.

### Recommendation
Add a caller-specified minimum-output parameter (e.g., `expected`) to `ExchangeWithdrawContract`, mirroring `ExchangeTransactionContract`, and validate `anotherTokenQuant >= expected` in `ExchangeWithdrawActuator.doValidate()`/`execute()` before mutating balances.

### Proof of Concept
1. Attacker observes a pending `ExchangeWithdrawContract` from victim on `exchange_id = X` withdrawing `tokenQuant` of `firstTokenID`.
2. Attacker submits an `ExchangeTransactionContract` on the same `exchange_id` that sells a large amount of `secondTokenID` into the pool, shifting `firstTokenBalance`/`secondTokenBalance` unfavorably for the victim, and ensures it is processed first (e.g., higher fee ordering or same-block placement).
3. Victim's `ExchangeWithdrawContract` executes against the manipulated ratio: `anotherTokenQuant = secondTokenBalance * tokenQuant / firstTokenBalance` is computed post-manipulation [4](#0-3) , with no `expected`/minimum check to reject the unfavorable outcome, unlike the analogous swap path [5](#0-4) .
4. Attacker optionally reverses their swap afterward to restore the pool and pocket the difference extracted from the victim's withdrawal.
