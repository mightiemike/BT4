### Title
Disk-index bucket "restart" reuse validates version/bucket-count/max_search but never validates the on-disk element layout size, allowing stale bytes to be reinterpreted under a mismatched `IndexEntry<T>` layout - ([File: bucket_map/src/restart.rs])

### Summary
The accounts-index disk bucket map persists a "restart" metadata file so that on validator restart it can reuse previously-written bucket index files instead of recreating them from scratch. The compatibility check performed before reuse (`Restart::get_restart_file` / `Header`) only compares a manually-maintained `HEADER_VERSION` constant, the number of buckets, and `max_search`. It never records or checks the actual per-element on-disk layout size (`elem_size`, i.e. `size_of::<IndexEntry<T>>()`), which is exactly the kind of implementation detail that changes across code versions without anyone remembering to bump `HEADER_VERSION`. If the layout backing an index-file element changes (analogous to the reported "outdated implementation" that no longer complies with the format its data was written under), `BucketStorage::load_on_restart` will mmap and reinterpret old-format bytes as if they were the current `IndexEntry<T>` layout, silently producing wrong `slot_list`/`ref_count`/pubkey data for accounts-index entries loaded from disk on restart.

### Finding Description
`bucket_map/src/restart.rs` defines the persisted compatibility `Header`: [1](#0-0) 

and validates it purely against `version`, `buckets`, and `max_search`: [2](#0-1) 

Nowhere in this check is the per-element size (`elem_size`, i.e. `size_of::<IndexEntry<T>>()`) recorded or verified. `Bucket::new` unconditionally attempts to reuse a prior on-disk file (found via the restart metadata) by calling `BucketStorage::load_on_restart` with the *current* `elem_size`: [3](#0-2) 

`BucketStorage::load_on_restart` computes the element count purely from `file_len / elem_size` and then reinterprets the mmap'd bytes as `O::new(Capacity::Actual(num_elems))`/`IndexEntry<T>` via raw pointer casts, with no assertion that the file was ever written with this exact `elem_size`/layout: [4](#0-3) [5](#0-4) 

The `IndexEntry<T>` on-disk record (pubkey, ref_count/occupied flags, slot_list value of type `T`, packed via `DataBucketRefCountOccupiedHeader`/`BucketWithHeader`) is exactly the payload used to resolve, for each pubkey, which slot/storage offset holds the authoritative account data: [6](#0-5) 

This mirrors the external report's bug class precisely: a receiver/consumer of a fixed on-disk "interface" (the byte layout of an index entry) that silently drifts from the version that produced the data it is reading, with the compatibility gate (`Header`/`HEADER_VERSION`) checking coarse, unrelated fields instead of the actual layout contract. Just as the Dapper wallet's stale `onERC721Received` signature silently mis-decoded call data instead of failing loudly, a stale/mismatched `elem_size`/`IndexEntry<T>` layout would cause `load_on_restart` to silently misinterpret bytes rather than refuse to reuse the file.

### Impact Explanation
If the size or field layout of `IndexEntry<T>` (or the generic slot-list value type `T` used by the bucket map) changes between two agave builds/releases without a corresponding bump of `HEADER_VERSION`, a validator upgraded and restarted in place will reuse its prior on-disk accounts-index bucket files under the new (incompatible) layout. Because `load_on_restart` derives element count from `file_len / elem_size` and directly casts raw bytes into the new struct shape, this produces:
- Garbage/incorrect `slot_list` entries (slot + storage offset) for pubkeys in the accounts index, causing the accounts index to resolve a pubkey to the wrong slot/offset and load a stale or wrong-version account,
- Corrupted `ref_count`/occupied bits, potentially causing entries to be treated as free/occupied incorrectly, silently dropping or duplicating accounts in the index,
- Consequently, a startup/replay accounts hash or accounts-lt-hash mismatch (or, in less lucky cases, a wrong balance silently loaded) that differs between an honest node that rebuilt its index from scratch vs. one that reused the mismatched restart files.

This falls in the allowed AccountsDB/bucket-map/snapshot-rebuild scope: it is a concrete path to stale/wrong-version account loads and hash divergence caused by the index reuse mechanism silently trusting file contents whose format contract it does not actually verify.

### Likelihood Explanation
This requires an actual, in-place layout change of `IndexEntry<T>` (or its generic parameter `T`) between the version that wrote the restart files and the version that reads them on the next restart, without a corresponding `HEADER_VERSION` bump — this is a maintenance/versioning discipline issue rather than something an external attacker can trigger directly. It is realistically triggered by validator operators restarting after certain upgrades (in-place same-machine restarts are exactly the scenario the restart-file feature is designed for), and the bug would be silent (no panic, no error) unless something downstream (index/consistency check, accounts hash verification at startup) happens to catch the resulting corruption.

### Recommendation
Include a layout/version fingerprint of `IndexEntry<T>` (e.g. `elem_size` itself, or a type-specific discriminant covering `T`) in the persisted `Header`/restart metadata, and reject/delete-and-recreate the on-disk bucket files if the fingerprint does not match at `Restart::get_restart_file` / `get_restartable_buckets` time, in addition to the existing `version`/`buckets`/`max_search` checks. This closes the gap the same way the ERC721 fix added the missing argument to make the interface robust to spec drift — by making the compatibility check cover the actual data contract being relied upon.

### Proof of Concept
Conceptual reproduction (not executable against production data, but demonstrates the code path):
1. Build the bucket map with `IndexEntry<T>` for some `T` (e.g. `T = u64`), write entries, and persist via `Restart::new`/`set_file`, matching `bucket_map/src/restart.rs:56-101`.
2. Simulate an upgrade that changes `size_of::<IndexEntry<T>>()` (e.g. change `T` to a differently-sized type) without changing `HEADER_VERSION`.
3. Restart the process; `Restart::get_restart_file` succeeds because `version`/`buckets`/`max_search` are unchanged (`bucket_map/src/restart.rs:147-177`).
4. `Bucket::new` reuses the old file and calls `BucketStorage::load_on_restart` with the new, different `elem_size` (`bucket_map/src/bucket.rs:130-148`, `bucket_map/src/bucket_storage.rs:226-253`).
5. `num_elems = file_len / new_elem_size` differs from the actual number of records written, and subsequent `get::<T>`/`get_slice` calls reinterpret misaligned byte ranges as `IndexEntry<T>`, yielding corrupted pubkeys/slot_lists/ref_counts — silently, with no error surfaced.

    pub(crate) fn get_restart_file(config: &BucketMapConfig) -> Option<Restart> {
        let path = config.restart_config_file.as_ref()?;
        let metadata = std::fs::metadata(path).ok()?;
        let file_len = metadata.len();

        let expected_len = Self::expected_len(config.max_buckets);
        if expected_len as u64 != file_len {
            // mismatched len, so ignore this file
            return None;
        }

        let file = OpenOptions::new()
            .read(true)
            .write(true)
            .create(false)
            .open(path)
            .ok()?;
        let mmap = unsafe { MmapMut::map_mut(&file).unwrap() };

        let restart = Restart { mmap };
        let header = restart.get_header();
        if header.version != HEADER_VERSION
            || header.buckets != config.max_buckets as u64
            || header.max_search != config.max_search.unwrap_or(MAX_SEARCH_DEFAULT)
        {
            // file doesn't match our current configuration, so we have to restart with fresh buckets
            return None;
        }

        Some(restart)
    }

    /// load and mmap the file that is this disk bucket if possible
    pub(crate) fn load_on_restart(
        path: PathBuf,
        elem_size: NonZeroU64,
        max_search: MaxSearch,
        stats: Arc<BucketStats>,
        count: Arc<AtomicU64>,
    ) -> Option<Self> {
        let offset = Self::get_offset_to_first_data();
        let num_elems = std::fs::metadata(&path)
            .ok()
            .map(|metadata| metadata.len().saturating_sub(offset) / elem_size)?;
        if num_elems == 0 {
            return None;
        }
        let mmap = Self::map_open_file(&path, false, 0, &stats)?;
        Some(Self {
            path,
            mmap,
            cell_size: elem_size.into(),
            count,
            stats,
            max_search,
            contents: O::new(Capacity::Actual(num_elems)),
            // since we loaded it, it persisted from last time, so we obviously want to keep it present disk.
            delete_file_on_drop: false,
        })
    }

    pub(crate) fn get_slice<T>(&self, ix: u64, len: u64, header: IncludeHeader) -> &[T] {
        // If the caller is including the header, then `len` *must* be 1
        debug_assert!(
            (header == IncludeHeader::NoHeader) || (header == IncludeHeader::Header && len == 1)
        );
        let start = self.get_start_offset(ix, header);
        let slice = {
            let size = std::mem::size_of::<T>() * len as usize;
            let slice = &self.mmap[start..];
            debug_assert!(slice.len() >= size);
            &slice[..size]
        };
        let ptr = {
            let ptr = slice.as_ptr().cast();
            debug_assert!((ptr as usize).is_multiple_of(std::mem::align_of::<T>()));
            ptr
        };
        unsafe { std::slice::from_raw_parts(ptr, len as usize) }
    }

/// header for elements in a bucket
/// needs to be multiple of size_of::<u64>()
#[derive(Copy, Clone)]
#[repr(C)]
struct DataBucketRefCountOccupiedHeader {
    /// stores `ref_count` and
    /// occupied = OCCUPIED_OCCUPIED or OCCUPIED_FREE
    packed_ref_count: PackedRefCount,
}

#[derive(Debug, PartialEq)]
pub enum OccupyIfMatches {
    /// this entry is occupied and contains the same pubkey but with a different value, so this entry could not be updated
    FoundDuplicate,
    /// this entry was free and contains this pubkey and either value matched or the value was written to match
    SuccessfulInit,
    /// this entry had a different pubkey
    PubkeyMismatch,
}

/// allocated in `contents` in a BucketStorage
#[derive(Copy, Clone)]
#[repr(C)]
pub struct BucketWithHeader {
    capacity_pow2: Capacity,
}

impl BucketOccupied for BucketWithHeader {
    fn occupy(&mut self, element: &mut [u8], ix: usize) {
        assert!(self.is_free(element, ix));
        let entry = get_mut_from_bytes::<DataBucketRefCountOccupiedHeader>(element);
        entry.packed_ref_count.set_occupied(OCCUPIED_OCCUPIED);
    }
    fn free(&mut self, element: &mut [u8], ix: usize) {
        assert!(!self.is_free(element, ix));
        let entry = get_mut_from_bytes::<DataBucketRefCountOccupiedHeader>(element);
        entry.packed_ref_count.set_occupied(OCCUPIED_FREE);
    }
    fn is_free(&self, element: &[u8], _ix: usize) -> bool {
        let entry = get_from_bytes::<DataBucketRefCountOccupiedHeader>(element);
        entry.packed_ref_count.occupied() == OCCUPIED_FREE
    }
    fn offset_to_first_data() -> usize {
        std::mem::size_of::<DataBucketRefCountOccupiedHeader>()
    }
    fn new(capacity: Capacity) -> Self {
        assert!(matches!(capacity, Capacity::Pow2(_)));
        Self {
            capacity_pow2: capacity,
        }
    }
}
