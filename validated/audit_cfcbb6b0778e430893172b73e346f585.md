Based on my review of the range-proof verification path:

**No vulnerability found for this question.**

### Analysis

The entry point for both amount and balance range checks is `confidential_range_proofs::assert_valid_range_proof`, which is the only `public(friend)` function exposed from this module — the private `verify_batch_range_proof` helper (which takes a `num_bits` parameter) is not reachable from outside the module. [1](#0-0) 

Critically, `assert_valid_range_proof` always hardcodes `num_bits` to `confidential_balance::get_chunk_size_bits()` — there is no parameter or code path that lets a caller (or attacker-controlled transaction data) override this value. It is baked into the function body, not passed in. [2](#0-1) 

Both call sites in `confidential_asset.move` — for `zkrp_amount` and `zkrp_new_balance` in `assert_valid_transfer_proof`, and for `zkrp_new_balance` in the withdrawal path — invoke this same `assert_valid_range_proof` function with no way to inject a different bit-width: [3](#0-2) [4](#0-3) 

So there is no "code path that reuses `verify_batch_range_proof` for both amount and balance checks" with attacker-controllable `num_bits`; the only entry point fixes `num_bits` internally to the module-defined chunk size (16 bits) for every call, regardless of the caller.

Additionally, even hypothetically, the underlying native `verify_batch_range_proof_internal`/Rust `verify_multiple` cryptographically binds the proof to the specific `bit_length` at verification time — supplying a mismatched `num_bits` relative to how the proof was constructed causes verification to fail (return `false`), not to accept an out-of-range value. This is consistent with the existing test `test_invalid_batch_range_proof_fails_verification` demonstrating that tampered/mismatched proofs are rejected. [5](#0-4) 

Since the `num_bits` value is not attacker-influenceable and is fixed identically for both amount and balance proofs via the single hardcoded call in `assert_valid_range_proof`, the described exploit path does not exist in this codebase.
