## Title
Spot-price swap quote with no TWAP/oracle protection allows MEV sandwich extraction on gas-deposit auto-swap and gas-refund paths - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report's core theme is that a strategy relies on values (prices/exchange rates) that are not protected against adverse movement, so ordinary/unprivileged conditions produce unfair, unrecovered losses for users. The Push Chain analog is in the GAS / GAS_AND_PAYLOAD inbound auto-swap path and the outbound gas-refund path: both fetch a Uniswap V3 `QuoterV2` spot quote and immediately execute the swap in the very same keeper call, bounding slippage to a flat 5% of that just-fetched (and therefore attacker-influenceable) quote instead of using a TWAP or external price oracle.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` for the current pool state [1](#0-0) , and immediately afterward the keeper computes `minPCOut = quote * 95 / 100` and executes the real swap via `CallPRC20DepositAutoSwap` in the GAS inbound path [2](#0-1)  and in the GAS_AND_PAYLOAD path [3](#0-2) . The same pattern is reused for excess-gas refunds via `getSwapQuoteForRefund` and `applyGasRefund` [4](#0-3) .

Because the quote and the swap execution both happen inside a single Push Chain block (triggered by an ordinary `MsgVoteInbound`/`MsgVoteOutbound` that reaches quorum), an unprivileged attacker who observes the pending vote transaction in the mempool can:
1. Front-run it with a swap against the same Uniswap V3 PRC20/WPC pool to push the price away from fair value.
2. Let the vote-triggering transaction execute — `GetSwapQuote` now reads the manipulated pool state, so `minPCOut` is derived from an already-skewed price, and the real deposit/refund swap executes at that skewed price.
3. Back-run with an opposite swap to restore the pool price, capturing the price impact as MEV profit extracted directly from the value that should have gone to the depositor/refund recipient.

The 5% slippage bound does not protect against this because it is computed *from* the manipulated quote, not from any independent reference price (no TWAP, no external oracle, no user-supplied minimum). Any pool with modest liquidity can be moved well past 5% within a single block via a flash-loan-funded swap.

### Impact Explanation
This corrupts PRC20/native asset accounting and gas-fee/refund accounting for the deposited or refunded amount: the intended recipient (a UEA-controlled depositor performing a GAS or GAS_AND_PAYLOAD inbound, or an outbound sender/fund-recipient receiving an unused-gas refund) receives materially fewer PC tokens than fair value, with the difference siphoned to the attacker. This is an unprivileged, unauthorized value transfer out of user-controlled funds through a production, user-reachable flow (ordinary inbound/outbound voting), matching the "corruption of ... gas fee accounting, refund accounting ... token mapping" allowed-impact bucket.

### Likelihood Explanation
Exploitation only requires public mempool visibility of the vote transaction and the ability to trade against the same Uniswap V3 pool used by `UniversalCore` — both are available to any unprivileged actor, with no validator/relayer/governance privilege required. Profitability depends on pool liquidity/fees vs. the notional swapped, so it is most attractive on larger deposits/refunds through thinner pools, but the underlying protection mechanism is missing regardless of amount.

### Recommendation
Do not derive slippage protection from a quote fetched in the same call that immediately executes the swap. Use a time-weighted average price (TWAP) from the pool, or a protocol-controlled/external price oracle, to compute `minPCOut`, and/or add a maximum allowed deviation between the spot price and the TWAP before allowing the auto-swap/refund to proceed (aborting or falling back to the no-swap deposit path otherwise, similar to the existing fallback logic in `applyGasRefund`).

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteInbound` (GAS/GAS_AND_PAYLOAD) or `MsgVoteOutbound` transaction that will reach quorum and trigger `ExecuteInboundGas`/`applyGasRefund`.
2. Attacker submits a higher-gas-priced swap against the relevant PRC20/WPC Uniswap V3 pool to shift its spot price unfavorably for the upcoming deposit/refund direction.
3. The validator's vote transaction executes; `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) reads the manipulated pool state, `minPCOut` is computed as 95% of that skewed quote, and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap at the bad price.
4. Attacker submits a reverse swap to restore the pool price, realizing the price-impact difference as profit while the legitimate recipient receives less PC than fair value for their deposited/refunded tokens.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
