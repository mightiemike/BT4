### Title
Free, unauthenticated on-chain account creation via gasless message whitelist bypasses authorization check — enables unbounded state-bloat DoS - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` creates a brand-new on-chain `BaseAccount` for the signer of any transaction whose message types are in the gasless whitelist (`app/txpolicy/gasless.go`), as long as it can produce a self-consistent signature over `account_number=0, sequence=0` for a fresh keypair. It does this purely by checking the transaction's *message type URLs* — it never checks whether the signer is actually authorized to send that message type (e.g., a bonded Universal Validator for `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration`). Any external actor can generate an arbitrary number of fresh keypairs, craft a syntactically valid but semantically doomed gasless message (e.g., `MsgVoteInbound` from a non-UV address), and get a new account permanently written to chain state at zero fee cost, because `DeductFeeDecorator`/`MinGasPriceDecorator` also skip cost enforcement for gasless txs [3](#0-2) [4](#0-3) .

### Finding Description
`AccountInitDecorator.AnteHandle` runs early in the Cosmos ante chain (before `SetPubKeyDecorator`, `SigVerificationDecorator`, etc.) and is gated *only* on `txpolicy.IsGaslessTx(tx)` — a pure message-type-URL check, not an authorization check [5](#0-4) . If the sole signer of that tx has no existing account, the decorator:

1. Verifies the signature is self-consistent (signed by the claimed pubkey over `account_number=0, sequence=0`) via `verifySignatureForNewAccount` [6](#0-5) .
2. Unconditionally creates and persists a new `BaseAccount` with `sequence=1` for that address [7](#0-6) .
3. Returns `ctx, nil` directly — **short-circuiting the rest of the ante chain**, meaning `next(ctx, tx, simulate)` is never called for this path.

Crucially, this authorization-free path applies to *all* gasless message types, including `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, and `MsgVoteFundMigration` [8](#0-7) . The actual authorization check for these — `IsBondedUniversalValidator` / `IsTombstonedUniversalValidator` — happens only inside the msg-server handlers (`VoteInbound`, `VoteOutbound`), i.e., *after* the ante chain has already committed the account creation to the store [9](#0-8) . Since Cosmos SDK's `runTx` commits the AnteHandler's cache-store writes before executing the message handler in its own separate cache, the account persists on-chain even though the subsequent message execution fails with "not bonded."

An attacker therefore does not need to be a Universal Validator, hold any funds, or pay any fee (`MinGasPriceDecorator` and `DeductFeeDecorator` both skip enforcement for gasless txs) — only the ability to generate a keypair and produce a signature over fixed `account_number=0`/`sequence=0` values, something trivially automatable at scale.

### Impact Explanation
This is an unauthenticated, cost-free mechanism to permanently write new account records to consensus state, without ever passing the actual application-level authorization gate the message type was meant to require. Under the "State safety" and "gasless allowlisting ... must not turn attacker input into accepted authorization" pivots, this is exactly the failure mode being probed: attacker input alone (no privileged role, no fee) is converted into an accepted, persisted on-chain state mutation. Repeated at scale (bot-generated keypairs), it grows the account/IAVL state without bound, degrading storage and sync performance for all nodes — the same "attacker-controlled artifacts pile up forever with no cost to the attacker and no cleanup path" pattern as the original CUP-share purger bug, mapped here onto Push Chain's first-use account-initialization admission path instead of the consensus-pool purger.

### Likelihood Explanation
High. No special role, stake, or existing balance is required. The only friction is producing one Ed25519/secp256k1 signature per fresh account, which is computationally trivial and can be scripted without limit. The underlying vote message will fail post-ante-chain, but that failure occurs after the account is already persisted, so it doesn't deter the attack — it can be repeated indefinitely at essentially zero cost (each attempt only consumes some block gas via `ConsumeGasForTxSizeDecorator`, but not the fee itself).

### Recommendation
`AccountInitDecorator` should not unconditionally create accounts based solely on message-type membership in the gasless whitelist. Before creating the account, it should verify that the signer is actually entitled to submit the specific gasless message (e.g., check `IsBondedUniversalValidator` for vote messages, or the UEA-ownership binding for `MsgExecutePayload`), or alternatively defer account creation until after the message-level authorization check succeeds (e.g., by having the message handlers themselves request account creation post-authorization, rather than doing it unconditionally in the ante chain).

### Proof of Concept
1. Generate a fresh secp256k1 keypair `K` with address `A` that has never had a Push Chain account and is not a registered Universal Validator.
2. Construct `MsgVoteInbound{Signer: A, Inbound: <arbitrary well-formed content>}`.
3. Build a transaction containing only this message (qualifies for `IsGaslessTx`), sign it with `K` using `account_number=0, sequence=0`.
4. Broadcast the transaction with zero fee.
5. Observe: `AccountInitDecorator` creates and commits a `BaseAccount` for `A` in the ante chain (state write persists); the subsequent `VoteInbound` message handler call fails with `"universal validator for signer ... is not bonded"`, but the account remains on-chain.
6. Repeat with new keypairs indefinitely at no fee cost, growing the account keyspace/state size without bound.

	if !ok {
		return errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	// stdSigs contains the sequence number, account number, and signatures.
	// When simulating, this would just be a 0-length slice.
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return err
	}

	signers, err := sigTx.GetSigners()
	if err != nil {
		return err
	}

	// check that signer length and signature length are the same
	if len(sigs) != len(signers) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "invalid number of signer;  expected: %d, got %d", len(signers), len(sigs))

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
