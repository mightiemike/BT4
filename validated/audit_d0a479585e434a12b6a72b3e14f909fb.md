### Title
Unsanitized `shop` param reaches `MerchantCustomAuth.authenticate` for non-embedded apps, enabling Admin API token exfiltration via SSRF - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts])

### Summary
`validateShopAndHostParams` only calls `sanitizeShop`/`sanitizeHost` when `config.isEmbeddedApp` is true. For non-embedded custom apps (the typical `MerchantCustomAuth` deployment), the raw `shop` query parameter is read directly in `getSessionTokenContext` and passed unvalidated to `strategy.authenticate`, which for `MerchantCustomAuth` builds a session via `api.session.customAppSession(shop)` using that raw string as the API hostname together with the statically configured admin API access token.

### Finding Description
In `authenticateAdmin` (packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts), when a request has no session-token header, the code runs: [1](#0-0) 
`validateShopAndHostParams` guards shop/host sanitization entirely behind `config.isEmbeddedApp`: [2](#0-1) 
For a non-embedded app, `getSessionTokenContext` then falls into the else branch and takes `shop` straight from the URL query string with no sanitization at all: [3](#0-2) 
This unsanitized `shop` is forwarded into `strategy.authenticate(request, {session, sessionToken, shop})` at: [4](#0-3) 
`MerchantCustomAuth.authenticate` (the strategy used for non-embedded/custom apps) performs no validation of `shop` and passes it directly into `api.session.customAppSession(shop)`: [5](#0-4) 
`respondToOAuthRequests` for this strategy is a no-op, confirming custom apps have no OAuth/HMAC step that would otherwise validate the shop domain: [6](#0-5) 
`customAppSession` (in `@shopify/shopify-api`) builds a `Session` whose `shop` field is used verbatim as the hostname for subsequent Admin API/GraphQL client requests, combined with the app's statically configured `adminApiAccessToken`. Since the resulting `Session.shop` is never checked against the `*.myshopify.com` pattern (that check only happens via `sanitizeShop`, which is skipped here), an attacker can supply an arbitrary hostname in the `shop` query parameter. Any subsequent Admin API call made through `context.admin` in the loader/action will be directed to that attacker-controlled host, carrying the app's real Admin API access token in the request headers — resulting in secret disclosure to a third-party server (SSRF combined with credential exfiltration).

### Impact Explanation
An anonymous, unprivileged HTTP client can force a non-embedded/custom Shopify app to send its statically configured Admin API access token to an attacker-controlled domain, by simply requesting any admin-authenticated route with `?shop=attacker.example.com`. This is a credential/secret disclosure (the app's permanent Admin API token) plus an SSRF primitive, matching Shopify's bounty class for "leaked/stolen API credentials" and "SSRF with real consequence."

### Likelihood Explanation
Preconditions: `isEmbeddedApp: false` with the `MerchantCustomAuth` strategy — this is the standard, documented configuration for Shopify custom/merchant apps, not a misconfiguration. No secrets, privileged roles, or MITM are required; the attacker only needs to send a normal HTTP GET/POST to any app route wrapped by `authenticate.admin()` without a session-token header, supplying a crafted `shop` parameter. This is trivially repeatable and requires no timing or race conditions.

### Recommendation
Remove the `config.isEmbeddedApp` conditional gate in `validateShopAndHostParams`, or otherwise always call `api.utils.sanitizeShop` on the `shop` parameter (and enforce it matches the app's configured shop / a `*.myshopify.com` pattern) before it is used to build a session or passed to any strategy's `authenticate` method, regardless of embedded/non-embedded mode. Additionally, `MerchantCustomAuth.authenticate` should independently validate `shop` before calling `customAppSession(shop)`, since it cannot assume upstream sanitization occurred.

```typescript
export function validateShopAndHostParams(
  params: BasicParams,
  request: Request,
) {
  const {api, config, logger} = params;

  if (config.isEmbeddedApp) {
    const url = new URL(request.url);
    const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!);
    if (!shop) {
      logger.debug('Missing or invalid shop, redirecting to login path', {
        shop,
      });
      throw redirectToLoginPath(request, params);
    }

    const host = api.utils.sanitizeHost(url.searchParams.get('host')!);
    if (!host) {
      logger.debug('Invalid host, redirecting to login path', {
        shop,
        host: url.searchParams.get('host'),
      });
      throw redirectToLoginPath(request, params);
    }
  }
```
