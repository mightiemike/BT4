## Analog Found

### Title
Auto-swap deposit path derives `minPCOut` slippage protection from the same manipulable Uniswap V3 pool it swaps against, allowing an attacker to sandwich `GAS`/`GAS_AND_PAYLOAD` inbound deposits and steal user value - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/evm.go, x/uexecutor/keeper/outbound.go)

### Summary
The external report describes a classic "donation/manipulated-exchange-rate" vulnerability: a value derived from a spot, attacker-influenceable on-chain balance is used both to price a user's deposit and to define the "protection" against bad pricing, so the protection can never actually catch manipulation of that same spot value. Push Chain's `uexecutor` module has a structurally identical pattern in its `GAS`/`GAS_AND_PAYLOAD` inbound auto-swap flow and in gas-refund swaps: `minPCOut` is computed from a `GetSwapQuote` call that reads the live Uniswap-V3-style pool state at execution time, immediately before performing the real swap in the same flow.

### Finding Description
When a `GAS` or `GAS_AND_PAYLOAD` inbound reaches quorum, `ExecuteInboundGas` (x/uexecutor/keeper/execute_inbound_gas.go:103-153) and `gasAndPayloadDepositAutoSwap` (x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379) both:
1. Call `GetSwapQuote` [1](#0-0)  to fetch the *current* pool price via `QuoterV2.quoteExactInputSingle` against the live Uniswap-V3-style PC/PRC20 pool.
2. Derive `minPCOut` as exactly 95% of that same live quote: [2](#0-1) 
3. Immediately execute the real swap via `CallPRC20DepositAutoSwap` using that `minPCOut` [3](#0-2) .

The same self-referential pattern is used for gas refunds in `applyGasRefund`/`getSwapQuoteForRefund`: [4](#0-3) [5](#0-4) .

Because the "slippage bound" is computed from the very pool state that an attacker can manipulate immediately beforehand (by submitting an ordinary, unprivileged EVM swap transaction against the same PC/WPC-PRC20 pool), the 5% band only protects against price movement between the quote call and the swap call within the same keeper execution — it provides no protection against pre-existing price manipulation. An attacker can:
1. Submit a large swap into the pool (before the validators' `MsgVoteInbound` transactions that trigger quorum execution land in the block, or by getting included earlier in the same block as block proposer/via normal mempool ordering), pushing the PRC20→WPC price down.
2. When quorum is reached and `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` runs, `GetSwapQuote` reads the now-manipulated price, computes `minPCOut` as 95% of that manipulated (already-bad) quote, and the auto-swap deposit executes at the bad price — this still "passes" the check because the check was built from the same distorted reference.
3. The user's deposited gas token is swapped into PC at a value far below fair market price; the underlying inbound `Amount` (attacker-uncontrollable, from the external chain) is fixed, so the resulting shortfall in PC accrues to LPs/arbitrageurs, effectively realized by the attacker reversing their pool position after the deposit executes (a sandwich).
4. The same issue applies to `applyGasRefund`'s refund-with-swap path, where excess gas refunded to users can similarly be shortchanged.

This is the on-chain analog of the reported bug class: a mutable, attacker-influenceable on-chain value (pool spot price/reserves, analogous to `balanceOf` in the LiquidStake report) is used to both price the user's operation and to derive the "protection" against bad pricing, so genuine manipulation is never caught.

### Impact Explanation
An unprivileged attacker can extract value from ordinary users' `GAS`/`GAS_AND_PAYLOAD` inbound deposits and from gas refunds by sandwiching the module's own auto-swap execution, since the `minPCOut` slippage guard is derived from the same manipulated pool state it is meant to protect against. This results in users receiving less PC (and thus less gas / less refund) than the fair-market value of their deposited/swapped assets — a partial loss/theft of user funds routed through legitimate, unprivileged transaction submission, matching the in-scope impact of "stealing ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting."

### Likelihood Explanation
The trigger requires only ordinary, permissionless EVM transactions (a swap on the PC/PRC20 pool) timed around the block(s) in which validators cast `MsgVoteInbound` votes that reach quorum for a pending `GAS`/`GAS_AND_PAYLOAD` inbound, or around outbound gas-refund execution. No validator, TSS, or admin collusion is required — this is a standard MEV/sandwich pattern applied to a module-driven swap whose own slippage bound is self-referential. Profitability depends on pool liquidity depth relative to the deposit size and the fixed 5% band, but the mechanism itself has no additional gating.

### Recommendation
Do not derive the slippage bound (`minPCOut`) solely from a spot quote fetched immediately before the swap. Instead, use a manipulation-resistant reference price (e.g., a TWAP over a meaningful window from the Uniswap V3 pool, or an off-chain/oracle-derived reference price bounded against the spot quote), and/or cap the maximum price impact the module-driven swap itself is allowed to cause. Consider also enforcing a minimum pool liquidity/TVL threshold before permitting auto-swap execution for a given PRC20, and emitting/alerting when realized slippage vs. TWAP exceeds a safety threshold so anomalous executions can be reverted or retried rather than settled at a manipulated price.

### Proof of Concept
1. Attacker identifies (or predicts) an upcoming `GAS`/`GAS_AND_PAYLOAD` inbound for a given PRC20 that will trigger `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`.
2. Attacker submits an ordinary EVM swap transaction that sells a large amount of WPC into the PRC20/WPC pool (or vice versa) to move the pool price unfavorably for the upcoming auto-swap, timed to land in the block/right before the validators' inbound-vote transaction that reaches quorum.
3. Validators' votes reach quorum; `ExecuteInboundGas` calls `k.GetSwapQuote` [6](#0-5) , which reads the now-manipulated pool price, and computes `minPCOut` as 95% of that manipulated quote [2](#0-1) .
4. `CallPRC20DepositAutoSwap` executes the deposit+swap at the manipulated price, which trivially satisfies `minPCOut` since it was derived from the same manipulated state [7](#0-6) .
5. Attacker reverses their earlier swap, extracting the price-impact profit that came at the expense of the amount of PC actually delivered to the user's UEA from their gas-token deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
}
