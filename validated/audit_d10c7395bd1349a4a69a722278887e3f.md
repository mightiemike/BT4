This confirms the design is self-consistent: `SlotCache::insert` at accounts-db/src/accounts_cache.rs:101-135 replaces any prior entry for the same `(slot, pubkey)` pair (last-write-wins, `is_new_key=false` on overwrite), so an intra-slot zero-then-nonzero write sequence collapses to a single cache entry holding the final nonzero balance — there is no possibility of two co-existing cache entries for the same pubkey/slot that could be double-counted. [1](#0-0) 

## No Vulnerability found for this question.

**Reasoning summary:**

`calculate_capitalization_at_startup_from_index` at accounts-db/src/accounts_db.rs:4736-4798 sums `storage_capitalization` over every pubkey present in `accounts_index.account_maps` (each key visited exactly once) and then applies a `cached_update` correction over `accounts_cache.cached_pubkeys()` that always subtracts the *same* `stored_lamports(pubkey)` value it added in the index walk and adds `cached_lamports` instead: [2](#0-1) 

Algebraically, for any pubkey this reduces to: if it's only in the index, contribute `stored_lamports`; if only in the cache, contribute `cached_lamports` (since `stored_lamports` on an index-miss returns `0` via `unwrap_or(0)`); if in both, the index contribution cancels and only `cached_lamports` (the newest value) survives. This holds regardless of how many intermediate zero/nonzero writes happened before the final cache write, because:

1. `accounts_cache::cached_pubkeys()` (accounts-db/src/accounts_cache.rs:432-438) is built from a per-pubkey index (`AccountsCacheIndex`) that dedups pubkeys across slots — each pubkey appears once.
2. `SlotCache::insert` (accounts-db/src/accounts_cache.rs:101-135) makes each `(slot, pubkey)` a single overwritten entry, so an attacker's zero-then-nonzero-in-one-slot pattern within `write_accounts_to_cache` (accounts-db/src/accounts_db.rs:5413-5461) simply ends with the last-written (nonzero) value in that slot's cache — no duplicate or phantom entries are created.
3. The zero-lamport "ephemeral" skip logic (`is_ancestor_zero_lamport`, accounts-db/src/accounts_db.rs:5391-5406) only prevents brand-new zero-lamport accounts from entering the cache/index at all; it never creates an extra entry that could be double-counted.

This design is exercised by existing unit tests covering exactly these zero/nonzero mixing patterns within and across slots — `test_new_zero_lamport_accounts_skipped`, `test_write_accounts_to_cache_scenarios`, `test_calculate_capitalization_simple`, `test_verify_bank_capitalization`, and `with_chained_zero_lamport_accounts` in accounts-db/src/accounts_db/tests/impl.rs and runtime/src/serde_snapshot/tests.rs — all of which assert exact capitalization equality after zero-lamport transitions. [3](#0-2) [4](#0-3) 

Additionally, this function is explicitly documented as "Only intended to be called at startup by ledger-tool or tests" and "NOT safe to call concurrently with flush operations" — it is not part of the live, per-block bank-hash computation path, so even a hypothetical bug here would not produce a consensus-relevant bank-hash mismatch during normal validation; at most it would affect an offline `calculate_capitalization_for_tests`/snapshot-restore consistency check, and no such bug was found. [5](#0-4)

fn test_new_zero_lamport_accounts_skipped() {
    let accounts_db = AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG);
    let pubkey1 = Pubkey::new_unique();
    let pubkey2 = Pubkey::new_unique();
    let pubkey3 = Pubkey::new_unique();
    let zero_account = AccountSharedData::new(0, 0, &Pubkey::default());
    let account = AccountSharedData::new(100, 0, &Pubkey::default());
    let slot = 0;
    let mut ancestors = Ancestors::from(vec![slot]);

    // 1. Insert a single zero-lamport account and verify it is not added to the index or the
    //    write cache. Since this is the first write to this slot, the slot cache should not be
    //    created.
    accounts_db.store_accounts_unfrozen(
        (slot, [(&pubkey1, &zero_account)].as_slice()),
        UpdateIndexThreadSelection::Inline,
        &ancestors,
    );
    assert!(!accounts_db.accounts_index.contains(&pubkey1));
    assert!(accounts_db.accounts_cache.slot_cache(slot).is_none());

    // 2. Insert a zero-lamport (pubkey1) together with non-zero lamport accounts
    //    (pubkey2, pubkey3) in the same slot and verify only the non-zero lamport pubkeys are
    //    stored.
    accounts_db.store_accounts_unfrozen(
        (
            slot,
            [
                (&pubkey1, &zero_account),
                (&pubkey2, &account),
                (&pubkey3, &account),
            ]
            .as_slice(),
        ),
        UpdateIndexThreadSelection::Inline,
        &ancestors,
    );
    assert!(!accounts_db.accounts_index.contains(&pubkey1));
    assert!(
        !accounts_db
            .accounts_cache
            .slot_cache(slot)
            .unwrap()
            .contains_key(&pubkey1)
    );
    // pubkey2 and pubkey3 are in the write cache but not the index; cache writes reach the
    // index only on flush.
    assert!(!accounts_db.accounts_index.contains(&pubkey2));
    assert!(
        accounts_db
            .accounts_cache
            .slot_cache(slot)
            .unwrap()
            .contains_key(&pubkey2)
    );
    assert!(!accounts_db.accounts_index.contains(&pubkey3));
    assert!(
        accounts_db
            .accounts_cache
            .slot_cache(slot)
            .unwrap()
            .contains_key(&pubkey3)
    );

    // 3. Insert a zero-lamport update for pubkey2, which already has a non-zero entry in the
    //    write cache. The update is stored rather than skipped, overwriting the cache entry
    //    with zero lamports.
    accounts_db.store_accounts_unfrozen(

        UpdateIndexThreadSelection::Inline,
        &ancestors,

    assert_eq!(

            .accounts_cache
            .load(slot, &pubkey2)
            .unwrap()
            .account

        0

    //    (last written as zero in step 3) are absent; only pubkey3 is in the index.
    accounts_db.add_root_and_flush_write_cache(slot);
    assert!(!accounts_db.contains(&pubkey1));
    assert!(!accounts_db.contains(&pubkey2));
    assert!(accounts_db.contains(&pubkey3));

    let slot = slot + 1;

        UpdateIndexThreadSelection::Inline,

    assert!(account_info.1.is_zero_lamport());
