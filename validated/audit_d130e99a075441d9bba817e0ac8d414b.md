## Analysis Result [1](#0-0) 

### Title
Unauthenticated free declare via the public `BOOTSTRAP` sender address bypasses fee, nonce, and signature checks - (File: `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
`AccountTransaction::execute_raw` special-cases Declare transactions whose `sender_address` equals a fixed, publicly-derivable constant (`DeclareTransaction::bootstrap_address()`), whose `nonce == 0`, and whose `charge_fee` flag is `false`. When this "bootstrap declare" condition is met, the transaction skips `__validate_declare__`, skips the nonce increment, and skips fee charging entirely — it only writes the class hash to storage. [2](#0-1) 

### Finding Description
The gating condition `is_bootstrap_declare` is:
```
sender_address == Self::bootstrap_address() && nonce == 0 && !charge_fee
``` [3](#0-2) 

All three inputs of this check are attacker-controlled or publicly known:
- `bootstrap_address()` is a hardcoded constant (`0x424f4f545354524150`, i.e. ASCII "BOOTSTRAP") computable by anyone, not a secret or privileged key. [4](#0-3) 
- `nonce == 0` is trivially satisfiable since, critically, when the bootstrap branch is taken, `check_and_increment_nonce` is never called — so the nonce for this address never advances, meaning the condition can be met repeatedly, not just once at genesis.
- `charge_fee` is computed via `enforce_fee(&tx, only_query)`, which is derived purely from the transaction's own resource bounds/max fee (as shown by the parallel test where `enforce_fee` becomes `false` simply because the sender set `max_amount: 0`): [5](#0-4) 

Because the stateless/stateful gateway path must already accept zero-resource-bound Declare transactions from this address (this is required for the legitimate bootstrap flow to work at all), any external, unprivileged transaction sender can construct a Declare V3 transaction with `sender_address = bootstrap_address()`, `nonce = 0`, and zero resource bounds. This transaction requires no valid signature (validation is skipped) and no funded balance (fee charge is skipped), yet still results in `dict_update`/`compiled_class_hashes` state changes declaring an arbitrary class: [6](#0-5) 

This is directly analogous to the Astaria bug: a code path intended to be reached only through a privileged/trusted flow (here: one-time genesis bootstrapping performed by the network operator) is instead reachable by any unprivileged transaction sender because the "authorization" check is based solely on transaction fields the sender fully controls, rather than any actual privilege check (e.g., block number == 0, a system/internal transaction flag, or an out-of-band admin signature).

### Impact Explanation
Any unprivileged party can submit unlimited Declare transactions (as long as the target class hash hasn't been declared yet) that consume sequencer CPU/compilation resources (Sierra→CASM compilation, hashing) and permanently write class declarations to state, without ever paying fees and without incrementing any nonce (so this is repeatable without any nonce-based rate limit). This is a fee/resource-accounting bypass: an attacker gets "free" declares (i.e. gets a privileged, resource-consuming action normally requiring balance/fee) with no cost — mirroring "requesting a loan without depositing collateral." This can be used to spam the network with free class declarations, undermining the declare-fee economic model and potentially exhausting compilation/bouncer resources reserved for paying users.

### Likelihood Explanation
High. The only "secret" required is a widely-visible hardcoded constant in the open-source code (`bootstrap_address()`), and the other gating conditions (zero nonce, zero resource bounds) are self-declared and don't require any privileged relationship with the sequencer operator or genesis process.

### Recommendation
Do not gate the bootstrap-declare special case purely on transaction-supplied fields (`sender_address`, `nonce`, `charge_fee`). Additionally require that the transaction only be accepted when the sequencer/OS is actually in genesis/bootstrap mode (e.g., `block_number == 0` or an explicit `is_bootstrapping` flag passed from the block builder/consensus layer, not derived from the transaction itself), or require the bootstrap declare to be an internally-injected system transaction rather than one accepted from the public mempool/gateway.

### Proof of Concept
1. Craft an `RpcTransaction::Declare` (V3) with:
   - `sender_address = ContractAddress::from(0x424f4f545354524150)` (the public "BOOTSTRAP" constant)
   - `nonce = Nonce(Felt::ZERO)`
   - `resource_bounds` set so `max_possible_fee() == 0` (as in `ValidResourceBounds::create_for_testing_no_fee_enforcement()` used by `generate_bootstrap_declare()`) [7](#0-6) 
   - An empty/default signature (no signing key needed, since `__validate_declare__` is never invoked).
2. Submit through the Gateway `add_tx`; assuming stateless/stateful validation allows zero-bound declare transactions for this flow (required for legitimate bootstrapping to function), the transaction is queued.
3. During block building, `AccountTransaction::execute_raw` detects `is_bootstrap_declare(charge_fee=false) == true`, skips validation/fee/nonce, and commits the declared class hash to state — for free, and repeatably since nonce for this address is never incremented.

**Caveat / uncertainty:** I could not fully verify the contents of `check_declare_permissions` in `crates/apollo_gateway/src/gateway.rs` (only its call site was visible in the index), which might impose an additional whitelist restricting who may submit Declare transactions. If that function specifically excludes the `bootstrap_address()` sender for external submissions (or restricts declare senders to a permission list that would exclude this constant), the bypass described above would be mitigated at the gateway layer. Confirming this requires reading the full implementation of `check_declare_permissions`, which was not available in the indexed context — starting a Devin session with full repository access would allow verifying this precisely.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

        // Do not run validate or perform any account-related actions for declare transactions that
        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),
                );
                let mut remaining_gas = 0;
                let res = tx.run_execute(state, &mut context, &mut remaining_gas)?;
                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());
