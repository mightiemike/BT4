### Title
Cost-blind global admission control lets attackers convert flat QPS tokens into disproportionate TVM CPU time - (File: `framework/src/main/java/org/tron/core/services/ratelimiter/GlobalRateLimiter.java`)

### Summary
`GlobalRateLimiter` grants exactly one token per request from a single shared `RateLimiter` (`QPS`), regardless of which endpoint is called or how much CPU/TVM work that endpoint performs. Because `triggerconstantcontract`/`estimateenergy` execute arbitrary attacker-supplied bytecode under this same flat budget as cheap read endpoints like `getnowblock`, an attacker can consume the shared admission budget almost entirely with CPU-heavy constant calls, starving other unprivileged clients of cheap-query capacity for the same token cost.

### Finding Description
Every HTTP servlet extending `RateLimiterServlet` and every gRPC method wrapped by `RateLimiterInterceptor` calls the identical static gate:
`boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);` [1](#0-0) [2](#0-1) 

`GlobalRateLimiter` itself has no concept of request weight — it holds a single static `RateLimiter rateLimiter = RateLimiter.create(QPS)` and every accepted call (`tryAcquire`/`acquire`) consumes exactly one uniform token from that shared bucket, whether the underlying handler is a trivial DB read or a full TVM execution: [3](#0-2) 

Per-endpoint limiters exist (`GlobalPreemptibleAdapter`, `QpsRateLimiterAdapter`, `IPQPSRateLimiterAdapter`), but if none is explicitly configured for an endpoint, `DefaultBaseQqsAdapter`/`QpsStrategy.DEFAULT_QPS_PARAM` applies a flat default of `qps=1000` uniformly, and by default no endpoint-specific overrides for `TriggerConstantContractServlet` / `EstimateEnergyServlet` exist in `reference.conf`'s commented-out `rate.limiter.http` / `rate.limiter.rpc` examples: [4](#0-3) 

`triggerconstantcontract` invokes the TVM (`vm.supportConstant`), and its cost model — `vm.maxEnergyLimitForConstant`, `vm.longRunningTime`, `vm.constantCallTimeoutMs` — governs only the *per-call* CPU ceiling, not the *admission* cost relative to cheap endpoints: [5](#0-4) 

Because constant calls are local-only (not broadcast, no energy/bandwidth fee charged to the caller as they would be for a real on-chain transaction), the attacker pays nothing beyond the flat rate-limiter token to trigger a potentially near-`maxEnergyLimitForConstant`/`longRunningTime`-bounded TVM execution — while a `getnowblock` caller pays the identical token for negligible CPU. Existing checks (`TransactionCapsule.validateSignature`, energy/bandwidth accounting, actuator `validate()`) do not apply here because constant calls are not broadcast transactions consuming chain resources — they bypass that economic gate entirely, and the only gate left is the flat, cost-blind `GlobalRateLimiter`.

### Impact Explanation
This is a DoS-via-RPC-API class issue: an attacker who is admitted at the same per-token rate as any other caller can bias the shared global admission budget toward CPU-heavy TVM executions, increasing aggregate CPU-time consumed per unit of the global QPS budget and degrading response latency/availability for all other unprivileged clients sharing the same `GlobalRateLimiter` instance (single fullnode/JSON-RPC/gRPC service). Impact is scoped to responsiveness degradation of the rate-limited surface, not to consensus, funds, or key material.

### Likelihood Explanation
Preconditions are minimal: mere API access (anonymous HTTP/gRPC), no signed transaction or fee required since constant calls are local execution only. An attacker can deploy or reuse an expensive-but-legal contract and repeatedly call `triggerconstantcontract`/`estimateenergy` against it at just under the effective per-endpoint and global QPS ceilings, which by default are generous (`global.qps = 50000`, `global.api.qps = 1000` per endpoint) — well within reach of a scripted, repeatable flood. No privileged role, no chain-state mutation, and no bypass of any signature/permission checks is needed, only sustained request volume against an already-permitted endpoint.

### Recommendation
Introduce cost-weighted admission in `GlobalRateLimiter` (or an additional gate ahead of it) so that expensive/TVM-executing endpoints (`triggerconstantcontract`, `estimateenergy`, `triggersmartcontract` view/pure dispatch) consume proportionally more tokens per call than cheap endpoints — e.g., by acquiring multiple permits scaled to `maxEnergyLimitForConstant`/estimated execution cost, or by enforcing a dedicated, low, non-shared QPS/concurrency ceiling (`GlobalPreemptibleAdapter` with a small `permit=N`) specifically for constant-call endpoints in the default `reference.conf`, rather than relying on operators to opt in via commented-out examples.

### Proof of Concept
```java
// Benchmark-style PoC (JUnit) demonstrating disproportionate CPU time
// consumed per accepted GlobalRateLimiter token.
@Test
public void testExpensiveConstantCallConsumesSameTokenAsCheapCall() throws Exception {
  // Simulate the shared GlobalRateLimiter budget
  resetGlobalRateLimiter(/*globalQps=*/ 5.0, /*ipQps=*/ 100.0);

  long startCheap = System.nanoTime();
  for (int i = 0; i < 5; i++) {
    Assert.assertTrue(GlobalRateLimiter.tryAcquire(runtimeDataFor("1.1.1." + i)));
    // simulate GetNowBlockServlet handler: negligible CPU
  }
  long cheapElapsed = System.nanoTime() - startCheap;

  resetGlobalRateLimiter(5.0, 100.0);
  long startExpensive = System.nanoTime();
  for (int i = 0; i < 5; i++) {
    Assert.assertTrue(GlobalRateLimiter.tryAcquire(runtimeDataFor("2.2.2." + i)));
    // simulate TriggerConstantContractServlet handler: run heavy TVM bytecode
    // (e.g. tight loop contract up to vm.maxEnergyLimitForConstant)
    runHeavyConstantContract();
  }
  long expensiveElapsed = System.nanoTime() - startExpensive;

  // Both loops consumed identical GlobalRateLimiter budget (5 tokens each),
  // yet expensiveElapsed >> cheapElapsed, proving admission cost is not
  // proportional to actual CPU/energy work performed per accepted token.
  Assert.assertTrue(expensiveElapsed > cheapElapsed * 10);
}
```
Request-level reproduction: flood `POST /wallet/triggerconstantcontract` with a contract whose bytecode approaches `vm.maxEnergyLimitForConstant`, at a rate just under the configured per-endpoint and `rate.limiter.global.qps`; observe elevated CPU/latency for concurrent `GET /wallet/getnowblock` requests admitted through the same `GlobalRateLimiter.rateLimiter` instance.

  private static RateLimiter rateLimiter = RateLimiter.create(QPS);

  public static boolean tryAcquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null || !r.tryAcquire()) {
        return false;
      }
    }
    return rateLimiter.tryAcquire();
  }

  public static boolean acquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null) {
        return false;
      }
      r.acquire();
    }
    rateLimiter.acquire();
    return true;
  }
