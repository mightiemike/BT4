## Analysis

The reported Solidity issue is about a mutable `redeemable` address pointer (`UXDController.setRedeemable`) that can be swapped underneath users, silently redirecting them to a different token contract and breaking redemption/accountability. The reachable nearcore analog is the **global contract "by account id"** mechanism, which is a first-class, unprivileged-reachable feature with the same "mutable reference resolved at call time" shape.

### Root cause

`DeployGlobalContractAction` supports `GlobalContractDeployMode::AccountId`, under which the contract is addressed not by its immutable code hash but by the deploying account's `AccountId`. The doc/schema explicitly states the intent: *"This allows the owner to update the contract for all its users."* [1](#0-0) 

Any other account can opt into this shared code via `UseGlobalContractAction { contract_identifier: GlobalContractIdentifier::AccountId(id) }`, which stores only `AccountContract::GlobalByAccount(id)` — a *name*, not a hash pin — on the consuming account. [2](#0-1) 

`action_deploy_global_contract`/`initiate_distribution` performs no ownership continuity check beyond "the transaction's receiver_id/account_id equals the identifier being written" — there is no persistent capability or key binding tying the *identifier* to a specific keypair across the lifetime of the account: [3](#0-2) 

Named NEAR accounts, once deleted via `DeleteAccountAction`, free up their `AccountId` for reuse; a subaccount `x.near` can be re-created by anyone via the open `create_account` registration flow on the `near` top-level account (standard, unprivileged, permissionless NEAR account-naming behavior), and top-level/implicit forms have their own permissionless re-creation paths. `action_create_account`/`action_delete_account` enforce no "this name was previously bound to a global contract identifier, block re-registration" invariant: [4](#0-3) [5](#0-4) 

Consequently, once an `AccountId`-mode global contract's owning account is deleted (self-deletion, e.g. via `DeleteAccountAction`, is an ordinary unprivileged operation any account can perform on itself), any unrelated unprivileged party who re-registers that same `AccountId` can issue a fresh `DeployGlobalContractAction` with `AccountId` mode and silently overwrite the code that every other account which had previously called `UseGlobalContract(AccountId(id))` continues to execute — with no notification, no re-consent, and no on-chain signal distinguishing "same trusted owner" from "new unrelated owner squatting the recycled name."

### Impact

Accounts that use a `GlobalByAccount` contract execute the referenced WASM with their own account's authority (balance, promise-issuing rights). If an attacker reclaims the identifier's `AccountId` and republishes malicious code, every consuming account's subsequent `FunctionCall` receipts silently run attacker-chosen logic in the context of the victim account, enabling unauthorized transfers of the victim's NEAR balance (e.g., issuing `promise_batch_action_transfer` sweeping funds to the attacker) — a direct "unauthorized value movement" outcome, without any privileged (governor-only) action being required, unlike the original Solidity report where at least an `onlyOwner` gate existed.

### Likelihood

Requires: (1) an `AccountId`-mode global contract deployer account to be deleted (a normal, permissionless self-action, or induced via social engineering/incident), (2) the freed name to be re-registrable (true for ordinary NEAR sub-accounts under an open-registration parent, and inherent to the permissionless account-naming model), (3) existing or new consumers still referencing that `AccountId` identifier via `UseGlobalContract`. All three are reachable purely through standard signed transactions (`DeleteAccount`, `CreateAccount`, `DeployGlobalContract`, `UseGlobalContract`) from unprivileged signers — no validator/network/operator role needed.

### Title
Global contract "by AccountId" identifier can be hijacked after the owning account is deleted and its name is re-registered - (File: runtime/runtime/src/global_contracts.rs)

### Summary
`GlobalContractDeployMode::AccountId` binds a shared, upgradable global contract's identity to a recyclable `AccountId` rather than to a persistent key or capability. Because NEAR account names can be deleted and later re-registered by an unrelated party through ordinary permissionless transactions, control over a global contract identifier can pass to an attacker without any consuming account's consent.

### Finding Description
`DeployGlobalContractAction` with `deploy_mode = AccountId` writes global contract code under `GlobalContractIdentifier::AccountId(account_id)` [1](#0-0) , and `initiate_distribution` re-derives that identifier purely from the acting `account_id` on every deploy, with no check that the caller is the "same" logical owner across account lifetimes [3](#0-2) . Consuming accounts store only `AccountContract::GlobalByAccount(id)` via `use_global_contract` [2](#0-1) , so code resolution at call time simply looks up whatever is currently published under that name. `action_delete_account` and `action_create_account` have no cross-check against previously-registered global contract identifiers [5](#0-4) [4](#0-3) , so an account name can be freed and re-registered by an unrelated party, who can then republish arbitrary code under the same `GlobalContractIdentifier::AccountId`.

### Impact Explanation
Any account that opted into `UseGlobalContract(AccountId(id))` will begin executing attacker-supplied WASM the next time the shared contract is invoked, with the full authority of the victim account (balance, ability to issue promises/transfers). This enables unauthorized movement of victim funds without requiring any privileged role, matching the "unauthorized value movement" bar.

### Likelihood Explanation
All steps are ordinary, permissionless transactions available to any signer: self-deleting an account, re-registering the freed name (feasible under the open sub-account registration model), redeploying a global contract under that name, and waiting for/soliciting `UseGlobalContract` consumers. No validator, operator, or malicious-peer capability is needed.

### Recommendation
Bind `AccountId`-mode global contract ownership to a persistent identifier that survives account deletion and cannot be silently reacquired by an unrelated party — e.g., tie the identifier to the account's original creation nonce/hash rather than the raw reusable `AccountId`, or record a permanent "burned" marker preventing re-use of an `AccountId` that ever published a global contract, or require consuming accounts to pin to a specific code hash/nonce snapshot rather than a live-updating name.

### Proof of Concept
1. Account `A` deploys `DeployGlobalContractAction{ code: benign_wasm, deploy_mode: AccountId }`, publishing under `GlobalContractIdentifier::AccountId(A)`.
2. Account `V` (victim) calls `UseGlobalContractAction{ contract_identifier: AccountId(A) }`, and subsequently calls functions on itself that execute the shared code.
3. Account `A` is deleted via `DeleteAccountAction` (ordinary self-action).
4. Attacker registers a new account also named `A` (e.g., via the open `create_account` flow on the parent TLD account).
5. Attacker issues `DeployGlobalContractAction{ code: malicious_wasm, deploy_mode: AccountId }` from the new `A`.
6. `V`'s subsequent `FunctionCall` executes `malicious_wasm` under `V`'s authority, e.g. transferring `V`'s balance to the attacker.

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())
}

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

pub(crate) fn action_create_account(
    fee_config: &RuntimeFeesConfig,
    account_creation_config: &AccountCreationConfig,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    account_id: &AccountId,
    predecessor_id: &AccountId,
    result: &mut ActionResult,
) {
    if account_id.is_top_level() {
        if account_id.len() < account_creation_config.min_allowed_top_level_account_length as usize
            && predecessor_id != &account_creation_config.registrar_account_id
        {
            // A short top-level account ID can only be created registrar account.
            result.result = Err(ActionErrorKind::CreateAccountOnlyByRegistrar {
                account_id: account_id.clone(),
                registrar_account_id: account_creation_config.registrar_account_id.clone(),
                predecessor_id: predecessor_id.clone(),
            }
            .into());
            return;
        } else {
            // OK: Valid top-level Account ID
        }
    } else if !account_id.is_sub_account_of(predecessor_id) {
        // The sub-account can only be created by its root account. E.g. `alice.near` only by `near`
        result.result = Err(ActionErrorKind::CreateAccountNotAllowed {
            account_id: account_id.clone(),
            predecessor_id: predecessor_id.clone(),
        }
        .into());
        return;
    } else {
        // OK: Valid sub-account ID by proper predecessor.
    }

    *actor_id = account_id.clone();
    *account = Some(Account::new(
        Balance::ZERO,
        Balance::ZERO,
        AccountContract::None,
        fee_config.storage_usage_config.num_bytes_account,
    ));
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
