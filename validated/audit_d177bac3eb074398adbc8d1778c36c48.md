## Finding

### Title
V2 delegation index entries can be prematurely deleted while a locked `DelegatedResourceCapsule` balance still exists - ([File: actuator/src/main/java/org/tron/core/vm/nativecontract/UnDelegateResourceProcessor.java])

### Summary
`UnDelegateResourceProcessor.execute()` (the TVM-native "undelegate resource" path) only checks the *unlocked* (`lock=false`) `DelegatedResourceCapsule` before deciding to wipe the `DelegatedResourceAccountIndexStore` `V2_FROM_PREFIX`/`V2_TO_PREFIX` entries for an owner/receiver pair. Unlike its transaction-level counterpart `UnDelegateResourceActuator`, it never checks whether a *locked* (`lock=true`) capsule for the same pair still carries a nonzero balance. Consequently the index can be emptied while the owner still holds an outstanding locked delegation.

### Finding Description
`DelegatedResourceCapsule` records are keyed by `(owner, receiver, lock)` via `DelegatedResourceCapsule.createDbKeyV2(...)`, so a single owner/receiver pair can have up to two separate balance records: one locked, one unlocked. [1](#0-0)  However, the `DelegatedResourceAccountIndexStore` V2 index keys are keyed only by `(owner, receiver)` — `V2_FROM_PREFIX+owner+receiver` and `V2_TO_PREFIX+receiver+owner` — with no lock-flag component. [2](#0-1)  This means one index entry logically represents *both* possible balance records for a pair.

The transaction-level `UnDelegateResourceActuator.execute()` correctly accounts for this: it fetches both `unlockKey` and `lockKey` capsules and only calls `unDelegateV2` (removing the index) when **both** are `null`. [3](#0-2) 

In contrast, `UnDelegateResourceProcessor.execute()` (invoked from TVM native contract calls, e.g. via `DelegateResourceProcessor`/`UnDelegateResourceProcessor` reachable from Solidity precompiles) only loads the single `lock=false` key and blanks the index the moment that unlocked balance reaches zero — it never queries or checks the `lock=true` key: [4](#0-3) 

Exploit flow (attacker controls the owner key; receiver can be attacker-controlled or any valid account):
1. Owner freezes V2 bandwidth/energy balance.
2. Owner sends a `DelegateResourceContract` with `lock=true` to receiver A (normal actuator). This creates the `(owner, A, true)` `DelegatedResourceCapsule` with a nonzero, unexpired balance and populates the V2 index via `delegateV2`. [5](#0-4) 
3. Owner (or a smart contract it controls) invokes the TVM native delegate-resource path to delegate additional balance to the same receiver A. `DelegateResourceProcessor` always writes to the `lock=false` key, and re-invokes the same `delegateV2` index update for `(owner, A)`. [6](#0-5) 
4. Owner (or the same contract) invokes the TVM native undelegate path to fully withdraw the unlocked balance created in step 3. `UnDelegateResourceProcessor.execute()` reduces the `lock=false` capsule to zero and, seeing only that capsule is empty, blanks the `V2_FROM_PREFIX`/`V2_TO_PREFIX` index entries for `(owner, A)` — **without checking the still-nonzero locked capsule from step 2**. [7](#0-6) 

Result: `DelegatedResourceAccountIndexStore.getV2Index(owner)`/`getWithPrefix()` no longer lists A as a `toAccount` (and A's index no longer lists owner as `fromAccount`), even though `DelegatedResourceStore.get(createDbKeyV2(owner, A, true))` still returns a capsule with nonzero frozen balance. This breaks the "index membership iff balance > 0" invariant.

### Impact Explanation
Wallet/API consumers calling `getDelegatedResourceAccountIndexV2` (which reads from `getV2Index`) will silently miss an active, nonzero locked delegation between owner and receiver A. This is a state-divergence bug affecting any node/API/wallet relying on this index to enumerate delegation relationships (e.g., to detect who has delegated resources to a receiver, or to whom an owner is currently delegating), producing false negatives that do not reflect actual on-chain accounting (the underlying balances, `TronPower`, and resource accounting in `AccountStore`/`DelegatedResourceStore` remain correct and unaffected — only the auxiliary index diverges).

### Likelihood Explanation
Fully attacker-reachable with no privileged access: requires only (a) an account with frozen V2 balance, (b) one ordinary `DelegateResourceContract` transaction with `lock=true`, and (c) a smart contract (deployable by anyone) that invokes the native delegate/undelegate resource precompiles to create and then fully drain an unlocked delegation to the same receiver. All steps are standard, publicly reachable operations; no timing/expiry dependency is required since the unlocked entry created via the TVM path is immediately withdrawable. This is straightforward to reproduce deterministically.

### Recommendation
In `UnDelegateResourceProcessor.execute()`, before blanking the V2 index entries, also fetch the `lock=true` `DelegatedResourceCapsule` for `(ownerAddress, receiverAddress)` and only clear the index when **both** the unlocked and locked capsules are absent/zero-balance, mirroring the logic already present in `UnDelegateResourceActuator.execute()` (lines 178-185).

### Proof of Concept
```java
// Integration-test style PoC (framework/src/test/java/org/tron/core/vm/nativecontract)

@Test
public void testTvmUndelegateLeavesGhostIndexRemoval() throws Exception {
    byte[] owner = ByteArray.fromHexString(OWNER_ADDRESS);
    byte[] receiver = ByteArray.fromHexString(RECEIVER_ADDRESS);

    // 1. Freeze V2 bandwidth balance for owner.
    freezeBandwidthForOwner();

    // 2. Owner delegates LOCKED balance to receiver via normal actuator (lock=true).
    DelegateResourceActuator lockedActuator = new DelegateResourceActuator();
    lockedActuator.setChainBaseManager(dbManager.getChainBaseManager())
        .setAny(getLockedDelegateContractForBandwidth(OWNER_ADDRESS, RECEIVER_ADDRESS,
            1_000_000_000L, true));
    lockedActuator.validate();
    lockedActuator.execute(new TransactionResultCapsule());

    // sanity: locked capsule with nonzero balance exists
    DelegatedResourceCapsule lockedCapsule = dbManager.getDelegatedResourceStore()
        .get(DelegatedResourceCapsule.createDbKeyV2(owner, receiver, true));
    Assert.assertNotNull(lockedCapsule);
    Assert.assertTrue(lockedCapsule.getFrozenBalanceForBandwidth() > 0);

    // 3. Owner delegates UNLOCKED balance to same receiver via TVM native processor.
    DelegateResourceProcessor delegateProcessor = new DelegateResourceProcessor();
    DelegateResourceParam delegateParam = buildParam(owner, receiver, 500_000_000L, BANDWIDTH);
    Repository repo = RepositoryImpl.createRoot(dbManager.getChainBaseManager());
    delegateProcessor.validate(delegateParam, repo);
    delegateProcessor.execute(delegateParam, repo);
    repo.commit();

    // 4. Owner fully undelegates the UNLOCKED balance via TVM native processor.
    UnDelegateResourceProcessor unDelegateProcessor = new UnDelegateResourceProcessor();
    UnDelegateResourceParam unDelegateParam = buildUnDelegateParam(owner, receiver, 500_000_000L, BANDWIDTH);
    Repository repo2 = RepositoryImpl.createRoot(dbManager.getChainBaseManager());
    unDelegateProcessor.validate(unDelegateParam, repo2);
    unDelegateProcessor.execute(unDelegateParam, repo2);
    repo2.commit();

    // Assert divergence: locked balance still exists but index entry is gone.
    DelegatedResourceCapsule lockedCapsuleAfter = dbManager.getDelegatedResourceStore()
        .get(DelegatedResourceCapsule.createDbKeyV2(owner, receiver, true));
    Assert.assertNotNull(lockedCapsuleAfter);
    Assert.assertTrue(lockedCapsuleAfter.getFrozenBalanceForBandwidth() > 0);

    DelegatedResourceAccountIndexCapsule ownerIndex = dbManager
        .getDelegatedResourceAccountIndexStore().getV2Index(owner);
    // BUG: toAccountsList no longer contains receiver even though a nonzero
    // locked delegation still exists in DelegatedResourceStore.
    Assert.assertFalse(ownerIndex.getToAccountsList()
        .contains(ByteString.copyFrom(receiver))); // demonstrates the divergence
}
```
Expected (buggy) behavior: the assertion on the last line passes, proving that `getV2Index(owner)` fails to list `receiver` even though `DelegatedResourceStore` still holds a nonzero locked balance for that pair — violating the index-to-balance consistency invariant.
