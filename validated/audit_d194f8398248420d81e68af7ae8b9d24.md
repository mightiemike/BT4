### Title
Unbounded per-sender ServerRequest map growth in `server.Receive` allows single DON member to exhaust memory (DoS) - ([File: core/capabilities/remote/executable/server.go])

### Summary
`server.Receive` creates a new `ServerRequest` entry in `r.requestIDToRequest` / `r.messageIDToRequestIDsCount` for any message whose `CallerDonId` matches a *registered* workflow DON, without requiring F+1 quorum or any per-sender admission limit before allocating state. A single member of that DON can therefore submit an unbounded number of distinct `MessageId`/payload combinations to grow both maps and allocate a full `ServerRequest` object (with its own mutex and maps) per entry, all of which persist until the periodic `expireRequests()` sweep evicts them after `RequestTimeout`/`DefaultExecutableRequestTimeout`.

### Finding Description
In `Receive` [1](#0-0) , the only gating check performed before allocating a new `ServerRequest` and inserting it into `r.requestIDToRequest`/`r.messageIDToRequestIDsCount` is:

1. `GetMessageID(msg)` — validates the message id is a syntactically valid ID string, not that it's unique or rate-limited: [2](#0-1) .
2. `cfg.workflowDONs[msg.CallerDonId]` — validates the *DON* is registered, not that F+1 distinct members have actually sent the request: [3](#0-2) .

The F+1 quorum requirement (`e.minimumRequiredRequestsReceived()`) is only checked *after* the `ServerRequest` object already exists, inside `OnMessage`, and only gates whether the underlying capability is actually *executed* — not whether the bookkeeping state is allocated: [4](#0-3) .

Because `requestID := messageID + hex.EncodeToString(msgHash[:])` is derived directly from attacker-controlled `MessageId` and `Payload` [5](#0-4) , a single valid DON member can generate unlimited unique `requestID` values (unique `MessageId` or varying payload), each triggering a fresh map entry and heap-allocated `ServerRequest` (with its own `requesters`, `responseSentToRequester` maps and mutex) [6](#0-5) .

These entries are not bounded by `ServerMaxParallelRequests` — that value only bounds `r.parallelExecutor`'s concurrent goroutine slots used to run `OnMessage` [7](#0-6) , not the size of `requestIDToRequest`/`messageIDToRequestIDsCount`, which grow synchronously inside `Receive` under `receiveLock` before any task is dispatched. Cleanup only happens via `expireRequests()`, invoked on a ticker (`getServerTickerInterval`, defaulting to `RequestTimeout` or `defaultExpiryCheckInterval`), and entries are only deleted once `Evictable()` returns true — i.e., after both `RequestTimeout` and `commoncap.DefaultExecutableRequestTimeout` have elapsed [8](#0-7) , [9](#0-8) . Since a single attacker never supplies the F+1 quorum required for these entries to complete/respond, every entry they create is guaranteed to live for the full timeout window, accumulating in memory as fast as the attacker can send messages via the dispatcher.

### Impact Explanation
An attacker who is only one member of a registered workflow DON (no F+1 collusion, no elevated privilege) can flood a capability server node with unique `MessageId`/payload pairs to grow `r.requestIDToRequest` and `r.messageIDToRequestIDsCount` without bound between expiry sweeps, causing heap growth proportional to attacker-controlled message volume. This is a memory-exhaustion DoS scoped to the capability server instance (and thus DON capability execution) on the targeted node, matching a resource-exhaustion/denial-of-service bounty class impacting availability of capability execution for that DON.

### Likelihood Explanation
Highly feasible and repeatable: the attacker needs only valid dispatcher access as one member of any workflow DON registered with the target capability server (a normal, non-privileged participant), and can generate an effectively unlimited stream of distinct valid `MessageId`+payload combinations from a single identity. No signature forgery, no F+1 collusion, and no additional secrets are required — only the ability to call `Receive` repeatedly with fresh IDs, which is the expected capability-request path.

### Recommendation
Add an admission-control mechanism in `server.Receive` that is bounded independent of a single sender's request volume, e.g.:
- Cap the total number of pending (`requestIDToRequest`) entries and/or the number of pending entries per `(CallerDonId, sender)` pair, rejecting/dropping new entries beyond the cap instead of allocating unconditionally.
- Rate-limit per-sender `Receive` calls (e.g. token bucket keyed by sender peer ID) before allocating a `ServerRequest`.
- Shrink the eviction window for requests that have received fewer than F+1 distinct requesters (these can never complete) instead of waiting for the full `RequestTimeout`/`DefaultExecutableRequestTimeout`.

### Proof of Concept
Integration/load test plan (extending `server_test.go` style tests):
1. Configure a `server` with a `workflowDON` of `F=1` (needs 2 requesters) and a short `RequestTimeout`.
2. From a single registered peer identity, call `server.Receive` in a loop N times (e.g. N=100,000), each with a unique `MessageId` (e.g. `fmt.Sprintf("workflowID%d", i)+"workflowExecutionID"`) and unique payload.
3. Assert that `len(server.requestIDToRequest)` and `len(server.messageIDToRequestIDsCount)` grow linearly with N and are not bounded by any admission-control limit before the expiry ticker fires.
4. Assert that no rate-limiting or per-sender cap error is ever logged/returned, confirming unconditional acceptance and unbounded allocation from a single, non-colluding sender.

func (r *server) expireRequests() {
	r.receiveLock.Lock()
	defer r.receiveLock.Unlock()

	for requestID, executeReq := range r.requestIDToRequest {
		if executeReq.request.Expired() {
			ctx, cancelFn := r.stopCh.NewCtx()
			err := executeReq.request.Cancel(ctx, types.Error_TIMEOUT, "request expired by executable server")
			cancelFn()
			if err != nil {
				r.lggr.Errorw("failed to cancel request", "request", executeReq, "err", err)
			}
		}
		if executeReq.request.Evictable(commoncap.DefaultExecutableRequestTimeout) {
			delete(r.requestIDToRequest, requestID)
			delete(r.messageIDToRequestIDsCount, executeReq.messageID)
		}
	}
}

func (r *server) Receive(ctx context.Context, msg *types.MessageBody) {
	cfg := r.cfg.Load()
	if cfg == nil {
		r.lggr.Errorw("config not set, cannot process request")
		return
	}

	r.receiveLock.Lock()
	defer r.receiveLock.Unlock()

	switch msg.Method {
	case types.MethodExecute:
	default:
		r.lggr.Errorw("received request for unsupported method type", "method", remote.SanitizeLogString(msg.Method))
		return
	}

	messageID, err := GetMessageID(msg)
	if err != nil {
		r.lggr.Errorw("invalid message id", "err", err, "id", remote.SanitizeLogString(string(msg.MessageId)))
		return
	}

	msgHash, err := cfg.hasher.Hash(msg)
	if err != nil {
		r.lggr.Errorw("failed to get message hash", "err", err)
		return
	}

	// A request is uniquely identified by the message id and the hash of the payload to prevent a malicious
	// actor from sending a different payload with the same message id
	requestID := messageID + hex.EncodeToString(msgHash[:])

	r.lggr.Debugw("received request", "msgId", msg.MessageId, "requestID", requestID)

	if requestIDs, ok := r.messageIDToRequestIDsCount[messageID]; ok {
		requestIDs[requestID]++
	} else {
		r.messageIDToRequestIDsCount[messageID] = map[string]int{requestID: 1}
	}

	requestIDs := r.messageIDToRequestIDsCount[messageID]
	if len(requestIDs) > 1 {
		// This is a potential attack vector as well as a situation that will occur if the client is sending non-deterministic payloads
		// so a warning is logged
		r.lggr.Warnw("received messages with the same id and different payloads", "messageID", messageID, "lenRequestIDs", len(requestIDs))
	}

	if _, ok := r.requestIDToRequest[requestID]; !ok {
		callingDon, ok := cfg.workflowDONs[msg.CallerDonId]
		if !ok {
			r.lggr.Errorw("received request from unregistered don", "donId", msg.CallerDonId)
			return
		}

		sr, ierr := request.NewServerRequest(cfg.underlying, msg.Method, cfg.capInfo.ID, cfg.localDonInfo.ID, r.peerID,
			callingDon, messageID, r.dispatcher, cfg.remoteExecutableConfig.RequestTimeout, r.capMethodName, r.workflowDONBindingGate, r.lggr)
		if ierr != nil {
			r.lggr.Errorw("failed to instantiate server request", "err", ierr)
			return
		}

		r.requestIDToRequest[requestID] = requestAndMsgID{
			request:   sr,
			messageID: messageID,
		}
	}

func (e *ServerRequest) OnMessage(ctx context.Context, msg *types.MessageBody) error {
	e.metrics.countExecutionRequest(ctx)

	e.mux.Lock()
	defer e.mux.Unlock()

	if msg.Sender == nil {
		return errors.New("sender missing from message")
	}

	requester, err := remote.ToPeerID(msg.Sender)
	if err != nil {
		return fmt.Errorf("failed to convert message sender to PeerID: %w", err)
	}

	if err := e.addRequester(requester); err != nil {
		return fmt.Errorf("failed to add requester to request: %w", err)
	}

	e.lggr.Debugw("OnMessage called for request", "calls", len(e.requesters),
		"hasResponse", e.response != nil, "requester", requester.String(), "minRequsters", e.callingDon.F+1)

	if e.minimumRequiredRequestsReceived() && !e.hasResponse() {
		switch e.method {
		case types.MethodExecute:
			e.executeRequest(ctx, msg, executeCapabilityRequest)
		default:
			e.setError(types.Error_INTERNAL_ERROR, "unknown method %s"+e.method)
		}
	}

func (e *ServerRequest) Expired() bool {
	return time.Since(e.createdTime) > e.requestTimeout

func (e *ServerRequest) Evictable(minRetention time.Duration) bool {
	age := time.Since(e.createdTime)
	return age > e.requestTimeout && age > minRetention
}

// ExecuteTask executes a task in parallel up to the maximum allowed parallel executions. If the
// maximum execute limit is reached, the function will block until a slot is available or the
// context is cancelled.
func (t *ParallelExecutor) ExecuteTask(ctx context.Context, fn func(ctx context.Context)) error {
	select {
	case t.taskSemaphore <- struct{}{}:
		t.recordSlotUsage(ctx)
		stopped := !t.IfNotStopped(func() {
			t.wg.Go(func() {
				ctxWithStop, cancel := t.stopChan.Ctx(ctx)
				defer func() {
					<-t.taskSemaphore
					t.recordSlotUsage(ctxWithStop)
					cancel()
				}()
				fn(ctxWithStop)
			})
		})

		if stopped {
			return errors.New("executor stopped")
		}
	case <-t.stopChan:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}

	return nil
}
