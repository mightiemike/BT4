## Analysis

The external report's core invariant is: **a size-sensitive, price-quoted execution step (the SetToken bid) can be sandwiched by an unprivileged actor who freely mints/redeems around it, because the pricing mechanism trusts a quote that can be manipulated between quote-fetch and settlement.**

The closest concrete analog in Push Chain is the gas-abstraction auto-swap path used on every crosschain deposit: `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go`) and `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go`) fetch a live Uniswap V3 `QuoterV2` quote via `GetSwapQuote` and then swap PRC20→WPC with a static `5%` slippage tolerance, executed by the module account through `CallPRC20DepositAutoSwap`/`DerivedEVMCall`.

### Title
Static 5% slippage tolerance on inbound gas-abstraction auto-swap enables unprivileged sandwich extraction of user deposit value - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
Every `GAS` and `GAS_AND_PAYLOAD` inbound deposit routes PRC20 funds through an on-chain Uniswap V3 `QuoterV2`-quoted auto-swap into WPC/PC, bounded only by a fixed `minPCOut = quote * 95 / 100` computed at execution time [1](#0-0) . Because the quote is fetched and the swap is executed against a public, unprivileged AMM pool on Push Chain's own EVM, an outside actor can move the pool price before the swap lands and reverse it after, extracting up to the full 5% slippage headroom from the depositing user's (or protocol's) side of the trade — the same "manipulate price around a size-driven, formulaic settlement" pattern as the SetToken sandwich in the source report.

### Finding Description
`ExecuteInboundGas` computes `minPCOut` from a `GetSwapQuote` call made in the same execution as the swap itself [2](#0-1) , then calls `CallPRC20DepositAutoSwap`, a module-sender `DerivedEVMCall` into `depositPRC20WithAutoSwap` on `UNIVERSAL_CORE` [3](#0-2) . The identical pattern is repeated in `gasAndPayloadDepositAutoSwap` for `GAS_AND_PAYLOAD` inbounds [4](#0-3) .

Both the quote and the swap execution occur only once the corresponding `MsgVoteInbound` transaction (from a Universal Validator) is included and executed on Push Chain. This transaction is visible in the mempool before inclusion, just as the SetToken bidder's transaction was. An unprivileged attacker who is simply trading against the same on-chain pool (Uniswap-style, permissionless) can:
1. Front-run the `MsgVoteInbound` finalizing transaction with a swap that pushes the PRC20/WPC pool price against the pending deposit's expected direction.
2. Let the module's auto-swap execute and receive `minPCOut` (bounded only by the static 5% tolerance, not by the true pre-manipulation price).
3. Back-run to restore the pool price, realizing the value difference as profit.

This mirrors the confirmed bug class: an attacker profits by manipulating a size/price-sensitive settlement mechanism around a victim's transaction, using only unprivileged, ordinary actions (AMM trades) — the same "sandwich exploiting a static tolerance around a formulaic on-chain settlement" root cause acknowledged as Medium in the source report (the fix there being a supply cap; here the analogous fix is tightening/removing the fixed slippage assumption and/or protecting the quote-to-execution window).

### Impact Explanation
Because the swap output ultimately funds the recipient UEA's gas balance (or the module's refund flow in `applyGasRefund`, which uses the same `quote * 95/100` pattern [5](#0-4) ), a successful sandwich directly reduces the value delivered to the end user's UEA while the attacker captures the difference — this is unauthorized extraction of protocol/user-controlled value, falling under "stealing ... funds of user or protocol-controlled" and "corruption of ... gas fee accounting" in the allowed impact gate. Every gas-abstraction deposit across every supported source chain goes through this path, making it systemic rather than a one-off edge case.

### Likelihood Explanation
The attack requires only the ability to submit ordinary swap transactions against the public AMM pool used by `UNIVERSAL_CORE`/`QuoterV2` and awareness of pending `MsgVoteInbound` transactions in the mempool — both are unprivileged capabilities available to any external actor, with no validator, TSS, or admin involvement required. The 5% tolerance is a comfortably wide, static window regardless of pool depth or deposit size, making the attack economically viable whenever pool liquidity is thin relative to a deposit.

### Recommendation
Replace the static percentage slippage bound with a protection that accounts for pool depth/deposit size (e.g., TWAP-based quoting, dynamically sized tolerance, or a maximum price-impact cap), and/or reduce the exposure window between quote and execution. Consider routing large deposits through a mechanism resistant to atomic-block manipulation (e.g., commit-reveal or a keeper-attested price feed) rather than a single spot `QuoterV2` call immediately preceding execution.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (or the vote that will finalize one) for a large `GAS`/`GAS_AND_PAYLOAD` inbound whose `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` path will swap PRC20 → WPC.
2. Attacker submits an EVM transaction against the same Uniswap V3 pool, moving the price so that a swap along the deposit's direction is now up to 5% worse than the true pre-attack price.
3. The `MsgVoteInbound` finalizes; `GetSwapQuote` returns the manipulated price, `minPCOut` is computed as `quote*95/100` against that already-degraded price [1](#0-0) , and `CallPRC20DepositAutoSwap` executes at the worse rate.
4. Attacker submits a reverse trade restoring the pool price, net profit equal to the captured slippage, funded by value that should have reached the deposit recipient.

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
