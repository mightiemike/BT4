### Title
Unbounded gzip decompression of user-supplied legacy declare program causes memory-exhaustion DoS via JSON-RPC `estimateFee`/`simulateTransactions` - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The JSON-RPC `starknet_estimateFee` / `starknet_simulateTransactions` code path accepts a `BroadcastedDeclareTransaction::V1` containing a Cairo0 `DeprecatedContractClass` whose `compressed_program` field is base64+gzip encoded, user-controlled data. This is decompressed by `decompress_program` with **no size limit** on the decompressed output, unlike every other decompression path in the codebase (gateway, storage, `starknet_api::compression_utils`) which enforce explicit maximum-size bounds.

### Finding Description
`decompress_program` reads a base64-decoded gzip stream fully into memory with `decoder.read_to_end(&mut decompressed, ...)` and has an explicit `// TODO(dan): add time and size limits.` comment: [1](#0-0) 

This function is called from `user_deprecated_contract_class_to_sn_api`, which converts a user-submitted `DeprecatedContractClass` (from a `BroadcastedDeclareTransaction::V1`) into the SN-API contract class used for local execution: [2](#0-1) 

This conversion is invoked directly from the `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` implementation, on the `V1` branch, with no prior validation of the class's size or bytecode length: [3](#0-2) 

That `TryFrom` impl backs `simulate_transactions` and `estimate_fee`/`estimate_message_fee`-style JSON-RPC methods, which accept an array of `BroadcastedTransaction` (untrusted, unsigned-verification-not-required-at-this-stage input) directly from any RPC caller: [4](#0-3) 

This is a direct analog of the containerd bug class (CWE-400/770): an attacker-supplied compressed blob is decompressed with no limit on the resulting size, so a small gzip "bomb" can expand to an arbitrarily large in-memory buffer.

By contrast, every legitimate ingestion path in this codebase for a declared class enforces limits *before* or *during* decompression:
- The gateway's stateless validator checks `max_contract_bytecode_size` / `max_contract_class_object_size` on the (already-decompressed, in that flow non-gzip) Sierra program: [5](#0-4) 
- The generic gzip helper in `starknet_api` bounds the read via `.take(max_size + 1)`: [6](#0-5) 
- The storage layer's zstd decompression is bounded by `MAX_DECOMPRESSED_SIZE`: [7](#0-6) 

`decompress_program` is the sole exception that performs an unbounded `read_to_end`.

### Impact Explanation
A single unprivileged JSON-RPC client can call `starknet_estimateFee` or `starknet_simulateTransactions` with a `BroadcastedDeclareTransaction::V1` whose `compressed_program` is a crafted gzip bomb (e.g., a few KB compressing to hundreds of MB or GB). The node will allocate the full decompressed size in memory inside the RPC-serving process, potentially exhausting available memory and causing the node process to crash or become unresponsive (OOM), denying service to other RPC clients on that node. This satisfies the "network unable to confirm new transactions" / availability-loss criterion, since a node that serves both RPC and mempool/execution duties could be knocked out by this vector, and the fee-estimation/simulation path is heavily exercised by wallets and tooling before transaction submission.

### Likelihood Explanation
High likelihood: the vulnerable function is directly reachable from a public, unauthenticated JSON-RPC endpoint (`starknet_estimateFee`, `starknet_simulateTransactions`) with attacker-fully-controlled input (an arbitrary `BroadcastedDeclareTransaction::V1`), and no authentication, rate limiting, or size validation is applied to the compressed program before decompression, unlike the analogous flows elsewhere in the codebase that were hardened specifically against this bug class.

### Recommendation
Apply the same size-bounding pattern already used elsewhere in the codebase (`decompress_with_size_limit` / `MAX_DECOMPRESSED_SIZE`) to `decompress_program`: wrap the `GzDecoder` with `.take(max_size)` and reject decompression exceeding a configured maximum (mirroring `max_contract_bytecode_size`/`max_contract_class_object_size` used by the gateway), returning an RPC error instead of allocating unbounded memory. Also consider imposing a decompression time budget for defense-in-depth.

### Proof of Concept
1. Craft a `DeprecatedContractClass` with `compressed_program` set to a small, highly-compressible gzip payload (e.g., a few KB of repeated bytes compressing at >1000:1 ratio) that decompresses to hundreds of MB or several GB.
2. Submit it via JSON-RPC as `starknet_estimateFee` or `starknet_simulateTransactions`, e.g.:
```json
{"jsonrpc":"2.0","method":"starknet_estimateFee","params":[[{"type":"DECLARE","version":"0x1","contract_class":{"program":"<gzip-bomb-base64>","entry_points_by_type":{...},"abi":[]}, "sender_address":"0x1", "max_fee":"0x0", "nonce":"0x0", "signature":[]}], [], {"block_number":0}],"id":1}
```
3. The node calls `ExecutableTransactionInput::try_from(BroadcastedDeclareTransaction::V1(...))` → `user_deprecated_contract_class_to_sn_api` → `decompress_program`, which performs `decoder.read_to_end(&mut decompressed, ...)` with no size cap, allocating the full decompressed size and potentially exhausting node memory.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}
