### Title
Miner-controlled activity resets can suppress the signer inactivity timeout indefinitely, stalling tenure fallback - ([File: stacks-signer/src/chainstate/mod.rs](file))

### Summary
The signer's tenure-inactivity fallback (`is_timed_out`) is only suppressed once the sitting miner has *signed* a block, but before that point it relies on a `last_activity_time` timestamp that the sitting miner itself can refresh at will by repeatedly submitting competing block proposals. This mirrors the OpenBazaar bug: a party to the transaction (there, the buyer; here, the sortition-winning miner) can perpetually reset the "time since last modification" clock that a timeout mechanism depends on, indefinitely blocking the fallback path that exists specifically to route around that party's inaction.

### Finding Description
`SortitionState::is_timed_out` (v1 and v2) is the gate that lets signers fall back to the prior tenure when the current sortition's miner goes silent: [1](#0-0) 

It first checks `has_signed_block_in_tenure` — if the miner has ever produced one signed block, timeout is permanently disabled (by design, to protect a placed signature). If not, it falls back to `last_activity_time`, compared against `block_proposal_timeout`.

`last_activity_time` is written by `update_last_activity_time`, called from `SortitionData::check_latest_block_in_tenure` whenever an incoming, validly-signed block proposal from the *current tenure's miner* conflicts with something already pre-committed or signed at the same or lower chain length — i.e., exactly the "sibling/reorg-attempt" case, deliberately counted as "miner activity" so a genuinely slow miner isn't penalized: [2](#0-1) 

The persistence layer is a simple last-write-wins timestamp with no bound on how often, or by whom, it can be refreshed: [3](#0-2) 

The attack: a miner who wins a sortition but does not want the network to fall back to anyone else (e.g., to stall the chain while withholding real blocks, or to keep signers pinned to their tenure for other purposes) never lets a block cross the pre-commit/signature threshold. Instead, each time one of their proposals is pre-committed by some signers but not fully signed, they immediately submit a new, validly miner-signed sibling proposal at the same height. Each such proposal is a "reorg attempt" that hits the `is_fresh_pre_commit && chain_length <= …` branch and calls `update_last_activity_time`, resetting the clock signer-side. Because the resets require only the miner's own already-possessed mining key (the same key that won the sortition), this needs no majority, no signer key, and no additional privilege — precisely analogous to the buyer in the OpenBazaar bug topping up the escrow with dust to reset `lastModified`.

Because each signer applies this update locally and independently as proposals happen to reach it (subject to normal network timing), signers can diverge on whether/when a given tenure has timed out, i.e., whether to still evaluate that miner's proposals or capitulate to a fallback miner state — a temporary, minority-triggerable disagreement about the current tip/miner view, per the documented state machine flow: [4](#0-3) 

### Impact Explanation
This breaks the equality the timeout is supposed to enforce: "no globally accepted block for `block_proposal_timeout` ⇒ signers agree to fall back to the prior tenure." A single minority actor (the sitting miner, using only their own key) can keep that equality from ever being reached by perpetually re-arming `last_activity_time`, stalling tenure progress for as long as they choose, and — because the reset is observed asynchronously by different signers — producing a temporary tip/miner-view disagreement across the signer set while the withheld tenure lingers. This matches the "High" bucket: minority-triggerable static-validation/timeout divergence causing temporary tip disagreement, bounded to a liveness stall rather than a fund-loss or split that survives once the miner stops.

### Likelihood Explanation
The action requires nothing beyond what a sortition winner already has: their mining key and the ability to submit multiple valid, differently-timestamped/differently-built sibling block proposals at the same chain height. No majority collusion, no signer/admin key, and no protocol-level rate limit prevents this; `update_last_activity_time` is an unconditional last-write-wins timestamp with no cap on the number of resets (mirroring the missing "limit number of modifications" safeguard called out in the original report).

### Recommendation
Bound how much a single tenure's `last_activity_time` can be extended by unsigned/pre-commit-only competing proposals — e.g., track a cumulative or count-limited extension budget per tenure (similar to the fix suggested in the OpenBazaar report: cap the number of times a timer may be reset), or require that only chain-length-advancing proposals (not same-height siblings) count as activity, so a miner cannot indefinitely re-arm the inactivity clock without ever making forward progress. Alternatively, make `is_timed_out` consider "activity" relative to actual finalized progress (a signed block) rather than any pre-commit-conflicting proposal.

### Proof of Concept
1. A miner wins a sortition and begins tenure T.
2. Miner proposes block A at height N; some, but not enough, signers pre-commit to it (`BlockState::PreCommitted`, `approved_time` set, threshold not reached).
3. Before `tenure_last_block_proposal_timeout`/`block_proposal_timeout` elapses, the miner (using the same mining key) proposes a different, validly signed block B at the same height N.
4. Each signer evaluating B via `check_block_against_signer_db_state` → `check_latest_block_in_tenure` sees `is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length` and calls `signer_db.update_last_activity_time(...)`, resetting that signer's clock for tenure T (`stacks-signer/src/chainstate/mod.rs` lines 427-447).
5. Repeat step 3 indefinitely with new sibling proposals (C, D, E, …) before each timeout window elapses.
6. `SortitionState::is_timed_out` never returns `true` for tenure T on any signer that keeps receiving these resets, so `check_miner_inactivity`'s fallback to the prior tenure is never triggered, while no block from T ever reaches the global-acceptance threshold — the tenure stalls indefinitely at the sole discretion of the sitting miner, and different signers may disagree about T's liveness depending on which resets they happened to observe.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");

    /// Update the tenure (identified by consensus_hash) last activity timestamp
    pub fn update_last_activity_time(
        &mut self,
        tenure: &ConsensusHash,
        last_activity_time: u64,
    ) -> Result<(), DBError> {
        debug!("Updating last activity for tenure"; "consensus_hash" => %tenure, "last_activity_time" => last_activity_time);
        self.db.execute("INSERT OR REPLACE INTO tenure_activity (consensus_hash, last_activity_time) VALUES (?1, ?2)", params![tenure, u64_to_sql(last_activity_time)?])?;
        Ok(())
    }
