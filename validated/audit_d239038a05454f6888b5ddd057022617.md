### Title
PrivilegedWebContents MojoJS enablement bypasses the capability-allowlist origin gate, exposing privileged browser Mojo interfaces - (File: chrome/browser/chrome_content_browser_client.cc)

### Summary
The GEIC/glic PrivilegedWebContents (PWC) path enables MojoJS for every outermost primary main frame without verifying the committed origin against the PWC capability allowlist. This is the Chromium analog of the Purrlend admin-privilege-abuse root cause: a privileged administrative surface (privileged Mojo interfaces such as `GeicBrowserHost` and `PrivilegedBridge`) is reachable without the intended time-lock/allowlist gate, allowing an untrusted renderer or malicious page to assume the privileged role and invoke browser-side APIs.

### Finding Description
`ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame` returns `true` for any `pwc::PrivilegedWebContents` outermost main frame and contains an explicit TODO noting that the committed origin is not checked against the capability allowlist. [1](#0-0) [2](#0-1)  The same shortcut is repeated in `GeicPwcManager::TabEntry::RenderFrameCreated` and `ReadyToCommitNavigation`, which call `EnableMojoJsBindings` for every primary main frame. [3](#0-2) [4](#0-3)  Once MojoJS is enabled, the privileged process's frame binder registry exposes `pwc::mojom::PrivilegedBridge` and `geic::mojom::GeicApi`. [5](#0-4)  On desktop, `geic::mojom::GeicBrowserHost` is also registered. [6](#0-5)  `BindGeicApi` and `BindGeicBrowserHost` rely on `pwc::EnforceCapabilityGate` and a component check, but the MojoJS activation point has already bypassed the capability-allowlist origin gate, so a renderer from a navigation-allowlisted but not capability-allowlisted origin can attempt to bind these privileged interfaces. [7](#0-6) [8](#0-7)  The exact implementation of `pwc::EnforceCapabilityGate` was not reachable in the indexed files, but the MojoJS enablement bypass is explicit in the source.

### Impact Explanation
A malicious document loaded in a PWC can use `Mojo.bindInterface` to request `geic.mojom.GeicBrowserHost`. That interface exposes tab-opening APIs (`OpenSignInTab`, `CloseSignInTab`) and focused-tab context extraction, leading to security-UI spoofing and cross-origin disclosure of another tab's data. [9](#0-8) [10](#0-9)  This mirrors the attacker using the granted `BRIDGE_ROLE` to mint unbacked assets and borrow real collateral: a privileged browser role is exercised from an origin that should not have held it.

### Likelihood Explanation
The path is reachable from a single navigation payload: an attacker-controlled origin that is allowed to navigate within the PWC (the navigation allowlist can be broader than the capability allowlist) becomes a MojoJS-enabled privileged renderer. `ReadyToCommitNavigation` enables MojoJS before the navigation commits, based only on `IsInPrimaryMainFrame`, so the document can immediately request privileged interfaces. [11](#0-10)  The TODO comments reference `crbug.com/539909218` and describe the current behavior as a "prototype shortcut," confirming the gate is incomplete. [1](#0-0) [12](#0-11) 

### Recommendation
- Do not call `EnableMojoJsBindings` for PWC frames unless `PwcPolicyDelegate::IsCapabilityOrigin(frame->GetLastCommittedOrigin())` is true.
- Move the capability-allowlist check into `ShouldAllowMojoJsBindingsForFrame` and `GeicPwcManager::TabEntry` before enabling MojoJS.
- Scope MojoJS exposure to the minimal required interface set (e.g., only `GeicApi`) rather than the entire Mojo surface, and ensure `BindGeicApi`/`BindGeicBrowserHost` re-verify the committed origin against the capability allowlist.
- Introduce a staged/time-locked capability grant so that navigation to a new origin cannot immediately obtain privileged Mojo access.

### Proof of Concept
1. Configure a GEIC PWC whose navigation allowlist includes `https://attacker.example` but whose capability allowlist does not.
2. Navigate the PWC primary main frame to `https://attacker.example/poc.html`.
3. `GeicPwcManager::TabEntry::ReadyToCommitNavigation` calls `EnableMojoJsBindings` because the navigation is in the primary main frame, without checking the origin. [11](#0-10) 
4. The attacker page runs:
   ```js
   const pipe = Mojo.createMessagePipe();
   Mojo.bindInterface('geic.mojom.GeicBrowserHost', pipe.handle0);
   const host = new geic.mojom.GeicBrowserHostPtr(pipe.handle0);
   host.openSignInTab('https://accounts.google.com/phishing');
   ```
5. Because the process is privileged, `PopulateChromeFrameBinders` registered `geic.mojom.GeicBrowserHost`; with MojoJS enabled the renderer can request it. [6](#0-5)  If the bind-time gate does not reject the non-allowlisted origin, the attacker can open/close sign-in tabs or extract focused-tab context, achieving security-UI spoofing and cross-origin disclosure.
