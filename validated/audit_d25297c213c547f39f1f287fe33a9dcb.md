### Title
Unsanitized contract panic/revert data written to sequencer logs enables terminal escape-sequence injection - (File: `crates/blockifier/src/execution/stack_trace.rs`)

### Summary
`format_panic_data` (`crates/starknet_api/src/execution_utils.rs:4-11`) converts arbitrary attacker-chosen felts from a reverted call's `retdata` into a raw UTF-8/ASCII string using `format_next_item`/`quote_if_string`. This string becomes part of `Cairo1RevertSummary`/`ErrorStack`, which implements `Display` and is embedded verbatim into `TransactionExecutionError` messages (`crates/blockifier/src/transaction/errors.rs:82-127`, via `gen_tx_execution_error_trace`). These error strings are then logged unmodified by the sequencer, e.g. `warn!("... Revert Error: {}", revert_error)` in `crates/apollo_batcher/src/block_builder.rs:654-659` and `log::debug!("Transaction execution failed with: {error}")` in `crates/blockifier/src/transaction/transactions.rs:73`. ### Finding Description
Any account contract's constructor, `__validate__`, or `__execute__` can revert with arbitrary felt data (panic data). This data is fully attacker-controlled: a deployer/sender chooses the bytes encoded in each felt. `format_panic_data` decodes these felts to raw strings, embedding them (quoted) in the panic/revert message without stripping ANSI/terminal escape sequences, control characters, or newlines. This string flows into `TransactionExecutionError` `Display` implementations and is subsequently written to the node's log output via `warn!`/`log::debug!`/`info!` calls in the batcher and blockifier — paths reachable directly by submitting a single transaction that triggers a contract revert with a crafted panic message.

This mirrors the WEBrick CVE-2009-4492 pattern exactly: unsanitized, attacker-supplied bytes reach a log stream that may later be displayed in a terminal emulator, permitting terminal title/clipboard manipulation or, on vulnerable terminal emulators, more severe consequences (arbitrary command injection via OSC/DCS escape sequences, depending on the terminal used to view logs).

Notably, this codebase already contains deliberate mitigations for the *same* bug class elsewhere — e.g. `serialize_error` in `crates/apollo_http_server/src/errors.rs:127-140` sanitizes all non-alphanumeric characters (including control/escape bytes) before returning error messages to HTTP clients, and `is_safe_request_id_byte` in `crates/starknet_transaction_prover/src/server/request_log.rs:173-177` explicitly rejects non-printable bytes to prevent smuggling into logs. However, this sanitization is applied only to the HTTP-response and request-id paths, not to the internal `tracing`/`log` output paths that carry contract revert reasons. [5](#0-4) [6](#0-5) 

### Impact Explanation
An attacker (any unprivileged transaction sender or contract deployer) can, at negligible cost, cause the sequencer to write attacker-chosen bytes—including terminal control/escape sequences—into its log stream on every deployment/invoke transaction that triggers a crafted revert. This is a low-severity, log-injection class bug (matching the "Medium" severity of the referenced advisory): it does not directly cause consensus divergence or fund loss, but can corrupt structured logs, spoof log entries, or (depending on the terminal/log viewer used by operators) manipulate terminal state when logs are tailed interactively.

### Likelihood Explanation
High likelihood of triggering: any account contract can revert with `panic(array![...])`, and the sequencer logs the panic/revert reason on every reverted-but-accepted transaction (`block_builder.rs`) and on every execution failure (`transactions.rs`). No special privileges are required; a single ordinary `invoke`/`declare`+`deploy_account` transaction suffices.

### Recommendation
Apply the same sanitization already used for the HTTP-facing error path (`serialize_error` in `apollo_http_server/src/errors.rs`) to the internal log-facing revert/panic strings before they are embedded into `Display` output for `Cairo1RevertSummary`/`TransactionExecutionError`, or sanitize immediately before the `warn!`/`info!`/`debug!` calls in `block_builder.rs` and `transactions.rs`. At minimum, strip/escape ASCII control characters (0x00–0x1F, 0x7F) and any ANSI escape sequences from `format_panic_data`'s output before it is used in any log-facing `Display` implementation.

### Proof of Concept
1. Deploy an account/test contract whose constructor or `__execute__` reverts with a panic array containing raw bytes for a terminal escape sequence, e.g. felt-encoded `\x1b]0;PWNED\x07` (an OSC window-title-set sequence) or a large block of ANSI codes.
2. Submit an ordinary `invoke`/`deploy_account` transaction that triggers this revert.
3. Observe the sequencer batcher log line `warn!("Transaction {} is reverted during execution while still accepted. Revert Error: {}", ...)` (or the blockifier `log::debug!` line) containing the raw, unsanitized escape sequence, verifiable by inspecting the node's stdout/log file bytes for the injected `\x1b` sequence. use cairo_lang_runner::casm_run::format_next_item;
use starknet_types_core::felt::Felt;

pub fn format_panic_data(felts: &[Felt]) -> String {
    let mut felts = felts.iter().copied();
    let mut items = Vec::new();
    while let Some(item) = format_next_item(&mut felts) {
        items.push(item.quote_if_string());
    }
    if let [item] = &items[..] { item.clone() } else { format!("({})", items.join(", ")) }
}

            class_hash,

        ),

                error,
                class_hash,

            stack.push(ErrorStackSegment::StringFrame(error.to_string()));

        }

/// Serializes a `StarknetError` into an HTTP response, encode the error message
/// to defend potential Cross-Site risks.
fn serialize_error(error: &StarknetError) -> Response {
    let quote_re = Regex::new(r#"[\"`]"#).unwrap(); // " and ` => ' (single quote)
    let sanitize_re = Regex::new(r#"[^a-zA-Z0-9 :.,\[\]\(\)\{\}'_]"#).unwrap(); // All other non-alphanumeric characters except [:.,[](){}]_ => ' ' (space)

    let mut message = error.message.clone();
    message = quote_re.replace_all(&message, "'").to_string();
    message = sanitize_re.replace_all(&message, " ").to_string();

    let sanitized_error = StarknetError { code: error.code.clone(), message };

    serde_json::to_vec(&sanitized_error)
        .expect("Expecting a serializable StarknetError.")
        .into_response()
}
