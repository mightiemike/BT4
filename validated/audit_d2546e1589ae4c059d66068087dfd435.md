### Title
Silent truncation of `eth_getLogs`/`eth_getFilterLogs` results when a queried block range crosses the pruning boundary - ([File: chainbase/src/main/java/org/tron/core/db/BlockIndexStore.java])

### Summary
`BlockIndexStore.get(Long num)` throws `ItemNotFoundException` for pruned/unindexed block numbers, but this exception is swallowed inside `Manager.getTransactionInfoByBlockNum` and converted into an empty `TransactionInfoList`. `LogMatch.matchBlockOneByOne` treats an empty list as "no logs in this block" and silently `continue`s, so `eth_getLogs`/`eth_getFilterLogs` return a normal (HTTP 200, no JSON-RPC error) result that is missing all logs from any pruned block in the requested range, with nothing to inform the caller the result is incomplete.

### Finding Description
`eth_getLogs` resolves candidate blocks via `LogBlockQuery.getPossibleBlock()` using the bloom-filter section store, without checking whether those block numbers are still retained (i.e. above `ChainBaseManager.lowestBlockNum`) [1](#0-0) . The candidate list is then passed to `LogMatch.matchBlockOneByOne`, which for each block number calls `manager.getTransactionInfoByBlockNum(blockNum)`: [2](#0-1) 

`Manager.getTransactionInfoByBlockNum` first checks `TransactionRetStore`; if that has no data (e.g. history not retained), it falls back to `chainBaseManager.getBlockByNum(blockNum)`, which internally calls `getBlockIdByNum` → `BlockIndexStore.get(Long)`: [3](#0-2) [4](#0-3) 

For a pruned block number (below the store's lowest retained block, e.g. on a `LITE` node, or once history has been rotated out), `BlockIndexStore.get` throws `ItemNotFoundException`. `Manager.getTransactionInfoByBlockNum` catches this exception and simply logs a warning, returning the (empty) builder instead of propagating the failure: [5](#0-4) 

Back in `LogMatch.matchBlockOneByOne`, an empty `transactionInfoList` causes the loop to `continue` to the next candidate block without any signal that the block's real data could not be retrieved: [6](#0-5) 

The JSON-RPC layer (`TronJsonRpcImpl.getLogs`/`getFilterLogs` → `getLogsByLogFilterWrapper`) has no check against the pruning boundary either — it only validates `fromBlock <= toBlock` and (optionally) the configured max block range, never whether the range is still fully retained: [7](#0-6) [8](#0-7) 

Net effect: any unprivileged caller of the public `eth_getLogs`/`eth_getFilterLogs` JSON-RPC methods can request a `fromBlock`/`toBlock` range that straddles the pruning boundary (e.g. on a `LITE` node, or a full node with limited `transactionHistorySwitch`/retention window) and receive a normal, successful `LogFilterElement[]` response that silently omits logs belonging to the pruned portion of the range — there is no error code, no partial-result flag, and no distinguishable difference from a genuinely complete result with no matching logs.

### Impact Explanation
Any off-chain consumer (exchange, bridge, dispute-resolution tool) that relies on `eth_getLogs` to verify whether a settlement/transfer event occurred in a historical block range can be misled: the API returns a "successful", seemingly complete but actually truncated log set for ranges overlapping pruned history. This creates a state/observation divergence between the true chain history and what the JSON-RPC API reports, and could be leveraged by an attacker to falsely claim non-occurrence of an event (or by a service integrator to erroneously conclude an event never happened) without any error being surfaced.

### Likelihood Explanation
Reachable by any unauthenticated user with JSON-RPC access to a `LITE` node or a full node with limited history retention (`transactionHistorySwitch`/pruned `TransactionRetStore`/pruned `BlockIndexStore`/`BlockStore`). No special privileges are required — just knowledge of `lowestBlockNum` (obtainable, e.g., via the earliest retained block) and a crafted `fromBlock`/`toBlock` spanning that boundary. This is deterministic and repeatable on any node configured to prune history, which is a common, documented deployment mode (LiteFullNode).

### Recommendation
Do not silently swallow `ItemNotFoundException`/`BadItemException` in `Manager.getTransactionInfoByBlockNum` when the underlying cause is "block pruned" rather than "genuinely empty." Instead:
- Track and expose the store's lowest retained block number, and have `LogFilterWrapper.validateBlockRange`/`getLogsByLogFilterWrapper` reject (or clamp with an explicit warning/error) any `fromBlock` below that boundary.
- Alternatively, propagate a distinguishable error (e.g. a new `JsonRpcException` with a dedicated error code) up through `LogMatch`/`TronJsonRpcImpl.getLogs` when a candidate block's data cannot be retrieved due to pruning, instead of treating it identically to "no logs in this block."

### Proof of Concept
Integration test plan (JUnit, `framework` module):
1. Configure a test node as `LITE` (or otherwise seed `BlockIndexStore`/`TransactionRetStore`/`BlockStore` such that blocks `1..N` are absent while blocks `N+1..M` contain known logs), so `ChainBaseManager.getLowestBlockNum()` returns `N+1`.
2. Insert a transaction with a log at block `M` (> `N+1`), and leave blocks below `N+1` pruned/missing.
3. Call `tronJsonRpc.getLogs(new FilterRequest(hex(1), hex(M), null, null, null))` (range straddling the pruning boundary).
4. Current (buggy) behavior: call succeeds, returns `LogFilterElement[]` containing only the log from block `M`, with no error and no indication that blocks `1..N` were unretrievable.
5. Expected assertion for a fixed implementation: either the call throws a clear JSON-RPC error (e.g. `JsonRpcInvalidParamsException`/dedicated "range partially pruned" exception), or the returned result is provably complete for the entire declared range (i.e., the API refuses ranges extending below `lowestBlockNum`). The test should assert that the API never returns HTTP 200 with a "success" log array for a range it cannot fully service.

  public TransactionInfoList getTransactionInfoByBlockNum(long blockNum) {
    TransactionInfoList.Builder transactionInfoList = TransactionInfoList.newBuilder();

    try {
      TransactionRetCapsule result = getTransactionRetStore()
              .getTransactionInfoByBlockNum(ByteArray.fromLong(blockNum));

      if (!Objects.isNull(result) && !Objects.isNull(result.getInstance())) {
        result.getInstance().getTransactioninfoList().forEach(
            transactionInfo -> transactionInfoList.addTransactionInfo(transactionInfo)
        );
      } else {
        Protocol.Block block = chainBaseManager.getBlockByNum(blockNum).getInstance();

        if (block != null) {
          List<Transaction> listTransaction = block.getTransactionsList();
          for (Transaction transaction : listTransaction) {
            TransactionInfoCapsule transactionInfoCapsule = getTransactionHistoryStore()
                    .get(Sha256Hash.hash(CommonParameter.getInstance()
                            .isECKeyCryptoEngine(), transaction.getRawData().toByteArray()));

            if (transactionInfoCapsule != null) {
              transactionInfoList.addTransactionInfo(transactionInfoCapsule.getInstance());
            }
          }
        }
      }
    } catch (BadItemException | ItemNotFoundException e) {
      logger.warn(e.getMessage());
    }

    return transactionInfoList.build();
  }

  public LogFilterElement[] getLogs(FilterRequest fr) throws JsonRpcInvalidParamsException,
      ExecutionException, InterruptedException, BadItemException, ItemNotFoundException,
      JsonRpcMethodNotFoundException, JsonRpcTooManyResultException {
    disableInPBFT("eth_getLogs");

    long currentMaxBlockNum = wallet.getNowBlock().getBlockHeader().getRawData().getNumber();

  @Override
  public LogFilterElement[] getFilterLogs(String filterId) throws
      JsonRpcInvalidParamsException, ExecutionException,
      InterruptedException, BadItemException, ItemNotFoundException,
      JsonRpcMethodNotFoundException, JsonRpcTooManyResultException {
    disableInPBFT("eth_getFilterLogs");

    Map<String, LogFilterAndResult> eventFilter2Result;
    if (getSource() == RequestSource.FULLNODE) {
      eventFilter2Result = eventFilter2ResultFull;
    } else {
      eventFilter2Result = eventFilter2ResultSolidity;
    }

    filterId = ByteArray.fromHex(filterId);
    if (!eventFilter2Result.containsKey(filterId)) {
      throw new ItemNotFoundException(FILTER_NOT_FOUND);
    }

    LogFilterWrapper logFilterWrapper = eventFilter2Result.get(filterId).getLogFilterWrapper();
    long currentMaxBlockNum = wallet.getNowBlock().getBlockHeader().getRawData().getNumber();

    // re-check the block range against the current head: the filter was created without the cap
    // (eth_newFilter), so enforce it here to prevent an unbounded scan.
    logFilterWrapper.validateBlockRange(currentMaxBlockNum);

    return getLogsByLogFilterWrapper(logFilterWrapper, currentMaxBlockNum);
  }

  private LogFilterElement[] getLogsByLogFilterWrapper(LogFilterWrapper logFilterWrapper,
      long currentMaxBlockNum) throws JsonRpcTooManyResultException, ExecutionException,
      InterruptedException, BadItemException, ItemNotFoundException {
    //query possible block
    LogBlockQuery logBlockQuery = new LogBlockQuery(logFilterWrapper, manager.getChainBaseManager()
        .getSectionBloomStore(), currentMaxBlockNum, sectionExecutor);
    List<Long> possibleBlockList = logBlockQuery.getPossibleBlock();

    //match event from block one by one exactly
    LogMatch logMatch =
        new LogMatch(logFilterWrapper, possibleBlockList, manager);
    return logMatch.matchBlockOneByOne();
  }
