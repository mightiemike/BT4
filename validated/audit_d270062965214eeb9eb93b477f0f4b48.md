### Title
Unprotected same-block AMM auto-swap in gas-abstraction deposit path enables sandwich extraction from user deposits - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
The original report's bug class is "observable, delayed price update creates a front-runnable arbitrage window." The nearest Push Chain analog is not a cross-chain price broadcast, but the module-driven Uniswap-style auto-swap that converts a user's deposited PRC20 into the gas token (WPC) during inbound execution. The keeper fetches a spot quote and immediately executes the swap with only a flat 5% slippage bound and no deadline enforcement, giving an unprivileged attacker a reliable, mempool-visible target to sandwich, extracting value directly from the user's deposited funds.

### Finding Description
`ExecuteInboundGas` (for `GAS`-type inbounds) and `gasAndPayloadDepositAutoSwap` (for `GAS_AND_PAYLOAD`) both perform the same two-step pattern: call `GetSwapQuote` (a view call to `QuoterV2.quoteExactInputSingle`) and then immediately call `CallPRC20DepositAutoSwap`/`depositPRC20WithAutoSwap` with `minPCOut = quote * 95 / 100`. The quote itself is taken from `GetSwapQuote`, which calls the on-chain Uniswap V3-style quoter: [3](#0-2) 

The actual swap is submitted via `depositPRC20WithAutoSwap` with `deadline = 0` (meaning "contract uses its default"), so there is no meaningful expiry protection either: [4](#0-3) 

This module-originated swap is triggered deterministically inside `DeliverTx` when the third `MsgVoteInbound`/`MsgVoteOutbound` (or CEA-execution flow) is processed and finalizes an inbound. Because these are ordinary Cosmos transactions that pass through the node's mempool before block inclusion, an unprivileged attacker watching the mempool can:
1. Front-run the finalizing `MsgVoteInbound` tx with a large swap against the same PRC20/WPC Uniswap V3 pool, moving the spot price unfavorably for the upcoming module swap.
2. Let the module's deposit-and-autoswap execute at a materially worse price — the 5% flat tolerance is generous enough to absorb substantial price impact from the attacker's trade, and there is no TWAP or price-impact cap, only a static percentage off a quote taken in the same block.
3. Back-run with the reverse trade to realize the price recovery, capturing the spread as profit extracted from the value that should have gone to the user's UEA as gas token (WPC).

Unlike a true "flash-loan"-style atomic quote-then-swap where quote and execution share the exact same state with no attacker transaction interleaved, here the attacker's manipulating transaction can be ordered *before* the module's finalizing vote transaction within the same block, so the quote itself already reflects manipulated (or about-to-be-reverted) pool state, and the loose 5% band absorbs the loss.

### Impact Explanation
This directly reduces the amount of gas token (WPC) a user's UEA receives from an inbound deposit meant for gas abstraction, i.e., value is drained from a user-controlled deposit into an attacker's pocket via ordinary AMM manipulation — no validator, relayer, or TSS compromise is needed. This matches the in-scope impact "corruption of PRC20 or native asset accounting, gas fee accounting ... or refund accounting" and "draining ... of user or protocol-controlled funds," triggered purely by an unprivileged actor's own transactions plus knowledge of pending `MsgVoteInbound` transactions in the mempool.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: `MsgVoteInbound`/`MsgVoteOutbound`/CEA-execution transactions from Universal Validators are broadcast the same way as any Cosmos SDK transaction, are visible pre-confirmation, and are not shielded from front-running (no threshold encryption, no private mempool for these specific ballot-finalizing messages was found in scope). Every GAS or GAS_AND_PAYLOAD inbound execution triggers this same swap, making the attack surface recurring rather than one-off. The magnitude of extractable value scales with the deposit size and available pool liquidity/depth relative to the flat 5% band.

### Recommendation
- Replace the flat 5% `minPCOut` slippage tolerance with a TWAP-based or otherwise manipulation-resistant reference price, or compute the acceptable slippage bound from observed pool liquidity/depth rather than a fixed percentage.
- Set an explicit, tight `deadline` for `depositPRC20WithAutoSwap` rather than `0`.
- Consider executing the quote fetch and swap through mechanisms less exposed to same-block manipulation (e.g., commit-reveal ordering, batching, or routing execution through infrastructure resistant to transaction reordering), and/or capping per-block price impact accepted by the auto-swap path.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a pending `MsgVoteInbound` (or CEA execute-payload) transaction that will be the 2/3-quorum-completing vote for an inbound with a sizable `Amount` on a token with a shallow PRC20/WPC Uniswap V3 pool.
2. Attacker submits (with competitive gas/priority) a large swap PRC20→WPC (or WPC→PRC20, depending on direction) against the pool just before the finalizing vote tx lands, pushing the spot price unfavorably for the upcoming module swap.
3. The finalizing vote tx executes `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`: `GetSwapQuote` returns a price already impacted by step 2, and `CallPRC20DepositAutoSwap` executes with `minPCOut` at 95% of that already-degraded quote — well within the manipulated band — so the module's swap clears at the bad price.
4. Attacker submits the reverse swap immediately after, restoring the pool price and pocketing the spread, which came out of the value that should have converted into the user's WPC gas balance.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
