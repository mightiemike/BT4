### Title
Missing Actor Permission Check on `TransferToGasKey` Enables Griefing via Force-Funding Gas Keys Above Deletion Threshold — (File: `runtime/runtime/src/actions.rs`)

### Summary

`check_actor_permissions` in `runtime/runtime/src/actions.rs` explicitly exempts `Action::TransferToGasKey` from the `actor_id == account_id` guard that protects all other account-mutating actions (`WithdrawFromGasKey`, `AddKey`, `DeleteKey`, `Stake`, `DeployContract`, etc.). Any unprivileged account — including a malicious contract via the `promise_batch_action_transfer_to_gas_key` host function — can therefore fund any victim's gas key without consent. By depositing more than `MAX_BALANCE_TO_BURN` (1 NEAR) into a victim's gas key, an attacker can block the victim from deleting that gas key or their account until the victim manually drains the balance.

### Finding Description

In `check_actor_permissions` (`runtime/runtime/src/actions.rs:711–757`), the match arm for `Action::TransferToGasKey(_)` is grouped with `Transfer` and `FunctionCall` — intentionally permissionless actions — and returns `Ok(())` without any `actor_id != account_id` check:

```rust
Action::CreateAccount(_)
| Action::FunctionCall(_)
| Action::Transfer(_)
| Action::TransferToGasKey(_) => (),   // ← no permission check
``` [1](#0-0) 

By contrast, `Action::WithdrawFromGasKey(_)` is grouped with `DeployContract`, `Stake`, `AddKey`, `DeleteKey`, etc., and enforces `actor_id == account_id`:

```rust
Action::DeployContract(_)
| Action::Stake(_)
| Action::AddKey(_)
| Action::DeleteKey(_)
| Action::DeployGlobalContract(_)
| Action::UseGlobalContract(_)
| Action::WithdrawFromGasKey(_) => {
    if actor_id != account_id {
        return Err(ActionErrorKind::ActorNoPermission { ... }.into());
    }
}
``` [2](#0-1) 

The `action_transfer_to_gas_key` handler unconditionally adds `action.deposit` to `gas_key_info.balance` on the target account: [3](#0-2) 

If the resulting balance exceeds `MAX_BALANCE_TO_BURN = 1 NEAR`:

1. `delete_gas_key` returns `GasKeyBalanceTooHigh` and leaves the key intact.
2. `action_delete_account` sums all gas-key balances and also aborts with `GasKeyBalanceTooHigh`. [4](#0-3) 

The attack is reachable from an ordinary user transaction or from a contract via the `append_action_transfer_to_gas_key` host function: [5](#0-4) 

The `apply_action` call site confirms `check_actor_permissions` is the sole permission gate before dispatch: [6](#0-5) 

### Impact Explanation

An unprivileged attacker can:

1. Block a victim's gas key deletion until the victim manually calls `WithdrawFromGasKey` to drain the balance below 1 NEAR.
2. Block account deletion if the victim's gas key balance exceeds `MAX_BALANCE_TO_BURN`.

The victim can recover by calling `WithdrawFromGasKey` (which does enforce `actor_id == account_id`), so the lock is not permanent. However, the attacker can continuously re-fund the gas key to maintain the DoS, spending their own NEAR each time. The victim's funds are not stolen, but their ability to manage their own account state is disrupted. This is a non-network-level denial of service on account/key deletion, recoverable but requiring active victim response.

### Likelihood Explanation

The attack requires:
1. The victim to have a gas key (enabled at protocol version 85, `GasKeys` feature).
2. The attacker to spend > 1 NEAR per gas key targeted.
3. Continuous re-funding to maintain the DoS.

The `GasKeys` feature is new (PV 85), so the attack surface is currently limited. The cost to the attacker is non-trivial (> 1 NEAR per target gas key). Likelihood: low-to-medium.

### Recommendation

Add `Action::TransferToGasKey(_)` to the permission-checked arm in `check_actor_permissions`, requiring `actor_id == account_id`:

```rust
Action::DeployContract(_)
| Action::Stake(_)
| Action::AddKey(_)
| Action::DeleteKey(_)
| Action::DeployGlobalContract(_)
| Action::UseGlobalContract(_)
| Action::WithdrawFromGasKey(_)
| Action::TransferToGasKey(_) => {   // ← add here
    if actor_id != account_id {
        return Err(ActionErrorKind::ActorNoPermission { ... }.into());
    }
}
```

If permissionless funding of gas keys by third-party contracts is an intended use case (the host function `append_action_transfer_to_gas_key` suggests it may be), then the `MAX_BALANCE_TO_BURN` check in `delete_gas_key` and `action_delete_account` should be decoupled from the deletion path — for example, by burning the full balance regardless of size, or by automatically withdrawing the excess to the account before deletion — so that a force-funded gas key cannot block account management operations. [7](#0-6) 

### Proof of Concept

1. Victim `alice.near` creates a gas key with `AddKey` (`GasKeyFullAccess`, `num_nonces = 1`).
2. Attacker `eve.near` submits a transaction:
   - `signer_id = eve.near`, `receiver_id = alice.near`
   - Actions: `[TransferToGasKey { public_key: alice_gas_key_pk, deposit: 2_000_000_000_000_000_000_000_000 }]` (2 NEAR > `MAX_BALANCE_TO_BURN` = 1 NEAR)
3. The transaction is accepted — `check_actor_permissions` returns `Ok(())` for `TransferToGasKey` without checking `actor_id`.
4. Alice's gas key balance is now 2 NEAR > `MAX_BALANCE_TO_BURN`.
5. Alice submits `DeleteKey { public_key: alice_gas_key_pk }` → fails with `GasKeyBalanceTooHigh`.
6. Alice submits `DeleteAccount { beneficiary_id: ... }` → fails with `GasKeyBalanceTooHigh`.
7. Alice must first call `WithdrawFromGasKey` to drain the balance below 1 NEAR, then retry deletion.
8. Eve can immediately re-fund the gas key after Alice's withdrawal to maintain the DoS.

Expected outcome: Alice's gas key and account deletion are blocked until she drains the gas key balance, which Eve can continuously re-fund at the cost of her own NEAR.

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,

    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}
