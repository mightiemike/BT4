## No vulnerability found for this question.

**Rationale:** The premise—that a miner can legitimately reuse the same microblock signing pubkey hash across two different tenures (H1 and H2)—is prevented by an existing consensus-level guard, not merely a documentation gap.

When any anchored Stacks block is appended, `StacksChainState::append_block` explicitly checks whether `block.header.microblock_pubkey_hash` has ever been used before in that fork via `StacksChainState::has_microblock_pubkey_hash`, which is backed by the same first-seen store (`get_microblock_pubkey_hash_height`/`insert_microblock_pubkey_hash_height`) referenced in the question: [1](#0-0) 

If the pubkey hash was already recorded at an earlier height, the block is rejected outright as `Error::InvalidStacksBlock` and the whole block (including its coinbase) never enters the chainstate: [2](#0-1) 

This means a miner's H2 tenure block, if it reused the H1 tenure's microblock pubkey hash, would never be accepted into any fork in the first place — it fails validation before `handle_poison_microblock` could ever be invoked against it. Consequently, the scenario described (a legitimate reuse at H2 followed by a fork/poison at H2) cannot arise: any attempt to reuse the pubkey hash at H2 is rejected at block-append time, not silently accepted and later mis-attributed.

Because `mblock_pubk_height` returned by `get_microblock_pubkey_hash_height` inside `handle_poison_microblock` always reflects the *only* height at which that pubkey hash could ever have been validly used in a given fork (reuse is structurally impossible), the equality "block_height in the report tuple == the height of the tenure in which the actual equivocation occurred" is preserved: [3](#0-2) 

The existing test suite (`process_poison_microblock_same_block`, `process_poison_microblock_multiple_same_block`) confirms that the reported `block_height` always matches the single insertion height of the pubkey hash, consistent with this guard: [4](#0-3) 

No path exists for an unprivileged attacker to trigger the described wrong-tenure coinbase slashing.
