### Title
Missing enforcement of TriggerConfig.RequiredParams allows unprivileged senders to trigger workflows with incomplete/attacker-controlled params - ([File: core/capabilities/webapi/trigger/trigger.go])

### Summary
`triggerConnectorHandler.processTrigger` in `core/capabilities/webapi/trigger/trigger.go` never reads or enforces `webapiTrigger.config.RequiredParams` (populated from `TriggerConfig.RequiredParams` in `core/capabilities/webapi/webapicap/event_trigger_generated.go`). Any gateway sender that is in `AllowedSenders` and matches an `AllowedTopics` entry can submit a `TriggerRequestPayload` with an arbitrary or empty `Params` map and still receive a `capabilities.TriggerResponse` forwarded to the workflow engine.

### Finding Description
`processTrigger` ( [1](#0-0) ) only checks `trigger.allowedTopics[topic]`, `trigger.allowedSenders[sender.String()]`, and `trigger.rateLimiter.Allow(...)` before wrapping `payload` and sending a `TriggerResponse` on `trigger.ch`. The `RequiredParams []string` field defined on `webapicap.TriggerConfig` ( [2](#0-1) ) is stored in `webapiTrigger.config` at registration time ( [3](#0-2) ) but is never read anywhere in `processTrigger`, and grep across the repo confirms `.config.RequiredParams` / `reqConfig.RequiredParams` is not referenced outside registration and generated/test code. `payload.Params` (`TriggerRequestPayloadParams`, a `map[string]interface{}`) is fully attacker-controlled JSON from the gateway message body ( [4](#0-3) ) and is passed straight into `values.WrapMap(payload)` and emitted to the workflow engine without any presence/type validation against `RequiredParams`.

### Impact Explanation
Since a workflow author declares `RequiredParams` expecting the trigger contract to guarantee those keys exist before invoking downstream capability/workflow logic, the missing check means any authorized-but-still-untrusted sender (an allowed sender is not necessarily a fully trusted party — allowedSenders is a broad allowlist, not per-field authorization) can omit or manipulate required fields. This can cause: workflow logic operating on missing/nil fields (leading to panics, incorrect branching, or misreporting downstream), or reliance-based logic in the workflow silently proceeding with attacker-supplied substitutes for what should be validated fields. This maps to a data-integrity / misreporting-style impact rather than a full auth bypass, since sender/topic ACL and rate-limiting are still enforced.

### Likelihood Explanation
Precondition is that the attacker must be one of the `AllowedSenders` for a given trigger/topic (this is required by design — no ACL bypass is needed beyond being a permitted, but not necessarily trusted for every field, sender). Given that precondition, exploitation is trivial and 100% repeatable: simply POST a `TriggerRequestPayload` with `params` missing the keys listed in the trigger's `requiredParams` config, and `processTrigger` will still return `nil`/emit the event as long as topic, sender, and rate-limit checks pass.

### Recommendation
In `processTrigger`, before constructing and sending `tr := capabilities.TriggerResponse{...}`, validate that every key in `trigger.config.RequiredParams` is present (and non-empty/correctly typed as needed) in `payload.Params`; if any required param is missing, skip that workflow's match (treat as a validation failure, similar to sender/rate-limit failures) and return/report an error rather than forwarding the incomplete payload.

### Proof of Concept
Add a unit test in `core/capabilities/webapi/trigger/trigger_test.go`:
1. Call `RegisterTrigger` with `reqConfig.RequiredParams = []string{"foo"}`, `AllowedSenders` containing a test address, and `AllowedTopics` containing `"topicA"`.
2. Call `HandleGatewayMessage` (or directly `processTrigger`) with a `TriggerRequestPayload{Topics: []string{"topicA"}, Params: TriggerRequestPayloadParams{}}` (i.e., missing `"foo"`), signed/sent from the allowed sender.
3. Assert current behavior: `processTrigger` returns `nil` and a `TriggerResponse` is received on the registered channel despite `"foo"` being absent from `Params` — demonstrating the missing enforcement.
4. Expected (fixed) behavior: `processTrigger` should not deliver the `TriggerResponse` (or should report an explicit "missing required param" error) when `RequiredParams` are absent from `payload.Params`.

func (h *triggerConnectorHandler) processTrigger(ctx context.Context, gatewayID string, body *api.MessageBody, sender ethCommon.Address, payload webapicap.TriggerRequestPayload) error {
	// Pass on the payload with the expectation that it's in an acceptable format for the executor
	wrappedPayload, err := values.WrapMap(payload)
	if err != nil {
		return fmt.Errorf("error wrapping payload %w", err)
	}
	topics := payload.Topics

	// empty topics is error for V1
	if len(topics) == 0 {
		return errors.New("empty Workflow Topics")
	}

	// workflows that have matched topics
	matchedWorkflows := 0
	// workflows that have matched topic and passed all checks
	fullyMatchedWorkflows := 0
	for _, trigger := range h.registeredWorkflows {
		for _, topic := range topics {
			if trigger.allowedTopics[topic] {
				matchedWorkflows++
				if !trigger.allowedSenders[sender.String()] {
					err = fmt.Errorf("unauthorized Sender %s, messageID %s", sender.String(), body.MessageId)
					h.lggr.Debugw(err.Error())
					continue
				}
				if !trigger.rateLimiter.Allow(body.Sender) {
					err = fmt.Errorf("request rate-limited for sender %s, messageID %s", sender.String(), body.MessageId)
					continue
				}
				fullyMatchedWorkflows++
				TriggerEventID := body.Sender + payload.TriggerEventId

				// Emit trigger execution started event
				workflowExecutionID, genErr := events.GenerateExecutionID(trigger.workflowID, TriggerEventID)
				if genErr != nil {
					h.lggr.Errorw("failed to generate execution ID", "err", genErr)
					workflowExecutionID = ""
				}
				emitErr := events.EmitTriggerExecutionStarted(ctx, map[string]string{}, TriggerEventID, workflowExecutionID)
				if emitErr != nil {
					h.lggr.Errorw("failed to emit trigger execution started event", "err", emitErr)
				}

				tr := capabilities.TriggerResponse{
					Event: capabilities.TriggerEvent{
						TriggerType: TriggerType,
						ID:          TriggerEventID,
						Outputs:     wrappedPayload,
					},
				}
				select {
				case <-ctx.Done():
					return nil
				case trigger.ch <- tr:
					// Sending n topics that match a workflow with n allowedTopics, can only be triggered once.
					break
				}
			}
		}
	}
