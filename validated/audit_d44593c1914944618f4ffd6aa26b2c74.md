### Title
Recursion-depth counter reset on every group/extension re-entry allows unbounded recursion and stack-overflow crash - (File: internal/impl/codec_field.go)

### Summary
`proto.Unmarshal`'s recursion-depth defense is implemented as a per-call integer (`unmarshalOptions.depth` in `internal/impl/decode.go`) that is decremented once per message/group entered and threaded through recursive calls to `mi.unmarshalPointer`. However, the generic (non-`MessageInfo`) coder functions for group-kind fields — `consumeGroup`, `consumeGroupValue`, `consumeGroupSlice`, and `consumeGroupSliceValue` in `internal/impl/codec_field.go` — do not forward this depth counter. Instead they call `opts.Options()` [1](#0-0)  to build a brand-new `proto.UnmarshalOptions{}` (which never copies `RecursionLimit`), and then invoke `UnmarshalState` on it [2](#0-1) . Since `proto.UnmarshalOptions.UnmarshalState` treats a zero `RecursionLimit` as "unset" and resets it to `protowire.DefaultRecursionLimit` [3](#0-2) , every re-entry through this path restarts the recursion budget from the maximum value instead of continuing to consume the caller's remaining budget — mirroring exactly the reported bug class: "uncontrolled mutual recursion between validation functions, where each re-entry resets internal depth tracking."

### Finding Description
The depth-tracking invariant is correctly implemented in the primary decode loop: `mi.unmarshalPointer` decrements `opts.depth` and aborts with `errRecursionDepth` when it goes negative [4](#0-3) , and this `opts` value (carrying the decremented `depth`) is passed straight through for statically-typed group fields via `consumeGroupType` (`f.mi.unmarshalPointer(b, p.Elem(), f.num, opts)`) [5](#0-4) .

The break in the invariant is in the sibling functions used for the generic/reflection-based group coder and for group-typed extension fields:
- `consumeGroup` [2](#0-1) 
- `consumeGroupValue` (used for extension fields of group kind) [6](#0-5) 
- `consumeGroupSliceValue` [7](#0-6) 
- `consumeGroupSlice` [8](#0-7) 

All four build a fresh `proto.UnmarshalOptions` via `opts.Options()`, which only copies `Merge`, `AllowPartial`, `DiscardUnknown`, `Resolver`, and `NoLazyDecoding` — `RecursionLimit`/`depth` is silently dropped [1](#0-0) . The resulting `proto.UnmarshalOptions.UnmarshalState` call then sees `RecursionLimit == 0` and resets it to the full `protowire.DefaultRecursionLimit` before recursing back into `o.unmarshal` → `mi.unmarshal` → `mi.unmarshalPointer` [3](#0-2) .

Because Go stack growth, not the protobuf library's own bookkeeping, is the actual backstop once the intended logical limit is defeated, a message schema containing a self-referential (or mutually-recursive) group-kind extension field lets an attacker nest groups far beyond `DefaultRecursionLimit` while the internal counter never accumulates past a small number at each level — reproducing the "mutual recursion... resets internal depth tracking" pattern from the report, ultimately exhausting the goroutine stack and crashing the process (unrecoverable, unlike a `panic`/`recover`).

### Impact Explanation
Any process that calls `proto.Unmarshal`/`proto.UnmarshalOptions.Unmarshal` (the default binary parser) on attacker-controlled bytes against a trusted proto2 schema that declares a group-kind extension field capable of nesting into itself (directly or via a cycle) is exposed. The recursion-limit protection — the only line of defense against maliciously deep nesting in binary decoding — is silently defeated for that specific field kind, letting an unauthenticated peer crash the service with a single malformed message (fatal stack overflow, not a recoverable panic).

### Likelihood Explanation
Requires a schema with a self-referential/cyclic group-kind field or extension, which is valid, in-spec proto2 usage (groups remain supported for backward compatibility, e.g. via `mi.extensionOffset`/`ExtensionField` machinery that also routes through `coderGroupValue`/`coderGroupSliceValue`). No attacker-controlled schema or descriptor is needed — only crafted wire bytes matching an existing group/extension field already compiled into the trusted schema.

### Recommendation
Propagate the caller's decremented recursion depth into `unmarshalOptions.Options()` (e.g., add a `RecursionLimit: o.depth` field to the returned `proto.UnmarshalOptions` in `internal/impl/decode.go`) so that `consumeGroup`, `consumeGroupValue`, `consumeGroupSlice`, and `consumeGroupSliceValue` continue decrementing the same budget across nested group/extension boundaries instead of resetting it via `UnmarshalState`'s zero-value default logic.

### Proof of Concept
Given a trusted proto2 schema with a self-referential group extension, e.g.:
```protobuf
syntax = "proto2";
message M {
  extensions 100 to 200;
}
extend M {
  optional group G = 100 {
    optional M nested = 1;
  }
}
```
An attacker builds a deeply nested chain of `StartGroupType`/`EndGroupType` pairs for field 100, each wrapping another `M` with the same extension set, to a depth far exceeding `protowire.DefaultRecursionLimit` (10000), then sends this as the body of `proto.Unmarshal(data, &M{})`. Because `consumeGroupValue`/`consumeGroup` reset the internal depth counter to the full default on every re-entry via `opts.Options().UnmarshalState(...)` [2](#0-1) , the recursion-limit check never accumulates across levels, and the call stack grows unbounded until the Go runtime raises a fatal `stack overflow` and terminates the process — a pre-auth denial of service on any endpoint that unmarshals this message type from untrusted input.

func consumeGroup(b []byte, m proto.Message, num protowire.Number, wtyp protowire.Type, opts unmarshalOptions) (out unmarshalOutput, err error) {
	if wtyp != protowire.StartGroupType {
		return out, errUnknown
	}
	b, n := protowire.ConsumeGroup(num, b)
	if n < 0 {
		return out, errDecode
	}
	o, err := opts.Options().UnmarshalState(protoiface.UnmarshalInput{
		Buf:     b,
		Message: m.ProtoReflect(),
	})
	if err != nil {
		return out, err
	}
	out.n = n
	out.initialized = o.Flags&protoiface.UnmarshalInitialized != 0
	return out, nil
}

func (o UnmarshalOptions) UnmarshalState(in protoiface.UnmarshalInput) (protoiface.UnmarshalOutput, error) {
