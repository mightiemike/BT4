## Analog Found: Missing re-validation of cached Cairo0 (V0) compiled classes after a block revert allows execution of an undeclared class

### Title
Stale/undeclared Cairo0 class served from the shared `ContractClassManager` cache after a state revert — ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
The Chrome CVE is a use-after-free where a stale, previously-freed object is reused after the state that validated it is gone. The closest reachable analog in this sequencer is `StateReaderAndContractManager::get_compiled_from_class_manager`, which serves compiled classes from a long-lived, process-wide LRU cache (`ContractClassManager`) without re-checking against current state for Cairo0 (`RunnableCompiledClass::V0`) classes — even though the function's own comment acknowledges the cache can hold "a declared class from a reverted block."

### Finding Description
`get_compiled_from_class_manager` explicitly re-verifies `is_declared` against the state reader only for non-V0 (Cairo1+) classes, and skips this check entirely for V0 (Cairo0) classes: [1](#0-0) 

The comment on this branch states the exact hazard: cache existence does not guarantee current declaration status, "it might contain a declared class from a reverted block, for example." That mitigation is applied only to the `_` (non-V0) arm; the `V0` arm is a no-op, so a Cairo0 class hash that was cached while "declared" in a later-reverted block will continue to be served as valid indefinitely, since `ContractClassManager`/`GlobalContractCache` is a process-lifetime LRU cache, not scoped to a state view: [2](#0-1) 

This gap is corroborated by the fact that the codebase has two different revert code paths, and only one of them defensively clears the whole cache. The legacy Python-bound `native_blockifier` revert path explicitly clears the cache to avoid exactly this kind of staleness: [3](#0-2) 

However, the current sequencer's `Batcher::revert_block` — the actual production revert path used by `apollo_batcher` — does not clear `contract_class_manager` at all; it only reverts storage/commitment state: [4](#0-3) 

The `ContractClassManager` (a `ContractClassManager`/cloneable handle around a shared `GlobalContractCache`) is shared between block production and view calls, and the batcher never clears it on revert: [5](#0-4) 

The test suite even documents this exact scenario as a named case — "cached but verification failed after reorg" — proving the team is aware V1 classes need re-verification, but only for V1: [6](#0-5) 

### Impact Explanation
Because `is_declared` is skipped for V0 classes, once a Cairo0 class hash has been cached as compiled (e.g., during execution of a declare or of a contract that uses that class hash) and the block that declared it is later reverted (e.g., due to a reorg or crash-recovery revert), the state layer will correctly report the class as undeclared, but any node whose in-process `ContractClassManager` cache still holds the entry will keep treating it as declared and runnable. This produces:
- Honest-node divergence: nodes with a warm cache execute calls against the class hash successfully; nodes with a cold cache (freshly synced, or that cleared/evicted the entry) reject the same call with `UndeclaredClassHash`. Different honest nodes computing different results for the same block is a consensus-breaking bug class.
- Unauthorized contract execution: transactions can execute logic tied to a class hash that is not declared per the canonical (post-revert) state, undermining the invariant that all executed code must be declared in state.

### Likelihood Explanation
The trigger requires a state revert to occur (a normal sequencer/node operational event — L1 reorg handling, crash recovery, etc. — not attacker-controlled), after which any unprivileged user who deploys/invokes a contract referencing the previously-declared-then-reverted Cairo0 class hash exploits the stale cache with an ordinary transaction. The declare and the subsequent invoke are both unprivileged actions; only the intervening revert is outside attacker control, but reverts are an expected part of normal sequencer operation, not a "malicious operator/proposer" action, so this remains within scope as a state/cache-consistency defect in the execution layer.

### Recommendation
Apply the same `is_declared` re-verification currently done for non-V0 classes to the `RunnableCompiledClass::V0` branch in `get_compiled_from_class_manager`, or invalidate/clear the shared `ContractClassManager` cache on every revert path (including `apollo_batcher::Batcher::revert_block`), matching the defensive `contract_class_manager.clear()` already present in `native_blockifier::py_block_executor::revert_block`.

### Proof of Concept
1. Submit a `DECLARE` transaction for a Cairo0 class `C` and have it included in block `N`; during execution/re-execution, `get_compiled_from_class_manager` populates the shared `ContractClassManager` cache with `RunnableCompiledClass::V0` for `C`'s class hash.
2. Trigger (or wait for) a revert of block `N` via `Batcher::revert_block` — state storage now reports `C` as undeclared, but `contract_class_manager` is never cleared in this path.
3. Submit an ordinary `INVOKE`/`DEPLOY` transaction referencing class hash `C`. On any node whose cache still has the V0 entry, `get_compiled_from_class_manager` returns the cached `RunnableCompiledClass::V0` immediately (no `is_declared` check for V0), and the call succeeds — while a node without the stale cache entry (or one that queries `is_declared` for V1-equivalent) would reject it with `StateError::UndeclaredClassHash`.

pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }

    // This function will panic if there is a storage failure to revert the block.
    pub async fn revert_block(&mut self, input: RevertBlockInput) -> BatcherResult<()> {
        info!("Reverting block at height {}.", input.height);
        let height = self.get_height_from_storage()?.prev().ok_or(
            BatcherError::StorageHeightMarkerMismatch {
                marker_height: BlockNumber(0),
                requested_height: input.height,
            },
        )?;

        if height != input.height {
            return Err(BatcherError::StorageHeightMarkerMismatch {
                marker_height: height.unchecked_next(),
                requested_height: input.height,
            });
        }

        if let Some(height) = self.active_height {
            info!("Aborting all work on height {} due to a revert request.", height);
            self.abort_active_height().await;
        }

        // Wait for the revert commitment to be completed before reverting the storage.
        self.revert_commitment(height).await;

        self.storage_writer.revert_block(height);
        BUILDING_HEIGHT.decrement(1);
        GLOBAL_ROOT_HEIGHT.decrement(1);
        REVERTED_BLOCKS.increment(1);
        Ok(())
    }

pub(crate) struct StorageViewStateReaderFactory {
    pub(crate) storage_reader: StorageReader,
    pub(crate) contract_class_manager: ContractClassManager,
    pub(crate) class_manager_client: SharedClassManagerClient,
}

impl ViewStateReaderFactory for StorageViewStateReaderFactory {
    fn create(
        &self,
        block_number: BlockNumber,
        native_classes_whitelist: NativeClassesWhitelist,
        runtime: tokio::runtime::Handle,
        class_manager_request_timeout: Duration,
    ) -> Box<dyn StateReader + Send> {
        // The batcher's storage records class declarations but never writes the definitions, so a
        // class is only readable through the class manager.
        // The deadline is computed once here rather than passing the duration into `ClassReader`,
        // so a class hash that takes several class manager requests (Casm and Sierra) is still
        // bounded by a single `class_manager_request_timeout`, not a multiple of it.
        let class_reader = Some(ClassReader {
            reader: self.class_manager_client.clone(),
            runtime,
            deadline: Some(Instant::now() + class_manager_request_timeout),
        });
        let apollo_reader = ApolloReader::new_with_class_reader(
            self.storage_reader.clone(),
            block_number,
            class_reader,
        );
        // The class cache is shared with block production, so a view call fetches and compiles only
        // the classes neither has seen yet. Its hits and misses are counted apart from block
        // production's, which view calls would otherwise dominate.
        Box::new(StateReaderAndContractManager::new_with_native_classes_whitelist(
            apollo_reader,
            self.contract_class_manager.clone(),
            native_classes_whitelist,
            Some(BATCHER_VIEW_CALL_CLASS_CACHE_METRICS),
        ))
    }
