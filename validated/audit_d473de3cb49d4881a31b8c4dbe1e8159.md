### Title
Starknet OS `execute_replace_class` skips declared-class validation performed by Blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `replace_class` syscall lets any deployed contract change its own class hash. In the production execution engine (`blockifier`), this state mutation is gated by a mandatory check that the target class hash was actually declared. In the Starknet OS's Cairo re-implementation of the same syscall — the code path used to independently re-execute and verify transactions for proving — that same check is explicitly missing, acknowledged by a `TODO`.

### Finding Description
Any unprivileged account contract can trigger the `replace_class` syscall via a single `INVOKE` transaction (e.g. through the `test_replace_class` entrypoint pattern used across the feature contracts). In `blockifier`'s deprecated syscall hint processor, the handler explicitly reads/validates the compiled class before allowing the class hash swap: [1](#0-0) 

This is also proven out in the test suite, which asserts a `"is not declared"` error when an undeclared class hash is supplied: [2](#0-1) 

However, the Starknet OS Cairo implementation of `execute_replace_class` (used during OS re-execution / proof generation, i.e. the independently-verified state-transition path) does **not** perform this check. It directly reads the caller's state entry and overwrites `class_hash` with the caller-supplied value, unconditionally: [3](#0-2) 

The gap is explicitly called out in the code itself:
```
// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
``` [4](#0-3) 

This mirrors the reported bug class exactly: a state-mutating operation (`setPoolActive` in the original report, `replace_class`/class-hash mutation here) that lacks the access/validity check that a sibling/enforcing code path implements, allowing an unprivileged caller (any contract, reachable from a single submitted transaction) to force a state mutation that should have been rejected.

### Impact Explanation
The Starknet OS is the component whose execution is proven and whose output (the new state root / commitments) is what gets accepted as the canonical state transition. If the OS's independent re-execution of `replace_class` diverges from `blockifier`'s stricter validation (which is what actually builds/gates blocks during normal sequencing), it undermines the guarantee that the OS re-execution reproduces exactly the same state transition blockifier would allow. Any client or verification path relying on the OS's semantics being at least as strict as blockifier's is exposed to a rule inconsistent with the sequencer's own state-transition function, which is a state/commitment class of the bug (wrong committed state entry, i.e. permitting a contract to be redirected to an undeclared/non-existent class hash without the safety check the rest of the system enforces).

### Likelihood Explanation
Reaching this code path only requires deploying/using any contract that calls the `replace_class` syscall — a normal, permissionless Cairo syscall available to every contract, invoked via an ordinary `INVOKE` transaction. No special privileges, staking, or operator access are required; this is a fully unprivileged-transaction-sender-reachable path through the transaction execution/re-execution flow.

### Recommendation
Add the missing declared-class existence check (and ideally the additional consistency checks blockifier performs, e.g. rejecting a Cairo 0 class hash for a Cairo 1 contract) to `execute_replace_class` in the Starknet OS Cairo code, mirroring the check already present in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, before the state entry's `class_hash` is written to `contract_state_changes`.

### Proof of Concept
1. Deploy any contract exposing a `replace_class`-invoking entrypoint (pattern shown in `test_contract.cairo`'s `test_replace_class`). [5](#0-4) 
2. Submit a single `INVOKE` transaction calling that entrypoint with an arbitrary/undeclared `class_hash`.
3. In `blockifier` execution, `state.get_compiled_class(request.class_hash)` fails and the transaction reverts with `"is not declared"`.
4. Independently trace the corresponding Starknet OS Cairo function `execute_replace_class` (`syscall_impls.cairo`): it performs no such lookup and unconditionally writes the new (undeclared) class hash into `contract_state_changes`, demonstrating the code path where the OS would accept a state mutation that blockifier's execution semantics reject.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
