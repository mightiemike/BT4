### Title
`ensure_match_transaction_info` skips state-checkpoint / hot-state / position-checkpoint root verification during chunk replay-verify - (File: `types/src/transaction/mod.rs`, used from `execution/executor/src/chunk_executor/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole invariant check used by `ChunkExecutor::verify_execution` (state-sync / replay-verify / db-tool `replay-on-archive` path) to confirm that locally re-executed transaction outputs match the `TransactionInfo`s taken from an authenticated (accumulator-proven) source. It checks status, gas used, write-set hash, and event root hash, but it never checks `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` [1](#0-0) .

### Finding Description
`ensure_match_transaction_info` is documented in-code as intentionally incomplete: the function's own TODO states it "ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution" [2](#0-1) .

This function is invoked in `ChunkExecutor::verify_execution`, the code path used to re-execute a chunk of transactions during state sync / db-tool replay verification and compare the freshly computed `TransactionOutput`s against the `transaction_infos` obtained from an authenticated source (e.g., backup, or peer-provided accumulator-proven data) [3](#0-2) . Only `state_change_hash` (write-set hash) and `event_root_hash` are cross-checked; `state_checkpoint_hash` — the Sparse Merkle Tree root of the entire world state at a checkpoint boundary, and the newer `hot_state_checkpoint_hash`/`position_state_checkpoint_hash` fields carried in `TransactionInfoV1` — are never compared against anything computed from the replayed execution in this function.

Elsewhere, the state-checkpoint hash is computed by `do_state_checkpoint.rs`/`do_ledger_update.rs` (`assemble_transaction_infos`) and embedded into a *freshly built* `TransactionInfo` when a block is directly executed and committed [4](#0-3) , but that build path is not the one exercised by `ChunkExecutor::verify_execution`: it accepts a `transaction_infos` argument sourced externally (already contains a `state_checkpoint_hash`) and only calls `ensure_match_transaction_info`, which drops that field silently.

### Impact Explanation
Because `state_checkpoint_hash` (the world-state SMT root) is not validated during `verify_execution`, a divergence between the locally re-executed state and the externally supplied (supposedly accumulator-authenticated) `TransactionInfo`'s state root would not be detected by this specific check. This directly weakens the "replay must reproduce committed state" integrity gate: chunk/state-sync verification and db-tool's `replay_on_archive` can both report success even when the local node's derived state root differs from the canonical one. This is exactly the class of gap the Gate calls out ("Wrong accumulator root ... proof accepted as valid" / "replay ... must preserve deterministic proof binding").

However, the severity depends heavily on the broader context that I could not fully verify:
- Whether `ChunkExecutor::verify_execution`'s output (rather than the transaction_infos it received, which are used elsewhere for the actual commit and accumulator construction) is the value that ultimately gets persisted/trusted. If the trusted `transaction_infos` (with correct checkpoint hash) are what get committed to the DB and accumulator regardless of this check's outcome, then the primary committed-state integrity is not corrupted by this gap — only the *verification signal* (used to catch bugs/mismatches, e.g., in db-tool diagnostics) is weakened.
- Whether `verify_execution_mode.should_verify()` is even enabled on the normal state-sync fast path (vs. only in the explicit `db-tool replay-verify` utility).

### Likelihood Explanation
The gap is explicitly and deliberately acknowledged in the code's own TODO comment, indicating the authors are aware this must be fixed "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`" (a not-yet-fully-enabled on-chain feature gated behind `is_compute_trading_native_state_roots_enabled() && transaction_info_v1 && hotness_in_epilogue` in `BlockExecutorConfigFromOnchain::with_features`) [5](#0-4) . This suggests the gap for the new position/hot-state checkpoint fields is a known, currently-inert limitation pending that feature's rollout. But the comment also states the *existing* `state_checkpoint_hash` (present since V0, unconditional on any feature flag) is likewise unchecked in this comparator — that portion of the gap is live today, independent of the trading-native feature, in any code path relying on `ensure_match_transaction_info` for verification.

I was not able to fully confirm within the available budget whether any other independent check elsewhere in `ChunkExecutor` cross-validates the state_checkpoint_hash against re-executed state (e.g., by re-deriving a smt root and comparing versions before committing), which would mitigate the practical exploitability of this gap. Given the explicit developer acknowledgment but lack of confirmed downstream consequence on committed state (only on the verify-only diagnostic path), I assess this as a real but likely **Medium**, not Critical/High, integrity gap — analogous in spirit to the ERC20 "ignored return value" pattern (a check that should hard-fail on divergence but silently omits part of the comparison), but its blast radius is constrained to the replay-verification tooling rather than the core commit path.

### Recommendation
Extend `TransactionOutput::ensure_match_transaction_info` (or add a companion check specifically in `ChunkExecutor::verify_execution`) to recompute the state checkpoint hash (and, when V1/trading-native fields are populated, the hot-state and position-state checkpoint hashes) from the locally re-executed ledger state and assert equality with the corresponding fields on `txn_info`, exactly as already done for `write_set`/`event_root_hash`/`status`/`gas_used`. This should be done before any reliance on `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, per the existing TODO.

### Proof of Concept
Not applicable as a standalone runnable PoC — the finding is a structural gap in a verification routine rather than a directly triggerable state-corruption bug. Conceptually: run `ChunkExecutor::verify_execution` on a chunk where the supplied `transaction_infos[i].state_checkpoint_hash` is `Some(wrong_hash)` while all other fields (status, gas, write-set hash, event root) match the locally re-executed output; `ensure_match_transaction_info` returns `Ok(())` and `verify_execution` reports the chunk as successfully verified despite the state root mismatch [1](#0-0) [3](#0-2) .

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn assemble_transaction_infos(
        to_commit: &TransactionsWithOutput,
        transaction_info_v1: bool,
        state_checkpoint_hashes: &[Option<HashValue>],
        hot_state_checkpoint_hashes: Option<&[Option<HashValue>]>,
        position_state_checkpoint_hashes: Option<&[Option<HashValue>]>,
    ) -> (Vec<TransactionInfo>, Vec<HashValue>) {
        let _timer = OTHER_TIMERS.timer_with(&["assemble_transaction_infos"]);

        (0..to_commit.len())
            .into_par_iter()
            .with_min_len(optimal_min_len(to_commit.len(), 64))
            .map(|i| {
                let txn = &to_commit.transactions[i];
                let txn_output = &to_commit.transaction_outputs[i];
                let persisted_auxiliary_info = &to_commit.persisted_auxiliary_infos[i];
                // Use the auxiliary info hash directly from the persisted info
                let auxiliary_info_hash = match persisted_auxiliary_info {
                    PersistedAuxiliaryInfo::None => None,
                    PersistedAuxiliaryInfo::V1 { .. } => {
                        Some(CryptoHash::hash(persisted_auxiliary_info))
                    },
                    PersistedAuxiliaryInfo::TimestampNotYetAssignedV1 { .. } => None,
                };
                let state_checkpoint_hash = state_checkpoint_hashes[i];
                let event_hashes = txn_output
                    .events()
                    .iter()
                    .map(CryptoHash::hash)
                    .collect::<Vec<_>>();
                let event_root_hash =
                    InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash();
                let write_set_hash = CryptoHash::hash(txn_output.write_set());
                let status = txn_output
                    .status()
                    .as_kept_status()
                    .expect("Already sorted.");
                let txn_info = if transaction_info_v1 {
                    TransactionInfo::builder_v1()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .maybe_hot_state_checkpoint_hash(
                            hot_state_checkpoint_hashes.and_then(|hot| hot[i]),
                        )
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .maybe_position_state_checkpoint_hash(
                            position_state_checkpoint_hashes.and_then(|p| p[i]),
                        )
                        .build()
                } else {
                    TransactionInfo::builder_v0()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .build()
                };
                let txn_info_hash = txn_info.hash();
                (txn_info, txn_info_hash)
            })
            .unzip()
    }
