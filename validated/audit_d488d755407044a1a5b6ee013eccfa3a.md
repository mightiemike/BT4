### Title
Custom `RecursionLimit` protection is bypassed for lazily-unmarshaled message fields - ([File: internal/impl/lazy.go])

### Summary
`proto.UnmarshalOptions.RecursionLimit` is meant to bound recursive descent into nested submessages during unmarshaling, protecting against stack-overflow/DoS from deeply nested wire data. This limit is correctly threaded through the eager unmarshal path via `unmarshalOptions.depth`, decremented on every nested message in `MessageInfo.unmarshalPointer` [1](#0-0) . However, when a field is marked `lazy = true` in the schema and is later materialized (e.g., via its generated getter), the actual sub-decode is performed with a hardcoded, fixed-size `lazyUnmarshalOptions.depth = protowire.DefaultRecursionLimit`, completely independent of the depth/limit the caller originally supplied to `proto.Unmarshal`.

### Finding Description
When `proto.Unmarshal` is called with a custom, smaller `RecursionLimit` (e.g. to defend against maliciously deep nesting), that value flows into `unmarshalOptions{depth: in.Depth}` and is decremented at every nested message boundary in the eager path [2](#0-1) .

For messages containing a field declared `lazy = true` (a legitimate, supported schema feature, see `internal/testprotos/lazy/lazy_tree.proto`), lazy decoding is enabled by default (`enableLazy` defaults to `1` unless `GOPROTODEBUG=nolazy`) [3](#0-2) . During the initial parse, `unmarshalPointerLazy` only shallow-validates the lazy field's bytes via `mi.skipField` and stores the raw sub-buffer in `protolazy.XXX_lazyUnmarshalInfo`, without recursively decoding it (and thus without ever exhausting the caller-supplied depth budget for that subtree) [4](#0-3) .

The real recursive decode of the lazy field's bytes happens later, on demand, when application code reads the field (`GetXxx()` calls `protoimpl.X.UnmarshalField`, which calls `MessageInfo.lazyUnmarshal`) [5](#0-4) . This function calls `mi.unmarshalField`, which uses the package-level `lazyUnmarshalOptions` constant — not the options/depth the caller passed to the original `Unmarshal` call: [6](#0-5) [7](#0-6) 

Because `lazyUnmarshalOptions.depth` is always `protowire.DefaultRecursionLimit` (a large fixed constant), any `RecursionLimit` value the caller configured to be smaller than the default is silently ignored for the subtree rooted at a lazy field — the check that exists for the top-level/eager decode is bypassed for the lazily-decoded portion of the same message tree.

### Impact Explanation
An application that explicitly lowers `proto.UnmarshalOptions.RecursionLimit` below the library default (`protowire.DefaultRecursionLimit`) as a defense against maliciously deeply-nested messages does not get that protection for any lazily-decoded field. If the message type has a `lazy = true` submessage field and the actual message content behind it is deeply nested (still within `DefaultRecursionLimit`, but beyond the caller's intended, smaller limit), later access of that field via its accessor will recurse to the default limit, undermining the caller's explicit recursion-depth defense and potentially causing excessive stack usage/DoS on a request path that later reads the message field. This is analogous to the reported bug class: a bound check enforced in one code path (`_stake`/eager unmarshal) is silently skipped in a related path that produces the same kind of state (`_extendLock`/lazy field materialization).

### Likelihood Explanation
Requires the trusted schema to declare a field `lazy = true` (a supported, legitimate protobuf-go feature, enabled for lazy decoding by default) and requires the application to have configured a custom, smaller `RecursionLimit` specifically for DoS protection. Given those two conditions — both realistic in services using lazy fields and custom decode options — reading the affected field on ordinary decoded input triggers the bypass; no attacker-controlled resolver, descriptor, or privileged caller is needed.

### Recommendation
Thread the caller's configured recursion depth/limit (or the remaining depth budget from the originating `Unmarshal` call) through to `lazyUnmarshalOptions`/`mi.unmarshalField`/`mi.lazyUnmarshal`, instead of always resetting to the hardcoded `protowire.DefaultRecursionLimit`. At minimum, store the effective `RecursionLimit` used at initial unmarshal time in `protolazy.XXX_lazyUnmarshalInfo` and use it (or a remaining-depth counter) when lazily materializing nested fields.

### Proof of Concept
```go
// Schema (conceptual, mirrors internal/testprotos/lazy/lazy_tree.proto):
// message Node { Node nested = 99 [lazy = true]; ... }

// 1. Build wire bytes for a Node nested N levels deep (N < protowire.DefaultRecursionLimit
//    but > the RecursionLimit the application intends to enforce).
data := buildDeeplyNestedNode(depth /* e.g. 50 */)

// 2. Application unmarshals with an explicit, small RecursionLimit as a DoS guard.
n := &lazypb.Node{}
err := proto.UnmarshalOptions{RecursionLimit: 10}.Unmarshal(data, n)
// err == nil: outer/shallow decode succeeds because `nested` is lazy and only
// shallow-validated by unmarshalPointerLazy/skipField, never actually recursing
// through the 50-level-deep subtree with the caller's depth=10 budget.

// 3. Later, application code reads the field, triggering lazy materialization:
_ = n.GetNested() // internally: protoimpl.X.UnmarshalField -> mi.lazyUnmarshal
                   // -> mi.unmarshalField(..., lazyUnmarshalOptions)
                   // lazyUnmarshalOptions.depth == protowire.DefaultRecursionLimit (not 10)
// The 50-level-deep recursive decode succeeds despite RecursionLimit: 10,
// silently bypassing the caller's configured recursion-depth protection.
```

func UnmarshalField(m interface{}, num protowire.Number) {
	switch m := m.(type) {
	case *messageState:
		m.messageInfo().lazyUnmarshal(m.pointer(), num)
	case *messageReflectWrapper:
		m.messageInfo().lazyUnmarshal(m.pointer(), num)
	default:
		panic(fmt.Sprintf("unsupported wrapper type %T", m))
	}
}

func (mi *MessageInfo) lazyUnmarshal(p pointer, num protoreflect.FieldNumber) {
	var f *coderFieldInfo
	if int(num) < len(mi.denseCoderFields) {
		f = mi.denseCoderFields[num]
	} else {
		f = mi.coderFields[num]
	}
	if f == nil {
		panic(fmt.Sprintf("lazyUnmarshal: field info for %v.%v", mi.Desc.FullName(), num))
	}
	lazy := *p.Apply(mi.lazyOffset).LazyInfoPtr()
	start, end, found, _, multipleEntries := lazy.FindFieldInProto(uint32(num))
	if !found && multipleEntries == nil {
		panic(fmt.Sprintf("lazyUnmarshal: can't find field data for %v.%v", mi.Desc.FullName(), num))
	}
	// The actual pointer in the message can not be set until the whole struct is filled in, otherwise we will have races.
	// Create another pointer and set it atomically, if we won the race and the pointer in the original message is still nil.
	fp := pointerOfValue(reflect.New(f.ft))
	if multipleEntries != nil {
		for _, entry := range multipleEntries {
			mi.unmarshalField(lazy.Buffer()[entry.Start:entry.End], fp, f, lazy, lazy.UnmarshalFlags())
		}
	} else {
		mi.unmarshalField(lazy.Buffer()[start:end], fp, f, lazy, lazy.UnmarshalFlags())
	}
	p.Apply(f.offset).AtomicSetPointerIfNil(fp.Elem())
}
