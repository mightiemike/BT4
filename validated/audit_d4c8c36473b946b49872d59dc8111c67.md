### Title
Open redirect via backslash/slash mixed-encoding bypass in `sanitizeRedirectUrl` - ([File: packages/apps/shopify-app-react-router/src/server/authenticate/admin/helpers/validate-redirect-url.ts])

### Summary
`sanitizeRedirectUrl`'s `isSafe` check validates the raw `redirectUrl` string against `FILE_URI_MATCH` (only forward slashes `///`) and validates `url.pathname` (post-parse) against `INVALID_RELATIVE_URL`, but never checks that the resulting `url.host` matches the app domain. A path like `/\evil.com` is parsed by the WHATWG `URL` constructor as a scheme-relative reference (backslash counts as a path separator for special schemes), which overwrites the authority/host with `evil.com` while leaving `pathname` as `/` — bypassing both regex checks entirely.

### Finding Description
`isSafe` performs its slash/backslash checks in the wrong order relative to URL parsing: [1](#0-0) 

1. `FILE_URI_MATCH = /\/\/\//` is tested against the **raw** `redirectUrl` string, only catching three consecutive forward slashes (e.g. `///path`). It does not catch a `/` followed by a `\`.
2. `new URL(redirectUrl, domain)` is then constructed. Per the WHATWG URL spec, when parsing a relative reference against a "special scheme" base (http/https), a backslash is treated identically to a forward slash for the purpose of detecting a network-path (authority-relative) reference. Given input `/\evil.com`, the parser sees two consecutive slash-like characters at the start and switches to authority-parsing mode, consuming `evil.com` as the new **host**, not as part of the path. The resulting `pathname` becomes `/` (or empty), and `host` becomes `evil.com`.
3. `INVALID_RELATIVE_URL = /[/\\][/\\]/` is then tested against `url.pathname` — but by this point the offending `/\` characters have already been consumed by the URL parser into the host, so `pathname` no longer contains them and the regex never fires.
4. `VALID_PROTOCOLS`/`requireSSL` checks only look at `url.protocol`, which remains `https:` (inherited from the base), so they pass too.

The function therefore never verifies `url.host === new URL(domain).host`, relying entirely on the raw-string/pathname regex heuristics — which this input defeats. This is reachable from `renderAppBridge`, which passes an attacker-influenced redirect target directly into `sanitizeRedirectUrl(config.appUrl, redirectTo.url)`: [2](#0-1) 

The identical logic (and identical gap) exists in the sibling `shopify-app-remix` package's copy of this file.

### Impact Explanation
An attacker who controls the redirect-target parameter (e.g. the exit-iframe/App Bridge redirect flow) can cause the app to emit a `window.open(...)`/redirect to an attacker-controlled origin (`evil.com`) while the code believes it validated a same-origin, safe URL. This is an open redirect out of the embedded admin iframe context, which can be used for phishing or to leak OAuth/session-adjacent context to an attacker-controlled page — matching Shopify's "open redirect" bounty impact class.

### Likelihood Explanation
No privileges are required beyond the ability to influence the value passed as the redirect target (a URL/query parameter in the exit-iframe or app-bridge redirect flow). The bypass depends only on standard, spec-compliant `URL` parsing behavior (backslash-as-slash for special schemes), which is deterministic and reproducible in Node and all major browsers, so this is reliably repeatable, not conditional on host-app misconfiguration.

### Recommendation
After constructing `url = new URL(redirectUrl, domain)`, explicitly verify that `url.host === new URL(domain).host` (or `origin` equality) for any input that isn't an intentionally-allowed absolute cross-origin case, rather than relying solely on raw-string/pathname regex heuristics. Additionally, run the `FILE_URI_MATCH`/`INVALID_RELATIVE_URL` checks against a normalized form of `redirectUrl` that treats `\` and `/` equivalently, or reject any leading `\`/`/` combination before constructing the `URL` object.

```typescript
const FILE_URI_MATCH = /\/\/\//;
const INVALID_RELATIVE_URL = /[/\\][/\\]/;
const WHITESPACE_CHARACTER = /\s/;
const VALID_PROTOCOLS = ['https:', 'http:'];

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }
```
