### Title
Lack of Bytecode Validation for Factory and UniversalCore Contracts in `uexecutor` - ([File: x/uexecutor/keeper/evm.go](https://github.com/patrichyt/push-chain-node--005/blob/main/x/uexecutor/keeper/evm.go))

### Summary
The `uexecutor` module relies on deterministic system contract addresses (`FACTORY_PROXY_ADDRESS_HEX` and `UNIVERSAL_CORE`) to perform critical protocol operations including UEA deployment, PRC20 minting, and gas accounting. However, the keeper functions performing these calls (`CallFactoryToDeployUEA`, `CallPRC20Deposit`, etc.) do not validate that these addresses actually contain the expected contract bytecode before execution. In a scenario where these addresses are empty (e.g., due to a failed genesis deployment or state corruption), the EVM calls will return success with empty data, causing the protocol to persist "SUCCESS" status for material operations that never occurred.

### Finding Description
In Push Chain, the `uexecutor` module acts as a privileged EVM sender to manage cross-chain state. It uses `CallEVM` and `DerivedEVMCall` to interact with system contracts deployed at deterministic addresses [1](#0-0) . 

Specifically:
1. **UEA Deployment**: `CallFactoryToDeployUEA` calls the factory at `0x...eA` to deploy user accounts [2](#0-1) .
2. **Asset Accounting**: `CallPRC20Deposit` calls the `UNIVERSAL_CORE` contract at `0x...C0` to mint synthetic tokens [3](#0-2) .
3. **Gasless Admission**: `MsgExecutePayload` performs an "auto-deploy" check by calling the factory to resolve a UEA address [4](#0-3) .

The underlying `CallEVM` and `DerivedEVMCall` implementations (in the `pushchain/evm` fork) follow standard EVM semantics: calling an address with no code (an EOA or empty slot) returns `success = true` with empty return data. The `uexecutor` keeper functions do not check if the target address has bytecode (e.g., via `GetCodeHash`) before making these calls.

If the `FACTORY_PROXY_ADDRESS_HEX` is empty, `CallFactoryToGetUEAAddressForOrigin` will return a zero address and `isDeployed = false` [5](#0-4) . In `ExecuteInboundFundsAndPayload`, this leads to a call to `DeployUEAV2`, which calls `CallFactoryToDeployUEA`. This call will "succeed" (returning empty data), and the module will record a `SUCCESS` PCTx [6](#0-5) . The protocol then proceeds to `depositPRC20` to a zero or invalid address, again recording `SUCCESS` [7](#0-6) .

### Impact Explanation
The lack of validation breaks the material invariant that `SUCCESS` PCTx status represents a completed state transition. 
- **Fund Freezing**: Users depositing assets from external chains will have their inbounds marked as `SUCCESS` on Push Chain, but the actual PRC20 tokens will never be minted because the `UNIVERSAL_CORE` call was a no-op.
- **State Corruption**: The `UniversalTx` state will indicate that a UEA was deployed and funds were moved, while the EVM state remains unchanged. This creates a permanent divergence between the Cosmos synthetic state and the EVM reality.
- **Gasless Bypass**: If the factory is missing, `MsgExecutePayload` might fail to correctly resolve or deploy UEAs, potentially allowing unprivileged users to trigger "auto-deploy" logic that does nothing but consumes sequencer resources.

### Likelihood Explanation
The likelihood is low as these contracts are intended to be deployed at genesis [8](#0-7) . However, the external report highlights that assuming a contract exists at a specific address without validation is a material vulnerability class. In a multi-module environment like Push Chain, where state depends on the atomic success of cross-module EVM calls, this "silent success" on empty addresses leads to material loss of funds (unminted assets).

### Recommendation
Implement a `requireContract` helper that checks the `CodeHash` of system addresses before any material `DerivedEVMCall`.
```go
func (k Keeper) requireContract(ctx sdk.Context, addr common.Address) error {
    codeHash := k.evmKeeper.GetCodeHash(ctx, addr)
    if codeHash == types.EmptyCodeHash || codeHash == (common.Hash{}) {
        return fmt.Errorf("system contract not found at %s", addr.Hex())
    }
    return nil
}
```
Call this helper at the beginning of `CallFactoryToDeployUEA`, `CallPRC20Deposit`, and `CallUniversalCoreSetChainMeta`.

### Proof of Concept
1. An unprivileged user observes that `UNIVERSAL_CORE` deployment failed or the address is empty due to a misconfigured node.
2. The user sends a standard deposit to the Gateway on Sepolia.
3. Honest Universal Validators reach quorum and submit `MsgVoteInbound`.
4. `ExecuteInboundFunds` is triggered. It calls `k.depositPRC20` [9](#0-8) .
5. `k.depositPRC20` calls `k.CallPRC20Deposit` which uses `DerivedEVMCall` to the empty `UNIVERSAL_CORE` address [10](#0-9) .
6. The EVM returns `success=true` (standard behavior for calls to EOAs).
7. `uexecutor` records `pcTx.Status = "SUCCESS"` [11](#0-10) .
8. The `UniversalTx` is finalized. The user's funds are "minted" in the synthetic record but do not exist in the EVM. The funds are effectively lost/frozen.

func (k Keeper) CallFactoryToDeployUEA(
	ctx sdk.Context,
	from, factoryAddr common.Address,
	universalAccount *types.UniversalAccountId,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: deployUEA",
		"factory", factoryAddr.Hex(),
		"chain_namespace", universalAccount.ChainNamespace,
		"chain_id", universalAccount.ChainId,
		"owner", universalAccount.Owner,
	)

	abi, err := types.ParseFactoryABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse factory ABI")
	}

	abiUniversalAccount, err := types.NewAbiUniversalAccountId(universalAccount)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal account")
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,        // who is sending the transaction
		factoryAddr, // destination: FactoryV1 contract
		big.NewInt(0),
		nil,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"deployUEA",
		abiUniversalAccount,
	)
}

func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}
