### Title
Unchecked ERC20 `transfer` return value in fee charging allows fee-token contracts to accept payment without asserting success - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo])

### Summary
The reported bug class (unchecked `transferFrom`/`transfer` return value leading to silent failure and loss of funds) maps to the Starknet OS's `charge_fee` function, which invokes an ERC20 `transfer` on the fee token contract to pay the sequencer but never inspects the transfer's returned `success` felt.

### Finding Description
`charge_fee` in `transaction_impls.cairo` builds a `TransferCallData` and executes it via `non_reverting_select_execute_entry_point_func`: [1](#0-0) 

`non_reverting_select_execute_entry_point_func` only asserts that the call did not *revert* (`is_reverted = 0`) and returns `retdata_size`/`retdata` to the caller: [2](#0-1) 

Unlike `run_validate`, which explicitly checks `retdata[0] = VALIDATED` after calling `non_reverting_select_execute_entry_point_func`: [3](#0-2) 

`charge_fee` does **not** check the returned `retdata` (the ERC20 `success` felt per the standard fee-token ABI, which declares `transfer`/`transferFrom` with a `success: felt` output) at all — it simply calls the entry point and returns: [4](#0-3) 

The Rust-side blockifier equivalent, `execute_fee_transfer`, has the same gap: it executes the `transfer` call entry point and only propagates an `Err` if the call itself errors/reverts, never validating the retdata content for a `success` boolean: [5](#0-4) 

So if a fee-token contract class (or a Cairo0 "unsafe" ERC20 variant) returns `success = 0`/`FALSE` without reverting, both the OS re-execution path and the blockifier path treat the fee charge as successful anyway.

### Impact Explanation
Because this logic is part of `charge_fee`, which runs identically in the blockifier and in Starknet OS re-execution, a fee token contract that can be made to return a falsy success value without reverting would let the OS/blockifier commit the transaction as fee-paid while no value was actually moved (or only partial/no value transferred), causing honest-node state divergence between what's committed (fee "charged") and actual token balances, and enabling fee-token supply/accounting inconsistencies at the protocol level. This matches the "unauthorized account action / wrong committed state" impact class analogous to the Cooler.sol lender stealing collateral via unchecked `transferFrom`.

### Likelihood Explanation
This is reachable by any unprivileged transaction sender when the underlying fee token contract's class permits returning `success=0` without reverting the call (e.g., a legacy/Cairo0 ERC20 implementation or a malicious/nonstandard fee-token class declared by a user, if the chain's fee token address/class is not strictly pinned to the canonical STRK/ETH implementation). The current canonical fee-token contracts used by mainnet do assert on transfer success internally (my searches showed only the ABI declaring a `success` output — I could not confirm from the indexed context whether every deployed fee-token class body actually asserts on it), so likelihood depends on which fee-token class is configured; this could not be fully verified from the available indexed files.

### Recommendation
Explicitly assert on the `retdata` returned from the fee-transfer call in both `charge_fee` (Cairo, OS side) and `execute_fee_transfer`/`concurrency_execute_fee_transfer` (Rust, blockifier side), mirroring the pattern already used in `run_validate` (`assert retdata_size = 1; assert retdata[0] = SUCCESS`), so that a non-reverting-but-unsuccessful transfer causes the transaction to fail/revert rather than being silently accepted as a paid fee.

### Proof of Concept
Not independently executable from static review alone; would require deploying/declaring a custom fee-token class whose `transfer` entry point returns `0` (false) without reverting, configuring it as the `fee_token_address` in `os_global_context.starknet_os_config`, then submitting a transaction — expected: fee is recorded as charged in the OS output/receipt even though the ERC20 contract signaled failure via its return value, since neither `charge_fee` (Cairo) nor `execute_fee_transfer` (Rust) checks retdata for a success flag. [6](#0-5)

// Charges a fee from the user.
// If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{
    range_check_ptr,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;
    let max_fee = compute_max_possible_fee(tx_info=tx_info);

    if (max_fee == 0) {
        return ();
    }

    local low_actual_fee;
    %{ LoadActualFee %}
    local calldata: TransferCallData = TransferCallData(
        recipient=block_context.block_info_for_execute.sequencer_address,
        amount=Uint256(low=low_actual_fee, high=0),
    );

    // Verify that the charged amount is not larger than the transaction's max_fee field.
    assert_nn_le(calldata.amount.low, max_fee);

    // TODO(ilya, 01/01/2026): Consider caching the fee_token_class_hash.
    local fee_token_address = block_context.os_global_context.starknet_os_config.fee_token_address;
    let (fee_state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=fee_token_address
    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.
    local execution_context: ExecutionContext = ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=fee_state_entry.class_hash,
        calldata_size=TransferCallData.SIZE,
        calldata=&calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_execute,
            tx_info=tx_info,
            caller_address=tx_info.account_contract_address,
            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context
    );
    return ();
}

// Same as `select_execute_entry_point_func`, but does not support reverts and does
// not have an implicit 'revert_log' argument.
func non_reverting_select_execute_entry_point_func{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, execution_context: ExecutionContext*) -> (
    retdata_size: felt, retdata: felt*, is_deprecated: felt
) {
    let revert_log = init_revert_log();
    let (is_reverted, retdata_size, retdata, is_deprecated) = select_execute_entry_point_func{
        revert_log=revert_log
    }(block_context=block_context, execution_context=execution_context);
    assert is_reverted = 0;
    return (retdata_size, retdata, is_deprecated);
}

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }
