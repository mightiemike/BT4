### Title
Unrestricted `BOOTSTRAP`-address declare bypasses signature validation and fee enforcement at any block height - (File: `crates/starknet_api/src/executable_transaction.rs`)

### Summary
The Starknet OS / blockifier declare-transaction flow contains a special "genesis bootstrap" fast-path that skips `__validate_declare__` execution, nonce incrementing, and fee charging whenever a `Declare` V3 transaction is sent from a hard-coded, publicly known address (`'BOOTSTRAP'`) with `nonce == 0` and zero enforced fee. The gate that is supposed to make this path usable only during genesis is a mutable operator-side config flag (`validate_resource_bounds`) in the gateway, not a protocol-level, block-height-bound check. If that config is off (as the code explicitly documents it is meant to be "during the systems bootstrap phase"), any unprivileged party who can submit a transaction can hit the exact same code path the sequencer uses to bootstrap trusted genesis classes — declaring arbitrary classes for free with no signature check, and permanently claiming any not-yet-declared class hash.

### Finding Description
`DeclareTransaction::is_bootstrap_declare` decides whether a declare transaction should skip all account-related checks: [1](#0-0) 

The only conditions checked are: `sender_address == bootstrap_address()` (a fixed felt derived from the ASCII string `'BOOTSTRAP'`), `nonce == 0`, and `!charge_fee`. There is **no check that the block is the genesis block, that no state exists yet, or that the caller is a privileged/operator entity** — the "bootstrap" identity is just a magic constant that any sender can put in the `sender_address` field of a declare transaction.

`charge_fee` (whether fee is enforced) is derived purely from the transaction's own resource bounds via `enforce_fee`: [2](#0-1) 

i.e., if the attacker sets zero resource bounds, `enforce_fee()` returns `false`, satisfying `is_bootstrap_declare`.

When this path is taken, `AccountTransaction::execute_raw` completely skips `perform_pre_validation_stage` (nonce/fee checks), skips `__validate_declare__`, and directly executes `try_declare`, writing the attacker-supplied `class_hash -> compiled_class_hash` mapping into state: [3](#0-2) 

The equivalent Starknet OS Cairo logic performs the identical unauthenticated write directly into `contract_class_changes`, enforcing only a "declared once" `prev_value=0` semantics — i.e., first writer wins, permanently: [4](#0-3) 

The only real-world defense observed is a gateway-side, chain-config-controlled check that rejects any RPC transaction (including a declare) whose resource bounds yield zero possible fee — but this check is itself gated by a boolean flag that the code documents as being toggled off specifically "during the systems bootstrap phase": [5](#0-4) [6](#0-5) 

This means the security boundary for a genesis-only, unauthenticated, no-fee state-mutation primitive is delegated entirely to a mutable operator setting on one ingress component, rather than to an immutable protocol invariant (e.g., "only accepted if it's block 0" or "only accepted if no prior state exists"). This is directly analogous to the reported Pong-handler issue: a critical state-committing entry point (`pongHandler`/`registryPongHandler`) is guarded only by a caller-supplied, non-cryptographic identity value (a `packetId`/from-address style check) instead of real authorization, letting anyone who knows the "magic" value drive privileged state changes. Here the "magic value" is the literal string `'BOOTSTRAP'` as sender address plus a trivially satisfiable zero-fee condition.

### Impact Explanation
If the `validate_resource_bounds` gate is disabled, misconfigured, or not correctly re-enabled after genesis (which the code's own comments imply is a manual/temporal toggle, not derived from chain state), any unprivileged transaction sender can:
- Declare arbitrary classes for free, bypassing signature validation and fee payment entirely (unauthorized account action / resource-accounting bypass).
- Front-run and permanently "squat" any class hash not yet declared by writing a garbage `compiled_class_hash` for it via the bootstrap path — since the OS/blockifier declare logic enforces `prev_value == 0` (declare-once) semantics, legitimate later declarations of that same `class_hash` will permanently fail, a form of permanent griefing/freezing of a specific class's declaration ability.
- Repeatedly submit such transactions cheaply to consume sequencer/batcher/mempool resources, since no real fee is charged and no account signature validation work is amortized against an attacker-controlled balance.

### Likelihood Explanation
Reachability requires only a single, unprivileged, standard `Declare` V3 RPC transaction with `sender_address = 'BOOTSTRAP'` (a fixed, publicly known constant hard-coded in `starknet_api`), `nonce = 0`, and zero resource bounds — no special network position, staking, or privileged role is needed. The blockifier/OS-level enforcement (`is_bootstrap_declare`) has **no dependency on block height or system state**, so the only thing standing between "genesis bootstrap" and "attacker-triggerable at any time" is whether the gateway's `validate_resource_bounds` flag happens to be enabled at the time the transaction is processed, and whether every ingestion path (gateway RPC, sync/catch-up validation, batcher-internal paths) applies that same check consistently. I was not able to fully verify from the indexed code whether every internal ingestion path (e.g., state-sync catch-up, or non-gateway batcher paths) independently re-applies the `ZeroResourceBounds`/fee-enforcement gate, so the likelihood is conditioned on operational/config correctness of that single gateway-level flag rather than a protocol-level guarantee — this uncertainty should be verified in a full checkout since the index may not include all ingestion code paths.

### Recommendation
Tie the bootstrap-declare fast path to an immutable protocol invariant instead of a mutable, config-controlled gateway check — e.g., only allow it when `block_number == 0` (or more generally, only while no prior state/class has ever been declared, verified at the OS/blockifier level rather than solely at the RPC gateway). Alternatively, remove the general-purpose gateway `validate_resource_bounds` toggle as the sole gate and enforce the "must be genesis" condition directly inside `is_bootstrap_declare` and its Cairo OS counterpart, so that no ingestion path (gateway, sync, batcher-internal) can ever accept a bootstrap-style declare once the chain has progressed past genesis.

### Proof of Concept
1. Ensure (or wait for/trigger) a state where the gateway's `StatefulTransactionValidatorConfig::validate_resource_bounds` is `false` (documented in-code as the expected state "during the systems bootstrap phase" — see `crates/apollo_gateway/src/stateful_transaction_validator.rs:227`).
2. Craft and submit an RPC `Declare` V3 transaction with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (`0x424f4f545354524150`, i.e. ASCII `'BOOTSTRAP'`),
   - `nonce = 0`,
   - `resource_bounds` set so `max_possible_fee() == 0` (as in `mempool_test_utils::starknet_api_test_utils::generate_bootstrap_declare`, `crates/mempool_test_utils/src/starknet_api_test_utils.rs:585-595`),
   - an arbitrary attacker-chosen valid Sierra class + matching `compiled_class_hash`.
3. Observe (per `crates/blockifier/src/transaction/account_transactions_test.rs:905-991`, `test_bootstrap_declare`) that the transaction executes with **no signature/`__validate_declare__` call, no fee charged, no nonce bump**, and directly writes `compiled_class_hashes[class_hash] = compiled_class_hash` into the resulting state diff — exactly the behavior intended only for genesis bootstrapping, now attacker-triggerable outside genesis if the gating config lapses.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.

    fn validate_resource_bounds(
        &self,
        tx: &RpcTransaction,
    ) -> StatelessTransactionValidatorResult<()> {
        if !self.config.validate_resource_bounds {
            return Ok(());
        }

        let resource_bounds = *tx.resource_bounds();
        // The resource bounds should be positive even without the tip.
        if ValidResourceBounds::AllResources(resource_bounds).max_possible_fee(Tip::ZERO) == Fee(0)
        {
            return Err(StatelessTransactionValidatorError::ZeroResourceBounds { resource_bounds });
        }

        if resource_bounds.l2_gas.max_price_per_unit.0 < self.config.min_gas_price {
            return Err(StatelessTransactionValidatorError::MaxGasPriceTooLow {
                gas_price: resource_bounds.l2_gas.max_price_per_unit,
                min_gas_price: self.config.min_gas_price,
            });
        }
