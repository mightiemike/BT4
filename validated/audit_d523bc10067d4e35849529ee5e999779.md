## Title
Concurrent `Declare` compilations for the same class hash race on the on-disk class directory rename, causing spurious `ClassNotFound` errors / crashes during block building - ([File: crates/apollo_class_manager/src/class_storage.rs])

### Summary
The PowerDNS CVE describes concurrent transfers of the *same* RPZ zone racing on shared mutable zone state, leading to inconsistent data, use-after-free, or a crash. The closest reachable analog in this sequencer is `apollo_class_manager`'s `FsClassStorage::set_class` path, which is exercised concurrently — by design, via `max_concurrent_declare_compilations` — whenever multiple `Declare` transactions for the *same* new class are in flight at once. The persist step performs a non-atomic "check-exists → remove → rename" sequence on a directory keyed only by `class_id`, with no per-class lock, so two concurrent declarers of the identical class can race on the filesystem.

### Finding Description
`GatewayStaticConfig::max_concurrent_declare_compilations` (default 40) explicitly documents that Sierra-to-CASM compilations triggered by `Declare` transactions run concurrently: [1](#0-0) 

`ClassManager::add_class` first checks whether the class is already known, and only if not, proceeds to compile it and persist it — the cache check and the eventual write are not protected across the `await` boundary for concurrent duplicate declares of the same class: [2](#0-1) 

`CachedClassStorage::set_class` similarly checks `class_cached` and then delegates to the underlying storage; the check-then-act is not atomic with respect to another concurrent caller for the same `class_id`: [3](#0-2) 

The actual persistence in `FsClassStorage::set_class` writes to a fresh temp dir and renames it into a content-addressed persistent directory keyed only by `class_id`: [4](#0-3) 

The rename helper explicitly handles the case where the persistent directory already exists by deleting it and replacing it — a recovery mechanism intended for crash recovery, but with no synchronization against a genuinely concurrent second writer (or a concurrent reader) for the same `class_id`: [5](#0-4) 

Because `contains_class`/`class_cached` checks race with concurrent writers, two `Declare` transactions carrying the identical Sierra class (an attacker can trivially produce this by submitting the same `Declare` payload twice, or by resubmitting after a mempool eviction/resync) can both pass the "not yet declared" check, both compile, and both call `set_class` concurrently. The second writer's `rename_to_persistent_dir` observes `persistent_dir.exists() == true` (written by the first), deletes it via `remove_dir_all`, and re-renames its own copy over it. Any concurrent reader (`get_sierra`/`get_executable`, which take `&self` and can run via `ClassHashStorage`'s separate storage-reader-server that bypasses the actor's serialized message queue) hitting that directory during the delete/rename window sees the files missing and surfaces `FsClassStorageError::ClassNotFound`, an I/O error, or (in the worst case) reads a torn/partial write if the OS-level rename/remove interleaving is not atomic across the two racing processes.

### Impact Explanation
A transient `ClassNotFound`/I/O error surfacing while a block containing the `Declare` is being certified can break the pipeline that fetches Sierra/CASM classes for the declared class, e.g. the CENDE ambassador flow that must fetch both class artifacts before it can proceed: [6](#0-5) 

If this fetch fails (propagated `.ok_or(CendeAmbassadorError::ClassNotFound{..})?`) during block certification, block finalization for that block can fail or be delayed, and depending on how callers of the class-manager RPC handle the resulting error, this can manifest as node-level instability for any node reading class data at the wrong moment — i.e., an attacker who can get duplicate/simultaneous `Declare`s of the same class processed can intermittently disrupt legitimate class reads needed for block production, a concrete “network unable to confirm new transactions/blocks” type effect for that block.

### Likelihood Explanation
Reaching this requires only submitting ordinary `Declare` transactions for the same class content close together in time — well within reach of a single unprivileged declarer, and explicitly enabled by the sequencer's own concurrency knob (`max_concurrent_declare_compilations`). No malicious operator/proposer/peer role is needed.

### Recommendation
Serialize `set_class`/`write_class_atomically`/`rename_to_persistent_dir` per `class_id` (e.g., via a per-class lock or a global lock keyed by class hash, or by making the "already declared" check-and-write atomic under a single mutex held across the compile+persist sequence), and make sure the recovery path in `rename_to_persistent_dir` only triggers on genuine startup/crash recovery rather than being reachable from steady-state concurrent duplicate declares.

### Proof of Concept
Not independently executed; based on static analysis of `crates/apollo_class_manager/src/class_manager.rs` and `crates/apollo_class_manager/src/class_storage.rs`, combined with `crates/apollo_gateway_config/src/config.rs` confirming concurrent Sierra-to-CASM compilation is a supported, concurrent code path. I was unable to confirm within the tool budget whether the `ClassManager` component's request-handling framework fully serializes `&mut self` calls to `add_class` across all requests (which would narrow, though not eliminate, the race window to the async compile await) or spawns them independently; this is the main remaining uncertainty and would need to be verified in a full Devin session by tracing the `apollo_infra` component server dispatch for `ClassManager`.

    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }

    fn set_class(
        &mut self,
        class_id: ClassId,
        class: RawClass,
        executable_class_hash_v2: ExecutableClassHash,
        executable_class: RawExecutableClass,
    ) -> Result<(), Self::Error> {
        if self.class_cached(class_id) {
            return Ok(());
        }

        self.storage.set_class(
            class_id,
            class.clone(),
            executable_class_hash_v2,
            executable_class.clone(),
        )?;

        increment_n_classes(CairoClassType::Regular);
        record_class_size(ClassObjectType::Sierra, &class);
        record_class_size(ClassObjectType::Casm, &executable_class);

        // Cache the class.
        // Done after successfully writing to storage as an optimization;
        // does not require atomicity.
        self.classes.set(class_id, class);
        self.executable_classes.set(class_id, executable_class);
        // Cache the executable class hash last; acts as an existence marker.
        self.executable_class_hashes_v2.set(class_id, executable_class_hash_v2);

        Ok(())
    }

    /// Atomically moves the staged class directory `tmp_dir` into its content-addressed persistent
    /// directory.
    ///
    /// Recovers from a previous partial write: a crash between this rename and committing the
    /// existence marker (see `FsClassStorage::set_class`) can leave an orphaned, non-empty
    /// persistent directory. `std::fs::rename` refuses to replace a non-empty directory and fails
    /// with `ENOTEMPTY`, which permanently wedges sync on the class. Callers reach this only when
    /// the existence marker is absent, and the directory is named by the class hash, so an existing
    /// directory holds the same class; removing it lets the rename proceed and the marker get
    /// written, restoring filesystem/marker consistency.
    fn rename_to_persistent_dir(
        &self,
        tmp_dir: PathBuf,
        class_id: ClassId,
    ) -> FsClassStorageResult<()> {
        let persistent_dir = self.get_persistent_dir_with_create(class_id)?;
        if persistent_dir.exists() {
            warn!("Recovering orphaned class dir from a prior partial write: {persistent_dir:?}");
            std::fs::remove_dir_all(&persistent_dir)?;
        }
        std::fs::rename(tmp_dir, persistent_dir)?;

        Ok(())
    }

async fn get_contract_classes_if_declare(
    class_manager: SharedClassManagerClient,
    tx: &InternalConsensusTransaction,
) -> CendeAmbassadorResult<Option<(CentralSierraContractClassEntry, CentralCasmContractClassEntry)>>
{
    // Check if the tx is declare, otherwise return None.
    let InternalConsensusTransaction::RpcTransaction(InternalRpcTransaction {
        tx: InternalRpcTransactionWithoutTxHash::Declare(declare_tx),
        ..
    }) = &tx
    else {
        return Ok(None);
    };

    let class_hash = declare_tx.class_hash;

    // TODO(yael, dvir): get the classes in parallel from the class manager.
    let ContractClass::V1(casm) = class_manager
        .get_executable(class_hash)
        .await?
        .ok_or(CendeAmbassadorError::ClassNotFound { class_hash })?
    else {
        panic!("Only V1 contract classes are supported");
    };

    let hashed_casm = (declare_tx.compiled_class_hash, CentralCasmContractClass::from(casm.0));
    let sierra = class_manager
        .get_sierra(class_hash)
        .await?
        .ok_or(CendeAmbassadorError::ClassNotFound { class_hash })?;
    let hashed_sierra = (class_hash, CentralSierraContractClass { contract_class: sierra });

    Ok(Some((hashed_sierra, hashed_casm)))
}
