### Title
Committee-controlled feature flags gating UnfreezeV2/CancelAllUnfreezeV2 are enforced in the Actuator path but not in the TVM native-contract path - ([File: actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceV2Processor.java])

### Summary
The reported bug class (a state-changing function that omits a protocol-wide gating check that its sibling functions consistently enforce) has a concrete analog in java-tron's resource-unfreeze (UnfreezeV2) feature. The `*Actuator` classes that handle wallet-submitted transactions consistently gate execution behind committee-controlled `DynamicPropertiesStore` flags, but the corresponding `*Processor` classes that implement the same operations as TVM native contracts (callable from smart contract code, e.g. via `Program.java`) omit these same gating checks.

### Finding Description
For the UnfreezeV2 feature family, the wallet-facing actuators enforce the feature flag before executing:
- `UnfreezeBalanceV2Actuator.validate()` checks `if (!dynamicStore.supportUnfreezeDelay())` and reverts with "Not support UnfreezeV2 transaction, need to be opened by the committee". [1](#0-0) 
- `WithdrawExpireUnfreezeActuator.validate()` performs the identical check. [2](#0-1) 
- `CancelAllUnfreezeV2Actuator.validate()` checks `if (!dynamicStore.supportAllowCancelAllUnfreezeV2())` and reverts. [3](#0-2) 

However, the equivalent TVM native-contract implementations, which are reachable from smart contract bytecode through `Program.java` (see `cancelAllUnfreezeV2Action()`), do not perform these same flag checks:
- `UnfreezeBalanceV2Processor.validate()` never calls `dynamicStore.supportUnfreezeDelay()`. [4](#0-3) 
- `WithdrawExpireUnfreezeProcessor.validate()` also omits the `supportUnfreezeDelay()` check present in its Actuator counterpart. [5](#0-4) 
- `CancelAllUnfreezeV2Processor.validate()` omits the `supportAllowCancelAllUnfreezeV2()` check present in `CancelAllUnfreezeV2Actuator`. [6](#0-5) 

`Program.java` calls `CancelAllUnfreezeV2Processor.validate()`/`execute()` directly, with no additional feature-flag gating at the call site. [7](#0-6) 

This is directly analogous to the `HolyPaladinToken.cooldown()` finding: a subset of state-mutating entry points for the same feature family lack a protection check ("emergency"/feature-enable flag) that parallel functions consistently apply, creating an inconsistent security posture across code paths implementing the same logical operation.

### Impact Explanation
`UNFREEZE_DELAY_DAYS` and `ALLOW_CANCEL_ALL_UNFREEZE_V2` are committee-controlled chain parameters that must be explicitly approved via governance proposal before the UnfreezeV2/CancelAllUnfreezeV2 feature is meant to be active on the network (see `ProposalUtil.java`, which requires `UNFREEZE_DELAY_DAYS` to be non-zero before `ALLOW_CANCEL_ALL_UNFREEZE_V2` can even be proposed). [8](#0-7) 
If the TVM entry point (invoked from a smart contract via the corresponding precompiled/native-contract opcode) can be reached while the flag is not yet enabled by governance, a smart-contract-mediated caller could execute unfreeze/withdraw/cancel-unfreeze logic in a mode not sanctioned by the committee, bypassing the intended governance gate — an invalid-state / control-bypass condition analogous in kind (though not identical in mechanism) to the referenced report's "bypass emergency mode intent" impact.

### Likelihood Explanation
Exploitability depends on whether these TVM native-contract code paths (`UnfreezeBalanceV2Processor`, `WithdrawExpireUnfreezeProcessor`, `CancelAllUnfreezeV2Processor`) are actually reachable while the associated `DynamicPropertiesStore` flag is disabled — i.e., whether the calling opcode/precompile in the TVM (`VMConfig`/`Program.java`) is itself gated by the same flag before dispatch. I was only able to fully confirm the call site for `cancelAllUnfreezeV2Action()` in `Program.java`, which does not add the flag check before invoking the processor; I could not locate the corresponding `unfreezeBalanceV2Action`/`withdrawExpireUnfreezeAction` methods in `Program.java` within the available search results, so it is uncertain whether those two entry points might be independently gated elsewhere (e.g., in `VMConfig.allowXXX()` checks at opcode dispatch time) before reaching the processor's `validate()`. This should be verified directly in the full `Program.java` and `VMConfig.java` source, which may not be fully covered by the code index.

### Recommendation
Add the same committee-controlled feature-flag checks used in the corresponding Actuators to the TVM native-contract processors' `validate()` methods:
- `UnfreezeBalanceV2Processor.validate()`: add `if (!dynamicStore.supportUnfreezeDelay()) throw new ContractValidateException(...)`.
- `WithdrawExpireUnfreezeProcessor.validate()`: same check.
- `CancelAllUnfreezeV2Processor.validate()`: add `if (!repo.getDynamicPropertiesStore().supportAllowCancelAllUnfreezeV2()) throw new ContractValidateException(...)`.

This ensures TVM-callable and wallet-callable code paths for the same feature enforce identical governance gating, consistent with the `cooldown()`-in-`HolyPaladinToken.sol` mitigation pattern of adding the missing guard to the outlier function.

### Proof of Concept
Concrete exploitation could not be fully constructed without confirming the TVM opcode dispatch path in `Program.java`/`VMConfig.java` (not fully available in the indexed code). The structural PoC is:
1. Committee has not yet approved `UNFREEZE_DELAY_DAYS` (i.e., `dynamicStore.getUnfreezeDelayDays() == 0`, `supportUnfreezeDelay() == false`).
2. A normal wallet transaction calling `UnfreezeBalanceV2Actuator` would be rejected with "Not support UnfreezeV2 transaction, need to be opened by the committee" per [1](#0-0) .
3. If a smart contract can invoke the equivalent TVM native-contract path that dispatches into `UnfreezeBalanceV2Processor.validate()`/`execute()` without going through the Actuator's flag check, the same operation would succeed despite the feature not being enabled by governance, since `UnfreezeBalanceV2Processor.validate()` never inspects `supportUnfreezeDelay()` [9](#0-8) .

  public void validate(UnfreezeBalanceV2Param param, Repository repo)
      throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (accountCapsule == null) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + readableOwnerAddress + "] does not exist");
    }
    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    int unfreezingCount = accountCapsule.getUnfreezingV2Count(now);
    if (UnfreezeBalanceV2Actuator.getUNFREEZE_MAX_TIMES() <= unfreezingCount) {
      throw new ContractValidateException("Invalid unfreeze operation, unfreezing times is over limit");
    }
    switch (param.getResourceType()) {
      case BANDWIDTH:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.BANDWIDTH)) {
          throw new ContractValidateException("no frozenBalance(BANDWIDTH)");
        }
        break;
      case ENERGY:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.ENERGY)) {
          throw new ContractValidateException("no frozenBalance(ENERGY)");
        }
        break;
      case TRON_POWER:
        if (dynamicStore.supportAllowNewResourceModel()) {
          if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.TRON_POWER)) {
            throw new ContractValidateException("no frozenBalance(TRON_POWER)");
          }
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (dynamicStore.supportAllowNewResourceModel()) {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }

    if (!checkUnfreezeBalance(accountCapsule, param.getUnfreezeBalance(), param.getResourceType())) {
      throw new ContractValidateException(
          "Invalid unfreeze_balance, [" + param.getUnfreezeBalance() + "] is invalid");
    }
  }
