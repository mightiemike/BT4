Both message-fee computation and L1 data-gas computation in `blockifier` mirror the Optimism `MIN_GAS_CALLDATA_OVERHEAD` flaw: they charge Ethereum calldata gas at the flat non‑zero-byte rate (16 gas/byte) for message payload data, ignoring that many bytes of a felt are typically zero (which cost only 4 gas/byte on Ethereum). This directly overcharges transaction senders (L1 handler senders and any account emitting L2→L1 messages), and the overcharge flows straight into the actual `Fee` charged, matching the root cause and impact of the reported issue.

### Title
L1<->L2 message resource fee overcharges senders by using flat non-zero-byte gas rate instead of actual zero/non-zero byte counting - (File: crates/blockifier/src/fee/resources.rs)

### Summary
`MessageResources::get_starknet_gas_cost` charges L1/L2 messaging gas as `message_segment_length * eth_gas_constants::GAS_PER_MEMORY_WORD`, where `GAS_PER_MEMORY_WORD = GAS_PER_MEMORY_BYTE * WORD_WIDTH = 16 * 32 = 512`. This assumes every byte of every message-segment word (i.e., every felt in the L1↔L2 message payload) is a non-zero byte costing 16 gas, exactly like the flawed `MIN_GAS_CALLDATA_OVERHEAD` in the referenced Optimism report, which charged 16 gas/byte uniformly instead of the correct 4 gas for zero bytes. [1](#0-0) 

### Finding Description
The codebase already contains the *correct* per-byte accounting utility, `get_calldata_word_cost`, which properly differentiates zero bytes (4 gas) from non-zero bytes (16 gas): [2](#0-1) 

and constants `GAS_PER_MEMORY_ZERO_BYTE = 4` vs `GAS_PER_MEMORY_BYTE = 16`: [3](#0-2) 

However, `MessageResources::get_starknet_gas_cost` (used to price both L1→L2 handler messages and L2→L1 messages) never calls this helper. Instead it multiplies the entire `message_segment_length` (computed in `get_message_segment_length`, which sums word-granularity payload sizes for L1↔L2 messages) by the flat word rate `GAS_PER_MEMORY_WORD`: [1](#0-0) [4](#0-3) 

Since each Starknet felt occupies a 32-byte word and the vast majority of realistic payload values (addresses, small amounts, selectors, nonces) contain many leading zero bytes, this systematically overcharges L1 gas for every byte that is actually zero — the exact same class of overpayment identified in the Optimism `CrossDomainMessenger.baseGas` report.

This fee computation is not cosmetic: `TransactionReceipt::from_params` feeds the resulting `GasVector` (which includes `MessageResources::to_gas_vector`) directly into `tx_context.tx_info.get_fee_by_gas_vector(...)`, which becomes the transaction's actual charged `Fee`: [5](#0-4) 

This path is reachable both by L1 handler transactions (`TransactionReceipt::from_l1_handler`) and ordinary account transactions that emit L2→L1 messages (`TransactionReceipt::from_account_tx`), so any unprivileged sender who deposits from L1 or sends an L2→L1 message via the `send_message_to_l1` syscall is forced to overpay. [6](#0-5) 

### Impact Explanation
Every L1 handler transaction (i.e., every L1→L2 deposit/message) and every transaction sending an L2→L1 message is charged L1 gas as if all payload bytes were non-zero. Since felt payloads (addresses, amounts, selectors) are overwhelmingly zero-padded, users concretely overpay fees on essentially every cross-domain message, directly mirroring the "L1 depositors overpays gas fees" impact of the original report — a concrete, permanent loss of user funds (excess fee paid) with no way for the affected sender to recover the overcharge.

### Likelihood Explanation
This triggers on the default/common path with 100% likelihood: any user submitting a transaction with at least one L2→L1 message, or the sequencer processing an L1 handler transaction, hits this exact code, no adversarial condition required.

### Recommendation
Compute the message-segment gas cost using the accurate per-byte breakdown (`get_calldata_word_cost`, or equivalent exact zero/non-zero byte counting over the serialized felt data) instead of the flat `GAS_PER_MEMORY_WORD` rate in `MessageResources::get_starknet_gas_cost`, consistent with how `get_da_gas_cost` already attempts a partial discount for known always-populated fields.

### Proof of Concept
Consider an L1 handler transaction whose payload consists of felts encoding small values (e.g., addresses/amounts each < 2^32, so 28 of the 32 bytes per felt are zero). `get_message_segment_length` returns the payload size in words/felts, and `get_starknet_gas_cost` charges `message_segment_length * 512` gas — i.e., 16 gas for every one of the 32 bytes in each felt, including the ~28 zero bytes that should cost only 4 gas each. The correct cost per felt-word using `get_calldata_word_cost(4)` (4 non-zero bytes) would be `4*16 + 28*4 = 176` gas instead of `512` gas — nearly 3x overcharge per word, directly increasing the `Fee` returned by `TransactionReceipt::from_l1_handler`/`from_account_tx`.

/// Returns the number of felts added to the output messages segment as a result of adding
/// a transaction with the given parameters to a batch. Note that constant cells - such as the one
/// that holds the segment size - are not counted.
pub fn get_message_segment_length(
    l2_to_l1_payload_lengths: &[usize],
    l1_handler_payload_size: Option<usize>,
) -> usize {
    // Add L2-to-L1 message segment length; for each message, the OS outputs the following:
    // to_address, from_address, payload_size, payload.
    let mut message_segment_length = l2_to_l1_payload_lengths
        .iter()
        .map(|payload_length| constants::L2_TO_L1_MSG_HEADER_SIZE + payload_length)
        .fold(0, |accumulator, length| {
            usize::checked_add(accumulator, length).expect(
                "Sending a message to L1 costs gas proportional to payload, so total cannot \
                 exceed usize.",
            )
        });

    if let Some(payload_size) = l1_handler_payload_size {
        // The corresponding transaction is of type L1 handler; add the length of the L1-to-L2
        // message sent by the sequencer (that will be outputted by the OS), which is of the
        // following format: from_address=calldata[0], to_address=contract_address,
        // nonce, selector, payload_size, payload=calldata[1:].
        message_segment_length += constants::L1_TO_L2_MSG_HEADER_SIZE + payload_size;
    }
