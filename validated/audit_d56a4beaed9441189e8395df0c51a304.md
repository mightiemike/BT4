Missing declared-class validation in Starknet OS `execute_replace_class` allows a contract to replace its class with an undeclared class hash - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS implementation of the `replace_class` syscall in the Cairo (SNOS) code path contains an explicit, acknowledged gap: it does not verify that the requested `class_hash` corresponds to a previously declared contract class before writing it into the contract's state entry. This mirrors the reported bug class exactly — a function whose name/position implies validation (`execute_replace_class`) omits a check that a sibling implementation (the Rust blockifier) does perform, creating divergence between the two code paths that must produce identical state transitions.

### Finding Description
In the SNOS Cairo implementation: [1](#0-0) 

The comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` at line 902 confirms the class-hash existence check is not implemented — the code reads `request.class_hash` and unconditionally writes it into the contract's `StateEntry` via `dict_update`, with no assertion that the class was ever declared.

By contrast, the Rust blockifier's syscall handler for the same operation *does* perform this check, reading the compiled class (which fails if undeclared) and additionally validating the class is a Cairo1 class before allowing replacement: [2](#0-1) 

and the deprecated syscall handler similarly calls `get_compiled_class` first: [3](#0-2) 

This is directly analogous to the reported `add_auth_descriptor()` bug: a validation routine (`validate_auth_descriptor_args()`in the report, `execute_replace_class` here) is expected to enforce an invariant (signatures_required > 0 / class must be declared) but silently omits the check, while a parallel code path (`ft_auth`'s loop / the blockifier's `replace_class`) still enforces it implicitly — masking the bug until the implementations diverge or an edge case is hit.

The Starknet OS is re-executed to produce the committed state root and is the ultimate source of truth for state transitions used in proving/verification. Any contract (invoked via a single, unprivileged transaction calling the `replace_class` syscall, e.g. through `__execute__`) reaches this code path directly — no special privilege is required, matching the "unprivileged transaction sender" reachability requirement.

### Impact Explanation
If the OS-level `replace_class` handler accepts an undeclared (or otherwise invalid, e.g. Cairo0) class hash while the blockifier rejects it, the two execution engines diverge on the resulting state (a contract's `class_hash` field in its `StateEntry`, and thus the computed Patricia/state commitment root) for the exact same transaction. This is a "wrong committed root" / "honest-node divergence" class of impact: the blockifier (used for candidate block building/consensus) would reject a transaction that replaces a contract's class with a non-existent class hash, while the OS (used for proof generation / re-execution and the final committed state) would accept it and commit a class hash for which no compiled class exists in the state, corrupting subsequent calls to that contract and potentially permanently bricking or hijacking contract functionality tied to that address, and causing block-hash/state-root divergence between the two independently-executing code paths.

### Likelihood Explanation
Likelihood is currently constrained: while the code path is reachable by any unprivileged contract via a plain invoke transaction issuing the `replace_class` syscall, the practical exploitability depends on whether the OS hint (`GetContractAddressStateEntry`) or another Python-side hint implementation performs the missing declared-class check outside of the visible Cairo code (this cannot be confirmed from the indexed files). The developers' own explicit TODO comment (dated for 2026-01-01) is strong first-party acknowledgment that the check is currently missing in the Cairo assertions, which is the strongest available signal, but it is marked as a future task rather than a report of an active exploited bug, so severity should be treated as Medium given the uncertainty around hint-side mitigation.

### Recommendation
Add an explicit assertion in `execute_replace_class` (in `syscall_impls.cairo`) that the compiled class for `request.class_hash` exists in `contract_class_changes` (or the relevant declared-classes tracking structure) before performing the `dict_update`, mirroring the blockifier's `get_compiled_class` check in `crates/blockifier/src/execution/syscalls/syscall_base.rs` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`. This closes the divergence between the OS and blockifier execution paths for the `replace_class` syscall.

### Proof of Concept
Not independently reproducible from the indexed code alone since the hint implementation behind `%{ GetContractAddressStateEntry %}` (Python side) is not present in the code index — it is possible (but unconfirmed) that the missing check is enforced there. A concrete PoC would require: (1) declaring nothing, (2) invoking a contract whose `__execute__` calls the `replace_class` syscall with an arbitrary undeclared `class_hash`, and (3) running the same transaction through both the blockifier and the OS/SNOS re-execution to observe whether the blockifier rejects it (`ForbiddenClassReplacement`/`UndeclaredClassHash`) while the OS accepts it and commits a different state root. This verification step could not be completed with the available read-only tools; a Devin session with full repo/build access would be needed to confirm whether the Python hint enforces the check that the Cairo code (per its own TODO) does not.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
