### Title
Vault `accrue` pause pass-through returns stale index/lindex, which the market caches and treats as fresh for the rest of the block - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every vault contract implements a "pause pass-through" for its `accrue` entry point: when `pause-states.accrue` is `true`, the function skips all index recomputation and simply returns the **currently stored** `index`/`lindex` wrapped in `(ok ...)` instead of reverting [1](#0-0) . The market contract's `accrue-and-cache` treats whatever `vault-accrue` returns as canonical fresh data and stores it in `index-cache` keyed only by `{ timestamp: stacks-block-time, aid }`, then every subsequent read of that asset's index within the same block/transaction (debt valuation, ztoken price resolution via `resolve-ztoken`, health checks) is served from this cache without distinguishing "fresh" from "paused pass-through" values [2](#0-1) .

### Finding Description
1. `accrue` reads `pause-states`, `index`, `lindex` and, if `(get accrue states)` is true, short-circuits to `(ok { index: idx, lindex: lidx })` using the *current* (potentially many blocks old) stored values, never calling `next-index`/`next-liquidity-index`, and never updating `last-update` [3](#0-2) .
2. `market.clar`'s `accrue-and-cache` calls `vault-accrue aid` on a cache miss and unconditionally stores the returned `{index, lindex}` into `index-cache` for the current `stacks-block-time` [2](#0-1) . There is no flag distinguishing "this value is stale because the vault is paused" from "this value was freshly accrued" — both are cached identically.
3. All later reads in the same transaction for that `aid` — `accrue-debt-asset` for the caller's own debt, `accrue-collateral-asset` for rehypothecated (ztoken) collateral, and `resolve-ztoken` price resolution used for health checks and liquidation pricing — pull from this same cache entry [4](#0-3) [5](#0-4) .
4. Because the pause check is evaluated once, inside `accrue`, and the vault's true (unpaused) index would have been higher, a multi-step market operation (e.g., a composite tx that supplies/withdraws multiple assets, or a liquidation that both prices ztoken collateral and computes debt) that touches a paused vault will consistently use the stale, lower index for every operation on that asset for the whole block — including the liquidation health check and the subsequent seize/repay step that "changes what it checked." The pass-through is a deliberate design choice per-vault, but because market caches its output as if genuine, any downstream computation keyed off that index (ztoken price via `resolve-ztoken`, `resolve-callcode`) silently uses under-accrued interest data for that entire block, without any revert or warning that the value is degraded.

### Impact Explanation
Under-accrued debt index during a paused-accrue block understates a borrower's actual debt for every borrow/repay/health-check computation in that block, and understates a ztoken's `lindex`-scaled value for every collateral valuation in that block. This falls under temporary freezing/mispricing of funds: liquidations that should be triggered based on true debt growth can be blocked (temporary freezing of the ability to seize the correct amount of collateral, or bad debt socialization is delayed), and yield reflected by `lindex` used for ztoken collateral pricing is under-reported for the duration of the pause, which can misstate unclaimed yield in cross-asset health/pricing computations. This lands in the High impact bucket (temporary freezing of funds / theft or freezing of unclaimed yield), since it does not directly move principal but corrupts the block's shared index-cache used by every subsequent computation.

### Likelihood Explanation
Likelihood is contingent on the vault's `accrue` pause flag being enabled by governance/ops, which is an expected admin state (not "DAO compromise") — pausing accrual for a single vault is a normal operational lever, and once active it interacts silently with market.clar's per-block cache for as long as the pause persists, affecting every user transaction touching that asset during that window. No attacker action is required beyond normal usage while the pause is active, but occurrence is bounded to periods when this specific pause is set.

### Recommendation
Distinguish "paused pass-through" indexes from "freshly accrued" indexes at the market layer — e.g., have vault `accrue` return a `paused: bool` flag and have `accrue-and-cache` either avoid caching stale-pass-through results as valid for pricing/health-check purposes, or explicitly revert/exclude the affected asset from operations that depend on precise index freshness (borrow, liquidation health checks, ztoken price resolution) while its accrual is paused.

### Proof of Concept
1. Governance pauses `accrue` on `vault-stx` (sets `pause-states.accrue = true`) while leaving `borrow`/`redeem` operational for the market's other flows that don't call the vault's own guarded entry points directly.
2. A user transaction touches `STX`/`zSTX` in a multi-asset operation: `accrue-user-debts`/`accrue-user-collateral` call `accrue-and-cache STX`, which calls `vault-accrue`, hits the pause branch, and returns the old stored `index`/`lindex` [3](#0-2) .
3. `market.clar` caches this stale pair under `index-cache { timestamp: stacks-block-time, aid: STX }` [6](#0-5) .
4. The same transaction's health check / liquidation pricing calls `resolve-ztoken` for `zSTX`, which reads the cached (stale) `lindex` via `get-cached-indexes` [5](#0-4) , computing a collateral/debt valuation that does not reflect true accrued interest for the duration of the pause, distorting the liquidation/borrow decision made in that same transaction.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
