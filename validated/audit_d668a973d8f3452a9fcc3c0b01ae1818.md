The premise doesn't hold in the production code. In `crates/aptos-crypto/src/multi_ed25519.rs`, `MultiEd25519Signature`'s `bitmap` field is a fixed-size `[u8; BITMAP_NUM_OF_BYTES]` array (`BITMAP_NUM_OF_BYTES = 4`, i.e. exactly 32 bits), which matches `MAX_NUM_OF_KEYS = 32` [1](#0-0) . There is no mechanism for an attacker to set "bits beyond `BITMAP_NUM_OF_BYTES*8`" because the type itself has no storage for such bits — any bit index beyond 31 simply cannot be represented in this 4-byte array, so there is nothing to "silently truncate."

`bitmap_last_set_bit` iterates over exactly these 4 bytes and can only ever return a value in `0..=31` [2](#0-1) . `verify_arbitrary_msg` then checks `last_bit as usize < public_key.public_keys.len()`, a strict less-than comparison against the actual number of deserialized sub public keys [3](#0-2) . Since `public_keys.len() <= MAX_NUM_OF_KEYS = 32` and `last_bit <= 31`, this check correctly rejects any bitmap whose highest set bit falls outside the actual key range — there's no truncation window to exploit because the representable index space and the checked index space are the same fixed 32-bit domain.

Additionally, `TryFrom<&[u8]>` for `MultiEd25519Signature` independently enforces `bitmap_count_ones(bitmap) == num_of_sigs` and `num_of_sigs <= MAX_NUM_OF_KEYS`, and `bitmap_get_bit`/`bitmap_index` bounds are further guarded by `public_key.public_keys.get(bitmap_index)` returning an error on out-of-bounds access rather than panicking or silently succeeding [4](#0-3) [5](#0-4) .

(Note: the legacy `third_party/move/move-examples/diem-framework/crates/crypto/src/multi_ed25519.rs` variant uses `<=` instead of `<` in its analogous check, which is a genuine off-by-one, but that file lives under `move-examples` and is explicitly out of scope per the exclusion rules for examples, and is not part of the production Aptos framework signature-verification path.)

    fn try_from(bytes: &[u8]) -> std::result::Result<MultiEd25519Signature, CryptoMaterialError> {
        let length = bytes.len();
        let bitmap_num_of_bytes = length % ED25519_SIGNATURE_LENGTH;
        let num_of_sigs = length / ED25519_SIGNATURE_LENGTH;

// Find the last set bit.
fn bitmap_last_set_bit(input: [u8; BITMAP_NUM_OF_BYTES]) -> Option<u8> {
    input
        .iter()
        .rev()
        .enumerate()
        .find(|(_, byte)| byte != &&0u8)
        .map(|(i, byte)| (8 * (BITMAP_NUM_OF_BYTES - i) - byte.trailing_zeros() as usize - 1) as u8)
}
