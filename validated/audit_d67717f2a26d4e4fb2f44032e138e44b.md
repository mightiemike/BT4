Found a concrete analog. `Keeper.ExecutePayload` (the handler wired to `MsgExecutePayload` via `msg_server.go`) executes the UEA payload and deducts gas fees **directly on `sdkCtx`**, without the `CacheContext` isolation that its sibling `ExecutePayloadV2` uses.

### Title
Missing atomic rollback on `MsgExecutePayload` gas-fee deduction allows free/uncharged arbitrary UEA execution — ([File: x/uexecutor/keeper/msg_execute_payload.go])

### Summary
`ExecutePayloadV2` explicitly wraps `CallUEAExecutePayload` + `DeductGasFeesFromReceipt` in a `sdkCtx.CacheContext()` specifically "to close the free-execution gap when the UEA has no native UPC to cover gas" [1](#0-0) . The legacy handler `ExecutePayload`, which is what `msgServer.ExecutePayload` actually calls for the on-chain `MsgExecutePayload` message [2](#0-1) , performs the exact same two steps but directly on `sdkCtx` with no cache/rollback wrapper [3](#0-2) .

### Finding Description
This mirrors the vault bug's core defect class: an auxiliary step of a compound operation (the fee/repayment leg) is not enforced atomically with the primary state-changing leg, letting the caller retain the benefit of the primary action while evading the associated obligation.

In `ExecutePayload`:
1. `CallUEAExecutePayload` runs the arbitrary EVM call authorized by the owner's payload signature directly against `sdkCtx` — any state changes it makes (transfers, PRC20 moves, `msg.value` sends, self-destructs, etc.) are committed to the real state tree as soon as the underlying EVM keeper commits them, since there's no cache scope around it [4](#0-3) .
2. Only afterward does `DeductGasFeesFromReceipt` attempt to bill the UEA for the gas it just used, on the same uncached `sdkCtx` [5](#0-4) .
3. If the payload itself drains the UEA's `upc` balance (e.g., transfers the balance out to another address the owner controls) below what's needed to cover gas, `DeductGasFeesFromReceipt`'s `DeductAndBurnFees` call fails with insufficient balance [6](#0-5) , and `ExecutePayload` returns an error — but the EVM state changes from step 1 (the drain) were never wrapped in anything that gets discarded on this Go-level return; only the caller of the whole Cosmos message (the ante/runTx machinery) can revert, and only if the SDK's own message-level cache reverts on a returned error. The developer comment on the parallel `ExecutePayloadV2` explicitly documents that without the `CacheContext`, this exact gap exists: "closes the free-execution gap when the UEA has no native UPC to cover gas" [7](#0-6) .

Whether the outer `runMsgs`/`baseapp` message execution wraps each `Msg` in its own cache (which would still make this safe) is the open question the two functions' asymmetry raises: `ExecutePayloadV2`'s author clearly believed uncached execution was unsafe (hence writing a dedicated fix), yet the actually-wired `ExecutePayload` for `MsgExecutePayload` was left in the "before" state. This is directly analogous to the Trail-of-Bits Algorand vault report: the primary transfer (mint / EVM execution) happens without an atomically-enforced check on the auxiliary payment (fee), so the attacker keeps the value transferred by the primary leg without paying the associated cost.

### Impact Explanation
If reachable (i.e., if Cosmos SDK's per-message execution does not already provide equivalent all-or-nothing state isolation for `x/uexecutor`'s handler — this needs confirmation against the actual `baseapp`/`runMsgs` wiring, which was not directly inspected), an unprivileged UEA owner could submit a self-authorized `MsgExecutePayload` whose payload moves all spendable `upc` out of the UEA (or otherwise depletes it) before the fee-deduction step runs, causing fee deduction to fail while the fund-draining EVM call's effects persist. This directly violates the "gas fee accounting" and "unauthorized state transitions in universal execution flows" invariants named in the allowed-impact list, letting an attacker execute arbitrary authorized UEA transactions while evading the protocol's gas billing — a version of "unauthorized withdrawal without paying the corresponding cost."

### Likelihood Explanation
Medium-to-Low confidence without confirming baseapp-level atomicity: Cosmos SDK's default `runMsgs` does execute each message inside its own `CacheMultiStore` branch that is only committed if the message returns no error, which — if that's the deployment here — would already prevent this exact gap and make `ExecutePayloadV2`'s explicit `CacheContext` merely defense-in-depth/redundant rather than a necessary fix for a real gap. The fact that a dedicated, commented fix (`ExecutePayloadV2`) exists specifically to "close the free-execution gap" strongly suggests the author observed or reasoned about a real gap in the uncached path, but I could not fully verify from the indexed code whether `ExecutePayload` (the wired handler) inherits the same protection transitively via `x/uexecutor`'s `MsgServer` wiring or a shared ante/runMsgs cache layer.

### Recommendation
Wrap `CallUEAExecutePayload` and `DeductGasFeesFromReceipt` in `ExecutePayload` (used by `MsgExecutePayload`) in the same `sdkCtx.CacheContext()` pattern already used in `ExecutePayloadV2`, so EVM execution and fee deduction commit or roll back together, exactly as documented in `execute_payload.go`.

### Proof of Concept
Conceptual PoC (pending confirmation of SDK-level message atomicity):
1. Attacker deploys/owns a UEA with a small `upc` balance sufficient to look "funded."
2. Attacker submits `MsgExecutePayload` whose `UniversalPayload.Data` calls the UEA to transfer out (or burn) essentially its entire `upc` balance to an address the attacker controls, leaving it below the gas cost that will be computed post-execution.
3. `ExecutePayload` calls `CallUEAExecutePayload` on `sdkCtx` — the transfer executes and (if not further protected upstream) commits.
4. `DeductGasFeesFromReceipt` then fails due to insufficient UEA balance, and `ExecutePayload` returns an error.
5. If the outer message dispatch does not independently discard the state committed in step 3, the attacker has moved funds out of the UEA via a real EVM state transition while never paying the gas fee for that execution — the fee obligation tied to the state-changing action was skipped, mirroring the vault's missing RekeyTo/Tx2 check that let the attacker keep vault value without repaying wAlgo.

	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr

// ExecutePayload handles universal payload execution on the UEA.
func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}

func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}
