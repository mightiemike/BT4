## Analysis

The Trail of Bits finding is about an AMM (`LiquidityPool.computeOutputAmount`) executing swaps with no slippage/minimum-output enforcement, letting sandwich bots extract value from users. Push Chain's own module code implements a very similar swap flow — and while it does add a slippage parameter, the slippage bound is derived from the *same* spot price it is about to trade against, in the *same* execution, which reproduces the underlying vulnerability class rather than fixing it.

### Where the pattern lives

Two module-driven, unprivileged-user-triggered flows swap protocol/user funds through an on-chain Uniswap V3 pool using a "quote-then-swap" pattern where the quote and the trade both read/hit the same live pool state:

1. **Gas-abstraction inbound deposit swap** — `ExecuteInboundGas` (triggered by an ordinary `GAS` bridge deposit) and `gasAndPayloadDepositAutoSwap` (triggered by `GAS_AND_PAYLOAD`): [1](#0-0) [2](#0-1) 

2. **Excess-gas refund swap** — `applyGasRefund`, triggered whenever `MsgVoteOutbound` finalizes an outbound with `gasFeeUsed < gasFee`: [3](#0-2) 

Both paths call `GetSwapQuote`, which calls `QuoterV2.quoteExactInputSingle` against the live pool state: [4](#0-3) 

and then derive `minPCOut` as a flat `quote * 95 / 100` from that same quote, immediately passing it into the swap call (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`) that executes against the identical pool in the same keeper invocation: [5](#0-4) [6](#0-5) 

### Why this doesn't provide real slippage protection

The commit history explicitly frames this as the slippage fix for a previously "0-slippage" call: [7](#0-6) 

However, `minPCOut` bounds only the *movement between quote and execution*, not manipulation *of* the quote itself — because both the quote and the trade read the same permissionless, unprivileged-accessible Uniswap V3 pool (`WPC`/gas-token pair) within the same block/transaction context. An ordinary user (no validator, no admin, no TSS role) can:

1. Watch the mempool for a `MsgVoteInbound`/`MsgVoteOutbound` that will cross the 2/3 threshold and trigger `ExecuteInboundGas` / `applyGasRefund` for a victim's deposit or refund.
2. Front-run with a swap on the same pool that depresses the `PRC20 → WPC` price.
3. The module's `GetSwapQuote` call reads this manipulated price, computes `minPCOut = manipulatedQuote * 0.95`, and the subsequent swap executes against the manipulated pool without reverting (it's "protected" only relative to the price the attacker just set).
4. Back-run by reversing the manipulation trade, capturing the spread that should have gone to the depositor/refund recipient.

This directly corrupts refund accounting and gas-abstraction deposit accounting — the victim receives less native PC than a fair-value swap would have produced, and the difference is extracted by an unprivileged attacker, matching the in-scope impact "corruption of ... gas fee accounting, refund accounting ... must not misroute value."

### Title
Sandwichable auto-swap slippage bound derived from the same manipulable pool it trades against - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` compute `minPCOut` as 95% of a spot quote fetched from the same Uniswap V3 pool that the module immediately swaps against in the same execution. Because the "slippage protection" is self-referential (quote and trade hit identical live pool state), an unprivileged attacker can sandwich the module's automatic swap by manipulating the pool price immediately beforehand, causing users' bridged gas deposits and unused-gas refunds to be swapped at manipulated rates while extracting the spread.

### Finding Description
See analysis above: `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) queries `quoteExactInputSingle` on the live pool, and the caller derives `minPCOut = quote*95/100` before immediately invoking `CallPRC20DepositAutoSwap` (`evm.go:540-592`) or `CallUniversalCoreRefundUnusedGas` (`evm.go:595-644`), both executing on the same pool in the same block. No TWAP, oracle, or independent price source is used.

### Impact Explanation
Funds affected are user-bridged gas tokens (inbound `GAS`/`GAS_AND_PAYLOAD`) and outbound gas-fee refunds — both are user/protocol-controlled value that ends up misrouted (less native PC delivered than fair value), with the difference captured by the attacker. This falls under the allowed impact "corruption of ... gas fee accounting, refund accounting ... must not misroute value" and constitutes value extraction from ordinary users via a fully permissionless, non-privileged attack path.

### Likelihood Explanation
Requires an attacker with capital to move the specific WPC/gas-token pool and the ability to time transactions around observable `MsgVoteInbound`/`MsgVoteOutbound` finalizations (visible in mempool, or via a proposer/searcher advantage) — the same difficulty profile ("Low", per the original Trail of Bits classification) as classic sandwich attacks on any AMM lacking real slippage protection. It is more likely on chains/pools with thin liquidity for the specific PRC20 gas-token pairs.

### Recommendation
Replace the self-referential spot-quote slippage bound with either: (a) a TWAP-based reference price (or the existing `ChainMeta`/gas-price oracle already used elsewhere in this module) to compute `minPCOut` independently of the pool being traded against, or (b) enforce a maximum allowed deviation between the executed price and a recent oracle price, reverting the swap (falling back to the no-swap PRC20 deposit path, which already exists) if exceeded.

### Proof of Concept
1. Attacker holds inventory of the `PRC20` gas token and `WPC` on the relevant pool.
2. Attacker observes a pending `MsgVoteInbound` (or `MsgVoteOutbound`) that will cross the validator threshold and trigger `ExecuteInboundGas`/`applyGasRefund` for a victim deposit/refund of amount `A`.
3. Attacker submits a swap that pushes the pool price down just before the module's `GetSwapQuote`+`CallPRC20DepositAutoSwap` sequence executes in the same or next block.
4. The module computes `minPCOut` from the manipulated quote and executes the deposit/refund swap, delivering the victim fewer PC tokens than fair value.
5. Attacker reverses their manipulation trade, realizing the spread as profit, repeatable per victim inbound/refund event.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
