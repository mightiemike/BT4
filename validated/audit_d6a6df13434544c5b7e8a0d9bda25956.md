### Title
Missing negative-value check in `extractDestGasAmountFromMap` allows negative int64 to bypass validation before uint32 conversion - ([File: core/capabilities/ccip/ccipsolana/executecodec.go])

### Summary
`extractDestGasAmountFromMap` handles the `int64` case (produced when a LOOP gRPC relay converts a `uint32` DestExecData field to `int64`) by checking only `v > math.MaxUint32`, with no `v < 0` check, unlike the sibling function `parseExtraDataMap` in `msghasher.go` which explicitly validates `v < 0 || v > math.MaxUint32` for the analogous `ComputeUnits` and `IsWritableBitmap` fields. A negative `int64` therefore passes the upper-bound check and is converted via `uint32(v)`, silently wrapping to a large unsigned value that gets folded into `ccip_offramp.Any2SVMTokenTransfer.DestGasAmount` and hashed.

### Finding Description
The code path is: `MessageHasherV1.Hash` (`core/capabilities/ccip/ccipsolana/msghasher.go:64`) and `ExecutePluginCodecV1.Encode` (`core/capabilities/ccip/ccipsolana/executecodec.go:75`) call `h.extraDataCodec.DecodeTokenAmountDestExecData` to get `destExecDataDecodedMap`, then pass it to `extractDestGasAmountFromMap`. In that function:

```go
case "destgasamount":
    switch v := fieldValue.(type) {
    case uint32:
        return v, nil
    case int64: // LOOP converts expected uint32 to int64
        if v > math.MaxUint32 {
            return 0, fmt.Errorf("destGasAmount exceeds uint32 max, got %d", v)
        }
        return uint32(v), nil //nolint:gosec // G115: validated to be within uint32 max above
    ...
``` [1](#0-0) 

The only bound check is `v > math.MaxUint32`; there is no `v < 0` rejection. A negative `int64` (e.g., `-1`) satisfies `v > math.MaxUint32 == false`, so it falls through to `uint32(v)`, which for `-1` wraps to `4294967295` (`math.MaxUint32`), and for other negative values wraps to other large `uint32`s. This corrupted value is then used to construct `ccip_offramp.Any2SVMTokenTransfer.DestGasAmount` in both `Hash` (`msghasher.go:76`) and `Encode` (`executecodec.go:85`), directly affecting the consensus-critical message hash and the execution report encoding.

For comparison, the sibling `parseExtraDataMap` function in the same package correctly guards both bounds:
```go
case int64: // LOOP gRPC converts uint32 -> int64
    if v < 0 || v > math.MaxUint32 {
        return out, fmt.Errorf("ComputeUnits out of uint32 range: %d", v)
    }
``` [2](#0-1) 

This confirms the missing lower-bound check in `extractDestGasAmountFromMap` is an inconsistency/omission relative to the established pattern in this same file/package.

However, evaluating exploitability: the `int64`-typed value only arises from a LOOP gRPC plugin relay converting the source chain's decoded `DestExecData` map. The originating value comes from `ExtraDataCodecBundle.DecodeTokenAmountDestExecData`, which decodes the `DestExecData` bytes that were set by the **source chain's onRamp/message sender** (an unprivileged, arbitrary CCIP message sender can set arbitrary `destExecData` bytes on the source chain when sending a cross-chain message). If the decoder for that particular source-chain family decodes a signed/negative representation into the map as `int64` for the `destGasAmount` field, this path is reachable by an ordinary attacker sending a crafted CCIP message from the source chain, with no node-operator privilege required.

### Impact Explanation
If a negative `int64` is coerced into a large unsigned `DestGasAmount`, this corrupts the `ccip_offramp.Any2SVMTokenTransfer.DestGasAmount` field used in message hashing (`MessageHasherV1.Hash`) and in report encoding (`ExecutePluginCodecV1.Encode`). Since this hash is used in the OCR commit path, a mismatch between what an honest node computes here (if inputs differ across nodes/decoders) versus what's expected could cause report validation failures, and on the execution side it could cause the constructed Solana transaction to specify a bogus, very large gas/compute-unit-like parameter for the token transfer — potentially causing failed or inconsistent execution reports, or a hash divergence enabling a false-report / consensus mismatch on the token-transfer gas parameter.

### Likelihood Explanation
This requires: (1) a source chain relay implemented via LOOP gRPC that decodes `DestExecData` such that a negative value is representable as the map's `destgasamount` field with Go type `int64`, and (2) an unprivileged CCIP message sender on that source chain to actually set a negative encoded value in the `destExecData` field of a token transfer. Whether any currently-supported source-chain decoder can actually produce a negative `int64` for this specific field (as opposed to always encoding a strictly non-negative `uint32`-derived value) could not be confirmed from the code available — the codec's underlying wire encoding schema (e.g. protobuf field type, whether it's declared `uint32` or `int64`/`sint64` in the schema) determines whether negative values are even producible from an attacker-controlled `uint32`-only source field. This detail is outside what I was able to verify in the available index/context.

### Recommendation
Add a lower-bound check symmetric to the one in `parseExtraDataMap`:
```go
case int64:
    if v < 0 || v > math.MaxUint32 {
        return 0, fmt.Errorf("destGasAmount out of uint32 range: %d", v)
    }
    return uint32(v), nil
```
Apply the same fix to any other `extractDestGasAmountFromMap` implementations found in `ccipevm/msghasher.go`, `ccipaptos/msghasher.go`, and `ccipsui/msghasher.go` if they share this pattern (not independently verified here due to iteration limits).

func extractDestGasAmountFromMap(input map[string]any) (uint32, error) {
	// Search for the gas fields
	for fieldName, fieldValue := range input {
		lowercase := strings.ToLower(fieldName)
		switch lowercase {
		case "destgasamount":
			switch v := fieldValue.(type) {
			case uint32:
				return v, nil
			case int64: // LOOP converts expected uint32 to int64
				if v > math.MaxUint32 {
					return 0, fmt.Errorf("destGasAmount exceeds uint32 max, got %d", v)
				}
				return uint32(v), nil //nolint:gosec // G115: validated to be within uint32 max above
			default:
				return 0, errors.New("invalid type for destgasamount, expected uint32 or int64")
			}
		default:
		}
	}

	return 0, errors.New("invalid token message, dest gas amount not found in the DestExecDataDecoded map")
}
