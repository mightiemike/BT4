### Title
Starknet OS `execute_replace_class` Omits the Declared-Class Check Enforced by Blockifier, Causing State-Root Divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall does not verify that the target `class_hash` was actually declared before writing it into the contract's state entry, unlike the Rust `blockifier` implementation, which performs this exact check. This produces an implementation mismatch between the component that builds/validates blocks on the sequencer (`blockifier`) and the component that re-executes transactions to produce/verify proofs (Starknet OS), analogous to the Cooler.sol pattern where one code path mutates state (sets new "terms"/class hash) while a second code path that should gate/execute it skips the necessary authorization/validity check.

### Finding Description
Any account can trigger the `replace_class` syscall from an ordinary, unprivileged `invoke` transaction — this is a standard Starknet syscall available to any contract executing its own code, no special privilege required.

In the Rust execution engine (`blockifier`), the deprecated syscall handler explicitly guards this operation: [1](#0-0) 

which is validated by tests expecting failure with "is not declared" for an undeclared class hash: [2](#0-1) 

However, the equivalent function in the Starknet OS Cairo program — `execute_replace_class`, which the Starknet OS uses to independently re-execute/verify transactions for proving — has no such check. This is explicitly called out by an unresolved TODO in the code: [3](#0-2) 

Line 902 reads: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` [4](#0-3) 

The same missing check exists in the deprecated-syscall Cairo path used by the OS: [5](#0-4) 

Because the OS directly writes the new (unverified) `class_hash` into `contract_state_changes` and logs a revert-log entry without ever consulting `contract_class_changes` to confirm the hash corresponds to a declared class, the OS can be made to accept — and commit to a state root/tree containing — a contract whose class_hash points to a class that was never declared. The Rust `blockifier`, which is the reference implementation actually driving real network execution and consensus on tx success/failure, would reject (revert) the very same operation.

### Impact Explanation
This is a root-cause divergence between the two independent implementations of Starknet state transition (`blockifier` for sequencing/consensus vs. the Cairo `Starknet OS` used for proving/re-execution and verifying the committed state root). A block proposer/prover input that stages a transaction which calls `replace_class` with a bogus, undeclared class hash produces different outcomes:
- Under `blockifier`'s rules, the transaction fails/reverts (state unchanged for that call).
- Under the Starknet OS's rules, the syscall succeeds unconditionally, updating the contract's class_hash to the undeclared value and contributing that change to the computed/committed state root.

This mismatch can lead the Starknet OS to produce (and prove as valid) a state root that differs from what an honestly-executing `blockifier` node would compute for the same block, i.e., a wrong committed root — the exact class of impact explicitly called out as in-scope ("wrong committed root or block hash, honest-node divergence").

### Likelihood Explanation
The `replace_class` syscall is reachable from any single, unprivileged `invoke` transaction sent by a normal account/contract — no special role, staking, or operator privilege is required. The only requirement is supplying an arbitrary felt as `class_hash` that has not been declared, which any transaction sender fully controls. The bug is a straightforward code-path omission (confirmed by the maintainers' own TODO comment referencing a future date), not a subtle timing or racing condition, making it directly and deterministically triggerable.

### Recommendation
Add the same "class must be declared" check to `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` (and the corresponding deprecated-syscall path in `deprecated_execute_syscalls.cairo`) that already exists in the Rust `blockifier` implementation (`crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801`, and the analogous check used for the native/VM `replace_class` syscall in `syscall_base.rs`). Concretely, before updating `contract_state_changes` with the new `class_hash`, verify against `contract_class_changes` (or the equivalent declared-class dictionary) that the class hash was declared, mirroring the semantics of `state.get_compiled_class(request.class_hash)?` in the Rust code, and fail/panic the transaction in the same way `blockifier` reverts it.

### Proof of Concept
1. Deploy any contract exposing a function that calls the `replace_class_syscall` (e.g., the existing `test_replace_class` / `test_forbidden_syscall_in_virtual_mode` test contracts already contain such an entry point: [6](#0-5) ).
2. Submit a normal `invoke` transaction from any unprivileged account calling that entry point with an arbitrary, never-declared felt as the class hash (e.g. `1234`).
3. In `blockifier`, this reverts with "is not declared" as shown by the existing test: [2](#0-1) 
4. Feed the same transaction/block through the Starknet OS's `execute_replace_class` path; because the check at line 902 is absent, the syscall succeeds and the contract's `class_hash` state entry is committed as the undeclared value, producing a different state root/commitment than the one `blockifier` would produce for an honest execution of the same transaction.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
