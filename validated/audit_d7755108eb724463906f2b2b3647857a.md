## Title
Unhandled panic when `receipt_filter_fn` calls `.unwrap()` on `receiver_shard_id()` for a stale `GlobalContractDistribution` receipt after resharding — reachable transaction-triggered chunk-application halt (analog of OpenSIPS `codec_delete_except_re` crash-on-repeated-malformed-input) - ([File: runtime/runtime/src/congestion_control.rs])

### Summary
The OpenSIPS bug crashes the server because a codec-cleanup function is invoked repeatedly against state that has become inconsistent with the input, and the code does not defend against that repeat/aged condition. The structural analog in nearcore is the delayed-receipt filter used while draining the per-shard delayed-receipt queue: `DelayedReceiptQueueWrapper::receipt_filter_fn` unconditionally `.unwrap()`s the result of `Receipt::receiver_shard_id`, even though that function is documented and coded to return an `Err` precisely when a receipt has become stale relative to the *current* shard layout.

### Finding Description
`Receipt::receiver_shard_id` for `ReceiptEnum::GlobalContractDistribution` resolves the receipt's `target_shard` against the current layout, and if the shard id is no longer present in the current layout, falls back to `shard_layout.resolve_to_current_shard(target_shard)`: [1](#0-0) 

If `resolve_to_current_shard` cannot find a current descendant for the old `target_shard` (e.g., the shard's split lineage is not resolvable — deeper/older resharding history, or a corrupted/edge-case target shard id), the function correctly returns `Err(EpochError::ShardingError(...))` instead of panicking internally.

However, the only caller inside the delayed-receipt drain path ignores that `Result` and unwraps it: [2](#0-1) 

This `receipt_filter_fn` is invoked from `pop()` (used while draining the delayed-receipt queue during normal chunk application) and from `peek_iter()` (used for prefetch scheduling), both on the hot path of every chunk's `process_delayed_receipts`: [3](#0-2) [4](#0-3) 

A `GlobalContractDistribution` receipt is created by any unprivileged account deploying a global contract — a completely permissionless, single-transaction action. If that receipt lands in the delayed-receipt queue (which happens naturally under compute/storage-proof congestion) and survives across resharding events such that `resolve_to_current_shard` cannot map it back to a live shard, `receiver_shard_id` returns `Err`, and `receipt_filter_fn`'s `.unwrap()` panics.

Note that a dedicated regression test already exists specifically for the *two-resharding* case, confirming this exact bug class was previously exploitable and was only partially hardened (by making `receiver_shard_id` itself resolve ancestor shards) rather than by removing the `.unwrap()` at the call site: [5](#0-4) [6](#0-5) 

Because `resolve_to_current_shard`'s ancestor-resolution is bounded by whatever split-history bookkeeping the `ShardLayout::V3` retains, any scenario that exceeds that bookkeeping (more resharding generations than the fix's test covers, garbage-collected/pruned lineage, or any other case where the target shard cannot be mapped) still reaches the unguarded `.unwrap()` and panics — exactly the "fixed one instance, but the generic unwrap remains" pattern that mirrors how OpenSIPS's fix for `codec_delete_except_re` had to specifically patch the function handling repeated/aged SDP state rather than making the whole call path defensive.

### Impact Explanation
A panic inside `process_delayed_receipts` (called from `Runtime::apply`, which `NightshadeRuntime::apply_chunk` treats as an unrecoverable error) aborts chunk application on every honest node that must apply that chunk/shard, since `RuntimeError::ReceiptValidationError`/unexpected panics are not handled gracefully at this layer: [7](#0-6) 
This is a transaction-triggered halt of shard/chunk processing (liveness failure) reachable from a single unprivileged deploy-global-contract transaction combined with naturally-occurring congestion and resharding — it is not a malicious-validator, malicious-peer, or sandbox-only bug.

### Likelihood Explanation
Triggering it requires: (1) an ordinary account deploying a global contract while its shard is at or near compute/proof-size limits so the resulting `GlobalContractDistribution` receipt is pushed to the delayed queue, and (2) the shard undergoing resharding such that `resolve_to_current_shard` cannot resolve the receipt's stale `target_shard`. The exact conditions under which `resolve_to_current_shard` fails (how many resharding generations / how the split-history is bounded) were not fully verifiable within the available tool budget — the regression test only exercises the double-resharding case and confirms the fallback resolves that specific scenario, but the underlying `.unwrap()` at the `receipt_filter_fn` call site remains generic and unguarded for any case where resolution still fails.

### Recommendation
Replace the `.unwrap()` calls in `receipt_filter_fn` (and the analogous unwraps on `epoch_info_provider.shard_layout(...)`) with proper error propagation (`Result`/`?`) so an unresolved receipt causes a controlled `RuntimeError` rather than a hard panic, and treat an unresolvable stale receipt as a case to be handled explicitly (e.g., route to a default/last-known shard, or drop with a recorded inconsistency) rather than crashing chunk application.

### Proof of Concept
Not independently reproduced beyond the codebase's own regression test; a concrete PoC would extend `test_stale_global_contract_distribution_after_double_resharding` with additional resharding generations (or a manipulated/pruned split-history) sufficient to make `resolve_to_current_shard` return `None`, then verify that instead of the test's current assertion (`head_height >= drain_end`) the chain panics/stalls when the queue is drained, i.e., remove or exceed the specific fix boundary that the existing test covers: [8](#0-7)

    pub fn receiver_shard_id(&self, shard_layout: &ShardLayout) -> Result<ShardId, EpochError> {
        let shard_id = match self.receipt() {
            ReceiptEnum::Action(_)
            | ReceiptEnum::ActionV2(_)
            | ReceiptEnum::Data(_)
            | ReceiptEnum::PromiseYield(_)
            | ReceiptEnum::PromiseYieldV2(_)
            | ReceiptEnum::PromiseResume(_) => {
                shard_layout.account_id_to_shard_id(self.receiver_id())
            }
            ReceiptEnum::GlobalContractDistribution(receipt) => {
                let target_shard = receipt.target_shard();
                if shard_layout.shard_ids().contains(&target_shard) {
                    target_shard
                } else {
                    // The target shard may be from an arbitrarily old layout (the receipt could
                    // have been delayed across multiple resharding events). resolve_to_current_shard
                    // will find a shard descendant in the current layout.
                    let Some(current_shard) = shard_layout.resolve_to_current_shard(target_shard)
                    else {
                        return Err(EpochError::ShardingError(format!(
                            "Shard {target_shard} does not exist in the shard layout or its split history",
                        )));
                    };
                    current_shard
                }
            }
        };
        Ok(shard_id)
    }

    pub(crate) fn pop(
        &mut self,
        trie_update: &mut TrieUpdate,
        config: &RuntimeConfig,
    ) -> Result<Option<ReceiptOrStateStoredReceipt<'_>>, RuntimeError> {
        // While processing receipts, we need to keep track of the gas and bytes
        // even for receipts that may be filtered out due to a resharding event
        loop {
            // Check proof size limit before each receipt is popped.
            if trie_update.trie.check_proof_size_limit_exceed() {
                break;
            }
            let Some(receipt) = self.queue.pop_front(trie_update)? else {
                break;
            };
            let delayed_gas = receipt_congestion_gas(&receipt, &config)?;
            let delayed_bytes = receipt_size(&receipt)? as u64;
            self.removed_delayed_gas =
                self.removed_delayed_gas.checked_add(delayed_gas).ok_or(IntegerOverflowError)?;
            self.removed_delayed_bytes = self
                .removed_delayed_bytes
                .checked_add(delayed_bytes)
                .ok_or(IntegerOverflowError)?;

            // Track gas and bytes for receipt above and return only receipt that belong to the shard.
            if self.receipt_filter_fn(&receipt) {
                return Ok(Some(receipt));
            }
        }
        Ok(None)
    }

    pub(crate) fn peek_iter(
        &'a self,
        trie_update: &'a TrieUpdate,
    ) -> impl Iterator<Item = ReceiptOrStateStoredReceipt<'static>> + 'a {
        self.queue
            .iter(trie_update, false)
            .map_while(Result::ok)
            .filter(|receipt| self.receipt_filter_fn(receipt))
    }

    fn process_delayed_receipts(
        &self,
        mut processing_state: &mut ApplyProcessingReceiptState,
        receipt_sink: &mut ReceiptSink,
        compute_limit: u64,
        validator_proposals: &mut Vec<ValidatorStake>,
    ) -> Result<(), RuntimeError> {
        let delayed_processing_start = std::time::Instant::now();
        let protocol_version = processing_state.protocol_version;
        let mut delayed_receipt_count = 0;

        let mut next_schedule_after = {
            let mut prep_lookahead_iter =
                processing_state.delayed_receipts.peek_iter(&processing_state.state_update);
            schedule_contract_preparation(
                &mut processing_state.pipeline_manager,
                &processing_state.state_update,
                &mut prep_lookahead_iter,
            )
        };

        loop {
            if processing_state.total.compute >= compute_limit
                || processing_state.state_update.trie.check_proof_size_limit_exceed()
            {
                break;
            }

            let receipt = if let Some(receipt) = processing_state
                .delayed_receipts
                .pop(&mut processing_state.state_update, &processing_state.apply_state.config)?
            {
                receipt.into_receipt()
            } else {
                // Break loop if there are no more receipts to be processed.
                break;
            };

            // TODO(resharding): Add metric for tracking number of
            delayed_receipt_count += 1;
            if let Some(nsi) = &mut next_schedule_after {
                *nsi = nsi.saturating_sub(1);
                if *nsi == 0 {
                    let mut prep_lookahead_iter =
                        processing_state.delayed_receipts.peek_iter(&processing_state.state_update);
                    next_schedule_after = schedule_contract_preparation(
                        &mut processing_state.pipeline_manager,
                        &processing_state.state_update,
                        &mut prep_lookahead_iter,
                    );
                }
            }

            if let Some(prefetcher) = &mut processing_state.prefetcher {
                // Prefetcher is allowed to fail
                _ = prefetcher.prefetch_receipts_data(std::slice::from_ref(&receipt));
            }

            // Validating the delayed receipt. If it fails, it's likely the state is inconsistent.
            validate_receipt(
                &processing_state.apply_state.config.wasm_config.limit_config,
                &receipt,
                protocol_version,
                ValidateReceiptMode::ExistingReceipt,
            )
            .map_err(|e| {
                StorageError::StorageInconsistentState(format!(
                    "Delayed receipt {:?} in the state is invalid: {}",
                    receipt, e
                ))
            })?;

            self.process_receipt_and_instant_receipts(
                &receipt,
                &mut processing_state,
                receipt_sink,
                validator_proposals,
            )?;
            processing_state
                .processed_receipts
                .push(ProcessedReceipt { receipt, source: ReceiptSource::Delayed });

    // 2-epoch proposal-to-activation pipeline, so we need enough epochs for both splits.
    let max_saturation_height = start_height + epoch_length * 12;
    let mut both_splits_done = false;
    for target_height in (start_height + 1)..=max_saturation_height {

        {
            let node = env.node_for_account(&chunk_producer);

                    "burn_gas_raw",
                    gas_to_burn.as_gas().to_le_bytes().to_vec(),
                    Balance::ZERO,
                    gas_limit,

                node.submit_tx(tx);
            }
        }
