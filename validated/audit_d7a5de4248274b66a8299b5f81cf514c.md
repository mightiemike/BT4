## Analysis

The concern is valid: the auto-swap deposit path uses an **unprotected spot-price quote** as both the pricing source and the slippage-bound source, with no TWAP or external price validation.

### The flow

`gasAndPayloadDepositAutoSwap` (called from `ExecuteInboundGasAndPayload`) and the equivalent logic in `ExecuteInboundGas` both:
1. Fetch the Uniswap-style quoter address and WPC address from `UniversalCore` [1](#0-0) 
2. Call `GetSwapQuote`, which invokes `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96: big.NewInt(0)` — i.e. an unbounded, instantaneous spot-price quote against current pool reserves [2](#0-1) 
3. Derive `minPCOut` as exactly 95% of that same just-fetched quote [3](#0-2) 
4. Immediately execute the real swap via `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on `UniversalCore`, using that quote-derived bound [4](#0-3) 

The identical pattern is also used for gas-abstraction refunds in `applyGasRefund` / `getSwapQuoteForRefund` [5](#0-4) .

### Why the 5% bound doesn't protect against pre-existing price manipulation

The `minPCOut` check only protects against price movement *between* the quote fetch and the swap execution — and in this code, those two calls happen back-to-back within the same keeper invocation, with no external transaction able to interleave between them. It provides **zero protection against the pool price already being manipulated before `GetSwapQuote` is even called**, because the "reference" price and the "safety bound" are derived from the exact same manipulated on-chain state.

Since the pool feeding `GetUniversalCoreQuoterAddress`/`GetSwapQuote` is an ordinary Uniswap-V3-style pool, any unprivileged actor can submit a normal permissionless swap to move its spot price before their own inbound deposit is finalized by honest validators. Inbound observation → ballot finalization → execution is not instantaneous, giving an attacker a window to skew the pool, then have their own `ExecuteInboundGasAndPayload`/`ExecuteInboundGas` deposit auto-swap execute against that skewed price — extracting value from the pool's liquidity (protocol/LP-funded reserves) at fair-value's expense, entirely through the ordinary/inbound-deposit path with only honest validators involved.

This matches a well-known "spot price as oracle" anti-pattern rather than requiring any malicious validator, relayer, or admin — it is reachable purely by an unprivileged user pairing a normal DEX swap with their own inbound deposit.

### Title
Auto-swap deposit relies on manipulable spot-price quote as its own slippage bound, enabling price-manipulation value extraction - ([File: x/uexecutor/keeper/evm.go, execute_inbound_gas_and_payload.go, execute_inbound_gas.go, outbound.go])

### Summary
`GetSwapQuote` fetches an instantaneous Uniswap V3 `quoteExactInputSingle` price with no TWAP/oracle protection, and `minPCOut` is computed as a fixed 95% of that same just-fetched quote, then immediately consumed by `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas`. The slippage bound is derived from the manipulated price itself, so it cannot detect or prevent prior price manipulation.

### Finding Description
An unprivileged attacker can submit an ordinary permissionless swap against the pool backing the quoter (skewing `token/WPC` price), then trigger (or wait for) their own `GAS`/`GAS_AND_PAYLOAD` inbound deposit to be processed. Because `GetSwapQuote` and the derived `minPCOut` are both computed from the currently-manipulated pool state at execution time, the 5% band offers no defense against the pre-existing manipulation — only against further movement during the same atomic call sequence, which is not a realistic attack window here since no external tx can interleave between the quote and the swap.

### Impact Explanation
The autoswap executes real value transfer against pool reserves at an attacker-favorable price, extracting funds from pool liquidity that ultimately can be traced to protocol/LP-funded reserves, corrupting the deposit accounting and native (PC)/PRC20 balance outcome for that inbound. The same manipulable-quote pattern also affects `applyGasRefund`'s refund-with-swap path, extending the impact to refund accounting.

### Likelihood Explanation
Requires only an ordinary, permissionless DEX swap plus submission of a normal user deposit — both reachable by any unprivileged actor without validator, relayer, or admin cooperation. Feasibility depends on pool depth/liquidity relative to attacker capital, but the code provides no architectural defense (TWAP, oracle cross-check, or max price-impact check) regardless of pool size.

### Recommendation
Replace the instantaneous `quoteExactInputSingle`-based quote with a TWAP-based price (e.g., Uniswap V3 `observe`) or bound the acceptable price against an independently-tracked reference price, and/or clamp slippage tolerance to a much tighter bound with circuit-breaker checks on abnormal price deviation between blocks, applied consistently in both `gasAndPayloadDepositAutoSwap`/`ExecuteInboundGas` and `applyGasRefund`.

### Proof of Concept
1. Attacker observes the `prc20/WPC` pool used by `GetUniversalCoreQuoterAddress` has depth `D`.
2. Attacker submits a normal swap shifting the pool price so that `quoteExactInputSingle(prc20→WPC)` returns an inflated `amountOut`.
3. Attacker (or their pre-arranged inbound) has an inbound `GAS_AND_PAYLOAD` deposit processed; `gasAndPayloadDepositAutoSwap` computes `quote` from the now-skewed pool and `minPCOut = quote*95/100` [6](#0-5) .
4. `CallPRC20DepositAutoSwap` executes `depositPRC20WithAutoSwap` against the skewed price, paying out more PC than fair value would allow, funded by pool reserves.
5. Assert: regardless of the attacker's pre-transaction price shift, the enforced `minPCOut` tracks the manipulated `quote` 1:1 (always 95% of whatever `GetSwapQuote` returns at call time), proving no independent, manipulation-resistant bound exists.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
```
