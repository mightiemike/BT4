### Title
Double-division of `baseFee` by 1e18 zeroes out gas-fee accounting for universal-execution EVM calls - (File: x/uexecutor/keeper/fees.go)

### Summary
`Keeper.CalculateGasCost` in `x/uexecutor/keeper/fees.go` unwraps the `feemarketKeeper.GetBaseFee` value with an extra, unnecessary `Div(..., 1e18)` on top of the truncation `LegacyDec.BigInt()` already performs internally. This produces a near-permanent zero `effectiveGasPrice`/`gasCost`, so `DeductGasFeesFromReceipt` silently skips fee collection (`if gasCost.Sign() <= 0 { return nil }`) for essentially every universal-execution payload call, mirroring the analog bug class in the referenced report: an arithmetic scaling error in a reward/fee formula that silently produces a materially wrong (here: near-zero) accounted value instead of erroring loudly.

### Finding Description
`CalculateGasCost` is documented and implemented as: [1](#0-0) 

`baseFee` is a `sdkmath.LegacyDec` returned by `k.feemarketKeeper.GetBaseFee(sdkCtx)`. The cosmos-sdk `LegacyDec.BigInt()` implementation already truncates/chops the internal 18-decimal fixed-point precision before returning the `*big.Int` (i.e. it returns the actual decimal value, not `value * 1e18`). The comment in the code (“LegacyDec stores values with 18-decimal precision internally… This division unwraps the LegacyDec encoding back to the actual upc amount”) reflects a misunderstanding of this API: `BigInt()` has already performed that unwrap, so the extra `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` divides the correct value by `1e18` a second time.

Because realistic base-fee magnitudes (a handful to a few million `upc` per gas unit) are vastly smaller than `1e18`, integer division truncates `baseFeeBig` to `0` in virtually every real scenario. This flows directly into: [2](#0-1) 

With `baseFeeBig == 0`, the `maxFeePerGas >= baseFee` check trivially passes, `effectiveGasPrice` becomes `0`, and `gasCost = effectiveGasPrice * gasUsed = 0`, regardless of actual gas consumed.

This function feeds `DeductGasFeesFromReceipt`, which is the fee-collection step for module-originated EVM execution on the universal-execution path: [3](#0-2) 

When `gasCost.Sign() <= 0`, the function returns `nil` without deducting or burning any fee from the payload sender: [4](#0-3) 

`DeductGasFeesFromReceipt` is invoked from the standard universal payload execution flows (`execute_payload.go`, `execute_inbound_funds_and_payload.go`, `execute_inbound_gas_and_payload.go`, `msg_execute_payload.go`), meaning it is reachable by any ordinary, unprivileged user submitting a universal payload/inbound execution — no gasless allowlist entry or privileged role is required.

### Impact Explanation
This corrupts gas-fee accounting on the universal execution path: users who cause real EVM `DerivedEVMCall`/payload execution (consuming real chain resources and real EVM gas) are never charged the corresponding `upc` fee, because `gasCost` computes to `0` almost always. This is a direct instance of the in-scope impact “corruption of … gas fee accounting, refund accounting … reachable from ordinary user deposits, payloads, contracts, or default transaction submission paths alone,” with the concrete effect that the protocol permanently loses fee revenue that should have been burned from the executing account — a systemic, protocol-wide, unauthorized fee waiver reachable by any unprivileged user simply by submitting universal payloads. Unlike the referenced LotteryMath bug (which produced a wrong non-zero profit that could go negative in specific cases), this bug produces a deterministic zero-fee outcome for the overwhelming majority of realistic base-fee values, making the effect broad and repeatable rather than edge-case-only.

### Likelihood Explanation
High. The bug triggers on the default/common case (any base fee smaller than `1e18` in `upc`, which is essentially always true for a "smallest denomination" fee), not a rare edge condition. Every unprivileged user submitting a universal payload that results in an EVM call goes through `DeductGasFeesFromReceipt` → `CalculateGasCost`, so the corrupted accounting is hit on virtually every transaction of this type, requiring no special conditions, timing, or validator collusion.

### Recommendation
Remove the redundant `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` call in `CalculateGasCost`, since `baseFee.BigInt()` (via cosmos-sdk `LegacyDec.BigInt()`) already truncates the internal 18-decimal fixed-point representation to the actual integer value. Add a unit test asserting that for a realistic non-trivial `baseFee` (e.g., `LegacyNewDec(1000)`), `CalculateGasCost` returns a non-zero `gasCost` proportional to `gasUsed`, to prevent regression.

### Proof of Concept
Given `baseFee = sdkmath.LegacyNewDec(1000)` (1000 upc/gas — a realistic value), `maxFeePerGas = big.NewInt(1000)`, `gasUsed = 100000`:
1. `baseFee.BigInt()` → `1000` (LegacyDec already truncates the 18-decimal fixed-point encoding).
2. Code performs `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` → `1000 / 1_000_000_000_000_000_000 = 0` (integer division).
3. `effectiveGasPrice = 0`.
4. `gasCost = 0 * 100000 = 0`.
5. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without deducting/burning any fee, even though `100000` gas of real EVM execution occurred.

Note: I could not execute this directly against a live `cosmossdk.io/math` build within this environment (the dependency source is not indexed in this repository), so the exact `LegacyDec.BigInt()` truncation semantics are based on the well-documented upstream cosmos-sdk implementation rather than a locally-verified run; a Devin session with full repo/dependency access should confirm via `go test` before merging a fix.

```go
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,

	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
```
