### Title
Missing declared-class validation in the Starknet OS `replace_class` syscall handler causes execution divergence between blockifier and OS re-execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
This is a valid analog. The external report flags a missing address/receiver validation in a Solidity `requestWithdraw` function, causing loss-of-funds because the wrong destination is accepted without verification. The analogous bug class in this repo is a syscall handler that accepts an unvalidated identifier (a `class_hash` for `replace_class`) and writes it into committed state without verifying it corresponds to a real, declared object — exactly mirroring "missing validation on a user-controlled destination/target before it is persisted."

### Finding Description
Any contract invoked as part of a transaction can call the `replace_class` syscall with an arbitrary `class_hash` supplied by the caller. In the blockifier (the reference execution engine used by the sequencer to build and validate blocks), the handler explicitly validates that the class is declared before mutating state: [1](#0-0) 

and the Cairo1 path likewise rejects undeclared or version-mismatched class hashes, as shown by the dedicated negative tests: [2](#0-1) 

However, the Starknet OS (Cairo) implementation of the same syscall — which is executed during OS re-execution to attest to block validity/build the proof — does **not** perform this check. The code contains an explicit TODO acknowledging the missing validation: [3](#0-2) 

The deprecated (Cairo0) OS syscall path has the identical gap, with no declared-class check at all before the state dictionary is updated: [4](#0-3) 

Both OS entry points are directly reachable from a single transaction, since the OS dispatches `REPLACE_CLASS_SELECTOR` to `execute_replace_class` for any contract call that issues the syscall: [5](#0-4) 

### Impact Explanation
Because blockifier enforces the declared-class invariant but the OS Cairo program does not, a transaction that calls `replace_class` with an undeclared (or version-incompatible) class hash will be **rejected/reverted by the sequencer's blockifier execution**, but the **same transaction re-executed by the Starknet OS** would succeed and commit a `StateEntry` with a class hash that was never declared. This is a concrete honest-node divergence: the state root/block hash computed by OS re-execution (used for L1 state commitment and proof generation) can differ from what the sequencer's execution produced and gossiped, since the OS accepts a state mutation the blockifier would have refused. This can result in a wrong committed root, contracts entering a class-hash state that has no corresponding compiled code (breaking subsequent calls to that contract), or a network unable to reconcile/confirm blocks between the sequencer's view and the OS-verified view.

### Likelihood Explanation
The `replace_class` syscall is available to any contract executing under an ordinary invoke transaction (no privileged capability required). Triggering the divergence only requires submitting a transaction whose execution path calls `replace_class_syscall` with a `class_hash` that is not declared in the current state (or is a Cairo0 hash where a Cairo1 hash is expected, per the mismatch check present in blockifier but absent in OS). This requires no special permissions, timing, or race condition — it is a straightforward single-transaction, single-message call.

### Recommendation
Add the same "class must be declared" validation (and, if applicable, the Cairo0/Cairo1 hash type consistency check) to both `execute_replace_class` implementations in the Starknet OS Cairo program (`syscall_impls.cairo` for Cairo1 and `deprecated_execute_syscalls.cairo` for Cairo0) so that OS re-execution behavior is provably identical to blockifier's `replace_class` handler in `hint_processor.rs`/`syscall_base.rs`. This closes the TODO already flagged in the code and removes the divergence risk.

### Proof of Concept
1. Declare nothing extra; from a deployed account, submit an invoke transaction whose `__execute__` (or any inner call) executes `replace_class_syscall(some_undeclared_class_hash)`.
2. Under blockifier (sequencer execution), the transaction fails with `"... is not declared"` per [6](#0-5) .
3. Under the Starknet OS Cairo program's `execute_replace_class` (both variants shown above), no such declared-class check exists — the dict update at `contract_state_changes` proceeds unconditionally, writing the (possibly undeclared) class hash into the contract's state entry.
4. The divergence between "sequencer rejects" and "OS accepts" for the identical transaction constitutes the vulnerability; a full end-to-end PoC would require running both the blockifier test harness and the `starknet_os_flow_tests`/OS re-execution pipeline with the same transaction to directly observe the differing outcomes, which was not executed here (index/search only, no execution environment available).

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
