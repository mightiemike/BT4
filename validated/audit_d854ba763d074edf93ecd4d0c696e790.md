### Title
`translate_signers` derives PDAs via `Pubkey::create_program_address` without charging `create_program_address_units`, letting a CPI caller get PDA-derivation compute for free - ([File: program-runtime/src/cpi.rs])

### Summary
`cpi_common` only charges the flat `invoke_units` fee before calling `translate_signers`, which then calls `Pubkey::create_program_address` once per signer-seed set (up to `MAX_SIGNERS`) without ever charging `create_program_address_units`. This is inconsistent with the explicit `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress` syscalls, which explicitly meter `create_program_address_units` for every `create_program_address` attempt.

### Finding Description
In `cpi_common`, the only compute charge applied before signer translation is the flat `invoke_units` fee: [1](#0-0) 

`translate_signers` then iterates the caller-supplied `signers_seeds` (bounded by `MAX_SIGNERS` and, per seed group, by `MAX_SEEDS`) and calls `Pubkey::create_program_address` for each one directly, with no compute-meter charge for the derivation itself: [2](#0-1) 

By contrast, the syscall that exposes `create_program_address` directly to programs explicitly charges `create_program_address_units` per call before doing the same `Pubkey::create_program_address` work: [3](#0-2) 

An unprivileged attacker who deploys their own SBF program can invoke a CPI (`invoke_signed`) with the maximum allowed `signers_seeds_len` (up to `MAX_SIGNERS`) and, for each entry, the maximum number of seeds (`MAX_SEEDS`), forcing the validator to perform `MAX_SIGNERS` `create_program_address` computations (each involving hashing/curve validation work) while the compute meter is debited only the single flat `invoke_units` amount, not the `create_program_address_units`-equivalent cost per derivation that the equivalent explicit syscall would charge. None of the existing checks (`MAX_SIGNERS`, `MAX_SEEDS`, `MAX_SEED_LEN`) prevent this—they only bound the maximum amount of free work obtainable per CPI call, they do not add a compute charge.

### Impact Explanation
This is a compute-unit under-accounting bug: the validator performs real cryptographic work (`Pubkey::create_program_address`, which does a SHA-256-based off-curve check) that is not reflected in the CU price paid by the transaction. Because each CPI call can trigger up to `MAX_SIGNERS` such derivations for the price of the flat `invoke_units` fee, and a transaction can perform many CPI calls up to `max_instruction_trace_length`, an attacker can cause the validator to do measurably more real computational work per CU purchased than the fee/compute-unit model assumes. This falls into the "resource exhaustion / compute-cost mispricing" category rather than direct loss of funds, PDA/signer forgery, or consensus divergence—`create_program_address`'s cryptographic result is still correctly computed and checked, so no signer-authorization bypass occurs.

### Likelihood Explanation
Trivial and fully reachable by any unprivileged attacker: deploy an SBF program that calls `invoke_signed`/`sol_invoke_signed` with `signers_seeds_len = MAX_SIGNERS`, each entry containing `MAX_SEEDS` seeds, and repeat the CPI as many times as `max_instruction_trace_length` and the compute budget allow. Cost to the attacker is the fee for one ordinary transaction. Fully repeatable in every slot without any special preconditions.

### Recommendation
Charge `create_program_address_units` (or an equivalent per-derivation cost) for each signer-seed group processed inside `translate_signers`, mirroring the metering already applied in `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress`, so CPI signer translation cannot perform uncharged PDA derivations.

### Proof of Concept
Add an SBF integration test (e.g., extending `programs/sbf/rust/invoke`) that:
1. Invokes `invoke_signed` with `signers_seeds` containing `MAX_SIGNERS` entries, each with `MAX_SEEDS` seeds of `MAX_SEED_LEN` bytes.
2. Records `sol_remaining_compute_units()` before and after the CPI call.
3. Asserts that CU consumed is at least `invoke_units + MAX_SIGNERS * create_program_address_units` (mirroring the direct-syscall cost model), and shows that current behavior only charges `invoke_units` plus incidental translation costs, not the per-signer derivation cost—demonstrating the gap between charged and actual CU cost.

pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
