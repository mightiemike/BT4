### Title
PoX-4 `make_signer_set` can silently produce a non-empty-but-zero-weight signer set, driving `compute_voting_weight_threshold` to 0 and letting `verify_signer_signatures` accept a block with **no** signer signatures - ([File: stackslib/src/chainstate/stacks/boot/mod.rs], [File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
The reported DIA bug class is: a settable numeric parameter (`threshold`) is allowed to become `0`, which trivially satisfies a `>=` / `<` guard and disables the intended check. The same class of bug exists in the Nakamoto PoX-4 signer-weight pipeline: `StacksChainState::make_signer_set` (unlike its PoX-5 counterpart `pox_5_make_signer_set`) has no protection against every aggregated signer floor-dividing to weight `0`. When that happens, the resulting `RewardSet` carries `signers = Some(vec![])` (present but empty), so `RewardSet::total_signing_weight()` returns `0`, `NakamotoBlockHeader::compute_voting_weight_threshold(0)` returns `0`, and `verify_signer_signatures` accepts any block — including one with zero signer signatures — because `total_weight_signed (0) < threshold (0)` is false.

### Finding Description
`StacksChainState::make_signer_set` aggregates stacker amounts per signing key and divides each aggregate by a single `threshold` value; any signer whose `stacked_amt / threshold == 0` is filtered out: [1](#0-0) 

Unlike the newer `pox_5_make_signer_set`, which explicitly documents and defends against the case where "more than `reward_slots` distinct signers hold roughly equal stake [and] every base weight floors to 0" using a largest-remainder ("Hare") allocation so the set is never left entirely empty: [2](#0-1) 

the PoX-4 `make_signer_set` has no equivalent leftover-slot mechanism. If aggregate stacking participation is low enough that the 25%-of-liquid-uSTX floor dominates `get_reward_threshold_and_participation`'s `scale_by`, the resulting `threshold` can exceed every individual (or per-signing-key aggregated) stacker's amount, so **every** entry floors to weight `0` and is filtered out — yet the function still returns `Some(vec![])`, not `None`, because `entries.first()` was non-empty at the start: [3](#0-2) 

This is fed straight into `pox_4_compute_and_update_signers` with **no check** analogous to PoX-5's explicit guard (`if signer_set.is_empty() { return Err(...) }`): [4](#0-3) [5](#0-4) 

The resulting `RewardSet` (`signers = Some(vec![])`) is stored and later consumed by `RewardSet::total_signing_weight()`, which iterates the (empty) signer list and returns `0` rather than an error, since `signers()` is `Some` (non-`None`): [6](#0-5) 

`NakamotoBlockHeader::compute_voting_weight_threshold` then computes `threshold = ceil(0 * 7 / 10) = 0`: [7](#0-6) 

Finally, `verify_signer_signatures` uses this `total_weight` and `threshold` to gate block acceptance: [8](#0-7) 

With `signers_by_pk` empty (no signers), any signature in `self.signer_signature` fails the "public key not found" check and errors the block — but a block header with an **empty** `signer_signature` vector skips the loop entirely, leaving `total_weight_signed = 0`. The final check `if total_weight_signed < threshold` becomes `0 < 0`, which is `false`, so the function returns `Ok(0)` — the block is treated as validly signer-approved with **zero** actual signatures.

### Impact Explanation
This breaks the core Nakamoto consensus equality that a block header must carry signatures from signers holding ≥70% of signing weight before it is treated as approved. Because `verify_signer_signatures` is a deterministic, pure function of `(reward_set, epoch_id, header)`, every conforming node computes the same `threshold = 0` and reaches the same (wrong) verdict, so this is not merely a local divergence — it is a network-wide acceptance of an unsigned/unapproved Nakamoto block, i.e., an invalid block accepted network-wide. This qualifies as Critical impact per the rules (invalid block accepted network-wide).

### Likelihood Explanation
This does not require majority collusion or privileged keys. It is triggered purely by the state of aggregate PoX-4 stacking participation in a reward cycle: if `scale_by` (bounded below by `liquid_ustx / POX_MAXIMAL_SCALING`) computes a per-slot `threshold` that exceeds every individual stacker's aggregated stacked amount for a signing key, the degenerate empty-but-present signer set is produced automatically by the existing floor-division code — no attacker input is strictly required, though a minority of stackers could deliberately fragment their stacking commitments across many small signing keys to help engineer this condition. This is a genuine, minority-triggerable path through consensus-critical code (`make_signer_set` → `total_signing_weight` → `compute_voting_weight_threshold` → `verify_signer_signatures`), matching the "signer weight below threshold" analog class called out in scope.

### Recommendation
- Add a check equivalent to PoX-5's empty-signer-set guard to `pox_4_compute_and_update_signers`/`make_signer_set`: reject (or fail over to a safe non-Nakamoto/burn outcome) whenever the filtered signer set is empty but the input entries were non-empty.
- Additionally, make `compute_voting_weight_threshold` and/or `verify_signer_signatures` explicitly reject `total_weight == 0` (mirroring the recommendation to reject zero as a valid threshold/timeout parameter in the original report), rather than silently computing a `0` threshold that vacuously passes.
- Consider porting the largest-remainder ("Hare") allocation approach used in `pox_5_make_signer_set` back into the PoX-4 code path to avoid the floor-to-zero degenerate case entirely.

### Proof of Concept
1. Configure a PoX-4 reward cycle where aggregate stacking participation is dominated by the `liquid_ustx / POX_MAXIMAL_SCALING` floor in `get_reward_threshold_and_participation` (e.g., very low real participation with a large liquid supply), producing a `threshold` value larger than any individual (post-aggregation) signer's `amount_stacked`.
2. Let `pox_4_compute_and_update_signers` call `make_signer_set(threshold, reward_slots)`; because every aggregated entry's `stacked_amt / threshold == 0`, the returned `Vec` is empty, and `RewardSet::V0.signers = Some(vec![])` gets persisted (no PoX-5-style rejection exists for PoX-4).
3. In the next tenure, `RewardSet::total_signing_weight()` returns `0`; `NakamotoBlockHeader::compute_voting_weight_threshold(0)` returns `0`.
4. A miner proposes a Nakamoto block header with `signer_signature = vec![]` (no signer approvals gathered at all).
5. `verify_signer_signatures` computes `total_weight_signed = 0`, `threshold = 0`, and `0 < 0` is `false`, so the function returns `Ok(0)` — every node accepts the block as validly signer-approved despite there being no actual signer consensus.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

    pub fn get_reward_threshold_and_participation(
        pox_settings: &PoxConstants,
        addresses: &[RawRewardSetEntry],
        liquid_ustx: u128,
    ) -> (u128, u128) {
        let participation = addresses
            .iter()
            .fold(0, |agg, entry| agg + entry.amount_stacked);

        assert!(
            participation <= liquid_ustx,
            "CORRUPTION: More stacking participation than liquid STX"
        );

        // set the lower limit on reward scaling at 25% of liquid_ustx
        //   (i.e., liquid_ustx / POX_MAXIMAL_SCALING)
        let scale_by = cmp::max(participation, liquid_ustx / POX_MAXIMAL_SCALING);

        let reward_slots = u128::try_from(pox_settings.reward_slots())
            .expect("FATAL: unreachable: more than 2^128 reward slots");
        let threshold_precise = scale_by / reward_slots;
        // compute the threshold as nearest 10k > threshold_precise
        let ceil_amount = match threshold_precise % POX_THRESHOLD_STEPS_USTX {
            0 => 0,
            remainder => POX_THRESHOLD_STEPS_USTX - remainder,
        };
        let threshold = threshold_precise + ceil_amount;
        info!(
            "PoX participation threshold is {}, from {} + {} ({}), participation is {}",
            threshold, threshold_precise, ceil_amount, scale_by, participation
        );
        (threshold, participation)
    }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

    #[cfg_attr(test, mutants::skip)]
    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
