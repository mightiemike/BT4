The CVE-2018-19761 report describes an illegal/out-of-bounds memory access in libsixel's raw decoder due to insufficient bounds validation while parsing untrusted image data. Searching protobuf-go's decode paths for the same broken invariant (missing bounds checks before buffer access), I found that all core decode/skip primitives consistently validate buffer length before every read:

- `protowire.ConsumeBytes`, `ConsumeFixed64`, `ConsumeVarint` (and their inlined fast-paths in `internal/impl/codec_gen.go`) check `len(b)` against the required size before indexing, returning `errCodeTruncated`/negative length on failure. [1](#0-0) 
- `internal/protolazy/bufferreader.go`'s `DecodeVarint`, `DecodeVarint32`, `Skip`, `SkipVarint`, `SkipFixed64/32`, and `SkipBytes` all check `i >= len(buf)` or `len(b.Buf) < b.Pos+n` before reading, returning `io.ErrUnexpectedEOF`/`errOutOfBounds` on truncation. [2](#0-1) [3](#0-2) 
- The lazy-index builder (`buildIndex`) and `SkipGroup`/`SkipValue` used for group/message skipping also route through the same bounds-checked primitives, failing with an explicit error rather than reading past the buffer.

func ConsumeBytes(b []byte) (v []byte, n int) {
	m, n := ConsumeVarint(b)
