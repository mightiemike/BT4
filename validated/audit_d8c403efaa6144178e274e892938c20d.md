**Rationale:**

`ValidatorPerformances`/`ValidatorPerformance` in [1](#0-0)  is a plain client-side deserialization struct (derives `Serialize`/`Deserialize` with no custom decode logic) used only by the Aptos CLI's `GetPerformance` command to parse a REST-fetched `0x1::stake::ValidatorPerformance` resource, as seen in [2](#0-1) . It has no other production references in the codebase.

This struct never participates in the VM execution path, write-set construction, storage commit, accumulator/Merkle proof construction, or authenticated API response binding on a node — it is purely a downstream tool that decodes whatever bytes are already committed on-chain, for display purposes only. The actual invariant that the `validators` vector length matches the active validator set is enforced (or violated) by the Move framework's `stake.move` module during reconfiguration, not by this Rust type. There is no custom BCS/serde logic here that could "accept" an inconsistent empty vector while masking a state-consistency error — it faithfully decodes exactly what was serialized on-chain.

Since this path is client-only presentation logic reading an already-authenticated resource via the REST API, and does not corrupt committed state, proof material, or misbind an authenticated response, it falls outside the State-Integrity Gate (explicitly excluded as "presentation without corrupting authenticated state").
