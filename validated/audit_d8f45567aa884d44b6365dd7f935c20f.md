## Finding

Given the TOML advisory's bug class (unbounded recursive parsing of a nested/tree-shaped structure leading to native stack overflow), the closest reachable analog in this sequencer is the unbounded recursive handling of the Casm "bytecode segment" tree (`NestedIntList` / `bytecode_segment_lengths`) that is produced when compiling a user-submitted Sierra class and is later re-walked recursively multiple times (hash computation, Starknet-OS re-execution) with no depth limit.

### Title
Unbounded recursion over attacker-influenced CASM bytecode-segment tree causes stack-overflow DoS during declare validation and OS re-execution - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
`CasmContractClass.bytecode_segment_lengths` is a recursively-defined `NestedIntList` tree produced by compiling a declarer's Sierra program. It is consumed by fully recursive, depth-unbounded functions in sequencer code — `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`, lines 111-132) and `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, lines 277-307) — every time the compiled class hash needs to be (re)computed: during declare-transaction validation (`check_compile_class_hash_v2_declaration` in `crates/starknet_api/src/executable_transaction.rs:226-244`), during blockifier declare execution, and during Starknet OS re-execution (`load_classes_and_create_bytecode_segment_structures` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/implementation.rs:169-226`). Neither function limits recursion depth, unlike the analogous jackson-dataformat-toml parser that recursed unboundedly over nested TOML tables.

### Finding Description
`bytecode_hash_node`: [1](#0-0) 
recurses once per nesting level of the `NestedIntList`/`HashableNestedIntList` tree with no depth check. The same unbounded pattern exists in the Starknet OS hint helper: [2](#0-1) 

The tree depth originates from the compilation of a declarer-supplied Sierra program by `SierraToCasmCompiler`, whose config only bounds total bytecode size, CPU time, and memory — not the resulting segment-tree nesting depth: [3](#0-2) 

By contrast, a separate, apparently-unused helper in blockifier explicitly enforces a shallow depth for its own (different, test/estimation-only) `NestedFeltCounts` structure: [4](#0-3) 
This assertion is not present in the actual hash-computation path (`bytecode_hash_node`) or the OS hint path (`create_bytecode_segment_structure_inner`), so a deeply nested segment tree is not rejected there — it will simply recurse until the stack overflows.

The computed/validated hash from this recursive walk is invoked directly on the declare-transaction path: [5](#0-4) 
and again inside the Starknet OS during block re-execution when loading declared classes: [6](#0-5) 

### Impact Explanation
If an unprivileged declarer can shape their Sierra program's control flow (nested conditionals/branches/functions) so that the compiler emits a sufficiently deep `bytecode_segment_lengths` tree, then every node in the network that (a) validates the declare transaction, (b) executes it in the blockifier, or (c) re-executes the block in the Starknet OS will recurse over that same tree with no depth limit. This can exhaust the native call stack and crash the process handling the transaction — a network-wide denial of service triggered by a single declare transaction, causing honest nodes to be unable to process new transactions/blocks (consistent with the "network unable to confirm new transactions" impact criterion).

### Likelihood Explanation
Reachability requires only a standard Declare V3 transaction from any account, following the existing transaction-submission flow (Gateway → Sierra compilation → declare validation/execution → later OS re-execution), with no special privileges. The main uncertainty is whether the external Sierra→CASM compiler (a dependency, `cairo_lang_starknet_classes`) can actually be driven to emit an arbitrarily deep segmentation tree from adversarial Sierra source; this determines exploitability but is not verifiable from the sequencer repository alone since the compiler's segmentation algorithm lives in that external crate.

### Recommendation
Add an explicit maximum-depth (and/or iterative, non-recursive) traversal for `NestedIntList`/`HashableNestedIntList` in both `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) and `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`), rejecting (as a compilation/validation error) any CASM class whose bytecode-segment tree exceeds a small, protocol-defined nesting bound — mirroring the depth assumption already asserted (but not enforced against untrusted input) in `NestedFeltCounts::new_inner`.

### Proof of Concept
Not independently verifiable from the sequencer repository alone: reproducing this requires crafting a Sierra program whose compilation via the external `cairo_lang_starknet_classes` Sierra→CASM compiler yields a `bytecode_segment_lengths: NestedIntList` tree with unbounded nesting depth, then submitting it as a Declare V3 transaction and observing a stack-overflow crash during `check_compile_class_hash_v2_declaration` / OS re-execution. This exact behavior of the external compiler could not be confirmed from code available in this repository.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }

    /// Verifies that the compiled class hash field in the declare tx,
    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {
            let err_var = CasmHashMismatch {
                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }
