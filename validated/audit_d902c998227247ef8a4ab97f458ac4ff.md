### Title
Dust rounding in `other-debt-repayable` can flip `no-collateral-left` and trigger premature bad-debt socialization during `liquidate` - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
In `liquidate()`, the decision to socialize bad debt (`no-collateral-left`) depends on `other-debt-repayable`, a value derived through a chain of round-down divisions applied to the USD value of the borrower's *other* (non-liquidated) collateral. When that other-collateral USD value is small but non-zero (dust), the round-down chain can produce `other-debt-repayable == u0` even though real collateral value still exists and has not been seized. This mirrors the reported bug class: a `round down` conversion silently zeroes out a dust value that is then used to flip a boolean gate (`isMissingMargin` in the report / `no-collateral-left` here) governing whether the flow should keep processing (continue liquidating / collecting fees) or stop (break loop / socialize bad debt).

### Finding Description
Inside `liquidate()`: [1](#0-0) 

```
(target-coll-full-usd (normalize (* user-coll-balance coll-price) coll-decimals false))
(other-coll-usd (if (> total-collateral-usd target-coll-full-usd)
                    (- total-collateral-usd target-coll-full-usd)
                    u0))
(other-debt-repayable
  (if (> other-coll-usd u0)
    (let ((other-adj (div-bps-down other-coll-usd (+ BPS liq-penalty-max)))
          (other-tokens (mul-div-down other-adj (pow u10 debt-decimals) debt-price))
          (other-borrow-idx (get index (unwrap-panic (get-cached-indexes debt-aid))))
          (other-scaled (mul-div-down other-tokens INDEX-PRECISION other-borrow-idx)))
      (mul-div-up other-scaled other-borrow-idx INDEX-PRECISION))
    u0))
(no-collateral-left (and
                      (is-eq coll-removed u0)
                      (or
                        (is-eq (len (get collateral pos-full)) u1)
                        (and
                          (is-eq (len (get collateral pos-full)) (len (get collateral position)))
                          (is-eq other-debt-repayable u0)))))
```

`other-coll-usd` represents the USD value of collateral the borrower still holds that was *not* touched by this `liquidate()` call. `other-debt-repayable` is meant to answer: "is there still meaningfully liquidatable value in that other collateral?" It is computed with `div-bps-down` (round down) followed by two `mul-div-down` steps and one `mul-div-up`. When `other-coll-usd` is a dust amount (non-zero but small relative to `BPS + liq-penalty-max`, or relative to `debt-price`/`INDEX-PRECISION` scaling), `other-adj` (and consequently `other-tokens`/`other-scaled`) rounds down to `u0`, making `other-debt-repayable` evaluate to `u0` even though `other-coll-usd > u0`.

This is exactly the analog of the report's root cause: `withdrawMarginUsd()` rounds `requiredMarginInCollateralX18` down, so a dust USD amount converts to `0` collateral units, which makes the `marginCollateralBalanceX18.gte(requiredMarginInCollateralX18)` check pass trivially and incorrectly sets `isMissingMargin = false`, short-circuiting the fee-collection loop in `deductAccountMargin()`. Here, the dust-to-zero rounding similarly flips `other-debt-repayable` to zero, which flips `no-collateral-left` to `true`, short-circuiting the position at the "no remaining collateral" branch and routing straight into bad-debt socialization — while the borrower actually still holds unliquidated (dust) collateral value that was never checked/seized.

Once `no-collateral-left` is (incorrectly) `true`: [2](#0-1) 

the contract strips the remaining debt for `debt-aid`, folds `socialize-debt-asset` over the borrower's remaining debt list, and prints `bad-debt-socialized: true` — socializing (i.e., writing off across the pool/LPs) debt that a subsequent, correctly-computed liquidation of the leftover dust collateral could still have partially or fully repaid.

### Impact Explanation
This causes premature bad-debt socialization: debt is written off / spread onto liquidity providers while the borrower still holds real (if small) collateral value that was never seized to offset that debt. This is a protocol-insolvency-class impact — value that should have backed the debt is left stranded on the borrower's position (permanently, since no future liquidation is triggered for a position now marked "settled" via socialization) while the loss is absorbed by the pool. This falls under the in-scope "protocol insolvency" / "permanent freezing of funds" impact category, matching the root-cause mechanics of the referenced report (a rounding-down conversion of a dust value flips a boolean flag that gates whether more value should be collected/seized, causing a short-circuit that leaves due value uncollected).

### Likelihood Explanation
Requires a specific but reachable state: a partially-liquidated borrower whose *other* collateral (beyond the asset being liquidated in this call) has been reduced by price movement/prior partial liquidations to a small residual USD value such that `div-bps-down(other-coll-usd, BPS+liq-penalty-max)` (and the subsequent down-roundings) truncate to zero. Given liquidations happen incrementally (partial liquidation curve) and multiple collateral types with independent price feeds are supported, dust residues across assorted decimals/price combinations are a realistic occurrence, though it needs the specific combination of small `other-coll-usd`, `debt-price`, and `INDEX-PRECISION` scaling to trigger the rounding-to-zero. This is a single-transaction analog (one `liquidate()` call), not requiring privileged access or multi-user collusion.

### Recommendation
Round the `other-debt-repayable` computation (or at minimum the intermediate `div-bps-down`/`mul-div-down` steps that determine whether "meaningful" other collateral remains) up rather than down, or explicitly treat `other-coll-usd > u0` as "collateral remains" without collapsing it through a lossy conversion chain before comparing to zero — i.e., gate `no-collateral-left` on `other-coll-usd` (or a round-up conversion of it) being zero, not on the round-down-derived `other-debt-repayable`.

### Proof of Concept
1. Borrower has two collateral assets: Collateral A (being liquidated in this call) and Collateral B (dust residual value, e.g. from prior partial liquidations or price decay).
2. Call `liquidate()` on Collateral A/debt-aid such that `coll-removed == u0` (Collateral A fully removed) and `len(pos-full.collateral) == len(position.collateral)` (position's collateral count unchanged from perspective of the mask check).
3. `other-coll-usd = total-collateral-usd - target-coll-full-usd` equals Collateral B's small USD value (non-zero).
4. `other-adj = div-bps-down(other-coll-usd, BPS + liq-penalty-max)` rounds down to `u0` because `other-coll-usd` is dust relative to `BPS + liq-penalty-max` (e.g., ~10,000–15,000 scale) — see [3](#0-2) .
5. `other-tokens`, `other-scaled`, and the final `mul-div-up` chain all evaluate to `u0`, so `other-debt-repayable = u0`.
6. `no-collateral-left` evaluates to `true` at [4](#0-3) , even though Collateral B still holds real (dust) value.
7. The subsequent branch strips and socializes the borrower's remaining debt via `fold socialize-debt-asset ...` at [5](#0-4) , writing off debt onto the pool while Collateral B remains unseized on the borrower's position.

Note: I could not fully verify the exact numeric magnitude thresholds for `BPS`, `liq-penalty-max`, `INDEX-PRECISION`, and `debt-price` scaling from the indexed snippets alone (their definitions were only partially retrieved), so the PoC above establishes the rounding mechanism and control-flow path rather than concrete trigger values; a Devin session with full file access would be needed to compute concrete numeric inputs that trigger the zero-rounding in a live/test environment.
