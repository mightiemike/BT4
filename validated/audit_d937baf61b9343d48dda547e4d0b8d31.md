### Title
Malformed base64 `host` causes uncaught `atob`/`URL` exception in `sanitizeHost`, crashing/500-ing the auth flow - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` validates `host` with `base64regex.test(host)` but that regex only checks the character set, not that the length is a multiple of 4, and never wraps the subsequent `decodeHost`/`new URL()` calls in a try/catch. An attacker-controlled `host` query parameter that is charset-valid base64 but decodes to bytes containing forbidden URL host code points (e.g. NUL, `@`, `<`, control chars) or has an invalid base64 length can make `atob` or `new URL('https://' + decoded)` throw, and that exception propagates uncaught out of `sanitizeHost`.

### Finding Description
`sanitizeHost` in [1](#0-0)  does:
```
let sanitizedHost = base64regex.test(host) ? host : null;
if (sanitizedHost) {
  const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);
  ...
``` [2](#0-1) 

`base64regex = /^[0-9a-zA-Z+/]+={0,2}$/` only checks allowed characters and optional padding, it does not require the string length to be a multiple of 4, which real base64 requires. `decodeHost` is a trivial `atob(host)` wrapper with no error handling: [3](#0-2) . A charset-valid but length-invalid string (e.g. a single character or any length not congruent to 0 mod 4 without correct padding) makes `atob` throw. Separately, even when `atob` succeeds, the decoded bytes are attacker-controlled arbitrary bytes and are concatenated directly into a URL string (`https://${decoded}`) and passed to the WHATWG `URL` constructor. If the decoded value contains forbidden host code points (NUL, TAB, LF, CR, space, `#`, `/`, `:`, `<`, `>`, `?`, `@`, `[`, `\`, `]`, `^`, `|`) before any legitimate delimiter, `new URL()` throws a `TypeError: Invalid URL`.

Neither `sanitizeHost` itself, nor its direct callers `buildEmbeddedAppUrl`/`getEmbeddedAppUrl` ( [4](#0-3) ), nor `validateShopAndHostParams` used by the Remix/React Router admin authentication flow ( [5](#0-4) ) wrap the call in a try/catch. The `host` parameter is a raw, unauthenticated query-string value fully controlled by any anonymous client hitting the app's embedded/OAuth entry points, so no HMAC/session-token/nonce check protects this code path — those checks apply to different request-level signatures and are irrelevant to this parameter.

### Impact Explanation
An unauthenticated attacker can trigger an uncaught exception inside the authentication/redirect entry point of any app using `shopify-app-remix`/`shopify-app-react-router`/`shopify-app-express` by supplying a crafted `host` query parameter. Depending on the host framework's error handling, this results in an unhandled promise rejection/500 error per request, potentially with a stack trace disclosed to the client, and repeated requests can be used to generate load/noise or as part of a denial-of-service style disruption of the auth handler. This matches the "DoS in an authentication handler" bounty impact class.

### Likelihood Explanation
No preconditions are required beyond the library running its default configuration: the attacker only needs to send an HTTP GET/POST with a crafted `host` query parameter to any endpoint that calls `authenticate.admin()` (Remix/React Router) or `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` (core `shopify-api`), or any Express middleware invoking `sanitizeHost`. This is trivially and repeatably reproducible from the public internet with a single crafted request; no secret, session, or app-developer privilege is needed.

### Recommendation
Wrap the `decodeHost`/`new URL()` call in `sanitizeHost` in a try/catch and treat any thrown error as an invalid host (return `null` or throw `InvalidHostError` consistent with existing behavior), and tighten `base64regex` to also enforce a valid base64 length (`^(?:[0-9a-zA-Z+/]{4})*(?:[0-9a-zA-Z+/]{2}==|[0-9a-zA-Z+/]{3}=)?$` or equivalent), e.g.:
```ts
let sanitizedHost: string | null = null;
if (base64regex.test(host)) {
  try {
    const {hostname} = new URL(`https://${decodeHost(host)}`);
    sanitizedHost = host;
    // ... existing regex check
  } catch {
    sanitizedHost = null;
  }
}
```

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts

import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('sanitizeHost does not throw on malformed base64 length', () => {
  const shopify = shopifyApi(testConfig());
  // charset-valid per base64regex but invalid base64 length -> atob throws
  expect(() => shopify.utils.sanitizeHost('a')).not.toThrow();
});

test('sanitizeHost does not throw when decoded host contains forbidden URL host code points', () => {
  const shopify = shopifyApi(testConfig());
  // decodes to a string containing a NUL byte before any path separator
  const malicious = Buffer.from('evil\x00host.com/admin').toString('base64');
  expect(() => shopify.utils.sanitizeHost(malicious)).not.toThrow();
});
```
Both assertions currently fail (the calls throw uncaught `TypeError`/`DOMException` instead of returning `null`), demonstrating the unhandled-exception DoS surface reachable via the `host` query parameter.
