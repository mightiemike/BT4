## Title
Gas fee under-collection via integer-division truncation of fractional EIP-1559 base fee - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` recovers the "actual" per-upc base fee from the `feemarketKeeper.GetBaseFee` `LegacyDec` by doing a raw integer division of the Dec's internal big.Int representation by `1e18`. This mirrors the reported `Reserve.sol` bug class: instead of using the actual/precise value, the code unwraps a fixed-point/scaled representation with a lossy operation, silently discarding a fractional component and using a systematically lower value than the correct one wherever the base fee is not an exact integer number of `upc`.

### Finding Description
`CalculateGasCost` in [1](#0-0)  takes the current EVM base fee as a `sdkmath.LegacyDec` and does:

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

`LegacyDec.BigInt()` returns the *raw internal* big.Int, which encodes the decimal value with 18 digits of fixed-point precision (`internal = value * 1e18`). The code assumes `baseFee` is always a whole number of `upc` (per the inline comment at [2](#0-1) ), and therefore treats this division as a clean "unwrap." In practice, the `feemarket` module's base fee is adjusted every block by an EIP-1559-style formula (`baseFee * (1 ± gasUsedDelta/target/denominator)`), which routinely produces fractional `Dec` values. Any fractional component (e.g. `baseFee = 5.7`) is truncated to `5` by the integer `Div`, exactly analogous to the `Reserve.sol` bug of consuming a scaled supply value instead of the true one and ending up below the intended amount.

This value feeds directly into `effectiveGasPrice` and then `gasCost = effectiveGasPrice * gasUsed` at [3](#0-2) , which is charged and burned from the UEA/recipient account via `DeductGasFeesFromReceipt` → `DeductAndBurnFees` on every `MsgExecutePayload` call, reachable by any ordinary unprivileged user executing a universal payload: [4](#0-3)  and [5](#0-4) .

### Impact Explanation
This corrupts native gas-fee accounting network-wide: every payload execution whose current base fee has a non-zero fractional `upc` component (the common case under EIP-1559-style adjustment) burns strictly less than the protocol's own computed "correct" fee. This is a persistent, unprivileged-triggerable under-collection of protocol-burned fees (matches the in-scope impact "corruption of ... gas fee accounting ... reachable from ordinary user deposits, payloads, contracts, or default transaction submission paths alone"). The per-transaction magnitude is small (less than 1 `upc`), but it is systematic and occurs on essentially every `MsgExecutePayload` call, permanently eroding intended fee/burn accounting versus the on-chain fee-market state.

### Likelihood Explanation
High likelihood of occurrence (not adversarial-timing dependent): the EIP-1559 base-fee adjustment formula used by the `feemarket` module almost never lands on an exact integer number of `upc`, so the truncation triggers on nearly every block/transaction. No privileged access or special conditions are required — any user submitting a normal `MsgExecutePayload` transaction exercises this path.

### Recommendation
Do not perform a lossy integer division on the raw internal representation to "recover" the base fee. Instead, keep the computation in `LegacyDec`/`Int` domain preserving precision — e.g., compute `gasCost := baseFee.MulInt64(int64(gasUsed))` (or the big.Int equivalent) and only round/truncate the *final* total gas cost (in upc) once, rather than truncating the per-gas-unit base fee first. This mirrors the `Reserve.sol` fix of using the actual (non-scaled) value for the invariant-critical calculation.

### Proof of Concept
1. Let the `feemarket` base fee for the current block resolve to `5.7` `upc` (a realistic value after any block with gas usage above/below the target, since the adjustment formula is `baseFee * (1 ± Δ)`).
2. A user calls `MsgExecutePayload`, and after EVM execution `DeductGasFeesFromReceipt` calls `CalculateGasCost(baseFee=5.7, ..., gasUsed=100000)`.
3. `baseFeeBig := baseFee.BigInt()` → `5700000000000000000` (5.7 × 1e18).
4. `baseFeeBig.Div(baseFeeBig, 1e18)` → `5` (truncated, losing `0.7`).
5. `gasCost = 5 * 100000 = 500000` upc is burned instead of the "true" `5.7 * 100000 = 570000` upc — a 12% under-charge/under-burn for that transaction, repeatable on every subsequent payload execution while the base fee remains fractional.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}
```

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
