### Title
Auto-swap gas-abstraction and gas-refund flows derive slippage protection from a same-transaction spot quote, allowing MEV extraction of user/protocol funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The seed report describes routers losing value because a swap's slippage bound (`_maxIn`) was derived from stale/divergent state relative to the actual amount being swapped, letting slippage silently drain funds. Push Chain's `x/uexecutor` module has an analogous pattern in its PRC20→native-PC auto-swap paths: the `minPCOut` slippage floor is computed from a spot AMM quote fetched via `GetSwapQuote` (Uniswap `QuoterV2.quoteExactInputSingle`) *inside the same keeper call* that immediately executes the swap (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`), rather than from a user-supplied slippage tolerance or a manipulation-resistant price source (e.g., TWAP).

### Finding Description
Three call sites share the identical pattern: fetch a spot quote, apply a flat 5% tolerance, then immediately execute the swap using that quote as the only protection:

- `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`): `quote, execErr = k.GetSwapQuote(...)` then `minPCOut := quote * 95 / 100` then `k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)`. [1](#0-0) 
- `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379`) does the same thing for `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` deposits. [2](#0-1) 
- `applyGasRefund` (`x/uexecutor/keeper/outbound.go:174-257`) does the same for the excess-gas refund swap-back to native PC, via `getSwapQuoteForRefund` + `CallUniversalCoreRefundUnusedGas`. [3](#0-2) 

`GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) calls the Uniswap `QuoterV2` non-committed, which reads the pool's *current* reserves/tick state at call time — it is a spot price, not a TWAP or externally-verified price. [4](#0-3) 

Because the quote and the swap execution happen back-to-back in the same keeper invocation (triggered deterministically the moment ballot quorum is reached, which is publicly observable from pending `MsgVoteInbound`/`MsgVoteOutbound` transactions in the mempool), an unprivileged actor can manipulate the on-chain AMM pool (e.g. `WPC`/`PRC20` pool on Push Chain) immediately before the triggering vote lands, depressing the spot price. The `minPCOut` floor is then computed from the already-depressed price, so the subsequent `depositPRC20WithAutoSwap` / `refundUnusedGas` swap executes at the manipulated price and the 5% band provides no real protection — it merely tracks whatever price the attacker set. The attacker can then reverse their manipulation trade in the same or an adjacent block, extracting the difference as profit while the bridging user (or the gas-refund recipient) receives less native PC than the honest market price would have produced.

This mirrors the seed bug's core defect class: a "slippage protection" bound that is derived from the same corrupted/divergent context as the swap it is meant to protect, rather than from an independent, attacker-resistant reference, enabling silent value extraction from user/protocol-controlled funds.

### Impact Explanation
This falls squarely in scope: it is unauthorized draining of user-controlled funds during a default, non-privileged deposit/gas-abstraction/gas-refund flow, reachable by any external actor who can submit ordinary swap transactions against the Push Chain-hosted Uniswap pool. No validator, TSS, or admin compromise is required — only normal universal-validator honesty is assumed. The magnitude scales with pool depth and the fixed 5% tolerance, and recurs on every GAS/GAS_AND_PAYLOAD/FUNDS_AND_PAYLOAD inbound and every outbound gas refund, making it a systemic value-leak rather than a one-off edge case.

### Likelihood Explanation
Likelihood is high in early/low-liquidity phases (new PRC20/WPC pools deployed by the protocol itself) because: (1) the execution trigger point (ballot quorum reached) is deterministic and publicly visible before it lands, enabling precise front-running; (2) the swap always uses the module's own liquidity pools, which an attacker can freely trade against; (3) no external price oracle or TWAP cross-check exists to detect manipulation; (4) the 5% band is a fixed constant, not a function of pool depth, so shallow pools are trivially moved beyond that band and back.

### Recommendation
Do not derive `minPCOut` from a spot quote fetched in the same transaction that performs the swap. Instead: use a TWAP or otherwise manipulation-resistant price source; allow an explicit, user/relayer-supplied minimum-out parameter carried from the original inbound/outbound message (if available) rather than a keeper-computed spot-based value; or bound trade size/impact and add circuit breakers (e.g., reject if quoted price deviates significantly from a recent moving average) so the same-block quote cannot be used as the sole slippage protection.

### Proof of Concept
1. Attacker observes a `MsgVoteInbound` (GAS type) reaching quorum in the mempool, which will trigger `ExecuteInboundGas` for a bridging user.
2. Immediately before it is included, attacker submits a large swap against the same PRC20/WPC Uniswap pool on Push Chain to depress the PRC20→WPC price.
3. `ExecuteInboundGas` calls `k.GetSwapQuote(...)` which reads the now-depressed spot price, computes `minPCOut = quote*95/100` (still depressed), and calls `k.CallPRC20DepositAutoSwap(...)` which executes at the depressed price — well below the pre-manipulation fair value, but still "successfully" clears the (also depressed) `minPCOut` floor. [5](#0-4) 
4. Attacker reverses their manipulation trade in a following transaction/block, extracting the price difference; the bridging user's UEA receives fewer native PC tokens than fair-market conversion would have produced.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
