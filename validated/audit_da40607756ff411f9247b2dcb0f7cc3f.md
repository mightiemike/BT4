### Title
Integer-truncation of base fee to zero permanently defeats gas-fee burn for universal payload execution - ([File: x/uexecutor/keeper/fees.go])

### Summary
`Keeper.CalculateGasCost` truncates the fee-market `baseFee` (an 18‑decimal `LegacyDec`) to whole `upc` units via integer division before computing the gas cost that gets deducted and burned for module-originated EVM execution. When the dynamic base fee decays below one whole `upc` (a normal, unprivileged consequence of sustained low network utilization under the EIP-1559-style fee market), the truncation yields `effectiveGasPrice = 0`, so `gasCost = 0`. `DeductGasFeesFromReceipt` then short-circuits (`gasCost.Sign() <= 0 → return nil`) and skips `DeductAndBurnFees` entirely, letting an unprivileged user execute arbitrarily gas-heavy universal payloads for zero cost. This is the same rounding-to-zero class as the referenced Lido bug (an amount that should be a small-but-nonzero value rounds down to exactly zero and the code fails to reject/handle that case), here applied to Push Chain's gas-fee accounting instead of Lido's share accounting.

### Finding Description
`CalculateGasCost` in [1](#0-0)  unwraps the `LegacyDec` base fee back into whole `upc` units using plain integer division: [2](#0-1) 

Because `sdkmath.LegacyDec` always stores an 18-decimal-precision fractional value internally, and the EIP-1559-style fee market adjusts `baseFee` up or down (by design) in fractional increments each block, `baseFee` will naturally take on values below `1e18` (i.e., below 1 whole `upc`) whenever the chain experiences sustained below-target gas usage — an entirely ordinary, unprivileged, non-adversarial network condition (the same mechanism that lets Ethereum's `baseFeePerGas` trend toward very small values under low demand). When that happens, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`, making `effectiveGasPrice = 0` and therefore `gasCost = effectiveGasPrice * gasUsed = 0` regardless of how much gas was actually used.

`DeductGasFeesFromReceipt` treats this truncated zero as "nothing to charge" and returns early without burning any fee: [3](#0-2) 

This function is the sole gate for charging gas fees on module-originated `CallExecuteUniversalTx` / `DerivedEVMCall` executions triggered by inbound CEA/UEA payload flows, e.g. in `ExecuteInboundGasAndPayload`: [4](#0-3) 

There is no lower bound enforced on `baseFee` before this division, and no explicit check rejecting a computed `gasCost` of `0` when `gasUsed > 0` (the Lido-style "reject zero" guard that the original report recommends is missing here too).

### Impact Explanation
This corrupts gas-fee accounting: any unprivileged actor whose inbound/UEA payload gets executed through the universal execution path pays **zero** protocol fee for arbitrary EVM gas consumption once `baseFee` (as tracked by the fee market module) decays below one whole `upc`. Concretely this causes:
- Permanent loss of protocol fee revenue (the fee-burn mechanism is silently bypassed).
- A denial-of-service vector reachable without any privileged control: once base fee is in this regime, an attacker can spam gas-heavy universal payload executions with no economic cost, consuming validator/node computation resources for free.

This falls within the allowed impact gate for "corruption of ... gas fee accounting" and "denial of service ... reachable without privileged control," and is triggered purely by ordinary user payload submission once the network reaches a normal, non-adversarial fee-market state — no malicious validator, node, or privileged actor is required.

### Likelihood Explanation
The base fee only needs to drop below `1e18` (1 whole `upc`) for the bug to trigger, which is a natural steady-state outcome of the standard EIP-1559 base-fee adjustment algorithm during periods of low network utilization (each block can decrease base fee by up to ~12.5%, so a run of low-usage blocks converges toward sub-unit values). There is no minimum-base-fee floor enforced above 1 `upc` visible in this code path, and the condition is entirely reachable by ordinary transaction/network activity (or lack thereof) rather than requiring any special privilege.

### Recommendation
Do not truncate `baseFee` to whole `upc` before multiplying by `gasUsed`. Perform the multiplication in the higher-precision `LegacyDec` domain first (`baseFee.MulInt64(int64(gasUsed))`), then round the final result (e.g., `Ceil()`) back to an integer `upc` amount, or otherwise assert a floor value guaranteeing at least 1 `upc` per unit of gas used. In all cases, mirror the Lido fix: when `gasUsed > 0`, reject/round the computed `gasCost` such that it is never zero due to rounding — e.g., `gasCost = max(gasCost, 1)` when gasUsed > 0, or fail loudly instead of silently skipping the burn in `DeductGasFeesFromReceipt`.

### Proof of Concept
1. Let `baseFee` (as tracked by `feemarketKeeper.GetBaseFee`) decay, through normal EIP-1559-style adjustment over a sequence of low-utilization blocks, to any `LegacyDec` value `v` such that `0 < v < 1.0` (e.g. `v = 0.9`, internal big.Int representation `900000000000000000`).
2. A user submits an inbound CEA/UEA payload that is routed through `ExecuteInboundGasAndPayload` → `CallExecuteUniversalTx`, consuming e.g. `gasUsed = 500,000`.
3. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18)` → `0` (integer truncation of `0.9`), so `effectiveGasPrice = 0` and `gasCost = 0 * 500000 = 0`.
4. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without calling `DeductAndBurnFees`.
5. The 500,000 gas of EVM execution was fully performed at zero cost to the caller, and no `upc` was burned, even though real computational work occurred — repeatable indefinitely while `baseFee < 1e18`.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
