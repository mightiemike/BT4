### Title
Floor-rounded (non-ceiling) archival-data gas cost calculation can yield zero fee for non-zero calldata/signature/code size - (File: crates/blockifier/src/fee/resources.rs)

### Summary
`ArchivalDataResources::get_calldata_and_signature_gas_cost` and `get_code_gas_cost` compute gas cost as a `Ratio` (fractional cost-per-unit) multiplied by a data-size count, then truncate with `.to_integer()` (floor rounding) rather than `.ceil()`. Every other fee-relevant fractional-to-integer conversion in this codebase deliberately rounds **up** to avoid under-charging, but these two archival-data cost functions round **down**, reproducing the exact "fee-less" rounding-to-zero bug class described in the external report (`wadMul` truncation letting small amounts pay zero fee).

### Finding Description
`get_calldata_and_signature_gas_cost` and `get_code_gas_cost` multiply a `ResourceCost` (a `Ratio<u128>`, i.e. a fractional gas-per-unit constant from `VersionedConstants`) by the felt/byte count of the transaction's calldata, signature, or class code, and then convert to an integer amount via `.to_integer()`, which truncates towards zero: [1](#0-0) [2](#0-1) 

This is inconsistent with the rest of the fee-accounting code in the same crate, which explicitly rounds up fractional gas costs to prevent under-billing. For example:
- `calculate_resource_gas_cost` uses `.ceil().to_integer()`: [3](#0-2) 
- Sierra/L1 gas conversions explicitly document "upward rounding": [4](#0-3) 
- `to_discounted_l1_gas` uses `checked_div_ceil` for the same reason: [5](#0-4) 

If `gas_per_data_felt` (or `gas_per_code_byte`) is a fraction less than 1 in the relevant gas unit for a given `VersionedConstants` release, then for a small enough non-zero `extended_calldata_length + signature_length` (or `code_size`), the product `gas_per_data_felt * total_data_size` is less than 1, and `.to_integer()` truncates it to `0`. That resource dimension of the gas vector — and thus of the fee ultimately charged via `GasVector::cost` — silently contributes zero, even though the sender consumed a real, non-zero amount of that resource (bytes stored/proven on L2).

### Impact Explanation
Because `TransactionResources::to_gas_vector` feeds directly into the actual fee charged to the sender (`get_fee_by_gas_vector` → `GasVector::cost`), an attacker who crafts transactions whose calldata/signature/code sizes fall exactly in the truncation-to-zero range can have that resource-consumption dimension priced at zero. Depending on constants in effect for a given protocol version, this allows systematically under-priced (partially fee-less) transactions to be admitted and executed by the sequencer, which is a concrete loss of protocol revenue/mispricing of consumed resources — analogous in class and root cause to the referenced `calculateLoanOriginationFee` bug (fixed there by rejecting any loan whose fee rounds to zero).

### Likelihood Explanation
Reachable directly by any transaction sender: `extended_calldata_length`, `signature_length`, and `code_size` are attacker-controlled inputs of ordinary invoke/declare transactions, and the resulting gas vector flows straight into fee computation without any zero-cost validation/rejection step, unlike the safeguard the upstream Aave report ultimately adopted (reject if computed fee/cost is zero). Whether this is exploitable in practice depends on the concrete numeric value of `gas_per_data_felt`/`gas_per_code_byte` in the currently active `VersionedConstants` JSON (e.g. `blockifier_versioned_constants_0_14_3.json`); I was not able to fully inspect those numeric values before running out of tool budget, so likelihood should be confirmed by checking whether any active/historical version's `gas_per_data_felt` or `gas_per_code_byte` value is `< 1` in its respective gas unit.

### Recommendation
Change `get_calldata_and_signature_gas_cost`, `get_code_gas_cost`, and `get_client_side_proof_gas_cost` to use `.ceil().to_integer()` (matching `calculate_resource_gas_cost` and the Sierra/L1 conversion helpers) instead of plain `.to_integer()`, so that any non-zero resource consumption is guaranteed to round to at least 1 gas unit rather than truncating to zero. Add regression tests asserting that minimal non-zero calldata/signature/code sizes never produce a zero gas-vector component for any supported `VersionedConstants` version.

### Proof of Concept
1. Pick (or confirm) a `VersionedConstants` version where `archival_gas_costs.gas_per_data_felt` (from `get_archival_data_gas_costs`) is a `Ratio` `< 1` (e.g. a value like `1/2` or smaller expressed as gas per felt).
2. Submit an ordinary V3 invoke transaction with `extended_calldata_length + signature_length` small enough that `gas_per_data_felt * total_data_size < 1`.
3. Observe that `get_calldata_and_signature_gas_cost` at [6](#0-5)  yields `GasAmount(0)` for that component despite non-zero calldata/signature bytes, so the sender is not charged for that resource dimension in the final fee, unlike the ceil-rounded computation used for every other analogous fee/gas conversion in the codebase.

    /// Returns the cost for transaction calldata and transaction signature. Each felt costs a
    /// fixed and configurable amount of gas. This cost represents the cost of storing the
    /// calldata and the signature on L2.
    fn get_calldata_and_signature_gas_cost(
        &self,
        versioned_constants: &VersionedConstants,
        mode: &GasVectorComputationMode,
    ) -> GasVector {
        let archival_gas_costs = versioned_constants.get_archival_data_gas_costs(mode);

        // TODO(Avi, 20/2/2024): Calculate the number of bytes instead of the number of felts.
        let total_data_size = u64_from_usize(self.extended_calldata_length + self.signature_length);
        let gas_amount =
            (archival_gas_costs.gas_per_data_felt * total_data_size).to_integer().into();

        match mode {
            GasVectorComputationMode::All => GasVector::from_l2_gas(gas_amount),
            GasVectorComputationMode::NoL2Gas => GasVector::from_l1_gas(gas_amount),
        }
    }

pub fn to_discounted_l1_gas(
    l1_gas_price: NonzeroGasPrice,
    l1_data_gas_price: GasPrice,
    l1_gas: GasAmount,
    l1_data_gas: GasAmount,
) -> GasAmount {
    let l1_data_gas_fee = l1_data_gas.checked_mul(l1_data_gas_price).unwrap_or_else(|| {
        panic!(
            "Discounted L1 gas cost overflowed: multiplication of L1 data gas ({l1_data_gas}) by \
             L1 data gas price ({l1_data_gas_price}) resulted in overflow."
        );
    });
    let l1_data_gas_in_l1_gas_units =
        l1_data_gas_fee.checked_div_ceil(l1_gas_price).unwrap_or_else(|| {
            panic!(
                "Discounted L1 gas cost overflowed: division of L1 data fee ({l1_data_gas_fee}) \
                 by regular L1 gas price ({l1_gas_price}) resulted in overflow."
            );
        });
    l1_gas.checked_add(l1_data_gas_in_l1_gas_units).unwrap_or_else(|| {
        panic!(
            "Overflow while computing discounted L1 gas: L1 gas ({l1_gas}) + L1 data gas in L1 \
             gas units ({l1_data_gas_in_l1_gas_units}) resulted in overflow."
        )
    })
}
