### Title
Node Panic via Unguarded `.unwrap()` in `receipt_filter_fn` When Processing Stale `GlobalContractDistribution` Receipts After Resharding - (File: `runtime/runtime/src/congestion_control.rs`)

---

### Summary

`DelayedReceiptQueueWrapper::receipt_filter_fn` calls `.unwrap()` directly on the `Result` returned by `Receipt::receiver_shard_id`. For `GlobalContractDistribution` receipts whose embedded `target_shard` no longer exists in the current shard layout (because the shard was split during resharding), `receiver_shard_id` returns `Err(EpochError::ShardingError(...))`. The `.unwrap()` converts that error into a process-level panic, crashing the node. An ordinary user who deploys a global contract while the delayed-receipt queue is saturated can force this receipt to survive across a resharding boundary and trigger the panic.

---

### Finding Description

`receipt_filter_fn` is called from `DelayedReceiptQueueWrapper::pop` (and `peek_iter`) every time a delayed receipt is dequeued during chunk application:

```rust
// runtime/runtime/src/congestion_control.rs  lines 874-878
fn receipt_filter_fn(&self, receipt: &ReceiptOrStateStoredReceipt) -> bool {
    let shard_layout = self.epoch_info_provider.shard_layout(&self.epoch_id).unwrap(); // (1)
    let receipt_shard_id = receipt.get_receipt().receiver_shard_id(&shard_layout).unwrap(); // (2)
    receipt_shard_id == self.shard_id
}
```
