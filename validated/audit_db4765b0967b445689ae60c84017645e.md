### Title
Cairo 0 (deprecated) compiled classes cached from a reverted/non-canonical block are never revalidated against current declared-state - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` caches compiled classes in the long-lived, cross-block `ContractClassManager` global cache. For Cairo1 classes it explicitly re-validates a cache hit against the *current* state via `is_declared`, because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)". For Cairo0 (`RunnableCompiledClass::V0`) classes this revalidation is skipped entirely, so a class cached from a block that never became canonical is trusted forever afterwards, exactly like the reported Uniswap issue where a value snapshotted at one point in time is trusted for later security-relevant decisions without re-checking the live ground truth.

### Finding Description
`get_compiled_from_class_manager` reads the shared, persistent contract-class cache: [1](#0-0) 

```rust
if let Some(runnable_class) = self.contract_class_manager.get_runnable(...) {
    match &runnable_class {
        RunnableCompiledClass::V0(_) => {}
        _ => {
            // The Cairo1 class is cached; verify it is declared,
            // since existence in the cache does not guarantee that
            // (it might contain a declared class from a reverted block, for example).
            if !self.state_reader.is_declared(class_hash)? {
                return Err(StateError::UndeclaredClassHash(class_hash));
            }
        }
    }
    ...
    return Ok(runnable_class);
}
```

The `is_declared` contract explicitly documents that it can never validate Cairo0 classes: [2](#0-1) , so the `V0` branch is a no-op — a cache hit for a deprecated (Cairo0) class is returned unconditionally, with no check that the class is actually declared in the state currently being executed.

The cache that backs this lookup (`ContractClassManager`/`GlobalContractCache`) is a process-level, cross-block cache, not scoped to a single block's `CachedState`: [3](#0-2)  and [4](#0-3) . An entry is inserted the first time `get_compiled_classes` succeeds against *some* state reader on a cache miss: [5](#0-4) .

If a Cairo0 class hash is observed as declared while executing/building against a state that is later discarded (e.g., a rejected/rewound block-building attempt or a reorg — normal sequencer operations, not requiring a malicious operator), the class stays cached. On the canonical state, where that class hash was never actually declared, any subsequent transaction touching this class hash (e.g., an Invoke or a Library-call referencing it) will hit the cache and be treated as declared, since the `V0` branch performs no revalidation. This is precisely the audited bug class: a value captured once (`is_declared == true` at cache-insertion time) is trusted indefinitely for a security-relevant decision (whether execution against an undeclared class is even legal), even though the authoritative state can and does change.

The dedicated regression tests for this exact reorg scenario only cover the Cairo1 path (`cairo_1_declared_then_verification_failed_after_reorg`); there is no analogous test/guard for Cairo0: [6](#0-5)  vs. the untested/unchecked V0 scenario [7](#0-6) .

### Impact Explanation
An honest sequencer node that (correctly) has never observed this class hash declared on the canonical chain would reject execution with `UndeclaredClassHash`, while a node whose long-lived class cache was poisoned by an earlier non-canonical/reverted view of the state will silently execute the transaction against the stale cached bytecode. This produces execution-result divergence between nodes (different receipts, different state diffs), leading to a wrong committed state root/block hash for the affected node and consensus/re-execution mismatches against the Starknet OS, which strictly requires that only genuinely declared classes are executable.

### Likelihood Explanation
The trigger requires only ordinary conditions reachable by any transaction sender: (1) submit a Declare (Cairo0) transaction that is included in some transient/candidate block state that is subsequently not the one that gets committed (block-building retries, discarded proposals, or a chain reorg — all part of normal sequencer/consensus operation, no malicious operator needed), and (2) afterward submit any transaction that references that class hash on the canonical chain. No special privileges beyond issuing transactions are required.

### Recommendation
Remove the `V0` special case and apply the same `is_declared`-style revalidation to Cairo0 classes on every cache hit (or extend `is_declared` to also cover Cairo0), so that cached compiled classes are always re-checked against the state actually being executed, mirroring the fix already applied for Cairo1 classes.

### Proof of Concept
1. Build/propose a block that executes a `Declare` transaction for a Cairo0 class `C` against state reader `R1`; `get_compiled_from_class_manager` misses the cache, calls `R1.get_compiled_classes(C)` successfully, and inserts `C` into the shared `ContractClassManager` cache ( [8](#0-7) ).
2. That block/proposal is discarded/rewound (reorg or failed proposal round) so the canonical state `R2` never contains a declaration for `C`.
3. Submit an `Invoke`/library-call transaction referencing class `C` for execution against `R2`. `get_compiled_from_class_manager` hits the cache; since `RunnableCompiledClass::V0` skips the `is_declared` check, it returns `Ok(runnable_class)` instead of `Err(StateError::UndeclaredClassHash(C))`.
4. The node executes the transaction using the stale class, producing a receipt/state diff that an honest node (without the poisoned cache) would never produce, resulting in state root/block hash divergence.

impl CompiledClasses {
    pub fn to_runnable(&self) -> RunnableCompiledClass {
        match self {
            CompiledClasses::V0(compiled_class_v0) => {
                RunnableCompiledClass::V0(compiled_class_v0.clone())

            CompiledClasses::V1(compiled_class_v1, _sierra_contract_class) => {
                RunnableCompiledClass::V1(compiled_class_v1.clone())

                CachedCairoNative::Compiled(native_compiled_class_v1) => {
                    RunnableCompiledClass::V1Native(native_compiled_class_v1.clone())
                }
                CachedCairoNative::CompilationFailed(compiled_class_v1) => {
                    RunnableCompiledClass::V1(compiled_class_v1.clone())
                }
            },
        }
