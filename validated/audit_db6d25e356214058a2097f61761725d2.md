### Title
PoisonMicroblock accepts ECDSA-malleated re-encodings of a single signature as "two conflicting microblocks", allowing reward theft from an honest miner - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`, `stacks-codec/src/transaction.rs`)

### Summary
`handle_poison_microblock` and its supporting codec/validation checks only verify that two `StacksMicroblockHeader` structs are byte-unequal and recover to the same public key; they never verify that the headers actually encode distinct signed content beyond `sequence`/`prev_block` co-incidence. Because `check_recover_pubkey` uses `recover_to_pubkey_without_validating_low_s` (non-canonical signature acceptance), an attacker can take a single, honestly-broadcast microblock header and derive a second, byte-distinct `MessageSignature` (ECDSA malleation: `s' = n - s`, flipped recovery id) over the exact same digest, producing a "second" header that is structurally different but represents the same single signing event. This forged pair passes every check in the poison path and lets the attacker collect the `POISON_MICROBLOCK_COMMISSION_FRACTION` of an honest miner's coinbase reward, without any real equivocation having occurred and without needing any signer's private key.

### Finding Description
The claimed-broken equality: **"a valid PoisonMicroblock proof exists" should be equivalent to "the same signer produced two distinct signed microblocks at the same fork point."** The code base actually implements a weaker equality: "two distinct byte-encodings of a `StacksMicroblockHeader`, both recovering to the same pubkey hash, that agree on `sequence` or `prev_block`."

- Codec-level guard (`stacks-codec/src/transaction.rs`, `TransactionPayload::consensus_deserialize`, `PoisonMicroblock` arm) only checks:
```
if h1 == h2 { reject "microblock headers match" }
if h1.sequence != h2.sequence && h1.prev_block != h2.prev_block { reject "do not identify a fork" }
``` [1](#0-0) 
This equality check is on the full struct (including `signature`), so any signature-byte difference makes `h1 != h2` even if `(version, sequence, prev_block, tx_merkle_root)` — the actual signed content — is identical.

- The digest that gets signed excludes the signature field entirely:
```
fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
    self.serialize(&mut bytes, true) // empty_sig = true, zeroes out signature
    ...
}
``` [2](#0-1) 
So if `(version, sequence, prev_block, tx_merkle_root)` are identical between `h1` and `h2`, the signed digest is bit-for-bit identical for both headers.

- `check_recover_pubkey` calls `recover_to_pubkey_without_validating_low_s`, i.e. it does not enforce canonical/low-S signatures, which means the classical ECDSA malleability `(r, s) -> (r, n-s)` with a flipped recovery id is accepted as a valid, distinct-byte signature that recovers to the *same* public key for the *same* digest. [2](#0-1) 

- `handle_poison_microblock` and its helper `check_microblock_header_signer` only check that both headers recover to the same pubkey hash — they never re-check that `tx_merkle_root`/`prev_block` genuinely differ (only "same sequence" is required, trivially true for identical headers):
```

**Exploit flow:** Attacker observes any legitimately-broadcast microblock header `h1 = (version, sequence, prev_block, tx_merkle_root, sig=(r,s,v))` signed by the miner's microblock key. Attacker computes the malleated signature `sig' = (r, n-s, 1-v)` (public-key-only operation, no private key needed). Attacker builds `h2 = h1` with `signature = sig'`. `h1 != h2` (codec passes), `h1.sequence == h2.sequence` (fork-identification check passes trivially), `check_recover_pubkey(h1) == check_recover_pubkey(h2)` (same pubkey — codec/handler pass). The resulting `PoisonMicroblock(h1, h2)` transaction is accepted by `process_transaction`, and the attacker (as reporter) is credited a commission of the honest miner's coinbase via `POISON_MICROBLOCK_COMMISSION_FRACTION`, even though the miner never equivocated — only one microblock was ever produced.

This bypasses the intended guard because the codec's "headers match" check operates on the full struct (which includes the mutable/malleable `signature` field) rather than on the semantically-relevant content fields, and because the pubkey-recovery routine explicitly permits non-canonical (malleated) signatures.

### Impact Explanation
An attacker can slash/steal part of an honest miner's block reward (`POISON_MICROBLOCK_COMMISSION_FRACTION` of the coinbase, per `stackslib/src/chainstate/stacks/tests/block_construction.rs` reward-loss test pattern) by fabricating a fake "equivocation" from a single, honestly-signed microblock header, using only publicly observable data (no keys, no majority stake, no equivocation by the miner). This is direct block-reward theft/misappropriation matching the Critical category ("block-reward theft/double-payment/loss"), and it can be repeated against every miner's every published microblock header up until the `MINER_REWARD_MATURITY` window closes.

### Likelihood Explanation
- Preconditions: attacker needs to observe one broadcast, validly-signed `StacksMicroblockHeader` (any microblock published by any miner qualifies) before its underlying pubkey-hash "matures" (`MINER_REWARD_MATURITY` blocks).
- Cost: zero BTC/stake — malleating an ECDSA signature (`s' = n - s`) requires only public information and standard elliptic-curve arithmetic, no signing key.
- Feasibility: fully deterministic and repeatable against any/all currently-unmatured microblock public keys observed on the network; an unprivileged single participant (mempool submitter) can do this with only a signed transaction fee.

### Recommendation
- In the codec and in `check_microblock_header_signer`/`handle_poison_microblock`, require that the *content* fields relevant to equivocation (`prev_block` and `tx_merkle_root`, or more generally "the signed digest") actually differ between `mblock_header_1` and `mblock_header_2`, not merely that the raw structs (including signature bytes) differ.
- Enforce canonical (low-S) signature verification for microblock headers (reject or normalize high-S signatures) so that a single signing event cannot be represented by two distinct valid `MessageSignature` byte encodings.
- Add an explicit check: if the digests signed by `h1` and `h2` (i.e., serialization with `empty_sig=true`) are identical, reject the `PoisonMicroblock` transaction as not evidence of two independent equivocating microblocks.

#[test]
fn poison_microblock_rejects_ecdsa_malleated_duplicate() {
    // 1. Build and sign a legitimate microblock header h1 with `privk`.
    let mut h1 = StacksMicroblockHeader {
        version: 0,
        sequence: 5,
        prev_block: BlockHeaderHash([0x11; 32]),
        tx_merkle_root: Sha512Trunc256Sum::from_data(&[9,9,9]),
        signature: MessageSignature::empty(),
    };
    h1.sign(&privk).unwrap();

    // 2. Malleate the signature: (r, s, v) -> (r, n - s, 1 - v), no private key used.
    let sig2 = malleate_recoverable_ecdsa_signature(&h1.signature);
    let mut h2 = h1.clone();
    h2.signature = sig2;

    // Equality that should hold if the guard were correct:
    // "digest_signed(h1) != digest_signed(h2)"  <-- attacker breaks this: they are EQUAL.
    assert_eq!(h1.sequence, h2.sequence);
    assert_eq!(h1.prev_block, h2.prev_block);
    assert_eq!(h1.tx_merkle_root, h2.tx_merkle_root);
    assert_ne!(h1.signature, h2.signature); // codec's "headers match" check is fooled

    // 3. Confirm both recover to the same pubkey hash (same signer, same signing event).
    assert_eq!(h1.check_recover_pubkey().unwrap(), h2.check_recover_pubkey().unwrap());

    // 4. Submit PoisonMicroblock(h1, h2) as a transaction.
    let tx = build_poison_tx(&reporter_privk, h1.clone(), h2.clone());

    // 5. EXPECTED (fix): process_transaction should reject this as not representing
    //    two independent equivocating microblocks.
    let err = StacksChainState::process_transaction(&mut conn, &tx, false, None).unwrap_err();
    assert!(format!("{:?}", err).contains("not independent")); // new guard message

    // Without the fix, this currently SUCCEEDS and credits `reporter_privk`
    // with a commission of the honest miner's coinbase despite no real
    // double-signing having occurred — demonstrating the reward-theft bug.
}

        let mut bytes = vec![];

            )
        })?;

        Ok(Hash160::from_node_public_key(&pubk))
