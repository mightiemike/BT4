### Title
Unbounded per-call iteration over the global `ActiveBallotIDs` collection on every new ballot creation - ([File: x/uvalidator/keeper/ballot.go])

### Summary
`x/uvalidator/keeper/ballot.go`'s `CreateBallot` unconditionally invokes `ExpireBallotsBeforeHeight`, which walks the *entire* `ActiveBallotIDs` collection and does a `k.Ballots.Get` for every entry, on every single new ballot creation. Ballot IDs for inbound observations are derived directly from attacker-controlled cross-chain transaction content, so an unprivileged user can cheaply cause many distinct ballots to be opened by honest Universal Validators, inflating this global collection. Each subsequent new ballot creation (triggered by ordinary user activity) then re-scans the whole, ever-growing set — the same architectural bug class as the reported `pop_accept` loop: an unbounded scan over a global map that includes entries irrelevant to the current operation, driven by cheap unprivileged input.

### Finding Description
`CreateBallot` ( [1](#0-0) ) always calls `ExpireBallotsBeforeHeight` before creating the new ballot:
```go
if err := k.ExpireBallotsBeforeHeight(ctx, blockHeight); err != nil {
    return types.Ballot{}, err
}
```
`ExpireBallotsBeforeHeight` iterates the full `ActiveBallotIDs` collection and fetches each `Ballot` from `k.Ballots` to check its expiry height [2](#0-1) . This is an unfiltered, whole-map scan analogous to the reported `current_` map loop: it inspects every active ballot, most of which have nothing to do with the ballot currently being created.

`CreateBallot` is reached via `GetOrCreateBallot` → `VoteOnBallot`, which is invoked from `VoteOnInboundBallot` [3](#0-2)  every time a Universal Validator submits `MsgVoteInbound` for a source-chain observation. The ballot key is derived purely from the (attacker-supplied) inbound content via `types.GetInboundBallotKey(inbound)`, so any new/distinct inbound observed on an external chain produces a brand-new ballot ID and forces `isNew == true`, triggering `CreateBallot` → full `ActiveBallotIDs` scan.

Because `MsgVoteInbound` is in the gasless whitelist [4](#0-3)  and `DeductFeeDecorator` explicitly skips fee deduction for gasless messages [5](#0-4) , the CPU cost of processing these votes (and the underlying `ExpireBallotsBeforeHeight` scan) is not billed via gas to the honest UV or to the attacker. An unprivileged user who cheaply generates many distinct external-chain deposits/transactions (source-chain gas is the only cost, which can be minimal) causes honest, non-malicious UVs to submit distinct `MsgVoteInbound` messages that each create a new ballot, each of which re-scans the entire (now larger) `ActiveBallotIDs` set. Ballots remain active until they reach quorum or hit `DefaultExpiryAfterBlocks`, so within that expiry window the active-ballot set can accumulate without the attacker paying anything for the resulting O(N) work per creation — producing O(N²) aggregate work across N distinct low-cost inbound events, purely from ordinary/cheap user-submitted cross-chain activity and honest validator behavior.

### Impact Explanation
This is a denial-of-service risk reachable without any privileged control: an unprivileged attacker triggers the growth of `ActiveBallotIDs` through ordinary (cheap) cross-chain transaction submission, and honest, non-malicious Universal Validators unavoidably drive the expensive re-scan as part of normal, required inbound-voting duty. As the active-ballot set grows, every new inbound (including those from legitimate, non-attacker users) pays increasing latency to get its ballot created, degrading block processing time for the whole network — a non-network-level DoS vector reachable purely from ordinary user deposit/transaction submission, matching the "State safety path" and "denial of service ... reachable without privileged control" impact categories in scope.

### Likelihood Explanation
Medium. The attack requires only submitting many distinct, low-value cross-chain source transactions (or otherwise causing many honest UVs to observe distinct inbound content) within the ballot expiry window (`DefaultExpiryAfterBlocks`), no validator or admin collusion is needed, and the gasless-tx path means the resulting node-side computation is not economically deterred by the fee/gas mechanism the way an equivalent EVM-side loop would be. However, actual severity is bounded by the size of `DefaultExpiryAfterBlocks` (I was not able to confirm its exact numeric value from the available index; it is defined in `x/uexecutor/types/constants.go`) and by the real-world cost of generating enough distinct source-chain observations to make the O(N²) blowup material — this constrains but does not eliminate the risk.

### Recommendation
Avoid a synchronous, blocking full-collection scan on the hot ballot-creation path. Options:
- Move ballot expiry sweeping to a periodic `EndBlocker`/`BeginBlocker` job (bounded batch size per block) instead of running it inline inside every `CreateBallot` call.
- Maintain a secondary index keyed by expiry height (e.g., `Map<ExpiryHeight, []BallotID>`) so expired ballots can be looked up and removed without scanning the whole active set, mirroring the report's recommendation to track only the relevant subset rather than iterating the global collection.
- Cap the number of ballots swept per `CreateBallot` invocation to bound worst-case latency.

### Proof of Concept
1. An external, unprivileged actor submits many distinct low-value transactions/deposits on a connected source chain (cheap on that chain), each with unique content so `types.GetInboundBallotKey` produces a distinct ballot ID.
2. Honest Universal Validators observe these and submit `MsgVoteInbound` for each — a gasless message, so no PushChain-side fee is charged.
3. Each first-vote on a new inbound calls `VoteOnBallot` → `GetOrCreateBallot` → `CreateBallot`, which calls `ExpireBallotsBeforeHeight` and iterates the entire current `ActiveBallotIDs` set (see `x/uvalidator/keeper/ballot.go:320-364`).
4. As the attacker keeps submitting new distinct inbounds faster than they finalize/expire, `ActiveBallotIDs` grows; each subsequent `CreateBallot` call (for the attacker's own future inbounds, and for any other legitimate user's concurrent inbound) does proportionally more work, producing quadratic total node-side computation for N distinct low-cost source-chain events — the same class of unbounded/irrelevant iteration cost as the referenced `pop_accept` bug, but reachable by an ordinary unprivileged user rather than requiring EVM access-list gas purchases.

func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}
```

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
```
