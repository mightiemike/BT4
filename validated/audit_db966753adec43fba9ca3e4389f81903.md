## Analysis Result

### Title
`debug_redact` field option is never enforced by `proto.Message.String()` / debug `Format()`, causing sensitive fields to be logged in cleartext - (File: internal/impl/api_export.go, encoding/prototext/encode.go, encoding/protojson/encode.go)

### Summary
The protobuf schema exposes `google.protobuf.FieldOptions`/`EnumValueOptions.DebugRedact`, whose documented purpose is to prevent fields "annotated with this enum value ... to be printed out when using debug formats, e.g. when the field contains sensitive credentials" [1](#0-0) . In protobuf-go, none of the code paths that implement "debug formats" actually check this flag, so any field marked `debug_redact = true` in the schema is still emitted in cleartext whenever a message is stringified, e.g. via `fmt.Sprintf("%v", msg)`, error wrapping, or `log.Printf`.

### Finding Description
`proto.Message.String()` on every generated message ultimately calls `protoimpl.X.MessageStringOf`, which is implemented as:

```go
func (Export) MessageStringOf(m protoreflect.ProtoMessage) string {
	return prototext.MarshalOptions{Multiline: false}.Format(m)
}
``` [2](#0-1) 

`prototext.MarshalOptions.Format` is explicitly documented as being "for human consumption" (i.e., debug/log output) [3](#0-2) , and it walks every field through `marshalMessage` → `marshalField` → `marshalSingular`:

```go
func (e encoder) marshalSingular(val protoreflect.Value, fd protoreflect.FieldDescriptor) error {
	kind := fd.Kind()
	switch kind {
	case protoreflect.BoolKind:
		e.WriteBool(val.Bool())
	case protoreflect.StringKind:
		s := val.String()
		...
		e.WriteString(s)
``` [4](#0-3) 

At no point in `marshalField`/`marshalSingular` (or the analogous `protojson` encode path, `MarshalOptions.Format`) is `fd.Options()`/`FieldOptions.DebugRedact` consulted before writing the value [5](#0-4) [6](#0-5) . The internal human-readable formatter `internal/msgfmt` has the exact same gap — it iterates all fields via `order.RangeFields` and unconditionally appends every value, with no lookup of `DebugRedact` at all [7](#0-6) .

This is a genuine broken invariant: the schema-level contract ("this field must not appear in debug output because it holds credentials") is defined in the descriptor but is silently dropped by the reachable, default, unprivileged code path — the standard `%v`/`%s`/`String()` formatting that any service naturally uses in logs and error messages, exactly the class of defect described in the Glance report (sensitive value written in cleartext to an operator-visible sink because a designated-sensitive value bypasses the redaction the schema/author intended).

### Impact Explanation
Any application using generated protobuf-go messages that mark a credential/secret field with `[debug_redact = true]` (a real, documented option intended precisely for this use case) will still have that field's raw value written to logs, panics, error strings, or any code that calls `fmt.Sprintf("%v", msg)` / `msg.String()` — all default, unprivileged behavior triggered on any normal request path that logs a request/response message for debugging. This can leak credentials or other sensitive data into logs, consistent with CWE-200/cleartext-storage-in-log-files.

### Likelihood Explanation
High likelihood of reachability: calling `.String()` on a proto message (directly, via `%v`, or via any logging/error-wrapping call) is an extremely common, unprivileged, default operation in Go services. No attacker interaction or special parser configuration is required — it depends solely on whether the trusted schema author annotated a field with `debug_redact`, which is the exact scenario the option exists for.

### Recommendation
Have `prototext.MarshalOptions.Format`, `protojson.MarshalOptions.Format`, and `internal/msgfmt.Format` (and therefore `proto.Message.String()`) check `fd.Options().(*descriptorpb.FieldOptions).GetDebugRedact()` (or the enum-value-level `DebugRedact`) for each field/enum value before emitting it, and substitute a redaction placeholder (e.g. the C++/Java implementations emit something like `"<REDACTED>"`) instead of the raw value.

### Proof of Concept
```go
// schema (trusted, provided by service author):
// message Login {
//   string username = 1;
//   string password = 2 [debug_redact = true];
// }

msg := &pb.Login{Username: "alice", Password: "S3cr3t!"}

// Any ordinary logging/error path:
log.Printf("failed login attempt: %v", msg)
// or
fmt.Println(msg.String())

// Output (cleartext, despite debug_redact = true):
// failed login attempt: username:"alice"  password:"S3cr3t!"
```
Because `marshalSingular`/`appendMessage` never inspect `debug_redact`, the password is printed unredacted, mirroring the Glance defect of logging credentials in cleartext through a normal, unprivileged debug/error path.

func appendMessage(b []byte, m protoreflect.Message) []byte {
	if b2 := appendKnownMessage(b, m); b2 != nil {
		return b2
	}

	b = append(b, '{')
	order.RangeFields(m, order.IndexNameFieldOrder, func(fd protoreflect.FieldDescriptor, v protoreflect.Value) bool {
		b = append(b, fd.TextName()...)
		b = append(b, ':')
		b = appendValue(b, v, fd)
		b = append(b, delim()...)
		return true
	})
	b = appendUnknown(b, m.GetUnknown())
	b = bytes.TrimRight(b, delim())
	b = append(b, '}')
	return b
}
