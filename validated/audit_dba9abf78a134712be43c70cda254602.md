The reported CVE describes a classic C memory-safety defect: a size-calculation error in `opj_t2_encode_packet` causes a heap-based out-of-bounds *write* during buffer-bound pointer arithmetic. This bug class does not translate to protobuf-go's encoding paths.

protobuf-go's marshal paths (`proto/encode.go`, `internal/impl/encode.go`, `internal/impl/codec_gen.go`) build output exclusively via Go's `append()`-based `protowire.Append*` helpers and slice growth (`growcap`), which are memory-safe by construction — there is no manual buffer-length/pointer arithmetic that could produce an out-of-bounds write like in C. [1](#0-0) [2](#0-1) 

The one place where protobuf-go tracks an analogous "predicted size vs. actual encoded size" invariant (speculative length / size-cache for nested messages) is explicitly guarded: a mismatch between the cached size and actual marshaled bytes produces a `SizeMismatchError` that is returned to the caller, not a raw memory write past a buffer boundary. [3](#0-2)  This is demonstrated directly in the lazy-field size-mismatch test, where the deliberately corrupted cached size causes `Marshal` to fail safely with a `"size mismatch"` error rather than any unsafe write. [4](#0-3) 

Since Go's slice/append semantics eliminate the manual bounds-tracking bug class that caused CVE-2017-14039, and the one comparable size-tracking mechanism in protobuf-go fails closed with an error rather than an out-of-bounds write, there is no reachable analog on an unprivileged encode path.

```go
// growcap scales up the capacity of a slice.
//
// Given a slice with a current capacity of oldcap and a desired
// capacity of wantcap, growcap returns a new capacity >= wantcap.
//
// The algorithm is mostly identical to the one used by append as of Go 1.14.
func growcap(oldcap, wantcap int) (newcap int) {
	if wantcap > oldcap*2 {
		newcap = wantcap
	} else if oldcap < 1024 {
		// The Go 1.14 runtime takes this case when len(s) < 1024,
		// not when cap(s) < 1024. The difference doesn't seem
		// significant here.
		newcap = oldcap * 2
	} else {
		newcap = oldcap
		for 0 < newcap && newcap < wantcap {
			newcap += newcap / 4
		}
		if newcap <= 0 {
			newcap = wantcap
		}
	}
	return newcap
}
```
