### Title
Fulfillment-service HMAC does not bind the `X-Shopify-Shop-Domain` header, enabling cross-tenant session hijack via body/HMAC replay - ([File: packages/apps/shopify-app-remix/src/server/authenticate/fulfillment-service/authenticate.ts])

### Summary
`authenticateFulfillmentServiceFactory`'s `authenticate` function validates only that `rawBody` matches an HMAC computed from the app's shared secret, then blindly trusts the unauthenticated `X-Shopify-Shop-Domain` header to select which shop's offline session to load. Because `validateHmacFromRequestFactory` signs only `rawBody` (never the shop header), any holder of one valid `(rawBody, hmac)` pair for the app can replay it with an arbitrary shop-domain header and have the library resolve/act on a different tenant's offline session.

### Finding Description
`authenticate()` reads the raw body, calls `api.fulfillmentService.validate({rawBody, rawRequest: request})`, and only after that succeeds extracts `shop` from `request.headers.get(ShopifyHeader.Domain)` to call `ensureValidOfflineSession(params, shop)` [1](#0-0) .

The validation itself, `validateHmacFromRequestFactory`, computes the HMAC purely over `rawBody` using the app's `apiSecretKey` via `validateHmacString`, and never reads or incorporates the shop-domain header into the signed data [2](#0-1) . The underlying `validateFactory` simply forwards `rawBody` and the raw request/adapter args to that generic HMAC check, with no shop binding [3](#0-2) .

Since `apiSecretKey` is a single app-level secret shared by every merchant who installs the app, a merchant/customer of the app (an unprivileged actor with no special role) can obtain one genuine `(rawBody, hmac)` pair from their own shop's fulfillment order notification, then POST the exact same body/HMAC to the app's endpoint while swapping `X-Shopify-Shop-Domain` to a victim shop that also has the app installed. `validateHmacFromRequestFactory` still returns `valid: true` because it never checks the domain header, and `ensureValidOfflineSession(params, shop)` then loads/returns the victim's offline session, which is subsequently used to build an authenticated `admin` API client for the victim shop [4](#0-3) .

The existing repo test suite only exercises: missing/invalid HMAC, no session for shop, and a fully consistent valid body/hmac/shop triple — it never asserts that the shop header is bound to the HMAC, confirming there is no such check [5](#0-4) .

### Impact Explanation
This results in cross-tenant session confusion: the fulfillment-service handler returns a `session`/`admin` API client scoped to a shop that the HMAC never certified, based purely on an attacker-controlled header. Any app code trusting the returned `session`/`admin` client (e.g., to look up or act on fulfillment orders) would operate against the wrong (victim) tenant's offline access token, enabling cross-tenant data/state access — matching Shopify's "cross-tenant session access" bounty impact class.

### Likelihood Explanation
The precondition is realistic and does not require any privileged role or secret theft: the attacker only needs to be a normal merchant/customer of an app that (a) is installed on more than one shop and (b) exposes a fulfillment-service endpoint using this library's `authenticate.fulfillmentService`. Capturing a genuine `(rawBody, hmac)` pair is trivial for any merchant who has installed the app themselves (they receive real fulfillment order notifications). Crafting a replay request with a different `X-Shopify-Shop-Domain` header is a simple, repeatable HTTP request — no MITM, no host-app bug, default configuration.

### Recommendation
Bind the shop identity into the authenticated data before trusting it: either (1) include the shop domain as part of the HMAC-signed payload/verification (e.g., require the `shop`/domain to be present inside `rawBody`'s signed JSON and compare it against the header), or (2) derive `shop` only from data that was part of the HMAC computation, never from a raw untrusted header, mirroring how per-shop validation should tie authentication and tenant resolution together.

// packages/apps/shopify-app-remix/src/server/authenticate/fulfillment-service/__tests__/authenticate.test.ts
it('rejects HMAC-valid body replayed with a different shop domain', async () => {
  const sessionStorage = new MemorySessionStorage();
  const shopify = shopifyApp(testConfig({sessionStorage}));

  const body = {kind: 'FULFILLMENT_REQUEST'};
  const rawBody = JSON.stringify(body);
  const hmac = getHmac(rawBody); // same secret used across all shops

  // victim shop has a valid offline session set up
  const victimSession = await setUpValidSession(sessionStorage, {isOnline: false});

  // Attacker captured (rawBody, hmac) from their OWN shop's notification,
  // then replays it with the victim's shop domain.
  const forgedRequest = new Request(FULFILLMENT_URL, {
    method: 'POST',
    body: rawBody,
    headers: {
      'X-Shopify-Hmac-Sha256': hmac,
      'X-Shopify-Shop-Domain': victimSession.shop, // attacker-controlled header
    },
  });

  const {session} = await shopify.authenticate.fulfillmentService(forgedRequest);

  // Expected (secure) behavior: this should be rejected because the HMAC
  // never certified victimSession.shop.
  // Actual (vulnerable) behavior: session.shop === victimSession.shop
  expect(session.shop).not.toBe(victimSession.shop); // FAILS on current code
});

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
