### Title
Unsigned integer overflow in `AllPendingOutbounds` pagination causes out-of-range slice panic - (File: `x/uexecutor/keeper/query_server.go`)

### Summary
The `AllPendingOutbounds` query handler computes pagination bounds using raw `uint64` arithmetic without overflow checks, allowing an attacker-supplied `Offset`/`Limit` pair to wrap `end` below `start` and trigger a slice-bounds panic.

### Finding Description
`AllPendingOutbounds` builds an in-memory slice of all `PendingOutboundEntry` values and manually paginates it instead of using `query.CollectionPaginate` (which is used safely elsewhere in the same file, e.g. `AllUniversalTx`, `AllPendingInbounds`, `AllGasPrices`): [1](#0-0) 

```go
total := uint64(len(allEntries))
limit := req.Pagination.GetLimit()
if limit == 0 {
    limit = query.DefaultLimit
}
offset := req.Pagination.GetOffset()

start := offset
if start > total {
    start = total
}
end := start + limit
if end > total {
    end = total
}
pageEntries := allEntries[start:end]
```

`start` is clamped to `total` (a small number, since the pending-outbound set is expected to be small), but `end := start + limit` is unclamped `uint64` addition performed *before* the `end > total` check. If an attacker sets `Limit` close to `math.MaxUint64` (e.g. `Limit = math.MaxUint64` and `Offset = 1`, with at least one entry in `PendingOutbounds` so `total >= 1` and `start = 1`), then `end = 1 + math.MaxUint64` wraps around to `0` in `uint64` arithmetic. Since `end` (0) is not `> total`, the clamp `if end > total { end = total }` does not fire, and the code proceeds to `allEntries[1:0]`, which is an invalid slice range (`low > high`) in Go and panics with `slice bounds out of range`.

This is a straightforward arithmetic overflow bug reachable by any unprivileged client issuing a gRPC/ABCI query — `QueryAllPendingOutboundsRequest.Pagination.{Offset,Limit}` are fully attacker-controlled fields, and the only state precondition is that `PendingOutbounds` contains at least one entry (a normal, frequently-true condition during live outbound processing).

### Impact Explanation
A panic inside a query handler is generally recovered per-request by the gRPC/ABCI query serving layer in cosmos-sdk and does not crash the full node process or affect consensus/block production — it returns an internal error to that caller for that specific request. This matches a scoped, non-network-level DoS: the specific `AllPendingOutbounds` query becomes unusable with certain pagination parameters (and would return an internal error until a fixed binary is deployed), degrading observability/tooling that depends on this query (e.g. relayers/dashboards enumerating pending outbounds) without affecting chain liveness or fund safety.

### Likelihood Explanation
High likelihood of triggering the panic: the arithmetic condition is trivial to hit (any `Offset >= 1` combined with `Limit` near `math.MaxUint64`, given `PendingOutbounds` is non-empty), requires no privileged access, and is exposed through the standard gRPC/ABCI query interface used by any client.

### Recommendation
Clamp `limit` before adding it to `start`, or use saturating addition, e.g.:
```go
end := start
if limit > total-start {
    end = total
} else {
    end = start + limit
}
```
or reuse `query.CollectionPaginate` semantics consistently as done in the other query handlers in this file, which already avoid manual unbounded arithmetic on user-supplied pagination fields.

// AllPendingOutbounds implements types.QueryServer.
// Returns all pending outbound entries with full outbound data, sorted by block height.
// Uses pagination.reverse for descending order (default: ascending by created_at).
func (k Querier) AllPendingOutbounds(goCtx context.Context, req *types.QueryAllPendingOutboundsRequest) (*types.QueryAllPendingOutboundsResponse, error) {
	if req == nil {
		return nil, status.Error(codes.InvalidArgument, "invalid request")
	}

	ctx := sdk.UnwrapSDKContext(goCtx)

	// Collect all entries (pending set is small)
	var allEntries []types.PendingOutboundEntry
	err := k.PendingOutbounds.Walk(ctx, nil, func(_ string, value types.PendingOutboundEntry) (bool, error) {
		allEntries = append(allEntries, value)
		return false, nil
	})
	if err != nil {
		return nil, status.Error(codes.Internal, err.Error())
	}

	// Sort by CreatedAt (block height)
	reverse := req.Pagination.GetReverse()
	sort.Slice(allEntries, func(i, j int) bool {
		if reverse {
			return allEntries[i].CreatedAt > allEntries[j].CreatedAt
		}
		return allEntries[i].CreatedAt < allEntries[j].CreatedAt
	})

	// Apply pagination
	total := uint64(len(allEntries))
	limit := req.Pagination.GetLimit()
	if limit == 0 {
		limit = query.DefaultLimit
	}
	offset := req.Pagination.GetOffset()

	start := offset
	if start > total {
		start = total
	}
	end := start + limit
	if end > total {
		end = total
	}
	pageEntries := allEntries[start:end]
