### Title
Failed outbound attachment after successful payload execution silently drops fund-release outbound while recording no compensating state - (File: x/uexecutor/keeper/execute_inbound_funds_and_payload.go)

### Summary
When `ExecutePayloadV2` succeeds and its receipt emits a `UniversalTxOutboundEvent`, `AttachOutboundsToExistingUniversalTx` is called to convert that event into an `OutboundTx`. If `BuildOutboundsFromReceipt`'s call to `GetTokenConfigByPRC20` fails (e.g., because the log names a PRC20/chain pair with no registered token config), the whole attach operation aborts and returns an error. The caller only records this as a `RevertError` string field on the `UniversalTx` — it does not roll back the already-executed/committed payload, and it does not create any outbound (not even a revert/rescue outbound).

### Finding Description
In `ExecuteInboundFundsAndPayload` [1](#0-0) , once `ExecutePayloadV2` returns successfully (`payloadErr == nil`), the code calls `k.AttachOutboundsToExistingUniversalTx(sdkCtx, receipt, utx)`. If this fails, the only handling is:
```go
if storeErr := k.UpdateUniversalTx(sdkCtx, universalTxKey, func(u *types.UniversalTx) error {
    u.RevertError = attachErr.Error()
    return nil
}); storeErr != nil {
    return storeErr
}
```
No outbound is created, and the already-executed EVM payload (and any deposit that preceded it) is left committed. This differs from the `isSmartContract` branch which correctly guards fee-deduction with a `CacheContext`/`writeCache` pair [2](#0-1)  — but that guard has no bearing on the `AttachOutboundsToExistingUniversalTx` step, which happens strictly after the EVM execution has already been finalized via `ExecutePayloadV2` (called directly against `ctx`, not a cache context) at line 290.

`AttachOutboundsToExistingUniversalTx` delegates to `BuildOutboundsFromReceipt`, which for every `UniversalTxOutboundEvent` log calls `GetTokenConfigByPRC20(ctx, event.ChainId, event.Token)` and returns immediately on error, discarding any outbounds already built in the same loop iteration: [3](#0-2) . This lookup can fail if the event's `Token` (PRC20 address) is not present in the `PRC20Index` for the given `ChainId`, as implemented in `GetTokenConfigByPRC20` [4](#0-3) .

The payload executed via `ExecutePayloadV2` runs inside the UEA (a user-controlled smart-contract-account) and its logic — including which contract/event it emits from the `UniversalGatewayPC` address and what token address it references — is influenced by the payload the attacker/user submits as part of their own inbound transaction (`utx.InboundTx.UniversalPayload`) [5](#0-4) . If that payload triggers a call into the gateway that emits a `UniversalTxOutboundEvent` referencing a PRC20 token address that has no corresponding `uregistry` `TokenConfig`, `BuildOutboundsFromReceipt` fails and the entire outbound-creation step is skipped — while the payload execution that already moved/burned/locked funds inside the UEA has already committed to state.

### Impact Explanation
This results in funds that were already debited/moved by the payload execution having no corresponding outbound record: the `UniversalTx.OutboundTx` list remains empty, only a `RevertError` string is set (which is not a state used for retry, refund, or rescue eligibility checks in `AttachRescueOutboundFromReceipt`, which requires a `PENDING`/`FAILED` PcTx status or an existing `INBOUND_REVERT` outbound in `REVERTED` status [6](#0-5) ). Since the deposit `PcTx` is recorded `SUCCESS` and there is no `INBOUND_REVERT` outbound, the rescue path is also unreachable, permanently freezing the corresponding cross-chain fund release with no recovery mechanism reachable by an unprivileged user.

### Likelihood Explanation
This is triggerable by any ordinary user submitting an inbound with a crafted `UniversalPayload` that causes the UEA to call into the gateway contract in a way that emits an outbound event referencing a token/chain pair absent from the `uregistry` token registry (e.g., not-yet-registered token, or intentionally malformed/spoofed token address embedded in calldata that the payload forwards to the gateway). No privileged actor, validator, or TSS participant involvement is required — only ordinary payload execution via the honest node's own EVM.

### Recommendation
Treat `AttachOutboundsToExistingUniversalTx` failure as fatal to the whole inbound execution rather than a soft, silently-swallowed error: either (a) execute `ExecutePayloadV2` + outbound attachment inside a single `CacheContext`, only calling `writeCache()` after outbound extraction succeeds (mirroring the pattern already used in the `isSmartContract` branch), so a `GetTokenConfigByPRC20` failure reverts the entire payload execution; or (b) if committing payload execution independent of outbound extraction is intentional, guarantee that a fallback outbound (e.g., an `INBOUND_REVERT`/rescue-eligible outbound) is always created when attachment fails, so funds are never left in a state with no corresponding outbound and no rescue path.

### Proof of Concept
1. Submit an inbound transaction with `IsCEA=false`, causing UEA deployment/deposit as in the non-CEA path, and a `UniversalPayload` whose EVM calldata, when executed by the UEA, calls the `UniversalGatewayPC` contract in a way that emits a `UniversalTxOutboundEvent` (correct topic/signature) but with `event.Token` set to a PRC20 address never registered in `uregistry.TokenConfigs` for `event.ChainId`.
2. `ExecutePayloadV2` succeeds (`payloadErr == nil`), and `receipt` is committed to state normally (no cache-context guard at this call site) [7](#0-6) .
3. `AttachOutboundsToExistingUniversalTx` → `BuildOutboundsFromReceipt` calls `GetTokenConfigByPRC20` for the spoofed PRC20/chain pair, which returns `collections.ErrNotFound`, aborting outbound creation [8](#0-7) .
4. The `UniversalTx` ends up with `PcTx` marked `SUCCESS`, `RevertError` set to the lookup error, and `OutboundTx` empty — no outbound was ever created and no rescue eligibility criteria are met, so the moved/burned/locked funds are permanently unaccounted for and unrecoverable via any user-reachable flow.

```go
func (k Keeper) GetTokenConfigByPRC20(
	ctx context.Context,
	chain string,
	prc20Addr string,
) (types.TokenConfig, error) {

	if strings.TrimSpace(prc20Addr) == "" {
		return types.TokenConfig{}, fmt.Errorf("prc20 address is empty")
	}
	// Same canonical form as the index function, so any case variant hits the row.
	prc20Addr = canonicalPRC20(prc20Addr)

	// PRC20 addresses are globally unique by construction; MatchExact returns at most one.
	iter, err := k.TokenConfigs.Indexes.PRC20Index.MatchExact(ctx, prc20Addr)
	if err != nil {
		return types.TokenConfig{}, err
	}
	defer iter.Close()

	for ; iter.Valid(); iter.Next() {
		pk, err := iter.PrimaryKey()
		if err != nil {
			return types.TokenConfig{}, err
		}
		cfg, err := k.TokenConfigs.Get(ctx, pk)
		if err != nil {
			return types.TokenConfig{}, err
		}
		if cfg.Chain == chain {
			return cfg, nil
		}
	}

	return types.TokenConfig{}, collections.ErrNotFound
}
```
