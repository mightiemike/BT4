Confirmed: `RevertRecipient` in the outbound event is ABI-typed `address` (fixed 20-byte, always structurally valid), so the outbound-failure re-mint path (`handleFailedOutbound` → `CallPRC20Deposit`) is not attacker-exploitable in the way the report describes. The exploitable gap is on the **inbound** side, where `Inbound.Sender` and `RevertInstructions.FundRecipient` are free-form strings that are validated only for non-emptiness, never for well-formed hex, before being used (via `common.HexToAddress`, which silently degrades malformed input to the zero address) as the mint/refund destination.

### Title
Malformed `Inbound.Sender` / `RevertInstructions.FundRecipient` silently resolve to the zero address on revert, permanently burning bridged funds - (File: `x/uexecutor/types/inbound.go`, `x/uexecutor/keeper/build_revert_outbound.go`)

### Summary
`Inbound.ValidateBasic` only checks that `Sender` is non-empty, and `Inbound.ValidateForExecution` never validates `Sender` or `RevertInstructions.FundRecipient` as well-formed EVM addresses (only `Recipient` is checked with `utils.IsValidAddress`). `Canonicalize()` uses the *lenient* canonicalizer, which passes through the raw trimmed string unchanged when it fails to parse as a valid address, rather than rejecting it. This unvalidated string becomes the revert-outbound `Recipient`, and ultimately the destination used by `common.HexToAddress()` in the fund-release/refund path.

### Finding Description
`Inbound.ValidateBasic` ( [1](#0-0) ) only enforces that `p.Sender` is non-empty; it never checks that it is a syntactically valid address. `Inbound.ValidateForExecution` ( [2](#0-1) ) validates `p.Recipient` with `utils.IsValidAddress` for FUNDS/GAS/isCEA payload types, but at no point validates `p.Sender` or `p.RevertInstructions.FundRecipient`.

`Canonicalize()` deliberately uses the lenient variant so a malformed value is kept as trimmed input instead of being rejected: [3](#0-2)  and [4](#0-3) .

When a stuck/failed inbound is reverted, `buildRevertOutbound` uses `inbound.Sender` (or `RevertInstructions.FundRecipient` if set) directly as the outbound `Recipient` with no address-format check: [5](#0-4) . This same fallback pattern also appears in `handleFailedOutbound` for the on-chain PRC20 re-mint path: [6](#0-5) , where the recipient string is fed straight into `common.HexToAddress(recipient)`. Go-ethereum's `common.HexToAddress` silently returns the zero address for any string that fails hex-decoding (non-hex characters, wrong length, etc.) instead of erroring, so a malformed `Sender`/`FundRecipient` converts into `0x000...000` with no revert or guard, matching the exact bug class from the external report (`_swapUniswap` sending to `address(0)` unchecked).

### Impact Explanation
Any code path that mints/re-mints PRC20 balances or otherwise moves protocol-controlled value using `common.HexToAddress(inbound.Sender)` or `common.HexToAddress(revertInstructions.FundRecipient)` without first checking `IsHexAddress`/non-zero, silently burns that value to the zero address, an unrecoverable, unauthorized loss of funds matching the in-scope "permanent loss" / "unauthorized burn" impact categories.

### Likelihood Explanation
I was **not able to fully confirm** an end-to-end reachable path where this loss lands on Push-Chain-minted PRC20 balances rather than merely misdirecting an off-chain, TSS-executed refund transaction on the external source chain (which would likely just fail there rather than burn value on Push Chain). The clearest confirmed gap is the missing format validation on `Sender`/`FundRecipient` in `ValidateForExecution`/`ValidateBasic`; whether an attacker can actually get a malformed (non-hex) value into these fields depends on whether upstream validator observation of the external gateway event enforces `address`-typed encoding (which I could not verify for the inbound event decoder, unlike the outbound decoder in `gateway_pc_event_decode.go`, which I confirmed uses strict ABI `address` types). Given this uncertainty about attacker control over the raw value before it reaches `Canonicalize`/`ValidateForExecution`, likelihood should be treated as unconfirmed pending further tracing of the inbound event decode path (not covered in the reviewed files).

### Recommendation
Add explicit `utils.IsValidAddress(p.Sender, utils.HEX)` (and same for `RevertInstructions.FundRecipient` when set) checks in `Inbound.ValidateForExecution`, matching the existing check already applied to `Recipient`. Additionally, add a defensive `require`-equivalent check in `buildRevertOutbound`, `handleFailedOutbound`, and any other call site that converts a stored string into `common.HexToAddress` for a fund-moving call, rejecting (or aborting to `AbortOutbound`) when the resulting address is the zero address, mirroring the recommended fix from the cited Pickle Finance report.

### Proof of Concept
Not able to produce a concrete, fully-verified PoC within the scope of this investigation, since it depends on whether the inbound event decoder (not found in the reviewed files) allows a non-address-typed or attacker-malleable `Sender`/`FundRecipient` value to survive into `MsgVoteInbound`. Recommend a Devin session with full repository access to trace the inbound gateway-event decode path (analogous to `DecodeUniversalTxOutboundFromLog`) and confirm whether `Sender`/`RevertInstructions.FundRecipient` can be attacker-supplied as non-hex strings before reaching `common.HexToAddress` in `handleFailedOutbound`/`buildRevertOutbound`.

	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)

		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}

	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")

	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
