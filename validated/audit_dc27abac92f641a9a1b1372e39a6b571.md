### Title
Unbounded, unmetered reward-set iteration lets any staker halt reward-cycle processing - ([File: stackslib/src/chainstate/stacks/boot/mod.rs])

### Summary
At every PoX reward-cycle boundary, the chains coordinator fetches the full stacker/reward-set list from the active PoX contract by iterating `0..num_addrs`, invoking Clarity read-only calls once per index (`get-reward-set-pox-address`), all executed with a "free" (unmetered) cost tracker. `num_addrs` is `get-reward-set-size`, which grows by one on every successful `stack-stx`/`delegate-stack-stx`/`stack-aggregation-commit` call, and the PoX contracts require only `amount-ustx > 0` (no minimum) for `stack-stx`, so an attacker can post an unbounded number of nearly-free, low-amount stacking transactions and force this loop to be arbitrarily large.

### Finding Description
`StacksChainState::get_reward_addresses_pox_4` (and the pox_1/pox_2/pox_3 equivalents) at `stackslib/src/chainstate/stacks/boot/mod.rs` reads `get-reward-set-size` for the cycle, then loops `for i in 0..num_addrs` issuing one `eval_boot_code_read_only` call per entry [4](#0-3) . This is called from `OnChainRewardSetProvider::get_reward_set_epoch2` during the coordinator's automatic reward-cycle-boundary processing (`get_reward_cycle_info`), which every node must execute identically and unconditionally as part of ordinary block/burnchain processing [5](#0-4) .

Each of the `num_addrs` Clarity evaluations runs via `eval_boot_code_read_only`, which is executed with `LimitedCostTracker::new_free()` — i.e., zero execution-cost accounting [2](#0-1) . Because this "free" execution happens outside of any transaction's gas/cost budget, there is no mechanism limiting how large `num_addrs` can be before the loop becomes prohibitively expensive.

`num_addrs` itself is attacker-controlled: `pox-4.clar`'s `stack-stx` only requires `amount-ustx > 0` (checked in `minimal-can-stack-stx`) [6](#0-5) , and each successful call to `stack-stx`, `delegate-stack-stx`, or `stack-aggregation-commit` appends a distinct entry via `append-reward-cycle-pox-addr`, incrementing `reward-cycle-pox-address-list-len` [7](#0-6) . An attacker with many distinct principals (each principal may only stack once per cycle under its own principal, but can use many funded accounts) can insert enormous numbers of 1-uSTX stacking entries into a single reward cycle across the block-production window leading up to the reward cycle boundary, each paid for at normal (cheap) per-transaction fee/cost, while the resulting reconstruction loop that every full node must run at the reward-cycle boundary is unmetered and grows linearly (or worse, since `make_reward_set`/`make_signer_set` afterward also process the whole list) with the attacker-controlled entry count.

This breaks the equality that "every honest, up-to-date node reaches the same, timely chain tip": nodes whose reward-cycle-boundary processing takes excessively long (unmetered, unbounded) will stall in lockstep with all others, but the wall-clock cost of processing a block can be made arbitrarily large by an attacker spending only ordinary per-transaction fees, without needing majority stake or control of block production — directly analogous to the reported Cosmos SDK `GetAllBalances` unmetered-iteration DoS, but applied to the PoX reward-set/signer-set reconstruction path that every Stacks node must execute at reward-cycle boundaries.

### Impact Explanation
This is a minority-triggerable (single attacker, no stake-majority required) denial-of-service against the reward-cycle boundary processing that every full node performs identically. Because the iteration is unmetered, a sufficiently large but individually cheap stream of `stack-stx` transactions can make a reward-cycle transition arbitrarily slow across the whole network, stalling all conforming nodes at the same point — a temporary, network-wide chain-processing halt bounded only by the attacker's tolerance for posting many minimal-cost stacking transactions ahead of the reward-cycle boundary. This matches the "High" category: a minority-triggerable divergence/DoS on consensus-critical reward-cycle bookkeeping, causing temporary network-wide stall rather than a permanent fork or fund loss.

### Likelihood Explanation
Likelihood is High-to-Critical in practice terms: the only requirement is funding many accounts with the smallest possible stacking amount (`amount-ustx > 0`) and issuing one `stack-stx` transaction per account before a reward-cycle boundary. No special privileges, admin keys, or majority stake are needed; the attack is purely a function of how many distinct principals/transactions the attacker is willing to pay standard fees for.

### Recommendation
Bound the number of entries considered when reconstructing the reward/signer set per cycle (e.g., cap `get-reward-set-size`/enforce a maximum number of stacking entries per reward cycle in the PoX contracts), or charge/account for the cost of `get_reward_addresses_pox_*`/`get_pox_4_reward_slots` iteration against a real (non-free) cost tracker so that the aggregate work is bounded and attributable, similar to requiring a bounded list or scaling cost as recommended in the referenced report.

### Proof of Concept
1. Before a reward cycle's prepare phase, fund `N` distinct principals with the minimal amount of STX needed to pay transaction fees plus 1 uSTX each.
2. From each principal, submit a `stack-stx` transaction with `amount-ustx = 1` (or the smallest amount satisfying `amount-ustx > 0`), a valid `pox-addr`, and `lock-period = 1`; each call succeeds and appends one more entry via `append-reward-cycle-pox-addr`, growing `get-reward-set-size` for the cycle by 1 [8](#0-7) .
3. Repeat for a large `N` (bounded only by the attacker's budget for per-tx fees) across the blocks leading up to the reward cycle's prepare phase.
4. When the reward cycle boundary is reached, every node's coordinator calls `get_reward_addresses_pox_4`, which performs `N` unmetered Clarity read-only calls in a tight loop [9](#0-8) , followed by `make_reward_set`/`make_signer_set` also iterating over all `N` entries [10](#0-9) , causing every node to stall for a duration that scales with `N`.

    pub fn make_reward_set(
        threshold: u128,
        mut addresses: Vec<RawRewardSetEntry>,
        epoch_id: StacksEpochId,
    ) -> RewardSet {
        let mut reward_set = vec![];
        let mut missed_slots = vec![];
        // the way that we sum addresses relies on sorting.
        if epoch_id < StacksEpochId::Epoch21 {
            addresses.sort_by_cached_key(|k| k.reward_address.bytes());
        } else {
            addresses.sort_by_cached_key(|k| k.reward_address.to_burnchain_repr());
        }

        let signer_set = Self::make_signer_set(threshold, &addresses);

        while let Some(RawRewardSetEntry {
            reward_address: address,
            amount_stacked: mut stacked_amt,
            stacker,
            ..
        }) = addresses.pop()
        {
            let mut contributed_stackers = vec![];
            if let Some(stacker) = stacker.as_ref() {
                contributed_stackers.push((stacker.clone(), stacked_amt));
            }
            // Here we check if we should combine any entries with the same
            //  reward address together in the reward set.
            // The outer while loop pops the last element of the
            //  addresses vector, and here we peak at the last item in
            //  the vector (via last()). Because the items in the
            //  vector are sorted by address, we know that any entry
            //  with the same `reward_address` as `address` will be at the end of
            //  the list (and therefore found by this loop)
            while addresses.last().map(|x| &x.reward_address) == Some(&address) {
                let next_contrib = addresses
                    .pop()
                    .expect("BUG: first() returned some, but pop() is none.");
                let additional_amt = next_contrib.amount_stacked;

                if let Some(stacker) = next_contrib.stacker {
                    contributed_stackers.push((stacker.clone(), additional_amt));
                }

                stacked_amt = stacked_amt
                    .checked_add(additional_amt)
                    .expect("CORRUPTION: Stacker stacked > u128 max amount");
            }
            let slots_taken = u32::try_from(stacked_amt / threshold)
                .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
            info!(
                "Reward slots taken";
                "reward_address" => %address,
                "slots_taken" => slots_taken,
                "stacked_amt" => stacked_amt,
                "pox_threshold" => threshold,
            );
            for _i in 0..slots_taken {
                test_debug!("Add to PoX reward set: {:?}", &address);
                reward_set.push(address.clone());
            }
            // if stacker did not qualify for a slot *and* they have a stacker
            //   pointer set by the PoX contract, then add them to auto-unlock list
            if slots_taken == 0 && !contributed_stackers.is_empty() {
                info!(
                    "{}",
                    if epoch_id.supports_pox_missed_slot_unlocks() {
                        "Stacker missed reward slot, added to unlock list"
                    } else {
                        "Stacker missed reward slot"
                    };
                    "reward_address" => %address.clone().to_b58(),
                    "threshold" => threshold,
                    "stacked_amount" => stacked_amt
                );
                if !epoch_id.supports_pox_missed_slot_unlocks() {
                    continue;
                }
                contributed_stackers
                    .sort_by_cached_key(|(stacker, ..)| to_hex(&stacker.serialize_to_vec()));
                while let Some((contributor, amt)) = contributed_stackers.pop() {
                    let mut total_amount = amt;
                    while contributed_stackers.last().map(|(stacker, ..)| stacker)
                        == Some(&contributor)
                    {
                        let (add_stacker, additional) = contributed_stackers
                            .pop()
                            .expect("BUG: last() returned some, but pop() is none.");
                        assert_eq!(&add_stacker, &contributor);
                        total_amount = total_amount
                            .checked_add(additional)
                            .expect("CORRUPTION: Stacked stacked > u128 max amount");
                    }
                    missed_slots.push((contributor, total_amount));
                }
            }
        }
        if !epoch_id.supports_pox_missed_slot_unlocks() {
            missed_slots.clear();
        }
        info!("Reward set calculated"; "slots_occuppied" => reward_set.len());
        RewardSet::V0(RewardSetV0 {
            rewarded_addresses: reward_set,
            start_cycle_state: PoxStartCycleInfo {
                missed_reward_slots: missed_slots,
            },
            signers: signer_set,
            pox_ustx_threshold: Some(threshold),
        })
    }

    /// Get all PoX reward addresses from .pox-4
    /// TODO: also return their stacker signer keys (as part of `RawRewardSetEntry`
    fn get_reward_addresses_pox_4(
        &mut self,
        sortdb: &SortitionDB,
        block_id: &StacksBlockId,
        reward_cycle: u64,
    ) -> Result<Vec<RawRewardSetEntry>, Error> {
        // how many in this cycle?
        let num_addrs = self
            .eval_boot_code_read_only(
                sortdb,
                block_id,
                POX_4_NAME,
                &format!("(get-reward-set-size u{reward_cycle})"),
            )?
            .expect_u128()
            .map_err(|_| Error::Expects("get-reward-set-size did not return u128".to_string()))?;

        debug!(
            "At block {block_id:?} (reward cycle {reward_cycle}): {num_addrs} PoX reward addresses"
        );

        let mut ret = vec![];
        for i in 0..num_addrs {
            // value should be:
            // (optional {
            //     pox-addr: { version: (buff 1), hashbytes: (buff 32) },
            //     total-ustx: uint,
            //     stacker: (optional principal),
            //     signer: principal
            // })
            let tuple = self
                .eval_boot_code_read_only(
                    sortdb,
                    block_id,
                    POX_4_NAME,
                    &format!("(get-reward-set-pox-address u{reward_cycle} u{i})"),
                )?
                .expect_optional().map_err(|_| Error::Expects("get-reward-set-pox-address did not return an optional".to_string()))?
                .ok_or_else(|| {
                    Error::Expects(
                        format!("missing PoX address in slot {i} out of {num_addrs} in reward cycle {reward_cycle}")
                    )
                })?
                .expect_tuple().map_err(|_| Error::Expects("get-reward-set-pox-address did not return a tuple".to_string()))?;

            let entry = RawRewardSetEntry::from_pox_4_tuple(self.mainnet, tuple)?;
            ret.push(entry)
        }

        Ok(ret)
    }
