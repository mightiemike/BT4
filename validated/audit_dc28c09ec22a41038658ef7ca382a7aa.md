## Analysis Result

The Vault Inflation Attack's core mechanic — an attacker uses ordinary, permissionless transactions to skew a pricing reference used inside a protected transfer, then extracts value because the "protection" bound is derived from the same manipulated reference — maps onto Push Chain's **GAS / GAS_AND_PAYLOAD autoswap path**, where minPCOut slippage protection is computed from a single, same-call spot quote of an on-chain AMM pool rather than from any independent or time-weighted price source.

### Title
Self-referential spot-price slippage bound in GAS/GAS_AND_PAYLOAD autoswap allows AMM price-manipulation theft of inbound deposit value - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
`ExecuteInboundGas` and `ExecuteInboundGasAndPayload` convert an inbound PRC20 (gas token) into native PC by calling `GetSwapQuote` (a same-block, static `QuoterV2.quoteExactInputSingle` call) and then immediately deriving `minPCOut = quote * 95 / 100` for the real swap executed via `CallPRC20DepositAutoSwap` / `gasAndPayloadDepositAutoSwap`. Because the "slippage protection" bound is computed from the exact instantaneous pool price that the swap itself will execute against, an attacker who moves the pool's reserves immediately beforehand (via ordinary, permissionless swap-router transactions) can force any victim's inbound-triggered autoswap to execute at an attacker-favorable price, extracting the difference — the same "no protection against a manipulated reference price" pattern as the ERC4626 donation/inflation attack.

### Finding Description
`GetSwapQuote` at [1](#0-0)  performs a non-committing `quoteExactInputSingle` call against the live pool state at execution time — there is no TWAP, no oracle cross-check, and no separate reference price.

Both consuming code paths derive their sole slippage guard directly from that same quote: [2](#0-1) [3](#0-2) 

The pattern is: `quote := GetSwapQuote(currentPoolState)`, `minPCOut := quote * 0.95`, then execute the real swap against the same (now possibly still-manipulated) pool state via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`'s swap branch (also present in `applyGasRefund`, [4](#0-3) ). Since the bound is computed *from* the manipulated price rather than an independent honest price, "5% slippage protection" only bounds movement between the quote call and the swap call within the same keeper invocation — it does nothing to prevent an attacker from pre-positioning the pool at an unfavorable rate before either call happens.

An unprivileged attacker who can submit swaps on the underlying DEX pool (a normal, permissionless AMM action reachable by any user, not requiring validator/TSS/admin privilege) can:
1. Push the PRC20↔WPC pool price against the victim's expected conversion direction using a large temporary swap.
2. Wait for (or trigger, by sending their own qualifying small GAS inbound) a GAS/GAS_AND_PAYLOAD inbound to be executed at that skewed price — pending inbounds and their execution are driven by Universal Validator vote finality, which is publicly observable (`PendingInbounds`), giving the attacker a timing window.
3. Reverse the price-moving swap immediately after, capturing the value difference as arbitrage profit at the expense of the PRC20-to-PC (native asset) conversion that the recipient UEA/gas-refund recipient should have received.

### Impact Explanation
This corrupts the native/PRC20 asset-accounting invariant during autoswap: the recipient UEA (or gas-refund recipient in `applyGasRefund`) receives less native PC than the fair-market conversion of their deposited/refunded PRC20 amount, with the shortfall captured by the attacker. This falls under the allowed impact "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting ... or canonical UniversalTx state," reachable purely through ordinary user deposits and permissionless AMM trades, without any privileged validator, TSS, or admin action.

### Likelihood Explanation
Medium. The attack requires the attacker to have capital to move the pool and to time execution around inbound finalization, similar to standard AMM sandwich attacks; it does not require frontrunning within the same block since Push Chain inbound execution timing is UV-vote-driven and publicly observable via pending-inbound state, giving attackers a wider opportunistic window than typical single-block MEV. Pools created for lower-liquidity synthetic tokens (as seen in the e2e pool-creation setup with small seed liquidity) would be especially susceptible.

### Recommendation
Do not derive the slippage bound from the same live spot quote that the swap itself will execute against. Use either (a) a TWAP/oracle-based reference price independent of the immediately-preceding pool state, or (b) a protocol/admin-configured maximum-deviation check comparing the spot quote against a recent moving average before allowing the autoswap to proceed, reverting (or falling back to the no-swap deposit path) if the deviation exceeds a safe threshold.

### Proof of Concept
1. Attacker observes a pending GAS or GAS_AND_PAYLOAD inbound (via public `PendingInbounds` state) approaching UV vote quorum, or submits their own qualifying inbound.
2. Attacker submits a large swap on the PRC20/WPC pool (permissionless DEX action) to skew reserves so that a subsequent `quoteExactInputSingle(PRC20, WPC, amount)` call returns a depressed WPC amount.
3. When the inbound finalizes, `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetSwapQuote` against the skewed pool, computes `minPCOut = quote*0.95` from the skewed quote, and executes `CallPRC20DepositAutoSwap`, converting the victim's PRC20 to PC at the unfavorable rate — the 5% bound does not detect or block this because it was computed from the same skewed state.
4. Attacker reverses their initial swap, capturing the arbitrage profit that should have accrued to the victim's converted PC balance.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
