## Title
DoS via unhandled exception in block/log event-trigger post-processing causing full node `System.exit` — ([File: framework/src/main/java/org/tron/core/db/Manager.java])

### Summary
`Manager.blockTrigger()` wraps the JSON-RPC filter posting (`postBlockFilter`, `postLogsFilter`, `postSolidityFilter`) and event-subscribe trigger posting (`postBlockTrigger`, `postSolidityTrigger`) in a single try/catch that converts *any* `Exception` into a `TronError` with `ErrCode.EVENT_SUBSCRIBE_ERROR`. [1](#0-0)  `TronError` is documented as fatal: any thrown instance is caught by the JVM's default uncaught-exception handler and triggers a full process `System.exit`. [2](#0-1) [3](#0-2) 

### Finding Description
`blockTrigger` is invoked for every block processed by the node (both self-produced and blocks received from the network containing arbitrary user transactions), as part of normal block-application flow. [1](#0-0)  Within it, `postBlockFilter`/`postLogsFilter`/`postSolidityFilter` (JSON-RPC filters) and `postBlockTrigger`/`postSolidityTrigger` (event-subscribe triggers) are called unguarded by any per-call exception handling — unlike `postContractTrigger`, which explicitly catches `Throwable` per-trigger to avoid propagating failures. [4](#0-3)  Any runtime exception thrown while building or serializing these triggers/filters (e.g., a `NullPointerException` from a malformed capsule, or an exception while parsing/encoding contract log/event data contained in a transaction's execution result) escapes to `blockTrigger`'s catch block, which converts it to a `TronError`. [5](#0-4)  Because `TronError` is an `Error` and is never meant to be caught, `ExitManager`'s default uncaught-exception handler detects it via `findTronError` and immediately calls `System.exit`, halting the entire node process. [6](#0-5)  A unit test explicitly documents and asserts this exact behavior — a `RuntimeException` from `postBlockTrigger` is turned into a `TronError(EVENT_SUBSCRIBE_ERROR)`. [7](#0-6) 

This mirrors the reported Cosmos SDK `x/crisis` bug class in spirit but inverted in mechanism: instead of failing to halt on an invariant violation, java-tron here aggressively halts the *entire node process* on any exception surfaced from event/log post-processing that is driven by ordinary block/transaction content — a broad, unbounded failure domain triggerable by network-visible transaction data, not by a privileged or dedicated invariant-check transaction.

### Impact Explanation
If any transaction (or its resulting contract logs/events) can trigger an exception inside the JSON-RPC filter or event-subscribe trigger posting path — for example a decoding/formatting bug reachable from attacker-controlled event/log data emitted by a smart contract — every full node with `jsonrpc` or `event.subscribe` enabled that processes that block will crash via `System.exit`, since `blockTrigger` runs for every applied block. This is a network-wide denial-of-service: a single malicious transaction, once included in a block, can be replayed against or naturally propagate to all such nodes, taking them all offline simultaneously.

### Likelihood Explanation
Moderate. It requires (1) `event.subscribe` and/or the JSON-RPC filter feature to be enabled on the target nodes (a common node operator configuration, not the default), and (2) discovery of an exception-triggering condition in one of the unguarded posting paths (`postBlockFilter`, `postLogsFilter`, `postSolidityFilter`, `postBlockTrigger`, `postSolidityTrigger`) reachable from transaction/log content, similar in nature to the `NullPointerException` conditions already observed and asserted in `RealtimeEventServiceTest`. [8](#0-7) 

### Recommendation
Do not let generic, non-fatal exceptions from event/log/JSON-RPC trigger posting escalate to a process-terminating `TronError`. Apply the same defensive pattern already used in `postContractTrigger` (catch `Throwable`, log, and continue) to `postBlockFilter`, `postLogsFilter`, `postSolidityFilter`, `postBlockTrigger`, and `postSolidityTrigger`, or narrow `blockTrigger`'s catch clause to only escalate truly unrecoverable errors (e.g., I/O/storage corruption) rather than any `Exception` surfaced from optional subscription/filter features driven by attacker-influenced transaction/log data.

### Proof of Concept
`ManagerTest.blockTrigger()` already demonstrates the mechanism directly: mocking `postBlockTrigger` to throw a `RuntimeException` causes `Manager.blockTrigger()` to rethrow it as `TronError.ErrCode.EVENT_SUBSCRIBE_ERROR`. [7](#0-6)  Combined with `ExitManager.initExceptionHandler`'s `System.exit` on any `TronError`, an attacker who can craft a transaction whose resulting contract logs/events drive one of the unguarded posting paths into an exception (analogous to the `NullPointerException` paths already exercised in `RealtimeEventServiceTest`) can force any node with event subscription or JSON-RPC filters enabled to exit as soon as it applies the block containing that transaction.

  void blockTrigger(final BlockCapsule block, long oldSolid, long newSolid) {
    // post block and logs for jsonrpc
    try {
      if (CommonParameter.getInstance().isJsonRpcHttpFullNodeEnable()) {
        postBlockFilter(block, false);
        postLogsFilter(block, false, false);
      }

      if (CommonParameter.getInstance().isJsonRpcHttpSolidityNodeEnable()) {
        postSolidityFilter(oldSolid, newSolid);
      }

      if (EventPluginLoader.getInstance().getVersion() != 0) {
        lastUsedSolidityNum = newSolid;
        return;
      }

      // if event subscribe is enabled, post block trigger to queue (real-time, not removed)
      postBlockTrigger(block, false);
      // if event subscribe is enabled, post solidity trigger to queue
      // (also emits solidified-mode block/transaction triggers)
      postSolidityTrigger(newSolid);
    } catch (Exception e) {
      logger.error("Block trigger failed. head: {}, oldSolid: {}, newSolid: {}",
          block.getNum(), oldSolid, newSolid, e);
      throw new TronError(e, TronError.ErrCode.EVENT_SUBSCRIBE_ERROR);
    }
  }

  public static void initExceptionHandler() {
    Thread.setDefaultUncaughtExceptionHandler((t, e) -> {
      findTronError(e).ifPresent(ExitManager::logAndExit);
      logger.error("Uncaught exception", e);
    });
  }

  public static Optional<TronError> findTronError(Throwable e) {
    if (e == null) {
      return Optional.empty();
    }

    Set<Throwable> seen = new HashSet<>();

    while (e != null && !seen.contains(e)) {
      if (e instanceof TronError) {
        return Optional.of((TronError) e);
      }
      seen.add(e);
      e = e.getCause();
    }
    return Optional.empty();
  }

  public static void logAndExit(TronError exit) {
    final int code = exit.getErrCode().getCode();
    logger.error("Shutting down with code: {}, reason: {}", exit.getErrCode(), exit.getMessage());
    Thread exitThread = exitThreadFactory.newThread(() -> System.exit(code));
    exitThread.start();
  }
