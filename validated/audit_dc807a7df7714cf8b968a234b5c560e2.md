### Title
Missing `__execute__`-selector guard on `library_call` allows bypass of the direct-execute-call protection enforced on `call_contract` - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
Both the Starknet OS (Cairo) and the blockifier deliberately forbid a contract from directly invoking another contract's `__execute__` entry point through the `call_contract` syscall. The OS enforces this unconditionally in `execute_call_contract`, and the blockifier enforces it via the versioned-constants flag `block_direct_execute_call` (checked only inside the `call_contract` syscall handlers). The `library_call` syscall — which runs arbitrary class code in the *caller's own* storage/context (a delegate call) — implements no equivalent selector check anywhere in the OS or in the blockifier's VM/Native syscall handlers. This is structurally the same class of bug as CVE-2025-14282: an established security check applied to one code path (root-dropping for shell/file access in Dropbear; the `__execute__` guard for `call_contract`) is not propagated to a newer/alternate code path that reaches the same sensitive operation (unix-socket forwarding in Dropbear; `library_call` here), silently bypassing the intended restriction.

### Finding Description
- In the OS, `execute_call_contract` explicitly rejects calls to `EXECUTE_ENTRY_POINT_SELECTOR`: [1](#0-0) 
- The deprecated (Cairo0) syscall path enforces the same restriction for `CALL_CONTRACT_SELECTOR`: [2](#0-1) 
- The corresponding `execute_library_call` implementation in the OS has no such check — it builds the execution context straight from the request and calls `contract_call_helper` unconditionally: [3](#0-2) 
- In the blockifier, the guard is implemented as `maybe_block_direct_execute_call`, gated by `versioned_constants.block_direct_execute_call`: [4](#0-3) 
- This guard is invoked only from the `call_contract` handlers, both for the VM path and the Native path: [5](#0-4) [6](#0-5) 
- Both the VM and Native `library_call` implementations construct the entry point and dispatch execution without ever calling `maybe_block_direct_execute_call` or checking the selector against `__execute__`: [7](#0-6) [8](#0-7) 

The check `DirectExecuteCall` error variant exists in the error enum and is only produced from `call_contract`: [9](#0-8) 

Any contract can therefore invoke `library_call_syscall(class_hash, __execute__selector, calldata)` to run the target class's `__execute__` code in the caller's own storage/context, achieving the semantic equivalent of "directly calling `__execute__`" while completely sidestepping the restriction that `block_direct_execute_call`/the OS's `execute_call_contract` guard was designed to enforce.

### Impact Explanation
The restriction against directly invoking `__execute__` is intended to preserve the invariant that `__execute__` is only ever run as the top-level dispatch of a transaction that has gone through the proper `__validate__` → fee-charging → `__execute__` sequencing, and to prevent contracts from re-entering/replaying an account's execution logic outside of that flow (e.g., to avoid double-fee-charging bypass, unexpected reentrancy into account logic, or state confusion where `__execute__` code runs against a caller-controlled storage context). Because `library_call` reaches the identical `__execute__` code path without this check, and additionally executes it against the *caller's own* storage (not the target's), a malicious contract can trigger unauthorized execution of an account's `__execute__` logic, corrupting sequencer state semantics that honest nodes and the OS both assume are enforced. This can lead to unauthorized account actions / state divergence between what protocol invariants assume and what is actually reachable, undermining Starknet OS re-execution guarantees since the OS applies the block only on `call_contract`, not `library_call`.

### Likelihood Explanation
The `library_call` syscall is available to any contract in any transaction (invoke or L1 handler flows) with no special privilege required — an unprivileged transaction sender only needs to deploy or call a contract that issues `library_call_syscall(class_hash, __execute__selector, calldata)`. No race condition, no operator/proposer collusion, and no special network condition is required; the bypass is deterministic and always reachable, making likelihood high given the flaw exists on the fully-reachable execution path from any sender's transaction.

### Recommendation
Add the same `__execute__`-selector rejection to the `library_call` implementations in the OS (`execute_library_call` in `syscall_impls.cairo`) and to the blockifier's `library_call` handlers (`hint_processor.rs` and `native/syscall_handler.rs`), invoking `maybe_block_direct_execute_call`/the equivalent OS-level `assert_not_equal`/selector check exactly as done for `call_contract`, so that the "direct execute call" protection is enforced uniformly across every syscall capable of dispatching to `__execute__`.

### Proof of Concept
1. Deploy any contract `A` whose code calls `starknet::library_call_syscall(target_class_hash, selector!("__execute__"), calldata)`, where `target_class_hash` is the class hash of any deployed account contract.
2. Submit an ordinary `invoke` transaction that calls `A`'s external function which performs the above `library_call`.
3. Observe that the call succeeds and the account's `__execute__` entry-point logic runs in `A`'s storage context/caller context, whereas the same attempt via `call_contract_syscall(target_address, selector!("__execute__"), calldata)` against the OS/blockifier with `block_direct_execute_call` enabled is rejected with `"Invalid argument"` (blockifier) or a failure response (OS), as shown by the existing tests: [10](#0-9) [11](#0-10) 
No equivalent test or guard exists for the `library_call` path, confirming the bypass.

    fn library_call(
        &mut self,
        class_hash: Felt,
        function_selector: Felt,
        calldata: &[Felt],
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.library_call.base_syscall_cost(),
            SyscallSelector::LibraryCall,
        )?;

        let class_hash = ClassHash(class_hash);

        let wrapper_calldata = Calldata(Arc::new(calldata.to_vec()));

        let selector = EntryPointSelector(function_selector);

        let entry_point = CallEntryPoint {
            class_hash: Some(class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector,
            calldata: wrapper_calldata,
            // The call context remains the same in a library call.
            storage_address: self.base.call.storage_address,
            caller_address: self.base.call.caller_address,
            call_type: CallType::Delegate,
            initial_gas: *remaining_gas,
        };

        let error_wrapper_function =
            |e: SyscallExecutionError,
             class_hash: ClassHash,
             storage_address: ContractAddress,
             selector: EntryPointSelector| {
                e.as_lib_call_execution_error(class_hash, storage_address, selector)
            };

        Ok(self
            .execute_inner_call(entry_point, remaining_gas, class_hash, error_wrapper_function)?
            .0)
    }

    fn library_call(
        request: LibraryCallRequest,
        vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
        remaining_gas: &mut u64,
    ) -> Result<LibraryCallResponse, Self::Error> {
        let entry_point = CallEntryPoint {
            class_hash: Some(request.class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: request.function_selector,
            calldata: request.calldata,
            // The call context remains the same in a library call.
            storage_address: syscall_handler.storage_address(),
            caller_address: syscall_handler.caller_address(),
            call_type: CallType::Delegate,
            // NOTE: this value might be overridden later on.
            initial_gas: *remaining_gas,
        };

        let retdata_segment = execute_inner_call(entry_point, vm, syscall_handler, remaining_gas)
            .map_err(|error| match error {
            SyscallExecutionError::Revert { .. } => error,
            _ => error.as_lib_call_execution_error(
                request.class_hash,
                syscall_handler.storage_address(),
                request.function_selector,
            ),
        })?;

        Ok(LibraryCallResponse { segment: retdata_segment })
    }
