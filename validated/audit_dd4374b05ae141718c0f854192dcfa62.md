### No vulnerability found for this question.

**Reasoning:**

The equality the question assumes — "miner_pubkey_hash160 recovered from block signature == hash160 that the leader-key op is bound to via its Bitcoin `apparent_sender`" — is not part of the actual security model in this codebase. The design explicitly decouples the Bitcoin signer of the `LeaderKeyRegisterOp` transaction from the Stacks block-signing key hash160 embedded in the memo: [1](#0-0) 

`parse_data` takes the memo bytes verbatim from the Bitcoin transaction with no cross-check against `tx.apparent_sender()`: [2](#0-1) 

The actual invariant enforced by `check_miner_signature` is simply that the block's signature recovers to the hash160 stored in the leader key referenced by the *winning block-commit* of that tenure — nothing more: [3](#0-2) 

and this hash160 is pulled straight from `interpret_nakamoto_signing_key()` at block-validation time: [4](#0-3) 

Tracing the attacker's exact path: to become the tenure's block-commit winner, the attacker must win sortition using the VRF proving key referenced by that same `LeaderKeyRegisterOp` (validated via `validate_vrf_seed`/`check_normal_coinbase_tx`, which require the correct VRF private key). If the attacker sets `memo[0..20]` to a Hash160 for which they do **not** hold the private key, they can win the sortition (since VRF key ownership is independent of the memo field) but then cannot produce a block whose miner signature recovers to that hash160 — `check_miner_signature` will deterministically reject **every** node's attempt to accept such a block, since recovery is a pure function of the signature and message. This is a self-inflicted denial of the attacker's own tenure (loss of their own burn/reward), not an invalid-block acceptance, and it is fully deterministic and consistent across all honest nodes — no state divergence, no chain split, no double payment.

If instead the attacker sets memo to a hash160 for a key they *do* control, that is simply the intended design feature (miners are permitted to bind an arbitrary Stacks signing key distinct from their Bitcoin key), not unauthorized signer acceptance.

There is no code path where a block signed by an "uncontrolled" hash160's true owner is accepted without that owner's cooperation/signature, since the ECDSA recovery in `recover_miner_pubkh`/`check_miner_signature` cannot be forged. The claimed equality is therefore not a security invariant that is broken; it was never part of the design, and no divergence, invalid acceptance, or reward-mispayment path exists as a result.

```rust
    fn parse_data(data: &[u8]) -> Option<ParsedData> {
        /*
            Wire format:

            0      2  3              23                       55                      75        80
            |------|--|---------------|-----------------------|-----------------------|---------|
             magic  op consensus hash   proving public key      block-signing hash160    memo
                       (ignored)                                                       (ignored)

             Note that `data` is missing the first 3 bytes -- the magic and op have been stripped.
             `block-signing hash160` is new to Nakamoto.
        */
        // memo can be empty, and magic + op are omitted
        if data.len() < 52 {
            // too short to have a consensus hash and proving public key
            warn!(
                "LEADER_KEY_REGISTER payload is malformed ({} bytes)",
                data.len()
            );
            return None;
        }

        let consensus_hash = ConsensusHash::from_bytes(data.get(0..20)?)
            .expect("FATAL: invalid byte slice for consensus hash");
        let pubkey = match VRFPublicKey::from_bytes(data.get(20..52)?) {
            Some(pubk) => pubk,
            None => {
                warn!("Invalid VRF public key");
                return None;
            }
        };

        let memo = data.get(52..)?;

        Some(ParsedData {
            consensus_hash,
            public_key: pubkey,
            memo: memo.to_vec(),
        })
    }
```

```rust
    pub(crate) fn check_miner_signature(
        &self,
        miner_pubkey_hash160: &Hash160,
    ) -> Result<(), ChainstateError> {
        if self.is_shadow_block() {
            return Ok(());
        }

        let recovered_miner_hash160 = self.recover_miner_pubkh()?;
        if &recovered_miner_hash160 != miner_pubkey_hash160 {
            warn!(
                "Nakamoto Stacks block signature mismatch: {recovered_miner_hash160} != {miner_pubkey_hash160} from leader-key";
                "consensus_hash" => %self.header.consensus_hash,
                "stacks_block_hash" => %self.header.block_hash(),
                "stacks_block_id" => %self.header.block_id()
            );
            return Err(ChainstateError::InvalidStacksBlock(
                "Invalid miner signature".into(),
            ));
        }

        Ok(())
    }
```
