### Title
Unbounded/unclamped global resource-weight accumulators in TVM native contract Repository path allow negative `TotalNetWeight`/`TotalEnergyWeight`/`TotalTronPowerWeight`, corrupting network-wide resource pricing - ([File: actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java])

### Summary
`RepositoryImpl.addTotalNetWeight` / `addTotalEnergyWeight` / `addTotalTronPowerWeight` — the accounting hooks used by TVM native-contract processors (`FreezeBalanceV2Processor`, `UnfreezeBalanceV2Processor`, `CancelAllUnfreezeV2Processor`, `UnDelegateResourceProcessor`) — increment/decrement the global `TotalNetWeight`/`TotalEnergyWeight`/`TotalTronPowerWeight` counters with no lower bound. This mirrors the root cause of the Derby `totalWithdrawalRequests` bug: an accumulator that is supposed to track a bounded quantity but is updated without any reset/clamp guarantee, so repeated legitimate operations can drive it into an invalid state that corrupts downstream calculations that assume non-negative values.

### Finding Description
The direct-transaction path (`DynamicPropertiesStore`, used by ordinary actuators such as `FreezeBalanceV2Actuator`/`UnfreezeBalanceV2Actuator`) explicitly clamps these same global counters to a floor of zero: [1](#0-0) 

However, the TVM contract-triggered path routes through `RepositoryImpl`, whose implementations of the identical accounting methods contain **no clamping at all**: [2](#0-1) 

These `Repository` methods are invoked directly by the TVM native-contract processors that back the `freezeBalanceV2`, `unfreezeBalanceV2`, `cancelAllUnfreezeV2`, and `unDelegateResource` precompiled contract calls: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

All these processors are reachable from ordinary, unprivileged smart-contract execution via `Program.java`, i.e. from any broadcast transaction that calls a contract invoking these native operations: [7](#0-6) 

Because the weight delta computed in these processors is `newWeight - oldWeight` (a signed delta derived from a snapshot of the account's frozen balance before/after the operation), any accumulated rounding, ordering, or partial-decrement discrepancy across many delegate/undelegate/unfreeze/cancel operations on the same account can, over time, cause the aggregate global counter maintained via `RepositoryImpl` to diverge from the true sum of individually frozen balances and go negative — with nothing preventing or correcting this, unlike the `DynamicPropertiesStore` path which enforces `max(0, ...)` when `allowNewReward()` is active.

### Impact Explanation
`TotalNetWeight` / `TotalEnergyWeight` are consensus-critical global parameters used to compute every account's available bandwidth/energy limits network-wide (e.g. `calcCanDelegatedBandWidthMaxSize` / `calcCanDelegatedEnergyMaxSize` divide by these values): [8](#0-7) 

If this counter is driven negative or otherwise corrupted through the unguarded `RepositoryImpl` path while remaining clamped through the `DynamicPropertiesStore` path, the two accounting surfaces diverge, producing incorrect global bandwidth/energy limit calculations for the whole network (a resource/reward accounting corruption), and can also introduce negative divisors/negative weight values feeding into ratio computations used for delegated-resource math (`unDelegateMaxUsage` calculations use `dynamicStore.getTotalNetWeight()`/`getTotalEnergyWeight()` as a divisor): [9](#0-8) 
This is not a fund-locking DoS as in the Derby report, but it is the same bug class (accumulator without invariant enforcement in one code path, guarded in a sibling path) applied to a value that underpins global resource pricing/accounting across the network.

### Likelihood Explanation
Existing regression tests only exercise the "actuator" path and simple TVM freeze/unfreeze scenarios that keep the two counters consistent (`FreezeTest.java`, `FreezeV2Test.java`), so no test currently demonstrates the divergence. I could not conclusively reproduce a concrete sequence, within the available context, that forces the `RepositoryImpl` delta computation to diverge from a non-negative invariant — the trigger would require a specific combination of delegate/undelegate/freeze/unfreeze operations executed purely through TVM contract calls whose `oldWeight`/`newWeight` snapshots go out of sync with the true underlying balances (e.g. due to concurrent state changes not reflected in the account snapshot used for the delta, or due to precision loss from repeated `/ TRX_PRECISION` truncation across many small operations). Given this uncertainty about a concrete, reliably-triggerable divergence, likelihood is assessed as low-to-moderate rather than confirmed.

### Recommendation
Add the same `max(0, ...)` clamping logic (gated by the same `allowNewReward()`/feature-flag semantics) to `RepositoryImpl.addTotalNetWeight`, `addTotalEnergyWeight`, and `addTotalTronPowerWeight` so that the TVM native-contract accounting path can never push these global counters negative, matching the invariant already enforced in `DynamicPropertiesStore`. Additionally, audit all call sites of `repo.addTotalNetWeight/addTotalEnergyWeight/addTotalTronPowerWeight` for consistency with the corresponding `DynamicPropertiesStore` implementations to eliminate this dual-implementation divergence.

### Proof of Concept
Not fully verifiable within the current investigation — a concrete failing transaction sequence (e.g., precise ordering of `freezeBalanceV2` → `delegateResource` → `unDelegateResource` → `cancelAllUnfreezeV2` calls issued from a smart contract) that forces `RepositoryImpl`'s unclamped accumulator negative was not constructed/tested here due to tool limitations (no execution environment available). The core finding — that `RepositoryImpl`'s implementation lacks the clamp present in `DynamicPropertiesStore`'s implementation of the identical accounting semantics — is directly confirmed by the cited source excerpts.

  private long transferFrozenV2BalanceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);
    AccountCapsule inheritorCapsule = repo.getAccount(inheritorAddr);
    long now = repo.getHeadSlot();

    // transfer frozen resource
    ownerCapsule.getFrozenV2List().stream()
        .filter(freezeV2 -> freezeV2.getAmount() > 0)
        .forEach(
            freezeV2 -> {
              switch (freezeV2.getType()) {
                case BANDWIDTH:
                  inheritorCapsule.addFrozenBalanceForBandwidthV2(freezeV2.getAmount());
                  break;
                case ENERGY:
                  inheritorCapsule.addFrozenBalanceForEnergyV2(freezeV2.getAmount());
                  break;
                case TRON_POWER:
                  inheritorCapsule.addFrozenForTronPowerV2(freezeV2.getAmount());
                  break;
              }
            });

    // merge usage
    BandwidthProcessor bandwidthProcessor = new BandwidthProcessor(ChainBaseManager.getInstance());
    bandwidthProcessor.updateUsageForDelegated(ownerCapsule);
    ownerCapsule.setLatestConsumeTime(now);
    if (ownerCapsule.getNetUsage() > 0) {
      bandwidthProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getNetUsage(), BANDWIDTH, now);
    }

    EnergyProcessor energyProcessor =
        new EnergyProcessor(
            repo.getDynamicPropertiesStore(), ChainBaseManager.getInstance().getAccountStore());
    energyProcessor.updateUsage(ownerCapsule);
    ownerCapsule.setLatestConsumeTimeForEnergy(now);
    if (ownerCapsule.getEnergyUsage() > 0) {
      energyProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getEnergyUsage(), ENERGY, now);
    }

    // withdraw expire unfrozen balance
    long nowTimestamp = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long expireUnfrozenBalance =
        ownerCapsule.getUnfrozenV2List().stream()
            .filter(
                unFreezeV2 ->
                    unFreezeV2.getUnfreezeAmount() > 0 && unFreezeV2.getUnfreezeExpireTime() <= nowTimestamp)
            .mapToLong(Protocol.Account.UnFreezeV2::getUnfreezeAmount)
            .sum();
    if (expireUnfrozenBalance > 0) {
      inheritorCapsule.setBalance(inheritorCapsule.getBalance() + expireUnfrozenBalance);
      increaseNonce();
      addInternalTx(null, ownerAddr, inheritorAddr, expireUnfrozenBalance, null,
          "withdrawExpireUnfreezeWhileSuiciding", nonce, null);
    }
    clearOwnerFreezeV2(ownerCapsule);
    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);
    repo.updateAccount(inheritorCapsule.createDbKey(), inheritorCapsule);
    return expireUnfrozenBalance;
  }

  public long calcCanDelegatedBandWidthMaxSize(
          ByteString ownerAddress) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress.toByteArray());
    if (ownerCapsule == null) {
      return 0L;
    }

    BandwidthProcessor processor = new BandwidthProcessor(chainBaseManager);
    processor.updateUsage(ownerCapsule);

    long accountNetUsage = ownerCapsule.getNetUsage();
    accountNetUsage += TransactionUtil.estimateConsumeBandWidthSize(dynamicStore,
            ownerCapsule.getFrozenV2BalanceForBandwidth());

    long netUsage = (long) (accountNetUsage * TRX_PRECISION * ((double)
            (dynamicStore.getTotalNetWeight()) / dynamicStore.getTotalNetLimit()));

    long v2NetUsage = getV2NetUsage(ownerCapsule, netUsage, dynamicStore.disableJavaLangMath());

    long maxSize = ownerCapsule.getFrozenV2BalanceForBandwidth() - v2NetUsage;
    return max(0, maxSize, dynamicStore.disableJavaLangMath());
  }

  public long calcCanDelegatedEnergyMaxSize(ByteString ownerAddress) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress.toByteArray());
    if (ownerCapsule == null) {
      return 0L;
    }

    EnergyProcessor processor = new EnergyProcessor(dynamicStore, accountStore);
    processor.updateUsage(ownerCapsule);

    long energyUsage = (long) (ownerCapsule.getEnergyUsage() * TRX_PRECISION * ((double)
            (dynamicStore.getTotalEnergyWeight()) / dynamicStore.getTotalEnergyCurrentLimit()));

    long v2EnergyUsage = getV2EnergyUsage(ownerCapsule, energyUsage,
        dynamicStore.disableJavaLangMath());

    long maxSize =  ownerCapsule.getFrozenV2BalanceForEnergy() - v2EnergyUsage;
    return max(0, maxSize, dynamicStore.disableJavaLangMath());
  }
