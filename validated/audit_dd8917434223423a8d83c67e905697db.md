### Title
Starknet OS `replace_class` syscall omits declared-class validation performed by blockifier, causing sequencer/OS execution divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Rust blockifier enforces that a class hash passed to the `replace_class` syscall must correspond to an already-declared (and, for the Cairo1 path, Cairo1) class before mutating `class_hash_at` for the calling contract. The Cairo implementation of the same syscall inside the Starknet OS program (used for OS re-execution/proving) does not perform this check at all, and is explicitly marked with a `TODO` acknowledging the gap.

### Finding Description
Blockifier's native/Cairo1 syscall handler validates the class before applying the replacement: [1](#0-0) 

Blockifier's deprecated (Cairo0) syscall handler performs the equivalent check: [2](#0-1) 

Both paths call `state.get_compiled_class(class_hash)` and propagate a `StateError::UndeclaredClassHash` / syscall error if the class does not exist, which aborts/reverts the call.

In contrast, the Starknet OS's own Cairo implementation of `replace_class` (used during OS re-execution to independently verify/compute the state transition for proving) sets the new class hash unconditionally, with an explicit acknowledgment that the check is missing: [3](#0-2) 

The same omission exists in the deprecated (Cairo0) OS syscall path: [4](#0-3) 

Because the OS is a separate, independent re-implementation of Starknet's execution semantics in Cairo (it actually re-executes contract bytecode via the CairoVM rather than blindly trusting the sequencer's output), this check must mirror blockifier's logic exactly for the OS-computed state diff to match the sequencer-committed state diff. The `is_reverted` transaction-level flag consumed by the OS is itself derived from the prover's own `tx_execution_info` (produced by blockifier), while entry-point-level success/failure is determined by the OS's own real execution of the syscall body: [5](#0-4) [6](#0-5) 

Because the OS `execute_replace_class` never fails on an undeclared class hash, a contract call that blockifier rejects (aborting/reverting the transaction due to `UndeclaredClassHash`) will not fail when the OS independently re-executes the same call, producing a different (accepted) result and a different resulting `class_hash_at` state entry than what blockifier computed and committed.

### Impact Explanation
This is reachable by any unprivileged contract simply invoking the `replace_class_syscall` (Cairo1) or `REPLACE_CLASS` (Cairo0) syscall with an arbitrary, non-declared class hash felt — no special privileges, staking, or operator collusion required; any invoke transaction that triggers a contract's own `replace_class` call with attacker/user-controlled input reaches this path (see usage in feature-contract test helpers): [7](#0-6) 

Since blockifier and the Starknet OS disagree on whether such a call succeeds, this constitutes an "honest-node divergence" between the sequencer's committed execution result and the OS's independently re-executed result for the same block/transaction. Depending on how strictly downstream code (state-diff consistency assertions, DA computation, block-hash/commitment computation) cross-checks OS-computed values against the sequencer-provided state diff, this can manifest as: (a) OS proof generation failing/aborting for any block containing such a transaction (network unable to finalize/confirm blocks containing this pattern), or (b) a wrong/incorrect committed state entry for the affected contract's `class_hash_at` if the divergent path is not caught by later consistency checks. Both outcomes match accepted High-severity impact categories (wrong committed state, honest-node divergence, network liveness impact on block confirmation).

### Likelihood Explanation
High likelihood of triggerability: `replace_class` is a standard exposed syscall available to any Cairo0/Cairo1 contract, and there is no gateway/mempool/blockifier-level restriction preventing a contract from calling it with a garbage/undeclared class hash felt (the rejection only happens deep inside the syscall handler itself, at execution time). The bug requires no malicious sequencer, prover, or peer — a completely honest single transaction from any account triggers the divergence. The `TODO` comment left directly in the code by the developers confirms this is a known, currently-unaddressed gap in this repository snapshot.

### Recommendation
Add the same "class must be declared" (and Cairo1-type, for the syscall variant) validation to the Starknet OS's Cairo implementations of `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring `syscall_base.rs::replace_class` and `deprecated_syscalls/hint_processor.rs::replace_class`. This requires reading the declared-class fact from `contract_class_changes`/the OS's class-commitment structures and asserting existence (and, where applicable, Cairo1-only) before performing the `dict_update` that changes `class_hash`. Add a regression test analogous to `starknet_os_flow_tests` that submits a `replace_class` call with an undeclared class hash and asserts that OS re-execution reverts consistently with blockifier's behavior.

### Proof of Concept
1. Declare and deploy a Cairo1 (or Cairo0) contract that calls `replace_class_syscall(class_hash)`/`REPLACE_CLASS` with a caller-supplied `class_hash`, e.g. the pattern in: [8](#0-7) 
2. Submit an invoke transaction calling this entry point with an arbitrary felt that is not a declared class hash on-chain (e.g., `0x1234...`).
3. Observe blockifier execution: `state.get_compiled_class(class_hash)` fails with `StateError::UndeclaredClassHash`, and the transaction reverts (per `syscall_base.rs:369-378`).
4. Run the same block/transaction through the Starknet OS re-execution pipeline (`starknet_os_flow_tests`) and inspect the resulting `is_deprecated`/return value path in `execute_replace_class` (`syscall_impls.cairo:881-920`): no error is raised, and `contract_state_changes` is updated with the undeclared `class_hash`, in contradiction to blockifier's revert decision — demonstrating the execution divergence between the two supposedly-equivalent implementations.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
