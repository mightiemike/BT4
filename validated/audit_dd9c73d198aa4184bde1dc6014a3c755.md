### Title
`socialize-debt` mutates vault state using a stale `index`/`lindex` checkpoint because it never calls `accrue` - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every other state-mutating vault operation that depends on the interest-rate checkpoint (`index`, `lindex`, `last-update`) calls `(try! (accrue))` first, e.g. `system-borrow` and `system-repay`. `socialize-debt` is the one exception: it reads `index`, `lindex`, and `total-assets` directly from storage without accruing, then permanently writes down `lindex` and the vault's debt/asset bookkeeping using those stale values.

### Finding Description
`accrue` is the checkpoint-update function: it recomputes `next-index`/`next-liquidity-index` from elapsed time (`stacks-block-time - last-update`) and, if changed, commits `index`, `lindex`, and `last-update`. [1](#0-0) 

`system-borrow` and `system-repay` both bind `(u (try! (accrue)))` as the very first `let` binding before reading `index`/`total-borrowed`/`total-debt`, guaranteeing the checkpoint is fresh before any debt math or state mutation. [2](#0-1) [3](#0-2) 

`socialize-debt`, however, reads `idx` (`var-get index`), `current-lindex` (`var-get lindex`) and `old-total-assets` (`total-assets`, which itself uses `var-get index`, not `next-index`) with no preceding `accrue` call: [4](#0-3) 

If time has passed since the last accrual (`last-update` in the past relative to `stacks-block-time`), the real accrued debt is higher than `total-debt`/`total-assets` computed from the stale `index`. `socialize-debt` uses this understated `old-total-assets` and stale `idx` to compute `debt-reduction` and to write down `lindex` (`new-lindex`), and directly mutates `principal-scaled`, `total-borrowed`, and `assets` in storage - permanently baking the stale checkpoint into the new state rather than letting a subsequent accrual correct it first.

This is exactly the "cached value not invalidated when its source moves" pattern from the report: the checkpoint (`index`/`lindex`/`last-update`) is the cached value; time passing (accrual due) is the event that should invalidate it; `socialize-debt`'s direct writes to `lindex`, `principal-scaled`, `total-borrowed`, `assets` are the later use that consumes the stale value in a single transaction without an intervening accrual.

### Impact Explanation
Because `lindex` (the liquidity/share-price index used by `convert-to-assets`/`convert-to-shares` for all depositors) is overwritten with a value computed from stale debt/assets, depositor share pricing becomes distorted for the block(s) until another vault call happens to trigger `accrue`. Since `total-borrowed`, `principal-scaled`, and `assets` are also mutated based on the stale figures, the debt write-down applied during socialization is smaller/larger than the economically correct amount, meaning some unclaimed accrued interest is either lost from bookkeeping or double-counted — this is theft/misallocation of unclaimed yield across depositors and a temporary mispricing (freezing/loss) of funds, matching the in-scope "temporary freezing of funds" / "theft of unclaimed yield" impact classes.

### Likelihood Explanation
`socialize-debt` is only reachable via `check-caller-auth` (a privileged/system caller, e.g. the market/liquidation controller), so it is not attacker-triggerable by an arbitrary user; however, it is a normal, expected operational call, and the bug is deterministic — it fires any time `socialize-debt` is called after enough elapsed time for the index to move without accrual having occurred in the same or a prior transaction. This is a code-level correctness defect rather than requiring an adversarial setup, so likelihood is credible whenever socialize-debt is used in production without a preceding accrue in the same call.

### Recommendation
Add `(u (try! (accrue)))` as the first `let` binding in `socialize-debt`, mirroring `system-borrow`/`system-repay`, so `index`, `lindex`, `total-debt`, and `total-assets` are freshly checkpointed before computing `debt-reduction`, `principal-reduction`, and the new `lindex` write-down.

### Proof of Concept
1. Vault is active; `last-update` is set at time T0 with `index = I0`, `lindex = L0`.
2. Time passes to T1 > T0 without any intervening call to `accrue` (e.g., no deposits/borrows/repays occur in the interim, or `socialize-debt` is called as the first operation of the block/period).
3. Privileged caller invokes `socialize-debt(scaled-amount)`. The function binds `idx = var-get index = I0` (stale, should be `next-index` reflecting T1), `old-total-assets = total-assets` computed off `I0` (understated relative to the true accrued debt at T1). [5](#0-4) 
4. `debt-reduction = scaled-amount * I0 / INDEX-PRECISION` and `new-lindex` (written proportional to loss against the stale `old-total-assets`) are computed and committed via `var-set lindex new-lindex`, `var-set principal-scaled ...`, `var-set total-borrowed ...`, `var-set assets ...` — all in the same transaction, with no accrual ever having run to reconcile `I0` to the true T1 value. [6](#0-5) 
5. The vault's share price (`lindex`) and debt accounting now permanently reflect a socialization computed on stale interest data, misallocating accrued yield among lenders relative to the correct T1 accrual, and this state is never retroactively corrected since the accrual period was skipped rather than deferred.

Note: I could not fully verify the exact off-chain/on-chain call context (e.g., whether the market controller always calls `accrue` on the vault in the same transaction immediately before invoking `socialize-debt`) since that orchestration logic lives outside the vault contract; this affects confidence on real-world exploitability but the vault-level code path itself unambiguously omits the accrual call present in its sibling functions.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
