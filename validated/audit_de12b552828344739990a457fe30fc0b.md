### Title
Starknet OS `charge_fee` re-execution assumes the fee-token ERC20 transfer will never revert, hard-`assert`ing on it - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo])

### Summary
The Starknet OS Cairo program's `charge_fee` function (used to re-execute every account transaction's fee transfer during OS/proof re-execution) invokes the fee-token contract's `transfer` entry point through `non_reverting_select_execute_entry_point_func`, which hard-asserts `is_reverted = 0`. This mirrors exactly the reported bug class ("a callback/must-not-revert code path performs an external call that can revert, permanently halting the protocol flow"), except here the "callback" is the mandatory OS re-execution step that every block must pass through in order to be proven.

### Finding Description
`charge_fee` in [1](#0-0)  builds a `TransferCallData` and executes it via `non_reverting_select_execute_entry_point_func`, exactly as `run_validate` does for `__validate__` [2](#0-1) .

`non_reverting_select_execute_entry_point_func` itself is defined to unconditionally `assert is_reverted = 0` after executing the entry point: [3](#0-2) 

This is the Cairo-VM analog of "fulfillRandomWords must not revert": the function name itself encodes an invariant ("this call must not revert") that is enforced with a hard assertion rather than being handled gracefully. If the fee-token `transfer` call actually reverts (e.g. Cairo VM error/panic inside the ERC20 entry point, out-of-gas within the fixed `DEFAULT_INITIAL_GAS_COST` budget, or any other execution-path divergence versus what the sequencer's blockifier observed when it originally built the block), the `assert is_reverted = 0` fails and the entire Starknet OS program run for that block fails to produce a proof.

This is analogous to the reported issue in structure: a step in a pipeline that is required to always succeed performs an external, potentially-failing call, and a revert there is unrecoverable by the surrounding logic (VRF service stops retrying / OS proof run aborts) rather than being turned into a normal, recoverable failure path (e.g. a reverted transaction receipt).

### Impact Explanation
If any block contains a transaction whose fee-transfer re-execution in the OS reverts (whether via a genuine bug/divergence between blockifier execution and OS re-execution, or via a maliciously crafted/edge-case fee-token interaction that succeeds under the sequencer's blockifier gas/resource accounting but reverts under the OS's fixed `DEFAULT_INITIAL_GAS_COST` re-execution budget), the Starknet OS re-execution for that block cannot complete, and no proof can be generated for the block. This is a "network unable to confirm new transactions" class impact: block production/proving for the entire chain would halt at that block, since the OS re-execution step is mandatory infrastructure that every block must pass, and there's no fallback/graceful-revert path built into `charge_fee`'s use of `non_reverting_select_execute_entry_point_func`.

### Likelihood Explanation
Likelihood depends entirely on whether there exists a reachable transaction/fee-token state where the blockifier (Rust) execution of `execute_fee_transfer` [4](#0-3)  succeeds and is included in a block, while the OS's Cairo re-execution of the identical call in `charge_fee` reverts. I could not confirm from the code inspected within the available iterations that such a divergence currently exists (e.g., whether `DEFAULT_INITIAL_GAS_COST` in the OS constants and `os_constants.gas_costs.base.default_initial_gas_cost` used by blockifier are guaranteed to always match, and whether all built-in/legacy fee-token implementations behave identically under both gas budgets). This is a structural/design-invariant concern rather than a confirmed concrete exploit path in this codebase - the hard `assert` design decision itself is the root cause pattern shared with the reported bug, but I was not able to fully prove an unprivileged-transaction-reachable divergence within the available investigation.

### Recommendation
- Apply the same design constraint the Chainlink report recommends: do not let a mandatory, non-recoverable step (`charge_fee`'s fee-token transfer) unconditionally `assert is_reverted = 0`. Ensure the OS's execution parameters for the fee-transfer call (gas budget, resource bounds, and any other execution context) are provably always identical to what the sequencer's blockifier used to produce the block, so that a call accepted by the sequencer can never revert during OS re-execution.
- Alternatively/additionally, if a divergence is ever possible, handle the fee-transfer revert case in the OS the same way reverted transactions are already handled elsewhere (as seen in the `is_reverted` / revert-log machinery used for L1 handlers and other transactions), rather than aborting the entire OS run via a hard assertion.
- Audit all other call sites of `non_reverting_select_execute_entry_point_func` (currently used for both `run_validate`'s `__validate__` call and `charge_fee`'s ERC20 transfer) for the same "must never revert, enforced by hard assert" risk pattern.

### Proof of Concept
Not concretely demonstrated - I was unable to confirm within the available tool budget a specific transaction/fee-token state that causes the blockifier-side `execute_fee_transfer` to succeed while the OS-side `charge_fee`/`non_reverting_select_execute_entry_point_func` call reverts. The finding documents the shared root-cause *pattern* (a step that must not revert being enforced via unconditional assertion around an external call) and identifies the exact code locations where this pattern exists in this codebase for further validation with sequencer-level testing/fuzzing.

// Charges a fee from the user.
// If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{
    range_check_ptr,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;
    let max_fee = compute_max_possible_fee(tx_info=tx_info);

    if (max_fee == 0) {
        return ();
    }

    local low_actual_fee;
    %{ LoadActualFee %}
    local calldata: TransferCallData = TransferCallData(
        recipient=block_context.block_info_for_execute.sequencer_address,
        amount=Uint256(low=low_actual_fee, high=0),
    );

    // Verify that the charged amount is not larger than the transaction's max_fee field.
    assert_nn_le(calldata.amount.low, max_fee);

    // TODO(ilya, 01/01/2026): Consider caching the fee_token_class_hash.
    local fee_token_address = block_context.os_global_context.starknet_os_config.fee_token_address;
    let (fee_state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=fee_token_address
    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.
    local execution_context: ExecutionContext = ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=fee_state_entry.class_hash,
        calldata_size=TransferCallData.SIZE,
        calldata=&calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_execute,
            tx_info=tx_info,
            caller_address=tx_info.account_contract_address,
            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context
    );
    return ();
}

// Runs the account contract's "__validate__" entry point, which is responsible for
// signature verification.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the underlying invoke transaction.
func run_validate{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;
    local tx_execution_info: ExecutionInfo* = tx_execution_context.execution_info;

    // Do not run "__validate__" for version 0.
    if (tx_execution_info.tx_info.version == 0) {
        return ();
    }

    // "__validate__" is expected to get the same calldata as "__execute__".
    local validate_execution_context: ExecutionContext* = new ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=tx_execution_context.class_hash,
        calldata_size=tx_execution_context.calldata_size,
        calldata=tx_execution_context.calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_validate,
            tx_info=tx_execution_info.tx_info,
            caller_address=tx_execution_info.caller_address,
            contract_address=tx_execution_info.contract_address,
            selector=VALIDATE_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    // The __validate__ function should not revert.
    let (retdata_size, retdata, is_deprecated) = non_reverting_select_execute_entry_point_func(
        block_context=block_context, execution_context=validate_execution_context
    );
    if (is_deprecated == 0) {
        %{ CheckRetdataForDebug %}
        assert retdata_size = 1;
        assert retdata[0] = VALIDATED;
    }

    return ();
}

// Same as `select_execute_entry_point_func`, but does not support reverts and does
// not have an implicit 'revert_log' argument.
func non_reverting_select_execute_entry_point_func{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, execution_context: ExecutionContext*) -> (
    retdata_size: felt, retdata: felt*, is_deprecated: felt
) {
    let revert_log = init_revert_log();
    let (is_reverted, retdata_size, retdata, is_deprecated) = select_execute_entry_point_func{
        revert_log=revert_log
    }(block_context=block_context, execution_context=execution_context);
    assert is_reverted = 0;
    return (retdata_size, retdata, is_deprecated);
}

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }
