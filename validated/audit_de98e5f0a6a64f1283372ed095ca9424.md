## #Analog Vulnerability Found

### Title
Missing declared-class validation in Starknet OS `execute_replace_class` causes divergence from blockifier's `replace_class` syscall enforcement - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall lets any contract (reachable from an ordinary `INVOKE` transaction) rewrite its own class hash. In the blockifier (the sequencer's actual execution engine) this is gated by two checks: the class must be declared, and it must be a Cairo1 class. In the Starknet OS's independent re-implementation of this syscall (used for proving/re-execution), neither check is performed — the code contains a literal `TODO` acknowledging the missing declared-class check. This creates two independently-computed executions of the same syscall with different acceptance criteria, which is the root-cause pattern analogous to CVE-2020-6949 (missing authorization/validation check on a privileged state-changing action reachable by an unprivileged caller).

### Finding Description
In blockifier, `replace_class` requires the target class hash to be declared and Cairo1-only: [1](#0-0) 

This state mutation is only permitted to succeed when `self.state.get_compiled_class(class_hash)` resolves (i.e., the class was previously declared) and `is_cairo1` holds; otherwise the syscall — and typically the whole transaction — fails/reverts.

The Starknet OS's own syscall handler for the same `REPLACE_CLASS_SELECTOR`, executed independently during proving/re-execution, performs the state write without any declared-class or class-type check: [2](#0-1) 

The `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment on line 902 explicitly documents the gap. The same omission exists in the deprecated syscalls path: [3](#0-2) 

Both OS implementations only touch `contract_state_changes` (the per-contract `class_hash`/storage/nonce state entry) and never consult `contract_class_changes` (the declared-class dictionary) to verify the requested `class_hash` was actually declared, unlike blockifier's `get_compiled_class` gate.

### Impact Explanation
Any Cairo1 contract invoked by an ordinary transaction sender can call `replace_class_syscall(class_hash)` with an undeclared or otherwise blockifier-rejected class hash (e.g. a Cairo0 class, which blockifier explicitly forbids via `ForbiddenClassReplacement`). During normal sequencing, blockifier will reject/revert that call. During Starknet OS re-execution (which independently derives the state diff/commitment for the block used in proving), the same syscall silently succeeds and commits a different class hash for the contract's state entry. This produces a state-diff/commitment mismatch between the sequencer's authoritative execution (blockifier) and the OS's derived execution, i.e., a wrong committed root / honest-node divergence between the block builder and the prover for the same block and transaction set — directly matching the "wrong committed root or block hash, honest-node divergence" impact criterion.

### Likelihood Explanation
The syscall is reachable by any account/contract via a single `INVOKE` transaction calling `replace_class_syscall` with an attacker-chosen `class_hash` (declared-or-not, Cairo0-or-not) — no special privileges are required. The blockifier-side rejection logic (`is_cairo1` check, `get_compiled_class` declared-check) is straightforward to trigger a mismatch against, since the attacker fully controls the `class_hash` argument.

### Recommendation
Add the declared-class (and, to mirror blockifier, Cairo1-type) check to both `execute_replace_class` implementations in the Starknet OS (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), reading from `contract_class_changes` before writing the new `StateEntry`, so that the OS's acceptance criteria for `replace_class` exactly matches blockifier's, closing the referenced `TODO`.

### Proof of Concept
1. Deploy a Cairo1 contract `A` exposing an entry point that calls `replace_class_syscall(class_hash)` with an attacker-supplied `class_hash` value that is either (a) never declared on-chain, or (b) a validly-declared Cairo0 (deprecated) class hash.
2. Submit an `INVOKE` transaction calling that entry point.
3. In blockifier (sequencer execution), the call fails: `get_compiled_class` returns `StateError::UndeclaredClassHash` for case (a), or `is_cairo1` check returns `SyscallExecutionError::ForbiddenClassReplacement` for case (b) — see `crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`.
4. When the Starknet OS independently re-executes the same call trace for proving (`crates/apollo_starknet_os_program/.../syscall_impls.cairo:881-920`), no equivalent check exists, so the OS unconditionally records `new_state_entry` with the attacker-supplied `class_hash` in `contract_state_changes`.
5. Compare the state diff computed by the OS against the one committed by the sequencer for contract `A`'s class hash — they diverge, demonstrating the honest-node/state-commitment mismatch.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
