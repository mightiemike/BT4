### Title
`UnfreezeBalanceProcessor.execute()` skips unconditional vote-reward settlement (`VoteRewardUtil.withdrawReward`) before mutating frozen balance/vote state, unlike its actuator/processor siblings - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceProcessor.java`)

### Summary
The TVM native-contract path for unfreezing TRC10-era frozen balance, `UnfreezeBalanceProcessor.execute()`, does not unconditionally settle the account's accrued vote reward before mutating the account's frozen balance / total resource weight / vote state, unlike every sibling code path that performs the equivalent state transition.

### Finding Description
`VoteRewardUtil.withdrawReward()` is the accounting function that snapshots an account's vote list per cycle (`updateBeginCycle`, `updateEndCycle`, `updateAccountVote`) and credits pending rewards to `allowance` before any operation that can change the account's TronPower, votes, or frozen balance. Every comparable settlement path calls it unconditionally, at the very start of `execute()`:
- `UnfreezeBalanceActuator.execute()` — calls `mortgageService.withdrawReward(ownerAddress)` unconditionally at the top, before any balance/weight/vote mutation. [1](#0-0) 
- `VoteWitnessProcessor.execute()` — calls `VoteRewardUtil.withdrawReward(ownerAddress, repo)` unconditionally before touching votes. [2](#0-1) 
- `UnfreezeBalanceV2Processor.execute()` — same pattern, unconditional call at the top. [3](#0-2) 
- `WithdrawRewardProcessor.execute()` — same pattern. [4](#0-3) 

In contrast, `UnfreezeBalanceProcessor.execute()` — the processor backing the `unfreezeBalance` TVM opcode that any deployed smart contract can invoke — performs the frozen-balance reduction, balance credit, and `repo.addTotalNetWeight`/`addTotalEnergyWeight` weight adjustments and persists the account (`repo.updateAccount`) first, and only calls `VoteRewardUtil.withdrawReward()` afterward, and only conditionally, inside an `if (accountCapsule.getTronPower() < usedTronPower * TRX_PRECISION)` guard: [5](#0-4) 

This means whenever an account unfreezes bandwidth/energy through the TVM path while its remaining TronPower still covers its existing votes (the common case for partial unfreezes), `withdrawReward()` is never invoked for that transaction at all — the per-cycle vote checkpoint (`updateBeginCycle`/`updateEndCycle`/`updateAccountVote`) that all sibling paths perform is silently skipped for that account on that block, even though the account's TronPower-affecting frozen balance just changed.

### Impact Explanation
Skipping the reward-settlement checkpoint means the `beginCycle`/`endCycle`/`accountVote` bookkeeping used by `VoteRewardUtil.computeReward()`/`MortgageService.computeReward()` (delta-VI reward computation keyed to vote-list snapshots per cycle) can diverge from the actuator-driven path for functionally identical operations, depending only on whether the unfreeze was executed via a normal transaction (`UnfreezeBalanceActuator`) or via a smart-contract call to the `unfreezeBalance` TVM opcode (`UnfreezeBalanceProcessor`). This produces inconsistent/incorrect reward accounting for TVM-triggered unfreezes and is directly analogous to the Gondi `settleWithBuyout()` finding: a state-transition function that bypasses the shared accounting hook that its sibling paths always invoke, corrupting downstream reward/vote bookkeeping.

### Likelihood Explanation
Reachability is unprivileged and trivial: any deployed smart contract can call the native `unfreezeBalance` precompile, and any externally-owned account can trigger it via a `TriggerSmartContract` transaction, with no special permission required. The divergent behavior triggers deterministically whenever `accountCapsule.getTronPower() >= usedTronPower * TRX_PRECISION` after the unfreeze (i.e., any partial unfreeze that still leaves enough power to cover current votes) — a common, easily-satisfied condition, not an edge case.

### Recommendation
Move the `VoteRewardUtil.withdrawReward(ownerAddress, repo)` call in `UnfreezeBalanceProcessor.execute()` to the top of the method (before any frozen balance / weight / account mutation), mirroring `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Processor`, `VoteWitnessProcessor`, and `WithdrawRewardProcessor`, so the reward checkpoint is always taken prior to any TronPower-affecting state change, rather than only conditionally after the fact.

### Proof of Concept
Note: I could not execute code in this environment; the following is a static-trace PoC based on the cited source.
1. Deploy a contract and freeze balance for BANDWIDTH such that the account has votes cast for a witness and TronPower comfortably exceeds `usedTronPower`.
2. Call the `unfreezeBalance` TVM opcode from the contract to unfreeze a small portion of the frozen balance for BANDWIDTH, such that `accountCapsule.getTronPower() >= usedTronPower * TRX_PRECISION` still holds after the update (partial unfreeze). [6](#0-5) 
3. Observe that `VoteRewardUtil.withdrawReward()` is never invoked for this call because the `if (accountCapsule.getTronPower() < usedTronPower * TRX_PRECISION)` branch is not entered. [7](#0-6) 
4. Compare with issuing the equivalent `UnfreezeBalanceContract` transaction via `UnfreezeBalanceActuator`, where `mortgageService.withdrawReward(ownerAddress)` is called unconditionally regardless of the resulting TronPower/vote relationship. [1](#0-0) 
5. The reward-cycle checkpoint state (`getBeginCycle`/`getEndCycle`/`getAccountVote`) will differ between the two paths for the same logical operation, demonstrating the inconsistency.

  public long execute(UnfreezeBalanceParam param, Repository repo) {
    byte[] ownerAddress = param.getOwnerAddress();
    byte[] receiverAddress = param.getReceiverAddress();

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long unfreezeBalance = 0L;

    if (param.isDelegating()) {
      byte[] key = DelegatedResourceCapsule.createDbKey(ownerAddress, receiverAddress);
      DelegatedResourceCapsule delegatedResourceCapsule = repo.getDelegatedResource(key);

      // reset delegated resource and deduce delegated balance
      switch (param.getResourceType()) {
        case BANDWIDTH:
          unfreezeBalance = delegatedResourceCapsule.getFrozenBalanceForBandwidth();
          delegatedResourceCapsule.setFrozenBalanceForBandwidth(0, 0);
          accountCapsule.addDelegatedFrozenBalanceForBandwidth(-unfreezeBalance);
          break;
        case ENERGY:
          unfreezeBalance = delegatedResourceCapsule.getFrozenBalanceForEnergy();
          delegatedResourceCapsule.setFrozenBalanceForEnergy(0, 0);
          accountCapsule.addDelegatedFrozenBalanceForEnergy(-unfreezeBalance);
          break;
        default:
          //this should never happen
          break;
      }
      repo.updateDelegatedResource(key, delegatedResourceCapsule);

      // take back resource from receiver account
      AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
      if (receiverCapsule != null) {
        switch (param.getResourceType()) {
          case BANDWIDTH:
            receiverCapsule.safeAddAcquiredDelegatedFrozenBalanceForBandwidth(-unfreezeBalance,
                VMConfig.disableJavaLangMath());
            break;
          case ENERGY:
            receiverCapsule.safeAddAcquiredDelegatedFrozenBalanceForEnergy(-unfreezeBalance,
                VMConfig.disableJavaLangMath());
            break;
          default:
            //this should never happen
            break;
        }
        repo.updateAccount(receiverCapsule.createDbKey(), receiverCapsule);
      }

      // increase balance of owner
      accountCapsule.setBalance(oldBalance + unfreezeBalance);
    } else {
      switch (param.getResourceType()) {
        case BANDWIDTH:
          List<Protocol.Account.Frozen> frozenList = Lists.newArrayList();
          frozenList.addAll(accountCapsule.getFrozenList());
          Iterator<Protocol.Account.Frozen> iterator = frozenList.iterator();
          long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
          while (iterator.hasNext()) {
            Protocol.Account.Frozen next = iterator.next();
            if (next.getExpireTime() <= now) {
              unfreezeBalance += next.getFrozenBalance();
              iterator.remove();
            }
          }
          accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
              .setBalance(oldBalance + unfreezeBalance)
              .clearFrozen().addAllFrozen(frozenList).build());
          break;
        case ENERGY:
          unfreezeBalance = accountCapsule.getAccountResource().getFrozenBalanceForEnergy()
              .getFrozenBalance();
          Protocol.Account.AccountResource newAccountResource =
              accountCapsule.getAccountResource().toBuilder()
              .clearFrozenBalanceForEnergy().build();
          accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
              .setBalance(oldBalance + unfreezeBalance)
              .setAccountResource(newAccountResource).build());
          break;
        default:
          //this should never happen
          break;
      }

    }

    // adjust total resource, used to be a bug here
    switch (param.getResourceType()) {
      case BANDWIDTH:
        repo.addTotalNetWeight(-unfreezeBalance / TRX_PRECISION);
        break;
      case ENERGY:
        repo.addTotalEnergyWeight(-unfreezeBalance / TRX_PRECISION);
        break;
      default:
        //this should never happen
        break;
    }

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);

    if (VMConfig.allowTvmVote() && !accountCapsule.getVotesList().isEmpty()) {
      long usedTronPower = 0;
      for (Protocol.Vote vote : accountCapsule.getVotesList()) {
        usedTronPower += vote.getVoteCount();
      }
      if (accountCapsule.getTronPower() < usedTronPower * TRX_PRECISION) {
        VoteRewardUtil.withdrawReward(ownerAddress, repo);
        VotesCapsule votesCapsule = repo.getVotes(ownerAddress);
        accountCapsule = repo.getAccount(ownerAddress);
        if (votesCapsule == null) {
          votesCapsule = new VotesCapsule(ByteString.copyFrom(ownerAddress),
              accountCapsule.getVotesList());
        } else {
          votesCapsule.clearNewVotes();
        }
        accountCapsule.clearVotes();
        repo.updateVotes(ownerAddress, votesCapsule);
        repo.updateAccount(ownerAddress, accountCapsule);
      }
    }
