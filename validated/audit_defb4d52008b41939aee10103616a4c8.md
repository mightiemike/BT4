## Finding

### Title
On-chain Uniswap V3 quoter spot-price used as its own slippage bound enables sandwich-style value extraction during gas-abstraction swaps - (File: `x/uexecutor/keeper/evm.go`)

### Summary
`Keeper.GetSwapQuote` in `x/uexecutor/keeper/evm.go` calls the Uniswap V3 `QuoterV2.quoteExactInputSingle` function on-chain via `CallEVM` to obtain an expected swap output. [1](#0-0) 
This is the same anti-pattern flagged in the external report (Uniswap quoter functions are meant for off-chain simulation, not for driving live on-chain decisions), but the concrete Push Chain impact is not gas exhaustion — it is that the *same* manipulable spot quote is used both as the reference amount and as the basis for slippage protection, so the protection is defeated by design.

### Finding Description
The gas-abstraction inbound flow (`ExecuteInboundGas`) and the payload-with-gas flow (`gasAndPayloadDepositAutoSwap`) both compute `minPCOut` directly from `GetSwapQuote`'s live-pool spot quote: [2](#0-1) [3](#0-2) 

```go
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
```

The same pattern is repeated in the outbound gas refund path, `applyGasRefund`: [4](#0-3) 

In each case, the module:
1. Calls `quoteExactInputSingle` against the live Uniswap V3 pool state at the current block (`k.evmKeeper.CallEVM(ctx, ..., "quoteExactInputSingle", ...)`), and
2. Uses `quote * 95 / 100` as the *only* slippage/minOut protection before executing the real swap via `depositPRC20WithAutoSwap` / `refundUnusedGas`.

Because the quote and the "protective" minimum are both derived from the same spot-price read taken in the same block/transaction that performs the actual swap, an attacker who can move the underlying PRC20/WPC pool price immediately before the module's `DerivedEVMCall` executes (e.g., by submitting an ordinary swap transaction against the same pool that lands just before the validator-triggered inbound/outbound processing tx in the block) causes `GetSwapQuote` to return an already-depressed price. The 5% band computed off that depressed price does not protect the user/protocol — it merely tolerates an additional 5% below an already-manipulated number. The subsequent real swap then executes at (or near) the manipulated price, and the attacker can capture the difference (classic sandwich), while the victim's deposited PRC20 nets a corrupted, lower PC amount than fair value. Because this occurs inside module-originated `DerivedEVMCall` state transitions that finalize `UniversalTx`/`OutboundTx` records, the corrupted amount becomes canonical.

This is reachable purely from unprivileged, honest-validator flow: any user can submit an ordinary EVM transaction to manipulate the pool used for gas-token/PRC20↔WPC conversion (particularly for lower-liquidity token pairs), and any user can trigger a gas-abstraction deposit or cause a gas refund to fire, without needing any privileged, validator, or TSS role.

### Impact Explanation
This corrupts PRC20/native asset accounting and can cause material, unrecoverable loss of user or protocol funds during gas-abstraction deposit swaps and outbound gas refunds, since the "slippage protection" is calculated from the same manipulable value it is meant to bound against. This falls within the in-scope impact of "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting ... or canonical UniversalTx state" and "stealing ... permanent loss ... of user or protocol-controlled funds," triggered purely by ordinary unprivileged transaction submission with honest validators/nodes.

### Likelihood Explanation
Likelihood depends on pool liquidity depth for the specific PRC20/WPC pair and on the attacker's ability to land a manipulating swap in the same or an adjacent block just before the module-triggered swap executes. For thinly-liquid pairs (which is expected for a broad set of whitelisted bridged tokens), this is a low-cost, repeatable sandwich that does not require any privileged role — only capital and a well-timed swap transaction.

### Recommendation
- Do not derive the slippage bound from the same live on-chain quoter call used to price the swap; source an independent reference price (e.g., a TWAP oracle or externally-attested price feed) for computing `minPCOut`.
- Consider bounding deviation between the spot quote and a TWAP/oracle price, rejecting or deferring the auto-swap if they diverge beyond a safe threshold.
- Where feasible, execute swaps optimistically and validate the realized output against an independently sourced fair-value bound rather than trusting a same-block spot quote as ground truth, consistent with the original report's guidance to use oracle-based valuations instead of quoting expected amounts from the AMM being swapped against.

### Proof of Concept
1. Identify a PRC20↔WPC Uniswap V3 pool used by `UniversalCore` for a given `prc20` token (retrieved via `GetUniversalCoreQuoterAddress` / `GetUniversalCoreWPCAddress` / `GetDefaultFeeTierForToken`), with modest liquidity.
2. Attacker submits a large swap against that pool to move the spot price down for PRC20→WPC.
3. Attacker (or accomplice) triggers/awaits a legitimate user's gas-abstraction inbound deposit that lands in the same block window; `ExecuteInboundGas` calls `GetSwapQuote` and reads the manipulated spot price.
4. `minPCOut` is computed as 95% of that already-depressed quote via `execute_inbound_gas.go` lines 142-146.
5. `CallPRC20DepositAutoSwap` executes the real swap; because `minPCOut` was computed off the manipulated price, the swap succeeds while returning far less PC than fair value to the depositor's UEA.
6. Attacker then reverses their initial swap, extracting the value difference; the loss is borne by the depositor and is recorded as canonical, final state in `UniversalTx`. [1](#0-0) [2](#0-1) [5](#0-4)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
