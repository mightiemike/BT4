## Finding: Revert/refund outbound path does not enforce `IsChainOutboundEnabled`

### Summary
`x/uexecutor/keeper/create_outbound.go`'s `BuildOutboundsFromReceipt` explicitly gates normal (non-revert) outbound creation behind `k.uregistryKeeper.IsChainOutboundEnabled(ctx, event.ChainId)` and rejects the outbound if disabled: [1](#0-0) 

By contrast, `x/uexecutor/keeper/build_revert_outbound.go`'s `buildRevertOutbound`, which constructs the `INBOUND_REVERT` outbound sent back to the payload's source chain, performs no such check anywhere in its body — it only looks up token config for gas-fee enrichment and unconditionally returns a `PENDING` outbound targeting `inbound.SourceChain`: [2](#0-1) 

A repo-wide search for `IsChainOutboundEnabled`/`IsOutboundEnabled` usage inside `x/uexecutor/` only turned up the check in `create_outbound.go` (plus test/mocks) — there is no occurrence of this check in `build_revert_outbound.go` or in the caller that invokes it (`msg_server.go`), based on available search results.

### Impact
If outbound is administratively disabled for a source chain (e.g. during an incident, TSS pause, or asset freeze), the standard outbound path correctly blocks new outbound sends to that chain. The revert/refund path, however, appears to still build and enqueue a `PENDING` `INBOUND_REVERT` outbound targeting that same chain, bypassing the intended halt. Because reverts are themselves outbound sends of value back to the source chain, this asymmetry means the "outbound disabled" invariant is not uniformly enforced across all fund-egress paths — an attacker can trigger this by simply submitting a payload guaranteed to fail post-inbound-finalization on a chain that has outbound disabled, forcing a refund/revert outbound to be queued that should have been blocked.

### Caveat
I could not fully trace the caller path in `x/uexecutor/keeper/msg_server.go` that invokes `buildRevertOutbound` within this review to confirm there is no equivalent guard applied *before* calling it (only `grep` presence of the word "revert" in that file was observed, not its content). This should be verified directly against `msg_server.go` to confirm whether an outer guard exists that this analysis missed. Given the clear structural asymmetry between the two outbound-construction functions and the absence of any `IsChainOutboundEnabled`/`IsOutboundEnabled` reference in the revert-building file itself, this is a credible, code-supported gap rather than speculation.

### Recommendation
Add the same `IsChainOutboundEnabled` gate to `buildRevertOutbound` (or to its caller before invocation) so that revert/refund outbounds are blocked or queued for later resumption — rather than executed — when outbound is disabled for the destination (source) chain, matching the enforcement already present in `BuildOutboundsFromReceipt`.

### Proof of Concept (conceptual)
1. Admin/governance disables outbound for chain `eip155:X` (`IsOutboundEnabled = false`) via uregistry config.
2. Attacker submits a normal inbound deposit/payload from `eip155:X` that is accepted (inbound enabled) but is crafted to fail during payload execution after inbound finalization.
3. `buildRevertOutbound` is invoked to construct the `INBOUND_REVERT` outbound targeting `eip155:X`, with no call to `IsChainOutboundEnabled`.
4. The outbound is attached to the UTX as `PENDING`, entering the TSS signing/broadcast pipeline for a chain that was supposed to have outbound sends blocked — contradicting the invariant enforced elsewhere in `BuildOutboundsFromReceipt`.

// buildRevertOutbound creates an INBOUND_REVERT outbound with gas fields populated
// from the UniversalCore contract via getOutboundTxGasAndFees.
func (k Keeper) buildRevertOutbound(sdkCtx sdk.Context, inbound *types.Inbound) *types.OutboundTx {
	recipient := inbound.Sender
	if inbound.RevertInstructions != nil && inbound.RevertInstructions.FundRecipient != "" {
		recipient = inbound.RevertInstructions.FundRecipient
	}

	outbound := &types.OutboundTx{
		DestinationChain:  inbound.SourceChain,
		Recipient:         recipient,
		Amount:            inbound.Amount,
		ExternalAssetAddr: inbound.AssetAddr,
		Sender:            inbound.Sender,
		TxType:            types.TxType_INBOUND_REVERT,
		OutboundStatus:    types.Status_PENDING,
		Id:                types.GetOutboundRevertId(inbound.SourceChain, inbound.TxHash, inbound.LogIndex),
	}

	// Look up the PRC20 address for this external token
	tokenCfg, err := k.uregistryKeeper.GetTokenConfig(sdkCtx, inbound.SourceChain, inbound.AssetAddr)
	if err != nil || tokenCfg.NativeRepresentation == nil || tokenCfg.NativeRepresentation.ContractAddress == "" {
		k.Logger().Warn("failed to get PRC20 for revert outbound gas lookup, proceeding without gas fields",
			"chain", inbound.SourceChain,
			"asset", inbound.AssetAddr,
			"error", err,
		)
		return outbound
	}

	// Fetch gas fields from UniversalCore.getOutboundTxGasAndFees(prc20, 0)
	// 0 means use the contract's baseLimit for this chain
	gasToken, gasFee, gasPrice, gasLimit, err := k.GetGasFeeInfoForRevertOutbound(sdkCtx, tokenCfg.NativeRepresentation.ContractAddress)
	if err != nil {
		k.Logger().Warn("failed to fetch gas fee info for revert outbound, proceeding without gas fields",
			"chain", inbound.SourceChain,
			"prc20", tokenCfg.NativeRepresentation.ContractAddress,
			"error", err,
		)
		return outbound
	}

	outbound.GasToken = gasToken
	outbound.GasFee = gasFee
	outbound.GasPrice = gasPrice
	outbound.GasLimit = gasLimit

	return outbound
}
