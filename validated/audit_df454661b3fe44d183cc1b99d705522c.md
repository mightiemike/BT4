### Title
Bad-debt socialization shrinks `total-assets` without burning shares, inflating the shares/asset ratio toward overflow and DoS on deposit/withdraw - (File: `mainnet/contracts/vault/v0-vault-stx.clar` and equivalent `v0-vault-*.clar` vaults)

### Summary
Each Zest vault (`v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) prices its fungible-token shares (`zft`) against `total-assets` using a plain ratio, exactly like Sentiment's `SuperPool.convertToShares`. When bad debt is socialized after a liquidation with no remaining collateral, the vault writes down `assets` (and the liquidity index) but the outstanding share supply (`ft-get-supply zft`) is left untouched, so the shares-per-asset ratio permanently inflates. Repeated bad-debt events compound this ratio the same way as the referenced Sentiment finding, eventually causing `mul-div-down`/`mul-div-up` in the conversion helpers to abort on overflow (Clarity `uint` is only 128 bits, so this is reached even faster than in Solidity's 256-bit case), blocking deposits and withdrawals.

### Finding Description
The conversion helpers used for every deposit/withdraw path are: [1](#0-0) 

`ts` (total-supply-preview) is the outstanding `zft` share supply and `ta` (total-assets-preview) is computed from the `assets` variable plus accrued interest: [2](#0-1) 

When a liquidation in `market.clar`/`v0-4-market.clar` finds no collateral left on a position, it socializes the remaining scaled debt into the vault via `socialize-debt-asset` → `vault-socialize-debt`: [3](#0-2) [4](#0-3) 

`socialize-debt` in the vault reduces `assets` (and writes down `lindex`) by the bad-debt amount, but it never touches `total-supply` (the `zft` balances held by depositors): [5](#0-4) 

Because `assets` (the numerator input `ta` used by `convert-to-shares-preview`/`convert-to-assets-preview`) shrinks while `zft` supply (`ts`) stays fixed, the `ts/ta` ratio inflates exactly as in the Sentiment `SuperPool` bug: `Total Assets` drops sharply while `Total Shares` stays the same, so `Shares per Token` grows. Each subsequent bad-debt liquidation multiplies this further, since new deposits mint shares at the already-inflated ratio and any subsequent write-down again shrinks `assets` without shrinking `zft` supply. Given Clarity's `uint` is fixed at 128 bits (vs Solidity's 256-bit `uint256` in the original report), the `mul-div-down`/`mul-div-up` calls inside `convert-to-shares-preview`/`convert-to-assets-preview` overflow and abort far sooner, blocking `deposit`/`withdraw`/`get-total-assets` calls that depend on these read-only conversions.

### Impact Explanation
Once the ratio grows large enough, any call that exercises `convert-to-shares`/`convert-to-assets` (deposit, withdraw, and their previews) aborts due to Clarity arithmetic overflow in `mul-div-down`/`mul-div-up`. This permanently locks depositor funds inside the vault (temporary/permanent freezing of funds), matching the in-scope High impact class for freezing of funds, and can also mint disproportionately few shares to depositors as the ratio inflates (loss of unclaimed yield for new depositors), matching the medium/high classes described in the referenced report.

### Likelihood Explanation
This requires a position to be fully liquidated with zero collateral remaining and residual debt (a bad-debt liquidation), which is a normal, permissionless outcome of price volatility and is not gated behind any privileged/DAO action — `liquidate`/`liquidate-multi` are callable by any liquidator and bad-debt socialization triggers automatically when `no-collateral-left` is true. Because Clarity's 128-bit `uint` gives far less headroom than Solidity's 256-bit type used in the referenced Sentiment exploit, fewer bad-debt events are needed to reach overflow, increasing likelihood relative to the original finding.

### Recommendation
When socializing bad debt, burn a proportional amount of outstanding `zft` shares (or otherwise adjust the shares/asset accounting) so the `ts/ta` ratio does not drift upward indefinitely; alternatively, clamp/rescale the ratio used inside `convert-to-shares-preview`/`convert-to-assets-preview` the way the original report recommends (a dynamic adjustment factor) so that repeated bad-debt events cannot push the ratio toward the 128-bit overflow boundary.

### Proof of Concept
1. Vault starts with `assets = A0`, `zft` supply = `S0` (ratio ~1).
2. A borrower opens a position, borrows against the vault, and later becomes undercollateralized with no collateral left after seizure.
3. Liquidator calls `liquidate` in `market.clar`; `no-collateral-left` is `true`, triggering `socialize-debt-asset` → vault's `socialize-debt`, which reduces `assets` (and `lindex`) by the unpaid debt but leaves `zft` `total-supply` unchanged [6](#0-5) .
4. `ts/ta` (i.e., `total-supply-preview / total-assets-preview`) is now inflated; any new deposit computed via `convert-to-shares-preview` mints shares at this inflated ratio [7](#0-6) .
5. Repeat steps 2–3 across additional borrow/bad-debt cycles; each cycle multiplies the ratio further (same compounding pattern as the referenced report's PoC table).
6. After enough cycles, `mul-div-down`/`mul-div-up` inside `convert-to-shares-preview`/`convert-to-assets-preview` (and hence `get-total-assets`, `deposit`, `withdraw`) abort with an arithmetic-overflow error due to Clarity's 128-bit `uint`, freezing further deposits/withdrawals on that vault.

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })
