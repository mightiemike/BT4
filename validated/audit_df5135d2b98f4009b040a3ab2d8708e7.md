### Title
GAS_AND_PAYLOAD CEA execution reports the pre-swap gas-token amount/asset instead of the actual auto-swap output, corrupting the recipient contract's PRC20/native accounting - (File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
`ExecuteInboundGasAndPayload` handles `TxType_GAS_AND_PAYLOAD` inbounds where the recipient is a smart contract (CEA, not a UEA). For this path it first calls `gasAndPayloadDepositAutoSwap`, which swaps the source-chain gas token (PRC20) into native PC via Uniswap V3 and deposits the *swap output* to the recipient (`CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap`). It then calls `CallExecuteUniversalTx` on the recipient contract, but passes `scAmount = utx.InboundTx.Amount` (the original, pre-swap amount denominated in the source gas token) together with `prc20AssetAddr = prc20Addr` (the original gas-token PRC20 address) — not the actual amount/asset that was credited to the contract by the swap.

### Finding Description
In `ExecuteInboundGasAndPayload` (x/uexecutor/keeper/execute_inbound_gas_and_payload.go):
- Deposit leg: `receipt, execErr = k.gasAndPayloadDepositAutoSwap(sdkCtx, prc20AddrHex, ueaAddr, amount)` [1](#0-0)  which ultimately calls `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap(prc20, amount, target, fee, minPCOut, deadline)` [2](#0-1) . This swaps the gas-token PRC20 into native PC subject to a 5%-slippage `minPCOut` floor computed from a quote [3](#0-2) . The real amount (and asset) that ends up at the recipient is therefore the *swap output in native PC*, which can legitimately be anywhere between `minPCOut` and the full quote — not the original `amount` of gas-token PRC20.
- Execution leg for the CEA smart-contract branch: `CallExecuteUniversalTx(cacheCtx, ueaAddr, ..., scAmount, prc20Addr, txId)` is invoked with `scAmount, ok := scAmount.SetString(utx.InboundTx.Amount, 10)` (the untouched original inbound amount) and `prc20Addr` (the original gas-token PRC20 address, not WPC/native PC) [4](#0-3) . `receipt`/the return data from the auto-swap call is never inspected to recover the actual swap output amount; only `receipt.Hash`/`receipt.GasUsed` are used for bookkeeping [5](#0-4) .
- `executeUniversalTx(sourceChain, ceaAddress, payload, amount, prc20AssetAddr, txId)` is the recipient-contract-facing interface the CEA contract uses to reconcile what it was actually paid [6](#0-5) . Because the amount/asset communicated here (`scAmount` of `prc20Addr`) does not correspond to what was actually credited (a swap-derived amount of native PC), any CEA contract logic that trusts this call's `amount`/`prc20AssetAddr` parameters for accounting (e.g. crediting a user balance, releasing goods, or triggering a downstream transfer) will use the wrong asset and the wrong amount.

This is the direct native analog of the Connext `_executePortalTransfer` bug: the external report shows a protocol accounting the *nominal/requested* value of a variable-output operation (Aave `withdraw`) instead of the *actual* value returned by that operation, creating an internal accounting/asset mismatch. Here, Push Chain performs a variable-output operation (a Uniswap V3 swap with slippage tolerance) and then forwards the pre-swap nominal amount/asset — not the swap's actual output — into the module-originated `executeUniversalTx` call that a smart-contract recipient relies on for its own accounting.

Note: the exact same pattern (`gasAndPayloadDepositAutoSwap` output not reconciled with what is subsequently reported) appears in the UEA-recipient branch too — `ExecutePayloadV2`/UEA execution presumably reads live PRC20/PC balances rather than trusting a passed amount, but the *smart-contract CEA path* explicitly forwards a mismatched `amount`/`prc20AssetAddr` pair through a keeper-to-contract call, which is the concretely exploitable, code-verifiable divergence.

### Impact Explanation
For `TxType_GAS_AND_PAYLOAD` inbounds where `IsCEA=true` and the recipient is a deployed smart contract (not a UEA), the contract's `executeUniversalTx` is told it received `inbound.Amount` of the *source gas-token PRC20*, while what was actually deposited to it is a (slippage-bounded, price-dependent) amount of *native PC* from the auto-swap. Any recipient contract logic that credits balances, triggers refunds/transfers, or performs any accounting keyed off `amount`/`prc20AssetAddr` in `executeUniversalTx` will operate on incorrect values and the wrong asset identity — this corrupts PRC20/native asset accounting for the affected UniversalTx and can cause the contract to over- or under-credit value relative to what it actually holds. This matches the "corruption of PRC20 or native asset accounting… token mapping… canonical UniversalTx state" and "unauthorized module-originated EVM execution" impact categories.

### Likelihood Explanation
The path is reachable by any unprivileged user simply by sending a GAS-type inbound (fee-abstraction top-up) with `IsCEA=true` targeting a deployed smart contract address as recipient — no privileged actor, validator collusion, or admin action is required beyond the normal honest-validator quorum voting on the (attacker-chosen) inbound parameters (source chain, amount, recipient). The mismatch is deterministic whenever the swap output differs from the nominal input amount, which is essentially always true for any nonzero-fee/nonzero-slippage swap (only requires the swap to succeed above `minPCOut`, which is the common case).

### Recommendation
Capture the actual amount and asset that the recipient contract receives from `depositPRC20WithAutoSwap` (e.g., by decoding the swap output amount from the transaction's `Transfer`/`Deposit` event logs in `receipt.Logs`, similarly to how `BuildOutboundsFromReceipt` decodes gateway events) and pass that actual amount together with the correct output asset address (native PC / WPC, not the source gas-token PRC20) into `CallExecuteUniversalTx`. If the actual output cannot be reliably determined, prefer failing/reverting the CEA execution rather than forwarding a nominal, pre-swap value that misrepresents what the contract actually received.

### Proof of Concept
1. Attacker (or any user) submits a `GAS_AND_PAYLOAD` inbound event on a source chain with `IsCEA=true`, `Recipient` = the address of a deployed smart contract `C` (not a UEA) that implements `executeUniversalTx` and uses its `amount`/`prc20AssetAddr` parameters to credit an internal ledger or trigger a downstream action, `AssetAddr` = a supported gas token, `Amount` = X.
2. Honest Universal Validators reach quorum and vote the inbound in via `MsgVoteInbound`; `ExecuteInboundGasAndPayload` runs.
3. `gasAndPayloadDepositAutoSwap` swaps the gas-token PRC20 amount X into native PC via `depositPRC20WithAutoSwap`, depositing the swap output `Y` (bounded only by `minPCOut = 0.95 * quote`, i.e. `Y` can be materially less than X in token-value terms, and is a different asset — native PC, not the gas-token PRC20).
4. `CallExecuteUniversalTx` is then invoked on contract `C` with `amount = X` and `prc20AssetAddr` = the original gas token address, not `Y` / native PC.
5. Contract `C`'s accounting logic (which trusts the `executeUniversalTx` call's reported `amount`/`prc20AssetAddr`) credits/acts on `X` of the gas-token PRC20 even though it actually received `Y` of native PC — producing an internal PRC20/native accounting mismatch analogous to the Aave over-accounting bug in the Connext report.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// CallExecuteUniversalTx calls executeUniversalTx on a smart-contract recipient.
// This is used for isCEA inbounds whose recipient is a deployed contract (not a UEA).
func (k Keeper) CallExecuteUniversalTx(
	ctx sdk.Context,
	recipientAddr common.Address,
	sourceChain string,
	ceaAddress []byte,
	payload []byte,
	amount *big.Int,
	prc20AssetAddr common.Address,
	txId [32]byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	recipientABI, err := types.ParseRecipientContractABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse recipient contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		recipientABI,
		ueModuleAccAddress,
		recipientAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"executeUniversalTx",
		sourceChain,
		ceaAddress,
		payload,
		amount,
		prc20AssetAddr,
		txId,
	)
}
