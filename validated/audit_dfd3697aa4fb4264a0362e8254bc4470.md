### Title
Unbounded per-request base58Check/SHA256 encoding cost in `GetDelegatedResourceAccountIndexServlet` via attacker-inflatable `fromAccounts`/`toAccounts` prefix scan - (File: `framework/src/main/java/org/tron/core/services/http/GetDelegatedResourceAccountIndexServlet.java`)

### Summary
`GetDelegatedResourceAccountIndexServlet` returns a `DelegatedResourceAccountIndex` whose `fromAccounts`/`toAccounts` lists are rebuilt by an unbounded RocksDB prefix scan keyed by an attacker's own address, then every address in that list is base58Check-encoded (double SHA256) during JSON formatting. An unprivileged funded account can grow this list arbitrarily by issuing many cheap `DelegateResourceContract` transactions to distinct receiver addresses, then repeatedly hit the read-only endpoint to force CPU-heavy encoding work proportional to the attacker's historical activity.

### Finding Description
`GetDelegatedResourceAccountIndexServlet.fillResponse` calls `wallet.getDelegatedResourceAccountIndex(address)` [1](#0-0) , which delegates to `DelegatedResourceAccountIndexStore.getIndex(address)` [2](#0-1) .

`getIndex` first looks for a legacy single record; when the "delegate optimization" storage model is active (post `convert()`), that legacy record no longer exists, so it falls back to `getWithPrefix(FROM_PREFIX, TO_PREFIX, address)`, which performs an unbounded `prefixQuery` scan over all `(FROM_PREFIX|address|receiver)` and `(TO_PREFIX|address|sender)` keys and rebuilds the full `fromAccounts`/`toAccounts` lists from however many delegate/undelegate pairs exist for that address [3](#0-2) . Each delegate/undelegate pair is stored under a unique key (`delegate`/`delegateV2`), so the list size grows linearly and permanently with the number of distinct receiver addresses the attacker has ever delegated to [4](#0-3) .

The resulting `DelegatedResourceAccountIndex.fromAccounts`/`toAccounts` fields are registered in `HttpSelfFormatFieldName.AddressFieldNameMap` [5](#0-4) , so `JsonFormat.printToString(reply, visible)` with `selfType=true` calls `escapeBytesSelfType` for every repeated address entry, and `escapeBytesSelfType` calls `StringUtil.encode58Check(input.toByteArray())` (base58Check = double SHA256 + base58 encode) for each one [6](#0-5) .

`RateLimiterServlet` only throttles requests-per-second (QPS/global token bucket); it has no concept of per-request work cost, so it cannot mitigate a single expensive request whose cost is proportional to N historical delegations [7](#0-6) .

### Impact Explanation
Each GET/POST to `/wallet/getdelegatedresourceaccountindex` (and its solidity/PBFT variants) for an attacker-controlled address triggers: (1) an unbounded RocksDB prefix scan, and (2) O(N) base58Check computations (SHA256 x2 + base58 per address) where N is fully attacker-controlled and grows without bound over time. This is a DoS via RPC-API: CPU consumption per request scales with historical attacker activity rather than being bounded, allowing a modest number of cheap repeated GETs to consume disproportionate CPU on the shared HTTP thread pool, degrading service for other API consumers.

### Likelihood Explanation
Precondition: attacker is an ordinary funded account (no special privilege) that broadcasts N `DelegateResourceContract` transactions from one owner address to N distinct receiver addresses — normal, permitted account operations subject to only standard bandwidth/energy fees. Because these transactions are individually cheap and there is no cap on the number of distinct delegation targets recorded against one account, an attacker can incrementally build up a large N over time (this cost is a one-time investment; the resulting DoS amplification is reusable indefinitely via repeated free/cheap GET requests). This is fully reachable without any privileged role, matching the "unprivileged attacker" threat model.

### Recommendation
- Cap the number of distinct `fromAccounts`/`toAccounts` entries returned/serialized per response (pagination), or bound the underlying `prefixQuery` scan with a hard limit.
- Consider avoiding full base58Check re-encoding of every entry on each request; cache/precompute encoded values, or make `escapeBytesSelfType` cheaper for bulk repeated fields.
- Add per-request cost-based rate limiting (e.g., weight requests by response size / list length) in addition to plain QPS limiting in `RateLimiterServlet`.

```java
@Test
public void testUnboundedDelegatedResourceAccountIndexGrowth() {
  byte[] owner = ECKey.random().getAddress();
  // simulate attacker having previously delegated to N distinct receivers
  int N = 50_000;
  for (int i = 0; i < N; i++) {
    byte[] receiver = new ECKey(Utils.getRandom()).getAddress();
    delegatedResourceAccountIndexStore.delegate(owner, receiver, i + 1L);
  }

  long start = System.nanoTime();
  DelegatedResourceAccountIndexCapsule idx =
      delegatedResourceAccountIndexStore.getIndex(owner); // unbounded prefixQuery
  Protocol.DelegatedResourceAccountIndex reply = idx.getInstance();
  String json = JsonFormat.printToString(reply, true); // selfType=true -> N x encode58Check
  long elapsed = System.nanoTime() - start;

  Assert.assertEquals(N, reply.getToAccountsCount());
  // elapsed grows ~linearly with N, demonstrating unbounded per-request cost
}
```

```java
  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }
```
