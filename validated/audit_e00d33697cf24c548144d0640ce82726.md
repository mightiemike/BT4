### Title
UEA Factory proxy deployed at genesis without calling `initialize`, leaving `Ownable` owner unset and front-runnable - (File: `x/uexecutor/keeper/genesis.go`)

### Summary
`x/uexecutor`'s `InitGenesis` deploys the UEA Factory as a transparent upgradeable proxy (`deployFactoryEA` → `deployFactoryProxy` / `deployFactoryImplContract` / `deployProxyAdminContract`) by writing raw EVM state directly (bytecode + EIP-1967 admin/implementation slots), but it never issues an EVM call to the Factory's own `initialize(address initialOwner)` method. Test harnesses (`test/utils/contracts_setup.go`) explicitly call `CallEVM(..., "initialize", owner)` after deployment to set the `Ownable` owner — a step that is absent from the real genesis path in `x/uexecutor/keeper/keeper.go` `InitGenesis` / `x/uexecutor/keeper/genesis.go`.

### Finding Description
`deployFactoryEA` (`x/uexecutor/keeper/genesis.go:100-109`) performs three raw state writes:
- `deployFactoryImplContract` — sets code at `FACTORY_IMPL_ADDRESS_HEX`.
- `deployProxyAdminContract` — sets code at `PROXY_ADMIN_ADDRESS_HEX` and explicitly writes storage slot 0 (`Ownable.owner`) to `PROXY_ADMIN_OWNER_ADDRESS_HEX` — this contract's owner IS initialized.
- `deployFactoryProxy` — sets code at `FACTORY_PROXY_ADDRESS_HEX` and writes only the EIP-1967 `PROXY_ADMIN_SLOT` and `PROXY_IMPLEMENTATION_SLOT`.

Critically, the Factory implementation's `initialize(address initialOwner)` (selector `0xc4d66de8`, visible in `FactoryImplRuntimeBytecode`, `x/uexecutor/types/constants.go`) is never invoked through the proxy during genesis. The upgradeable-`Ownable` pattern used by OpenZeppelin-style contracts guards `initialize` with an `initializer` modifier that only checks "has this proxy's initializer already run," not "who is calling this." Because genesis never calls `initialize`, the Factory proxy starts life at Push Chain genesis with `owner() == address(0)` and its initializer flag unset.

This is called out explicitly in `x/uexecutor/README.md`:
> "On fresh genesis (`Exported=false`) it deploys the **UEA factory** contract."

but the actual deploy code only writes bytecode/storage slots, and unlike `test/utils/contracts_setup.go`'s `setupFactoryContract` (which does call `"initialize"` with a designated owner right after deployment in the test harness), there is no equivalent call in the production `InitGenesis` path.

### Impact Explanation
If the Factory proxy's `initialize` is never called by anyone with a privileged first-mover advantage, the very first unprivileged account to submit an EVM transaction calling `initialize(myAddress)` against the Factory proxy address (`0x00000000000000000000000000000000000000eA`) becomes the permanent `Ownable` owner of the UEA Factory. Depending on what the Factory's owner-gated functions control (per `x/uexecutor/types/abi.go`, at least `setUEAProxyImplementation` and factory administrative functions), an attacker owning the Factory could:
- Point `setUEAProxyImplementation` at a malicious UEA proxy implementation, corrupting the deterministic-address/UEA deployment flow used by every future `MsgDeployUEA` / inbound-triggered UEA deployment.
- Potentially perform unauthorized module-originated EVM execution/state manipulation of a core universal-execution primitive (the Factory that mints every user's UEA), which falls squarely in the "unauthorized UEA/CEA execution, unauthorized module-originated EVM execution" impact class.

This is a first-block/genesis race: whichever node validator or user gets the earliest transaction executed against the live chain can claim ownership, with no authentication tying that claim to the intended chain operator.

### Likelihood Explanation
High, if genesis truly never initializes the Factory — this is a straightforward "first tx wins" race requiring no privileged access, only mempool/tx-ordering luck at chain launch (or any point in the future before it's noticed and fixed, since nothing else calls `initialize`). I was not able to fully confirm from the available code index whether some other component (chain start-up script, an `x/upgrade` handler, or a first-block-only privileged transaction) calls `initialize` outside of the Go keeper code — the search only found `initialize` calls in test/integration code (`test/utils/contracts_setup.go`, `test/integration/uexecutor/execute_payload_test.go`, `x/uexecutor/keeper/msg_server_test.go`), never in a non-test production code path such as `InitGenesis`, `BeginBlock`, or a CLI/migration handler. This uncertainty should be verified against a full checkout before treating this as a confirmed live bug — the indexed code may be incomplete.

### Recommendation
- In `x/uexecutor/keeper/genesis.go` `deployFactoryEA` (called from `InitGenesis` in `x/uexecutor/keeper/keeper.go`), after deploying the Factory proxy/impl/admin, issue a `DerivedEVMCall`/`CallEVM` to `FACTORY_PROXY_ADDRESS_HEX.initialize(intended_owner)` using a well-defined, hardcoded/genesis-config-controlled owner address (mirroring how `PROXY_ADMIN_OWNER_ADDRESS_HEX` is deterministically set for the `ProxyAdmin` contract), rather than leaving the Factory owner unset.
- Alternatively, if an EOA/multisig owner is intended, bake `initialize` into the same genesis path with the designated owner constant, and add a genesis-state invariant check (similar to `TestDeploySystemContracts_ReportEveryProxyAdminOwner` in `x/uregistry`) asserting that `Factory.owner() != address(0)` immediately after genesis deployment.
- Add a regression test analogous to `x/uregistry/keeper/genesis_internal_test.go`'s `TestDeploySystemContracts_DeploysFullTripleForEveryReservedAddress` but for `x/uexecutor`'s `deployFactoryEA`, asserting the Factory's `owner` storage is non-zero and matches the expected value right after `InitGenesis`.

### Proof of Concept
1. Start a fresh Push Chain node from genesis with `x/uexecutor` genesis `Exported=false`, triggering `deployFactoryEA`.
2. Immediately after genesis (before any operator transaction initializes the Factory), submit, as any unprivileged account, an EVM transaction:
   `Factory(0x00000000000000000000000000000000000000eA).initialize(attacker_address)`
3. If the transaction succeeds (which it will if `initialize` was never called during genesis and the initializer guard is only "has-run-once," not access-controlled), query `Factory.owner()` and observe it now returns `attacker_address`.
4. From this point, the attacker calls `Factory.setUEAProxyImplementation(malicious_impl)` (or other owner-only Factory functions) to control future UEA deployments/implementation logic. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

func deployFactoryEA(ctx context.Context, evmKeeper types.EVMKeeper) {
	// Deploy the factory implementation contract
	deployFactoryImplContract(ctx, evmKeeper)

	// Deploy the proxy admin contract
	deployProxyAdminContract(ctx, evmKeeper)

	// Deploy the factory proxy contract
	deployFactoryProxy(ctx, evmKeeper)
}

// InitGenesis initializes the module's state from a genesis state.
func (k *Keeper) InitGenesis(ctx context.Context, data *types.GenesisState) error {

	if err := data.Params.ValidateBasic(); err != nil {
		return err
	}

	// Only deploy factory contracts on fresh genesis, not on import from export.
	// Re-deploying on import would overwrite existing EVM state or cause nonce collisions.
	if !data.Exported {
		deployFactoryEA(ctx, k.evmKeeper)
	}

func setupFactoryContract(
	t *testing.T,
	app *app.ChainApp,
	ctx sdk.Context,
	factoryABI abi.ABI,
	opts AppSetupOptions,
	accounts TestAccounts,
) error {
	factoryAddr := opts.Addresses.FactoryAddr
	owner := common.BytesToAddress(accounts.DefaultAccount.GetAddress().Bytes())

	// Check initial factory owner
	ownerResult, err := app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after genesis: %s", common.BytesToAddress(ownerResult.Ret).Hex())

	// Initialize factory with owner
	_, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "initialize", owner)
	require.NoError(t, err)

	// Verify owner is set
	ownerResult, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after initialization: %s", common.BytesToAddress(ownerResult.Ret).Hex())
