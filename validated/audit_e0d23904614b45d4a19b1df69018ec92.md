## Analysis: Excess gas-fee refund can be silently and permanently lost with no escalation path

Push Chain's `x/uexecutor` module implements an equivalent "leftover balance owed back to a party" flow to keep-tecdsa's `subsidyPool`: the **excess outbound gas fee** (`gasFee - gasFeeUsed`) that must be returned to the sender/fund-recipient once Universal Validators observe the destination-chain execution. Tracing this path surfaces the same failure class as the original report — a value that is supposed to be returned to a party is silently dropped when the return call fails, with no tracking or retry mechanism, unlike the sibling "revert" path in the same file which *does* escalate on failure.

### Title
Excess gas fee refund is silently and permanently lost on double refund failure, with no retry or operator escalation, unlike the sibling funds-revert path - (File: x/uexecutor/keeper/outbound.go)

### Summary
`applyGasRefund` computes `refundAmount = gasFee - gasFeeUsed` and attempts to return it to the user via `UniversalCore.refundUnusedGas`, first with a Uniswap swap, then falling back to a raw PRC20 deposit. If **both** attempts fail, the function only records `refundPcTx.Status = "FAILED"` on the outbound and returns — the outbound is still marked `OBSERVED`/`REVERTED` and the UTX processing completes normally. There is no retry queue, no re-attempt hook, and — critically — no call to `AbortOutbound` to flag the record for manual intervention, unlike the structurally identical "re-mint on revert failure" branch a few lines above it in the same file, which does call `k.AbortOutbound(...)` specifically to force manual operator follow-up.

### Finding Description [1](#0-0) 
On revert-fund re-mint failure, the code explicitly aborts and demands manual intervention:
```go
if err != nil {
    ...
    return k.AbortOutbound(ctx, utxId, outbound,
        fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
}
``` [2](#0-1) 
But the gas-refund fallback path treats an identical failure mode as a terminal, silent no-op:
```go
resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
if err != nil {
    refundPcTx.Status = "FAILED"
    refundPcTx.ErrorMsg = err.Error()
} else {
    ...
}
outbound.PcRefundExecution = refundPcTx
outbound.RefundSwapError = swapFallbackReason
```
The function returns normally, `handleSuccessfulOutbound`/`handleFailedOutbound` proceed to `k.UpdateOutbound(...)` and the outbound is finalized as `OBSERVED`/`REVERTED` — a terminal state with no code path anywhere in the module that re-attempts `CallUniversalCoreRefundUnusedGas` for a `PcRefundExecution.Status == "FAILED"` record. The excess `refundAmount` (already collected from the user as part of the outbound's `gasFee` at outbound-creation time via the `UniversalGatewayPC`/`UniversalCore` contracts) is now permanently unaccounted for on Push Chain's side: it is neither returned to the user nor flagged for governance/operator remediation, exactly mirroring how `subsidyPool` value could be silently stranded in `BondedECDSAKeepFactory` when the tracked pool and actual contract balance diverged after a failed distribution attempt.

### Impact Explanation
Falls under "permanent loss ... of user or protocol-controlled funds" in the allowed impact gate: an ordinary user who overpays outbound gas fee (a normal, expected, unprivileged flow — `gasFee` is fixed at outbound-creation time before the actual destination gas usage is known) has no way to recover the excess if both refund legs fail, and no alerting mechanism exists to tell an operator that a manual recovery is needed (contrast with the revert-mint path, which is designed precisely for this purpose).

### Likelihood Explanation
Both refund legs failing simultaneously is not attacker-privileged: the swap leg can fail organically (Uniswap `quoteExactInputSingle`/slippage revert on a thinly-traded `gasToken`, which any user routing through such a token triggers merely by using it), and the fallback leg can fail due to ordinary EVM-call failure modes (e.g., transient nonce/state issues from `DerivedEVMCall`, `UniversalCore` contract-level reverts on the deposit call). No malicious peer, validator, or privileged actor is required — an unprivileged user who selects an illiquid/short-listed `gasToken` for their outbound is enough to reach this state under normal honest-validator operation.

### Recommendation
On the `Step 2` failure branch in `applyGasRefund`, treat the failure the same way `handleFailedOutbound`'s re-mint failure is treated: call `k.AbortOutbound(...)` (or an equivalent explicit "refund pending manual resolution" status/flag) instead of silently finalizing the outbound as `OBSERVED`/`REVERTED` with only a `PcRefundExecution.Status == "FAILED"` breadcrumb. At minimum, add a retryable/queryable index (analogous to `PendingOutbounds`) for outbounds whose gas refund failed, so operators/governance can reconcile and manually re-issue the refund instead of the value being tracked nowhere and effectively burned.

### Proof of Concept
1. A user submits an inbound/outbound flow specifying an illiquid or freshly-listed PRC20 `gasToken` for relayer-fee payment, with `gasFee` set higher than the eventual `gasFeeUsed` reported by honest UVs.
2. UVs vote the outbound as `OBSERVED` with `gasFeeUsed < gasFee` via `MsgVoteOutbound`, honestly reporting actual consumption.
3. `applyGasRefund` computes a positive `refundAmount`. `GetDefaultFeeTierForToken`/`getSwapQuoteForRefund` fail or the swap-refund call reverts (common for illiquid pairs) → `swapFallbackReason` set.
4. The fallback `CallUniversalCoreRefundUnusedGas(..., withSwap=false, ...)` also fails (e.g., due to a transient `DerivedEVMCall` failure or `UniversalCore` contract-side revert).
5. `refundPcTx.Status = "FAILED"` is recorded, `outbound.PcRefundExecution`/`outbound.RefundSwapError` are set, but `k.UpdateOutbound` still finalizes the outbound as `OBSERVED`/`REVERTED`. No abort, no retry, no operator alert — `refundAmount` is now unrecoverable through any code path in `x/uexecutor`.
