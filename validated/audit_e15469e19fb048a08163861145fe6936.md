### Title
Cached deprecated (Cairo 0) contract classes remain executable after being undeclared, bypassing the declaration check performed for Cairo 1 classes - (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-validates that a Cairo 1 class returned from the process-local class cache is still declared in the current state before serving it, but explicitly skips this validation for Cairo 0 (`RunnableCompiledClass::V0`) classes, based on the invariant that `is_declared` "always return[s] false" for Cairo 0. If a class hash's declaration is later removed from state (e.g. via block revert) while the compiled class remains resident in the shared, long-lived `ContractClassManager` cache, any subsequent transaction referencing that class hash (deploy, `replace_class`, `library_call`) will still be served the stale cached bytecode with no re-check against current state, unlike the Cairo 1 path.

### Finding Description
`get_compiled_from_class_manager` implements the cache-hit path used by the gateway, batcher and OS-view readers: [1](#0-0) 

For a cache hit, the code branches on the runnable class kind:
- `RunnableCompiledClass::V0(_) => {}` — no validation at all.
- Any other variant (Cairo 1 / Cairo 1 Native) — calls `self.state_reader.is_declared(class_hash)?` and returns `StateError::UndeclaredClassHash` if the class is no longer declared, explicitly because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)".

The reason V0 is exempted is that `FetchCompiledClasses::is_declared` is documented and implemented to only ever answer for Cairo 1 declarations: [2](#0-1) [3](#0-2) 

`is_declared` reads only `get_class_definition_block_number`, i.e. the Cairo 1 declared-classes table, and structurally cannot detect whether a Cairo 0 (deprecated) class declaration was reverted. Consequently, `get_compiled_from_class_manager` has no mechanism to detect and reject a cached V0 class whose declaration was removed from the canonical state (e.g. by the node's supported block-revert feature, `revert_config`), while the identical scenario for Cairo 1 classes is explicitly guarded against.

The `ContractClassManager` (backed by `GlobalContractCache`/`NativeClassManager`) is a shared, process-wide, long-lived cache reused across blocks by the gateway (`stateful_transaction_validator.rs`), the batcher's block builder (`block_builder.rs`), and view calls (`batcher.rs`'s `ViewStateReaderFactory`) — it is never invalidated on state revert: [4](#0-3) [5](#0-4) 

### Impact Explanation
If a node ever reverts blocks that removed a Cairo 0 class declaration (a legitimate, supported node operation via `revert_config`), any node whose in-memory `ContractClassManager` still holds that class from before the revert will continue to serve it as executable for any subsequent transaction that deploys a contract with, or otherwise references, that class hash — even though the class is, per current canonical state, undeclared. A freshly-synced or restarted node (empty cache) would instead correctly reject the transaction with `StateError::UndeclaredClassHash`. This creates a state-execution divergence between honest nodes that had the class cached versus nodes that did not (e.g. a node that restarted, or a node that never had the class cached, versus one that has been running continuously since before the revert), which can lead to disagreement on transaction validity/outcome and hence on the computed state root — an honest-node divergence as specified in scope.

### Likelihood Explanation
Likelihood is limited by the precondition that a block revert must have actually un-declared a Cairo 0 class and that at least one node kept the stale compiled class cached in memory while at least one other did not (varying cache contents/restart timing across the network). Revert is an intentional, supported node capability (`revert_config.should_revert` / `revert_up_to_and_including`), not a hypothetical attacker action; once triggered, exploitation only requires an ordinary, unprivileged transaction referencing the old class hash. This is a real code-path gap (explicitly acknowledged and defended against for Cairo 1, but not for Cairo 0), though it depends on an operational revert event rather than being triggerable purely by a malicious transaction sender in normal operation.

### Recommendation
Extend `is_declared` (or add a parallel check reachable from `get_compiled_from_class_manager`) to also validate Cairo 0/deprecated class declarations against current state (e.g. by checking the deprecated-declared-classes table's block number the same way Cairo 1 declarations are checked), and apply the same re-validation to the `RunnableCompiledClass::V0(_)` branch in `get_compiled_from_class_manager` instead of unconditionally trusting the cache. Alternatively, invalidate/clear the shared `ContractClassManager` cache entries for any class hash affected by a block revert as part of the revert procedure.

### Proof of Concept
1. Declare and use a Cairo 0 class `C` via a normal transaction; a node's `ContractClassManager` cache populates `CompiledClasses::V0(...)` for `C`'s class hash (`get_compiled_from_class_manager`, cache-miss path, `crates/blockifier/src/state/state_reader_and_contract_manager.rs:88-103`).
2. Trigger (or the node performs) a supported block revert that rolls back the block declaring `C`, removing its entry from `deprecated_declared_classes` in storage (`revert_config`).
3. Submit a new, ordinary transaction (e.g. `deploy` or `library_call`) referencing class hash `C` to the same node.
4. `get_compiled_from_class_manager` hits the cache, matches `RunnableCompiledClass::V0(_) => {}`, performs no declaration check, and returns the stale compiled class — the transaction executes successfully using code that, per current state, is undeclared.
5. A second node whose cache does not contain `C` (fresh restart) instead calls `get_compiled_classes` → `ApolloReader::get_compiled_class_from_db`, finds no declaration, and returns `StateError::UndeclaredClassHash`, rejecting the same transaction — demonstrating divergence between the two honest nodes.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
