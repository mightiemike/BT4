## Finding

### Title
Instantaneous (non-TWAP) Uniswap V3 spot-price quote used to compute `minPCOut` in PRC20 auto-swap deposit and gas-refund flows enables sandwich/price-manipulation value extraction from the protocol swap pool - ([File: x/uexecutor/keeper/evm.go])

### Summary
The external report flags that `TapOracle`'s Uniswap V3 TWAP window (600s) is too short to resist price manipulation. Push Chain's `x/uexecutor` module has an analogous — and structurally weaker — pattern: it does not use a TWAP at all. `GetSwapQuote` calls Uniswap V3 `QuoterV2.quoteExactInputSingle` for the *current instantaneous spot price* of the pool, and that same spot quote is used to derive the slippage floor (`minPCOut = quote * 95/100`) that is then passed into the actual swap executed later in the same flow.

### Finding Description
`GetSwapQuote` reads a live, single-block spot price from the configured Uniswap V3 pool with no time-weighting whatsoever: [1](#0-0) 

This quote is used to compute a 5% slippage-bound `minPCOut` for two attacker-reachable, unprivileged flows:

1. **GAS / GAS_AND_PAYLOAD inbound deposit auto-swap** — triggered whenever *any* user bridges a gas-fee-abstraction inbound. The quote and the swap execution both happen inside the same keeper call chain, but the inbound itself sits in a multi-block finalization window (2/3 UV votes) before it executes, giving an attacker a predictable window to move the pool price beforehand: [2](#0-1) 

2. **Excess gas-fee refund swap on successful/failed outbound** — triggered automatically whenever `gasFee > gasFeeUsed` after any outbound completes, again quoting spot price and using it both for the swap-out amount and the caller-supplied floor: [3](#0-2) 

Because `minPCOut` is derived from the *same* instantaneous price that is manipulated, it provides no real protection — the floor moves with the manipulated price rather than anchoring to a manipulation-resistant reference (unlike even a 10-minute TWAP, which the external report already deems insufficient). Both flows are reachable purely by an ordinary unprivileged user submitting standard gas-abstraction inbounds/outbounds; no relayer, validator, or admin action is required to trigger the vulnerable code path — only to trigger the price movement on the pool itself, which any account can do by trading against it.

This is a native analog of the TWAP-duration bug class: absence (not just shortness) of a time-weighted price mechanism for a value computation that gates fund movement (PRC20 → PC swap amounts, and refund swap amounts) out of protocol-controlled liquidity.

### Impact Explanation
An attacker who can move the price of the relevant Uniswap V3 pool (trivial in low-liquidity pools, e.g. new PRC20/WPC pairs at launch) can:
- Depress/pump the spot price immediately before their own gas-deposit auto-swap or refund-swap executes, causing the swap to execute against a manipulated price and extract more PC than a fair execution would yield, at the expense of the pool's liquidity providers / protocol reserves.
- Since `minPCOut` is computed from the manipulated quote itself, it cannot prevent this — the "protection" is circular.

This falls under "corruption of PRC20 or native asset accounting ... refund accounting" and "unauthorized ... unauthorized release ... of protocol-controlled funds" in the allowed impact gate, reachable via ordinary user deposit/outbound flows with no privileged actor involved.

### Likelihood Explanation
Likelihood is low-to-medium, mirroring the external report's own characterization: it requires thin liquidity (most likely at protocol launch or for newly whitelisted gas tokens) and capital risk for the attacker (holding a manipulated position across the multi-block inbound-finalization window, exposed to arbitrage). It does not require a malicious validator, relayer, or admin — only an unprivileged trader interacting with the pool and the standard gas-abstraction bridging flow.

### Recommendation
Replace the instantaneous `quoteExactInputSingle` spot read with a manipulation-resistant reference (e.g., a Uniswap V3 TWAP over ≥30 minutes, or an independent oracle) for computing both the deposit auto-swap `minPCOut` and the gas-refund swap `minPCOut`. At minimum, do not derive the slippage floor from the same spot price being protected against; use a separately-sourced reference price with a fixed maximum deviation check, and consider requiring minimum pool liquidity/depth checks before allowing auto-swap paths to execute at all.

### Proof of Concept
1. Push Chain (or a partner) lists a new gas-token PRC20 with a freshly seeded, thin-liquidity Uniswap V3 pool against WPC.
2. Attacker bridges a GAS-type inbound through the gateway with a sizeable gas-token amount; the inbound enters `PendingInbounds` awaiting UV quorum (multi-block).
3. While the inbound is pending, the attacker trades heavily against the PRC20/WPC pool on Push Chain's EVM to skew the spot price favorably (raising the PRC20→WPC exchange rate).
4. Once UV quorum finalizes the inbound, `ExecuteInboundGas` calls `GetSwapQuote` → `GetSwapQuote` reads the manipulated spot price → `CallPRC20DepositAutoSwap` executes at (or near) that price, crediting the attacker's UEA with an inflated PC amount relative to fair value [4](#0-3) .
5. Attacker reverses their manipulating trade and/or arbitrageurs correct the pool, but the excess PC already credited to the attacker's UEA constitutes value extracted from the pool/protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
