### Title
App Proxy HMAC signature verification uses delimiter-less query-string concatenation, allowing parameter-boundary collisions to forge valid signatures - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
The `stringifyQueryForAppProxy` function builds the message that is HMAC-signed/verified for Shopify App Proxy requests by concatenating `key=value` pairs (sorted by key) with **no separator character between pairs**. Because the signed message is a non-injective serialization of the query parameters (the same string of bytes can be produced by more than one distinct parameter set), an attacker who controls arbitrary query parameter names/values on the app-proxy request can shift the "key/value" boundary and still produce a byte-identical signing input, causing `validateHmac(..., {signator: 'appProxy'})` to accept a forged or tampered parameter set as if it were the legitimately Shopify-signed one. This is conceptually the same bug class as the H-02 report: a supposedly unique/authoritative value (a `msg.sig` selector there, an HMAC signing message here) is derived through a lossy/ambiguous transformation, letting an attacker craft different inputs that collide onto the same authorization-critical value.

### Finding Description
`generateLocalHmac` picks the signing algorithm based on `signator`: [1](#0-0) 

For `signator === 'appProxy'`, the message is built by `stringifyQueryForAppProxy`, which sorts entries by key and simply appends `key=value` with **no `&`, `\n`, or any other delimiter** between pairs: [2](#0-1) 

This exact ambiguity is even demonstrated (unintentionally) by the project's own test fixtures, which construct the signing string by literal concatenation without delimiters: [3](#0-2) [4](#0-3) 

Because the concatenation has no delimiter, two different parameter dictionaries can serialize to the same string. For example:
- `{a: "1", ab: "2"}` sorted → `"a=1" + "ab=2"` = `"a=1ab=2"`
- `{a: "1a", b: "2"}` sorted → `"a=1a" + "b=2"` = `"a=1ab=2"`

Both produce the identical signing input `"a=1ab=2"`, so a signature that Shopify computed and sent for one set of parameters would also verify as valid for the other, attacker-chosen set of parameters.

This code path is directly reachable by an anonymous/unauthenticated HTTP request: `validateAppProxyHmac` in the app-proxy request-authentication handler calls `api.utils.validateHmac(searchParams, {signator: 'appProxy'})` on the raw incoming `URLSearchParams` of the app-proxy request before granting access to the offline session/admin/storefront API clients: [5](#0-4) [6](#0-5) 

The only mitigations present are (1) rejecting duplicate values for the fixed security params `hmac`, `shop`, `signature`, `timestamp` via `APP_PROXY_SINGLE_VALUE_PARAMS`, and (2) a 90-second timestamp tolerance: [7](#0-6) [8](#0-7) 
Neither of these addresses the delimiter-less concatenation ambiguity for the *other* (application-defined) query parameters that Shopify appends to app-proxy requests (e.g. `logged_in_customer_id`, `path_prefix`, and any custom parameters the app proxy route defines).

### Impact Explanation
An attacker who can observe one legitimately-signed app-proxy request (trivial — app-proxy URLs and their signed query strings are visible client-side/in browser network traffic on the storefront, since Shopify appends the signature to the redirect URL sent to the browser) can, in principle, construct a different parameter set whose concatenation collides with the original signed byte string, causing the app to treat attacker-controlled parameter values (e.g. `logged_in_customer_id`) as Shopify-authenticated. Since `logged_in_customer_id` is often used by app-proxy handlers to identify/authorize the storefront customer, a collision that lets an attacker substitute this value while keeping the same computed HMAC would let them impersonate a different customer to the app's app-proxy endpoint — a customer-impersonation / cross-tenant authorization bypass on an unprivileged, request-authentication code path.

### Likelihood Explanation
Exploitability requires the attacker to actually find a colliding parameter split that (a) is accepted by the character/format constraints of the target parameter (e.g. numeric `logged_in_customer_id`) and (b) doesn't collide with the reserved/duplicate-checked parameter names (`hmac`, `shop`, `signature`, `timestamp`), which does add friction. It is not a trivial forge-any-value primitive (unlike the original Solidity ROOT-selector collision, which was immediate), but it is a structurally real, non-cryptographic weakness in message construction reachable from an anonymous storefront visitor, and it violates the standard best practice of using an unambiguous delimiter (e.g. `&`) when building a signed canonical string — the same "supposedly-unique-but-actually-collidable" pattern flagged in the H-02 report. I could not find any code path elsewhere in the reachable in-scope files that further restricts the character set of the arbitrary/custom app-proxy query parameters, so likelihood should be treated as low-to-moderate depending on which parameters a given app's proxy route trusts.

### Recommendation
Change `stringifyQueryForAppProxy` (and ideally `stringifyQueryForAdmin`, though it goes through `URLSearchParams.toString()` which already inserts `&`) to insert an explicit, unambiguous separator (e.g. `&`) between `key=value` pairs, matching Shopify's documented app-proxy signature algorithm exactly, and add regression tests asserting that no two distinct parameter dictionaries can produce the same signing string.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/hmac-validator.ts
function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

// Two different parameter sets collide to the same signing string:
stringifyQueryForAppProxy({a: '1', ab: '2'});   // => "a=1ab=2"
stringifyQueryForAppProxy({a: '1a', b: '2'});   // => "a=1ab=2"  <-- identical bytes, different logical params
```
Given a legitimately Shopify-signed app-proxy request containing `{a: '1', ab: '2', signature: <sig>}`, an attacker who observes `<sig>` can submit `{a: '1a', b: '2', signature: <sig>}` to `shopify.authenticate.public.appProxy`, and `validateAppProxyHmac`/`validateHmac` will treat it as valid because `generateLocalHmac` recomputes the identical `"a=1ab=2"` string for both.

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

function validateHmacTimestamp(query: AuthQuery) {
  const {timestamp} = query;

  if (
    timestamp === undefined ||
    timestamp === null ||
    Array.isArray(timestamp)
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  const parsedTimestamp = Number(timestamp);

  if (!Number.isInteger(parsedTimestamp)) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  if (
    Math.abs(getCurrentTimeInSec() - parsedTimestamp) >
    HMAC_TIMESTAMP_PERMITTED_CLOCK_TOLERANCE_SEC
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is outside of the tolerance range',
    );
  }
}

export function authenticateAppProxyFactory(
  params: BasicParams,
): AuthenticateAppProxy {
  const {logger} = params;

  return async function authenticate(
    request: Request,
  ): Promise<AppProxyContext | AppProxyContextWithSession> {
    const url = new URL(request.url);
    const shop = url.searchParams.get('shop')!;
    logger.info('Authenticating app proxy request', {shop});

    if (!(await validateAppProxyHmac(params, url))) {
      logger.info('App proxy request has invalid signature', {shop});
      throw new Response(undefined, {
        status: 400,
        statusText: 'Bad Request',
      });
    }

    const session = await ensureValidOfflineSession(params, shop);

    if (!session) {
      logger.debug('Could not find offline session, returning empty context', {
        shop,
        ...Object.fromEntries(url.searchParams.entries()),
      });

      const context: AppProxyContext = {
        liquid,
        session: undefined,
        admin: undefined,
        storefront: undefined,
      };

      return context;
    }

    const context: AppProxyContextWithSession = {
      liquid,
      session,
      admin: adminClientFactory({params, session}),
      storefront: storefrontClientFactory({params, session}),
    };

    return context;
  };

async function validateAppProxyHmac(
  params: BasicParams,
  url: URL,
): Promise<boolean> {
  const {api, logger} = params;

  try {
    let searchParams = new URLSearchParams(url.search);
    if (!searchParams.get('index')) {
      searchParams.delete('index');
    }

    let isValid = await api.utils.validateHmac(searchParams, {
      signator: 'appProxy',
    });

    if (!isValid) {
      const cleanPath = url.pathname
        .replace(/^\//, '')
        .replace(/\/$/, '')
        .replaceAll('/', '.');
      const data = `routes%2F${cleanPath}`;

      searchParams = new URLSearchParams(
        `?_data=${data}&${searchParams.toString().replace(/^\?/, '')}`,
      );

      isValid = await api.utils.validateHmac(searchParams, {
        signator: 'appProxy',
      });

      if (!isValid) {
        const searchParams = new URLSearchParams(
          `?_data=${data}._index&${url.search.replace(/^\?/, '')}`,
        );

        isValid = await api.utils.validateHmac(searchParams, {
          signator: 'appProxy',
        });
      }
    }

    return isValid;
