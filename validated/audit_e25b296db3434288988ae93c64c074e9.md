### Title
`check_microblock_header_signer` never verifies the two poison headers actually conflict, allowing reward theft from non-equivocating miners - (File: stackslib/src/chainstate/stacks/db/transactions.rs)

### Summary
`check_microblock_header_signer` and `handle_poison_microblock` only verify that `mblock_header_1` and `mblock_header_2` were signed by the *same* public key hash; they never verify that the two headers actually differ (i.e., that a genuine equivocation/fork occurred). An attacker can submit the identical, honestly-broadcast microblock header twice as "proof" of poisoning, which trivially satisfies the same-signer check, and the tx will be accepted, redirecting the honest miner's coinbase reward to the attacker.

### Finding Description
The claimed invariant is: *poison-microblock reward paid == exactly one valid, previously-unreported DOUBLE-signature (two distinct, conflicting headers) by the slashed miner*.

`check_microblock_header_signer` recovers `pkh1` and `pkh2` from `mblock_hdr_1` and `mblock_hdr_2` and only checks `pkh1 != pkh2`: [1](#0-0) 

If the caller supplies the same header object (or two byte-identical headers) in both slots, `pkh1 == pkh2` trivially, and the function returns `Ok(pkh1)` — no error, despite there being zero evidence of equivocation.

`handle_poison_microblock` then proceeds using only `mblock_header_1.sequence`; note that `mblock_header_2` is never used again after the signer check — its `sequence`, `block_hash`, or any other field is never compared against `mblock_header_1`'s corresponding field: [2](#0-1) 

There is no check anywhere in this path that:
- `mblock_header_1.sequence == mblock_header_2.sequence` (the defining property of equivocation — two different blocks signed for the same sequence position), or
- `mblock_header_1 != mblock_header_2` in content (block hash / tx merkle root), which would prove the same key signed two different messages.

As long as `get_microblock_pubkey_hash_height` resolves the pubkey hash to a height within `MINER_REWARD_MATURITY`, the report is inserted via `insert_microblock_poison`, unconditionally slashing that miner's reward in favor of the `sender_principal` — even though the attacker supplied only one legitimately-signed, non-conflicting header duplicated into both argument slots.

### Impact Explanation
This directly causes block-reward theft: an honest, non-equivocating miner's coinbase reward is redirected to an unprivileged attacker at maturation. This matches the "Critical — block-reward theft/double-payment/loss" category, since funds move from the rightful miner to an attacker who did nothing but replay a single publicly-visible microblock header. It is repeatable against any miner whose microblock public key hash the attacker can observe on P2P prior to maturation.

### Likelihood Explanation
Preconditions are trivially met: any miner that produces microblocks records a `pubkh` via `insert_microblock_pubkey_hash`, and the header is broadcast in the clear over P2P, so any unprivileged network participant can obtain it. The attacker needs no stake, no signer weight, no majority position — merely to submit a `PoisonMicroblock` transaction with the cloned header before `MINER_REWARD_MATURITY` blocks pass. This is a low-cost, fully repeatable attack against every microblock-producing miner.

### Recommendation
In `check_microblock_header_signer` (or immediately in `handle_poison_microblock`), enforce that the two headers represent a genuine fork: require `mblock_header_1.sequence == mblock_header_2.sequence` and that the headers are not identical (e.g., differing `block_hash`/signature over different content), in addition to the same-signer check. Reject the transaction with `InvalidStacksTransaction` if `mblock_header_1 == mblock_header_2` or their sequences differ.

### Proof of Concept
1. Build a chainstate and mine an honest miner's microblock stream; capture one signed `StacksMicroblockHeader` (`hdr`) and confirm `insert_microblock_pubkey_hash` recorded the miner's `pubkh` at height `H`.
2. Construct `TransactionPayload::PoisonMicroblock(hdr.clone(), hdr.clone())` from an unprivileged reporter account, and submit/mine it in a block at height `<= H + MINER_REWARD_MATURITY`.
3. Assert `check_microblock_header_signer(&hdr, &hdr)` returns `Ok(pkh)` (no error) — showing the broken equality (single header treated as valid double-signature proof).
4. Advance the chain past `MINER_REWARD_MATURITY` and assert via the miner-reward query (`find_mature_miner_rewards`/`calculate_miner_reward`) that: (a) `get_poison_microblock_report`/`get_microblock_poison_report(H)` returns `Some((reporter, hdr.sequence))`, and (b) the honest miner's `MinerReward` for height `H` is zero/redirected to `reporter`, despite the miner never having equivocated (only one header, submitted twice, was ever provided).

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
