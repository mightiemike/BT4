### Title
Unbounded per-inbound outbound-count amplification causes permanent stuck/frozen UTX finalization - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
`BuildOutboundsFromReceipt` iterates every log in the EVM receipt produced by a single inbound's `UniversalPayload` execution and `attachOutboundsToUtx` then iterates every resulting `OutboundTx` to write per-outbound state (chain config lookup, `PendingOutbounds` index, event emission) — both loops are unbounded and their length is entirely controlled by the attacker's own payload. This is the same "unbounded loop over user-influenced list" bug class as the reported `massUpdateRewards`/`removeIdFromList` finding, but here it lives in Push Chain's universal-execution finalization path (`VoteInbound` → `ExecuteInbound*` → `attachOutboundsToUtx`) rather than a reward-accounting contract.

### Finding Description
An unprivileged, external user submits an inbound to a source chain whose `UniversalPayload` (carried in `Inbound.UniversalPayload` / decoded from `raw_payload`) calls the `UniversalGatewayPC` contract's withdraw path many times within the single `gasLimit` budget the user sets on their own payload (`x/uexecutor/keeper/execute_inbound_funds_and_payload.go` → `ExecutePayloadV2`/`CallUEAExecutePayload`). Each such call emits a `UniversalTxOutboundEvent` log.

When the finalizing Universal Validator's vote reaches quorum, `VoteInbound` (`x/uexecutor/keeper/msg_vote_inbound.go:153`) synchronously calls `ExecuteInbound` → `ExecuteInboundFundsAndPayload`/`ExecuteInboundGasAndPayload`, which after a successful payload run calls `AttachOutboundsToExistingUniversalTx` → `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go:16-105`). This function loops `for _, lg := range receipt.Logs` with **no cap on the number of matching outbound logs**, producing an `outbounds` slice whose length is fully attacker-controlled by how many gateway events their payload can emit.

That slice is then passed to `attachOutboundsToUtx` (`x/uexecutor/keeper/create_outbound.go:339-407`), which loops `for _, outbound := range outbounds` and, per element, does a `k.uregistryKeeper.GetChainConfig` lookup, a `k.PendingOutbounds.Set` KV write, and an event emission — all inside the single `UpdateUniversalTx` closure of the **same Cosmos message execution** (the finalizing validator's `MsgVoteInbound` tx). `MsgVoteInbound` is a whitelisted gasless message (`app/txpolicy/gasless.go`), so no minimum fee is required, but the SDK gas meter for the tx is still driven by the tx's declared `GasWanted`, bounded in practice by the chain's block gas limit.

Because the number of outbounds (and thus the total gas of this post-EVM Go-level loop plus the EVM gas spent producing them) scales linearly with attacker-chosen payload content, an attacker can construct an inbound whose outbound count is large enough that finalizing it (any validator, any time) requires more gas than any single transaction/block can ever provide. Since the inbound bytes, and therefore the required outbound count, are deterministic and fixed once observed, **every future finalization attempt fails identically** — the transaction reverts atomically (rolling back the deposit/mint and the UTX creation too, since it's all one Cosmos message execution), and the ballot never permanently transitions to a state from which the user's funds can be released or refunded.

### Impact Explanation
This falls under "permanent freezing of user or protocol-controlled funds" and "denial of service ... reachable without privileged control," both explicitly in-scope. An ordinary user (not a validator, not an admin) can craft a single inbound whose payload causes the universal-execution finalization path to become permanently un-executable, freezing that inbound's bridged funds (and possibly wasting proposer/validator resources on repeated failed finalization attempts) without any honest-validator misbehavior. Because `attachOutboundsToUtx` and `BuildOutboundsFromReceipt` have no cap on the number of outbounds attached to one `UniversalTx`, and `x/uregistry` docs/README confirm there is no batching/pagination in this synchronous path (unlike the read-only `AllPendingOutbounds` query, which explicitly paginates), this is a genuine state-transition-path unbounded loop, not merely a query-side cost.

### Likelihood Explanation
Exploitation requires only: (1) an inbound to a chain where inbound processing is enabled, (2) a `UniversalPayload` whose EVM execution calls the gateway's outbound-creating function repeatedly within the payload's own `gasLimit` (a value the user sets, e.g. tests show values as high as `21000000`), and (3) enough repeated calls that the subsequent SDK-side loop's total gas (plus the EVM gas already spent) exceeds what any single tx/block can carry. No validator or admin cooperation beyond ordinary honest quorum voting is needed — the attacker only needs their own funds and gas for the source-chain and payload-execution gas. Likelihood is Medium-High: it requires payload engineering to maximize outbound-log count per gas unit, but no cryptographic or trust-boundary bypass.

### Recommendation
- Cap the number of `OutboundTx` entries that may be attached to a single `UniversalTx` in `BuildOutboundsFromReceipt`/`attachOutboundsToUtx` (analogous to limiting `investmentIds` in the original report), rejecting/truncating and instead recording a failed PCTx + revert once the cap is exceeded.
- Alternatively, decouple per-outbound bookkeeping (chain-config lookup, indexing, eventing) from the atomic finalize-and-execute transaction, e.g., defer `PendingOutbounds` indexing to a bounded-batch `EndBlocker`/subsequent message so a single inbound's cost cannot scale unboundedly within one transaction.
- Enforce a sane maximum on `UniversalPayload.GasLimit` and/or the number of gateway-emitted outbound events per payload execution, so that the worst-case number of outbounds per UTX is bounded independent of block gas limit fluctuations.

### Proof of Concept
1. Attacker deploys/uses a contract on the source chain that triggers a bridge deposit whose `UniversalPayload.Data` calls the recipient UEA, which in turn calls `UniversalGatewayPC`'s withdraw entry point N times in a loop within one EVM call (bounded only by the payload's own `GasLimit`, chosen close to the practical per-tx/block gas ceiling).
2. Validators observe and vote `MsgVoteInbound` for this inbound; quorum is reached honestly.
3. The finalizing validator's `MsgVoteInbound` triggers `ExecuteInbound` → payload execution succeeds, emitting N `UniversalTxOutboundEvent` logs.
4. `BuildOutboundsFromReceipt` builds N `OutboundTx` objects; `attachOutboundsToUtx` then performs N chain-config lookups + N KV writes + N event emissions inside the same gas-metered Cosmos message.
5. If N is large enough that cumulative gas (EVM execution + SDK loop) exceeds the maximum any single transaction can be allotted, the finalizing tx fails with out-of-gas every time it is retried by any validator, since the inbound content (and thus N) is fixed — the inbound can never be finalized, and the user's bridged funds remain permanently unresolved.

*Note: I could not directly confirm within the indexed code whether `UniversalPayload.GasLimit` has an explicit maximum cap or the exact per-call gas cost of the gateway's withdraw path, nor whether `collections.Map.Set`/event emission consistently consume SDK gas proportional to payload size in this fork. func (k Keeper) BuildOutboundsFromReceipt(
	ctx context.Context,
	utxId string,
	receipt *evmtypes.MsgEthereumTxResponse,
) ([]*types.OutboundTx, error) {

	outbounds := []*types.OutboundTx{}
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	k.Logger().Debug("building outbounds from receipt", "utx_id", utxId, "tx_hash", receipt.Hash, "log_count", len(receipt.Logs))

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}

		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}

		if len(lg.Topics) == 0 {
			continue
		}

		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.UniversalTxOutboundEventSig) {
			continue
		}

		event, err := types.DecodeUniversalTxOutboundFromLog(lg)
		if err != nil {
			return nil, fmt.Errorf("failed to decode UniversalTxWithdraw: %w", err)
		}

		// Check if outbound is enabled for the destination chain
		outboundEnabled, err := k.uregistryKeeper.IsChainOutboundEnabled(ctx, event.ChainId)
		if err != nil {
			return nil, fmt.Errorf("failed to check outbound enabled for chain %s: %w", event.ChainId, err)
		}
		if !outboundEnabled {
			k.Logger().Warn("outbound disabled for chain", "chain_id", event.ChainId, "utx_id", utxId)
			return nil, fmt.Errorf("outbound is disabled for chain %s", event.ChainId)
		}

		// Get the external asset addr
		tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(
			ctx,
			event.ChainId,
			event.Token, // PRC20 address
		)
		if err != nil {
			return nil, err
		}

		outbound := &types.OutboundTx{
			DestinationChain:  event.ChainId,
			Recipient:         event.Target,
			Amount:            event.Amount.String(),
			ExternalAssetAddr: tokenCfg.Address,
			Prc20AssetAddr:    event.Token,
			Sender:            event.Sender,
			Payload:           event.Payload,
			GasFee:            event.GasFee.String(),
			GasLimit:          event.GasLimit.String(),
			GasPrice:          event.GasPrice.String(),
			GasToken:          event.GasToken,
			TxType:            event.TxType,
			PcTx: &types.OriginatingPcTx{
				TxHash:   receipt.Hash,
				LogIndex: fmt.Sprintf("%d", lg.Index),
			},
			RevertInstructions: &types.RevertInstructions{
				FundRecipient: event.RevertRecipient,
			},
			OutboundStatus: types.Status_PENDING,
			Id:             strings.TrimPrefix(event.TxID, "0x"),
		}

		k.Logger().Debug("outbound built from receipt",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"dest_chain", outbound.DestinationChain,
			"amount", outbound.Amount,
			"tx_type", outbound.TxType.String(),
		)
		outbounds = append(outbounds, outbound)
	}

	k.Logger().Debug("outbounds built from receipt", "utx_id", utxId, "count", len(outbounds))
	return outbounds, nil
}

func (k Keeper) attachOutboundsToUtx(
	ctx sdk.Context,
	utxId string,
	outbounds []*types.OutboundTx,
	revertMsg string, // revert msg if the outbound is for a inbound revert
) error {

	if len(outbounds) == 0 {
		return nil
	}
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {

		for _, outbound := range outbounds {

			utx.OutboundTx = append(utx.OutboundTx, outbound)

			// Compute signature expiry deadline for the destination chain.
			var signingDeadline int64
			if chainCfg, err := k.uregistryKeeper.GetChainConfig(ctx, outbound.DestinationChain); err == nil {
				if chainCfg.TssSigningDeadline != nil && *chainCfg.TssSigningDeadline > 0 {
					signingDeadline = ctx.BlockTime().Unix() + int64(chainCfg.TssSigningDeadline.Seconds())
				}
			}

			// Write to pending outbounds index (inside UpdateUniversalTx closure for atomicity)
			if err := k.PendingOutbounds.Set(ctx, outbound.Id, types.PendingOutboundEntry{
				OutboundId:      outbound.Id,
				UniversalTxId:   utxId,
				CreatedAt:       ctx.BlockHeight(),
				SigningDeadline: signingDeadline,
			}); err != nil {
				return fmt.Errorf("failed to set pending outbound index for %s: %w", outbound.Id, err)
			}

			var pcTxHash string
			var logIndex string

			if outbound.PcTx != nil {
				pcTxHash = outbound.PcTx.TxHash
				logIndex = outbound.PcTx.LogIndex
			}

			evt, err := types.NewOutboundCreatedEvent(types.OutboundCreatedEvent{
				UniversalTxId:    utxId,
				TxID:             outbound.Id,
				DestinationChain: outbound.DestinationChain,
				Recipient:        outbound.Recipient,
				Amount:           outbound.Amount,
				AssetAddr:        outbound.ExternalAssetAddr,
				Sender:           outbound.Sender,
				Payload:          outbound.Payload,
				GasFee:           outbound.GasFee,
				GasLimit:         outbound.GasLimit,
				GasPrice:         outbound.GasPrice,
				GasToken:         outbound.GasToken,
				TxType:           outbound.TxType.String(),
				PcTxHash:         pcTxHash,
				LogIndex:         logIndex,
				RevertMsg:        revertMsg,
				SigningDeadline:  signingDeadline,
			})
			if err == nil {
				ctx.EventManager().EmitEvent(evt)
			}
		}

		return nil
	})
}

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
