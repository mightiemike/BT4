This confirms the analog: Push Chain explicitly models an "L1 data-availability fee" concept (`L1GasFee`) for OP-stack destination chains and correctly incorporates it into the fund-migration sweep calculation, but the outbound gas-fee-used accounting path used for user refunds omits it entirely.

### Title
Outbound gas-fee-used accounting omits L1 data-availability fee, causing over-refund of relayer-paid gas - (File: `universalClient/chains/evm/tx_builder.go`)

### Summary
`GetGasFeeUsed` in `universalClient/chains/evm/tx_builder.go` computes the gas cost a relayer incurred to execute an outbound as `receipt.GasUsed * tx.GasPrice()` only <cite repo="patrichyt/push-chain-node--017" path="universalClient/chains/evm/tx_builder.go" start="452="/> [1](#0-0) . On OP-stack (or any L2 with a separate data-availability charge) destination chains, the actual cost paid by the relayer also includes an L1 fee, which the codebase already models elsewhere as `L1GasFee` — explicitly subtracted in the fund-migration sweep formula [2](#0-1)  and fetched on-chain via `GetL1GasFeeByChain` / `l1GasFeeByChainNamespace` [3](#0-2) . `GetGasFeeUsed`'s return value becomes `OutboundObservation.gas_fee_used`, voted on by Universal Validators via `MsgVoteOutbound` [4](#0-3) , and is consumed by `applyGasRefund` to compute `refundAmount = gasFee - gasFeeUsed` [5](#0-4) .

### Finding Description
The pre-paid `gasFee` baked into an outbound (fetched from `UniversalCore.getOutboundTxGasAndFees`) is meant to cover the relayer's full real-world cost of executing the outbound tx on the destination chain [6](#0-5) . `applyGasRefund` treats any amount of `gasFee` above the honestly-reported `gasFeeUsed` as "excess" and refunds it back to the user (via `CallUniversalCoreRefundUnusedGas`, either swapped back to PC or deposited directly) [7](#0-6) .

Because `GetGasFeeUsed` only reports `gasUsed * gasPrice` — the L2 execution cost — and never adds the L1 data-availability fee that the relayer actually pays on OP-stack style chains, the value voted on by honest Universal Validators systematically understates the relayer's real cost whenever the destination chain has a non-zero L1 fee. This is architecturally identical to the Atlas bug: the accounting variable only reflects one component of the real cost (execution gas / `gasleft()` deltas) while a separately-modeled, already-known cost component (base overhead / calldata cost in Atlas; L1 DA fee here) is dropped from the same accounting path, even though the codebase demonstrates elsewhere (`computeFundMigrationTransfer`) that it knows how to account for it correctly.

The result: `refundAmount` is inflated by exactly the L1 fee amount for every outbound to an L1-fee-bearing chain, and that inflated amount is minted/swapped back to the user out of protocol-held gas-fee funds — a real, quantifiable value leak on every successful or failed outbound to such chains, triggered purely by ordinary users submitting cross-chain transactions (no privileged or malicious actor required; UVs report honestly using the buggy client code).

### Impact Explanation
Every outbound routed to a destination chain with a non-zero `l1GasFeeByChainNamespace` (e.g., Optimism, Base) causes the protocol to over-refund the difference between the true relayer cost and the reported `gasFeeUsed`. This is a systematic, repeatable drain of protocol/gas-fee-pool funds on the corrected accounting invariant ("gas fee accounting ... must not misroute value"), scoped in-bounds under "corruption of ... gas fee accounting, refund accounting." It is reachable purely from default user cross-chain transaction flows (any inbound that produces an outbound to an L1-fee chain), with honest validators and honest nodes, matching the required unprivileged-attacker / honest-validator constraint.

### Likelihood Explanation
High. This triggers on every single successful (and failed) outbound to any configured L1-fee chain, with no attacker action needed beyond routing ordinary crosschain transactions through the affected destination chain — which is standard usage, not an edge case. The bug is deterministic given `l1GasFeeByChainNamespace > 0` for that chain.

### Recommendation
In `GetGasFeeUsed` (`universalClient/chains/evm/tx_builder.go`), query and add the chain's L1 data-availability fee to the reported `gasFeeUsed`, mirroring the pattern already used in `computeFundMigrationTransfer`/`GetFundMigrationSigningRequest`. Concretely, fetch the L1 fee (either via the destination chain's `GetL1Fee`-equivalent RPC precompile at execution time, or the registry's `l1GasFeeByChainNamespace` value used elsewhere) and sum it with `gasUsed * gasPrice` before returning, so `applyGasRefund`'s excess computation reflects the relayer's true cost.

### Proof of Concept
1. Register/configure a destination chain namespace with `l1GasFeeByChainNamespace > 0` (OP-stack chain) in `UniversalCore`.
2. Trigger a standard inbound that produces an outbound with `gasFee` computed via `GetOutboundTxGasAndFees` (this value already prices in the L1 fee component set on-chain) [6](#0-5) .
3. Relayer broadcasts and pays L2 execution gas + L1 DA fee to execute the outbound.
4. The Universal Validator client calls `GetGasFeeUsed`, which returns only `gasUsed * gasPrice`, omitting the L1 fee actually paid [1](#0-0) .
5. UVs vote `MsgVoteOutbound` with this understated `gasFeeUsed`.
6. `applyGasRefund` computes `refundAmount = gasFee - gasFeeUsed`, which is inflated by the omitted L1 fee, and this excess is refunded to the user's recipient address [8](#0-7) .
7. Repeat for every outbound to the L1-fee chain to continually drain the gas-fee buffer by the L1 fee amount per transaction.

Note: I could not directly confirm from the indexed code whether an additional compensating mechanism exists elsewhere (e.g., in the `UniversalCore` Solidity contract's `refundUnusedGas`) that independently re-derives or caps the refund using L1 fee data — the Solidity contract source itself was not available in the index. This should be verified in a full Devin session with complete repository access before treating the impact as final, since if `refundUnusedGas` on-chain independently validates against a chain-aware fee bound, the practical drain could be smaller or mitigated.

```go
// GetGasFeeUsed returns the gas fee used by a transaction on the EVM chain.
// Fetches the receipt for gasUsed and the transaction for gasPrice, then returns
// gasUsed * gasPrice as a decimal string. Returns "0" if not found.
func (tb *TxBuilder) GetGasFeeUsed(ctx context.Context, txHash string) (string, error) {
	hash := ethcommon.HexToHash(txHash)
	receipt, err := tb.rpcClient.GetTransactionReceipt(ctx, hash)
	if err != nil {
		return "0", nil
	}

	tx, _, err := tb.rpcClient.GetTransactionByHash(ctx, hash)
	if err != nil {
		return "0", nil
	}

	gasUsed := new(big.Int).SetUint64(receipt.GasUsed)
	gasPrice := tx.GasPrice()
	if gasPrice == nil || gasPrice.Sign() == 0 {
		return "0", nil
	}

	gasFeeUsed := new(big.Int).Mul(gasUsed, gasPrice)
	return gasFeeUsed.String(), nil
}
```

```go
// computeFundMigrationTransfer returns the native amount to sweep from the old
// TSS address to the new one: balance - (gasPrice * gasLimit) - l1GasFee.
// The l1GasFee covers OP-stack sequencer data-availability charges (0 for
// non-L2 chains). All validators must compute the same value — any drift
// here breaks the TSS signing hash.
func computeFundMigrationTransfer(balance, gasPrice *big.Int, gasLimit uint64, l1GasFee *big.Int) (*big.Int, error) {
	gasCost := new(big.Int).Mul(gasPrice, new(big.Int).SetUint64(gasLimit))
	totalFee := new(big.Int).Set(gasCost)
	if l1GasFee != nil && l1GasFee.Sign() > 0 {
		totalFee.Add(totalFee, l1GasFee)
	}
	maxTransfer := new(big.Int).Sub(balance, totalFee)
	if maxTransfer.Sign() <= 0 {
		return nil, fmt.Errorf("insufficient balance for gas: balance=%s gasCost=%s l1GasFee=%s",
			balance.String(), gasCost.String(), l1GasFeeString(l1GasFee))
	}
	return maxTransfer, nil
}
```

```go
// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
```
