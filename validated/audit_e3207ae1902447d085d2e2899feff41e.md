### Title
`accrue` pause pass-through returns stale indexes as if freshly accrued, causing under-accounting of interest fed into market health checks - ([File: local-testing/contracts/vault/vault-sbtc.clar])

### Summary
When a vault's `accrue` pause flag (`pause-states.accrue`) is set, `accrue` returns `(ok { index: idx, lindex: lidx })` using the *current* (stale) `index`/`lindex` data-vars instead of reverting or signalling staleness [1](#0-0) . `market.clar`'s `accrue-and-cache` treats this as a legitimate, successful accrual and caches it for the block [2](#0-1) , and every downstream health/notional calculation (`get-notional-evaluation`, `calculate-asset-notional-value`, `resolve-ztoken`) consumes that stale value as ground truth for the entire block, with no differentiation between a genuine fresh accrual and a paused pass-through [3](#0-2) .

### Finding Description
This is structurally the same bug class as the external report: a function silently substitutes a value for the "real" (up-to-date) state rather than rejecting the call, and that substituted value is then consumed by a later invariant-critical computation (health checks / notional value) without anyone knowing it is stale.

`accrue()` in `vault-sbtc.clar` (and the other `vault-*.clar` spokes) is designed to:
1. Compute `next-index()` / `next-liquidity-index()` from elapsed time and the borrow rate.
2. Update `index` / `lindex` data-vars and mint reserve shares to the DAO treasury.
3. Return `{ index, lindex }`.

But when `(get accrue states)` is `true` (i.e., accrual paused by DAO), the function takes the "PASSED-THROUGH" branch and simply returns the *existing* `idx`/`lidx` values wrapped in `ok`, without any indication to the caller that this is not a fresh accrual [4](#0-3) .

`market.clar`'s caching layer (`accrue-and-cache`) calls `vault-accrue` and unconditionally caches whatever comes back as the authoritative per-block index for that asset id, keyed only by `{ timestamp, aid }` [2](#0-1) . This cached value is then used to:
- Convert scaled debt to actual, notional debt in USD in `calculate-asset-notional-value` (`debt-notional`), which feeds `is-healthy`/`is-healthy-with-mask` checks in `borrow`, `collateral-add`, `collateral-remove`, and `liquidate` [5](#0-4) .
- Price zToken collateral via `resolve-ztoken`, which reads the cached `lindex` directly and multiplies it into the collateral price [6](#0-5) .

Because the vault silently substitutes stale numbers instead of surfacing an error/staleness flag, `market.clar` cannot distinguish "interest correctly accrued to now" from "interest frozen at whatever it was when the DAO paused accrual." All borrow/collateral-add/collateral-remove/liquidate health math for that block is computed on outdated debt/liquidity indexes, exactly analogous to the `depositFor` report's core defect: a privileged/administrative state transition (locking a veNFT / pausing accrual) is not propagated into a function whose output is later trusted as current truth by downstream accounting.

### Impact Explanation
If the DAO pauses `accrue` on a vault (e.g., during an incident response or oracle outage) while leaving borrowing/collateral operations active, all subsequent notional-debt and zToken-collateral valuations in `market.clar` are computed against frozen indexes rather than the true, interest-accruing values. Debt keeps compounding economically (rate model still runs once unpaused) but is under-reported to the health engine while paused, and zToken collateral value is similarly frozen rather than reflecting real vault growth. This can let a borrower's position appear healthier than it truly is (temporary freezing/misstatement of unclaimed yield/interest accounting) for the duration of the pause, and lets under-collateralized borrows/collateral-removals go through that would otherwise fail the health check once real (unpaused) indexes are applied — this is a temporary freezing/misstatement of protocol yield/interest accounting reachable without any special privilege beyond the DAO's already-intended pause action.

### Likelihood Explanation
Triggering requires only the DAO's already-existing "pause accrue" operational lever (a normal, documented pause flag, not a compromise) combined with a normal user calling `borrow`/`collateral-add`/`collateral-remove`/`liquidate` while that pause is active. This is a plausible operational sequence (e.g., DAO pauses accrual on a distressed vault for other reasons), and no attacker collusion or multi-user interference is required — a single user's transaction, executed after the pause is engaged, exploits the stale-value pass-through.

### Recommendation
`accrue()` should not return `ok` with unrefreshed values when paused in a way that is indistinguishable from a genuine up-to-date accrual. Either:
1. Have the paused branch return an explicit staleness indicator (e.g., include a `stale: true` flag in the returned tuple) that `market.clar`'s `accrue-and-cache`/`get-notional-evaluation`/`resolve-ztoken` explicitly check and reject with an error (e.g., `ERR-ACCRUAL-PAUSED`) rather than silently caching and using the frozen index, or
2. Ensure that when `accrue` is paused, `market.clar` refuses to execute borrow/collateral-add/collateral-remove/liquidate for that asset entirely (fail closed) instead of proceeding with whatever `vault-accrue` happens to return.

### Proof of Concept
1. DAO calls `set-pause-states` on `vault-sbtc` (or any vault) setting `accrue: true` [7](#0-6) .
2. Time passes (multiple blocks); real interest should have accrued on outstanding sBTC debt/liquidity, but `index`/`lindex` remain frozen at their pre-pause values because `accrue` takes the pass-through branch every call.
3. A borrower with sBTC debt (or zsBTC collateral) calls `market.clar`'s `borrow`/`collateral-add`/`collateral-remove` for a different asset. Internally, `accrue-user-debts`/`accrue-user-collateral` call `accrue-and-cache sBTC`, which calls `vault-accrue`, gets the stale `{index, lindex}` pass-through, and caches it as if fresh [2](#0-1) .
4. `get-notional-evaluation`/`calculate-asset-notional-value` compute `debt-notional` using this stale `index`, understating the real debt-in-USD value that should include the interest that would have accrued absent the pause [5](#0-4) .
5. `is-healthy`/`is-healthy-with-mask` pass on a position that would fail with correctly accrued debt, allowing the borrower to add debt, remove collateral, or avoid liquidation that should otherwise have been triggered.

Note: I was unable to fully inspect `mainnet/contracts/vault/v0-vault-sbtc.clar`'s exact `accrue`/pause-state block in this session (file reads failed due to a tool parameter issue on the final iteration), so the mainnet-path confirmation relies on the `local-testing` mirror plus the identical `accrue-and-cache`/`get-notional-evaluation` logic already confirmed in both `local-testing/contracts/market/market.clar` and `mainnet/contracts/market/v0-4-market.clar`. A Devin session with full file access should re-verify the exact mainnet vault pause branch before treating this as fully confirmed.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
