### Title
Panic due to negative `strings.Repeat` count in `normalizeHex` from unpadded hex `workflowID`/`workflowOwner` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` only rejects hex strings whose *total* length (including any `0x` prefix) exceeds `expectedLength`; it does not require a `0x` prefix nor account for the prefix when computing the decoded byte length. An attacker can submit a `workflowID`/`workflowOwner` value that is exactly `workflowIDLength` (66) or `workflowOwnerLength` (42) hex characters long but omits the `0x` prefix. This passes validation, but when `normalizeHex` later strips the (non-existent) `0x` prefix and pads, `expectedHexLength-len(hexStr)` becomes negative, causing `strings.Repeat` to panic.

### Finding Description
The validation function [1](#0-0)  checks `len(input) > expectedLength` on the raw string as supplied by the user (which may or may not include `0x`), and only decodes it as hex after stripping any `0x` prefix — it never verifies the prefix is actually present or that the *hex payload length* (post-strip) matches the expected byte length exactly.

`resolveWorkflowID` at [2](#0-1)  calls `normalizeHex(workflowID, workflowIDLength)` (or `workflowOwner, workflowOwnerLength`) right after validation succeeds.

`normalizeHex` computes:
```go
hexStr := strings.TrimPrefix(input, "0x")
expectedHexLength := length - 2
paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
``` [3](#0-2) 

If the attacker supplies exactly `workflowIDLength` (66) lowercase hex characters **without** the `0x` prefix (e.g. a 66-character string of `0-9a-f`), then:
- `validateHexInput`: `len(input) == 66`, not `> 66`, so the length check passes; `hex.DecodeString` on the 66-char string succeeds (valid hex, even length) → validation passes.
- `normalizeHex`: `TrimPrefix` does nothing (no `0x` present), so `hexStr` stays at length 66; `expectedHexLength = 66-2 = 64`; `expectedHexLength-len(hexStr) = 64-66 = -2`.
- `strings.Repeat("0", -2)` panics with `"strings: negative Repeat count"`.

The identical flaw applies to `workflowOwner` with `workflowOwnerLength = 42` (40 hex chars expected after prefix strip, but a 42-char no-prefix input yields `-2` again).

This code path is reached directly from `HandleUserTriggerRequest`, which is the entry point processing unauthenticated/user-supplied gateway trigger requests (`workflows.execute` JSON-RPC method) — no node-operator privilege is required to send such a payload; it is a normal external HTTP-trigger request into the gateway.

Repository-wide searches did not find any `recover()` guarding this call chain within `core/services/gateway` handlers (only test files reference `recover()`), so a panic here is likely to propagate up the goroutine/handler stack. Whether it crashes the entire gateway process or is caught by a higher-level Go HTTP server recovery middleware could not be conclusively determined from the available index (the request-handling wiring into `network/httpserver.go`/`wsserver.go` was only partially inspected before the tool budget was exhausted).

### Impact Explanation
At minimum, an unauthenticated/unprivileged remote caller can trigger a Go runtime panic within request-processing logic of the Gateway's capability HTTP trigger handler by sending a single crafted JSON-RPC `workflows.execute` request with a specially-shaped `workflowID` or `workflowOwner` string. If unrecovered, this results in denial-of-service against the Gateway node (goroutine/process crash), which handles the CRE/workflow HTTP-trigger capability for the whole DON's gateway. This matches a service disruption / DoS impact class.

### Likelihood Explanation
The precondition is trivial: craft a `workflowID` (or `workflowOwner`) string of exactly the expected total character length, composed of valid lowercase hex digits, without a `0x` prefix. No authentication, no valid workflow reference, and no special privileges are needed since `resolveWorkflowID`/`normalizeHex` execute before any DON authorization (`authorizeRequest`) or rate-limit check in `HandleUserTriggerRequest`. This makes the panic trivially and repeatably reproducible by any client capable of sending an HTTP-trigger JSON-RPC request to the gateway.

### Recommendation
In `normalizeHex`, guard against `len(hexStr) > expectedHexLength` before computing the repeat count, returning an error (and rejecting the request) instead of silently padding; alternatively, tighten `validateHexInput` to require the `0x` prefix and compute the length check against the trimmed hex payload (`length-2` hex characters) rather than the full raw string length, matching what `normalizeHex` expects.

### Proof of Concept
Unit test in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler_test.go`:
1. Build a `jsonrpc.Request[json.RawMessage]` with `Method = gateway_common.MethodWorkflowExecute`, a valid JSON `Input` (`{}`), and `Workflow.WorkflowID` set to a 66-character lowercase hex string with no `0x` prefix (e.g. `strings.Repeat("a", 66)`).
2. Call `httpTriggerHandler.HandleUserTriggerRequest(ctx, req, callback, time.Now())`.
3. Expected (buggy) behavior: the call panics with `strings: negative Repeat count` inside `normalizeHex`, instead of returning a handled JSON-RPC error via `handleUserError`.
4. Assert (post-fix) that the function instead returns an error / sends an `ErrInvalidRequest` user error without panicking.

A `workflowOwner`-only variant (42-char, no-prefix hex, plus valid `workflowName`/`workflowTag`) reproduces the identical panic via the `workflowOwner` branch of `resolveWorkflowID`.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}
