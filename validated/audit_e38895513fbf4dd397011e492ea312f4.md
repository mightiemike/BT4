## Analysis

This finding maps the BendDAO `isolateRepay()` bug — an attacker-controlled `onBehalf` address letting an unprivileged caller mutate a *third party's* accounting state without any check binding the caller to that party — onto Push Chain's `MsgExecutePayload` gas-billing path. [1](#0-0) 

In `Keeper.ExecutePayload`, the EVM call to the target UEA's `executeUniversalTx` runs directly on `sdkCtx` (no `CacheContext` wrapper, unlike the CEA and `ExecutePayloadV2` paths), and gas fees are deducted from the UEA (`ueaAddr`, derived from the attacker-supplied `UniversalAccountId.Owner`) via `DeductGasFeesFromReceipt` **before** checking whether the call itself (`execErr`) succeeded: [2](#0-1) 

`DeductGasFeesFromReceipt` bills `receipt.GasUsed` (real gas the EVM consumed before reverting) at the network base fee, taken straight out of the recipient's native `upc` balance and burned: [3](#0-2) 

### Title
Unprivileged `MsgExecutePayload` griefing drains arbitrary UEA native balances via billed-but-reverted signature checks - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`MsgExecutePayload` is gasless and open to any Cosmos signer. `Signer` and `UniversalAccountId.Owner` are intentionally decoupled — that decoupling is documented as safe *for state changes* because the UEA contract's signature check prevents unauthorized `executeUniversalTx` execution. However, gas-fee accounting is not protected by the same signature check: `ExecutePayload` deducts and burns real `upc` from the target UEA's balance based on `receipt.GasUsed` *before* inspecting whether the call reverted due to signature-verification failure. This is the same class of bug as BendDAO's `isolateRepay`: an unprivileged party supplies an "on behalf of" identifier (there, `onBehalf`; here, `UniversalAccountId.Owner`) that is never checked against the actual caller, letting the caller mutate accounting state (there, `userScaledIsolateBorrow`; here, native UEA balance) belonging to someone else.

### Finding Description
An attacker who knows any deployed UEA's public identifiers (`ChainNamespace`, `ChainId`, `Owner` — all public, derivable from any known source-chain EOA) can submit `MsgExecutePayload` with a garbage `VerificationData` and an arbitrary `UniversalPayload` (attacker fully controls `GasLimit`, `Data`, `To`, etc.) targeting the victim's UEA: [4](#0-3) 

The message costs the attacker nothing (it is on the gasless whitelist): [5](#0-4) 

Inside `ExecutePayload`, `CallUEAExecutePayload` is invoked; because `VerificationData` doesn't match the owner's key, the UEA contract's ECDSA/Ed25519 check reverts inside `executeUniversalTx`. As documented elsewhere in the codebase, an EVM call that executes and then reverts still returns a non-nil receipt with `GasUsed > 0` ("EVM execution consumed gas ... proves it ran"): [6](#0-5) 

`ExecutePayload` calls `DeductGasFeesFromReceipt(ctx, sdkCtx, ueaAddr, receipt, universalPayload)` unconditionally on this receipt — and only *after* that succeeds does it check `execErr` and return the failure. Since the deduction runs on the live `sdkCtx` (not a `CacheContext` like the other execution paths), the burn of the victim UEA's `upc` is committed to state regardless of whether the payload execution ultimately failed: [1](#0-0) 

The victim never authorized this action (their real signature never appears anywhere in the flow) and the message signer bears none of the cost. This lets any unprivileged actor repeatedly grief/drain the native balance of any UEA on Push Chain, for free, with no signature match required.

### Impact Explanation
This falls under "draining ... permanent loss ... of user ... controlled funds" from an unprivileged, honest-validator-reachable path (`MsgExecutePayload` requires no bonded/UV status, only a Cosmos signer, which is created for free via `AccountInitDecorator` on first use). Repeated calls can fully drain a victim UEA's native `upc` balance to zero, denying the victim gas for their own legitimate future `executeUniversalTx`/payload calls and destroying value with no economic cost to the attacker.

### Likelihood Explanation
High. `UniversalAccountId` fields are public (CAIP-2 namespace/chain-id plus the owner's known source-chain address), `MsgExecutePayload` accepts any signer, is gasless, and requires no special state (only that the target UEA is already deployed, which is itself typically public/observable). No validator collusion, no privileged access, and no correct signature are required — only a syntactically valid but cryptographically wrong `VerificationData`.

### Recommendation
Mirror the fix pattern from BendDAO's `isolateRepay`: don't let the caller unilaterally impose a cost on `onBehalf`/`Owner` without authorization. Concretely:
- Wrap the `CallUEAExecutePayload` + `DeductGasFeesFromReceipt` sequence in `ExecutePayload` inside a `CacheContext`, discarding (not billing) the fee-burn when `execErr != nil` due to signature/authorization failure — consistent with how `ExecutePayloadV2` and the CEA paths already behave.
- Alternatively/additionally, only charge the UEA for gas when the underlying signature check actually passed (i.e., condition billing on a specific "authorized-but-application-reverted" signal from the receipt, not on any revert).

### Proof of Concept
1. Identify a deployed victim UEA: `UniversalAccountId{ChainNamespace: "eip155", ChainId: "<chain>", Owner: "<victim EOA>"}` (public).
2. Attacker (any funded-or-fresh Cosmos account, since `MsgExecutePayload` is gasless) submits `MsgExecutePayload{Signer: attacker, UniversalAccountId: victimId, UniversalPayload: {arbitrary To/Data/GasLimit/MaxFeePerGas>=baseFee}, VerificationData: "0x00"}`.
3. `CallUEAExecutePayload` reverts (bad signature) but returns `receipt.GasUsed > 0`.
4. `DeductGasFeesFromReceipt` burns `gasUsed * baseFee` from the victim UEA's `upc` balance before `execErr` is checked, per [2](#0-1) .
5. The Cosmos tx from the attacker still succeeds (only the inner `execErr` is returned by the handler after the burn has already committed on `sdkCtx`).
6. Repeat indefinitely at zero cost to the attacker until the victim's UEA balance is exhausted.

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

	k.Logger().Debug("gas fees deducted",
		"recipient", recipient.Hex(),
		"gas_used", receipt.GasUsed,
		"gas_cost", gasCost.String(),
	)
	return nil
```

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
