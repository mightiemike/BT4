### Title
Missing declared-class validation in Starknet OS `execute_replace_class` causes divergence from Blockifier, enabling commitment of undeclared class hashes - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall handler in the Rust `blockifier` (the sequencer's actual transaction-execution engine) enforces that the target class hash is declared before allowing a contract to change its class, but the equivalent Cairo implementation inside the Starknet OS (used for re-execution/proving) omits this check entirely — a fact the code itself acknowledges via an explicit `TODO`. Any account can trigger this code path from a normal `Invoke` transaction by calling the `replace_class` syscall with an arbitrary class hash.

### Finding Description
The Rust syscall handler for `replace_class`, invoked during real block execution by `blockifier`, explicitly reads/validates the class before mutating state: [1](#0-0) 

This check ("Ensure the class is declared") is also what backs the Cairo1-native and CASM syscall paths that ultimately route to `syscall_handler.base.replace_class(...)`: [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of `execute_replace_class` (used during OS re-execution / proving of the block) directly writes the new `class_hash` into `contract_state_changes` with **no check that the class is declared** — the missing validation is explicitly called out in the source: [4](#0-3) 

The same absence of validation exists in the deprecated syscall path of the OS: [5](#0-4) 

Both OS entry points are reached directly from dispatch on the `REPLACE_CLASS_SELECTOR`, confirming this is on the mainline syscall-execution path exercised for every `replace_class` syscall issued by a contract: [6](#0-5) 

This is structurally analogous to the reported bug class: a state-mutating operation that should be gated by a validation/authorization check is instead reachable and effective without it. Here, the "guard" that blockifier enforces (must-be-declared class) is missing in the parallel OS implementation that is supposed to be functionally equivalent for proof soundness.

### Impact Explanation
The Starknet OS's re-execution of a block's transactions must produce state changes and a state commitment that are provably consistent with the sequencer's real execution semantics (as implemented by `blockifier`). Because the OS omits the declared-class check that `blockifier` enforces, the OS accepts and commits state where a contract's class hash is set to an undeclared/invalid class hash — a state that `blockifier`'s real execution would have rejected with `StateError::UndeclaredClassHash`, reverting the transaction. This is a soundness gap between the two independently-required-equivalent execution engines: it can lead to a wrong committed state root/class hash being accepted through the Starknet OS path (in scope per the review's stated impact categories: "wrong committed root or block hash" / "honest-node divergence"), and can permanently corrupt/freeze the affected contract, since no CASM/Sierra program exists for the assigned class hash, making the contract's storage unreachable/uncallable through that code (loss of functionality/funds locked behind an unusable class).

### Likelihood Explanation
`replace_class` is a standard, unprivileged Starknet syscall callable by any deployed contract from any `Invoke` transaction — no special permissions, staking, or operator role is required. The vulnerable code path (`execute_replace_class` in the OS) is on the syscall dispatch mainline for every replace_class invocation during OS re-execution, so the missing check is reached deterministically whenever this syscall is exercised with a class hash that isn't declared.

### Recommendation
Add the same declared-class validation to the Starknet OS's `execute_replace_class` implementations (both `execute_syscalls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` variants) that `blockifier` performs — i.e., verify that a compiled/declared class exists for `class_hash` (consistent with how `guess_compiled_class_facts` / class-fact validation already works elsewhere in the OS) before writing the new `StateEntry`, so that OS re-execution and `blockifier` execution remain semantically identical and reject the same invalid transactions.

### Proof of Concept
1. Deploy any contract and, from within it (or from an account contract executed via `__execute__`), invoke the `replace_class` syscall with a `class_hash` for which no class has ever been declared.
2. In real sequencer execution via `blockifier`, this fails with `StateError::UndeclaredClassHash` at `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801` (or the CASM/native equivalents), reverting the transaction.
3. When the same transaction trace is replayed through the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo`), no equivalent check exists; the OS updates `contract_state_changes` to set the contract's class hash to the undeclared value without error, producing a state diff/commitment that could not have been legitimately produced by `blockifier`'s enforcement rules.

Note: I could not fully trace how a divergent OS-computed state diff would concretely interact with the proof-verification/commitment pipeline end-to-end (e.g., whether an upstream check elsewhere in the OS or in Starknet L1 verification would catch this before finalization), since that requires deeper tracing through the OS's block-level commitment logic and verifier contracts, which is outside what I could confirm with the available search results.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
