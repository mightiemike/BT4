### Title
Poison-microblock proof accepted via ECDSA signature malleation of a single honestly-signed `StacksMicroblockHeader`, punishing an honest miner without real equivocation - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`check_microblock_header_signer` only checks that `check_recover_pubkey()` on both headers returns the same `Hash160`, and the wire-format check in `TransactionPayload::consensus_deserialize` only requires the two headers to differ in *some* field and share `sequence` or `prev_block`. Because ECDSA signature recovery in this codebase is done via `recover_to_pubkey_without_validating_low_s` (which skips low-S normalization), an attacker can flip the sign of `s` and the recovery-id parity of one honestly-produced signature to synthesize a second, bitwise-different `MessageSignature` over the *same* message that still recovers to the *same* pubkey-hash, with all non-signature fields (version, sequence, prev_block, tx_merkle_root) identical.

### Finding Description
The broken equality is: *"h1 != h2 (raw struct) AND check_recover_pubkey(h1) == check_recover_pubkey(h2)" implies "the signer produced two distinct microblocks at the same slot (equivocation)."* This equality does not hold because signature malleability lets an attacker manufacture h2 from h1 alone.

- `StacksMicroblockHeader::check_recover_pubkey` hashes the header with the signature zeroed out (`self.serialize(&mut bytes, true)`), i.e., the signed digest excludes the signature field itself: [1](#0-0) .
- Recovery uses `recover_to_pubkey_without_validating_low_s`, which explicitly skips the high-S rejection that `verify()`/mempool tx-auth paths enforce elsewhere: [2](#0-1) .
- The codebase's own test proves the malleation: negating `s` mod n and flipping the recovery-id parity produces a signature that is bitwise different from the original yet recovers to the identical public key over the identical message: [3](#0-2) .
- `check_microblock_header_signer` used by `handle_poison_microblock` only compares the two recovered pubkey-hashes, with no check that the headers' content (e.g. `tx_merkle_root`) actually diverges: [4](#0-3) .
- The wire-level `consensus_deserialize` guard for `PoisonMicroblock` only requires `h1 != h2` (any field, including just the signature bytes) and `sequence`/`prev_block` match — it never requires `tx_merkle_root` to differ: [5](#0-4) .
- The mempool admission check (`TransactionPayload::PoisonMicroblock` arm) reinforces the same insufficient checks (equal sequence/prev_block/version, equal recovered pubkeyhash) without ever requiring the headers to encode genuinely different content: [6](#0-5) .

Exploit flow: attacker observes any honestly broadcast, signed `StacksMicroblockHeader` h1 (from the P2P network, since microblocks are public). Attacker computes h2 = h1 with `signature = negate_s_and_flip_recid(h1.signature)`. h1 != h2 (bytes differ), same sequence/prev_block/version, and `check_recover_pubkey(h2) == check_recover_pubkey(h1)`. Attacker submits `PoisonMicroblock(h1, h2)`; it passes `consensus_deserialize`, mempool admission, and `handle_poison_microblock`'s `check_microblock_header_signer`, triggering the punishment/report logic against the honest miner's microblock pubkey-hash even though the miner never authored a second, conflicting microblock.

### Impact Explanation
This is bounded to a single miner's coinbase/fee reward at one microblock-pubkey height — the reporter (attacker) becomes entitled to the punished miner's coinbase commission via `insert_microblock_poison`/report logic: [7](#0-6) . No chain split or state-root divergence occurs; the impact matches "High — a poison or reward mis-payment bounded to fees," since an honest miner can be slashed for equivocation they never committed, and any attacker (unprivileged, minority-stake) who merely observes broadcast microblocks can repeat this against any miner whose signed header they can see, as long as it is within `MINER_REWARD_MATURITY` of the current height.

### Likelihood Explanation
The attack requires no privileged role, no majority stake, and no private key — only the ability to observe one legitimately signed microblock header (which is broadcast publicly during normal mining) and perform an elementary EC scalar negation (`s -> n - s`, flip recovery-id parity), which is exactly what the repo's own `with_negated_s` test helper does. It is trivially repeatable against every miner and every microblock height within the maturity window, at zero BTC/stake cost to the attacker beyond the fee to submit the `PoisonMicroblock` transaction.

### Recommendation
Reject poison-microblock proofs where the two headers are identical in every field except `signature` (i.e., require that the non-signature content, notably `tx_merkle_root`, actually differs, or equivalently require that `h1.block_hash() != h2.block_hash()` when computed over a signature-normalized/low-S-only encoding). Additionally, `check_recover_pubkey`/`check_microblock_header_signer` should reject high-S (non-canonical) signatures the same way ordinary transaction verification does, closing the malleability path entirely.

### Proof of Concept
```rust
// stackslib/src/chainstate/stacks/db/transactions.rs (test module)
#[test]
fn poison_microblock_self_malleation_forges_equivocation_proof() {
    let privk = StacksPrivateKey::from_hex("...").unwrap();
    let pubkh = Hash160::from_node_public_key(&StacksPublicKey::from_private(&privk));

    let mut h1 = StacksMicroblockHeader {
        version: 0x12,
        sequence: 0x34,
        prev_block: BlockHeaderHash([0u8; 32]),
        tx_merkle_root: Sha512Trunc256Sum([7u8; 32]),
        signature: MessageSignature::empty(),
    };
    h1.sign(&privk).unwrap();

    // Attacker-only operation: malleate signature (s -> n-s, flip recid parity)
    let malleated_sig = h1.signature.with_negated_s();
    let mut h2 = h1.clone();
    h2.signature = malleated_sig;

    // Equality check 1: raw headers differ only in signature bytes
    assert_ne!(h1, h2);
    assert_eq!(h1.sequence, h2.sequence);
    assert_eq!(h1.prev_block, h2.prev_block);
    assert_eq!(h1.tx_merkle_root, h2.tx_merkle_root); // NOT a real content fork

    // Equality check 2: both recover to the SAME pubkeyhash
    let pkh1 = h1.check_recover_pubkey().unwrap();
    let pkh2 = h2.check_recover_pubkey().unwrap();
    assert_eq!(pkh1, pkh2);
    assert_eq!(pkh1, pubkh);

    // This currently succeeds even though no real equivocation occurred:
    let result = StacksChainState::check_microblock_header_signer(&h1, &h2);
    assert!(result.is_ok(), "forged poison-microblock proof was accepted without genuine equivocation");
}
```
This demonstrates that `check_microblock_header_signer` (and therefore `handle_poison_microblock`) accepts a self-malleated pair as valid proof, violating the intended equality that a valid poison proof must encode two independently-authored, content-diverging microblocks.

    pub fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
        let mut bytes = vec![];
        self.serialize(&mut bytes, true)
            .expect("BUG: failed to serialize to a vec");
        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }
