### Title
`protodelim.UnmarshalOptions.UnmarshalFrom` fails to discard the oversized message body on `SizeTooLargeError`, desynchronizing the delimited-message stream - ([File: encoding/protodelim/protodelim.go])

### Summary
`UnmarshalFrom` reads a varint length prefix from a stream and then rejects the frame with a `SizeTooLargeError` if the declared size exceeds `MaxSize`. When this happens, the function returns immediately without reading (or discarding) the `size` bytes of payload that the untrusted peer declared for that message. On a persistent `Reader`/`bufio.Reader` used to decode a sequence of size-delimited messages — the exact use case this API exists for — the leftover, unconsumed bytes remain in the stream and are reinterpreted as the header/body of the *next* call to `UnmarshalFrom`. This mirrors the CVE-2022-22720 bug class: a parser that fails to fully consume/discard the current unit on error, leaving residual bytes that get reinterpreted as the start of the next unit, causing a request/message boundary desynchronization.

### Finding Description
`UnmarshalFrom` in [1](#0-0)  reads the varint size prefix, then checks it against `MaxSize`:
```go
} else if size > uint64(maxSize) {
    return errors.Wrap(&SizeTooLargeError{Size: size, MaxSize: uint64(maxSize)}, "")
}
```
This `return` happens *before* any attempt to read or skip the `size` bytes of the declared message body [2](#0-1) . The subsequent body-reading logic (`br.Peek`/`br.Discard` or `io.ReadFull`) at [3](#0-2)  is never reached on this error path.

The function is explicitly documented and designed for reading a sequence of framed messages off a stream (`io.Reader`/`*bufio.Reader`), analogous to reading a sequence of HTTP requests off a persistent connection: "MaxSize is the maximum size in wire-format bytes of a single message... A zero MaxSize will default to 4 MiB... corresponds to the default gRPC max request/response size" [4](#0-3) . Callers are expected to call `UnmarshalFrom` repeatedly in a loop over the same reader to decode successive messages, as shown in the package's own tests [5](#0-4) .

Because the oversized-message's payload bytes are never consumed from the underlying reader when `SizeTooLargeError` is returned, an application that catches this per-message error and continues the read loop (a natural pattern, since the error type is specifically designed to be caught and handled per-message via `errors.As`, as shown in `TestMaxSize` [6](#0-5) ) will feed the still-buffered, attacker-controlled bytes of the rejected message back into the *next* `UnmarshalFrom` call. Those bytes get reinterpreted: the first bytes are parsed as a new varint length prefix, and subsequent bytes as a new message body — a stream desynchronization directly analogous to HTTP request smuggling, where a server's failure to discard a rejected request's body causes trailing bytes to be misinterpreted as the start of the next request.

### Impact Explanation
An attacker who controls one message in a stream of size-delimited protobuf messages (e.g., a client submitting a stream of framed messages to a server using `protodelim.UnmarshalFrom` in a loop) can declare an oversized message that trips `MaxSize`, but craft the "oversized payload" bytes such that, once resynchronization occurs on the next `UnmarshalFrom` call, an attacker-chosen size prefix and message body are parsed in place of what the server expected as the legitimately-following message. This can smuggle a message that bypasses whatever per-message validation the size-limit check was meant to enforce, or cause the server to misattribute message boundaries in a multiplexed/pipelined message stream — the protobuf analog of HTTP request smuggling.

### Likelihood Explanation
This requires an application to: (1) use `protodelim.UnmarshalFrom` in a loop over a persistent `Reader` to decode multiple untrusted messages (the documented, intended usage pattern for this API, explicitly designed to mirror gRPC's max-message-size semantics), and (2) catch and continue past `SizeTooLargeError` rather than tearing down the connection. Given the API's stated purpose (streaming multiple size-delimited messages, with a configurable per-message `MaxSize` error meant to be handled gracefully rather than fatally), this is a foreseeable and encouraged usage pattern, making the likelihood credible for services built on this package.

### Recommendation
On the `SizeTooLargeError` path, discard `size` bytes from `r` (e.g., via `io.CopyN(io.Discard, r, int64(size))` or, for the `bufio.Reader` fast-path, `br.Discard`) before returning the error, so the stream remains framing-consistent for subsequent reads. Alternatively, document explicitly that callers MUST NOT continue reading from `r` after any error from `UnmarshalFrom` (including `SizeTooLargeError`), and that the connection must be closed/reset — mirroring the fix direction for CVE-2022-22720.

### Proof of Concept
```go
package main

import (
	"bufio"
	"bytes"
	"fmt"

	"google.golang.org/protobuf/encoding/protodelim"
	"google.golang.org/protobuf/encoding/protowire"
	"google.golang.org/protobuf/internal/testprotos/test3"
)

func main() {
	buf := &bytes.Buffer{}

	// "Rejected" oversized frame: size prefix = 10, but body bytes are
	// attacker-crafted so that, when left unconsumed, they form a valid
	// smuggled follow-on frame.
	buf.Write(protowire.AppendVarint(nil, 10))
	// 10 bytes of payload for the oversized message, crafted so that when
	// resynchronization occurs, a new size+message boundary appears here.
	buf.Write([]byte{
		0x02,                   // <- reinterpreted as size=2 for "next" message
		0x08, 0x2a,             // <- reinterpreted as field 1 varint = 42 (smuggled message)
		0xAA, 0xAA, 0xAA, 0xAA, 0xAA, 0xAA, 0xAA, // filler bytes belonging to the rejected frame
	})

	r := bufio.NewReader(buf)

	out := &test3.TestAllTypes{}
	err := protodelim.UnmarshalOptions{MaxSize: 1}.UnmarshalFrom(r, out)
	fmt.Println("first call error:", err) // *protodelim.SizeTooLargeError, body NOT discarded

	// Application catches SizeTooLargeError and continues the loop,
	// expecting to read the *next* legitimate message...
	out2 := &test3.TestAllTypes{}
	err2 := protodelim.UnmarshalOptions{}.UnmarshalFrom(r, out2)
	fmt.Println("second call error:", err2)
	fmt.Println("second call result:", out2) // populated from smuggled/leftover bytes of the rejected frame
}
```
This demonstrates that bytes belonging to a rejected, oversized frame are never discarded, so they are misinterpreted as an independent, attacker-controlled message on the next read — the message-stream analog of HTTP request smuggling.

func (o UnmarshalOptions) UnmarshalFrom(r Reader, m proto.Message) error {
	var sizeArr [binary.MaxVarintLen64]byte
	sizeBuf := sizeArr[:0]
	for i := range sizeArr {
		b, err := r.ReadByte()
		if err != nil {
			// Immediate EOF is unexpected.
			if err == io.EOF && i != 0 {
				break
			}
			return err
		}
		sizeBuf = append(sizeBuf, b)
		if b < 0x80 {
			break
		}
	}
	size, n := protowire.ConsumeVarint(sizeBuf)
	if n < 0 {
		return protowire.ParseError(n)
	}

	maxSize := o.MaxSize
	if maxSize == 0 {
		maxSize = defaultMaxSize
	}
	if maxSize == -1 {
		// No limit specified: Just check that size fits into an integer,
		// otherwise the make([]byte, size) call below will panic.
		if size > math.MaxInt {
			return errors.Wrap(&SizeTooLargeError{Size: size, MaxSize: math.MaxInt}, "")
		}
	} else if size > uint64(maxSize) {
		return errors.Wrap(&SizeTooLargeError{Size: size, MaxSize: uint64(maxSize)}, "")
	}

func TestMaxSize(t *testing.T) {
	in := &test3.TestAllTypes{SingularInt32: 1}

	buf := &bytes.Buffer{}

	if n, err := protodelim.MarshalTo(buf, in); err != nil {
		t.Errorf("protodelim.MarshalTo(_, %v) = %d, %v", in, n, err)
	}

	out := &test3.TestAllTypes{}
	err := protodelim.UnmarshalOptions{MaxSize: 1}.UnmarshalFrom(bufio.NewReader(buf), out)

	var errSize *protodelim.SizeTooLargeError
	if !errors.As(err, &errSize) {
		t.Errorf("protodelim.UnmarshalOptions{MaxSize: 1}.UnmarshalFrom(_, _) = %v (%T), want %T", err, err, errSize)
	}
	got, want := errSize, &protodelim.SizeTooLargeError{Size: 3, MaxSize: 1}
	if diff := cmp.Diff(want, got); diff != "" {
		t.Errorf("protodelim.UnmarshalOptions{MaxSize: 1}.UnmarshalFrom(_, _): diff -want +got = %s", diff)
	}
}
