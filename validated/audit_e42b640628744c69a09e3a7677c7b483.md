### Title
Unrestricted `TransferToGasKey` actor allows griefing that permanently blocks account/gas-key deletion - (File: `runtime/runtime/src/access_keys.rs`, `runtime/runtime/src/actions.rs`)

### Summary
`action_transfer_to_gas_key` allows **any** transaction/receipt predecessor to increase the `GasKeyInfo.balance` of a gas key on an account it does not own, because `TransferToGasKeyAction` is exempted from the actor-permission check in `check_actor_permissions`. `WithdrawFromGasKey` (which reduces the balance) and `DeleteKey`/`DeleteAccount` (which burn the balance if it is below `MAX_BALANCE_TO_BURN`) are restricted to the account owner or capped by that burn threshold. An attacker can repeatedly fund a victim's gas key(s) past `GasKeyInfo::MAX_BALANCE_TO_BURN`, causing `DeleteKey`/`DeleteAccount` to fail with `GasKeyBalanceTooHigh`, analogous to the referenced report's griefing where an unprivileged party performs an action "on behalf of" a victim to disrupt the victim's ability to exit/withdraw.

### Finding Description
`check_actor_permissions` in `runtime/runtime/src/actions.rs` (around lines 755-801) enforces `actor_id == account_id` for `AddKey`, `DeleteKey`, `Stake`, `DeployContract`, `DeleteAccount`, etc., but explicitly places `Action::TransferToGasKey` in the unrestricted bucket alongside `CreateAccount`, `FunctionCall`, and `Transfer`: [1](#0-0) 

`action_transfer_to_gas_key` in `runtime/runtime/src/access_keys.rs` simply loads the target account's gas key by `(account_id, public_key)` and adds `action.deposit` to `gas_key_info.balance`, with no ownership check of the caller: [2](#0-1) 

By contrast, `action_withdraw_from_gas_key` (which could reduce the balance again) requires the caller to be the account itself, since `WithdrawFromGasKey` is in the restricted list in `check_actor_permissions`: [3](#0-2) 

Deleting a single gas key burns its balance only if it is below `GasKeyInfo::MAX_BALANCE_TO_BURN`; otherwise the whole `DeleteKey` action fails: [4](#0-3) 

Deleting the entire account sums **all** gas-key balances on the account and rejects deletion if that sum exceeds the same threshold: [5](#0-4) 

Because `TransferToGasKey` can be triggered by anyone against any account's gas key, an attacker can push a victim's gas key balance (or the sum across gas keys) above `MAX_BALANCE_TO_BURN` at will, at any time, including immediately after the victim withdraws enough to get below the threshold, mirroring the "deposit on behalf of others resets the state a victim needs to be below" pattern from the report.

### Impact Explanation
This blocks `DeleteKey` for the targeted gas key and blocks `DeleteAccount` for the whole account as long as the aggregate gas-key balance stays above `MAX_BALANCE_TO_BURN`. Since a victim can only reduce the balance via `WithdrawFromGasKey` (owner-only) but the attacker can immediately re-fund it via another `TransferToGasKey` from an outside account, the attacker can perpetually re-grief the account, indefinitely preventing account deletion and the associated storage-stake refund/beneficiary payout in `action_delete_account`. This is a denial-of-service/griefing vector that can permanently freeze an account's ability to reclaim its storage stake and close out, at the low cost of the attacker's deposited (recoverable by the victim, but continuously reappliable) balance and gas fees. It qualifies under "permanently frozen funds" for as long as the attacker chooses to keep grieving, and it is reachable purely by submitting a standard `TransferToGasKeyAction` transaction/receipt from any account — no privileged role required.

### Likelihood Explanation
Likelihood is moderate: `TransferToGasKeyAction` is a normal, permissionless action type reachable from any signed transaction against any target account holding a gas key, requiring only knowledge of the target account id and gas key public key (which is public/discoverable via `view_access_keys`). The attacker's cost is the deposited balance (recoverable if the victim withdraws again, but the attacker can simply re-deposit), plus ordinary gas fees, making repeated griefing cheap and directly analogous to the "cost equals `minDepositAmount` every lockout period" griefing cost model in the original report.

### Recommendation
Restrict `TransferToGasKey` the same way `WithdrawFromGasKey` and `AddKey`/`DeleteKey` are restricted — require `actor_id == account_id` in `check_actor_permissions`, or otherwise require the depositor to hold the account's own access key. If third-party funding of gas keys is an intended feature, the burn-threshold check (`MAX_BALANCE_TO_BURN`) used to gate `DeleteKey`/`DeleteAccount` should not be defeatable by a third party's deposit — e.g., by allowing deletion to burn arbitrarily large balances, or by tracking "self-funded" vs. "externally-funded" balance separately so an account owner is never blocked from deleting their own key/account by funds they did not choose to accept.

### Proof of Concept
1. Victim account `victim.near` creates a gas key `pk_v` with `AddKeyAction` (`access_keys.rs::add_gas_key`), balance starts at `0`.
2. Attacker (any funded account) submits a transaction with `Action::TransferToGasKey(TransferToGasKeyAction { public_key: pk_v, deposit: D })` where `D > GasKeyInfo::MAX_BALANCE_TO_BURN`, targeting `victim.near`. `check_actor_permissions` allows this because `TransferToGasKey` is unrestricted (`runtime/runtime/src/actions.rs:755-801`), and `action_transfer_to_gas_key` performs no ownership check (`runtime/runtime/src/access_keys.rs:257-288`).
3. Victim later attempts `Action::DeleteKey(DeleteKeyAction { public_key: pk_v })` or `Action::DeleteAccount(...)`. Both fail with `GasKeyBalanceTooHigh` because the balance exceeds `MAX_BALANCE_TO_BURN` (`access_keys.rs:93-111`, `actions.rs:370-379`).
4. Even if the victim calls `WithdrawFromGasKey` to drain the balance, the attacker can immediately resubmit `TransferToGasKey` to re-inflate it before the victim's `DeleteKey`/`DeleteAccount` transaction lands, perpetually blocking deletion.

pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) | Action::UniversalStateInit(_) => (),
    };
    Ok(())
}

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}
