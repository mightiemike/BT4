### Title
Stale/reverted Cairo0 class remains servable via the Batcher's shared `ContractClassManager` cache after `revert_block` — ([File: crates/apollo_batcher/src/batcher.rs])

### Summary
The GLPI report describes a deleted/deactivated account whose session cookie is never invalidated, letting the stale credential keep working. The structural analog here is a *stale authorization credential that is never invalidated on the equivalent of a "logout" event*. In the sequencer, `Batcher::revert_block` reverts on-disk class-declaration state but never invalidates the in-memory, cross-request `ContractClassManager`/`GlobalContractCache` that both block-production and view (`call_contract`) paths share. For Cairo0 (deprecated) classes specifically, the code path that re-validates cache hits against current chain state is explicitly skipped, so a class hash that was "declared" in a block that later gets reverted can remain servable from the warm cache indefinitely on that node, while other (cold-cache) honest nodes correctly treat it as undeclared.

### Finding Description
The class cache consistency check lives in `get_compiled_from_class_manager`: [1](#0-0) 

For Cairo1 (V1/V1Native) classes, a cache hit is re-validated against `self.state_reader.is_declared(class_hash)` specifically *because* the comment says the cache "might contain a declared class from a reverted block". For Cairo0 (`RunnableCompiledClass::V0(_)`), this re-validation is intentionally skipped, because `is_declared` is defined to always return `false` for Cairo0 classes: [2](#0-1) [3](#0-2) 

So the *only* remaining safeguard against serving a stale/reverted Cairo0 class is clearing the entire global cache whenever a block revert happens. That safeguard exists in the legacy Python-integration path: [4](#0-3) 

But the production Rust `Batcher::revert_block`, which is the path actually invoked by consensus reverts (`ConsensusManager::revert_batcher_blocks` → `BatcherClient::revert_block`), only reverts on-disk storage (headers/body/state-diff/commitment) — it never calls `contract_class_manager.clear()` or otherwise invalidates the shared `ContractClassManager`/`GlobalContractCache`: [5](#0-4) [6](#0-5) 

The underlying `GlobalContractCache` is a simple LRU with no TTL/versioning tied to block height: [7](#0-6) 

And a batcher test explicitly documents that the same `ContractClassManager` instance backs both view calls (`call_contract`) and block-production execution, i.e., it is a single long-lived, cross-height cache: [8](#0-7) 

Storage-side revert does correctly remove the Cairo0 class from the `deprecated_declared_classes` table (confirmed by the revert unit tests), so on-disk state and in-memory cache diverge after a revert: [9](#0-8) [10](#0-9) 

### Impact Explanation
This is a state/consensus-safety issue, not a "network-DoS"/"malicious-operator" issue: it is triggered by ordinary chain-revert handling (a normal, expected sequencer operation) combined with any transaction path that reads a Cairo0 class (`get_compiled_class`). A node whose cache was warmed with the reverted class (e.g. from prior block execution or a `call_contract` RPC) will continue to treat the class hash as declared/executable, while a node with a cold cache (or that restarted after the revert) will correctly reject it as `UndeclaredClassHash`. Any subsequent transaction whose validity depends on this class hash (e.g. a `deploy_account`/`invoke` against a contract instance carrying that class hash, or attempting to redeclare it) can therefore execute successfully on some honest nodes and fail on others for the *same* input — a nondeterministic execution result that leads to honest-node state divergence / differing computed state roots for the same block. This falls squarely in the "honest-node divergence" impact category the prompt accepts, is reachable purely from a normal transaction submission (no malicious operator/proposer needed) once a revert has occurred, and is Medium severity given it requires the (routine, not rare) precondition of a block revert plus a warm cache — matching the CVSS profile (AC:H) of the original GLPI report.

### Likelihood Explanation
Block reverts are a normal, periodically-occurring event in this codebase (consensus-triggered reverts, sync catch-up, etc. all call `Batcher::revert_block`). Any prior read of the class (block execution, mempool validation, or an RPC `call_contract`) is sufficient to warm the cache. No special privileges are needed by the transaction sender — the divergence is purely a function of node cache state versus committed storage state, so likelihood is moderate: it depends on the specific class hash having been read into the cache before the revert, which is plausible for actively-used classes/contracts but not guaranteed for every class.

### Recommendation
Invalidate (or version-tag by block height) the shared `ContractClassManager`/`GlobalContractCache` inside `Batcher::revert_block`, mirroring what `py_block_executor::revert_block` already does (`self.contract_class_manager.clear()`), and additionally remove the special-case skip for `RunnableCompiledClass::V0` in `get_compiled_from_class_manager` so Cairo0 cache hits are also revalidated against current storage state (e.g., by extending `is_declared`/`FetchCompiledClasses` to cover deprecated classes as well, rather than defining it to be unconditionally `false` for V0).

### Proof of Concept
1. Node executes/serves a block that deprecated-declares Cairo0 class `C` at hash `h`, and some component (block execution or a `call_contract` view) causes `h` to be inserted into the shared `ContractClassManager` cache via `get_compiled_from_class_manager`.
2. Consensus/sync triggers `Batcher::revert_block` for that height. Storage correctly deletes `h` from `deprecated_declared_classes` (per `delete_deprecated_declared_classes`), but the in-memory `ContractClassManager` cache entry for `h` is untouched (no `.clear()` call in `Batcher::revert_block`).
3. A subsequent transaction (e.g., an `Invoke`/`DeployAccount`) referencing class hash `h` is executed on this node: `get_compiled_from_class_manager` hits the cache, sees `RunnableCompiledClass::V0`, skips the `is_declared` check, and returns the stale compiled class successfully.
4. A second honest node that did not warm its cache for `h` (fresh restart, or simply never executed/queried that class before) calls `state_reader.get_compiled_classes(h)` on the same transaction and correctly returns `UndeclaredClassHash`, causing the transaction to fail/revert differently.
5. The two honest nodes compute different execution results (and thus different state roots) for the same transaction/block, demonstrating consensus-breaking divergence caused purely by the stale, un-invalidated class cache after `revert_block`.

        &self,
        class_hash: ClassHash,

        if let Some(runnable_class) =

                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);

    pub async fn revert_block(&mut self, input: RevertBlockInput) -> BatcherResult<()> {
        info!("Reverting block at height {}.", input.height);
        let height = self.get_height_from_storage()?.prev().ok_or(

                marker_height: BlockNumber(0),
                requested_height: input.height,
            },

            return Err(BatcherError::StorageHeightMarkerMismatch {
                marker_height: height.unchecked_next(),
                requested_height: input.height,
            });
        }

        if let Some(height) = self.active_height {
            info!("Aborting all work on height {} due to a revert request.", height);
            self.abort_active_height().await;
        }

        // Wait for the revert commitment to be completed before reverting the storage.
        self.revert_commitment(height).await;

        self.storage_writer.revert_block(height);
        BUILDING_HEIGHT.decrement(1);
        GLOBAL_ROOT_HEIGHT.decrement(1);
        REVERTED_BLOCKS.increment(1);
        Ok(())
    }

use cached::{Cached, SizedCache};

use crate::core::ClassHash;

type ContractLRUCache<T> = SizedCache<ClassHash, T>;
type LockedClassCache<'a, T> = MutexGuard<'a, ContractLRUCache<T>>;

// TODO(Yoni, 1/2/2025): consider defining CachedStateReader.
/// Thread-safe LRU cache for contract classes (Sierra or compiled Casm/Native), optimized for
/// inter-language sharing when `blockifier` compiles as a shared library.
#[derive(Clone, Debug)]
pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }
}

fn delete_deprecated_declared_classes<'env>(
    txn: &'env DbTransaction<'env, RW>,
    block_number: BlockNumber,
    thin_state_diff: &ThinStateDiff,
    deprecated_declared_classes_table: &'env DeprecatedDeclaredClassesTable<'env>,
    file_handlers: &FileHandlers<RW>,
) -> StorageResult<IndexMap<ClassHash, DeprecatedContractClass>> {
    // Class hashes of the contracts that were deployed in this block.
    let deployed_contracts_class_hashes = thin_state_diff.deployed_contracts.values();

    // Merge the class hashes from the state diff and from the deployed contracts into a single
    // unique set.
    let class_hashes: HashSet<&ClassHash> = thin_state_diff
        .deprecated_declared_classes
        .iter()
        .chain(deployed_contracts_class_hashes)
        .collect();

    let mut deleted_data = IndexMap::new();
    for class_hash in class_hashes {
        // If the class is not in the deprecated classes table, it means that either we didn't
        // download it yet or the hash is of a deployed contract of a new class type. We've decided
        // to avoid deleting these classes because they're from at most 0.11.
        if let Some(IndexedDeprecatedContractClass {
            block_number: declared_block_number,
            location_in_file,
        }) = deprecated_declared_classes_table.get(txn, class_hash)?
        {
            // If the class was declared in a different block then we should'nt delete it.
            if block_number == declared_block_number {
                deleted_data.insert(
                    *class_hash,
                    file_handlers.get_deprecated_contract_class_unchecked(location_in_file)?,
                );
                deprecated_declared_classes_table.delete(txn, class_hash)?;
            }
        }
    }

    Ok(deleted_data)
}
