### Title
Starknet OS `execute_replace_class` omits the "class must be declared" check enforced by the Blockifier, allowing a state root / block hash divergence between sequencer execution and OS proof - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `replace_class` syscall handler in the Blockifier (the component that executes transactions on the live sequencer) explicitly validates that the target `class_hash` has actually been declared before allowing a contract to replace its class, by calling `get_compiled_class(request.class_hash)` and propagating the error if undeclared. [1](#0-0) 

The Starknet OS's own re-implementation of the same syscall, `execute_replace_class`, used both for the deprecated (Cairo0) execution path and the Cairo1 syscall path, does **not** perform this check. This is called out by the code's own TODO comment. [2](#0-1) [3](#0-2) 

### Finding Description
The `replace_class` syscall lets any contract, at any unprivileged caller's request, change its own `class_hash` in state (this is a standard Starknet syscall, reachable from any invoke transaction as long as the called contract exposes a code path invoking `replace_class_syscall`, e.g. a test/utility contract or any user-deployed contract).

Two independent implementations of this syscall exist in the sequencer:
1. **Blockifier** (`crates/blockifier/...`), which performs real execution when building/validating blocks. Its `replace_class` handler reads the compiled class for `request.class_hash` via `state.get_compiled_class(...)` before mutating the class hash — if the class was never declared, execution of that syscall/entry point fails with a "not declared" error, as confirmed by the corresponding tests. [4](#0-3) [5](#0-4) 

2. **Starknet OS** (`crates/apollo_starknet_os_program/...`), the Cairo program that re-executes the same block's transactions to produce the STARK proof and the committed state root / block hash. Its `execute_replace_class` functions (for both the deprecated/Cairo0 execution path and the Cairo1 syscall path) unconditionally accept the request's `class_hash`, write it into `contract_state_changes`, and record a `CHANGE_CLASS_ENTRY` in the revert log — with an explicit unresolved `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` [6](#0-5) 

Because the OS is supposed to be a faithful, protocol-conformant re-execution of exactly what the Blockifier did (it consumes the actual execution trace/hints from the sequencer and is expected to reproduce the same state transitions when computing the block's state commitment), any place where the OS's semantics are more permissive than the Blockifier's is a soundness gap: the OS can accept and commit a state transition that the Blockifier itself would have rejected (reverted) during real execution.

### Impact Explanation
This is not merely a permission bug like the reference "onlyOwner" report — it is the sequencer-analog: a validation/authorization asymmetry between the two authoritative execution paths of the protocol. An unprivileged transaction sender who deploys or calls a contract that invokes `replace_class_syscall` with an undeclared (attacker-chosen, arbitrary) class hash will:
- Have the syscall **fail/revert** under real Blockifier execution (correct behavior, protects against replacing a contract's implementation with a nonexistent/garbage class).
- Have the syscall **succeed** under the Starknet OS's re-execution, silently applying `CHANGE_CLASS_ENTRY`/setting the contract's class hash to the undeclared value in the OS's view of `contract_state_changes`.

If the OS's execution trace and hints diverge from what the sequencer's real state actually produced (i.e., the hinted `state_entry`/success path assumes the syscall succeeded when the sequencer's Blockifier would have reverted it), this yields:
- A wrong committed state root / block hash being proven and posted, diverging from the sequencer's real state (honest-node divergence between the executing sequencer and the OS-proof output).
- A contract's class hash being set to an undeclared class in the proven state — an unauthorized/invalid state mutation with no corresponding valid code, corrupting that contract's on-chain represented behavior, and permanently affecting anyone interacting with it.

This satisfies the "wrong committed root or block hash" / "honest-node divergence" impact bar from the rules, reached purely by an unprivileged transaction sender invoking a standard syscall — no privileged operator/prover role required to trigger the divergence (though the proving/committing pipeline is what ultimately surfaces the wrong root).

### Likelihood Explanation
`replace_class` is a syscall exposed to any contract in the Cairo1/Cairo0 execution model; test/utility contracts in this very repository (`test_contract.cairo`'s `test_replace_class`) demonstrate the trivial calldata needed to invoke it with an arbitrary class hash. Any account or contract deployed by an unprivileged user could similarly expose (directly or via delegate/library call) a path to `replace_class_syscall` with attacker-supplied `class_hash`. The bug is deterministic — not timing- or race-dependent — and the divergent code paths (Blockifier check vs. missing OS check) are both present and unconditionally reachable whenever this syscall executes with an undeclared class hash.

### Recommendation
Add the same "class must be declared" validation to the OS's `execute_replace_class` in both `syscall_impls.cairo` (Cairo1 path) and `deprecated_execute_syscalls.cairo` (Cairo0 path), mirroring the Blockifier's `get_compiled_class`/declared-class check, before writing the new `state_entry`/`CHANGE_CLASS_ENTRY`. This resolves the noted `TODO(Yoni, 1/1/2026)` and restores parity between the two execution engines so that the OS cannot commit state transitions the Blockifier would have rejected.

### Proof of Concept
1. An unprivileged user deploys (or reuses) a contract exposing an entry point that calls `replace_class_syscall(class_hash)` with a `class_hash` value that has never been declared (e.g., the pattern used in `test_replace_class` at [7](#0-6) ).
2. Submit an INVOKE transaction calling that entry point with an arbitrary undeclared `class_hash`.
3. Under Blockifier execution, this syscall fails with "class ... is not declared" (see the negative-flow assertions in `deprecated_syscalls_test.rs:375-391` and `replace_class.rs:15-29`), so the real sequencer state's `class_hash_at(contract)` is unchanged.
4. Under the Starknet OS's re-execution (`execute_replace_class` in `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo`), the missing declared-class check means the corresponding hinted execution path can accept the syscall and write the undeclared `class_hash` into `contract_state_changes`, producing a `CHANGE_CLASS_ENTRY` — a state transition inconsistent with what the Blockifier actually computed.

Note: full confirmation that this divergence is exploitable end-to-end (i.e., that no other layer — such as the hint generation from the sequencer's own execution trace — implicitly forces the OS onto the same reverted path) would require tracing how `GetContractAddressStateEntry`/hints are populated from the Blockifier's actual `CallInfo`/revert data for a failed inner call, which was not fully explored here due to tool-call limits. The code-level asymmetry (Blockifier enforces the check; OS explicitly marks it as a `TODO`, unimplemented) is confirmed directly from the source.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
