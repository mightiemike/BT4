## Analog Vulnerability Found

### Title
Failed `GAS`-type outbounds are never re-minted on Push Chain, permanently burning user gas funds — (File: `x/uexecutor/keeper/outbound.go`)

### Summary
This is the Push Chain analog of the Livepeer `L1Migrator.migrateETH()` bug: value that has already been withdrawn/committed on one side of a bridge is not properly reconciled back when the corresponding cross-chain send fails, causing permanent loss of funds. In Push Chain, `handleFailedOutbound` only re-mints (reverts) the bridged PRC20 amount for `TxType_FUNDS`, `TxType_GAS_AND_PAYLOAD`, and `TxType_FUNDS_AND_PAYLOAD`. A `TxType_GAS` outbound — whose token amount is already burned/withdrawn on the EVM side (`UniversalGatewayPC`) at outbound-creation time — is silently excluded from this list, so if the outbound broadcast fails on the destination chain, the burned funds are never returned to the user.

### Finding Description
`BuildOutboundsFromReceipt` decodes `UniversalTxOutboundEvent` logs emitted by `UNIVERSAL_GATEWAY_PC` and creates an `OutboundTx` with whatever `TxType` the EVM contract encoded (`SolidityTxTypeToProto`), including `TxType_GAS`, which per the module's own documentation represents "refund of unused gas back to a source chain." [1](#0-0) 

When Universal Validators later vote that this outbound failed on the destination chain, `FinalizeOutbound` calls `handleFailedOutbound`: [2](#0-1) 

The re-mint (`CallPRC20Deposit`) branch is gated by an explicit `TxType` allowlist that omits `TxType_GAS`:
```go
if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
    outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {
``` [3](#0-2) 

For a `TxType_GAS` outbound, execution falls straight through to marking the outbound `Status_REVERTED` and only running `applyGasRefund` — which computes and refunds *excess gas fee* (`gasFee - gasFeeUsed`), a completely separate accounting bucket from the outbound's own `Amount`: [4](#0-3) [5](#0-4) 

Because the PRC20 for this amount was already burned/withdrawn on Push Chain when the EVM gateway emitted the `UniversalTxOutbound` event (that's what makes it eligible to become a pending outbound in the first place), and the destination-chain vault transaction subsequently failed (broadcast failure, revert, or destination-chain issue reported honestly by UVs), the withdrawn amount has no path back to the user. It is neither delivered externally (broadcast failed) nor re-minted internally (missing from the allowlist) — a direct structural match to the original bug, where `BridgeMinter`'s withdrawn ETH was neither delivered to L2 nor recoverable on L1.

### Impact Explanation
Any `GAS`-type outbound that fails on the destination chain results in permanent loss of the associated bridged/withdrawn amount for the affected user — a protocol-level fund-freezing/loss bug reachable purely by an honest destination-chain failure (network hiccup, gas spike causing tx revert, destination contract issue) with no privileged actor involved. This falls squarely within the "permanent loss/permanent freezing of user or protocol-controlled funds" impact category.

### Likelihood Explanation
The trigger requires only an ordinary user's cross-chain flow that produces a `TxType_GAS` outbound, followed by an honest failure vote from Universal Validators on the destination-chain broadcast (a routine, non-adversarial occurrence — gas spikes, RPC issues, or destination reverts are common). No malicious validator, relayer, or privileged actor assumption is required, matching the in-scope "denial of service / fund loss reachable from ordinary user deposits and default transaction submission paths."

### Recommendation
Add `types.TxType_GAS` to the fund-revert allowlist in `handleFailedOutbound` (and audit whether `TxType_PAYLOAD`, `TxType_INBOUND_REVERT`, and `TxType_RESCUE_FUNDS` outbounds can also carry non-zero withdrawn amounts requiring the same reconciliation), so that any outbound type whose `Amount` was debited/burned on Push Chain at creation time is re-minted back to the appropriate recipient when the destination-chain execution is observed to have failed.

### Proof of Concept
1. A user submits a cross-chain payload/action on Push Chain that results in the EVM `UNIVERSAL_GATEWAY_PC` contract emitting a `UniversalTxOutbound` event with `txType = GAS` and a non-zero `Amount` (gas refund back to the source chain). At this point the PRC20/gas-token amount is already withdrawn/burned on Push Chain.
2. `BuildOutboundsFromReceipt` creates a `PENDING` `OutboundTx` with `TxType_GAS` and the withdrawn `Amount`, indexed in `PendingOutbounds`.
3. Universal Validators sign and broadcast the corresponding vault transaction on the source/destination chain via `GetOutboundSigningRequest` / `BroadcastOutboundSigningRequest`.
4. The broadcast transaction fails or reverts on the external chain for a normal, non-malicious reason (e.g., insufficient vault balance, destination contract revert, gas spike).
5. Honest Universal Validators observe the failure and submit `MsgVoteOutbound` with `success = false`.
6. `FinalizeOutbound` → `handleFailedOutbound` runs: since `outbound.TxType == TxType_GAS`, the `if` block re-minting funds via `CallPRC20Deposit` is skipped entirely; only `applyGasRefund` runs (refunding just the unused-gas-fee delta, not the outbound `Amount`).
7. The outbound is marked `Status_REVERTED`, but the underlying `Amount` that was withdrawn from Push Chain for this `GAS` outbound is never re-minted to the user — it is permanently lost.

// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely

		if outbound.RevertInstructions != nil &&

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
