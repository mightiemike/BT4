### Title
Factory proxy contract deployed at genesis is never initialized, allowing any attacker to front-run `initialize()` and seize ownership - (File: x/uexecutor/keeper/genesis.go)

### Summary
The reported MultiSig bug class is "a base constructor/initializer that assigns `initialOwner` is never invoked, so the owner-gated state is left at its zero/default value." The native analog is the `x/uexecutor` UEA Factory proxy: `deployFactoryEA` (via `deployFactoryProxy`/`deployFactoryImplContract`/`deployProxyAdminContract`) writes the Factory's EIP-1967 proxy/implementation bytecode and storage slots directly at genesis, but never calls the Factory's own `initialize(address initialOwner)` function defined in `FactoryV1ABI` [1](#0-0)  that is supposed to set the owner used by `onlyOwner`-gated admin functions such as `setUEAProxyImplementation` and `registerNewChain`/`registerUEA`.

### Finding Description
`InitGenesis` calls `deployFactoryEA` only on fresh (non-exported) genesis [2](#0-1) , which in turn deploys the implementation, proxy-admin, and proxy contracts by directly writing EVM account/code/storage slots: [3](#0-2) 

Unlike the `ProxyAdmin` contract, whose `Ownable.owner` storage slot is explicitly and directly written during deployment [4](#0-3) , the Factory implementation/proxy deployment never writes an owner slot and never issues an EVM call to the Factory's `initialize(initialOwner)` method. The only place in the whole indexed codebase that ever calls `initialize` on the Factory is a test helper, which does it manually and even logs the pre/post owner to confirm it starts unset: [5](#0-4) 

This test-only call pattern confirms that production genesis wiring in `x/uexecutor/keeper/genesis.go` does not invoke `initialize` on the Factory — exactly analogous to the reported bug where `Ownable`'s base constructor is skipped so `initialOwner` is never assigned.

### Impact Explanation
The Factory ABI's `initialize(address initialOwner)` matches the standard OpenZeppelin `Initializable` + `Ownable` pattern used behind upgradeable proxies: the `initializer` modifier only prevents *re*-initialization, it does not restrict *who* may call it the first time. Because genesis deployment never calls `initialize`, the Factory proxy remains in its "uninitialized" state with `owner() == address(0)` once deployed on a live network. Any unprivileged external account can then be the first to call `initialize(attacker)` and become the permanent owner of the Factory contract. From there, the attacker controls `setUEAProxyImplementation` (which sets the implementation address used by every UEA proxy deployed through `deployUEA`) and `registerNewChain`/`registerUEA` (which control chain-to-implementation routing). This lets the attacker point all subsequently-deployed Universal Execution Accounts (UEAs) at an attacker-controlled implementation, enabling arbitrary state manipulation, fund theft/drain, or unauthorized execution across every user account routed through the Factory — a direct violation of the "unauthorized UEA/CEA execution" and "unauthorized module-originated EVM execution" invariants in scope.

### Likelihood Explanation
High, assuming this genesis code path runs unmodified on a real network launch: the race to call `initialize` first is trivially winnable by any bot watching the genesis block/first block for the known, deterministic `FACTORY_PROXY_ADDRESS_HEX` address, since deployment happens deterministically at genesis and no other actor calls `initialize` first. The likelihood should be treated as uncertain to the extent that the actual Factory Solidity implementation bytecode (`FactoryImplRuntimeBytecode`) is not available in the indexed code, so it cannot be 100% confirmed from source that the deployed bytecode uses the standard `Initializable` guard (only that its ABI declares an `initialize(initialOwner)` method, consistent with that pattern, and the deployment code writes no analogous owner storage slot the way `ProxyAdmin` does).

### Recommendation
In `deployFactoryEA` / `deployFactoryProxy` (`x/uexecutor/keeper/genesis.go`), either:
1. Directly set the Factory's owner storage slot at genesis (mirroring what `deployProxyAdminContract` already does for the `ProxyAdmin` owner slot), or
2. Issue a `DerivedEVMCall`/`CallEVM` to `initialize(initialOwner)` against the Factory proxy address immediately after deploying it, using a deterministic, trusted owner address (e.g., the same `PROXY_ADMIN_OWNER_ADDRESS_HEX` constant), before the chain accepts any external transactions.

### Proof of Concept
Given the indexed code, the concrete reachable trigger is:
1. Chain launches from genesis; `InitGenesis` runs `deployFactoryEA`, deploying implementation/proxy-admin/proxy contracts for the Factory at the well-known constant addresses (`FACTORY_IMPL_ADDRESS_HEX`, `FACTORY_PROXY_ADDRESS_HEX`) [3](#0-2)  without ever calling `initialize`.
2. An attacker submits a normal EVM transaction calling `FactoryV1ABI.initialize(attackerAddress)` on `FACTORY_PROXY_ADDRESS_HEX` in the first available block — nothing in the deployment code prevents this because no owner was ever set.
3. The attacker is now the Factory owner and can call `setUEAProxyImplementation`/`registerNewChain`/`registerUEA` to redirect UEA deployment/execution to attacker-controlled logic.

I was not able to directly inspect the Factory's Solidity/bytecode source (`FactoryImplRuntimeBytecode`) to confirm the exact `initializer` guard semantics, since the raw bytecode/source is not present in the indexed files — only the ABI and deployment wiring were available. A Devin session with full repository access would be needed to confirm the exact bytecode behavior and any existing mitigations before treating this as fully confirmed.

func setupFactoryContract(
	t *testing.T,
	app *app.ChainApp,
	ctx sdk.Context,
	factoryABI abi.ABI,
	opts AppSetupOptions,
	accounts TestAccounts,
) error {
	factoryAddr := opts.Addresses.FactoryAddr
	owner := common.BytesToAddress(accounts.DefaultAccount.GetAddress().Bytes())

	// Check initial factory owner
	ownerResult, err := app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after genesis: %s", common.BytesToAddress(ownerResult.Ret).Hex())

	// Initialize factory with owner
	_, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "initialize", owner)
	require.NoError(t, err)

	// Verify owner is set
	ownerResult, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after initialization: %s", common.BytesToAddress(ownerResult.Ret).Hex())
