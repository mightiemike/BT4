### Title
Global contract identity bound to a mutable, reusable AccountId enables silent code hijack for all referencing accounts - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
`DeployGlobalContractAction` with `GlobalContractDeployMode::AccountId` and `UseGlobalContractAction` referencing `GlobalContractIdentifier::AccountId(id)` bind trust to a plain `AccountId` rather than to an immutable identity. Neither the deploy path nor the use path validates that the entity currently controlling `id` is the same one that originally published the code, and account deletion does not invalidate or clear the associated global-contract state. Because `RuntimeContractIdentifier::resolve` always re-resolves the current code for `AccountId(id)` at call time, any subsequent redeploy under that identifier retroactively and silently changes the executable code for every account that ever called `UseGlobalContractByAccountId(id)`, with no consent step from those accounts. This directly mirrors the reported `setTranche`-style bug class: an address-like reference is accepted without binding/verification, and changing what it points to afterwards breaks dependent functionality.

### Finding Description
- `validate_use_global_contract_action` (`runtime/runtime/src/action_validation.rs:301-307`) only checks that the referenced `AccountId` is syntactically valid via `validate_global_contract_identifier` (`runtime/runtime/src/action_validation.rs:592-600`). It performs no check tying the identifier to a specific, immutable owner.
- `use_global_contract` (`runtime/runtime/src/global_contracts.rs:76-108`) only checks that `TrieKey::GlobalContractCode{identifier}` currently exists; it stores `AccountContract::GlobalByAccount(id)` on the caller's account — a live pointer, not a pinned code hash.
- `action_deploy_global_contract` / `initiate_distribution` (`runtime/runtime/src/global_contracts.rs:25-63`, `143-171`) let whoever currently controls account `id` (re)deploy code under `GlobalContractIdentifier::AccountId(id)` at any time, overwriting the previous code for that identifier. This is documented as intentional for the *original* owner ("This allows the owner to update the contract for all its users" — `core/primitives/src/action/mod.rs:140-143`), but nothing enforces that the redeployer is the *same* logical owner over time.
- `remove_account` (`core/store/src/utils/mod.rs:505-575`), invoked from `action_delete_account` (`runtime/runtime/src/actions.rs:330-406`), removes the `Account`, its local `ContractCode`, access keys, gas-key nonces, and contract data — but never removes/invalidates the `TrieKey::GlobalContractCode{AccountId(id)}` entry.
- Account creation rules (`runtime/runtime/src/actions.rs`, documented in `protocol-model/spec/accounts-keys.md:71`) allow **any** unprivileged signer to create a *top-level* account whose length is `>= min_allowed_top_level_account_length` without registrar permission.
- `RuntimeContractIdentifier::resolve` (`runtime/runtime/src/contract_code.rs:36-73`) re-resolves `GlobalByAccount(id)` to whatever code is currently stored under that identifier on every `FunctionCall`, i.e. there is no snapshot/pinning at `UseGlobalContract` time.

Putting this together: an attacker (or the original publisher acting maliciously later) can publish a benign-looking global contract under a long top-level `AccountId`, get it adopted by unrelated accounts via `UseGlobalContractByAccountId`, delete that account (self-deletion is unrestricted here since global-contract storage is not charged against the depositing account's own `storage_usage`, so it doesn't trip `MAX_ACCOUNT_DELETION_STORAGE_USAGE`), and then have anyone recreate an account with that exact name (since long top-level names require no registrar) and redeploy new code under the *same* `AccountId` identifier. Every account that previously called `UseGlobalContractByAccountId` on that identifier will transparently start executing the new code the next time it makes a `FunctionCall`, without submitting any transaction of their own.

### Impact Explanation
This allows unauthorized value movement: malicious code substituted under a previously-trusted `GlobalContractIdentifier::AccountId` executes with the calling context (balance, storage, promises) of every victim account that referenced it, and can issue arbitrary `Transfer`/`FunctionCall` promise actions (e.g., drain balances to an attacker-controlled account) the next time those victim accounts are invoked — with zero action or consent from the victims. This is a concrete state-transition/trust violation reachable purely through ordinary, unprivileged transactions (`CreateAccount`, `DeployGlobalContract`, `UseGlobalContract`, `DeleteAccount`).

### Likelihood Explanation
Reachable end-to-end by any transaction signer using only standard actions; no validator, network, or privileged role is required. The only precondition is that some victim account previously opted into `UseGlobalContractByAccountId` for the attacker's identifier (a normal adoption pattern the feature is designed to encourage for widely shared code), and that the identifier's `AccountId` is either a name the attacker/original publisher controls or a sufficiently long top-level name (which anyone can (re)claim after deletion).

### Recommendation
- Bind `UseGlobalContractAction`'s `AccountId` mode to an immutable value at use-time (e.g., pin the resolved code hash instead of dynamically re-resolving the current code for `AccountId(id)` on every call), or require an explicit re-`UseGlobalContract` action to adopt updated code.
- On `action_delete_account`, clear or tombstone the `GlobalContractCode{AccountId(id)}` entry (and any dependent `GlobalByAccount` references) so a recreated account of the same name cannot silently inherit control over a previously published global contract.
- Alternatively, disallow `DeleteAccount` for an account that currently owns a live `AccountId`-mode global contract with active consumers, or require the deploying account id itself to be immutable (i.e., only allow `GlobalContractDeployMode::CodeHash` for identifiers reachable via `UseGlobalContractByAccountId` semantics that are meant to be shared long-term).

### Proof of Concept
1. Attacker signs `CreateAccount` for a top-level id `L` with `len(L) >= min_allowed_top_level_account_length` (no registrar required, per `protocol-model/spec/accounts-keys.md:71`).
2. Attacker signs `DeployGlobalContractAction{ code: benign_code, deploy_mode: AccountId }` on `L` (`runtime/runtime/src/global_contracts.rs:25-63`).
3. Victim `V` signs `UseGlobalContractAction{ contract_identifier: AccountId(L) }`; `V.contract` becomes `AccountContract::GlobalByAccount(L)` (`runtime/runtime/src/global_contracts.rs:76-108`).
4. Attacker signs `DeleteAccountAction` on `L` with `beneficiary_id = attacker2`; `remove_account` deletes `L`'s account/keys but leaves `TrieKey::GlobalContractCode{AccountId(L)}` untouched (`core/store/src/utils/mod.rs:505-575`).
5. Anyone signs `CreateAccount` to recreate `L` (allowed, same rule as step 1), then `DeployGlobalContractAction{ code: malicious_code, deploy_mode: AccountId }` on `L`, overwriting the code at `GlobalContractCode{AccountId(L)}`.
6. Next time `V` (or anything else that previously did `UseGlobalContractByAccountId(L)`) is invoked via `FunctionCall`, `RuntimeContractIdentifier::resolve` (`runtime/runtime/src/contract_code.rs:36-73`) fetches the new malicious code and executes it under `V`'s account context, with no transaction from `V` involved. fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,

    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
