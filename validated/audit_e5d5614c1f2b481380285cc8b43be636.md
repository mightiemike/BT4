### Title
Unbounded gzip decompression of attacker-supplied Cairo-0 contract class program causes sequencer node OOM — ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The RPC write-API's `decompress_program` helper decompresses a base64/gzip-encoded legacy contract `program` supplied inside a `BroadcastedDeclareV1Transaction` with **no size limit and no time limit**, unlike every other decompression path in this codebase (which all use `decode_and_decompress_with_size_limit`/`decompress_with_size_limit` bounded by a configured `max_size`). This mirrors CVE-2024-29025 exactly: attacker-controlled input causes unbounded server-side memory accumulation, producing an OOM.

### Finding Description
`decompress_program` reads the caller-supplied `compressed_program` field, gzip-decompresses it fully into a `Vec<u8>` with no cap, then parses it as JSON: [1](#0-0) 

The `TODO(dan): add time and size limits.` comment on this exact function acknowledges the gap. This is reachable from an unprivileged RPC caller through the standard `try_into::<ExecutableTransactionInput>()` conversion of a `BroadcastedDeclareTransaction::V1`: [2](#0-1) 

which is invoked by the RPC "write API" endpoints for fee estimation and transaction simulation (`starknet_estimateFee`, `starknet_simulateTransactions`) on any `BROADCASTED_DECLARE_TXN_V1` (Cairo-0 declare, containing a `DEPRECATED_CONTRACT_CLASS` with a `compressed_program` string): [3](#0-2) 

By contrast, every other decompression path in the repository (gateway's deprecated-gateway declare conversion, storage serde for `SierraContractClass`/`DeprecatedContractClass`/`CasmContractClass`) explicitly enforces a byte-size cap before or during decompression: [4](#0-3) [5](#0-4) 

`decompress_program` is the one path that skips this defense entirely — a small base64 gzip payload (a classic "zip bomb") can decompress to an arbitrarily large buffer, exhausting process memory before any of the stateless/stateful gateway-side size checks (`max_contract_bytecode_size`, `max_contract_class_object_size`, `max_sierra_program_size`) are ever consulted, because this is the RPC execution path, not the gateway ingestion path.

### Impact Explanation
This node exposes the RPC service, gateway, mempool, batcher and consensus roles from the **same consolidated binary** in supported deployment topologies. An OOM crash triggered via the RPC `estimateFee`/`simulateTransactions` endpoints can therefore terminate the same process hosting the sequencer's gateway/mempool/batcher/consensus components, halting block production — i.e., "a network unable to confirm new transactions" if the affected node is the active sequencer. Even in split deployments, this is a reliable, cheap, remotely-triggerable resource-exhaustion primitive (CWE-770) against any node exposing this RPC method.

### Likelihood Explanation
High. This requires only a single unauthenticated JSON-RPC call (`starknet_estimateFee` or `starknet_simulateTransactions`) with a crafted `BROADCASTED_DECLARE_TXN_V1` whose `contract_class.program` is a small, highly-compressible gzip/base64 payload. No on-chain funds, valid signature validity, or prior state are required since decompression happens before validation succeeds/fails.

### Recommendation
Apply the same bounded-decompression pattern used elsewhere in the codebase: replace the manual `GzDecoder::read_to_end` in `decompress_program` with a size-limited read (e.g., `Read::take(max_size)` followed by an explicit length check, matching `decompress_with_size_limit` in `crates/starknet_api/src/compression_utils.rs`), and enforce a configured maximum decompressed program size (consistent with `max_sierra_program_size` / `max_contract_bytecode_size`) before attempting `serde_json::from_reader`.

### Proof of Concept
1. Craft a `program` JSON blob of size just under any incidental limits, gzip it, and construct a payload where the compressed form base64-encodes to a modest string but decompresses (via repeated/structured content) to many GBs.
2. Submit it as `contract_class.compressed_program` inside a `BROADCASTED_DECLARE_TXN_V1` to `starknet_estimateFee` or `starknet_simulateTransactions`.
3. `user_deprecated_contract_class_to_sn_api` → `decompress_program` decompresses the payload fully into memory with no cap, exhausting available RAM and crashing/OOM-killing the process before any subsequent validation runs.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
