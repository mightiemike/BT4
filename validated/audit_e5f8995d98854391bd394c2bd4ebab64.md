### Title
Unsanitized `shop` query parameter reflected into CSP `frame-ancestors` and Link headers in `renderAppBridge` (shopify-app-remix) - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/render-app-bridge.ts`)

### Summary
The `shopify-app-remix` package's `renderAppBridge` helper passes the raw, attacker-controlled `shop` URL search parameter directly into `addDocumentResponseHeaders`, which embeds it verbatim into the `Content-Security-Policy: frame-ancestors` directive and the preconnect `Link` header, with no validation/sanitization at that call site. The sibling `shopify-app-react-router` package (which shares essentially identical code) was hardened to call `api.utils.sanitizeShop(...)` before passing `shop` into the same helper — this fix does not appear to be present in `shopify-app-remix`.

### Finding Description
`renderAppBridge` in `shopify-app-remix` reads the `shop` param straight from the request URL and forwards it unsanitized: [1](#0-0) 

That value flows into `addDocumentResponseHeaders`, which builds the CSP header by string interpolation with no escaping or validation of `shop`: [2](#0-1) 

Critically, this code path is reachable **before** any shop validation occurs. In `authStrategyFactory`, `respondToBouncePageRequest` (for `config.auth.patchSessionTokenPath`) and `respondToExitIframeRequest` (for `config.auth.exitIframePath`) both call `renderAppBridge` unconditionally as soon as the request path matches — well before `validateShopAndHostParams` (which does call `api.utils.sanitizeShop`) is ever invoked: [3](#0-2) [4](#0-3) 

By contrast, the equivalent `shopify-app-react-router` file explicitly sanitizes `shop` right before calling `addDocumentResponseHeaders`, with a comment describing exactly this attack: [5](#0-4) 

The corresponding CHANGELOG entry for `shopify-app-react-router` confirms this was a deliberate security fix intended to prevent attacker-controlled `shop` values from being reflected into CSP/Link headers: [6](#0-5) 

I was unable to find an equivalent CHANGELOG entry or fix commit for `shopify-app-remix`, and the `render-app-bridge.ts`/`add-response-headers.ts` files there still use the unsanitized value.

### Impact Explanation
Because `frame-ancestors https://${shop} ...` is built without validating that `shop` is a genuine `*.myshopify.com`/Shopify-admin domain, an unauthenticated attacker can send a request such as:

`GET /patch-session-token?shop=evil.com` (or `/exit-iframe?shop=evil.com&exitIframe=...`)

and the resulting response's CSP header becomes `frame-ancestors https://evil.com https://admin.shopify.com ...`, permitting the app's bounce/exit-iframe page (and the App Bridge script it loads) to be framed by `https://evil.com`. This defeats the very purpose of the `frame-ancestors` CSP directive (preventing clickjacking / embedding outside of legitimate Shopify surfaces), enabling clickjacking-style attacks against merchants who are lured to an attacker-controlled page that iframes this endpoint.

### Likelihood Explanation
High likelihood of reachability: both `respondToBouncePageRequest` and `respondToExitIframeRequest` are hit on every request to two fixed, well-known, unauthenticated routes (`config.auth.patchSessionTokenPath` and `config.auth.exitIframePath`) before any session/shop validation takes place, so no authentication or prior state is required — a single anonymous GET request is sufficient to trigger the vulnerable header construction.

### Recommendation
Apply the same fix used in `shopify-app-react-router`: sanitize the `shop` query parameter with `api.utils.sanitizeShop(...)` before passing it to `addDocumentResponseHeaders` in `shopify-app-remix`'s `render-app-bridge.ts`, so that malformed/attacker-controlled `shop` values are rejected (return `null`) rather than reflected into security-sensitive headers.

### Proof of Concept
1. Deploy an embedded app using `@shopify/shopify-app-remix`.
2. As an unauthenticated actor, send `GET https://<app-host>/<patchSessionTokenPath>?shop=evil.com`.
3. Observe the response: `Content-Security-Policy: frame-ancestors https://evil.com https://admin.shopify.com https://*.spin.dev https://admin.myshopify.io https://admin.shop.dev;` — confirming `evil.com` is reflected unsanitized into the CSP frame-ancestors directive, per [7](#0-6)  combined with the unvalidated call in [1](#0-0) .

```typescript
export function addDocumentResponseHeaders(
  headers: Headers,
  isEmbeddedApp: boolean,
  shop: string | null | undefined,
) {
  if (shop) {
    headers.set(
      'Link',
      '<https://cdn.shopify.com/shopifycloud/app-bridge.js>; rel="preload"; as="script";',
    );
  }

  if (isEmbeddedApp) {
    if (shop) {
      headers.set(
        'Content-Security-Policy',
        `frame-ancestors https://${shop} https://admin.shopify.com https://*.spin.dev https://admin.myshopify.io https://admin.shop.dev;`,
      );
    }
  } else {
    headers.set('Content-Security-Policy', `frame-ancestors 'none';`);
  }
```
