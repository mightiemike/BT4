### Title
Unbounded free account creation via gasless `MsgExecutePayload`/`MsgMigrateUEA` bypasses the ante pipeline's fee-based Sybil protection - (File: `app/ante/account_init_decorator.go`, `app/txpolicy/gasless.go`)

### Summary
The gasless-transaction pipeline was designed to let bonded Universal Validators submit vote messages (`MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`) without holding gas tokens [1](#0-0) . However, the same allowlist also includes two ordinary, unprivileged, user-submitted messages — `MsgExecutePayload` and `MsgMigrateUEA` [2](#0-1) . Because `AccountInitDecorator` unconditionally creates a brand-new on-chain account for any first-seen signer of a gasless tx — before the message itself is ever validated or executed — an unprivileged attacker can generate unlimited keypairs, sign one cheap `MsgExecutePayload` per keypair, and get a permanent account entry written to state for zero fee, with no gas-price or fee-deduction check at all, and independent of whether the payload subsequently fails execution.

### Finding Description
`IsGaslessTx` treats a transaction as gasless if every message in it belongs to a fixed allowlist, which includes `MsgExecutePayload` (regular user payload execution) and `MsgMigrateUEA` (regular user UEA migration), not just validator vote messages [3](#0-2) .

`MinGasPriceDecorator` and `DeductFeeDecorator` both short-circuit entirely for any tx classified as gasless, skipping the minimum-gas-price check and all fee deduction [4](#0-3) [5](#0-4) .

`AccountInitDecorator` runs before signature/pubkey/sequence decorators in the ante chain [6](#0-5) . For any gasless tx whose signer has no existing account, it only checks the signature against a fixed `account_number=0, sequence=0` signer-data tuple, then unconditionally materializes the account with `SetSequence(1)` and writes it to the account store [7](#0-6) . This is the only gate before permanent state is created — no funding, no protocol-level validation of the message payload's semantic correctness, and no limit on how many distinct signer addresses may go through this path.

`MsgExecutePayload.ValidateBasic()` only performs shallow structural checks (non-nil `UniversalAccountId`/`UniversalPayload`, non-empty hex `VerificationData`) [8](#0-7) , and the message handler itself performs no bonded/permissioned check on `msg.Signer` (unlike `VoteInbound`/`VoteOutbound`/`VoteChainMeta`, which all require `IsBondedUniversalValidator`) [9](#0-8) . An attacker only needs a syntactically valid, self-signed message to reach and pass `AccountInitDecorator`; whether `ExecutePayload` later succeeds or fails downstream in `ms.k.ExecutePayload` is irrelevant to whether the account gets created — the account creation happens unconditionally in the ante handler, prior to any message execution.

### Impact Explanation
An unprivileged attacker can, at zero cost (no fee, no minimum gas price, no funding requirement), mint unlimited new accounts on-chain by submitting one solo-signed `MsgExecutePayload` (or `MsgMigrateUEA`) per fresh keypair. Each such tx:
- Bypasses `MinGasPriceDecorator` and `DeductFeeDecorator` entirely (gasless).
- Forces `AccountInitDecorator` to write a new `BaseAccount` with `sequence=1` into the account keeper's KV store, permanently, regardless of whether the payload is garbage and the subsequent `ExecutePayload` call fails.

This defeats the fee-based Sybil/spam resistance that the DeductFee/MinGasPrice decorators are meant to provide, and produces unbounded, permanent, cost-free growth of the account store — a denial-of-service-class impact reachable purely through ordinary unprivileged user transaction submission, matching the in-scope "denial of service ... reachable without privileged control" category. It is directly analogous to the Timelock report's bug class: a control meant to gate a privileged/limited flow (fee-gated account creation, timelocked governance) can be entered through an adjacent, less-restricted door (the gasless allowlist being broader than its intended validator-only purpose, an admin function reachable with immediate effect) and used to fully negate the intended protection.

### Likelihood Explanation
High. No special privileges, validator bonding, or chain state are required — only the ability to generate a keypair and broadcast a signed transaction, which is the default capability of any external user of the chain.

### Recommendation
Restrict `AccountInitDecorator`'s free account-creation behavior to message types where the signer's authority is independently verified as a bonded/permissioned participant (i.e., only the validator-vote messages: `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`), and exclude general user-initiated messages such as `MsgExecutePayload` and `MsgMigrateUEA` from `IsGaslessTx`'s allowlist, or otherwise require a bonded/registered UEA/on-chain funding check before the ante handler is allowed to materialize a brand-new account for free.

### Proof of Concept
1. Attacker generates N distinct secp256k1/ed25519 keypairs, none of which have ever transacted (no on-chain account).
2. For each keypair, attacker crafts a solo-signed `MsgExecutePayload` with `Signer` set to the derived bech32 address, and any structurally-valid (but semantically meaningless/unexecutable) `UniversalAccountId`, `UniversalPayload`, and hex `VerificationData` satisfying `ValidateBasic` [8](#0-7) .
3. Attacker signs each tx over `account_number=0, sequence=0` and broadcasts it with zero fee and zero gas price.
4. `IsGaslessTx` classifies each tx as gasless because `MsgExecutePayload` is in the allowlist [2](#0-1) ; `MinGasPriceDecorator` and `DeductFeeDecorator` both skip their checks [4](#0-3) [5](#0-4) .
5. `AccountInitDecorator` sees `HasAccount == false`, verifies the (attacker-controlled, self-consistent) signature, and unconditionally calls `NewAccountWithAddress` / `SetAccount` [10](#0-9) , permanently persisting the new account regardless of what happens next.
6. `ExecutePayload`'s subsequent module-level execution may fail (invalid payload/UEA), but the account creation from step 5 is not rolled back, since it already committed at the ante stage of a separate/prior successful ante pass (or, even within the same tx, the account write occurs unconditionally before the message handler runs and is not reverted by a later message failure within the same tx execution, since account creation is a state write performed in the ante handler itself).
7. Repeating steps 1–4 across N keypairs floods the account store with N permanent entries at zero cost to the attacker.

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}

func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}
