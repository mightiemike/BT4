Confirmed: `httpTriggerHandler.callbacks` is a single global map `map[string]savedCallback // requestID -> savedCallback` [1](#0-0)  keyed purely by the caller-supplied JSON-RPC `req.ID`, with no scoping by workflow ID or owner/signer.

### Title
Malicious user can block another user's HTTP trigger request via request-ID squatting - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The gateway's HTTP trigger handler uses the caller-supplied JSON-RPC request `ID` as the sole, globally-unique key for tracking in-flight requests. Any unauthenticated/any-user request that reaches `validateRequestID`-then-`setupCallback` can reserve an arbitrary request ID before the legitimate owner submits their own request with that same ID, causing the victim's request to be rejected.

### Finding Description
`HandleUserTriggerRequest` validates the request, resolves the workflow, authorizes it, checks rate limits, and finally calls `setupCallback(ctx, req.ID, callback, requestStartTime)` [2](#0-1) . `setupCallback` stores the callback keyed only by the raw `requestID` string, and if that key is already present it returns a conflict error without any check on who owns the ID or which workflow it's associated with:

```go

	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
	...
``` [3](#0-2) 

`validateRequestID` only rejects empty IDs or IDs containing `/`; it performs no ownership binding, no per-workflow namespacing, and no derivation from request content [4](#0-3) . The map itself is declared as a flat `requestID -> savedCallback` structure without any owner/workflow component in the key [5](#0-4) .

This mirrors the reported bug class exactly: a user-controlled value (there: `unbondingTxHash`; here: JSON-RPC `id`) is trusted as a unique key for a shared resource without any cryptographic binding to the caller or the request content, so anyone can pre-empt another user's identifier and deny them service. The test suite explicitly documents that submitting a second request with the same ID fails, regardless of who submits it: `TestHttpTriggerHandler_HandleUserTriggerRequest/duplicate_request_id` [6](#0-5) .

### Impact Explanation
An attacker who can predict or observe an intended request ID (e.g., IDs following a predictable convention, IDs communicated out-of-band, or simply by racing common/likely IDs) can pre-register that ID with an arbitrary (even garbage) workflow selector before the legitimate caller's real request arrives. The legitimate caller's subsequent request with the same ID is rejected with `jsonrpc.ErrConflict` / "requestID has already been used," denying them the ability to trigger their workflow via that request ID. Because the workflow execution path (HTTP trigger for CRE/workflow ingestion) is a user-facing trust boundary, this is a denial-of-service against legitimate workflow invocations, analogous in class/impact (medium severity, availability impact against an honest user without any attacker compromise) to the original unbonding-blocking bug.

### Likelihood Explanation
Likelihood is high in scenarios where request IDs are not high-entropy secrets known only to the caller (e.g., deterministic/sequential IDs, IDs shared with the workflow author for correlation, or simple UUID races won by a faster attacker). Any party capable of sending a JSON-RPC request to the gateway's HTTP trigger endpoint (subject only to workflow ID resolution and rate limiting, not per-ID ownership) can attempt this, since `setupCallback` is reached after authorization to the *workflow*, not authorization tied to the specific `req.ID` value being squatted for a *different* request.

### Recommendation
Do not use the raw, unauthenticated caller-supplied `req.ID` as a global collision domain. Scope the in-flight-request map by a composite key that includes the authenticated signer/workflow owner (e.g., `(authorizedOwner, requestID)` similar to the pattern already used in the vault gateway handler, which prefixes the authorized owner onto the request ID: `req.RequestId == "0xworkflow"+vaulttypes.RequestIDSeparator+"1"` [7](#0-6) ) so that two different callers cannot collide on the same bare ID. Apply this scoping before the `setupCallback` uniqueness check in `http_trigger_handler.go`.

### Proof of Concept
1. Attacker sends a well-formed but otherwise arbitrary `workflows.execute` JSON-RPC request to the gateway with `id = "victim-req-1"` (an ID the attacker expects/guesses the victim will use), targeting any workflow the attacker is authorized to invoke.
2. The gateway calls `setupCallback(ctx, "victim-req-1", ...)`, which succeeds and inserts the entry into `h.callbacks["victim-req-1"]` [8](#0-7) .
3. Victim later sends their legitimate request with `id = "victim-req-1"` for their own workflow.
4. `setupCallback` finds the existing entry and rejects the victim's request with `jsonrpc.ErrConflict`: "requestID: victim-req-1 has already been used" [9](#0-8) , exactly as reproduced by the existing unit test for duplicate request IDs [6](#0-5) , except here the second, blocked caller is a different, honest user rather than the same session retrying.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, doneCh)

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
	threshold := (len(h.donConfig.Members)+h.donConfig.F)/2 + 1
	agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
	if err != nil {
		return nil, errors.New("failed to create response aggregator: " + err.Error())
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:           callback,
		requestStartTime:   requestStartTime,
		createdAt:          time.Now(),
		responseAggregator: agg,
		doneCh:             doneCh,
	}
	return doneCh, nil
