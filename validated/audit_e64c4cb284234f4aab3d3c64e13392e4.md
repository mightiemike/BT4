### Title
GEiC Privileged Web Contents Grants MojoJS Bindings Without Origin Verification, Allowing a Malicious Origin to Front-Run `RegisterClient` and Hijack the Trusted Tab-Context Client - ([File: chrome/browser/geic/geic_pwc_manager.cc])

### Summary
The GEiC (Gemini-in-Chrome) privileged web contents feature enables the full MojoJS binding surface—including the ability to call `GeicBrowserHost::RegisterClient`—on the primary main frame of its dedicated `PrivilegedWebContents` without checking that the frame's *committed origin* matches the configured guest/capability allowlist origin at the moment bindings are granted. This mirrors the reported smart-contract class of bug ("initializer can be front-run"): a privileged, one-shot registration function (`RegisterClient`, acting like Allo's/Registry's owner-setting `initialize()`) can be called by whichever content reaches it first, and the code explicitly acknowledges the missing origin check.

### Finding Description
`GeicPwcManager::TabEntry::RenderFrameCreated` and `ReadyToCommitNavigation` unconditionally call `EnableMojoJsBindings()` on the primary main frame of the GEiC `PrivilegedWebContents`, with an explicit developer TODO stating the exposure is broader than intended and that origin is not checked here: [1](#0-0) 

Once MojoJS bindings are enabled, the frame can reach `mojom::GeicBrowserHost` via `BindGeicBrowserHost`, which is gated only by `pwc::EnforceCapabilityGate(rfh)` (a frame/component-type check), not by validating the frame's *currently committed origin* against the intended guest origin: [2](#0-1) 

`GeicBrowserHostImpl::RegisterClient` behaves as the "initializer": it unconditionally rebinds `client_remote_` to whatever pending remote is passed in and immediately returns sensitive initial state (`GeicInitialState`, including current-tab `TabMetadata` with URL, title, and favicon): [3](#0-2) [4](#0-3) 

Because (a) MojoJS bindings are exposed before/without verifying the committed origin, and (b) `RegisterClient` accepts and blindly trusts the first caller reached through those bindings, any content that manages to execute in that main frame before (or instead of) the intended first-party guest script—e.g., through a navigation race, an open-redirect on the configured guest URL, or any script injected during the brief window `EnableMojoJsBindings` fires relative to `DidFinishNavigation`—can "front-run" the legitimate guest and register itself as `client_remote_`. It would then receive all subsequent `OnFocusedTabChanged` pushes for the life of the tab, i.e., continuous exfiltration of the user's active-tab metadata (URL, title, favicon) to an untrusted origin.

### Impact Explanation
This is a cross-origin information-disclosure primitive: a hostile origin that wins the race to call `RegisterClient` gains a standing channel from the browser process delivering the user's currently focused tab's URL, title, and favicon on every tab/URL change, without further user interaction. This falls squarely in scope as a "cross-origin disclosure" reachable purely from a renderer-controlled Mojo message, matching the accepted bug classes.

### Likelihood Explanation
Exploitability is bounded by two developer-acknowledged gaps rather than a single trivial trigger: `EnableMojoJsBindings` fires on `RenderFrameCreated`/`ReadyToCommitNavigation` for the primary main frame without an origin check [1](#0-0) , and `BindGeicBrowserHost` does not re-validate the committed origin against the capability allowlist before exposing `RegisterClient` [2](#0-1) . The comments themselves flag this as a known prototype shortcut ("this exposes the entire Mojo surface... and the committed origin is not checked against the capability allowlist here"), indicating the maintainers consider it an unresolved gap rather than a fully mitigated design, which raises confidence that a race/redirect path exists even though the exact trigger (e.g., timing of `ReadyToCommitNavigation` vs. an intermediate/error-page commit, or an open redirect on the guest URL) would need further confirmation in a live build.

### Recommendation
- In `BindGeicBrowserHost` and in `EnableMojoJsBindings` call sites, verify `rfh->GetLastCommittedOrigin()` (not just frame type/component) against the capability allowlist/guest origin before exposing the interface or accepting `RegisterClient`.
- Bind `RegisterClient` acceptance to a specific, previously-authenticated navigation/document instance (e.g., via `NavigationHandle`'s validated origin at commit time) rather than trusting the first caller through an already-open Mojo pipe.
- Consider rejecting `RegisterClient` calls after the first legitimate registration for a given committed document, instead of silently `reset()`-and-`Bind()`-ing to a new remote.

### Proof of Concept
Not independently reproduced against a running build; this is based on static analysis of the code paths above. A concrete PoC would require constructing a navigation/redirect sequence on the GEiC `PrivilegedWebContents` such that a non-guest origin's script executes and calls `mojom.GeicBrowserHost.registerClient()` (via MojoJS bindings) before or in place of the legitimate guest page's client script, then observing that it receives `OnFocusedTabChanged` callbacks for the user's browsing tab.

void BindGeicBrowserHost(
    content::RenderFrameHost* rfh,
    mojo::PendingReceiver<mojom::GeicBrowserHost> receiver) {
  pwc::PrivilegedWebContents* privileged = pwc::EnforceCapabilityGate(rfh);
  if (!privileged) {
    return;
  }

  if (privileged->component() != pwc::PrivilegedComponent::kGeic) {
    bad_message::ReceivedBadMessage(rfh->GetProcess(),
                                    bad_message::PWC_BRIDGE_UNQUALIFIED_FRAME);
    return;
  }

  Profile* profile = Profile::FromBrowserContext(rfh->GetBrowserContext());
  auto* manager = GeicPwcManager::GetOrCreateForProfile(profile);
  if (manager) {
    GeicBrowserHostImpl* host = manager->GetBrowserHostForPwc(privileged);
    if (host) {
      host->BindBrowserHost(std::move(receiver));
    }
  }
}

void GeicBrowserHostImpl::RegisterClient(
    mojo::PendingRemote<mojom::GeicClient> client,
    RegisterClientCallback callback) {
  DVLOG(1) << "[geic] RegisterClient, client_valid=" << client.is_valid();
  client_remote_.reset();
  client_remote_.Bind(std::move(client));

  auto state = mojom::GeicInitialState::New();
  state->focused_tab_data = GetCurrentFocusedTabData();
  std::move(callback).Run(std::move(state));
}
