### Title
OAuth callback shop-value desynchronization between HMAC-validated query and access-token/session shop - ([File: packages/apps/shopify-api/lib/auth/oauth/oauth.ts])

### Summary
In `callback()`, the query object that is HMAC/state-validated (`authQuery`, built via `Object.fromEntries(query.entries())`) is not the same object used to determine the shop that OAuth acts on (`query.get('shop')`, the raw `URLSearchParams`). For a duplicated `shop` query parameter, `Object.fromEntries` keeps the **last** occurrence while `URLSearchParams.get()` returns the **first** occurrence, so the shop value that gets HMAC-verified can differ from the shop value used to build the token-exchange URL and the persisted `Session`.

### Finding Description
`begin()`/`callback()` in [1](#0-0)  parse the callback URL into `URLSearchParams` and read `shop` with `query.get('shop')` for logging. Later, `authQuery` is derived with `Object.fromEntries(query.entries())` [2](#0-1)  and passed into `validQuery` → `validateHmac(config)(query)` [3](#0-2) .

Because `authQuery` is a plain object (not a `URLSearchParams` instance), `normalizeQuery` in `hmac-validator.ts` takes the early-return branch and performs **no** duplicate-detection for the `admin` signator path — that check is gated behind `signator === 'appProxy'` [4](#0-3) . So for the OAuth admin callback, duplicate `shop` values are silently resolved by `Object.fromEntries` semantics (last value wins) before `validateHmac` ever sees them, and the HMAC comparison is computed and checked entirely against that "last-wins" value .

Immediately after HMAC/state validation succeeds, the code re-derives the shop independently from the raw `URLSearchParams` object: `sanitizeShop(config)(query.get('shop')!, true)!` [5](#0-4) , which is the **first** occurrence, not `authQuery.shop` (the last occurrence that was actually HMAC-validated). This `cleanShop` value is what's used to build the `/admin/oauth/access_token` POST URL and to construct the persisted `Session` object [6](#0-5) .

This is precisely the "validated field ≠ acted-upon field" desync the question describes: the object passed to `validateHmac` and the object used for `cleanShop`/session creation are two independently-parsed representations of the same duplicated query string, using opposite first/last precedence rules.

### Impact Explanation
This is a genuine library-level bug that breaks the invariant that the HMAC-validated `shop` is the one the app acts on. However, full cross-tenant token theft requires Shopify's own `/admin/oauth/access_token` endpoint to accept an authorization `code` against a shop domain (`cleanShop`) different from the shop domain Shopify itself used when generating that `code`/HMAC. Shopify's OAuth server binds authorization codes to the specific shop domain, so the POST to a mismatched `cleanShop` (e.g., `victim.myshopify.com`) with a `code` issued for a different shop is expected to be rejected by Shopify's server — an external control outside this library's boundary, and this materially limits real-world exploitability of a full account/token takeover. The concretely demonstrable impact confined to this library is: incorrect/attacker-influenced shop binding is used for the token-exchange request and for `Session.shop` despite HMAC validation nominally protecting the request — a structural authenticity violation, but not a self-contained, library-only path to forged sessions without Shopify's server also failing to enforce code-shop binding.

### Likelihood Explanation
An unauthenticated attacker fully controls the callback URL sent to a victim/merchant (e.g., via a phishing link, matching the described precondition), and can trivially append a duplicate `shop=` parameter. No secret or privileged access is needed to construct the malicious URL. The remaining blocker for full exploitation is Shopify's own authorization-code/shop binding at the real `/admin/oauth/access_token` endpoint, which is outside this repo's control and is presumed to enforce shop-domain matching, making full compromise unlikely but not something this codebase's tests/logic guarantee.

### Recommendation
Normalize the callback query exactly once (using the same `normalizeQuery`/`URLSearchParams`-aware logic used inside `hmac-validator.ts`, including duplicate-key rejection for `shop`) and reuse that single normalized object for every downstream decision — HMAC validation, state comparison, `cleanShop` derivation, and `Session` construction — instead of re-parsing `query.get('shop')` separately in `oauth.ts`. Additionally, reject (not just admin-comma-join) duplicate `shop`/`hmac`/`timestamp`/`code`/`state` parameters for the `admin` signator the same way `APP_PROXY_SINGLE_VALUE_PARAMS` is enforced for `appProxy`.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/auth/oauth/__tests__/oauth-shop-desync.test.ts
import {URLSearchParams} from 'url';

test('shop used for token exchange differs from shop used for HMAC validation on duplicate param', () => {
  const query = new URLSearchParams(
    'shop=victim.myshopify.com&shop=attacker.myshopify.com&hmac=deadbeef&timestamp=1700000000&code=abc&state=xyz',
  );

  // Mirrors oauth.ts line 147: raw first-value parse used for cleanShop/session
  const rawShop = query.get('shop');
  expect(rawShop).toBe('victim.myshopify.com');

  // Mirrors oauth.ts line 178: Object.fromEntries collapses duplicates to LAST value
  const authQuery = Object.fromEntries(query.entries());
  expect(authQuery.shop).toBe('attacker.myshopify.com');

  // Assert the desync: the shop actually HMAC-validated (authQuery.shop)
  // is NOT the shop later used for the token-exchange URL / Session (rawShop).
  expect(authQuery.shop).not.toBe(rawShop);
});
```
This confirms `validateHmac` in [7](#0-6)  verifies against `authQuery.shop` ("attacker.myshopify.com") while `cleanShop`/`Session.shop` in [8](#0-7)  use `query.get('shop')` ("victim.myshopify.com") — two different values for the same request.

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }
