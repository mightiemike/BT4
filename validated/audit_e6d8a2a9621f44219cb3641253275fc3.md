### Title
Repeated full-backlog rescanning in `shrink_ancient_slots`/`get_sorted_potential_ancient_slots` causes superlinear (quadratic) background CPU cost for N attacker-created single-account ancient slots - (File: accounts-db/src/accounts_db.rs, accounts-db/src/ancient_append_vecs.rs)

### Summary
`shrink_ancient_slots` recomputes `get_sorted_potential_ancient_slots` and `calc_ancient_slot_info` over the *entire* set of remaining ancient slots on every periodic invocation, but `combine_ancient_slots_packed_internal` only combines/removes a bounded subset per call (capped by `max_ancient_slots`/`max_resulting_storages`). When an unprivileged attacker creates a large number `N` of distinct single-account ancient slots, the background loop must run `N / max_ancient_slots` passes to drain the backlog, and each pass re-scans/re-sorts the shrinking-but-still-large remainder, producing aggregate `O(N²)` work for `O(N)` attacker fees.

### Finding Description
`get_sorted_potential_ancient_slots` (`accounts-db/src/accounts_db.rs:3076-3082`) calls `self.storage.slots_less_than(oldest_non_ancient_slot)` and sorts the full result on every call: [1](#0-0) 

`shrink_ancient_slots` (`accounts-db/src/accounts_db.rs:3086-3099`), invoked periodically by the accounts background service, passes this entire sorted list straight into `combine_ancient_slots_packed`: [2](#0-1) 

Inside `combine_ancient_slots_packed_internal` (`accounts-db/src/ancient_append_vecs.rs:417-442`), `collect_sort_filter_ancient_slots` → `calc_ancient_slot_info` iterates over *all* of the passed-in slots (`O(R)` where `R` is the current backlog size) to build `SlotInfo` entries: [3](#0-2) 

`filter_ancient_slots` then sorts these `R` entries multiple times (`sort_shrink_indexes_by_bytes_saved`, `filter_by_smallest_capacity`'s `sort_unstable_by`) — `O(R log R)`: [4](#0-3) [5](#0-4) 

Only after this full-backlog scan/sort does `truncate_to_max_storages` cut the list down to a bounded number of storages that will actually be combined this pass, governed by `tuning.max_ancient_slots`/`max_resulting_storages` (fixed to 10 packed storages per call in `combine_ancient_slots_packed`): [6](#0-5) [7](#0-6) 

Because each periodic call only shrinks/removes a small, roughly-constant number of slots from the backlog, but each call's cost is proportional to the *entire remaining backlog* `R`, draining a backlog of size `N` requires `~N / c` calls (where `c` is the per-call combine capacity), and the summed cost across all calls is `Σ R log R ≈ O(N² / c · log N)`. An unprivileged attacker can grow this backlog cheaply by writing a small, unique account in as many distinct rooted slots as possible over time (one tiny write per slot, at the network's natural slot cadence), paying only the linear per-transaction fee for `N` slots/accounts, while the validator's background ancient-combining thread performs quadratic aggregate work to catch up. None of the existing guards (zero-lamport handling, ref-count separation, `is_candidate_for_shrink`) bound the *input* scanning cost per call — they only affect which slots are `should_shrink` or filtered out after the full scan already occurred.

### Impact Explanation
This produces disproportionate CPU/allocation cost in the validator's background cleaning thread relative to the fees the attacker paid to create the underlying accounts/slots — the `shrink_ancient_slots`/`combine_ancient_slots_packed` path violates the expected near-linear (fees-proportional) cost invariant for account lifecycle bookkeeping. Repeated quadratic rescans can starve/delay background cleaning (`ActiveStatItem::SquashAncient`), increasing memory/CPU pressure and available-disk-space pressure from a slowly-draining backlog of tiny ancient AppendVecs, which matches the "disproportionate storage and CPU cost" bounty category rather than causing stale reads, hash divergence, or balance corruption (no such corruption was found; correctness of combining logic appears intact in the reviewed tests).

### Likelihood Explanation
Feasible but requires sustained, patient effort: the attacker must get one small write rooted in as many distinct slots as possible (bounded by real slot cadence, ~2.5 slots/second network-wide), so building a backlog of, e.g., hundreds of thousands of single-account ancient slots takes many hours to days of continuous cheap transactions, not a single call. It is unprivileged (any fee-paying user), reproducible, and does not require validator/leader control, but the time-extended nature and dependence on the shared, natural slot-creation rate make it a background/DoS-style degradation rather than an instant crash.

### Recommendation
Bound the per-call scan/sort cost of `get_sorted_potential_ancient_slots`/`calc_ancient_slot_info` to a fixed-size window (e.g., process only the oldest `k` candidate slots per pass, or maintain a persistent sorted/priority structure updated incrementally as slots are added/removed) so that the cost of each `shrink_ancient_slots` invocation is bounded independently of total backlog size `N`, restoring `O(N)` (amortized) total cleanup cost for `N` attacker-created slots.

    fn truncate_to_max_storages(
        &mut self,
        tuning: &PackedAncientStorageTuning,
        stats: &ShrinkAncientStats,
    ) {
        // these indexes into 'all_infos' are useless once we truncate 'all_infos', so make sure they're cleared out to avoid any issues
        self.shrink_indexes.clear();
        let total_storages = self.all_infos.len();
        let mut cumulative_bytes = Saturating(0u64);
        let low_threshold = tuning.max_ancient_slots * 50 / 100;
        let mut bytes_from_must_shrink = 0;
        let mut bytes_from_smallest_storages = 0;
        let mut bytes_from_newest_storages = 0;
        for (i, info) in self.all_infos.iter().enumerate() {
            cumulative_bytes += info.alive_bytes;
            let ancient_storages_required =
                cumulative_bytes.0.div_ceil(tuning.ideal_storage_size.get()) as usize;
            let storages_remaining = total_storages - i - 1;

            // if the remaining uncombined storages and the # of resulting
            // combined ancient storages are less than the threshold, then
            // we've gone too far, so get rid of this entry and all after it.
            // Every storage after this one is larger than the ones we've chosen.
            // if we ever get to more than `max_resulting_storages` required ancient storages, that is enough to stop for now.
            // It will take a lot of time for the pack algorithm to create that many, and that is bad for system performance.
            // This should be a limit that only affects extreme testing environments.
            // We do not stop including entries until we have dealt with all the high slot #s. This allows the algorithm to continue
            // to make progress each time it is called. There are exceptions that can cause the pack to fail, such as accounts with multiple
            // refs.
            if !info.is_high_slot
                && (storages_remaining + ancient_storages_required < low_threshold
                    || ancient_storages_required as u64 > u64::from(tuning.max_resulting_storages))
            {
                self.all_infos.truncate(i);
                break;

    fn filter_by_smallest_capacity(
        &mut self,
        tuning: &PackedAncientStorageTuning,
        stats: &ShrinkAncientStats,
    ) {
        let total_storages = self.all_infos.len();
        if total_storages <= tuning.max_ancient_slots {
            // currently fewer storages than max, so nothing to shrink
            self.shrink_indexes.clear();
            self.all_infos.clear();
            return;
        }

        // sort by:
        // 1. `high_slot`: we want to include new, high slots each time so that we try new slots
        //     each time alg runs and have several high target slots for packed storages.
        // 2. 'should_shrink' so we make progress on shrinking ancient storages
        // 3. smallest capacity to largest so that we remove the most slots possible
        self.all_infos.sort_unstable_by(|l, r| {
            r.is_high_slot
                .cmp(&l.is_high_slot)
                .then_with(|| r.should_shrink.cmp(&l.should_shrink))
                .then_with(|| l.written_bytes.cmp(&r.written_bytes))
        });

        // remove any storages we don't need to combine this pass to achieve
        // # resulting storages <= 'max_storages'
        self.truncate_to_max_storages(tuning, stats);
    }

    fn calc_ancient_slot_info(
        &self,
        slots: Vec<Slot>,
        tuning: &PackedAncientStorageTuning,
    ) -> AncientSlotInfos {
        let len = slots.len();
        let mut infos = AncientSlotInfos {
            shrink_indexes: Vec::with_capacity(len),
            all_infos: Vec::with_capacity(len),
            ..AncientSlotInfos::default()
        };
        let mut randoms = 0;
        let max_slot = slots.iter().max().cloned().unwrap_or_default();
        // heuristic to include some # of newly eligible ancient slots so that the pack algorithm always makes progress
        let high_slot_boundary = max_slot.saturating_sub(HIGH_SLOT_OFFSET);
        let is_high_slot = |slot| slot >= high_slot_boundary;
        for slot in &slots {
            if let Some(storage) = self.storage.get_slot_storage_entry(*slot) {
                let is_candidate_for_shrink = self.is_candidate_for_shrink(&storage);
                let alive_bytes_after_shrink = self.alive_bytes_after_shrink(&storage) as u64;
                if infos.add(
                    *slot,
                    storage,
                    alive_bytes_after_shrink,
                    tuning.can_randomly_shrink,
                    tuning.ideal_storage_size,
                    is_high_slot(*slot),
                    is_candidate_for_shrink,
                ) {
                    randoms += 1;
                }
