### Title
`AccountStore.recordBalance` O(n) max-scan and immutable-list rebuild per operation causes quadratic CPU cost for transactions with many balance-mutating native calls - ([File: chainbase/src/main/java/org/tron/core/store/AccountStore.java])

### Summary
`AccountStore.put`/`delete` call `recordBalance`, which on every invocation streams the entire `operationList` of the shared per-transaction `TransactionBalanceTrace` to find the current max `operationIdentifier`, then rebuilds the immutable protobuf via `toBuilder().addOperation().build()` (which copies the whole existing list). [1](#0-0)  Because native opcodes such as `FREEZEBALANCEV2`, `UNFREEZEBALANCEV2`, `DELEGATERESOURCE` each call `AccountStore.put` and each costs a fixed, linear energy amount (10,000 per call), an attacker contract that chains N such opcodes in one transaction causes N `AccountStore.put` invocations, each rescanning/rebuilding a list of growing size, yielding O(N²) work for O(N) charged energy. [2](#0-1) [3](#0-2) 

### Finding Description
`AccountStore.put` is gated by `CommonParameter.isHistoryBalanceLookup()`; when enabled, every balance-changing `put`/`delete` triggers `recordBalance`, which pulls the transaction-scoped `TransactionBalanceTrace` from `BalanceTraceStore.getCurrentTransactionBalanceTrace()`, computes `transactionBalanceTrace.getOperationList().stream().mapToLong(...).max()` over the *entire* current operation list, then does `transactionBalanceTrace.toBuilder().addOperation(operation).build()`, which for Protobuf `List` fields internally copies the accumulated list into a new builder/message. [1](#0-0)  This trace object is shared across the whole transaction, including nested TVM internal calls, so any TVM opcode that triggers a balance-affecting `AccountStore.put` accumulates onto the same list. [4](#0-3) 

TVM exposes several native opcodes reachable from ordinary contract bytecode that each perform an `AccountStore.put`/balance mutation and can be invoked repeatedly in a loop within a single `TriggerSmartContract`: `freezeBalanceV2`/`unfreezeBalanceV2` (`Program.freezeBalanceV2`/`unfreezeBalanceV2`, `FreezeBalanceV2Processor.execute` → `repo.updateAccount`) and `delegateResource`/`unDelegateResource` (via `DelegateResourceActuator`/native processor calling `accountStore.put`). [3](#0-2) [5](#0-4) [6](#0-5)  Each opcode charges a fixed energy cost (`FREEZE_V2 = 10000`, `UNFREEZE_V2 = 10000`, `DELEGATE_RESOURCE = 10000`, etc.), which is declared as strictly linear per call. [7](#0-6)  None of the existing checks (signature validation, actuator `validate()`, energy accounting) account for the CPU cost of the balance-trace bookkeeping — energy is charged per opcode invocation, not per size of the accumulated in-memory trace, so the metering model does not reflect the true O(N²) cost incurred by `recordBalance`.

### Impact Explanation
This is a CPU-cost/metering-faithfulness issue rather than an asset-corruption or consensus-divergence bug: nodes that enable `isHistoryBalanceLookup` (used by indexing full nodes/exchanges for historical balance queries) will do disproportionately more CPU work processing a single transaction than the energy fee paid for it, as N grows within the block's/transaction's energy limit. This matches a "DoS via the TRON protocol implementation" class impact, but is bounded: energy limits on both a single transaction and a block cap N, and the per-call constant-factor work in `recordBalance` (an in-memory list max-scan and protobuf builder copy) is small, so realistic N (bounded by transaction/block energy limits, each native op costing 10,000 energy) produces a bounded, though wasteful, quadratic blow-up rather than unbounded resource exhaustion.

### Likelihood Explanation
The feature is opt-in (`isHistoryBalanceLookup`), so it does not affect default-configuration nodes — most consensus-critical or default RPC-serving nodes are unaffected. Only node operators who explicitly enable historical balance lookup (a documented, legitimate operational mode for full nodes/exchanges) are exposed. Given the rules exclude "non-default node configuration" from consideration, and the primary precondition here is exactly a non-default flag, this weakens the case for treating it as a directly exploitable, in-scope vulnerability against default nodes. The attacker's cost is real (10,000 energy × N per opcode) and bounded by the chain's max energy per transaction, limiting the realistically achievable N and thus the magnitude of the quadratic penalty.

### Recommendation
Track the current max `operationIdentifier` incrementally (e.g., store a running counter alongside the trace, or in `BalanceTraceStore`) instead of rescanning `getOperationList()` on every call, and avoid full-list-copy protobuf rebuilds per operation (e.g., accumulate operations in a mutable `List<Operation>`/builder held by `BalanceTraceStore` for the duration of the transaction and only build the immutable `TransactionBalanceTrace` once at the end).

### Proof of Concept
Not provided as a full end-to-end exploit: this finding hinges on a non-default node configuration (`isHistoryBalanceLookup=true`), which per the audit rules should generally be excluded from in-scope findings targeting default node behavior. A benchmark JUnit test (as sketched in the question) deploying a contract that loops N calls to `freezeBalanceV2`/`unfreezeBalanceV2`/`delegateResource` within one `TriggerSmartContract`, with `isHistoryBalanceLookup` enabled, and measuring wall-clock time vs. N would demonstrate the O(N²) scaling of `AccountStore.recordBalance`, but does not constitute an impact against default node operation.

  private void recordBalance(AccountCapsule accountCapsule, long diff) {
    TransactionBalanceTrace transactionBalanceTrace = balanceTraceStore.getCurrentTransactionBalanceTrace();

    if (transactionBalanceTrace == null) {
      return;
    }

    long operationIdentifier;
    OptionalLong max = transactionBalanceTrace.getOperationList().stream()
        .mapToLong(Operation::getOperationIdentifier)
        .max();
    if (max.isPresent()) {
      operationIdentifier = max.getAsLong() + 1;
    } else {
      operationIdentifier = 0;
    }

    ByteString address = accountCapsule.getAddress();
    Operation operation = Operation.newBuilder()
        .setAddress(address)
        .setAmount(diff)
        .setOperationIdentifier(operationIdentifier)
        .build();
    transactionBalanceTrace = transactionBalanceTrace.toBuilder()
        .addOperation(operation)
        .build();
    balanceTraceStore.setCurrentTransactionBalanceTrace(transactionBalanceTrace);
  }

  public void execute(FreezeBalanceV2Param param, Repository repo) {
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();

    byte[] ownerAddress = param.getOwnerAddress();
    long frozenBalance = param.getFrozenBalance();
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }
    switch (param.getResourceType()) {
      case BANDWIDTH:
        long oldNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForBandwidthV2(frozenBalance);
        long newNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        repo.addTotalNetWeight(newNetWeight - oldNetWeight);
        break;
      case ENERGY:
        long oldEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForEnergyV2(frozenBalance);
        long newEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        repo.addTotalEnergyWeight(newEnergyWeight - oldEnergyWeight);
        break;
      case TRON_POWER:
        long oldTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        accountCapsule.addFrozenForTronPowerV2(frozenBalance);
        long newTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        repo.addTotalTronPowerWeight(newTPWeight - oldTPWeight);
        break;
      default:
        logger.debug("Resource Code Error.");
    }

    // deduce balance of owner account
    long newBalance = accountCapsule.getBalance() - frozenBalance;
    accountCapsule.setBalance(newBalance);
    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
  }

  private void delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
                                long balance, boolean lock, long lockPeriod) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource
    long now = chainBaseManager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    //modify DelegatedResourceStore
    long expireTime = 0;
    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }

    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

    //modify AccountStore for receiver
    AccountCapsule receiverCapsule = accountStore.get(receiverAddress);
    if (isBandwidth) {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(balance);
    } else {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(balance);
    }
    accountStore.put(receiverCapsule.createDbKey(), receiverCapsule);
  }
