### Title
LDAP login endpoint leaks distinguishable error messages enabling user/account enumeration - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`ldapAuthenticator.CreateSession` returns three distinct error strings for connection failure, bad credentials, and valid-credentials-but-no-role-group cases [1](#0-0) , and `SessionsController.Create` forwards this raw `err` directly to the unauthenticated HTTP client via `jsonAPIError(c, http.StatusUnauthorized, err)` [2](#0-1) . This lets an unauthenticated network attacker distinguish "valid credentials but no assigned LDAP role group" from "invalid credentials" by inspecting the HTTP response body.

### Finding Description
`CreateSession` binds to the LDAP server with attacker-supplied credentials and sets `returnErr` to one of three separate `errors.New(...)` messages depending on outcome: connection failure ("unable to establish connection to LDAP server..."), bad bind ("unable to log in with LDAP server. Check credentials"), or a successful bind followed by a failed `FindUser` group lookup ("log in successful, but no assigned groups to assume role") [1](#0-0) . This `err` is returned unmodified up the call stack to `SessionsController.Create`, which passes it straight into `jsonAPIError` without wrapping it into a single generic authentication-failure message [2](#0-1) . An unprivileged attacker who only has network access to `POST /sessions` can submit many email/password guesses and, by inspecting the distinct returned error text, determine that a given email address (a) exists in the LDAP directory with a correct/incorrect password bound state, and (b) whether the account has a role-group assignment — all without needing valid credentials. No rate limiting differentiates or masks the message content; the `UnauthenticatedPeriod`/`Unauthenticated` limiter throttles request volume only [3](#0-2) , it does not collapse the error message space.

### Impact Explanation
This is an information disclosure / account-enumeration issue, not a direct authentication bypass: the attacker cannot obtain a session, only confirm that an email address is a valid LDAP-directory user lacking role mapping versus an unknown/incorrect-credential account. This assists targeted phishing/credential-stuffing and account-existence reconnaissance against the node's admin/LDAP-backed accounts, but does not by itself grant a session, escalate privilege, or leak secrets/tokens.

### Likelihood Explanation
Highly feasible: the endpoint is reachable by any unauthenticated network client with only email/password guesses required, and the differentiated error text is returned deterministically and repeatably on every request; the only friction is the existing per-IP unauthenticated rate limiter, which slows but does not prevent enumeration.

### Recommendation
Collapse all `CreateSession` client-facing authentication-failure paths (connection failure, bad bind, and no-role-group) into a single generic message (e.g., "invalid credentials") before returning to `SessionsController.Create`, while retaining the detailed distinction only in server-side logs (`l.lggr.Infof/Errorf`) as is already done.

### Proof of Concept
Integration test extending `TestSessionsController_Create` / `TestORM_CreateSession_UpstreamBind`-style tests: mock LDAP client to (1) fail `Bind` for a nonexistent user, (2) succeed `Bind` but fail `FindUser` group lookup for a real user lacking group membership, (3) fail `CreateEphemeralConnection`. Issue `POST /sessions` for each case and assert the JSON `errors[0].detail` body — expected: all three cases currently return distinguishable strings ("unable to log in...", "log in successful, but no assigned groups...", "unable to establish connection..."); after fix, assert all collapse to the same generic message string.

func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

	// Bind was successful meaning user and credentials are present in LDAP directory
	// Reuse FindUser functionality to fetch user roles used to create ldap_session entry
	// with cached user email and role
	foundUser, err := l.FindUser(ctx, escapedEmail)
	if err != nil {
		l.lggr.Infof("Successful user login, but error querying for user groups: user: %s, error %v", escapedEmail, err)
		returnErr = errors.New("log in successful, but no assigned groups to assume role")
	}

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
