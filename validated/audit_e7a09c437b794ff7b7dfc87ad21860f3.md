### Title
Attacker-controlled short `DestExecData` causes panic in `ExtraDataDecoder.DecodeDestExecDataToMap`, crashing OCR transmit goroutine - ([File: core/capabilities/ccip/ccipsolana/extradatacodec.go])

### Summary
`ExtraDataDecoder.DecodeDestExecDataToMap` calls `binary.BigEndian.Uint32(destExecData)` without validating that `destExecData` is at least 4 bytes long, unlike its sibling `DecodeExtraArgsToMap`, which explicitly checks `len(extraArgs) < 4` before slicing. A CCIP message from an untrusted source chain with `TokenAmounts[i].DestExecData` shorter than 4 bytes reaches this function via `decodeExecData` in the SVM (and Sui) contract transmitters, causing `binary.BigEndian.Uint32` to panic on an out-of-bounds slice access.

### Finding Description
The call chain is: `SVMExecCalldataFunc` → `decodeExecData` (core/capabilities/ccip/ocrimpls/svm_contract_transmitter.go:126-153), which loops over `message.TokenAmounts` and calls `codec.DecodeTokenAmountDestExecData(tokenAmount.DestExecData, ...)` for each token amount [1](#0-0) . This is forwarded through `ExtraDataCodecRegistry.DecodeTokenAmountDestExecData` (core/capabilities/ccip/common/extradatacodecregistry.go:76-83) with no length validation [2](#0-1) , ultimately reaching `ExtraDataDecoder.DecodeDestExecDataToMap`, which unconditionally executes `binary.BigEndian.Uint32(destExecData)` [3](#0-2) . `binary.BigEndian.Uint32` in the Go standard library indexes `b[3]` unconditionally, and will panic with "index out of range" if `len(b) < 4`. The `message.TokenAmounts[i].DestExecData` field originates from the source-chain CCIP message and is not validated for minimum length anywhere in this path — contrast this with the neighboring `DecodeExtraArgsToMap` function in the same file, which explicitly guards against short input with `if len(extraArgs) < 4 { return nil, fmt.Errorf(...) }` [4](#0-3) . No other check (authz, signature, replay, or codec-level) exists in this path to prevent an undersized `DestExecData` byte slice from being passed all the way to the unguarded `binary.BigEndian.Uint32` call.

### Impact Explanation
An unhandled panic in `decodeExecData`, invoked from `SVMExecCalldataFunc` during OCR report transmission, will crash the goroutine performing CCIP execute report submission on Solana/SVM destination chains (and similarly `sui_contract_transmitter.go`, which shares the same `decodeExecData` pattern). This blocks legitimate execute report submission, resulting in denial of service on CCIP execute transmission for the affected lane.

### Likelihood Explanation
The precondition is that an attacker controls the content of a CCIP message on a source chain that is subsequently relayed to an SVM (or Sui) destination chain — specifically the `DestExecData` field attached to a `TokenAmount` entry. Since `DestExecData` is derived from message/token-pool configuration data carried in the cross-chain message and is not independently length-validated by the destination-side codec, a message with `DestExecData` of 0–3 bytes reliably triggers the panic every time the offchain reporting execute-report calldata function runs for that report, making this highly repeatable once the malformed data is included in an accepted report.

### Recommendation
Add the same length check used in `DecodeExtraArgsToMap` to `DecodeDestExecDataToMap`: validate `len(destExecData) < 4` and return an error instead of calling `binary.BigEndian.Uint32` on undersized input, e.g.:
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	if len(destExecData) < 4 {
		return nil, fmt.Errorf("dest exec data too short: %d, should be at least 4", len(destExecData))
	}
	return map[string]any{
		svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
	}, nil
}
```

### Proof of Concept
Unit test in `core/capabilities/ccip/ccipsolana/extradatacodec_test.go`:
```go
func TestDecodeDestExecDataToMap_ShortInput(t *testing.T) {
	d := ExtraDataDecoder{}
	for _, n := range []int{0, 1, 2, 3} {
		_, err := d.DecodeDestExecDataToMap(make(cciptypes.Bytes, n))
		require.Error(t, err, "expected error for short DestExecData, got panic instead")
	}
}
```
Before the fix, this test panics with "runtime error: index out of range" instead of returning an error. Additionally, an integration-level PoC can construct an `ExecuteReportInfo` with a single `AbstractReport`/`Message` whose `TokenAmounts[0].DestExecData` is a 2-byte slice, call `decodeExecData` (or `SVMExecCalldataFunc`) directly, and assert it returns an error rather than panicking.
