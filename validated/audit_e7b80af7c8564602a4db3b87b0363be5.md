## Analysis

The reported bug class (missing `DOMAIN_SEPARATOR()` in EIP-2612, i.e. a signed message that lacks a chain-specific binding, enabling cross-chain replay) has a concrete analog in nearcore's NEP-366/NEP-461 meta-transaction signing scheme.

### Title
Meta-transaction `SignedDelegateAction`/`VersionedSignedDelegateAction` signatures lack a chain-specific domain separator, enabling cross-network replay - (File: `core/primitives/src/signable_message.rs`, `core/primitives/src/action/delegate.rs`)

### Summary
`DelegateAction` and `DelegateActionV2` (NEP-366 meta transactions) are signed via `SignableMessage`, which only binds the message to a `MessageDiscriminant` (a NEP number tag) plus the action payload itself (`sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`). [1](#0-0) [2](#0-1)  Unlike a regular `SignedTransaction`, which is bound to a specific `block_hash` for chain-specific and time-bound replay protection, the signed payload for a delegate action contains no genesis hash, chain ID, or any other network-identifying value — only a plain `max_block_height: BlockHeight` integer.

### Finding Description
`SignedDelegateAction::verify`/`sign` and `VersionedSignedDelegateAction::verify`/`sign` compute the signed hash purely from the discriminant plus the `DelegateAction`/`DelegateActionV2` struct fields: [3](#0-2) [4](#0-3)  None of `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, or `public_key` identify which NEAR network (mainnet, testnet, or any other nearcore-derived chain) the signature is scoped to. `max_block_height` is only a monotonically increasing integer that is not unique across chains, in contrast to a `block_hash`, which is cryptographically unique per chain and is what ordinary transactions rely on for replay protection (`transaction_validity_period` window keyed off a specific chain's block hash). Because accounts, public keys, and nonces routinely exist identically across multiple NEAR-based networks (e.g. a user reuses the same seed-derived account/key on testnet and mainnet, or a network undergoes a chain split/fork producing two independent chains that share history up to the fork point), a `SignedDelegateAction`/`VersionedSignedDelegateAction` produced for use on one chain contains nothing that prevents a relayer from wrapping and submitting the exact same signed bytes on a different chain where the sender account, public key, and access-key nonce state still make it valid.

### Impact Explanation
On the destination chain, `validate_delegate_action_key` in the runtime only checks that the access key exists, that the delegate nonce exceeds the on-chain access-key/gas-key nonce, and that it is below the block-height-derived nonce upper bound — none of these checks are chain-specific. [5](#0-4)  If the same account/key/nonce state coincidentally (or by design, e.g. testnet mirroring mainnet state, or post-fork chains) exists on both chains, a relayer (or any third party who intercepts a `SignedDelegateAction`, which per the meta-tx design docs is handed to a relayer off-chain) can replay a user's signed delegate action — including transfers, `AddKey`, or other privileged inner actions — on a chain the signer never intended, resulting in unauthorized execution of the delegated actions and potential unauthorized value movement or account compromise (e.g. an inner `AddKeyAction` granting full access replayed on the "wrong" chain).

### Likelihood Explanation
This requires two nearcore-based networks/chains to share the same account_id + public_key + current nonce state for the targeted account (e.g., testnet/mainnet key reuse, custom nearcore-based appchains derived from the same genesis, or a chain split scenario), so it is not universally exploitable against arbitrary mainnet accounts today. However, it is fully reachable from a completely unprivileged actor: any user who signs a `DelegateAction` and hands it to a relayer (the standard, documented NEP-366 flow) is exposed, and no validator, node operator, or network-layer compromise is required — only an off-chain relayer/third party with access to the signed bytes and knowledge that mirrored state exists on another chain.

### Recommendation
Include a chain-specific domain-separating value (e.g., the genesis hash or an explicit chain ID field) inside the `SignableMessage`/`DelegateAction`/`DelegateActionV2` payload that gets hashed and signed, analogous to `block_hash` in `SignedTransaction`, so that a signature produced for one NEAR network cannot be verified as valid on any other network.

### Proof of Concept
1. On Chain A (e.g. testnet) and Chain B (e.g. a nearcore-based appchain sharing the same genesis/account layout), provision the same account `alice.near` with the same public key and identical access-key nonce.
2. Alice signs a `DelegateAction { sender_id: "alice.near", receiver_id: "bob.near", actions: [Transfer], nonce, max_block_height, public_key }` via `SignedDelegateAction::sign`, intending it for Chain A only. [6](#0-5) 
3. A relayer submits the identical `SignedDelegateAction` bytes as a transaction on Chain B instead.
4. `VersionedSignedDelegateAction::verify`/`SignedDelegateAction::verify` succeeds on Chain B because the hashed payload contains nothing tying it to Chain A, and `validate_delegate_action_key` accepts it if the nonce/access-key state matches. [7](#0-6)

/// Validate access key which was used for signing DelegateAction:
///
/// - Checks whether the access key is present fo given public_key and sender_id.
/// - Validates nonce and updates it if it's ok.
/// - Validates access key permissions.
fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }

    let upper_bound = apply_state.block_height
        * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER;
    if delegate_nonce.nonce() >= upper_bound {
        result.result = Err(ActionErrorKind::DelegateActionNonceTooLarge {
            delegate_nonce: delegate_nonce.nonce(),
            upper_bound,
        }
        .into());
        return Ok(());
    }
