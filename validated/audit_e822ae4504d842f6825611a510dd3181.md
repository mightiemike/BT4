### Title
`accrue()` pause "passes through" instead of freezing state, letting deposit/redeem price conversions drift from the persisted index - (File: `local-testing/contracts/vault/vault-stx.clar`)

### Summary
When the `accrue` pause flag is set, `accrue()` does not revert and does not update the persisted `index`/`lindex`/`last-update` state — it simply returns the stale cached values as a pass-through. However, `deposit` and `redeem` compute the actual conversion rate used for minting/burning shares via `convert-to-shares-preview` / `convert-to-assets-preview`, which independently recompute `total-assets-preview` → `debt-preview` → `(next-index)` rather than using the value returned by `accrue()`. This creates a persistent state where the interest-index used for pricing user deposits/redemptions can diverge from the interest-index actually persisted in the vault's storage.

### Finding Description
`accrue()` explicitly branches on the `accrue` pause flag: [1](#0-0) 

When paused, it returns `{ index: idx, lindex: lidx }` — the old, stored values — without touching `last-update`, `index`, `lindex`, or minting treasury LP shares (line 839-841: "PAUSED: Pass-through without reverting"). This is the "pause passes through instead of reverting" pattern: instead of blocking the caller, the pause silently substitutes a stale-but-valid-looking result and lets execution continue.

The problem is that `deposit` and `redeem` do not rely solely on that cached `accrue()` result for pricing. Both call `(try! (accrue))` for its side effect, then separately call `convert-to-shares-preview` / `convert-to-assets-preview`: [2](#0-1) [3](#0-2) 

These preview helpers pull from `total-assets-preview`, which is computed from `debt-preview` — itself derived from `(next-index)`, a function of elapsed time since `last-update` — the same code pattern is repeated identically across every vault (`v0-vault-usdh.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`): [4](#0-3) 

Because `next-index`/`debt-preview` are pure functions of stored state and elapsed wall-clock time (not gated by the pause flag), they keep advancing even while `accrue`'s pause branch freezes the persisted `index`/`lindex`/`last-update`. Consequently, once `accrue` is paused, deposit/redeem share-conversion math (mint/burn amounts) is computed off a live, still-ticking interest projection, while the actual ledger state (`index`, `lindex`, `total-borrowed`, `assets`) is frozen at the pre-pause values and the deferred treasury-LP mint for accrued reserve interest during the pause window is permanently skipped rather than deferred and later applied.

### Impact Explanation
This produces an accounting mismatch between the value used to price a deposit/redeem transaction (based on a moving projected index) and the value actually persisted in storage (frozen). Any interest that should have accrued to the reserve/treasury during the pause is dropped rather than caught up later, since the paused branch simply short-circuits with the old values and no future accrual step re-applies the missed interval retroactively. This is a form of temporary/permanent freezing (or misallocation) of unclaimed protocol/treasury yield accrued during the pause window, and can distort LP share pricing for any deposit/redeem executed while `accrue` is paused.

### Likelihood Explanation
Likelihood is conditional on the DAO ever toggling the `accrue` pause flag via `set-pause-states` — a normal operational lever, not an attacker-controlled trigger: [5](#0-4) 

Any deposit or redeem transaction that occurs after `accrue` is paused (and before it is unpaused, at which point `last-update` is simply jumped to "now," discarding the skipped interval rather than reconciling it) will exhibit the pricing/state divergence described above. This does not require a malicious counterparty — it is purely a self-contained state/pricing inconsistency triggered by a single administrative action followed by ordinary user calls.

### Recommendation
Have `convert-to-shares-preview`/`convert-to-assets-preview` (and their `total-assets-preview`/`debt-preview` dependencies) respect the same `accrue` pause flag that `accrue()` checks, so that pricing is frozen consistently with persisted state during a pause. Alternatively, have the pause branch of `accrue()` cause `deposit`/`redeem` to revert (`ERR-PAUSED`) rather than silently passing through, and ensure the skipped accrual interval is either fully preserved (not discarded via the `last-update` jump on unpause) or explicitly written off with an event, not silently dropped.

### Proof of Concept
1. DAO calls `set-pause-states` setting `accrue: true` on `vault-stx` [6](#0-5) . This freezes `index`, `lindex`, and `last-update`.
2. Time passes (or a later block occurs) while the pool continues to owe interest per its configured curve.
3. A user calls `deposit`; it calls `(try! (accrue))`, hitting the paused pass-through branch (index/lindex/last-update unchanged) [7](#0-6) .
4. The same `deposit` call computes `inkind` via `convert-to-shares-preview`, which internally calls `total-assets-preview`/`debt-preview`, using `(next-index)` computed from elapsed time since the (now-stale) `last-update` [8](#0-7) .
5. The minted share amount reflects interest that is never persisted into `index`/`lindex`, nor minted to `.dao-treasury` as reserve LP, because the paused `accrue()` branch skipped that logic entirely.
6. When `accrue` is unpaused later, `last-update` is jumped straight to `stacks-block-time` [9](#0-8) , permanently discarding the interest interval that was already reflected in step 4's user-facing pricing but never reconciled in vault state — a durable state/pricing divergence introduced in a single pause/unpause cycle.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
