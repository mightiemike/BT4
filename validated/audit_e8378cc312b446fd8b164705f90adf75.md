### Title
Gas-abstraction autoswap slippage protection truncates to zero for small deposit amounts, allowing full-value extraction via sandwich attack - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The gas-abstraction swap path (`ExecuteInboundGas`) and the gas+payload variant (`gasAndPayloadDepositAutoSwap`) compute the swap's minimum-output slippage guard using integer division: `minPCOut = quote * 95 / 100`. For small quoted output amounts this truncates to `0`, which removes the slippage protection entirely on an attacker-controlled deposit path, mirroring the precision-loss pattern from the fractional-vault report where a rounding-to-zero on a protective threshold caused user value loss.

### Finding Description
In `x/uexecutor/keeper/execute_inbound_gas.go`: [1](#0-0) 

`quote` is fetched from `GetSwapQuote` based on the inbound `amount` (attacker-controlled — it is the amount of an external-chain asset the attacker deposits via the gasless/gas-abstraction inbound flow), and then:

```go
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
```

Because this is integer arithmetic, any `quote` value in the range `[0, 1]` (in the smallest WPC unit) truncates `minPCOut` to `0`. The identical pattern exists in the GAS_AND_PAYLOAD path: [2](#0-1) 

`minPCOut` is then passed straight into `CallPRC20DepositAutoSwap` as the DEX minimum-output guard. When `minPCOut == 0`, the swap will settle regardless of how unfavorable the actual execution price is — the slippage check can never fail. Since the deposit amount, and thus the quoted output, is entirely attacker-controlled (an attacker simply bridges a very small amount of an asset through the gasless gas-abstraction inbound), an attacker can deliberately choose a dust-sized deposit to guarantee `minPCOut = 0`, then sandwich the autoswap transaction (front-run to move the WPC/PRC20 pool price unfavorably, let the zero-slippage-protected swap execute at the manipulated price, back-run to restore price and capture the difference). This is directly analogous to the original report's core defect: a threshold/guard value computed by integer division rounds to zero for small inputs, silently disabling the protection it was meant to provide and causing loss of user-controlled value.

### Impact Explanation
An unprivileged attacker can extract essentially all of the swap's economic value for any inbound gas-abstraction deposit that quotes to a small enough amount, since the 5%-slippage safety net is bypassed. This is a direct loss of user (protocol-routed) funds during the swap that the gas-abstraction flow (`ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap`) performs on the user's behalf, matching the "unauthorized … loss of user or protocol-controlled funds" and "corruption of … gas fee accounting" impact categories in scope.

### Likelihood Explanation
Reachable by any external, unprivileged user who can submit a cross-chain gas-abstraction deposit of a small enough amount (no special chain, validator, or admin privilege required) and who can additionally submit ordinary swap transactions against the same on-chain WPC/PRC20 pool to sandwich it — both of which are default, permissionless capabilities on Push Chain. The exact `quote` scale at which truncation occurs depends on the token's decimals/price ratio (not independently verified from `GetSwapQuote`'s implementation, which was not located in the indexed code), so the precise dust threshold is uncertain, but the truncation-to-zero defect in the `minPCOut` formula itself is unconditional and reproducible for any `quote <= 1`.

### Recommendation
Replace the truncating integer division with a rounding scheme that never yields zero protection for a non-zero quote (e.g., round up, or enforce `minPCOut = max(1, quote*95/100)`), and/or reject autoswap execution when the computed `minPCOut` is `0` while `quote > 0`, forcing such dust deposits through a path that doesn't silently disable slippage protection (analogous to the original report's recommendation to enforce a minimum viable threshold before allowing the operation to proceed).

### Proof of Concept
1. Attacker bridges a very small amount of an external asset via the gas-abstraction inbound flow (`TxType_GAS`), chosen such that `GetSwapQuote(... , amount)` returns a `quote` of `0` or `1` (smallest WPC unit).
2. `ExecuteInboundGas` computes `minPCOut = quote*95/100 = 0`.
3. Before the block containing this UTX-driven swap is finalized/executed, the attacker submits transactions that move the WPC/PRC20 pool price unfavorably (front-run).
4. `CallPRC20DepositAutoSwap` executes the autoswap with `minPCOut = 0`, so it cannot revert regardless of the resulting output.
5. Attacker restores the pool price (back-run), capturing the value difference; the depositor's autoswap settles for far less PC than fair value, with the slippage guard having provided no protection.
