### Title
Uniswap V3 QuoterV2 spot-price quote used for auto-swap slippage protection is manipulable within a single block, allowing an attacker to drain value from inbound deposit and gas-refund auto-swaps - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report describes a mechanism that derives a critical financial parameter (auto-roll price) from a single, unverified, easily-manipulated data point rather than a more robust, manipulation-resistant aggregate. Push Chain's `uexecutor` module has a structurally identical pattern in its PRC20→PC auto-swap logic: it computes `minPCOut` slippage protection from a single spot-price call to a Uniswap V3 `QuoterV2.quoteExactInputSingle`, which reflects the pool's *current* (single-block) price with no time-weighted averaging or reliability checks, and then immediately executes the real swap against that same manipulable quote.

### Finding Description
`Keeper.GetSwapQuote` fetches a swap quote by calling `quoteExactInputSingle` on the on-chain Uniswap V3 `QuoterV2` contract, which simulates the swap against the pool's current reserves/spot price with `SqrtPriceLimitX96` set to `0` (no price limit): [1](#0-0) 

This quote is used, unverified against any longer-window or reliability-checked reference price, to compute a 5% slippage tolerance and is passed straight into the real swap call `CallPRC20DepositAutoSwap`: [2](#0-1) 

The same pattern is repeated for the `GAS_AND_PAYLOAD` inbound route: [3](#0-2) 

...and for the excess-gas refund flow triggered on outbound vote finalization: [4](#0-3) 

This is documented as an explicit protocol upgrade feature — the slippage check was changed from "0-slippage" to "quote × 95%", using the QuoterV2 contract as the price source: [5](#0-4) 

Because the AMM pool (Uniswap V3 fork deployed as part of the `UniversalCore` system contract set, referenced via `uniswapV3Factory_` / `uniswapV3SwapRouter_` / `uniswapV3Quoter_`) lives on Push Chain itself and is a permissionless, publicly tradeable pool, any unprivileged EVM user can submit ordinary transactions to move the PRC20/WPC pool's spot price before an inbound deposit or gas refund is executed by the core validator. Because `GetSwapQuote` and `CallPRC20DepositAutoSwap` both read the *same* momentarily-manipulated pool state, the 5% tolerance check does not protect against this: it only bounds the swap's execution price relative to the attacker-manipulated quote, not relative to the token's true market value. This is the exact bug class in the external report — deriving a critical value from a single unverified, momentarily-manipulable price rather than a robust weighted/TWAP-checked price — applied to Push Chain's own on-chain swap-quote mechanism instead of a lending market's auto-roll price.

### Impact Explanation
An attacker who manipulates the PRC20/WPC pool price immediately before a victim's `GAS` / `GAS_AND_PAYLOAD` inbound (or a gas refund) is processed can cause the auto-swap to execute at an artificially unfavorable price for the depositor, extracting value from the user's deposited/refunded funds via the pool (classic sandwich pattern against a spot-price oracle). This directly impacts "corruption of PRC20 or native asset accounting" and "draining of user ... funds" in the allowed-impact scope, since the amount of native PC token minted/credited to the user's UEA is determined by the manipulated quote.

### Likelihood Explanation
Any unprivileged account can submit ordinary swap transactions against the on-chain pool with no special privileges; inbound deposit processing and gas refunds are triggered by ordinary user/validator activity (deposits, outbound observations) that occur continuously, giving an attacker many opportunities to time or trigger a manipulation window. No malicious validator, relayer, or TSS participant assumption is required — the manipulation happens entirely at the AMM/EVM layer that any user can interact with.

### Recommendation
Do not rely solely on a single-block `quoteExactInputSingle` spot-price call for slippage protection. Use a manipulation-resistant reference price (e.g., a TWAP over a window observed via the pool's oracle/observations, or the `ChainMeta`/oracle-style aggregated median mechanism already used elsewhere in this codebase for gas prices, with a minimum-liquidity/minimum-reliability check) to compute `minPCOut`, or bound the acceptable deviation between the spot quote and a longer-window reference price before allowing the swap to proceed.

### Proof of Concept
1. Attacker observes (or triggers, e.g., by submitting their own bridge deposit) that an inbound `GAS`/`GAS_AND_PAYLOAD` transaction for token `X` is pending core-validator execution.
2. Attacker submits a large swap on the on-chain PRC20(X)/WPC Uniswap V3 pool to push the pool's spot price against `X` immediately before the core validator calls `GetSwapQuote` → `CallPRC20DepositAutoSwap` for the pending inbound.
3. `GetSwapQuote` returns a depressed `amountOut` reflecting the manipulated pool state; `minPCOut = quote * 95/100` is computed from this depressed value.
4. `CallPRC20DepositAutoSwap` executes the swap and succeeds (since the check only compares against the already-manipulated quote), crediting the victim's UEA with far less PC than the token's true value.
5. Attacker reverses their swap in a follow-up transaction, capturing the arbitrage profit extracted from the victim's deposit.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
```
