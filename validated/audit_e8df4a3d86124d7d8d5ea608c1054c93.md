The strongest scoped analog to the Cooler "propose favorable terms → front-run with unfavorable terms right before acceptance" pattern is the on-chain AMM quote used as the slippage bound for `x/uexecutor`'s auto-swap deposit/refund flows.

### Title
Attacker can sandwich the auto-swap deposit/refund quote-and-execute flow because `minPCOut` is derived from the same manipulable Uniswap V3 pool it is meant to protect against — (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
For `GAS` and `GAS_AND_PAYLOAD` inbounds, and for excess-gas refunds on successful outbounds, `x/uexecutor` fetches a spot quote from the Uniswap V3 `QuoterV2` contract and computes a "slippage-protected" minimum output as `quote * 95 / 100`, then immediately executes the swap using that same computed bound [1](#0-0) . Because the reference quote and the executed swap both read the same live, manipulable pool state (no TWAP, no external price oracle), an unprivileged attacker can move the pool price immediately before the module's swap executes and move it back immediately after, capturing the difference — analogous to the lender front-running `rollLoan` with unfavorable terms right before the borrower's acceptance executes.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false` against live pool reserves [2](#0-1) . The very next step multiplies that quote by 95% and passes it as `minPCOut` into `CallPRC20DepositAutoSwap`, which performs the real swap via `DerivedEVMCall` [3](#0-2) . The same quote→95%→swap pattern is repeated in three places:
- `ExecuteInboundGas` (GAS inbound autoswap) [1](#0-0) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound autoswap) [4](#0-3) 
- `applyGasRefund` (outbound excess-gas refund swap) [5](#0-4) 

Because `quoteExactInputSingle` reflects the pool's *current* reserves (not a time-weighted average), it is not an independent reference price — it is exactly the price the subsequent swap will execute against. A `minPCOut` derived from that same spot state offers no real protection against price manipulation: an attacker can submit an ordinary swap on Push Chain's embedded Uniswap-V3-style pool to skew the price just before the module's deposit-autoswap (or refund-autoswap) transaction lands in the block, causing the quote (and therefore `minPCOut`) to be computed off the skewed price, then reverse the manipulation afterward (classic sandwich). The 5% band bounds slippage *relative to the manipulated price*, not relative to fair market value, so it does not prevent the attack — it only bounds how large a single sandwich can be, similar to how simply capping a lender's rate would not fully close the Cooler front-run without binding acceptance to a rate the borrower actually saw.

This differs from the Cooler bug only in mechanism (AMM price vs. lender-set interest rate), but the invariant broken is the same: a party (here, the protocol acting on behalf of the user) commits to accept whatever "terms" (price) are live at execution time, and an unprivileged external actor can shift those terms immediately beforehand for their own benefit, at the expense of the user's deposited/refunded value.

### Impact Explanation
Every `GAS` or `GAS_AND_PAYLOAD` inbound deposit, and every outbound excess-gas refund, routes the user's native gas token through this auto-swap path to mint PRC20/native PC to the recipient. A sandwich attacker can extract value from each such swap, degrading the amount of PC the user's UEA/recipient actually receives versus fair value — a direct, repeatable value-extraction vector against ordinary user deposits and refunds, falling under "corruption of PRC20 or native asset accounting" and "unauthorized... loss of user or protocol-controlled funds" in the allowed impact set.

### Likelihood Explanation
No privileged role is required — any external account that can submit ordinary EVM transactions against the pool used by `UniversalCore`'s configured Uniswap V3 factory/router can execute the sandwich. The only timing requirement is submitting transactions before/after the block in which the inbound-processing or outbound-refund transaction lands, which is realistic given Push Chain's deterministic, validator-vote-triggered execution and standard mempool visibility. This is a systemic pattern (present in 3 call sites) rather than a one-off edge case, increasing realistic exploitability.

### Recommendation
Do not derive the slippage floor from a spot quote fetched immediately before execution of the same swap. Use a manipulation-resistant reference (e.g., a TWAP over a meaningful window, an external price oracle, or a validator/consensus-driven chain-meta price feed already used elsewhere in the protocol) to compute `minPCOut`, or let it be bounded by a governance-set maximum acceptable deviation from that independent reference rather than a fixed percentage of the same block's spot quote.

### Proof of Concept
1. Attacker observes (or predicts) that a validator-finalized `GAS`/`GAS_AND_PAYLOAD` inbound (or a successful-outbound refund) is about to trigger `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund`.
2. Attacker submits a large swap against the same Uniswap V3 pool (PRC20 gas token ↔ WPC) in the same or immediately preceding block to move the pool price unfavorably for the upcoming module swap.
3. The module calls `GetSwapQuote` [2](#0-1) , which reads the now-skewed pool state, and computes `minPCOut = quote * 95 / 100` [6](#0-5) .
4. `CallPRC20DepositAutoSwap` executes the swap against the same skewed pool, succeeding because `minPCOut` was computed from the attacker-controlled price [7](#0-6) .
5. Attacker reverses their initial swap in a following transaction, capturing the price-impact spread extracted from the user's deposit/refund at the expense of the recipient UEA/user.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
