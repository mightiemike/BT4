### Title
`safeCompare` throws instead of returning `false` on type-mismatched input, causing unhandled exceptions in HMAC/OAuth request validation - (File: `packages/apps/shopify-api/lib/auth/oauth/safe-compare.ts`)

### Summary
`safeCompare`, the primitive used throughout `shopify-app-js` to validate HMACs and OAuth state on incoming requests, is documented and typed as a function that "returns `true`/`false`" for whether two values match. In reality, when the two arguments have different `typeof`, it throws `ShopifyErrors.SafeCompareError` instead of returning `false`. This is the same bug class as the OpenZeppelin `ERC165Checker` advisory (GHSA-qh9x-gcfh-pcrw / CVE-2022-31170): a boolean-returning "is this valid?" check that is assumed to never revert/throw, but can be made to throw by supplying unexpected input, and callers that don't specifically guard for the exception will fail in undefined ways.

### Finding Description
`safeCompare` is defined as: [1](#0-0) 

```ts
export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    ...
    return timingSafeEqual(buffA, buffB);
  } else {
    throw new ShopifyErrors.SafeCompareError(...);
  }
  return false;
};
```
If the two arguments differ in `typeof` (e.g. one is a `string` and the other is an `object`/array), it throws rather than returning `false`.

This function is the sole comparison primitive used by `validateHmac` to check the `hmac`/`signature` query parameter against the server-computed HMAC: [2](#0-1) 

The query-normalization step (`normalizeQuery`) only guards against array-valued security parameters (`hmac`, `shop`, `signature`, `timestamp`) when the `signator` is `'appProxy'` and the query is a plain object, not for the default `'admin'` signator: [3](#0-2) 

`validateHmac` is invoked directly from the OAuth callback handler, which processes an anonymous, attacker-influenced HTTP GET request (Shopify's `/auth/callback` redirect), via `validQuery`: [4](#0-3) 

Because most HTTP frameworks (e.g. Express's default `qs` query parser) parse a repeated query parameter such as `?hmac=aaa&hmac=bbb` into an array, an attacker who controls the OAuth callback request query string (this callback URL is publicly reachable and unauthenticated prior to validation) can pass `hmac` as an array of strings. `normalizeQuery` will not reject/flatten that for the `'admin'` signator, so `hmac` remains a `string[]`, while `localHmac` (server-computed) remains a `string`. The subsequent `safeCompare(hmac as string, localHmac)` call then compares a `string[]` to a `string`, hits the `typeof strA !== typeof strB` branch, and throws `SafeCompareError` instead of `validateHmac` resolving to `false`.

### Impact Explanation
`validateHmac`/`safeCompare` is a security boundary meant to fail closed (return `false`) on any malformed/spoofed request. Turning that into an unhandled thrown exception:
- Converts a security check into an uncaught-exception surface reachable by an anonymous actor hitting the public OAuth callback endpoint, which is a Denial-of-Service vector against the auth handler if the throw is not caught by the surrounding request pipeline (behavior depends on the specific adapter's error handling, which was not fully traceable in the available index).
- More importantly, it breaks the safety invariant relied upon by any caller (in `@shopify/shopify-app-express`, `@shopify/shopify-app-remix`, etc.) that expects `validateHmac`/`safeCompare` to always resolve to a boolean and never throw for an unauthenticated/spoofed input; such callers may not have `try/catch` around this specific call, given the documented contract explicitly promises a boolean return (`docs/reference/utils/validateHmac.md` states "Return: `boolean`").

This mirrors the exact risk called out in the ERC165Checker advisory: code that expects a boolean and instead crashes on unexpected but attacker-reachable input to a "should never revert" check.

### Likelihood Explanation
Likelihood is high for triggering the throw (a single crafted OAuth callback query string with a duplicated `hmac` parameter is trivial to send, and standard query-string parsers turn duplicates into arrays automatically), but the downstream severity depends on whether any caller in the request pipeline fails to catch `SafeCompareError`, which could not be fully confirmed from the retrieved code alone (the `callback()`/`begin()` error-handling wrapper in `oauth.ts` was not fully retrieved before the tool budget ran out).

### Recommendation
Change `safeCompare` to return `false` (not throw) when the compared values have mismatched `typeof`, consistent with its documented "always returns boolean" contract, and additionally normalize/reject array-valued values for the `hmac`/`signature` parameters in `normalizeQuery` for the `'admin'` signator (not only `'appProxy'`) so that repeated query parameters cannot reach `safeCompare` as an array in the first place.

### Proof of Concept
1. Send an OAuth callback request to the app with a duplicated `hmac` query parameter, e.g.:
   `GET /auth/callback?shop=test.myshopify.com&state=...&code=...&timestamp=...&hmac=aaa&hmac=bbb`
2. A framework using array-style query parsing (e.g. Express default `qs`) parses `query.hmac` as `['aaa', 'bbb']`.
3. `validQuery` → `validateHmac(config)(query)` → `normalizeQuery` (admin path, no array check) leaves `hmac` as an array → `safeCompare(hmac as string, localHmac)` compares `string[]` vs `string`.
4. `safeCompare` hits the `typeof strA !== typeof strB` branch and throws `ShopifyErrors.SafeCompareError` instead of returning `false`, as shown in: [4](#0-3) [2](#0-1) [1](#0-0)

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
```

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
```
