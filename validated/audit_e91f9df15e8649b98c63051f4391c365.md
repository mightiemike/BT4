### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows honest-node state divergence from Blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `ReplaceClass` syscall handler in the Starknet OS Cairo program (used for re-execution/proving of blocks) never verifies that the target `class_hash` corresponds to a previously declared contract class before writing it into the contract's state entry. The equivalent Rust `Blockifier` implementation of the same syscall (the code path that actually executes transactions when a block is built) does perform this check. This asymmetry between the two independent implementations of the same syscall is directly analogous to the Teller `commitCollateral` bug: a state-mutating entry point omits a validation check that is enforced elsewhere in the system, letting an unprivileged caller push the protected state (here, a contract's class hash) into an invalid configuration.

### Finding Description
The Rust Blockifier's `replace_class` syscall implementation explicitly reads the compiled class to ensure it is declared, and additionally forbids downgrading to a Cairo0 class: [1](#0-0) 

```
pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
    // Ensure the class is declared (by reading it), and of type V1.
    let compiled_class = self.state.get_compiled_class(class_hash)?;
    if !is_cairo1(&compiled_class) {
        return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
    }
    self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
    Ok(())
}
``` [1](#0-0) 

The Starknet OS's Cairo re-implementation of the exact same syscall (`execute_replace_class` in `syscall_impls.cairo`, used to re-execute/prove the block) skips this validation entirely — it directly fetches the contract's `StateEntry` and overwrites `class_hash` with the caller-supplied, unverified value, with an explicit `TODO` acknowledging the missing check: [2](#0-1) 

```

        key=contract_address,

```

The same missing check exists in the deprecated syscalls path used for legacy transactions: [3](#0-2) 

By contrast, the Blockifier test suite confirms the intended, enforced behavior — that an undeclared class hash (or a Cairo0 downgrade) must be rejected: [4](#0-3) 

Any contract can trigger this syscall via a single, ordinary `invoke` transaction (as demonstrated by the test contract's `test_replace_class` entry point, which just forwards to `replace_class_syscall`): [5](#0-4) 

### Impact Explanation
This is an honest-node divergence bug class: the Blockifier (the execution engine that determines which transactions are accepted into a block and what state diff results) enforces a class-declaration invariant that the Starknet OS (the Cairo program that independently re-executes the block's transactions to produce the proof and validate/commit the resulting state) does not enforce. Any transaction that legitimately reaches `replace_class_syscall` with a class hash that is undeclared, or that is a Cairo0 class hash being used to replace a Cairo1 class, is rejected/reverted by the Blockifier but would be accepted by the OS's Cairo implementation, silently writing an invalid class hash into `contract_state_changes`. Since the STF (state transition function) must be identical across both implementations for the system to be sound, this divergence can propagate through to the committed state root: the OS-computed state (and thus the value fed into commitment/Patricia-tree updates and ultimately the block hash) can differ from what the Blockifier actually executed on-chain, corrupting the contract's declared class hash association with no path to legitimately reproduce or correct it. This can result in either the OS rejecting a legitimately-accepted block (denial of block confirmation) or, more critically, the OS committing/proving a state root inconsistent with the actual Blockifier-derived state (wrong committed root), matching the "wrong committed root or block hash / honest-node divergence" impact criteria.

### Likelihood Explanation
The syscall is reachable directly from any contract via an ordinary `invoke` transaction with no special privileges — any account can deploy a contract that calls `replace_class_syscall` with an arbitrary felt as the class hash. Supplying an undeclared class hash, or a Cairo0 class hash while replacing a Cairo1 class, is trivial and requires no elevated cost; there is no other mempool/gateway/blockifier-external guard preventing the syscall arguments themselves from reaching the OS's re-execution phase for any transaction that is otherwise valid. The `TODO(Yoni, 1/1/2026)` comment confirms this is a known, currently-unaddressed gap.

### Recommendation
Add the same validation present in `syscall_base.rs::replace_class` to the OS's Cairo implementation(s) of `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`: before updating `contract_state_changes`, verify (via `contract_class_changes` / declared-class dictionary lookup) that `class_hash` corresponds to a declared, Cairo1 (non-deprecated) compiled class, and revert/fail the syscall otherwise, mirroring the Blockifier's `ForbiddenClassReplacement`/`UndeclaredClassHash` semantics exactly.

### Proof of Concept
1. Deploy a Cairo1 contract exposing `test_replace_class(class_hash)` which calls `replace_class_syscall(class_hash)` (as in `cairo_steps_test_contract.cairo`).
2. Submit an `invoke` transaction calling `test_replace_class` with an arbitrary, never-declared `class_hash` felt value.
3. Under Blockifier execution (actual sequencing), `syscall_base.rs::replace_class` calls `self.state.get_compiled_class(class_hash)` which returns `UndeclaredClassHash`, causing the transaction to revert — the contract's class hash is left unchanged.
4. When the Starknet OS independently re-executes the same transaction/syscall trace (`execute_replace_class` in `syscall_impls.cairo`), no declared-class check exists; the OS writes the new (undeclared) `class_hash` into `contract_state_changes` and treats the transaction as successful, producing a state diff/state root that differs from what the Blockifier actually committed for this block.
