### Title
Unauthenticated PBFT commit messages are parsed and cached before signature validation, enabling cheap CPU/cache-churn DoS - ([File: framework/src/main/java/org/tron/core/net/messagehandler/PbftDataSyncHandler.java])

### Summary
`PbftDataSyncHandler.processMessage` accepts any inbound `PBFT_COMMIT_MSG` from a connected peer, performs a protobuf `Raw.parseFrom(...)` and inserts the result into `pbftCommitMessageCache` keyed by the attacker-controlled `raw.getViewN()` value, without any signature/authenticity check. Signature validation (`validPbftSign`) only happens later, in `processPBFTCommitMessage`, which is triggered from `processPBFTCommitData` on block production — not from `processMessage` itself.

### Finding Description
The message reaches `processMessage` via `P2pEventHandlerImpl.processMessage` routing `PBFT_COMMIT_MSG` to `pbftDataSyncHandler.processMessage(peer, msg)` [1](#0-0) . Any connected peer can send arbitrary `PbftCommitMessage` payloads; construction only wraps raw bytes into a `PbftSignCapsule` with no validation [2](#0-1) .

In `processMessage`, the only gate before parsing/caching is `allowPBFT()` (a cheap global boolean flag on `DynamicPropertiesStore`, not a per-message auth check). It then unconditionally does:
```java
Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
pbftCommitMessageCache.put(raw.getViewN(), pbftCommitMessage);
``` [3](#0-2) 

No `validPbftSign` call, no `srSignList` size/quorum check, and no per-view or per-peer dedup/rate-limit are applied at this stage — those checks live only in `processPBFTCommitMessage`, invoked from the block-production path `processPBFTCommitData` [4](#0-3) . The cache is bounded to `maximumSize(200)` with a 10-minute TTL [5](#0-4) , so an attacker sending distinct `viewN` values continuously forces Guava cache eviction churn on every insert once the bound is exceeded, in addition to a protobuf parse per message.

I checked for mitigating rate-limiting: `P2pRateLimiter.tryAcquire` is only invoked in `processMessage` for `P2P_DISCONNECT` and via `checkInvRateLimit` for `INVENTORY`-type messages [6](#0-5) ; no equivalent `tryAcquire`/registration call gates `PBFT_COMMIT_MSG` before dispatch to `pbftDataSyncHandler.processMessage`, and no per-type rate limiter registration for `PBFT_COMMIT_MSG` was found in the codebase.

### Impact Explanation
An unprivileged connected peer can force repeated protobuf `Raw.parseFrom` calls and Guava cache put/evict cycles on the node with negligible cost to the attacker (no signature construction required, since verification never happens on this path), consuming CPU and triggering GC pressure. This is a scoped resource-exhaustion / underpriced-work issue rather than a state-corruption or fund-theft bug — no PBFT sign data store (`PbftSignDataStore`) writes occur from `processMessage` itself, only the in-memory `pbftCommitMessageCache`.

### Likelihood Explanation
Preconditions: `allowPBFT()` must be enabled at the network level (i.e., PBFT feature active) — a normal network condition on mainnet/testnet configurations that enable PBFT. Beyond that, any peer that can establish a P2P connection (unprivileged) can send arbitrarily many `PbftCommitMessage`s with distinct `viewN`, so the issue is highly repeatable and requires no special privileges, keys, or witness status.

### Recommendation
Move cheap-but-sufficient validation before the parse/cache step in `processMessage`: at minimum verify `srSignList` is non-empty and meets the quorum size check, and ideally perform full `validPbftSign` verification (or a lighter per-peer/per-viewN rate limit) prior to `Raw.parseFrom` and `pbftCommitMessageCache.put`. Additionally, register a `P2P_COMMIT_MSG`-specific `P2pRateLimiter` entry and enforce `tryAcquire` in the dispatch path in `P2pEventHandlerImpl.processMessage`, consistent with how `INVENTORY` is already gated.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/net/messagehandler/PbftDataSyncHandlerFloodTest.java
@Test
public void testFloodDistinctViewNCausesCacheChurn() throws Exception {
  PbftDataSyncHandler handler = new PbftDataSyncHandler();
  ChainBaseManager chainBaseManager = Mockito.mock(ChainBaseManager.class);
  DynamicPropertiesStore dps = Mockito.mock(DynamicPropertiesStore.class);
  Mockito.when(chainBaseManager.getDynamicPropertiesStore()).thenReturn(dps);
  Mockito.when(dps.allowPBFT()).thenReturn(true);
  Field field = PbftDataSyncHandler.class.getDeclaredField("chainBaseManager");
  field.setAccessible(true);
  field.set(handler, chainBaseManager);

  long start = System.nanoTime();
  for (long viewN = 0; viewN < 10_000; viewN++) {
    Protocol.PBFTMessage.Raw raw = Protocol.PBFTMessage.Raw.newBuilder()
        .setViewN(viewN).setEpoch(0)
        .setDataType(Protocol.PBFTMessage.DataType.BLOCK)
        .setMsgType(Protocol.PBFTMessage.MsgType.COMMIT)
        .setData(ByteString.EMPTY).build();
    // No signatures included -- attacker never needs a valid quorum signature
    PbftSignCapsule capsule = new PbftSignCapsule(raw.toByteString(), new ArrayList<>());
    PbftCommitMessage msg = new PbftCommitMessage(capsule);
    handler.processMessage(null, msg); // unauthenticated peer path
  }
  long elapsed = System.nanoTime() - start;
  // Assert: cache size capped at 200 (eviction thrashing occurred on every insert past bound)
  Field cacheField = PbftDataSyncHandler.class.getDeclaredField("pbftCommitMessageCache");
  cacheField.setAccessible(true);
  com.google.common.cache.Cache<?, ?> cache =
      (com.google.common.cache.Cache<?, ?>) cacheField.get(handler);
  Assert.assertTrue(cache.size() <= 200);
  // Compare elapsed against a baseline where a cheap validity check
  // (e.g., signature/quorum check) short-circuits before parseFrom/put,
  // demonstrating parse+cache cost is paid for every unauthenticated message.
}
```
Expected result: all 10,000 unauthenticated, unsigned messages are parsed via `Raw.parseFrom` and inserted into `pbftCommitMessageCache`, causing continuous eviction once the 200-entry bound is exceeded — confirming no validation gate exists before the expensive parse+store operations.

  private void processPBFTCommitMessage(PbftCommitMessage pbftCommitMessage) {
    try {
      PbftSignDataStore pbftSignDataStore = chainBaseManager.getPbftSignDataStore();
      Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
      if (!validPbftSign(raw, pbftCommitMessage.getPBFTCommitResult().getSignatureList(),
          chainBaseManager.getWitnesses())) {
        return;
      }
      if (raw.getDataType() == DataType.BLOCK
          && pbftSignDataStore.getBlockSignData(raw.getViewN()) == null) {
        pbftSignDataStore.putBlockSignData(raw.getViewN(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the block {} pbft commit data", raw.getViewN());
      } else if (raw.getDataType() == DataType.SRL
          && pbftSignDataStore.getSrSignData(raw.getEpoch()) == null) {
        pbftSignDataStore.putSrSignData(raw.getEpoch(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the srl {} pbft commit data", raw.getEpoch());
      }
    } catch (InvalidProtocolBufferException e) {
      logger.error("", e);
    }
  }
