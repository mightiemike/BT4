### Title
Sandwichable auto-swap slippage check uses a spot quote from the same manipulable pool it swaps against, allowing value extraction from GAS/GAS_AND_PAYLOAD deposits and gas refunds - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The external report flags Uniswap liquidity removal that lacks a caller-supplied minimum-output check, letting an attacker move price before execution and extract value from the LP with no protection. Push Chain's inbound gas/payload processing and outbound gas-refund flow implement an analogous auto-swap (PRC20 → WPC) and *do* add a "slippage" bound, but the bound is derived from `GetSwapQuote`, an on-chain spot quote from the same Uniswap V3 pool that the swap itself executes against, fetched inline in the same finalizing transaction as the swap [1](#0-0) . Any unprivileged user who can predict when `VoteInbound` will finalize (last UV vote lands in a public mempool) can submit an ordinary sandwich swap against the WPC/PRC20 pool immediately before the finalizing `MsgVoteInbound` transaction, push the spot price to an extreme, let the protocol's `GetSwapQuote`+`CallPRC20DepositAutoSwap` execute against that manipulated price (minPCOut computed from the same manipulated quote, so the 95% check always "passes"), then reverse the manipulation afterward and pocket the difference — the classic pattern the report describes as "attacker moves the price into a zone such that there is loss to the user," just implemented on Push Chain's own AMM router calls instead of Uniswap's LP-removal path.

### Finding Description
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` all follow the same pattern:
1. Fetch `quote = GetSwapQuote(quoterAddr, tokenIn, wpcAddr, fee, amount)` — a **live, static call** to Uniswap V3 `QuoterV2.quoteExactInputSingle`, which reads the pool's current reserves/sqrtPrice [2](#0-1) .
2. Compute `minPCOut = quote * 95 / 100` (a fixed 5% band around that same spot quote) [3](#0-2) [4](#0-3) [5](#0-4) .
3. Immediately call `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which performs the actual on-chain swap against the very same pool [6](#0-5) .

Because the quote and the swap read the identical pool state (no TWAP, no independent oracle, no user-supplied minimum), an attacker can sandwich the entire operation: submit a large swap that pushes the pool price against the user just before the module's finalizing transaction, then swap back right after. The module's own "slippage protection" is computed off the manipulated price, so it never blocks the manipulated trade — it only guards against unrelated block-to-block drift, not against price manipulation timed to the same block as execution. The trigger event (`VoteInbound` finalizing, or an outbound observation finalizing) is driven by ordinary honest-validator votes reaching quorum, which is publicly observable in the mempool, so an unprivileged attacker does not need any validator/relayer collusion to time the sandwich — this matches the "in scope" unprivileged-attacker model (corruption of PRC20/gas accounting and value extraction from user/protocol-controlled funds via ordinary user-reachable flows).

Affected value at risk:
- User's PC output from GAS / GAS_AND_PAYLOAD inbound deposits (`ExecuteInboundGas`, `ExecuteInboundGasAndPayload`) — the recipient UEA receives less WPC than fair value.
- The refund-with-swap leg of `applyGasRefund` on successful/failed outbound observation, where `refundAmount` of gas token is swapped to PC for the sender/fund_recipient — again sandwichable.

### Impact Explanation
This lets an unprivileged attacker extract value from ordinary protocol-driven auto-swaps: gas-deposit conversions and gas-refund conversions systematically settle at attacker-manipulated prices instead of fair market prices, draining value from users' deposited/refunded gas token into the attacker's sandwich profit. Because the module performs these swaps as `module`-sender transactions with real capital (users' PRC20 gas tokens), this is a direct, repeatable value-extraction vector on every GAS/GAS_AND_PAYLOAD inbound and every gas-refund event, not merely informational slippage — it corrupts the gas-fee/refund accounting outcome and represents unauthorized value transfer away from users to an attacker, which loosely maps to the report's "loss to the user" impact, though the magnitude is capped by the swap size and available pool liquidity/fee tier (self-limiting versus an unbounded loss).

### Likelihood Explanation
Moderate. The attacker needs: (a) capital to move the WPC/PRC20 pool price temporarily, (b) ability to time transactions around the finalizing `MsgVoteInbound`/outbound-vote transaction in the same block, which is generic MEV/front-running behavior available to any chain user with gas-price control, not a privileged actor. It requires enough pool depth/thinness to be profitable and enough block-ordering control (proposer-level MEV or same-block inclusion), so it is not guaranteed to be economically attractive on every pool, but the code path itself offers no defense (no TWAP, no external price check, no minimum enforced independent of the same-block spot quote), so any thin/attacker-controllable pool is exploitable.

### Recommendation
Replace the same-block spot quote with slippage protection that is resistant to same-block manipulation:
- Use a TWAP-based quote (e.g., `OBSERVE`/`consult` over a window) instead of `quoteExactInputSingle`'s instantaneous quote, or
- Bound the acceptable deviation between the on-chain spot price and a governance/oracle-set reference price, rejecting the swap (and falling back to the no-swap deposit path, which already exists) if the deviation exceeds a safe threshold, and/or
- Enforce a maximum price-impact check (e.g., compare `amountOut` against `amount * referencePrice` rather than deriving the bound purely from the same spot quote being executed against).

### Proof of Concept
Conceptual (no direct test harness for the Uniswap pool state was available in the indexed code, so this is a reasoning-level PoC based on the traced call chain):
1. Attacker observes a pending `MsgVoteInbound` in the mempool that will finalize a GAS or GAS_AND_PAYLOAD inbound for victim `V` with amount `A` of `prc20AddressHex`.
2. Attacker submits, in the same block and ordered before the finalizing vote tx, a large swap on the same Uniswap V3 pool (`prc20AddressHex` → `wpcAddress`) that pushes the pool's spot price down for `prc20AddressHex`.
3. The finalizing `MsgVoteInbound` executes `VoteOnInboundBallot` → `ExecuteInbound` → `ExecuteInboundGas`, which calls `GetSwapQuote` (reflecting the attacker-manipulated price) and then `CallPRC20DepositAutoSwap` with `minPCOut = quote*95/100` computed from that same manipulated quote [7](#0-6) ; the swap executes at the manipulated price and always satisfies its own minPCOut check.
4. Attacker submits a reverse swap immediately after (same or next block) to restore the pool price, realizing sandwich profit extracted from `V`'s deposited gas amount.

Because I could not execute Solidity/Foundry tests against the live Uniswap V3 pool contracts referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress` from within this indexed environment, the PoC above traces the exact vulnerable code path rather than a runnable exploit script; a background Devin session with repository and test-harness access would be needed to write and run a concrete Foundry/Go integration test demonstrating measurable loss.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
