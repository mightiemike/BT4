### Title
Unbounded Recursive `MemTrieNodeId::remove_ref` Enables Stack Overflow DoS During Trie GC — (`core/store/src/trie/mem/node/encoding.rs`)

---

### Summary

`MemTrieNodeId::remove_ref` is implemented with unbounded recursion: when a node's refcount reaches zero it calls `remove_ref` on every child, which in turn calls `remove_ref` on their children, and so on. The recursion depth equals the depth of the in-memory trie. An unprivileged attacker can insert storage keys crafted to maximise trie depth, then delete them, causing `delete_until_height` (the GC path) to overflow the call stack and abort the node process.

---

### Finding Description

The recursive deallocation is at: [1](#0-0) 

```rust
pub(crate) fn remove_ref(&self, arena: &mut impl ArenaWithDealloc) -> u32 {
    ...
    if new_refcount == 0 {
        let mut children_to_unref: SmallVec<[ArenaPos; NUM_CHILDREN]> = SmallVec::new();
        let node_ptr = self.as_ptr(arena.memory());
        for child in node_ptr.view().iter_children() {
            children_to_unref.push(child.id().pos);
        }
        let alloc_size = node_ptr.size_of_allocation();
        arena.dealloc(self.pos, alloc_size);
        for child in &children_to_unref {
            MemTrieNodeId { pos: *child }.remove_ref(arena); // ← recursive, unbounded
        }
    }
    new_refcount
}
```

`iter_children` yields one child for `Extension` nodes and up to 16 for `Branch`/`BranchWithValue` nodes: [2](#0-1) 

Because children are processed in a sequential loop, the **call-stack depth equals the depth of the trie**, not the total node count. There is no iterative fallback, no explicit depth limit, and no `stacker`/`recursive` crate usage.

The GC entry point is `delete_until_height`, which calls `delete_root`, which calls `remove_ref` on the root: [3](#0-2) [4](#0-3) 

---

### Impact Explanation

Each `remove_ref` stack frame holds, at minimum:
- `children_to_unref: SmallVec<[ArenaPos; 16]>` — 16 × 8 = 128 bytes inline
- `node_ptr`, `alloc_size`, `refcount` locals, saved registers, return address

Conservatively ~300–600 bytes per frame. In a Merkle-Patricia trie, the maximum depth in nodes equals the key length in nibbles (each branch node consumes exactly one nibble). NEAR's storage key limit is 4 KB = 8 192 nibbles, giving a worst-case depth of ~8 192 nodes and a stack requirement of **2.5–5 MB**. Rust's default spawned-thread stack is **2 MB**; even the 8 MB main-thread stack is reachable with sufficiently deep tries. A stack overflow triggers an unrecoverable `SIGSEGV`/abort, killing the node process and stalling block processing until the operator restarts.

---

### Likelihood Explanation

- The attacker only needs to submit ordinary contract storage writes (`env::storage_write`) with keys crafted to maximise trie depth (e.g., keys that share a prefix of length N−1 nibbles but differ at nibble N, forcing a chain of branch nodes).
- No privileged role, validator key, or special permission is required.
- The GC fires automatically via `delete_until_height` during normal block processing.
- The attack is reproducible and deterministic once the deep trie is committed.

---

### Recommendation

Replace the recursive descent with an explicit iterative worklist (a `Vec` or `VecDeque` acting as a stack/queue). Collect all nodes to deallocate in a loop rather than via call-stack recursion:

```rust
let mut worklist = vec![*self];
while let Some(node_id) = worklist.pop() {
    // decrement refcount, collect children, dealloc, push children
}
```

This eliminates the call-stack depth dependency entirely and is O(1) stack regardless of trie depth.

### Proof of Concept

```rust
#[test]
fn test_remove_ref_deep_trie_no_stack_overflow() {
    // Build a trie with maximum-depth keys:
    // keys 0x00, 0x0000, 0x000000, ... up to 4096 bytes
    // Each key is a prefix of the next, forcing a chain of
    // branch nodes one nibble deep at each level.
    let mut tries = MemTries::new(ShardUId::single_shard());
    let mut changes = vec![];
    for depth in 1..=2048usize {
        let key = vec![0u8; depth];
        changes.push((key, Some(vec![1u8])));
    }
    // apply changes at height 1
    // ... (apply_memtrie_changes)
    // delete all keys at height 2
    // ... (apply_memtrie_changes with all deletions)
    // trigger GC — this should NOT abort with stack overflow
    tries.delete_until_height(2);
    assert_eq!(tries.num_roots(), 0);
}
```

The test asserts the process does not abort; without the fix it will `SIGSEGV` on a thread with a 2 MB stack.

        // It's possible that in a hybrid memory setup, we are accessing the read-only part of memory.
        // In that case, we don't need to decrement the refcount.
        if !arena.memory_mut().is_mutable(self.pos) {
            return 1;
        }
        // Refcount is always encoded as the first four bytes of the node memory.
        // cspell:words unref
        let refcount_memory = arena.memory_mut().raw_slice_mut(self.pos, size_of::<u32>());
        let refcount = u32::from_le_bytes(refcount_memory.try_into().unwrap());
        let new_refcount = refcount.strict_sub(1);
        refcount_memory.copy_from_slice(new_refcount.to_le_bytes().as_ref());
        if new_refcount == 0 {

    pub fn delete_root(&mut self, state_root: &CryptoHash) {
        if let Some(ids) = self.roots.get_mut(state_root) {
            let last_id = ids.last().unwrap();
            let new_ref = last_id.remove_ref(&mut self.arena);
