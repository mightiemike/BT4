### Title
Missing declared-class validation in `replace_class` syscall re-execution within the Starknet OS (SNOS) — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler inside the Starknet OS (SNOS) Cairo re-execution code updates a contract's class hash without verifying that the target class hash is actually declared. Blockifier — the Rust execution engine used for real block building — enforces this check. The two engines must be semantically identical because SNOS independently re-executes every transaction in a block to prove the state transition that Blockifier already computed. The missing check is an unauthorized/unchecked state mutation analogous to the reported `VestedZeroNFT.mint()` bug: a state-changing operation that is supposed to be gated by a validity check, but isn't, in one of the two code paths that must agree.

### Finding Description
Any contract can invoke `replace_class_syscall(class_hash)` — this requires no special privilege, only a normal transaction from any account/contract.

In Blockifier (Rust, used by the sequencer to actually build/execute blocks), the deprecated (Cairo0) syscall handler explicitly enforces that the class must be declared before the class hash can be swapped in: [1](#0-0) 

This is directly tested and confirmed to error with `"is not declared"` for an undeclared class hash: [2](#0-1) 

However, the corresponding Cairo implementation used by the Starknet OS to independently re-execute the same syscall (for Cairo1/Sierra contracts) performs the state update with **no declared-class check at all**, and this omission is explicitly flagged by the developers themselves with a TODO comment: [3](#0-2) 

The deprecated (Cairo0) execution path inside the OS has the identical gap — it too updates `contract_state_changes` unconditionally: [4](#0-3) 

Both dispatch sites route arbitrary `replace_class` requests straight into these unchecked functions: [5](#0-4) [6](#0-5) 

### Impact Explanation
Since SNOS re-execution is the mechanism used to independently verify/prove that a proposed block's state transition is correct (the OS is meant to reproduce, syscall-for-syscall, exactly what Blockifier computed), any semantic divergence between the two engines for a reachable syscall breaks the core soundness assumption of the pipeline. For a transaction that calls `replace_class_syscall` with an undeclared class hash:
- Blockifier (the real execution/consensus engine) fails the call and reverts the transaction (only fee state changes persist).
- SNOS re-execution, lacking the same guard, would accept the call and produce a state entry with the undeclared class hash, treating the transaction as non-reverted.

This is a genuine execution-engine divergence reachable from a single ordinary transaction (no malicious proposer/operator required — merely calling a documented, unprivileged syscall with an argument that should be, but isn't, validated on one of the two paths). Consequences include: SNOS computing a different state diff / revert status than Blockifier for the same transaction (honest-node divergence in the state committed vs. proven), and/or the proving pipeline later crashing (unhandled Cairo VM assertion failure) when a subsequent call/entry-point-execution attempts to look up compiled-class facts for the now-undeclared class hash, which is not present in `compiled_class_facts_bundle` — halting block proof generation for that block.

### Likelihood Explanation
Triggering the divergence requires only a single, unprivileged transaction from any contract calling the standard `replace_class_syscall` with an arbitrary (undeclared) class hash — a call any account or contract can make without special permissions, using calldata fully controlled by the caller. No collusion, staking role, or privileged infrastructure access is needed.

### Recommendation
Add the same "class must be declared" validation to the OS Cairo implementations of `execute_replace_class` (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that Blockifier already performs in `deprecated_syscalls/hint_processor.rs::replace_class` (and, if not already present, the modern `syscall_base.rs`/`hint_processor.rs::replace_class` path), so both execution engines reject `replace_class` on an undeclared class hash identically. Resolve the outstanding `TODO(Yoni, 1/1/2026)` before it ships to a network that relies on SNOS for proof generation.

### Proof of Concept
1. Deploy any contract exposing a function that calls `replace_class_syscall(class_hash)` with a caller-supplied `class_hash` (e.g. the existing test helper below). [7](#0-6) 
2. Submit an ordinary `INVOKE` transaction calling `test_replace_class(class_hash)` with a `class_hash` value that has never been declared on-chain.
3. Observe that Blockifier execution fails with `"... is not declared"` (as demonstrated in the existing unit test `test_replace_class`), reverting the transaction. [8](#0-7) 
4. Trace the equivalent syscall through the OS Cairo implementation (`execute_replace_class` in `syscall_impls.cairo`) and note that no equivalent "declared" check exists before `dict_update` commits the new (undeclared) class hash into `contract_state_changes` — confirming the two engines would compute different outcomes for the identical transaction.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
