### Title
Poison-microblock report key derived from mutable `microblock_pubkey_hash → height` map allows the same equivocation evidence to be paid out twice from two different tenures' coinbases - (File: `clarity/src/vm/database/clarity_db.rs`)

### Summary
`insert_microblock_pubkey_hash_height` stores a mapping from a microblock public-key hash to the height of whichever block most recently declared it, with no enforcement that a given pubkey hash is globally unique across tenures. [1](#0-0)  Because `get_microblock_poison_report`/`insert_microblock_poison` key their state purely off this mutable, overwritable height lookup rather than off anything intrinsic to the conflicting header pair, the same underlying double-signing evidence can be reported and paid out once per height it happens to resolve to. [2](#0-1) 

### Finding Description
The broken equality is: **reward paid == exactly one poison commission per unique double-signature (privkey, conflicting-header-pair)**. Instead, the actual invariant enforced by the code is only **reward paid == exactly one poison commission per height**, where "height" is resolved by looking up `get_microblock_pubkey_hash_height(pubkey_hash)` at the moment the `PoisonMicroblock` transaction is processed. [3](#0-2) 

`get_microblock_poison_report(height)`/`insert_microblock_poison(height, reporter, seq)` deduplicate reports only within the same `height` key. [4](#0-3)  There is no check anywhere in this data model that ties a report to the specific `pubkey_hash`/tenure it was first attributed to, nor any enforcement that a `microblock_pubkey_hash` is globally unique across all tenures a miner ever wins — `insert_microblock_pubkey_hash_height` simply overwrites the previous height for that hash whenever a new block declares it. [1](#0-0) 

Attacker input/exploit flow (attacker needs only to win two separate leader-election slots over time, i.e. no majority stake required):
1. Attacker wins a sortition and mines block H1, declaring `microblock_pubkey_hash = PKH` in the header, causing `insert_microblock_pubkey_hash_height(PKH, H1)`.
2. Attacker deliberately signs two conflicting microblocks (a fork) with the private key behind `PKH`.
3. A `PoisonMicroblock` transaction citing these two headers is mined while the map still resolves `PKH → H1`; this calls `insert_microblock_poison(H1, reporter, seq)`.
4. Later, the attacker wins another sortition and mines block H2, again declaring the *same* `microblock_pubkey_hash = PKH` (nothing prevents key reuse), causing `insert_microblock_pubkey_hash_height(PKH, H2)` to overwrite the H1 entry.
5. A second `PoisonMicroblock` transaction, citing the *exact same* two conflicting headers, is mined after this overwrite. The lookup now resolves `PKH → H2`, and since no report yet exists at key H2, `insert_microblock_poison(H2, reporter, seq)` succeeds, creating an independent report for the same offense.
6. When H1's coinbase matures, the reward for H1 is redirected to the reporter as poison commission; when H2's coinbase later matures, its reward is *also* redirected to the reporter — paying twice for a single act of key double-signing.

Existing guards do not stop this: the per-height dedup guard in `get_microblock_poison_report` only prevents a second report from being written at the *same* height key, and does nothing to detect that two different height keys were populated from the same underlying `pubkey_hash`/evidence. There is no cross-reference from `insert_microblock_poison` back to the `pubkey_hash` that produced the height, so the same header pair legitimately resolves to two disjoint report records.

### Impact Explanation
This results in block-reward double-payment: the same reported offense drains poison commission from two separate tenures' coinbases instead of one, i.e. a wrongful/duplicated reward payout. This matches the Critical category ("block-reward theft/double-payment/loss").

### Likelihood Explanation
Preconditions are attacker-only: the attacker must win two separate leader-election slots at different heights (achievable by any miner with nonzero committed BTC over time, not requiring majority stake), deliberately reuse the same microblock private key across both tenures, and produce one pair of conflicting microblocks. Both coinbases must mature within the `MINER_REWARD_MATURITY` window relative to the chain tip, which is a normal/expected condition and not an extra barrier. This is fully repeatable per pair of tenures a single attacker-controlled miner wins with a reused microblock key, at no cost beyond the normal cost of winning two sortitions.

### Recommendation
Bind the poison-microblock report/payout state to something intrinsic to the offense rather than to a mutable, overwritable `pubkey_hash → height` map — e.g., key the report by (or additionally validate against) the `pubkey_hash` itself, and/or reject/ignore `insert_microblock_pubkey_hash_height` writes that would overwrite an existing mapping for a `pubkey_hash` that already has an associated height and/or poison report, so a given microblock signing key can only ever be attributed to (and poison-forfeit) one tenure's reward.

### Proof of Concept
Rust integration test plan (chainstate/sim harness):
1. Construct two tenures at heights H1 and H2 where the anchored block header sets the same `microblock_pubkey_hash` (derived from one reused microblock private key) for both.
2. Sign one pair of conflicting microblocks (same sequence number, divergent content) with that private key.
3. Mine a `PoisonMicroblock` transaction citing this pair immediately after H1 (before H2 exists), and assert `get_microblock_poison_report(H1)` becomes `Some(reporter, seq)`.
4. Mine block H2 with the same `microblock_pubkey_hash`, and assert `get_microblock_pubkey_hash_height(PKH)` now returns `H2` (overwritten).
5. Mine a second `PoisonMicroblock` transaction citing the *same* header pair, and assert `get_microblock_poison_report(H2)` also becomes `Some(reporter, seq)`.
6. Advance the chain past `MINER_REWARD_MATURITY` for both H1 and H2, call `calculate_miner_reward` for each, and sum the STX paid to `reporter`.
7. Assert `total_paid_to_reporter > poison_microblock_commission(single_coinbase)` — i.e., strictly greater than one commission payout, proving double payment for one offense.

    pub fn get_microblock_pubkey_hash_height(
        &mut self,
        pubkey_hash: &Hash160,
    ) -> Result<Option<u32>, VmExecutionError> {
        let key = ClarityDatabase::make_microblock_pubkey_height_key(pubkey_hash);
        self.get_data(&key)?
            .map(|height_str: String| {
                height_str.parse::<u32>().map_err(|_| {
                    VmInternalError::Expect(
                        "BUG: inserted non-u32 as height of microblock pubkey hash".into(),
                    )
                    .into()
                })
            })
            .transpose()
    }

    /// Returns (who-reported-the-poison-microblock, sequence-of-microblock-fork)
    pub fn get_microblock_poison_report(
        &mut self,
        height: u32,
    ) -> Result<Option<(StandardPrincipalData, u16)>, VmExecutionError> {
        let key = ClarityDatabase::make_microblock_poison_key(height);
        self.get_data(&key)?
            .map(|reporter_hex_str: String| {
                let reporter_value = Value::try_deserialize_hex_untyped(&reporter_hex_str)
                    .map_err(|_| {
                        VmInternalError::Expect(
                            "BUG: failed to decode serialized poison-microblock reporter".into(),
                        )
                    })?;
                let tuple_data = reporter_value
                    .expect_tuple()
                    .map_err(|_| VmInternalError::Expect("Expected tuple".into()))?;
                let reporter_value = tuple_data
                    .get("reporter")
                    .map_err(|_| {
                        VmInternalError::Expect(
                            "BUG: poison-microblock report has no 'reporter'".into(),
                        )
                    })?
                    .to_owned();
                let seq_value = tuple_data
                    .get("sequence")
                    .map_err(|_| {
                        VmInternalError::Expect(
                            "BUG: poison-microblock report has no 'sequence'".into(),
                        )
                    })?
                    .to_owned();

                let reporter_principal = reporter_value
                    .expect_principal()
                    .map_err(|_| VmInternalError::Expect("Expected principal".into()))?;
                let seq_u128 = seq_value
                    .expect_u128()
                    .map_err(|_| VmInternalError::Expect("Expected u128".into()))?;

                let seq: u16 = seq_u128
                    .try_into()
                    .map_err(|_| VmInternalError::Expect("BUG: seq exceeds u16 max".into()))?;
                if let PrincipalData::Standard(principal_data) = reporter_principal {
                    Ok((principal_data, seq))
                } else {
                    Err(VmInternalError::Expect(
                        "BUG: poison-microblock report principal is not a standard principal"
                            .into(),
                    )
                    .into())
                }
            })
            .transpose()
    }
