### Title
Missing slashing/inactivity-leak enforcement for Super Representative misbehavior enables risk-free liveness attacks and reward capture - ([File: consensus/src/main/java/org/tron/consensus/dpos/StatisticManager.java])

### Summary
Java-tron's DPoS consensus tracks Super Representative (SR/witness) block production and double-block "cheat" evidence, but never converts this evidence into any economic penalty. A witness can go offline, double-produce blocks, or otherwise misbehave and still keep earning full voting/block rewards each cycle, with removal from the active set possible only through voter-driven vote withdrawal — never automatically. This mirrors exactly the reported bug class: absence of slashing, absence of inactivity leak, and lack of enforcement from misbehavior evidence.

### Finding Description
Block production/miss statistics are tracked purely for informational purposes in `StatisticManager.applyBlock`: for each slot the scheduled witness misses, `totalMissed` is incremented and logged, but no penalty, fund forfeiture, or state-transition consequence is applied. [1](#0-0) 

Separately, `WitnessProductBlockService.validWitnessProductTwoBlock` detects the on-chain equivalent of double-signing/double-production evidence (a witness producing two different blocks for the same slot) — analogous to `abci.Evidence` in the referenced report — but this evidence is only stored in an in-memory `cheatWitnessInfoMap` for display via `NodeInfoService`/metrics. No slashing, no removal from the active witness set, and no reward reduction is triggered. [2](#0-1) [3](#0-2) 

Active-witness-set membership is recomputed only from vote counts in `MaintenanceManager.doMaintenance()`; there is no automatic ejection based on `totalMissed`, `isJobs` history, or double-production evidence. A malicious or dead SR that nobody bothers to un-vote remains "active" indefinitely and continues to be scheduled/rewarded. [4](#0-3) 

Additionally, becoming an SR only requires a one-time fee-style balance check (`accountCapsule.getBalance() >= dynamicStore.getAccountUpgradeCost()`), not a continuously at-risk bonded stake that can be forfeited for misbehavior — funds can be transiently pooled/funded immediately before the transaction and are simply burned/paid as a fee, with no ongoing collateral tied to good behavior. [5](#0-4) [6](#0-5) 

`StateManager` does detect duplicate-block production for the node's own local safety (`isDupWitness`) to change its own consensus `State`, but this is a local liveness/self-protection guard, not a network-wide punitive mechanism against the offending SR's stake or rewards. [7](#0-6) 

### Impact Explanation
This creates a risk-free grief/liveness vector directly analogous to the reported bug class:
- An SR (super representative) that goes offline or intentionally withholds block production suffers no loss — it only accumulates `totalMissed` counters for cosmetic display, while still collecting rewards distributed via the maintenance/incentive cycle to all active witnesses regardless of performance.
- A malicious SR that double-produces blocks (equivocation) is only logged into `cheatWitnessInfoMap`, exposed via node metrics/API, but is not removed, slashed, or excluded from future reward distribution or the active set.
- Because active-set membership updates only from votes, an attacker who accumulates enough votes (or colludes/pools votes) can seat a malicious or non-performing witness that remains active until voters manually react — there is no automatic, protocol-enforced inactivity leak or eviction.
- This weakens the network's liveness and safety guarantees under the exact same rationale as the original report: censorship (skipping block production/transactions when scheduled), and the ability to repeatedly grief consensus participation without economic consequence.

### Likelihood Explanation
High likelihood of occurrence in practice: no adversarial action beyond acquiring/controlling sufficient votes or an existing SR slot is required. The behavior (missing blocks, double-producing) requires no special privilege and is a natural consequence of the current implementation rather than requiring an exploit of a parsing/authorization bug — it is a structural design gap consistently present across `StatisticManager`, `MaintenanceManager`, and `WitnessProductBlockService`.

### Recommendation
- Convert `totalMissed` tracking and `cheatWitnessInfoMap` double-production evidence into enforceable on-chain penalties (e.g., temporary/ permanent removal from the active SR set, vote-count/reward reduction, or stake slashing).
- Implement an automatic inactivity-leak mechanism in `MaintenanceManager.doMaintenance()` that evicts or down-weights witnesses whose missed-block ratio exceeds a threshold, independent of voter action.
- Require a continuously locked/bonded stake for SR candidacy (rather than a one-time `AccountUpgradeCost` fee) that can be forfeited upon proven misbehavior (double-signing/production) or extended inactivity.
- Feed `WitnessProductBlockService`'s cheat-detection output into the consensus state-transition logic so it has real economic/participatory consequences instead of being purely observational (metrics/API only).

### Proof of Concept
Conceptual walkthrough (no code changes required to demonstrate the gap, since it is a structural absence):
1. An SR is elected into the active set via `MaintenanceManager.doMaintenance()` based on vote count only. [8](#0-7) 
2. The SR goes offline for its scheduled slots. `StatisticManager.applyBlock` increments `totalMissed` for every missed slot but takes no other action. [1](#0-0) 
3. Alternatively, the SR runs two nodes with the same key and produces two different blocks for the same slot; `WitnessProductBlockService.validWitnessProductTwoBlock` records this into `cheatWitnessInfoMap`, visible only via `NodeInfoService.setCheatWitnessInfo`. [2](#0-1) 
4. In either case, the SR remains in the active set (no code path removes it based on `totalMissed` or cheat evidence) and continues to receive rewards distributed each maintenance cycle, with zero cost incurred for the misbehavior — confirming the risk-free nature of the attack.

  public void validWitnessProductTwoBlock(BlockCapsule block) {
    try {
      BlockCapsule blockCapsule = historyBlockCapsuleCache.getIfPresent(block.getNum());
      if (blockCapsule != null && Arrays.equals(blockCapsule.getWitnessAddress().toByteArray(),
          block.getWitnessAddress().toByteArray()) && !Arrays.equals(block.getBlockId().getBytes(),
          blockCapsule.getBlockId().getBytes())) {
        String key = ByteArray.toHexString(block.getWitnessAddress().toByteArray());
        if (!cheatWitnessInfoMap.containsKey(key)) {
          CheatWitnessInfo cheatWitnessInfo = new CheatWitnessInfo();
          cheatWitnessInfoMap.put(key, cheatWitnessInfo);
        }
        cheatWitnessInfoMap.get(key).clear().setTime(System.currentTimeMillis())
            .setLatestBlockNum(block.getNum()).add(block).add(blockCapsule).increment();
      } else {
        historyBlockCapsuleCache.put(block.getNum(), new BlockCapsule(block.getInstance()));
      }
    } catch (Exception e) {
      logger.error("valid witness same time product two block fail! blockNum: {}, blockHash: {}",
          block.getNum(), block.getBlockId().toString(), e);
    }
  }

  public Map<String, CheatWitnessInfo> queryCheatWitnessInfo() {
    return cheatWitnessInfoMap;
  }

  public void receiveBlock(BlockCapsule blockCapsule) {
    if (blockCapsule.generatedByMyself) {
      currentBlockId = blockCapsule.getBlockId();
      return;
    }

    if (blockCapsule.getBlockId().equals(currentBlockId)) {
      return;
    }

    if (dposService.isNeedSyncCheck()) {
      return;
    }

    if (System.currentTimeMillis() - blockCapsule.getTimeStamp() > BLOCK_PRODUCED_INTERVAL) {
      return;
    }

    ByteString witness = blockCapsule.getWitnessAddress();
    if (!dposService.getMiners().containsKey(witness)) {
      return;
    }

    if (dposService.getBlockHandle().getState() != State.OK) {
      dupBlockCount.set(1);
      return;
    }

    if (null != currentBlockId
        && currentBlockId.toString().compareTo(blockCapsule.getBlockId().toString()) > 0) {
      return;
    }

    dupBlockCount.set(1);
    dupBlockTime.set(System.currentTimeMillis());

    logger.warn("Dup block produced: {}", blockCapsule);
  }

  private boolean isDupWitness() {
    if (dupBlockCount.get() == 0) {
      return false;
    }
    if (System.currentTimeMillis() - dupBlockTime.get() > dupBlockCount.get() * blockCycle) {
      dupBlockCount.set(0);
      return false;
    }
    return true;
  }
