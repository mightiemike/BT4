Based on my research, I found a genuine native analog to the GLM truncation bug in Push Chain's gas fee accounting path.

### Title
Gas fee truncation to zero in `CalculateGasCost` allows fee-free payload execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
The GLM report describes a Solidity bug where `getGmTokenValueInUSDC()` performs `(gmTokenPrice * _amount * usdcPrice) / 1e30 / 1e18`, and for small `_amount` values the multi-step division truncates the result to `0`, so the caller's real, non-zero deposit is treated as worth nothing. Push Chain's `CalculateGasCost` in [1](#0-0)  has the same shape: it takes a `sdkmath.LegacyDec` `baseFee`, pulls out the raw fixed-point integer via `baseFee.BigInt()`, and then performs `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` to "unwrap" the Dec encoding back into a whole `upc` amount, based on a documented assumption that the base fee is *always* a whole number of `upc`.

### Finding Description
`DeductGasFeesFromReceipt`, at [2](#0-1)  calls `k.feemarketKeeper.GetBaseFee(sdkCtx)` and passes it straight into `CalculateGasCost`. If the true base fee (as computed by the EIP-1559-style feemarket module) is a fractional number of `upc` — e.g. `0.75`, which as an internal `LegacyDec` fixed-point integer is `750000000000000000` — then `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` performs Go big-int floor division and yields `0`, not `0.75` or `1`. This directly mirrors the GLM bug's `/1e30/1e18` truncation-to-zero for sub-threshold inputs.

Once `effectiveGasPrice` is `0`, `gasCost := effectiveGasPrice * gasUsed` is `0` regardless of how much gas was actually consumed, at [3](#0-2) . Back in `DeductGasFeesFromReceipt`, the check `if gasCost.Sign() <= 0 { return nil }` at [4](#0-3)  then silently skips fee deduction entirely — no `SendCoinsFromAccountToModule`/`BurnCoins` call happens via `DeductAndBurnFees` at [5](#0-4) .

The correctness of the whole calculation hinges on the in-code comment's claim: "the base fee is always a whole number of upc -- no fractional upc exists" ( [6](#0-5) ). This is an assumption about the feemarket module's EIP-1559 adjustment arithmetic (which multiplies the previous base fee by elasticity/gas-target ratios using `Dec` math), not an invariant enforced anywhere in the scoped `uexecutor` code. I was not able to fully verify from the indexed code whether the feemarket module actually clamps/rounds its base-fee output to a whole `upc` in all configurations (e.g., very low minimum gas price combined with sustained low block utilization). If that guarantee does not hold in some parameter/traffic regime, an ordinary user executing a `UniversalPayload` through `DeductGasFeesFromReceipt` at low network base fee would consume gas but pay zero `upc` for it.

### Impact Explanation
If the truncation is reachable, an unprivileged user's `DerivedEVMCall`/universal-payload gas cost silently rounds to zero, corrupting gas fee accounting: real EVM gas is consumed by the chain but the corresponding `upc` is never burned from the recipient. This is a direct analog of the "user's real value truncates to 0 in accounting" defect from the GLM report, falling under the explicitly in-scope "corruption of ... gas fee accounting" impact.

### Likelihood Explanation
Likelihood depends entirely on whether the feemarket module can produce a genuinely fractional base fee (in `upc` terms) under low-base-fee / low-utilization conditions, which I could not conclusively confirm or rule out from the available index. If the feemarket module always rounds/floors its base fee to a whole `upc` internally, this code path is dead and not exploitable. I could not read the feemarket base-fee computation source in this pass, so this should be verified against the exact feemarket parameters/genesis config in use before treating this as confirmed.

### Recommendation
Do not assume `baseFee` is exactly whole; use rounding-safe conversion (e.g., `baseFee.Ceil()`/explicit rounding with a documented policy) instead of raw integer division, and add a floor of at least `1 upc` per gas unit when `gasUsed > 0`, so gas consumption can never map to a zero fee. Alternatively, assert/enforce the "whole `upc`" invariant inside the feemarket module itself (fail loudly instead of silently truncating) so this code's assumption is actually guaranteed rather than just documented.

### Proof of Concept
1. Drive network conditions (via genesis min-gas-price or sustained low utilization) so `feemarketKeeper.GetBaseFee` returns a `LegacyDec` value with a non-zero fractional part below `1e18` in its integer representation (e.g. `0.9`).
2. Submit any inbound that results in a `UniversalPayload` execution and non-zero `receipt.GasUsed`.
3. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18)` = `0`, so `effectiveGasPrice = 0`, `gasCost = 0`.
4. `DeductGasFeesFromReceipt` returns `nil` without deducting/burning any fee, even though the EVM call consumed real gas — confirmed at [4](#0-3) .

**Caveat**: this finding's validity is conditional on the feemarket module's ability to produce a sub-1-`upc` fractional base fee, which I could not verify in this pass due to index coverage limits on the feemarket module source. Recommend starting a full Devin session with filesystem access to inspect `x/feemarket` (or the vendored cosmos/evm feemarket) base-fee computation to confirm or rule out this precondition before treating this as a confirmed, exploitable bug.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
