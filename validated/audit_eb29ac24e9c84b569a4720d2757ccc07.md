## Analysis

This is a valid finding. The client-side SVM event ingestion pipeline treats any `"Program data: "` log line whose first 8 bytes match a configured discriminator as a genuine gateway event, with no verification that the log was actually emitted by the gateway program's own instruction execution.

**Root cause chain:**

1. `processSlotRange` discovers candidate signatures via `GetSignaturesForAddress(gatewayAddr, ...)` [1](#0-0) . Solana's `getSignaturesForAddress` RPC returns any transaction where the address merely appears among an instruction's account keys — it does not require the address to be the *executed* program.

2. `processSignatureBatch` then iterates **every** log line in `tx.Meta.LogMessages` and calls `determineEventType`, which only checks the `"Program data: "` prefix and the leading 8-byte discriminator: [2](#0-1) [3](#0-2) . There is no correlation with the surrounding `"Program <id> invoke [n]"` / `"Program <id> success"` bracket lines that Solana runtime uses to attribute a log line to the program that was executing when it called `sol_log_data`.

3. `ParseEvent` / `parseSendFundsEvent` decode the base64 payload trusting it entirely as a well-formed `sendFunds` (or finalize/revert) event, including sender, recipient, amount, raw payload, and `VerificationData`: [4](#0-3) .

4. `event_confirmer.processPendingEvents` only checks `tx.Meta.Err == nil` and slot depth before promoting to `CONFIRMED` — again no program-provenance check: [5](#0-4) .

5. `EventProcessor.processInboundEvent` then submits `MsgVoteInbound` via the signer: [6](#0-5) . Because parsing is fully deterministic given the immutable on-chain transaction, **every honest UV** running unmodified client code independently derives the identical forged `Inbound`, so 2/3+ honest votes converge naturally — this is not a malicious-validator scenario.

6. Once the ballot passes, `VoteInbound` creates a canonical `UniversalTx` and calls `k.ExecuteInbound`, which mints PRC20/native representation and can run an attacker-chosen payload through the UEA: [7](#0-6) .

An unprivileged attacker can build a single Solana transaction that (a) references the real gateway program address as a read-only/unused account in one instruction (satisfying `GetSignaturesForAddress`), and (b) invokes any other callable program (including one they deploy themselves, since Solana program deployment is permissionless) that emits `sol_log_data` with a crafted 8-byte discriminator equal to the registered `sendFunds` identifier, followed by an attacker-chosen Borsh payload matching `decodeUniversalTxEvent`'s expected layout. No real gateway instruction, and no real fund movement on Solana, is required.

### Title
Forged inbound gateway event accepted because SVM log parser doesn't verify program provenance - (File: `universalClient/chains/svm/event_listener.go`, `universalClient/chains/svm/event_parser.go`)

### Summary
`determineEventType`/`ParseEvent` in the SVM event pipeline treat any `"Program data: "` log line with a matching 8-byte discriminator as an authentic gateway event, without verifying that the log was emitted by the gateway program's own CPI frame. `GetSignaturesForAddress(gatewayAddr,...)` further only requires the gateway address to appear somewhere in the transaction's account list, not to be the invoked program. Combined, an unprivileged user can craft an ordinary Solana transaction — invoking an unrelated (even self-deployed) program that logs a fabricated `sendFunds`/`finalizeUniversalTx` discriminator plus arbitrary payload bytes — and have it deterministically parsed by every honest Universal Validator's client as a real inbound deposit.

### Impact Explanation
Because the forgery is embedded in an immutable on-chain transaction, all honest UVs derive the identical bogus `Inbound` and reach quorum honestly via `MsgVoteInbound`, causing `x/uexecutor` to create a canonical `UniversalTx` and execute it — minting PRC20/native representation to an attacker-chosen recipient and/or running an attacker-chosen `UniversalPayload` through a UEA, with no real funds ever having moved on Solana. This is unauthorized minting / forged accepted protocol state with material fund-loss and accounting-corruption impact [8](#0-7) .

### Likelihood Explanation
High. Deploying an arbitrary Solana program and calling `sol_log_data`/CPI-log with attacker-controlled bytes is a standard, permissionless, low-cost operation; no privileged role, validator collusion, or key compromise is required.

### Recommendation
When scanning `tx.Meta.LogMessages`, track the invocation stack (the `"Program <id> invoke [n]"`/`"Program <id> success"` bracket lines) and only accept a `"Program data:"` line as a gateway event if it falls within the stack frame where the invoked program equals the configured gateway address. Additionally, prefer parsing structured `innerInstructions`/CPI logs (or Anchor's typed event log parser) rather than raw string scanning of the flat log array.

### Proof of Concept
1. Deploy (or reuse) any Solana program `X` that calls `sol_log_data(discriminator_bytes || fake_payload)`.
2. Build a transaction with two instructions: (a) any benign instruction listing the real gateway program address as a read-only account, and (b) an instruction invoking `X` with `discriminator_bytes` = the registered `sendFunds` `EventIdentifier` and `fake_payload` matching the `decodeUniversalTxEvent` Borsh layout (sender/recipient/bridge_token/bridge_amount/raw_payload/revert_recipient/tx_type/sig_data).
3. Submit the transaction (any funded wallet, no gateway interaction needed).
4. `GetSignaturesForAddress(gatewayAddr,...)` returns this signature; `processSignatureBatch` → `determineEventType` → `ParseEvent` produce a fabricated `store.EventTypeInbound` event and store it via `InsertEventIfNotExists` [9](#0-8) .
5. After confirmation depth passes (`tx.Meta.Err` is nil since `X`'s own instruction succeeded), `EventProcessor` submits `MsgVoteInbound` with the forged data; every honest UV does the same, ballot passes, and `ExecuteInbound` mints/executes on Push Chain.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

// parseSendFundsEvent parses a sendFunds event as UniversalTx
func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event

// processInboundEvent processes an inbound event by voting on it and confirming it
func (ep *EventProcessor) processInboundEvent(ctx context.Context, event *store.Event) error {
	ep.logger.Debug().
		Str("event_id", event.EventID).
		Msg("processing inbound event")

	// Extract inbound data from event
	inbound, err := ep.constructInbound(event)
	if err != nil {
		return fmt.Errorf("failed to construct inbound: %w", err)
	}

	// Execute vote on blockchain
	voteTxHash, err := ep.signer.VoteInbound(ctx, inbound)
	if err != nil {
		ep.logger.Error().
			Str("event_id", event.EventID).
			Err(err).
			Msg("failed to vote on event - keeping status for retry")
		return err
	}
