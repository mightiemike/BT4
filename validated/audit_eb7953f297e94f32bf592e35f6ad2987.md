## Analysis

The GMX bug is fundamentally about a code path where a swap operation can fail, and the failure-handling branch does not preserve the fund-safety guarantee that the success branch provides — leaving the user's value unprotected in the failure case. Push Chain's `x/uexecutor` module has a close analog in the isCEA `GAS_AND_PAYLOAD` inbound execution flow, where a failed slippage-protected autoswap results not in reduced output (as in GMX) but in **permanent loss of the fallback/revert path entirely**, i.e. a stronger version of the same underlying defect class: "swap failure is not compensated for."

### Title
Permanent freezing of bridged funds when isCEA `GAS_AND_PAYLOAD` autoswap fails slippage/quote checks - (File: `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
For `isCEA`-flagged `GAS_AND_PAYLOAD` inbounds, `ExecuteInboundGasAndPayload` deposits and swaps the bridged asset via `gasAndPayloadDepositAutoSwap`, which computes a 5%-slippage `minPCOut` bound and calls `CallPRC20DepositAutoSwap` [1](#0-0) . If this atomic mint+swap EVM call reverts (e.g. quote moved beyond the 5% band, quoter/fee-tier lookup failure, or any on-chain condition causing the swap to miss `minPCOut`), `execErr` is set [2](#0-1) , but the code explicitly documents that "isCEA failures never create an INBOUND_REVERT outbound" [3](#0-2)  and simply records a FAILED `PCTx` and returns with no further action [4](#0-3) .

### Finding Description
Because the inbound was already observed and voted PASSED by validators (the bridging deposit already occurred and was consumed on the source chain), the `UniversalTx` on Push Chain represents funds that are owed to the user. When the on-chain autoswap mint fails its slippage check, no PRC20 is minted on Push Chain (the EVM call reverts atomically, so nothing is created), and — unlike the non-isCEA path, which calls `buildRevertOutbound`/`attachOutboundsToUtx` to schedule an `INBOUND_REVERT` outbound refunding the user on the source chain [5](#0-4)  — the isCEA branch deliberately skips this recovery mechanism. The `UniversalTx` is left with a FAILED `PCTx` and no `OutboundTx`, and the module provides no automatic or user-triggered mechanism afterward to retry or refund an isCEA-failed deposit.

This mirrors the GMX root cause precisely: a swap's failure path does not carry forward the same value-preservation guarantee that the success path provides. In Push Chain's case, the failure path is even more severe than GMX's (partial loss due to reused slippage bound) — it is total, permanent loss of the bridged value with no recourse.

### Impact Explanation
This directly matches the in-scope impact "permanent freezing... of user... funds" and "corruption of... canonical UniversalTx state" — the `UniversalTx` for the inbound reaches a terminal FAILED `PcTx` state with no `OutboundTx` attached, and `PendingInbounds` is cleared on ballot finalization regardless of `execErr`, so there is no automatic retry surface. The user's asset, already spent/locked on the source chain by their own honest transaction, has no path to be represented on Push Chain nor refunded back.

### Likelihood Explanation
No privileged or malicious actor is required. An ordinary user submitting an isCEA `GAS_AND_PAYLOAD` inbound can trigger this purely through normal price movement inside the block window between when validators build the on-chain quote and when the swap executes, especially since the slippage tolerance is a fixed 5% band [6](#0-5) ; any temporary quoter/fee-tier lookup failure has the same effect. This makes the condition reachable through default, unprivileged transaction submission alone.

### Recommendation
For isCEA inbound failures in the swap-dependent path, either (a) attach a fallback deposit-without-swap (mirroring the pattern already used in `applyGasRefund`'s `withSwap=false` fallback) so the user still receives value on Push Chain, or (b) allow an `INBOUND_REVERT` outbound to be scheduled for isCEA failures just as it is for non-isCEA failures, so funds are returned to the source chain instead of being stranded.

### Proof of Concept
1. User bridges an asset via an isCEA `GAS_AND_PAYLOAD` inbound with `Recipient` set to a deployed UEA.
2. Validators reach quorum and finalize the inbound vote; `ExecuteInboundGasAndPayload` runs.
3. `gasAndPayloadDepositAutoSwap` computes `minPCOut` from a quote fetched at execution time; before/at the same EVM call, on-chain liquidity price shifts (or the quoter/fee-tier call intermittently fails), causing `CallPRC20DepositAutoSwap`'s underlying `depositPRC20WithAutoSwap` to revert.
4. `execErr != nil` is set; because `utx.InboundTx.IsCEA == true`, execution falls into the "isCEA failures: record FAILED PCTx but no revert" branch and returns `nil` [4](#0-3) .
5. Query the `UniversalTx`: it shows a FAILED `PcTx` entry, empty `OutboundTx`, and no further processing occurs — the bridged funds are unrecoverable through any user-reachable path.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
