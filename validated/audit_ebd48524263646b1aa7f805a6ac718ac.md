### Title
`accrue` pause flag silently skips interest accrual instead of blocking dependent operations, letting deposit/borrow/repay/redeem run against a frozen index - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
In all six vault contracts (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`), the `accrue` function is designed as a pause "pass-through" rather than a hard stop: when the `accrue` bit of `pause-states` is set, it returns `(ok { index: idx, lindex: lidx })` without recomputing `next-index`/`next-liquidity-index`, without minting the treasury reserve share, and without updating `last-update`. All state-mutating entry points (`deposit`, `redeem`, `system-borrow`, `system-repay`) call `(try! (accrue))` and then continue to execute using the (now stale) `index`/`lindex` values as if nothing were wrong.

### Finding Description
`accrue` is gated by a pause bit rather than being enforced as an invariant-preserving checkpoint: [1](#0-0) 

When `(get accrue states)` is `true`, the function returns early with the *unchanged* `idx`/`lidx` and an `ok` result — it never reverts, and none of the side effects that keep the index consistent with elapsed time (`var-set index next`, `var-set lindex nliq`, treasury `ft-mint?`, `var-set last-update`) happen.

Every state-mutating operation calls `accrue` as a checkpoint and then proceeds unconditionally on its `ok` result: [2](#0-1) [3](#0-2) [4](#0-3) 

Because `try!` only short-circuits on an `err`, and the paused branch of `accrue` always returns `ok`, pausing accrual does not block `deposit`, `redeem`, `system-borrow`, or `system-repay` from executing — it merely freezes the `index`/`lindex` used by all of them. This is precisely the pattern of "a pause that passes through instead of reverting": the guard exists syntactically (`try! (accrue)`) but its semantics silently no-op instead of halting the dependent, invariant-sensitive operations that rely on `index` accurately reflecting elapsed time and rate.

The root cause is that `next-index` computes the multiplier from `interest-rate` and `time-delta` every call, and while paused this computation and its resulting debt/interest bookkeeping (`old-debt`, `new-debt`, `debt-delta`, `reserve-inc`, `treasury-lp`) are skipped entirely rather than being bounded/deferred safely — the analogous defect to `_getOverheadForTransaction` not bounding the intermediate quantities it derives, except here the un-checked quantity is time-based interest accrual that keeps advancing in reality but is frozen in state while dependent operations keep mutating principal/assets.

### Impact Explanation
While `accrue` is paused (an operator action, but the abuse itself requires no operator collusion — any user can act during the pause window):
- Borrowers can `system-borrow`/`system-repay` at a frozen `index`, effectively borrowing/repaying without correct interest being charged for the duration of the pause, capturing interest that would otherwise accrue to LPs/treasury.
- LPs are prevented from earning the yield they would otherwise be due (`treasury-lp` mint and `index` growth are both skipped), while deposits/redemptions continue to be priced off the stale index via `convert-to-shares-preview`/`convert-to-assets-preview`.

This matches the in-scope impact class of theft/temporary freezing of unclaimed yield: LP yield that should have accrued during the pause window is lost/frozen, and the value is effectively captured or diluted through unaffected borrow/repay activity continuing on a stale rate basis.

### Likelihood Explanation
Triggering the condition requires the `accrue` pause bit to be set (an operator/DAO action), but once set, any ordinary user can call `deposit`, `redeem`, `system-borrow`, or `system-repay` — no special privilege is needed to exploit the stale-index window, and the exploit is a single-transaction interaction with each of these entry points. The likelihood is moderate: it depends on the pause being active (e.g., during an incident response), which is exactly when this pass-through failure mode would matter most and be most damaging.

### Recommendation
Change `accrue`'s paused branch so that pausing "accrue" also blocks (reverts) the operations that depend on it — i.e., have `deposit`, `redeem`, `system-borrow`, and `system-repay` explicitly check the `accrue` pause bit and `asserts! ... ERR-PAUSED` instead of relying on `accrue`'s `ok` pass-through to implicitly signal safety. Alternatively, have `accrue` return an `err` when paused and only allow the specific admin/rescue functions that are meant to operate under an accrual pause to call it.

### Proof of Concept
1. Operator/DAO sets `pause-states` with `accrue: true` on `v0-vault-stx` (e.g., during an interest-rate-model incident).
2. Attacker calls `system-borrow` (or `deposit`/`redeem`/`system-repay`) on the vault.
3. Inside `system-borrow`, `(try! (accrue))` hits the paused branch and returns `(ok { index: idx, lindex: lidx })` with the old, un-updated `idx`. [5](#0-4) 
4. `system-borrow` proceeds normally using the stale `idx`, computing `scaled-amount` and updating `principal-scaled`/`total-borrowed` as if no interest had accrued during the pause, even though real time (`stacks-block-time`) has advanced.
5. Repeat across the pause window: every borrow/repay/deposit/redeem executes against the frozen index, permanently skipping the interest and treasury-fee accrual that should have applied for that period once accrual resumes (since `last-update` is only advanced when the index actually changes), rather than the pause reverting these operations.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
