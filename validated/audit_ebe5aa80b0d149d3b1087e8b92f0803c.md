### Title
Missing "class must be declared" validation in Starknet OS `execute_replace_class` causes execution divergence from Blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS Cairo implementation of the `ReplaceClass` syscall omits the check that the target `class_hash` must correspond to a declared class, a validation that the Blockifier (the execution engine that actually builds/commits blocks) explicitly performs. This missing precondition in the OS re-execution path is analogous to the reported Solidity bug class: a state-mutating entry point that is missing a required guard that its sibling/equivalent implementation enforces, allowing an unprivileged caller (any contract, via a single submitted transaction) to reach a codepath that should have rejected the action.

### Finding Description
In the Blockifier, the `replace_class` syscall handler explicitly ensures the target class is declared before mutating state: [1](#0-0) 

The non-deprecated syscall path funnels into the same guarded `syscall_base::replace_class`, and dedicated tests confirm this behavior — an undeclared class hash is rejected with `"is not declared"`: [2](#0-1) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used for STARK-proof re-execution of the block) performs the state mutation directly, with an explicit `TODO` acknowledging that the declared-class check is not implemented: [3](#0-2) 

The same gap exists in the deprecated (Cairo0) syscall path in the OS program: [4](#0-3) 

This is reachable by any contract executing `replace_class_syscall(class_hash)` with an arbitrary, undeclared `class_hash` — a single unprivileged transaction/contract call is sufficient to trigger the divergent codepath, matching the "unauthorized account action" and "Starknet OS re-execution" categories in scope.

### Impact Explanation
Because Blockifier enforces the "class must be declared" precondition and reverts/fails the call when it is violated, while the Starknet OS Cairo implementation performs the class-hash swap unconditionally, the two execution engines can produce different outcomes (success vs. revert) for the identical transaction and identical undeclared `class_hash` input. Since the OS is the component responsible for re-executing transactions to produce the proven state transition (used in the honest-node/proving path), this divergence between the committed Blockifier execution result and the OS's independently computed result can lead to an incorrect state root / wrong committed state being proven, or a proof-verification failure that halts block finalization — i.e., honest-node divergence and inability to correctly confirm the state transition, corresponding to the "wrong committed root" / "honest-node divergence" impact categories.

### Likelihood Explanation
The trigger is trivial and fully attacker-controlled: any account/contract can call `replace_class_syscall` with a `class_hash` that has never been declared, from within any Invoke, Declare-follow-up, or `__execute__` call. No special privileges, staking, or network position is required — a single ordinary transaction reaching this syscall is enough to expose the divergence during OS re-execution/proving of that block.

### Recommendation
Add the missing "class must be declared" check to the OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` implementations) so that it mirrors the Blockifier's `get_compiled_class` check in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801`, ensuring both execution engines reject (or accept) the syscall identically before committing/proving any state change of the contract's class hash.

### Proof of Concept
1. Deploy a contract that exposes a wrapper around `replace_class_syscall`.
2. Submit a transaction invoking that wrapper with a `class_hash` value that has not been declared on-chain.
3. Under Blockifier (block building), the call fails with `"is not declared"` as shown by the test at [2](#0-1) .
4. Under the Starknet OS Cairo re-execution of the same call (`execute_replace_class` in `syscall_impls.cairo:881-920`), no such check exists, so the class hash swap proceeds unconditionally — producing a different execution result/state update than the one Blockifier committed for that transaction.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
