### Title
`TransactionOutput::ensure_match_transaction_info` omits checkpoint-hash verification, allowing replay/verification to accept outputs with a divergent authenticated state root - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used to check that a locally-computed `TransactionOutput` matches an authenticated `TransactionInfo` (the object committed into the transaction accumulator and signed via `LedgerInfo`). The function explicitly skips verification of `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` — the very fields that bind a `TransactionInfo` to the correct state-tree root — even though the code comment acknowledges this is unsafe once the trading-native state roots feature is enabled.

### Finding Description
`ensure_match_transaction_info` checks transaction status, gas used, write-set hash (`state_change_hash`), and event root hash against the authenticated `TransactionInfo`, but never calls `TransactionInfo::state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()` for comparison: [1](#0-0) 

The function's own trailing comment documents the gap directly: [2](#0-1) 

`TransactionInfoV1` carries `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` as part of the authenticated, hashed structure that is signed by validators inside `LedgerInfo`: [3](#0-2) 

These checkpoint hashes are exactly the values computed independently during execution/commit (`do_state_checkpoint.rs`, `do_ledger_update.rs`) to prove the state-tree root, hot-state root, and (when `compute_trading_native_state_roots` is enabled) the native "position" state root: [4](#0-3) 

Because `ensure_match_transaction_info` is the generic sanity-check API used by verification/replay tooling (`aptos-debugger`, `db-tool`'s `replay_on_archive`, CLI commands, and the executor's chunk-executor path) to assert "my locally recomputed output matches what's committed," any caller relying on it as a *complete* correctness check will not detect a mismatch between locally derived state/hot-state/position roots and the authenticated roots baked into the signed `TransactionInfo`.

### Impact Explanation
If a local execution/replay path (or state-sync verification path) trusts `ensure_match_transaction_info` as its full validity check while feeding it a `TransactionInfo` that carries `state_checkpoint_hash`/`position_state_checkpoint_hash`, a divergence between the locally computed state root and the authenticated on-chain root would not be caught. This falls squarely under the "state proof accepted as valid despite wrong root" and "hard-fork-only divergence during commit/replay" categories in scope, since it is specifically the state-tree/position-tree commitment binding that is skipped, not an event-only or cosmetic mismatch.

### Likelihood Explanation
I could only confirm this at the level of the shared library function and its documented gap; I was not able to finish tracing, within the tool budget, whether any **live/mainnet-critical** commit or state-sync path (as opposed to strictly offline debugging/replay tooling in `db-tool` and `aptos-debugger`) depends on this function without an additional, independent checkpoint-hash comparison elsewhere in the call chain (e.g., `execution/executor/src/chunk_executor/mod.rs`, which I found references `ensure_match_transaction_info` but did not get to read in full). The feature this gap specifically threatens (`compute_trading_native_state_roots` / native position-state roots) also appears to be a not-yet-fully-enabled feature per the TODO comment, which lowers, but does not eliminate, present-day exploitability.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and (when applicable) `position_state_checkpoint_hash` from `txn_info` against the locally computed values, gated appropriately for versions/paths that don't produce hot/position checkpoints, before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` on mainnet. Independently, confirm whether `execution/executor/src/chunk_executor/mod.rs`'s use of this function is backstopped elsewhere by a full checkpoint-hash check, since I was unable to verify that in this session.

### Proof of Concept

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
