### Title
Sandwichable single-block Uniswap V3 quote used as slippage bound for module-originated gas-abstraction swap - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
`ExecuteInboundGas` computes the amount of native PC a user receives when their deposited PRC20 is auto-swapped for gas, by calling `GetSwapQuote` (a `QuoterV2.quoteExactInputSingle` view call against the live Uniswap V3 pool state) and deriving `minPCOut` as `quote * 95 / 100` [1](#0-0) . The quote and the deposit+swap execution (`CallPRC20DepositAutoSwap`) happen back-to-back inside the same inbound-processing call, with no TWAP, oracle check, or minimum-quality guard, mirroring the audited Frax pattern of pricing off a single manipulable AMM read used immediately for a fund-affecting decision.

### Finding Description
`GetSwapQuote` queries `quoteExactInputSingle` on the configured Uniswap V3 pool for `prc20 -> wpc` at the current pool tick/liquidity state [2](#0-1) . `ExecuteInboundGas` then applies a flat 5% slippage tolerance on top of that single spot-style quote and passes the resulting `minPCOut` straight into `CallPRC20DepositAutoSwap`, which performs the actual on-chain swap via the `UniversalCore.depositPRC20WithAutoSwap` handler [3](#0-2) [4](#0-3) . Because the quote is read and consumed within the same block/transaction context, an attacker who can move the underlying Uniswap V3 pool price immediately before the module's inbound is processed (e.g., by depositing an inbound whose processing is predictable, then trading against the same pool in an adjacent transaction within the block) can bias the quote in either direction: pushing it down tightens `minPCOut` so the swap still executes at a bad rate against the module (protocol-controlled) side, or — more importantly — pushing it up inflates the accepted `minPCOut` floor so that when the price reverts before/at execution the swap either reverts (denial of the user's gas-abstraction deposit, forcing a revert-and-refund cycle) or completes at an unfavorable rate that drains value from the protocol-held liquidity/module funds used to source PC for the swap.

### Impact Explanation
This function executes module-originated EVM calls that move real funds (a user's deposited PRC20 collateral swapped for native PC via a protocol-controlled AMM path) with no oracle, TWAP, or multi-block sanity check backing the slippage bound — only a bespoke ±5% band on a single spot read. That fits the in-scope impact "corruption of ... gas fee accounting, refund accounting ... PRC20 or native asset accounting" and potential "unauthorized module-originated EVM execution" producing a wrong-value outcome, since the fund-moving decision (`minPCOut`) is derived from attacker-influenceable, single-point AMM state rather than a manipulation-resistant price source.

### Likelihood Explanation
Likelihood is constrained by two factors I could not fully verify from the indexed code: (1) whether `ExecuteInboundGas` runs deterministically in the same block as attacker-controlled DEX trades (Cosmos SDK `DeliverTx`/ABCI ordering and whether inbound execution is triggered synchronously by ballot finalization in the same block as arbitrary user EVM txs), and (2) the actual liquidity depth/configuration of the `uniswapV3Quoter`/pool used for `prc20`→`wpc`, which determines how cheaply the quote can be moved. Given typical low liquidity of a newly-launched internal WPC pool and the lack of any TWAP/oracle cross-check in the code shown, the likelihood of profitable manipulation is plausible but not confirmed without further investigation into block-scheduling and pool liquidity parameters, which the index does not fully expose.

### Recommendation
- Short term: do not rely solely on `quoteExactInputSingle`'s instantaneous quote; add a maximum-quote-vs-config-price deviation check, or source `minPCOut` from a TWAP (`observe()`) over a window resistant to single-block manipulation.
- Long term: bound gas-abstraction auto-swap amounts by a registry-configured reference price (already available via `uregistry`/chain-meta oracle infrastructure) and reject/fallback-to-non-swap-deposit when the live AMM quote deviates beyond a safe threshold from that reference.

### Proof of Concept
Not directly demonstrable from the indexed repository alone: constructing a concrete PoC requires confirming (a) exact block/ordering semantics between `MsgVoteInbound`-triggered execution of `ExecuteInboundGas` and ordinary EVM transactions in the same block, and (b) the deployed Uniswap V3 pool's liquidity for the `prc20`/`WPC` pair, neither of which is available in the indexed contents. A Devin session with full repo/build access would be needed to trace `x/uvalidator` ballot finalization scheduling relative to EVM tx inclusion and to inspect the on-chain `UniversalCore`/pool deployment parameters before confirming exploitability end-to-end.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
