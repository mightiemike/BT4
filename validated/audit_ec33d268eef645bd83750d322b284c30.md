Based on my research, `RevertStuckInbound` is an **admin-only** escape hatch (line 187: `if admin != msg.Signer`), which is explicitly out of scope per the task's privileged-actor exclusion. The unprivileged, user-reachable angle is that a normal user's inbound event can be split into multiple `InboundVariant`s by honest validators decoding the same on-chain event slightly differently (e.g. divergent field formatting/rounding), each producing a distinct ballot key. If none of these variants reach the 2/3 threshold before expiry, `BallotHooks.afterInboundBallotTerminal` archives the whole audit trail into `ExpiredInbounds` and **no `UniversalTx`, no outbound, and no refund is ever created** — the docstrings and proto comments repeatedly confirm the actual refund flow is only "future" work, and the only present remedy (`MsgRevertStuckInbound`) requires the chain admin to manually resubmit the exact inbound off-chain, with no automatic or user-triggered path.

### Title
Unprivileged inbound-variant fragmentation permanently strands user deposits with no non-admin refund path - (File: x/uexecutor/keeper/ballot_hooks.go)

### Summary
When Universal Validators independently vote on the same source-chain inbound event but marshal even slightly different `Inbound` byte representations, `x/uexecutor` treats each byte-distinct payload as a separate `InboundVariant` with its own ballot and its own 2/3 threshold [1](#0-0) . If the votes for a single logical deposit split across variants such that no single variant ever reaches quorum before its ballot expires, `BallotHooks.afterInboundBallotTerminal` removes the tracking entry from `PendingInbounds` and archives it into `ExpiredInbounds` — without ever creating a `UniversalTx`, minting PRC20s, or emitting a refund outbound [2](#0-1) . The proto and code comments explicitly state this archive is only "consumed by the future escape-hatch refund flow" — i.e., that flow does not yet exist [3](#0-2) .

### Finding Description
A user deposits funds into the external-chain gateway/vault, generating a single logical inbound event. Universal Validators observe this event and submit `MsgVoteInbound`; the ballot key is `hex(marshal(Inbound))`, so any byte-level divergence in how honest validators decode/format the event (e.g. differing numeric formatting, optional-field presence, canonicalization edge cases not fully covered by `Inbound.Canonicalize()`) produces a different ballot per variant [4](#0-3) . Each variant needs independent 2/3 threshold votes to pass [5](#0-4) .

If validator votes for the same deposit are split across two or more variants such that none reaches its own threshold before `BlockHeightExpiry`, every variant terminates `EXPIRED`/`REJECTED`. `afterInboundBallotTerminal` then moves the whole entry to `ExpiredInbounds` with no `UniversalTx`, no PRC20 mint, and no outbound revert created [6](#0-5) .

The only currently implemented remedy, `MsgRevertStuckInbound`, is gated to `signer == uvalidator Params.Admin` [7](#0-6) , requires the admin to manually reconstruct the exact canonical `Inbound` bytes off-chain since "the chain does not persist ballot payloads" [8](#0-7) , and only operates on a ballot that is already `EXPIRED` (not one still churning across multiple never-finalizing variants) [9](#0-8) . There is no user-callable message and no automatic chain-driven path to reclaim funds once `ExpiredInbounds` is populated.

### Impact Explanation
This mirrors the Linea report's core defect: a user's deposit can become permanently unrecoverable through any ordinary, user- or validator-side (non-malicious) code path, with the only recovery mechanism gated behind a privileged admin action that itself depends on manual off-chain reconstruction of the exact voted bytes. Funds already locked/burned on the source-chain gateway have no way back to the user without that specific admin intervention — the escape hatch documented as the actual fix ("future escape-hatch refund flow") does not exist yet in this codebase.

### Likelihood Explanation
Requires only ordinary honest-validator divergence in decoding/marshaling one source-chain event (not malicious behavior) — something the codebase itself anticipates and builds an entire variant-tracking system around, which indicates it is a real, expected occurrence rather than a hypothetical edge case. Triggering full fragmentation across enough variants to prevent any one from reaching quorum requires either a moderately large validator set or unlucky/adversarial event encoding on the source chain (e.g. ambiguous ABI decoding), making likelihood moderate rather than trivial, but the total absence of an automated recovery path means any occurrence results in permanent loss.

### Recommendation
Implement the "future escape-hatch refund flow" referenced throughout the code: automatically (or via a permissionless, rate-limited user message) create a revert/refund `UniversalTx` and outbound for entries that land in `ExpiredInbounds`, without requiring the admin to manually resupply canonical bytes. At minimum, allow the depositor (identified by `Sender`/`RevertInstructions.FundRecipient` recovered from any one archived variant) to trigger the refund permissionlessly once all variants are confirmed terminal.

### Proof of Concept
1. User deposits funds via the external-chain gateway, producing one gateway event.
2. Two honest Universal Validators observe the event but, due to a decoding/formatting discrepancy (e.g. differing byte padding or field ordering not caught by `Inbound.Canonicalize()`), submit `MsgVoteInbound` with two different marshaled `Inbound` byte sequences → two `InboundVariant`s under the same `PendingInboundEntry` [10](#0-9) .
3. Remaining validators split their votes across the two variants such that neither variant ever reaches the 2/3 threshold before `BlockHeightExpiry`.
4. Both ballots terminate `EXPIRED`; `afterInboundBallotTerminal` fires for each, and once all variants are terminal, the entry is removed from `PendingInbounds` and copied into `ExpiredInbounds` [2](#0-1) , confirmed by `TestBallotHook_MultiVariant_AllExpiredRoutesEntireEntry` [11](#0-10) .
5. No `UniversalTx` exists for this deposit, so the user cannot query or claim it; the only recovery is `MsgRevertStuckInbound`, restricted to the module's admin address and requiring off-chain reconstruction of the original payload — with no user-facing or automated fallback in the current code.

func (k Keeper) VoteInbound(ctx context.Context, universalValidator sdk.ValAddress, inbound types.Inbound) error {
	// Canonicalize first so every derived key + the stored inbound use one
	// representation per logical event.
	inbound.Canonicalize()

	k.Logger().Info("vote inbound received",
		"validator", universalValidator.String(),
		"source_chain", inbound.SourceChain,
		"tx_hash", inbound.TxHash,
		"tx_type", inbound.TxType.String(),
		"sender", inbound.Sender,
	)

	// Check inbound enabled before any state changes
	enabled, err := k.uregistryKeeper.IsChainInboundEnabled(ctx, inbound.SourceChain)
	if err != nil {
		return errors.Wrap(err, "failed to check inbound enabled")
	}
	if !enabled {
		k.Logger().Warn("vote inbound rejected: chain inbound disabled", "source_chain", inbound.SourceChain)
		return fmt.Errorf("inbound is disabled for chain %s", inbound.SourceChain)
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Step 1: Derive UTX key from the original inbound data (source_chain:tx_hash:log_index)
	universalTxKey := types.GetInboundUniversalTxKey(inbound)
	found, err := k.HasUniversalTx(ctx, universalTxKey)
	if err != nil {
		return errors.Wrap(err, "failed to check UniversalTx")
	}
	if found {
		k.Logger().Warn("vote inbound rejected: utx already exists", "utx_key", universalTxKey)
		return fmt.Errorf("universal tx with key %s already exists", universalTxKey)
	}

	// use a temporary context to not commit any ballot state change in case of error
	tmpCtx, commit := sdkCtx.CacheContext()

	// Step 2: Record this validator's vote in the per-utx PendingInbounds entry
	// (variant-aware audit trail). Each unique Inbound payload becomes its own
	// variant; multiple variants per utx_key indicate validator divergence.
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return errors.Wrap(err, "failed to derive inbound ballot key")
	}
