### Title
Integer truncation in `CalculateGasCost` can zero out gas-fee deduction for user-executed UEA payloads - (File: `x/uexecutor/keeper/fees.go`)

### Summary
Analogous to the gETH `_findPricesClearBuffer` bug — where a raw value was divided by the wrong scaling factor and produced a badly wrong result — `CalculateGasCost` in `x/uexecutor/keeper/fees.go` unwraps the `feemarketKeeper` base fee from its `LegacyDec` (18-decimal) representation using plain integer division by `1e18`, silently truncating any base fee below `1 upc`. [1](#0-0) 

### Finding Description
`CalculateGasCost` computes the effective gas price from the feemarket's `baseFee` (an `sdkmath.LegacyDec`) by taking `baseFee.BigInt()` (the raw fixed-point integer, i.e. `value * 1e18`) and dividing it by `1e18` with integer `Div`: [1](#0-0) 

The inline comment asserts "the base fee is always a whole number of upc — no fractional upc exists," but this is only true if the feemarket's dynamic base fee never drops below `1 upc` (1e18 raw wei-equivalent units) in `LegacyDec` terms. If the base fee legitimately settles at a fractional value less than `1 upc` (e.g. `0.5 upc`, raw `5e17`), the integer division truncates to `0`.

This feeds `effectiveGasPrice = 0`, so `gasCost = effectiveGasPrice * gasUsed = 0`. `DeductGasFeesFromReceipt` explicitly treats a non-positive `gasCost` as "nothing to deduct" and returns early without charging or burning any fee: [2](#0-1) 

`DeductGasFeesFromReceipt` is invoked after real EVM execution triggered by ordinary user flows (`ExecutePayloadV2` / UEA payload execution), meaning the underlying EVM computation is genuinely metered and paid for by the module/protocol path, but the corresponding recipient-side fee collection can be skipped entirely due to this truncation. [3](#0-2) 

### Impact Explanation
If the feemarket base fee falls below `1 upc` — a state reachable simply from the market's normal EIP-1559 adjustment as long-run gas demand drops — every UEA-originated payload execution that then occurs bypasses gas-fee accounting, i.e., the recipient smart account is never charged/burned for gas even though real EVM gas was consumed and paid by the protocol. This is unauthorized fee evasion / a corruption of gas-fee accounting reachable purely by ordinary users submitting payloads, matching the "corruption of ... gas fee accounting ... reachable from ordinary user ... default transaction submission paths alone" allowed-impact category. Repeated, this represents a permanent drain on protocol-held funds used to subsidize gas with no compensating burn.

### Likelihood Explanation
Likelihood depends entirely on whether the base fee can actually be `< 1 upc` in practice. I could not fully verify the feemarket's minimum-base-fee floor configuration (e.g. whether `MinGasPrice`/`elasticity`/`baseFeeChangeDenominator` params guarantee `baseFee >= 1e18` at all times) within the available index; `app/cosmos/min_gas_price.go` and feemarket params would need to be inspected in a full checkout to confirm the floor. If the chain's feemarket params guarantee a floor at or above `1 upc`, this is not exploitable; if not, it is trivially and repeatedly triggerable by any unprivileged user submitting UEA payload transactions during low-demand periods.

### Recommendation
Do not rely on integer truncation to unwrap the `LegacyDec`. Compute the gas cost using full `LegacyDec` precision (e.g. `baseFeeDec.MulInt64(int64(gasUsed))`, rounding up), or explicitly reject/floor the case where the computed integer gas cost is zero but the underlying `LegacyDec` value is positive, so the recipient is still charged (e.g. round up to at least 1 upc) instead of silently skipping deduction.

### Proof of Concept
1. Configure/observe feemarket state such that `GetBaseFee(ctx)` returns a `LegacyDec` value less than `1e18` raw units (i.e., less than `1 upc`), which is a plausible steady state of an EIP-1559-style base fee under low network utilization.
2. As an ordinary user, submit a `MsgExecutePayload` (or trigger an inbound gas-and-payload flow) causing `ExecutePayloadV2` to run and produce a receipt with `GasUsed > 0`.
3. `DeductGasFeesFromReceipt` calls `CalculateGasCost`, which computes `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` → `0`, giving `gasCost = 0`.
4. `DeductGasFeesFromReceipt` returns `nil` without deducting or burning any fee from the recipient, even though the payload execution consumed real EVM gas paid by the protocol. [2](#0-1) 

I was unable to conclusively confirm within the indexed code whether the feemarket parameters (min gas price floor) prevent the base fee from ever dropping below `1 upc`; this would need to be checked directly in a full repository checkout (feemarket module params/genesis config and `app/cosmos/min_gas_price.go`) to determine actual exploitability versus a purely theoretical edge case.

```go
// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
