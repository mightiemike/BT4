### Title
Unbounded recursive JSON parsing of untrusted JSON‑RPC request bodies causes an uncatchable stack‑overflow crash of the node process - (File: `chain/jsonrpc-primitives/src/message.rs`, `chain/jsonrpc/src/api/mod.rs`)

### Summary
The reported `yaml` advisory (CVE-2026-33532) is a textbook case of CWE-674 (uncontrolled recursion): the compose/resolve phase recurses once per nesting level with no depth bound, so a tiny (2–10 KB) deeply-nested payload exhausts the call stack and raises an uncatchable `RangeError`, crashing the host process instead of returning a typed parse error. Nearcore's JSON-RPC ingress path has the analogous shape: incoming request bodies are deserialized with `serde_json`, whose `Value`/untagged-enum deserialization recurses once per array/object nesting level with no depth limit, and the resulting stack overflow aborts the whole process rather than being caught as a normal parse error.

### Finding Description
Every JSON-RPC request body is first parsed into a `Message`/`WireMessage` via `serde_json::de::from_slice` in `from_slice`/`from_str`, `chain/jsonrpc-primitives/src/message.rs` lines 262-271, using an `#[serde(untagged)]` `WireMessage`/`Broken` enum (lines 217-246). Untagged-enum deserialization in `serde_json` buffers the input into an internal `Content`/`Value`-like tree before variant matching, which is built by recursive descent: each nested `[`/`{` adds one Rust stack frame with no depth cap.

The `params` field of a request is a raw `serde_json::Value` (`chain/jsonrpc-primitives/src/message.rs`), and application-level request types then call `serde_json::from_value(value)` on it again in `Params::parse`/`unwrap_or_parse`, `chain/jsonrpc/src/api/mod.rs` lines 151-166, used by essentially every RPC method (`query`, `view_account`, `EXPERIMENTAL_*`, etc., per `chain/jsonrpc/RPC_ARCHITECTURE.md` lines 105-141). None of these paths impose a nesting-depth limit before or during deserialization.

Unlike a C++/`std::panic` recoverable error, a Rust stack overflow triggers a guard-page SIGSEGV that terminates the entire process — it cannot be caught by `catch_unwind`, `Result`, or any JSON-RPC error handling in `rpc_handler()`/`process_request_internal()`. Because `neard` runs the JSON-RPC server, `ClientActor`, and consensus/chunk-production logic in the same OS process, a crash triggered while handling an RPC request kills the whole node, including any validator role it holds.

This mirrors the exact bug class in the report (compose/resolve-phase unbounded recursion, not the CST/lexer, which is typically iterative) — here the JSON parser's recursive value-tree construction plays the role of the vulnerable "compose" phase, and there is no equivalent of `yaml`'s later fix (a depth counter returning a typed error) anywhere in the request-parsing pipeline.

The codebase is aware of this bug class elsewhere and has already mitigated it for the two other places it could arise from attacker input:
- `NonDelegateAction`/`NonDelegateActionOperation` (`core/primitives/src/action/delegate.rs` lines 360-444, `chain/rosetta-rpc/src/models.rs` lines 907-940) explicitly reject nested `DelegateAction`s to bound recursion depth during Borsh/JSON deserialization of transactions.
- WASM contract preparation (`runtime/near-vm-runner/src/prepare/prepare_v3.rs`, `instrument_v3.rs`) enforces `max_blocks_per_function`/`max_blocks_per_contract` limits specifically to bound nested-block recursion/compilation cost.

No equivalent bound exists for the generic JSON-RPC request-body/`params` deserialization path.

### Impact Explanation
A single unauthenticated JSON-RPC request (a few KB) can crash the receiving `neard` process. If the operator co-locates RPC serving with validation (a common and even default deployment pattern, since `rpc.addr` is enabled by default), this is a remote, unauthenticated, single-request denial-of-service against a validator node, which can be repeated against every validator whose RPC port is reachable, degrading or halting block production/finality for the network. This satisfies the "JSON-RPC and view calls" in-scope reachable path and produces a genuine node-halting condition analogous to the reported CVE's process-crashing effect, rather than a benign resource-only issue.

### Likelihood Explanation
High: the attack requires no credentials, no on-chain transaction, no special account, and no protocol knowledge beyond sending a valid HTTP POST with a small deeply-nested JSON body (e.g., `{"jsonrpc":"2.0","id":1,"method":"status","params": <5000 levels of nested arrays>}`) to any publicly reachable RPC endpoint. The vulnerable code paths (`from_slice`, `Params::parse`/`unwrap_or_parse`) are on the mandatory front door of every JSON-RPC request.

### Recommendation
Impose an explicit nesting-depth limit before/while deserializing untrusted request bodies and `params` values (e.g., wrap the deserializer with a depth-tracking `Deserializer`, reject inputs whose JSON nesting exceeds a small fixed bound such as 64–128 levels, or run request-body parsing in a dedicated thread with a bounded stack and convert the resulting fault into a normal RPC error). Apply the same bound at both `from_slice`/`from_str` in `chain/jsonrpc-primitives/src/message.rs` and the generic `Params::parse` in `chain/jsonrpc/src/api/mod.rs`, so all current and future RPC methods inherit the protection.

```rust
/// A trick to easily deserialize and detect valid JSON, but invalid Message.
#[derive(serde::Deserialize)]
#[serde(untagged)]
pub enum WireMessage {
    Message(Message),
    Broken(Broken),
}

pub fn decoded_to_parsed(res: JsonResult<WireMessage>) -> Parsed {
    match res {
        Ok(WireMessage::Message(Message::UnmatchedSub(value))) => Err(Broken::Unmatched(value)),
        Ok(WireMessage::Message(m)) => Ok(m),
        Ok(WireMessage::Broken(b)) => Err(b),
        Err(e) => Err(Broken::SyntaxError(e.to_string())),
    }
}

pub type Parsed = Result<Message, Broken>;

/// Read a [Message](enum.Message.html) from a slice.
///
/// Invalid JSON or JSONRPC messages are reported as [Broken](enum.Broken.html).
pub fn from_slice(s: &[u8]) -> Parsed {
    decoded_to_parsed(::serde_json::de::from_slice(s))
}

/// Read a [Message](enum.Message.html) from a string.
///
/// Invalid JSON or JSONRPC messages are reported as [Broken](enum.Broken.html).
pub fn from_str(s: &str) -> Parsed {
    from_slice(s.as_bytes())
}
```

```markdown
When a POST request arrives at `/`:

1. **`rpc_handler()`** - Deserializes the body into a JSON-RPC `Message`. Calls `JsonRpcHandler::process()`.
2. **`process()`** - Validates it's a `Request`, extracts `id`, delegates to `process_request()`.
3. **`process_request()`** - Metrics wrapper (timing, request count, error count per method). Delegates to `process_request_internal()`.
4. **`process_request_internal()`** - Core routing. Tries in order:
   - Adversarial requests (only with `test_features` cargo feature).
   - `process_basic_requests_internal()` - matches method name against known RPC methods.
   - Special `"query"` branch with sub-type metrics tracking.
   - Returns `method_not_found` if no match.
5. **`process_method_call()`** - Generic helper: parses params via `R::parse()`, invokes handler, serializes result, converts errors.
6. **HTTP status code mapping** in `rpc_handler()`: 200 (success), 400 (validation), 408 (timeout), 422 (UNKNOWN_BLOCK behind head), 500 (internal).
```

```rust
/// This struct is needed to avoid the recursion when Action/DelegateAction is deserialized.
```
