### Title
Cross-delegator accounting corruption in `UnDelegateResourceActuator` zeroes out the receiver's entire acquired-resource pool instead of the caller's share - (File: `actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java`)

### Summary
The Fractional finding shows that when a shared pooled balance (fractions from many depositors) is consumed by a state transition, the code must track and subtract only the specific portion belonging to the triggering actor — not sweep the entire shared pool. `UnDelegateResourceActuator.execute()` (and its TVM-native twin `UnDelegateResourceProcessor`) contains the same pattern: multiple, unrelated accounts can delegate BANDWIDTH/ENERGY to the same `receiverAddress`, and the receiver tracks the sum of all of these contributions in a single aggregate field, `AcquiredDelegatedFrozenV2BalanceForBandwidth`/`...ForEnergy`. When *any single* delegator submits an `UnDelegateResourceContract`, the actuator compares only that caller's `unDelegateBalance` against the receiver's aggregate value and, if the aggregate is smaller, zeroes the entire aggregate rather than subtracting the caller's own delegated amount. [1](#0-0) [2](#0-1) 

### Finding Description
`UnDelegateResourceContract` is a public, unprivileged transaction type that any account can broadcast, provided they have an existing `DelegatedResourceCapsule` entry with the given receiver (validated only against the *caller's own* delegation record): [3](#0-2) 

Note that `validate()` only checks that the caller's own delegated-resource record (`unlockResourceCapsule`/`lockResourceCapsule`) has enough balance for the amount they intend to undelegate — it never inspects or bounds the check against `receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth()`, the aggregate value fed by *all* delegators to that receiver.

In `execute()`, the receiver-side bookkeeping is then updated using only the caller's local view of `unDelegateBalance` versus the receiver's aggregate:

```
if (receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth() < unDelegateBalance) {
  // A TVM contract suicide, re-create will produce this situation
  receiverCapsule.setAcquiredDelegatedFrozenV2BalanceForBandwidth(0);
} else {
  ...
  receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(-unDelegateBalance);
}
``` [1](#0-0) 

This branch is documented as being intended only for the narrow scenario where a TVM contract receiver self-destructs and is later re-created with fresh (smaller/zeroed) account state. However, the check as written triggers unconditionally whenever the *aggregate* acquired balance recorded on the receiver happens to be smaller than what *this single caller* is attempting to undelegate — a condition that is not guaranteed to correlate with contract-suicide/recreation. It can also occur through ordinary concurrent activity (e.g., prior partial undelegations by other delegators, or receiver account state drifting from the sum of individual delegator claims for any reason), because the aggregate is a shared counter contributed to by multiple independent, unrelated senders, exactly like the pooled "fractions" balance in the referenced Fractional bug. Any one delegator's undelegate call can wipe the entire shared counter to `0`, discarding the bookkeeping for every other delegator's still-active delegation to that receiver, rather than only subtracting their own share. The identical unconditional-zero pattern is duplicated in the native/TVM-invocable path: [4](#0-3) 

### Impact Explanation
`AcquiredDelegatedFrozenV2BalanceForBandwidth`/`ForEnergy` on the receiver account is used to compute the receiver's total available bandwidth/energy weight and drives `unDelegateMaxUsage`/`transferUsage` calculations for other delegators' future undelegations. Zeroing this shared aggregate via one delegator's transaction corrupts resource accounting for every other unrelated delegator pointing at the same receiver: their still-outstanding delegated balances become untracked at the receiver side, while their own local `DelegatedResourceCapsule` records remain unchanged, producing an inconsistent global state. This is an asset/resource accounting-corruption bug reachable by broadcasting an ordinary transaction type, matching the accepted "asset or accounting corruption" impact category, though it stops short of direct outright fund theft (TRX/fraction) since delegated resource balances are internally-tracked network resources rather than a token balance a third party could redirect to themselves.

### Likelihood Explanation
Exploitation requires only broadcasting a valid `UnDelegateResourceContract` transaction with an `unDelegateBalance` that exceeds the receiver's currently recorded aggregate acquired balance — a state that can arise from normal multi-delegator usage patterns on a shared receiver, not just the narrow suicide/recreate scenario the comment describes. No special privileges, keys, or node access are needed; it is reachable directly from an unprivileged actuator/broadcast path.

### Recommendation
Do not zero the receiver's entire aggregate acquired balance when it is smaller than the caller's own `unDelegateBalance`. Instead, clamp the subtraction to the minimum of the two values (`min(receiverAcquired, unDelegateBalance)`), so only the amount actually attributable to the caller's delegation is removed, leaving other delegators' contributions to the receiver's aggregate untouched — mirroring the Fractional recommendation to track and consume only the amount specifically belonging to the triggering action rather than the whole shared pool.

### Proof of Concept
1. Delegator A delegates `X` BANDWIDTH-equivalent TRX to receiver `R` (`R.acquired += X`).
2. Delegator B (a different, unrelated account) delegates `Y` BANDWIDTH-equivalent TRX to the same receiver `R` (`R.acquired += Y`, total `= X + Y`).
3. Through any sequence that leaves `R.acquired < X` at the point delegator A calls `UnDelegateResourceContract` for `unDelegateBalance = X` (e.g., B has already partially/fully undelegated first, or receiver state was recreated), the `<` branch in `UnDelegateResourceActuator.execute()` fires and executes `receiverCapsule.setAcquiredDelegatedFrozenV2BalanceForBandwidth(0)`, wiping out any remaining balance that legitimately still belongs to other, still-active delegators of `R`.
4. Subsequent undelegate/accounting operations for other delegators of `R` now operate against a corrupted (zeroed) aggregate value that no longer reflects the sum of outstanding legitimate delegations. [5](#0-4)
