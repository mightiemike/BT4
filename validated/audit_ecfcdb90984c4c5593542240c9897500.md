### Title
Non-injective colon-delimited concatenation in `GetInboundUniversalTxKey` / `GetOutboundRevertId` / `GetRescueFundsOutboundId` permits boundary-shift key collisions across CAIP-2 namespaces without hex/base58 format enforcement — (File: `x/uexecutor/types/keys.go`)

### Summary
The reported bug class is "hashing a delimiter-joined tuple of fields without individually hashing/length-prefixing them, so a value that embeds the delimiter can shift a field boundary and make two logically different inputs collapse to the same digest." Push Chain's own code base explicitly documents this exact bug class and fixes it in one place (`hashFields`, used by `GetInboundBallotKey`/`GetOutboundBallotKey`) but leaves the fix unapplied in three sibling identity-key functions that use the naive `fmt.Sprintf("%s:%s:%s", ...)` + `sha256` pattern: `GetInboundUniversalTxKey`, `GetOutboundRevertId`, and `GetRescueFundsOutboundId` in [1](#0-0) , [2](#0-1) .

### Finding Description
`hashFields` was introduced specifically to close boundary-shift collisions: it hashes each field independently before joining, with the comment "Per-field hashing makes it injective — a sub-hash can't contain ':', so no field value can shift a boundary and collide with a different tuple" [3](#0-2) .

However, the *UniversalTx identity key* — the primary key that determines whether an inbound event is treated as a brand-new UTX or an existing one (`k.HasUniversalTx(ctx, universalTxKey)` in `VoteInbound`) — is still computed with the vulnerable naive pattern:
```go
data := fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)
hash := sha256.Sum256([]byte(data))
``` [4](#0-3) 

The same unhardened pattern is reused for the source-chain replay-protection identifiers used as the `subTxId` on the external gateway call: `GetOutboundRevertId` and `GetRescueFundsOutboundId` [2](#0-1) .

Field validation does not prevent delimiter injection into these three fields for non-`eip155`/non-`solana` CAIP-2 namespaces:
- `Inbound.ValidateBasic()` only checks that `SourceChain` contains a colon (CAIP-2 shape) and that `TxHash`/`LogIndex` are non-empty — it never restricts their character set [5](#0-4) .
- `LenientCanonicalizeTxHash`/`LenientCanonicalizeAddress` only enforce hex/base58 shape for the `eip155` and `solana` namespaces; for any other namespace they fall through to `default: return addr, nil` / `return txHash, nil`, i.e. the raw trimmed string is used verbatim, colons and all [6](#0-5) .
- `LogIndex` is never format-checked at all (not even for `eip155`/`solana`), only trimmed [7](#0-6) , [8](#0-7) .

This is the direct native analog of the reported issue: joining un-delimited-safe, attacker-influenceable strings with `":"` and hashing the concatenation, instead of hashing each field independently, so two semantically different `(chain, txHash, logIndex)` triples can be engineered to serialize to the identical byte string and therefore the identical `sha256` digest / UTX key / outbound subTxId.

### Impact Explanation
If exploitable, a collision on `GetInboundUniversalTxKey` would let one inbound event masquerade as / merge with a different one at the `HasUniversalTx` dedup check in `VoteInbound`, corrupting canonical `UniversalTx` state identity — directly matching the in-scope impact "corruption of ... canonical UniversalTx state" and "unauthorized state transitions in universal execution flows." A collision on `GetOutboundRevertId`/`GetRescueFundsOutboundId` would produce a duplicate `subTxId` used for replay protection on the external gateway, potentially breaking the uniqueness guarantee the comments explicitly call out ("This ID is also used as the subTxId on the source-chain gateway call, providing replay protection — so it must be unique per inbound event") [9](#0-8) .

### Likelihood Explanation
Exploitability under the strict "unprivileged attacker + honest UVs/honest nodes" threat model is **low/uncertain** and I could not fully confirm it in this session:
- For the currently supported and validated namespaces (`eip155`, `solana`), `TxHash` is canonicalized into a strict hex or base58 form that cannot contain `:`, and in practice `LogIndex` is populated by honest UV client code from a numeric log position, not from attacker-controlled free text. Under those conditions the boundary-shift attack is not reachable by an unprivileged attacker alone.
- The gap only becomes concretely exploitable if (a) a registered chain uses a CAIP-2 namespace other than `eip155`/`solana` (so `CanonicalizeTxHashByNamespace`/`CanonicalizeAddressByNamespace` fall through to the unchecked `default` branch), and (b) an attacker can influence the raw bytes that an honest Universal Validator's chain client reports as `TxHash` or `LogIndex` for that chain (e.g., a chain whose "tx identifier" is attacker-supplied metadata rather than a consensus-derived hash). I was not able to verify, within the available tool budget, whether any currently-registered/enabled chain configuration in `x/uregistry` (or `chains/*.json`) uses such a namespace, nor whether any `universalClient` chain-specific event parser ever derives `TxHash`/`LogIndex` from attacker-influenceable strings for such a chain. This should be verified against the live chain registry and each chain client's event parser before treating this as confirmed live-exploitable — I flag it as an unresolved reachability question rather than an assumption.

### Recommendation
Route `GetInboundUniversalTxKey`, `GetOutboundRevertId`, and `GetRescueFundsOutboundId` through the same injective `hashFields` construction already used by `GetInboundBallotKey`/`GetOutboundBallotKey`, so every identity/replay-protection key in `x/uexecutor` is uniformly collision-safe regardless of which CAIP-2 namespace introduces free-form string content in the future. As a defense-in-depth measure, also enforce a restrictive charset (or length-prefix) on `LogIndex` in `Inbound.ValidateBasic()`/`Canonicalize()`, and consider making `CanonicalizeTxHashByNamespace`/`CanonicalizeAddressByNamespace` reject (or hex/base58-normalize) unknown namespaces instead of passing raw attacker-influenceable text through unchanged.

### Proof of Concept
Conceptual collision (illustrative, pending confirmation that a non-`eip155`/`solana` namespace is actually reachable in production registry config):
```
Event A: sourceChain = "foo:1", txHash = "bar",   logIndex = "1"
Event B: sourceChain = "foo:1", txHash = "bar:1", logIndex = ""   // logIndex empty is rejected by ValidateBasic, so this exact PoC needs a variant that keeps logIndex non-empty while still shifting the boundary, e.g. txHash="bar", logIndex="1:2" vs sourceChain="foo:1", txHash="bar:1", logIndex="2"
```
Both serialize to the same `fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)` byte string once boundaries shift across the `:` separators, producing an identical `sha256` digest and thus the identical `GetInboundUniversalTxKey`/`GetOutboundRevertId` value for two distinct logical events — reproducing, in this codebase's own key-derivation layer, the exact "different data, same hash" defect described in the external report.

// GetInboundUniversalTxKey: UTX identity from canonical (source_chain, tx_hash,
// log_index). Canonicalizes locals; caller's inbound is not mutated.
func GetInboundUniversalTxKey(inbound Inbound) string {
	chain := strings.TrimSpace(inbound.SourceChain)
	txHash := utils.LenientCanonicalizeTxHash(chain, inbound.TxHash)
	logIndex := strings.TrimSpace(inbound.LogIndex)
	data := fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)
	hash := sha256.Sum256([]byte(data))
	return hex.EncodeToString(hash[:]) // hash[:] converts [32]byte → []byte
}

// hashFields = sha256( hex(sha256(domain)) : hex(sha256(f0)) : ... ). Per-field
// hashing makes it injective — a sub-hash can't contain ':', so no field value
// can shift a boundary and collide with a different tuple.
func hashFields(domain collections.Prefix, parts ...string) string {
	hashed := make([]string, 0, len(parts)+1)
	d := sha256.Sum256(domain.Bytes())
	hashed = append(hashed, hex.EncodeToString(d[:]))
	for _, p := range parts {
		sum := sha256.Sum256([]byte(p))
		hashed = append(hashed, hex.EncodeToString(sum[:]))
	}
	final := sha256.Sum256([]byte(strings.Join(hashed, ":")))
	return hex.EncodeToString(final[:])
}

// outbound. sourceChain is the CAIP-2 identifier of the chain the inbound came from

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

// CanonicalizeAddressByNamespace canonicalizes an address for the given
// CAIP-2 chain. Empty input passes through (optional fields).
func CanonicalizeAddressByNamespace(chain, addr string) (string, error) {
	addr = strings.TrimSpace(addr)
	if addr == "" {
		return "", nil
	}
	switch CAIP2Namespace(chain) {
	case namespaceEVM:
		return CanonicalizeEVMAddress(addr)
	case namespaceSolana:
		return canonicalizeSolanaValue(addr)
	default:
		return addr, nil
	}
}

// CanonicalizeTxHashByNamespace canonicalizes a transaction hash/signature
// for the given CAIP-2 chain. Empty input passes through (e.g. failed
// outbound observations carry no hash).
func CanonicalizeTxHashByNamespace(chain, txHash string) (string, error) {
	txHash = strings.TrimSpace(txHash)
	if txHash == "" {
		return "", nil
	}
	switch CAIP2Namespace(chain) {
	case namespaceEVM:
		return CanonicalizeEVMHash(txHash)
	case namespaceSolana:
		return canonicalizeSolanaTxHash(txHash)
	default:
		return txHash, nil
	}
}
