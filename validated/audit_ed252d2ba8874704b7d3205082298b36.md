### Title
Silent, permanent loss of excess-gas refunds when gas fields are unset on outbound finalization - ([File: x/uexecutor/keeper/outbound.go])

### Summary
`applyGasRefund` in `x/uexecutor/keeper/outbound.go` short-circuits and silently returns whenever `outbound.GasFee`, `outbound.GasToken`, or `obs.GasFeeUsed` is empty, exactly mirroring the Notional `AbstractRewardManager._claimVaultRewards` pattern where `if (rewardPool.rewardPool == address(0)) return;` discards a legitimate branch instead of handling it.

### Finding Description
`FinalizeOutbound` calls `handleFailedOutbound`/`handleSuccessfulOutbound`, both of which call `applyGasRefund` to compute and return excess relayer gas fees to the user: [1](#0-0) 

The guard clause:
```go
if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
    return
}
```
returns without any error, log entry, or state marker when any of these fields is empty, and the caller (`handleFailedOutbound`/`handleSuccessfulOutbound`) then proceeds to call `k.UpdateOutbound` and mark the outbound `REVERTED`/finalized as if the refund step ran normally.

Crucially, `outbound.GasFee`/`GasToken` can legitimately be empty for `INBOUND_REVERT` outbounds. `buildRevertOutbound` populates these fields via `GetGasFeeInfoForRevertOutbound`, but on any lookup failure (missing/unset `NativeRepresentation` in the token registry, or a failed/erroring `getOutboundTxGasAndFees` EVM call) it deliberately returns the outbound **without** gas fields, only logging a warning: [2](#0-1) 

This is a normal, unprivileged code path — it is reached whenever an ordinary user's inbound fails validation/execution and gets reverted (`handleFailedInboundValidation`, `execute_inbound_gas_and_payload.go`), with no attacker action required beyond a routine deposit that later needs to be reverted: [3](#0-2) 

Once such an outbound reaches `FinalizeOutbound` with observed gas-fee-used data, `applyGasRefund` silently drops the refund step permanently: the outbound is marked `REVERTED`/finalized, `PcRefundExecution` is left `nil`, and there is no retry mechanism or error surfaced anywhere in the UTX/outbound record that would let an operator or the user detect that a refund is owed but was never issued.

### Impact Explanation
The user's excess relayer gas fee (the "gasFee - gasFeeUsed" amount that should be refunded via `CallUniversalCoreRefundUnusedGas`) is permanently and silently unrecoverable whenever the gas-fee lookup at outbound-build time failed to populate `GasToken`/`GasFee`. Because the outbound is still marked as successfully finalized, there is no error flag, no `RefundSwapError`, and no re-processing path — the funds are simply lost with no on-chain trace distinguishing "refund not needed" from "refund silently skipped." This is a direct funds-loss condition for ordinary users going through the revert/refund flow, analogous in class to the cited report where legitimate reward claims were dropped due to a defensive early-return that didn't account for an alternate but valid state.

### Likelihood Explanation
The trigger conditions (token registry missing `NativeRepresentation`, or a transient/erroring `getOutboundTxGasAndFees` EVM call) are not attacker-forced but can occur during ordinary operation for any user whose inbound needs to be reverted, making this a real design gap rather than a purely theoretical edge case. It does not require a malicious peer, validator, or governance actor — only a normal inbound revert flow encountering an EVM call/config hiccup. However, I could not fully verify from the available code how frequently `NativeRepresentation` is left unset in the live token registry or how often `getOutboundTxGasAndFees` calls fail in practice, so exact likelihood of triggering the empty-field state is uncertain.

### Recommendation
Do not silently swallow the missing-gas-fields case in `applyGasRefund`. Either (a) block finalization until gas info can be resolved (retry/queue rather than proceed), or (b) explicitly record on the outbound (e.g. via a new `RefundSwapError`/status field) that the refund step was skipped due to missing gas data, so it is queryable and can be manually/administratively resolved, mirroring the existing fallback pattern already used in the swap-refund branch (`RefundSwapError`).

### Proof of Concept
Conceptual trace (no live environment verification performed, as this repository index does not expose a running testnet):
1. User submits a deposit inbound that later fails `ValidateForExecution`.
2. `handleFailedInboundValidation` calls `buildRevertOutbound`, which calls `GetGasFeeInfoForRevertOutbound`; the registry entry for the deposited external asset has no `NativeRepresentation` set (or the `getOutboundTxGasAndFees` EVM call errors), so the function returns early leaving `GasToken`, `GasFee`, `GasPrice`, `GasLimit` all `""` on the built `OutboundTx` [2](#0-1) .
3. Universal Validators later vote the outbound `OBSERVED` with a non-empty `GasFeeUsed`.
4. `FinalizeOutbound` → `handleFailedOutbound`/`handleSuccessfulOutbound` → `applyGasRefund` hits the empty-field guard and returns without ever calling `CallUniversalCoreRefundUnusedGas` [4](#0-3) .
5. The outbound is persisted as finalized/`REVERTED` with `PcRefundExecution == nil` and no error recorded, permanently losing the user's owed gas refund.

```go
// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
```
