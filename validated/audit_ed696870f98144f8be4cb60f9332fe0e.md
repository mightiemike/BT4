### Title
`TokenConfig.Enabled` flag is never enforced in inbound execution, allowing continued minting/bridging of a token the registry admin marked as disabled — (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/handler.go`)

### Summary
The Morpho report is about a config flag (`LTV = 0`) that is meant to change protocol behavior for an asset but whose semantics silently diverge from the analogous system (Aave), producing unexpected/unsafe user outcomes because the flag's effect wasn't fully or correctly threaded through the accounting logic. The Push Chain analog is `uregistry.TokenConfig.Enabled` — documented as "Whether this token is enabled for minting/bridging" [1](#0-0)  — which is stored and validated but is never actually read/checked anywhere in the execution paths that mint PRC20 tokens for inbound transfers.

### Finding Description
`TokenConfig` defines an `Enabled` field intended to gate whether a token can be used for minting/bridging [2](#0-1) . The keeper only exposes a plain `GetTokenConfig` lookup with no enabled-gating logic [3](#0-2) , and `GetTokenConfigByPRC20` similarly returns the config with no enabled check [4](#0-3) .

Every consumer of the token config in the inbound execution pipeline calls `GetTokenConfig` and immediately proceeds to use `NativeRepresentation.ContractAddress` for a PRC20 deposit, without inspecting `Enabled`:
- `depositPRC20` in the shared handler fetches the token config and calls `CallPRC20Deposit` regardless of `Enabled` [5](#0-4) .
- `ExecuteInboundGas` fetches the token config and proceeds to deposit/swap logic without checking `Enabled` [6](#0-5) .
- `ExecuteInboundGasAndPayload` fetches the token config and performs `gasAndPayloadDepositAutoSwap` for both CEA and non-CEA paths without checking `Enabled` [7](#0-6) .

I confirmed via repo-wide search that `tokenConfig.Enabled` (or `.GetEnabled()`) is never referenced anywhere outside of protobuf-generated getters, the `ValidateBasic`/test files, and the `keeper.go` symbol matches that turned out to be unrelated `ChainConfig.Enabled` (`IsInboundEnabled`/`IsOutboundEnabled`) checks — not `TokenConfig.Enabled`. `IsChainInboundEnabled`/`IsChainOutboundEnabled` are checked (e.g. in `VoteInbound` [8](#0-7) ), but the token-level `Enabled` flag has no equivalent gate anywhere in the module.

The module's own README documents `MsgUpdateTokenConfig` as the admin-curated mechanism to "Modify a token config" [9](#0-8) , implying that flipping a token to `Enabled = false` is the intended way to pause bridging for that token (analogous to Aave/Morpho disabling an asset). But because no execution path enforces it, this administrative "kill switch" is dead code with respect to inbound minting/bridging.

### Impact Explanation
This diverges from the intended (and documented) protocol behavior in the same class of way the Morpho report criticizes: a config flag meant to gate/restrict token usage does not propagate correctly into the execution/accounting logic, producing behavior that is materially different from what governance/admin intends. Concretely: if the registry admin sets `Enabled = false` on a `TokenConfig` — e.g., in response to a compromised source-chain token contract, a depegged/broken asset, or a decision to sunset a bridge route — ordinary users can still submit inbound transactions for that asset, honest validators will still vote it to quorum, and `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/`depositPRC20` will still mint the corresponding PRC20 and execute payloads/autoswaps against it. This is an unauthorized/uncontrolled continuation of minting and value movement that governance explicitly intended to halt, which can lead to accounting corruption of PRC20 supply relative to a now-untrusted or paused source asset, and denies the protocol its only in-band lever to stop bridging of an asset without also disabling the whole chain (`ChainConfig.Enabled`, which is a much coarser, all-token control).

### Likelihood Explanation
Reachability requires no privileged action from the attacker — any ordinary external-chain user's normal deposit is sufficient to trigger minting once quorum is reached, exactly matching an "ordinary user deposits" trigger in scope. The only precondition is that an admin has (for a legitimate reason) set `Enabled = false` on a token, at which point the flag's ineffectiveness is passively and continuously exploitable by any unprivileged user simply by using the normal deposit flow — there is no special crafting needed since the check simply doesn't exist.

### Recommendation
Add an explicit `Enabled` check in `GetTokenConfig`/`GetTokenConfigByPRC20` (or in each execution entrypoint that consumes the token config: `ExecuteInboundGas`, `ExecuteInboundGasAndPayload`, `depositPRC20`, and any outbound/rescue paths that resolve a token config) that rejects further minting/deposit/autoswap processing for a disabled token, and drives the inbound into the existing "FAILED PCTx + revert" flow (the same pattern already used when `GetTokenConfig` returns not-found, as covered by `test/integration/uexecutor/execute_inbound_gas_test.go` lines 364-403). Document the exact behavior (revert destination, refund semantics) for in-flight inbounds when a token transitions to `Enabled = false` mid-flight, mirroring the transparency recommendation from the Morpho report.

### Proof of Concept
1. Admin registers a `TokenConfig` for `USDC` on `eip155:11155111` with `Enabled = true` via `MsgAddTokenConfig`, matching the test fixture pattern [10](#0-9) .
2. Admin later calls `MsgUpdateTokenConfig` to set `Enabled = false` on that same token (e.g., because the source-chain token contract was compromised), via `UpdateTokenConfig` [11](#0-10)  — this merely overwrites the stored `TokenConfig`, with no other module state changed.
3. An ordinary (unprivileged) user deposits funds into the gateway contract on `eip155:11155111` exactly as before. Honest universal validators observe the deposit and vote via `MsgVoteInbound`, reaching quorum normally (chain-level inbound is still enabled, so `VoteInbound`'s `IsChainInboundEnabled` check passes) [8](#0-7) .
4. On ballot finalization, `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetTokenConfig`, which succeeds (config exists, only `Enabled` is false) and is not checked [12](#0-11) . The deposit and PRC20 mint proceed to completion exactly as if the token were still enabled — no `FAILED` PCTx, no revert, and no acknowledgement anywhere that the token was administratively disabled.

Note: I was not able to fully trace whether other paths — e.g. `x/uexecutor/keeper/msg_execute_payload.go`, `msg_migrate_uea.go`, or outbound/rescue flows — read a different, effective `Enabled`-style gate before minting/burning; the `Enabled` matches found there were for `ChainConfig.Enabled` fields based on the surrounding context, but I could not view the full file contents to be 100% certain no `TokenConfig.Enabled` check exists deeper in those files. A Devin session with full file access would be needed to close out that last check exhaustively.

func (k Keeper) GetTokenConfigByPRC20(
	ctx context.Context,
	chain string,
	prc20Addr string,
) (types.TokenConfig, error) {

	if strings.TrimSpace(prc20Addr) == "" {
		return types.TokenConfig{}, fmt.Errorf("prc20 address is empty")
	}
	// Same canonical form as the index function, so any case variant hits the row.
	prc20Addr = canonicalPRC20(prc20Addr)

	// PRC20 addresses are globally unique by construction; MatchExact returns at most one.
	iter, err := k.TokenConfigs.Indexes.PRC20Index.MatchExact(ctx, prc20Addr)
	if err != nil {
		return types.TokenConfig{}, err
	}
	defer iter.Close()

	for ; iter.Valid(); iter.Next() {
		pk, err := iter.PrimaryKey()
		if err != nil {
			return types.TokenConfig{}, err
		}
		cfg, err := k.TokenConfigs.Get(ctx, pk)
		if err != nil {
			return types.TokenConfig{}, err
		}
		if cfg.Chain == chain {
			return cfg, nil
		}
	}

	return types.TokenConfig{}, collections.ErrNotFound
}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

// UpdateTokenConfig updates an existing token configuration in the uregistry.
func (k Keeper) UpdateTokenConfig(ctx context.Context, tokenConfig *types.TokenConfig) error {
	storageKey := types.GetTokenConfigsStorageKey(tokenConfig.Chain, tokenConfig.Address)

	// Check if the token config exists
	if has, err := k.TokenConfigs.Has(ctx, storageKey); err != nil {
		return err
	} else if !has {
		return fmt.Errorf("token config for %s on chain %s does not exist", tokenConfig.Address, tokenConfig.Chain)
	}

	if err := k.TokenConfigs.Set(ctx, storageKey, *tokenConfig); err != nil {
		return err
	}
	k.Logger().Info("token config updated",
		"chain", tokenConfig.Chain,
		"token_address", tokenConfig.Address,
	)
	return nil
}
