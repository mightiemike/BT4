## Analysis

The concern is valid. `GetSwapQuote` at [1](#0-0)  is a pure spot-price read against the on-chain `QuoterV2.quoteExactInputSingle` contract with `SqrtPriceLimitX96: 0` — there is no TWAP, no independent reference price, and no cross-check against a prior or external price feed anywhere in this code path. The resulting `minPCOut` is derived purely from that same live, manipulable quote:

```go
quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
...
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
``` [2](#0-1) 

The same pattern exists in `ExecuteInboundGas` [3](#0-2)  and in the outbound gas-refund swap path via `getSwapQuoteForRefund` [4](#0-3) .

Because `GetSwapQuote` and `CallPRC20DepositAutoSwap` execute back-to-back inside a single atomic keeper call with no consensus-level reordering possible *between* them, an attacker cannot sandwich the internal quote-then-swap sequence itself. However, nothing prevents an attacker from moving the pool's spot price via an ordinary, permissionless swap in a transaction that lands in the same or an immediately preceding block relative to when their own inbound's `GAS`/`GAS_AND_PAYLOAD` execution fires (execution timing is driven by validator vote-quorum finalization, but the attacker can still race/front-run with a higher-fee tx once they observe quorum is imminent). The "5% slippage" check is self-referential — it bounds movement *after* the quote is read, not manipulation baked into the quote at read time — so it provides no actual protection against an attacker who has just pushed the AMM price in their own favor before their deposit's auto-swap executes, extracting value from the pool's PC reserves.

This is reachable purely through: (1) an ordinary permissionless swap on the Uniswap-style pool, and (2) an ordinary user-initiated inbound deposit — no validator, relayer, or admin privilege required, and it directly corrupts native/PRC20 accounting for the swap leg of deposit processing.

### Title
Spot-price AMM quote with self-referential slippage bound allows price-manipulation value extraction during deposit auto-swap - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
`GetSwapQuote` reads a live spot quote from the Uniswap V3-style `QuoterV2` with no TWAP or manipulation-resistant pricing, and `minPCOut` is computed as a fixed 95% of that same, potentially attacker-manipulated quote before calling `CallPRC20DepositAutoSwap`. An unprivileged attacker can push the pool's spot price via an ordinary swap immediately before their own `GAS_AND_PAYLOAD`/`GAS` inbound executes the auto-swap, causing the auto-swap to execute at the manipulated rate and extract value from the pool's PC reserves.

### Finding Description
`gasAndPayloadDepositAutoSwap` [5](#0-4)  and the equivalent logic in `ExecuteInboundGas` [6](#0-5)  fetch a swap quote and derive `minPCOut` solely from that single spot read, then immediately execute the real swap via `CallPRC20DepositAutoSwap` [7](#0-6) . Because the reference price and the executed price come from the same manipulable on-chain pool state, and there is no TWAP, price-deviation cap, or external price check anywhere in this module (confirmed by the absence of any such mechanism in the surrounding `evm.go` helpers), the slippage bound only defends against price movement strictly *after* the quote call — which is effectively none within the same atomic execution — not against price manipulation that already occurred before execution began.

### Impact Explanation
An attacker can manipulate the pool price with an ordinary swap timed just before their own inbound deposit is processed by honest validators, causing the auto-swap to mint/settle PC to the attacker's UEA at a rate favorable to the attacker and unfavorable to the protocol-owned liquidity pool, corrupting native/PRC20 accounting for that deposit and extracting value from the shared liquidity pool.

### Likelihood Explanation
Requires the attacker to have capital to move the pool price and to win a timing race against validator vote-quorum finalization for their own inbound; feasibility scales inversely with pool liquidity depth and is highest for low-liquidity token pairs, making it plausible but not trivial to execute reliably.

### Recommendation
Introduce a manipulation-resistant reference price (e.g., a short TWAP from the pool, or comparison against a stored/attested chain-meta price) and bound the spot quote's deviation from that reference before deriving `minPCOut`, rather than deriving the slippage floor solely from the same instantaneous spot quote that is about to be consumed.

### Proof of Concept
Not directly demonstrable from static code alone; would require a local devnet with the `UniversalCore`/`QuoterV2` contracts deployed, in which a test performs a large spot-price-moving swap against the pool, then triggers `ExecuteInboundGasAndPayload` for a crafted inbound and observes that `GetSwapQuote`/`minPCOut` reflect the manipulated price with the subsequent `CallPRC20DepositAutoSwap` settling at that manipulated rate, independent of the pool's pre-manipulation fair price.

func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),

	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
