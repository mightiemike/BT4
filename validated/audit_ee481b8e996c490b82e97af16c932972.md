Based on the code investigated, I found a genuine analog in the `x/uexecutor` chain-meta gas-price oracle path, tied directly to the outbound gas fee accounting flow.

### Title
Stale gas-price oracle after Universal Validator downtime lets an unprivileged inbound/outbound requester lock in a gas fee that does not reflect the destination chain's real market price — ([File: x/uexecutor/keeper/chain_meta.go])

### Summary
`VoteChainMeta` freezes the on-chain `gasPriceByChainNamespace` oracle whenever fewer than `chainMetaMinVotesForFirstWrite`/no "fresh" votes exist, and once bootstrapped a single fresh vote is enough to move the entire median. `GetOutboundTxGasAndFees` (used to compute `OutboundTx.GasFee` at outbound-creation time) always reads whatever price is currently stored in the on-chain oracle, with no additional check on how old the underlying `LastAppliedChainHeight`/vote data actually is. This is structurally the same class of bug as the reported Stop-order issue: a price value that is supposed to represent "current market conditions" is instead served from a window that may be arbitrarily stale relative to the real destination-chain gas market, and the timing of when a user's inbound/outbound is processed (relative to validator liveness) determines which price gets locked in.

### Finding Description
`chainMetaVoteStalenessSeconds` (300s) governs which validator votes are "fresh" enough to participate in the median (`x/uexecutor/keeper/chain_meta.go:16-19,110-127`) [1](#0-0) . If all votes go stale (e.g., during any period where UVs are not actively refreshing gas price — network issue, RPC failure on the destination chain, validator restarts, etc.), `len(fresh) == 0` and the code explicitly **does not update the EVM oracle**, leaving the previously-applied (now stale) `gasPriceByChainNamespace` value in place indefinitely [2](#0-1) . There is no mechanism to detect that `LastAppliedChainHeight`'s underlying data is stale and force a live read of destination-chain price at outbound-creation time.

Every outbound's gas fee is fixed once, at creation, via `GetOutboundTxGasAndFees`, which reads directly from this on-chain oracle [3](#0-2) . Whatever value happens to be stored — fresh or arbitrarily stale — becomes the immutable `OutboundTx.GasFee` charged against the user's bridged/PRC20 assets and later reconciled against `gas_fee_used` reported by validators in `applyGasRefund` (`x/uexecutor/keeper/outbound.go:174-257`) [4](#0-3) . Reconciliation only ever refunds the user when `gasFee > gasFeeUsed`; when `gasFeeUsed > gasFee` (because real destination-chain gas jumped while the stored oracle price stayed stale) there is no additional charge — the shortfall is simply absorbed by the protocol (the relayer/vault has no on-chain mechanism to collect the difference).

This mirrors the reported bug's mechanics precisely: (1) a price feed with a staleness window, (2) a "which data source is used" branch (fresh median vs. frozen last-applied value) that depends purely on external validator liveness timing, and (3) a downstream accounting step (gas fee locked into `OutboundTx`) that is computed exactly once from whatever the oracle currently holds, with no re-check against live market conditions at execution.

### Impact Explanation
Any inbound or outbound whose gas fee is computed while the chain-meta oracle is stale locks in a price that can diverge arbitrarily from the destination chain's real gas market. If real gas costs are higher than the frozen oracle price at the time of actual relay, the protocol under-collects the fee and the deficit is not billed back to the user — a recurring loss of protocol-controlled value. Because `chainMetaMinVotesForFirstWrite` bootstrap gating is bypassed once `LastAppliedChainHeight > 0`, a single validator's fresh vote is also enough to unilaterally move the oracle once bootstrapped, compounding the staleness/timing risk during partial validator downtime.

### Likelihood Explanation
Likelihood is low-to-medium: it requires either a genuine gap in UV gas-price reporting (RPC outage, restart, or destination-chain instability) or is exacerbated any time gas markets are volatile immediately before/after such a gap — conditions outside any single unprivileged attacker's direct control, similar to the "sequencer down" precondition in the original report. However, unlike the original report, the beneficiary here is any ordinary user submitting inbound/outbound traffic during that window, not a privileged actor, and no malicious validator/relayer collusion is required.

### Recommendation
Track and expose the freshness of the currently-applied chain-meta price (e.g. `LastAppliedAtSeconds`) so that outbound-creation logic (`GetOutboundTxGasAndFees` / `GetGasFeeInfoForRevertOutbound`) can detect when the on-chain price is beyond the staleness window and either (a) block outbound creation for that chain until a fresh median is available, or (b) apply a conservative safety margin/markup instead of the raw stale value. Additionally, reconsider allowing a single fresh vote to move the post-bootstrap median — require a minimum fresh-vote count on every write, not only the first one, to reduce the ability of stale/degraded validator sets to swing the oracle on isolated votes.

### Proof of Concept
1. Let 3 UVs establish a bootstrapped `ChainMeta` entry for chain `C` with gas price `P1` (`chainMetaMinVotesForFirstWrite` satisfied).
2. All UVs stop voting chain-meta for `C` for > `chainMetaVoteStalenessSeconds` (300s) — e.g., destination-chain RPC outage. `fresh` becomes empty on the next vote attempt; the stored `gasPriceByChainNamespace` for `C` remains `P1` (see `x/uexecutor/keeper/chain_meta.go:145-154`).
3. Real destination-chain gas price rises sharply to `P2 >> P1` during the outage.
4. A user submits an outbound (e.g., a `FUNDS` withdrawal) for chain `C` while the oracle is still stuck at `P1`. `GetOutboundTxGasAndFees` returns `GasPrice = P1`, and `OutboundTx.GasFee` is computed and locked from that stale value.
5. UVs relay the outbound at the real cost `P2`, and vote `gas_fee_used = fee(P2) > GasFee`. `applyGasRefund` computes `gasFee.Cmp(gasFeeUsed) <= 0` and returns without any refund or additional charge — the protocol has permanently under-collected the fee for that outbound.

func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
```

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
```
