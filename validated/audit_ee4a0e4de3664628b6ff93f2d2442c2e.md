### Title
`ensure_match_transaction_info` skips checkpoint-hash validation, so `verify_execution` replay/backfill can accept a corrupted state/hot-state/position root - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` — used by the chunk executor's `verify_execution` path (transaction backfill / `db-tool replay-on-archive`) — validates status, gas, write-set hash, and event root against a given `TransactionInfo`, but explicitly does **not** validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`. This mirrors the external report's root cause (an aggregation/verification routine that omits a required per-item check, letting an unchecked value corrupt a subsequent commit/verify decision), but in a state-commitment/proof-verification context on Aptos rather than an asset-allowlist context.

### Finding Description
`ensure_match_transaction_info` ( [1](#0-0) ) is the function that reconciles a locally-recomputed `TransactionOutput` against a `TransactionInfo` supplied from an external/untrusted source (e.g., an archive being replayed, or a backfill/verification chunk). It checks:
- execution status
- gas used
- write-set hash vs `state_change_hash`
- event root hash

but the function's own comment states it "ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`)" [2](#0-1) .

This function is invoked from `ChunkExecutor::verify_execution`, which is the code path used to verify transactions being replayed/backfilled against externally supplied `TransactionInfo`s ( [3](#0-2) ). Because the checkpoint hash fields are excluded from this per-transaction comparison, a `TransactionInfo` whose `state_checkpoint_hash` / `hot_state_checkpoint_hash` / `position_state_checkpoint_hash` diverges from what local execution actually produced can still pass `verify_execution` as long as status/gas/write-set/event hashes line up. The state checkpoint root itself is computed and cross-checked separately during `DoStateCheckpoint::run` -> `get_state_checkpoint_hashes` when `known_state_checkpoints` are supplied at the chunk level ( [4](#0-3) ), so the plain state-checkpoint hash is not silently missed for the currently-shipped feature. However, the position-native state root path (`compute_trading_native_state_roots`) is explicitly gated as not-yet-safe by the same TODO, which says the comparator "can report a successful replay even when the authenticated position state root diverges from local execution" and that checkpoint hashes must be validated here "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`" ( [5](#0-4) ).

### Impact Explanation
If `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (position-native state roots) were enabled while this gap remains, `verify_execution`/replay tooling (e.g. `db-tool`'s `replay_on_archive`, used for chain-of-custody / replay-verify testing) would accept and report success for a chunk whose `position_state_checkpoint_hash` does not match what local execution actually computed — i.e., an authenticated-response/proof field bound to the wrong ledger state could pass verification undetected. This is exactly the "authenticated API or state-view output bound to the wrong version/proof context" and "wrong ... proof accepted as valid" class of impact called out in the state-integrity gate. It is currently mitigated only by the fact that the feature (`COMPUTE_TRADING_NATIVE_STATE_ROOTS`) that depends on this check is apparently not yet turned on in this comparator's intended use, per the developer's own TODO gating language.

### Likelihood Explanation
Low-to-moderate as a live mainnet issue today: the code comment itself documents this as a known, intentionally-tracked gap that must be closed "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`," implying the feature is not (yet) safe to enable and the team is aware. I could not fully confirm from local index searches whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/trading-native state roots is already active on mainnet vs. still under development — this is called out in `types/src/on_chain_config/aptos_features.rs` and `storage/aptosdb/src/db/aptosdb_reader.rs`/`aptosdb_writer.rs`, but I did not have enough remaining iterations to trace its activation status or default value across those files. If the feature is enabled anywhere before this fix lands, likelihood becomes high, since the check is unconditionally skipped, not just conditionally.

### Recommendation
Extend `ensure_match_transaction_info` to compare `self`-derived state/hot-state/position checkpoint hashes (when present on the transaction being validated, e.g. via the paired `StateCheckpointOutput`) against `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, and `txn_info.position_state_checkpoint_hash()`, matching the same fail-closed pattern already used for `state_change_hash`/`event_root_hash`. This should be done and verified as a blocking prerequisite before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled on any network.

### Proof of Concept
Not exploitable end-to-end from local static analysis alone — confirming a concrete PoC would require validating (a) that `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is reachable/enabled on some network configuration, and (b) crafting a chunk-transfer/backfill scenario feeding an externally-controlled `TransactionInfo` with a mismatched `position_state_checkpoint_hash` through `ChunkExecutor::verify_execution`. Given the remaining iteration budget, I could not trace the feature's on-chain default/activation status; this should be verified in a live environment (e.g., a Devin session) before treating this as an actionable, in-scope mainnet finding rather than a documented, already-tracked pre-launch gap.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }
