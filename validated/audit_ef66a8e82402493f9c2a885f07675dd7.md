The claim is structurally correct. Here is the precise analysis:

**How the register sentinel works:** In NEAR VM host functions, when `ptr == u64::MAX`, the `len` parameter is reinterpreted as a **register ID**, not a byte count. `get_memory_or_register!` returns the entire register contents regardless of the `len`/register-ID value. This is the standard NEAR VM convention.

**The ordering problem:** `pay_per(yield_resume_byte, payload_len)` is called **before** `get_memory_or_register!` resolves the payload. At that point, `payload_len` is the caller-supplied value. When `payload_ptr == u64::MAX`, `payload_len` is the register ID (e.g., `0`, `1`, `2`), not the actual byte count. Gas is therefore charged for `0`, `1`, or `2` bytes of `yield_resume_byte` cost, while the actual payload submitted is the full register contents.

**What is and is not undercharged:** The doc comment at line 3733 lists two separate fees: `yield_resume_byte` per byte of payload, and fees for reading the payload. The `get_memory_or_register!` call does charge a register-read fee based on actual register size. So the register-read component is correctly charged. Only the `yield_resume_byte` component is undercharged.

**The size limit guard:** After reading, `payload_len` is overwritten with `payload.len()` and checked against `max_yield_payload_size`. This correctly bounds the payload size but does not retroactively fix the already-charged gas.

**Conclusion:** The `yield_resume_byte` fee is genuinely undercharged when a register sentinel is used. The attacker pays the register-read cost but bypasses the `yield_resume_byte` per-byte cost for the actual payload size. This is a real but **partial** fee bypass, bounded by `max_yield_payload_size`.

### Title
`yield_resume_byte` Gas Undercharge via Register Sentinel in `promise_yield_resume` - (`runtime/near-vm-runner/src/logic/logic.rs`)

### Summary
`promise_yield_resume` charges `yield_resume_byte` gas using the caller-supplied `payload_len` before resolving the actual payload. When `payload_ptr == u64::MAX` (register sentinel), `payload_len` is a register ID (a small integer), not a byte count. Gas is charged for that small integer's worth of bytes, but the full register contents are submitted as the payload.

### Finding Description
In `VMLogic::promise_yield_resume`:

```rust
self.result_state.gas_counter.pay_per(yield_resume_byte, payload_len)?;  // uses caller-supplied value
let payload = get_memory_or_register!(self, payload_ptr, payload_len)?;   // when ptr==u64::MAX, len is register ID
let payload_len = payload.len() as u64;                                   // actual size, too late
```

When `payload_ptr == u64::MAX`, `payload_len` is treated as a register ID by `get_memory_or_register!`. The gas charge uses this register ID (e.g., `0`) as the byte count. The actual payload returned is the full register contents, which can be up to `max_yield_payload_size` bytes. The `yield_resume_byte` fee for those bytes is never charged. [1](#0-0) 

### Impact Explanation
An unprivileged contract can bypass the `yield_resume_byte` per-byte gas cost for yield resume payloads. By pre-loading a large blob into a register and calling `promise_yield_resume` with `payload_ptr = u64::MAX` and `payload_len = <register_id>`, the contract pays `yield_resume_byte * register_id` instead of `yield_resume_byte * actual_payload_size`. This is a fee payment bypass. The register-read gas is still charged, so the bypass is partial, but the `yield_resume_byte` cost is a distinct protocol-defined fee that is fully skipped.

### Likelihood Explanation
Any contract author can exploit this deliberately. The register sentinel (`u64::MAX`) is a documented and widely used NEAR VM convention, so the pattern is easy to discover. The bypass is bounded by `max_yield_payload_size` but is repeatable across transactions.

### Recommendation
Move the `pay_per(yield_resume_byte, ...)` call to after `get_memory_or_register!` resolves the payload, using the actual payload length:

```rust
let payload = get_memory_or_register!(self, payload_ptr, payload_len)?;
let payload_len = payload.len() as u64;
self.result_state.gas_counter.pay_per(yield_resume_byte, payload_len)?;
```

Apply the same fix to `promise_yield_resume_with_yield_id`. [3](#0-2) 

### Proof of Concept
Pre-load a 1 MB blob into register 0. Call `promise_yield_resume(data_id_len, data_id_ptr, 0, u64::MAX)`. The gas charged for `yield_resume_byte` is `0 * yield_resume_byte_cost = 0`. The actual payload submitted is 1 MB. Compare against calling with `payload_len = 1_000_000` and `payload_ptr` pointing to memory: the gas charged for `yield_resume_byte` is `1_000_000 * yield_resume_byte_cost`. The register path pays zero of this cost.
