### Title
Starknet OS `execute_replace_class` accepts undeclared/invalid class hashes, diverging from Blockifier's validated `replace_class` syscall - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `kro` advisory describes a confused-deputy pattern where a privileged component (the kro controller) blindly trusts user-supplied input (an arbitrary image reference) and acts on it without validating that the input meets the trust assumptions the rest of the system relies on. The analogous pattern in this sequencer is the Starknet OS's implementation of the `replace_class` syscall: unlike the Rust `blockifier` execution engine — the actual privileged component that decides what constitutes a valid state transition — the Cairo OS program that re-derives/proves that same state transition omits the authorization check that the class hash being written into a contract's state must correspond to an actually-declared (and Cairo1) class.

### Finding Description
`replace_class` lets any contract change its own `class_hash` at will; the only safety property enforced by the protocol is that the supplied `class_hash` must refer to a class that has actually been declared (and, for V1 contracts, must remain a Cairo1 class). In the `blockifier` (the sequencer's Rust execution engine used to build and validate blocks), this is enforced explicitly: [1](#0-0) 

This reads the compiled class (failing with `UndeclaredClassHash`/"is not declared" if it doesn't exist) and further rejects replacement with a Cairo0 (V0) class hash via `ForbiddenClassReplacement`.

The Starknet OS Cairo program, which re-executes transactions to produce the proof of the block's state transition, implements the identical syscall but with the validation explicitly missing, as flagged by its own TODO comment: [2](#0-1) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The OS unconditionally performs the `dict_update` writing the caller-supplied `class_hash` into `contract_state_changes`, with no check that the class was ever declared and no check rejecting Cairo0 class hashes. The deprecated (Cairo0) syscall path in the OS has the same gap: [3](#0-2) 

This is a confused-deputy-style trust violation: the OS is the ultimate arbiter of "what is a valid Starknet execution" for proving purposes, yet it trusts a value (`class_hash`) supplied by an ordinary, unprivileged contract call without verifying it against the actually-declared class set — the same verification the blockifier itself insists on before accepting the same syscall.

### Impact Explanation
Any account or contract can invoke `replace_class_syscall` with an arbitrary, non-existent (or Cairo0) class hash from a single ordinary transaction — no special privileges needed. The `blockifier` (used by the sequencer to build/validate the block and to independently re-execute it, e.g. via `apollo_batcher`/re-execution flows) will reject this call ("is not declared" / `ForbiddenClassReplacement`), typically causing the transaction to revert. The Starknet OS, however, will happily accept it and commit the class-hash change into `contract_state_changes` when it re-executes the same call while generating the block's correctness proof. This produces a state-transition computed by the OS that differs from the state transition actually committed by the sequencer/blockifier for the same transaction — a direct honest-node divergence between the two components that are supposed to agree on Starknet's execution semantics, per the rules' explicitly in-scope category "Starknet OS re-execution" and impact "honest-node divergence" / "wrong committed root". Depending on how proof verification reconciles this mismatch, it can manifest either as an inability to produce a valid, matching proof for an otherwise-honest block (halting proof generation and thus blocking new transaction confirmation), or as a state root computed by the prover that does not match what blockifier-based nodes computed.

### Likelihood Explanation
Likelihood is high: `replace_class_syscall` is a standard, unrestricted syscall available to any deployed contract, requires no special account permissions, and the only precondition is calling it with a class hash that has not been declared (trivially satisfiable — e.g. a random felt). No race conditions, no p2p assumptions, and no privileged party is required to trigger this from a single submitted transaction/contract call.

### Recommendation
Add the missing declared-class (and Cairo-version) check to the OS's `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` (and the deprecated variant in `deprecated_execute_syscalls.cairo`), mirroring the blockifier's `syscall_base.rs::replace_class`: look up the class hash in the OS's tracked declared-classes/contract-class-changes dictionary and fail (or otherwise short-circuit consistent with blockifier's revert semantics) when the class hash is undeclared or is a Cairo0 class, before performing the `dict_update` on `contract_state_changes`.

### Proof of Concept
1. Deploy any Cairo1 contract that exposes `replace_class_syscall` (e.g. the `test_replace_class` external function pattern used in feature-contract tests).
2. From an ordinary account, invoke that entry point passing an arbitrary, never-declared `class_hash` (e.g. `felt!(1234)`), analogous to the existing blockifier test: [4](#0-3) 
3. In the blockifier, this call fails with "is not declared" and the transaction reverts (or fails), i.e. no state change is recorded for that contract's class hash.
4. In the Starknet OS's `execute_replace_class` (`syscall_impls.cairo:881-920`), the identical call — because the declared-class check is absent — would proceed to `dict_update` the contract's class hash to the undeclared value, producing a `contract_state_changes` entry that the blockifier never produced for the corresponding transaction, demonstrating the divergence between the two "identical" execution engines.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
