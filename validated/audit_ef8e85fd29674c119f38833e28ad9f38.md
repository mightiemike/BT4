## Analysis: Permanently Locked Bridged Funds When Inbound Ballot Fails to Reach Quorum

The C4 report's bug class — deposited funds having no permissionless withdrawal path once the intended automatic mechanism doesn't fire — has a direct, still-open analog in `x/uexecutor`'s inbound voting pipeline.

### Title
Bridged inbound funds are permanently unrecoverable when an inbound ballot terminates as EXPIRED/REJECTED — the escape-hatch refund flow does not exist and the only alternative is a privileged admin action - (File: `x/uexecutor/keeper/ballot_hooks.go`)

### Finding Description
When a user bridges an asset from a source chain, Universal Validators (UVs) submit `MsgVoteInbound` and the vote is recorded per-variant via `RecordInboundVote` [1](#0-0) . If the ballot(s) for that inbound never reach the PASSED threshold — e.g. votes split across encodings/variants, or validators simply never finish voting before the deadline — `AfterBallotTerminal`/`afterInboundBallotTerminal` routes the entry into `ExpiredInbounds` once **all** variants terminate as EXPIRED or REJECTED, explicitly *without ever creating a `UniversalTx`* [2](#0-1) .

Critically, the code and proto comments state this data is "Consumed by the **future** escape-hatch refund flow" [3](#0-2) [4](#0-3)  — i.e. that flow does not exist yet. `ExpiredInbounds` is read-only, exposed solely via a paginated query `AllExpiredInbounds` [5](#0-4) ; there is no message type that lets the original depositor claim or trigger a refund for an entry sitting in this collection.

The only code path that can turn a stuck inbound into a refund is `RevertStuckInbound`, but it is gated to the module's governance/admin address:
```go
admin, err := ms.k.uvalidatorKeeper.GetAdmin(ctx)
...
if admin != msg.Signer {
    return nil, errors.Wrapf(govtypes.ErrInvalidSigner, ...)
}
``` [6](#0-5) 

and even for the admin it only works if the ballot's status is precisely `EXPIRED` (not `REJECTED`), and the admin must separately run `MsgRecomputeBallotQuorum` beforehand to force a stuck ballot into that state:
```go
if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
    return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, ...)
}
``` [7](#0-6) 

So exactly as in the C4 report — where USDM deposits sat in the Curve pool with no user-triggerable withdraw and only a guardian could move them — here the user's bridged asset (already committed on the source-chain gateway/vault by an honest, unprivileged user) has:
1. No PRC20 ever minted on Push Chain (since the UTX was never created for failed-quorum inbounds), and
2. No permissionless path back to the source chain, since the revert/rescue outbound machinery (`buildRevertOutbound`, `attachOutboundsToUtx`) is only reachable from execution failure paths after a UTX exists, or from the admin-only `RevertStuckInbound`.

### Impact Explanation
Funds committed by an ordinary user to bridge into Push Chain become permanently frozen the moment quorum fails to converge (REJECTED) or expires without admin intervention. This is a direct "permanent freezing of user-controlled funds" outcome, matching the in-scope impact category, and is triggered purely by honest-but-non-converging validator votes or benign timing (validators failing to finish voting before ballot expiry) — no malicious actor is required.

### Likelihood Explanation
Ballot non-convergence/expiry is a normal operational condition (the codebase already has dedicated tests and an audit-trail mechanism, `ExpiredInbounds`, purpose-built for this exact scenario — see `TestQueryAllExpiredInbounds` [8](#0-7) ), so this is not a rare edge case but an anticipated, recurring situation for which the fix is explicitly deferred ("future escape-hatch refund flow").

### Recommendation
Implement the promised escape-hatch refund flow as a permissionless message (e.g. `MsgClaimExpiredInboundRefund`) that any caller (ideally restricted to the original sender/recipient) can submit once an `ExpiredInbounds` entry exists for their inbound, driving the same `buildRevertOutbound`/`attachOutboundsToUtx` path that `RevertStuckInbound` uses, without requiring governance/admin signature.

### Proof of Concept
1. User submits a bridge deposit on the source chain; UVs begin voting via `MsgVoteInbound`.
2. Voters split across ballot variants (different encodings) such that no single variant reaches quorum before `BlockHeightExpiry`, or votes reach the REJECTED threshold.
3. `MarkBallotFinalized`/`MarkBallotExpired` fires `AfterBallotTerminal` → `afterInboundBallotTerminal`, and once all variants are terminal-failure, the entry is moved to `ExpiredInbounds` [9](#0-8)  with no `UniversalTx` and no outbound ever created.
4. The user has no message to call to reclaim the source-chain funds; only the admin's `MsgRevertStuckInbound` could act, and only for `EXPIRED` (not `REJECTED`) ballots, requiring manual admin operations. Funds remain stuck indefinitely absent that discretionary admin action.

func (k Keeper) AllExpiredInbounds(goCtx context.Context, req *types.QueryAllExpiredInboundsRequest) (*types.QueryAllExpiredInboundsResponse, error) {
	if req == nil {
		return nil, status.Error(codes.InvalidArgument, "invalid request")
	}
	ctx := sdk.UnwrapSDKContext(goCtx)
	entries, pageRes, err := query.CollectionPaginate(ctx, k.ExpiredInbounds, req.Pagination, func(_ string, value types.ExpiredInboundEntry) (types.ExpiredInboundEntry, error) {
		return value, nil
	})
	if err != nil {
		return nil, status.Error(codes.Internal, err.Error())
	}

	return &types.QueryAllExpiredInboundsResponse{
		Entries:    entries,
		Pagination: pageRes,
	}, nil
}

func (ms msgServer) RevertStuckInbound(ctx context.Context, msg *types.MsgRevertStuckInbound) (*types.MsgRevertStuckInboundResponse, error) {
	ms.k.Logger().Info("msg: RevertStuckInbound", "signer", msg.Signer)

	admin, err := ms.k.uvalidatorKeeper.GetAdmin(ctx)
	if err != nil {
		return nil, errors.Wrap(err, "failed to read uvalidator admin")
	}
	if admin != msg.Signer {
		return nil, errors.Wrapf(govtypes.ErrInvalidSigner, "invalid admin; expected %s, got %s", admin, msg.Signer)
	}

	if msg.Inbound == nil {
		return nil, errors.Wrap(sdkErrors.ErrInvalidRequest, "inbound is required")
	}

	utxId, outboundId, err := ms.k.RevertStuckInbound(ctx, *msg.Inbound)
	if err != nil {
		return nil, err
	}

func (k Keeper) RevertStuckInbound(ctx context.Context, inbound types.Inbound) (utxId, outboundId string, err error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Same canonical form as the vote path, so the admin-supplied payload
	// derives the same ballot key / UTX key the votes did.
	inbound.Canonicalize()

	if vErr := inbound.ValidateBasic(); vErr != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, vErr.Error())
	}

	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, fmt.Sprintf("failed to derive ballot key: %s", err))
	}

	ballot, err := k.uvalidatorKeeper.GetBallot(ctx, ballotKey)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrNotFound, fmt.Sprintf("ballot for inbound not found (key=%s): %s", ballotKey, err))
	}

	if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("ballot %s status is %s; admin revert requires EXPIRED (use MsgRecomputeBallotQuorum to drive a stuck pending ballot to EXPIRED)",
				ballotKey, ballot.Status.String()))
	}
