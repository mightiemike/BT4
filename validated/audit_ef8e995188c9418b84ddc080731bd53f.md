### Title
Unauthenticated `batchProver_pauseProving` / `citrea_haltCommitments` RPC calls let anyone stop batch proving and sequencer commitment publishing - ([File: crates/common/src/rpc/auth.rs])

### Summary
The `Auth` RPC middleware only requires an API key for three hard-coded methods (`backup_create`, `backup_validate`, `backup_info`). All other JSON-RPC methods exposed on the same public port — including `batchProver_pauseProving`, `batchProver_setCommitments`, `batchProver_prove`, `citrea_haltCommitments`, and `citrea_resumeCommitments` — are reachable by any caller without authentication, mirroring the "anyone who uses the same adapter has the ability to pause it" pattern from the source report: a state-mutating control-plane action that should require creator/owner privilege is instead callable by an unprivileged party.

### Finding Description
The RPC server wires a single `Auth` middleware layer over the entire merged `RpcModule`: [1](#0-0) 

The `Auth` implementation only gates a fixed allow-list of "protected" method names and passes every other method straight through with no privilege check at all: [2](#0-1) 

Batch-prover and sequencer control RPCs — which are meant to be operator-only actions — are registered into the exact same `RpcModule<()>` as public `eth_*`/`citrea_*` methods, with no additional authorization check inside the handlers themselves: [3](#0-2) [4](#0-3) [5](#0-4) 

Once received, `pauseProving` sets `proving_paused = true` in the `Prover` run loop, halting all future proving jobs, and `haltCommitments`/`resumeCommitments` toggle the sequencer's commitment publishing: [6](#0-5) 

Additionally, `batchProver_setCommitments` allows anyone to overwrite the prover's pending-commitment state ("It overrides the commitment already if exists, so use with caution"): [7](#0-6) 

None of these methods are in `PROTECTED_METHODS`, so an unauthenticated caller who can reach the batch prover's or sequencer's RPC endpoint can invoke them directly.

### Impact Explanation
This breaks the intended authority boundary: "operator/owner-authorised state mutation" versus "any network caller." Calling `pauseProving` repeatedly stops the batch prover from ever proving new commitments, which stalls the proof pipeline that ultimately produces the batch proofs feeding the light-client/bridge state — directly analogous to the source finding where an unprivileged actor pauses an adapter shared by other vaults, freezing yield generation. Calling `haltCommitments` stops the sequencer from publishing sequencer commitments to L1, halting the entire rollup's progress toward L1 finality/proving. `setCommitments` can corrupt the prover's view of pending commitments, potentially causing incorrect partitioning or wasted/incorrect proving attempts. This matches the "High" bucket in the rules: "an unauthenticated JSON-RPC call that mutates node state or bypasses Auth."

### Likelihood Explanation
High if the RPC endpoint (bind_host/bind_port) is reachable over the network, which is the default deployment topology for prover/sequencer RPC ports serving both public `eth_*` calls and these control methods on the same listener. No credentials, keys, or special role are needed — a single unauthenticated JSON-RPC POST request suffices.

### Recommendation
Add `batchProver_pauseProving`, `batchProver_setCommitments`, `batchProver_prove`, `batchProver_submitFakeProof`, `batchProver_createCircuitInput`, `citrea_haltCommitments`, and `citrea_resumeCommitments` (and any other state-mutating operator RPCs) to the `PROTECTED_METHODS` list in `crates/common/src/rpc/auth.rs`, or move them to a separate RPC module bound to a private/admin-only listener that is never exposed alongside public JSON-RPC methods.

### Proof of Concept
1. Start a batch prover node with default configuration (RPC port bound and reachable, no `api_key` set or caller lacking it).
2. From any unauthenticated client, send:
```
curl -X POST http://<prover-rpc-host>:<port> \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"batchProver_pauseProving","params":[],"id":1}'
```
3. Observe the request succeeds (no 401), and `Prover::run` sets `proving_paused = true`, permanently halting new proving jobs until an equally unauthenticated `prove` call or restart occurs.
4. Similarly, `citrea_haltCommitments` can be sent to a sequencer's RPC endpoint to stop sequencer commitment publication with no authentication.

```rust
const PROTECTED_METHODS: [&str; 3] = ["backup_create", "backup_validate", "backup_info"];

#[derive(Debug, Clone)]
pub struct Auth<S> {
    service: S,
    api_key: Option<String>,
}

impl<S> Auth<S> {
    pub fn new(service: S, api_key: Option<String>) -> Self {
        Self { service, api_key }
    }
}

impl<'a, S> RpcServiceT<'a> for Auth<S>
where
    S: RpcServiceT<'a> + Send + Sync + Clone + 'a,
{
    type Future = BoxFuture<'a, MethodResponse>;

    fn call(&self, req: Request<'a>) -> Self::Future {
        let method = req.method_name();
        let service = self.service.clone();
        let api_key = self.api_key.clone().map(Value::from);

        if !PROTECTED_METHODS.contains(&method) {
            return Box::pin(service.call(req));
        }
```
