### Title
Module-originated EVM value transfers (`DerivedEVMCall`) trust Go-level `err == nil` and never check `MsgEthereumTxResponse.VmError`, allowing reverted PRC20 re-mints and gas refunds to be recorded as `SUCCESS` - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The original report flags Solidity `.transfer()`/`.send()` being used for ETH transfers without checking the boolean success of the underlying call, post-Istanbul. The Push Chain analog is structurally identical at the module level: every fund-moving `DerivedEVMCall` (re-mint on revert, unused-gas refund, PRC20 deposit) is only checked via the Go-level `error` return value, never via the EVM execution-level `VmError`/status field on the returned `*evmtypes.MsgEthereumTxResponse`. In `cosmos-evm`-style stacks, an EVM-level revert of the underlying Solidity call (e.g. `depositPRC20Token` reverting inside the handler contract) commonly surfaces as `err == nil` with the revert reason recorded only in the response's `VmError`/`Ret` fields, exactly the same "silent failure" class the ETH-transfer report warns about.

### Finding Description
`k.evmKeeper.DerivedEVMCall(...)` is the single production entry point for all module-originated EVM state changes [1](#0-0) . Every fund-critical call site in `x/uexecutor/keeper/evm.go` — `CallPRC20Deposit`, `CallPRC20DepositAutoSwap`, `CallUniversalCoreRefundUnusedGas`, `CallExecuteUniversalTx` — only inspects the returned Go `error`, never the response's execution-level result [2](#0-1) [3](#0-2) .

In `handleFailedOutbound` (the code path that re-mints bridged PRC20 tokens back to a user after a failed outbound), the receipt is treated as authoritative proof of success purely because `err == nil`: [4](#0-3) 

Likewise `applyGasRefund`, which calls `CallUniversalCoreRefundUnusedGas` for the gas-refund swap and no-swap fallback paths, records `refundPcTx.Status = "SUCCESS"` solely on `err == nil`: [5](#0-4) 

A grep across the repository confirms `VmError` (or any equivalent EVM-execution-status field) is never referenced anywhere in `x/uexecutor` or `universalClient`, meaning a reverted-but-technically-error-free `DerivedEVMCall` is architecturally indistinguishable from a real success at every call site.

### Impact Explanation
Because `OutboundTx.PcRevertExecution`/`PcRefundExecution` are written to `"SUCCESS"` without verifying that the deposit/refund Solidity call actually executed (rather than reverting internally), an unprivileged, ordinary user-observable sequence — an outbound that legitimately fails on the destination chain, or a gas-refund whose swap/deposit call reverts inside `UniversalCore` for any reason (e.g., liquidity cap checks, paused token, insufficient allowance/liquidity) — can be finalized by honest validators as a successful revert/refund while the PRC20 balance was never actually re-minted to the user. This is a direct, unprivileged path to **permanent loss of user funds**: the `OutboundTx` moves to `REVERTED`/is finalized, `PendingOutbounds` is cleared (per the README's stated invariant that pending entries are removed only on consensus success) [6](#0-5) , and there is no automatic re-trigger of the mint because the UTX component state says it already ran successfully.

### Likelihood Explanation
Reachability requires no privileged actor — any ordinary crosschain deposit/withdrawal whose destination-chain leg fails (a routine, attacker-uninfluenced-but-user-reachable occurrence) drives execution into `handleFailedOutbound`/`applyGasRefund`. Any condition that makes the underlying Solidity call revert without failing at the Go/ABI-encoding layer (mismatched liquidity cap, paused PRC20, zero balance in the vault, arithmetic revert in `refundUnusedGas`) is sufficient to trigger the false-success recording; none of this needs an unusual or adversarial precondition.

### Recommendation
After every `DerivedEVMCall` used for a fund-moving/refund/revert operation, explicitly check the EVM execution-level result (equivalent to Solidity's `.call()` return-boolean check recommended in the original report) — i.e., inspect `MsgEthereumTxResponse.VmError`/failure status in addition to the Go `error`, and only mark `PcTx.Status = "SUCCESS"` when both the RPC-level call succeeded and the underlying EVM execution did not revert. Apply this uniformly to `CallPRC20Deposit`, `CallPRC20DepositAutoSwap`, `CallUniversalCoreRefundUnusedGas`, and `CallExecuteUniversalTx`, and thread that check through `handleFailedOutbound`/`applyGasRefund`/`ExecuteInboundGasAndPayload` so a reverted derived call is recorded as `FAILED`/`ABORTED` and retried/investigated instead of being treated as a completed fund movement.

### Proof of Concept
1. Drive a `UniversalTx` to a state where `handleFailedOutbound` runs (an `OutboundTx` observed as failed by UVs for a `FUNDS`/`GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` tx type) [7](#0-6) .
2. Arrange (via ordinary, non-privileged means — e.g., a token whose liquidity cap or pause state causes `depositPRC20Token` to revert inside `UniversalCore`) for the underlying Solidity re-mint call to revert while `DerivedEVMCall` still returns `err == nil` with a non-nil receipt carrying a VM-level failure.
3. Observe `pcTx.Status` set to `"SUCCESS"` and `outbound.PcRevertExecution` populated as success purely from `receipt != nil && err == nil` [8](#0-7) , while the user's PRC20 balance was never actually credited on the EVM side.
4. The outbound is finalized as `REVERTED` and removed from `PendingOutbounds`, permanently losing the user's bridged funds with no operator-visible signal distinguishing this from a genuine successful re-mint.

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}
