## Analog Vulnerability Found

### Title
Stale ETH/STRK exchange-rate fallback lets a transaction sender pay gas fees in a mispriced fee token — ([File: crates/apollo_l1_gas_price_config/src/config.rs], [File: crates/apollo_consensus_orchestrator/src/utils.rs])

### Summary
The Starknet sequencer prices every resource (`l1_gas`, `l1_data_gas`, `l2_gas`) in **two parallel fee tokens**, ETH (wei) and STRK (fri), derived from a single `eth_to_fri_rate` that is applied uniformly to convert one token's price vector into the other's [1](#0-0) . Exactly like the yAxis vault that minted/burned shares treating all deposited stablecoins as fungible at 1:1 regardless of their real relative value, the sequencer treats ETH and STRK gas prices as fungible via this single conversion rate, and that rate is allowed to go stale for very long windows before being rejected.

### Finding Description
`GasPrices` stores an `eth_gas_prices` vector (wei) and a `strk_gas_prices` vector (fri); the two are linked only via `eth_to_fri_rate`, computed with `wei_to_fri`/`fri_to_wei` [2](#0-1) . A single unprivileged transaction sender selects which token to pay fees in simply by choosing the transaction version/`fee_type` (legacy V1/V2 pay in ETH wei, V3 pays in STRK fri) [3](#0-2) .

The `eth_to_fri_rate` used to build each block's `GasPrices` comes from an oracle with a configured freshness window. The default configuration accepts a Chainlink feed reading as fresh for up to `max_staleness_seconds = 90000` (25 hours) [4](#0-3) , and the rate itself is only clamped to a very wide `eth_strk` band — "10,000 .. 1,000,000 STRK per ETH, roughly 10x either side of spot" [5](#0-4) . Additionally, when the oracle or L1 gas price provider fails entirely, the orchestrator falls back first to reusing the *previous accepted block's* wei/fri prices and re-derived rate, and — if no previous block exists — to a hard-coded `DEFAULT_ETH_TO_FRI_RATE` (10^21, i.e. 1 ETH = 1000 STRK) combined with configured minimum wei prices [6](#0-5) . The module doc explicitly favors availability over price accuracy: "undercharging slightly is better than overcharging... The configured minimums and the default ETH→STRK rate are safe floors" [7](#0-6) .

Because gas-price and fee-token validation only checks that a transaction's declared `max_price_per_unit` is not below the *current block's* gas price for that resource/fee-type [8](#0-7)  and [9](#0-8) , there is no cross-check that the block's ETH-denominated and STRK-denominated gas prices are mutually consistent with real-time market value. If the true ETH/STRK market rate moves meaningfully within the (up to 25-hour) staleness/fallback window — well within the accepted 10x band — the sequencer keeps quoting gas in the *stale* rate for whichever fee token an attacker chooses.

### Impact Explanation
An attacker can submit L1-gas/L1-data-gas-heavy transactions paid in whichever fee token (ETH or STRK) is currently underpriced relative to the true market exchange rate captured by the stale/fallback `eth_to_fri_rate`. This is directly analogous to the reported vault bug: instead of "deposit DAI, withdraw USDT at 1:1 while true prices diverge," here it is "declare fees in the fee-token/tx-version whose gas price is temporarily mispriced relative to the other, while the resource consumed (L1 gas paid to Ethereum) has a real, unchanging cost." The result is systematic under-collection of fees relative to the sequencer's actual L1 posting costs — a concrete, protocol-level value leak reachable by any ordinary transaction sender, not an operator or validator.

### Likelihood Explanation
The staleness window (up to 90000s / 25h) and rate-bound tolerance (~10x) are wide enough that meaningful ETH/STRK divergence during that period is plausible, especially combined with the "previous block" fallback chain that can propagate a once-valid-but-now-stale rate indefinitely as long as blocks keep proposing successfully (each successful proposal re-derives the rate from the still-frozen previous values) [10](#0-9) . No special privileges are required — the attacker only needs to pick the transaction version/fee type and submit L1-gas-consuming calls during the stale window.

### Recommendation
- Tighten the acceptable staleness window and rate-divergence tolerance for `eth_to_fri_rate`, or require the rate to be periodically re-validated against a live oracle rather than perpetually re-derived from previous block info.
- Cross-check ETH-denominated and STRK-denominated gas prices against each other and against a live market source before finalizing a block, rejecting/flagging blocks where the implied rate has drifted materially from the last confirmed live oracle reading.
- Consider bounding how many consecutive blocks may rely on the "previous block" fallback before forcing a hard fallback to conservative minimums, rather than allowing an indefinitely stale rate to propagate.

### Proof of Concept
1. Force (or wait for) the L1 gas price oracle/provider to fail (e.g., transient outage) so the orchestrator enters the "previous block" or "default rate" fallback path [6](#0-5) .
2. During this window, monitor real-world ETH/STRK market price; if it has moved such that STRK-priced L1 gas is now cheaper in real terms than the frozen fri conversion implies, submit V3 (STRK fee) transactions with heavy L1 calldata/blob usage, paying resource_bounds priced at the stale/fallback rate.
3. Repeat while the fallback/staleness condition persists (up to 25 hours per `max_staleness_seconds`), extracting L1 resource consumption at fees below true market-equivalent cost, mirroring the vault exploit's `deposit(cheap_token) -> withdrawAll(expensive_token)` pattern but applied to sequencer fee-token pricing.

impl GasPrice {
    pub fn wei_to_fri(self, eth_to_fri_rate: u128) -> Result<GasPrice, StarknetApiError> {
        // We use integer division since wei * eth_to_fri_rate is expected to be high enough to not
        // cause too much precision loss.
        Ok(self
            .checked_mul_u128(eth_to_fri_rate)
            .ok_or_else(|| {
                StarknetApiError::GasPriceConversionError(format!(
                    "Gas price is too high: {:?}, eth to fri rate: {:?}",
                    self, eth_to_fri_rate
                ))
            })?
            .checked_div(WEI_PER_ETH)
            .expect("WEI_PER_ETH must be non-zero"))
    }
    pub fn fri_to_wei(self, eth_to_fri_rate: u128) -> Result<GasPrice, StarknetApiError> {

                    "Gas price is too high: {:?}, eth to fri rate: {:?}",
