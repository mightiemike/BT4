## Title
Hardcoded 5% slippage computed from a same-block, un-TWAP'd Uniswap V3 spot quote allows value extraction from gas-token auto-swaps and gas refunds — (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Push Chain's gas-token auto-swap and gas-refund paths compute `minPCOut` (the Uniswap V3 slippage floor) as 95% of a quote fetched from the pool's *current* spot price via `QuoterV2.quoteExactInputSingle`, immediately before executing the real swap in the same code path. This is the same bug class as the BondingTax `minOutput` issue: the "expected output" used to bound slippage is derived from the very same AMM state the swap will execute against, rather than an independent/TWAP reference price. An attacker can move the PRC20↔WPC pool price before the deposit-and-swap (or refund-and-swap) executes, causing the module to accept a swap result far below fair value while still satisfying its own self-referential 5% check, then reverse the trade afterward to capture the difference.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` (a view simulation against live pool reserves/sqrtPriceX96) to obtain `amountOut` for a `prc20 → wpc` swap. This quote is then multiplied by 95% to derive `minPCOut`, and immediately used as the slippage floor for the actual on-chain swap performed by `CallPRC20DepositAutoSwap` in [2](#0-1) .

This pattern is repeated in three separate flows:
- `ExecuteInboundGas`, where `quote` is fetched and `minPCOut := quote * 95/100` is computed just before `CallPRC20DepositAutoSwap`: [3](#0-2) 
- `gasAndPayloadDepositAutoSwap`, identical pattern for GAS_AND_PAYLOAD inbounds: [4](#0-3) 
- `applyGasRefund`, which refunds excess destination-chain gas by swapping the gas token back to native PC using the same quote-then-95%-slippage pattern: [5](#0-4) 

In all three cases, the "expected" price and the "minimum acceptable" price are both derived from the same instantaneous AMM state at swap time — there is no independent oracle, no TWAP observation, and no bound relative to a historical/fair reference price. Any user can permissionlessly trade against the `PRC20/WPC` Uniswap V3 pool (these are ordinary on-chain pools, not privileged infrastructure) to move the spot price immediately before an inbound/outbound is finalized and its associated swap executes. Because the module always re-derives its "expected output" from the currently-manipulated pool state, the 5% slippage check can never detect or block the manipulation — it only bounds noise around whatever (possibly manipulated) price exists at call time.

### Impact Explanation
This directly maps to fund-loss/value-extraction impact in the audit scope: "stealing... permanent loss... of user or protocol-controlled funds" during universal execution and refund/registry accounting flows. A user depositing a gas-paying PRC20 token for GAS or GAS_AND_PAYLOAD inbound routing, or a user receiving an excess-gas refund on outbound observation, can have their swap executed at an attacker-manipulated price, receiving materially less native PC than fair value — with the deficit captured by the attacker via a sandwich. Because the check is self-referential, this happens through the ordinary, unprivileged inbound/outbound/refund flow, not through any validator, relayer, or admin compromise.

### Likelihood Explanation
Likelihood is realistic: PRC20/WPC pools are ordinary, permissionlessly tradeable Uniswap V3 pools; any external account can submit swap transactions to shift spot price. Because the finalize-and-swap logic runs the quote and the swap sequentially using live pool state (not a delayed/TWAP price), an attacker only needs to move the pool price shortly before the module's `DerivedEVMCall` executes (e.g., ahead of the block/tx that finalizes the triggering inbound/outbound ballot) and reverse it afterward — a standard sandwich pattern requiring no privileged access, no validator collusion, and no protocol bug beyond the missing independent price reference.

### Recommendation
Do not derive the slippage floor from the same spot quote used immediately before the swap. Use a manipulation-resistant reference price instead, e.g.:
- A Uniswap V3 TWAP (time-weighted average price over a meaningful window) via `observe()`, or
- An independently reported/oracle price for the PRC20/WPC pair, or
- A conservative, governance-configured minimum-price floor per token, updated infrequently and bounded against extreme deviation from recent observed prices.

Apply this consistently to `GetSwapQuote`'s consumers: `ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund`.

### Proof of Concept
1. Attacker observes that a large GAS_AND_PAYLOAD inbound (or outbound gas refund) is about to be finalized (ballot close to quorum / pending finalize tx visible).
2. Attacker submits a large swap against the `PRC20/WPC` Uniswap V3 pool used by `GetSwapQuote`, pushing the spot price so that `prc20 → wpc` yields far less WPC than fair value.
3. The finalize transaction executes; `k.GetSwapQuote(...)` (`x/uexecutor/keeper/evm.go:502-538`) reads the now-manipulated pool state and returns a depressed `quote`.
4. `minPCOut := quote * 95 / 100` is computed from this depressed quote (`x/uexecutor/keeper/execute_inbound_gas.go:142-148`), so it is trivially satisfied by the equally depressed real swap output.
5. `CallPRC20DepositAutoSwap` executes the swap at the manipulated price, crediting the user's UEA with far less native PC than the token was worth before the attack.
6. Attacker reverses their initial trade, restoring the pool price and pocketing the value difference extracted from the victim's swap.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
