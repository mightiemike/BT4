## Analysis: BIND recursive-parsing DoS → Sierra/CASM bytecode-segment recursion in Starknet sequencer

The CVE describes unbounded native recursion while parsing a nested/attacker-influenced structure before any authentication check, exhausting the stack and crashing the process. The closest reachable analog in this codebase is the recursive processing of the CASM `bytecode_segment_lengths` tree (`NestedIntList`) that is derived from a declarer-submitted Sierra program and then walked recursively — without any depth bound — whenever the compiled-class hash is computed or the class is re-executed by the Starknet OS.

### Title
Unbounded native recursion over attacker-influenced `NestedIntList` bytecode-segment tree causes stack-overflow DoS during compiled-class hashing/OS re-execution - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
`bytecode_hash_node` in [1](#0-0)  recursively walks the `bytecode_segment_lengths` (`NestedIntList`) tree of a `CasmContractClass` with plain (non-tail) Rust recursion and no depth limit. The equivalent function `create_bytecode_segment_structure_inner` in [2](#0-1)  does the same during Starknet OS re-execution. This tree is produced by the Sierra-to-CASM compiler from a declarer-submitted Sierra program, and the sequencer never validates its nesting depth before recursing over it.

### Finding Description
When a `Declare` transaction is submitted, the gateway's `SierraCompiler::compile` compiles the Sierra program to CASM and immediately computes the compiled class hash via `executable_class.hash(&HashVersion::V2)` [3](#0-2) . `hash()` calls `hash_inner`, which calls `bytecode_hash`, which recurses through `bytecode_hash_node` over the entire `bytecode_segment_lengths` structure [4](#0-3) . The same hash is recomputed at execution time whenever a V3+ Declare transaction is applied, via `check_compile_class_hash_v2_declaration` [5](#0-4) , which is invoked from `DeclareTransaction::run_execute` for every declaring node [6](#0-5) .

`bytecode_segment_lengths` is an `Option<NestedIntList>` where `NestedIntList::Node(Vec<NestedIntList>)` is unbounded in nesting depth by type [7](#0-6) . It is generated by the (external) Sierra-to-CASM compiler based on the structure of the submitted Sierra program's functions/branches, and nowhere in this repository is the resulting tree depth capped before it is recursively traversed — contrasting with the sibling function `NestedFeltCounts::new_inner`, which explicitly asserts `segmentation_depth <= 1` [8](#0-7) , showing that the codebase itself acknowledges segment depth needs bounding, yet the two hashing/segment-structure functions used on the hot declare/execution/OS-reexecution paths lack this guard.

Unlike Cairo VM execution recursion (bounded by `max_recursion_depth` via `RecursionDepthGuard` [9](#0-8) ) or gas-limited Sierra execution, this bytecode-segment recursion runs entirely in native Rust with no gas/step accounting and no explicit depth check — mirroring the BIND flaw where recursion depth is bounded only by input size, not by an explicit, authenticated limit.

### Impact Explanation
A crafted Sierra program that compiles into a CASM contract whose `bytecode_segment_lengths` tree has sufficient nesting depth can trigger a Rust stack overflow, which aborts the process (not a catchable panic). Because every node independently compiles/hashes a newly declared class (gateway `SierraCompiler::compile`) and every node re-executes/re-verifies the Declare transaction (`check_compile_class_hash_v2_declaration`, and Starknet OS `create_bytecode_segment_structure`), a single malicious Declare transaction can crash all participating sequencer/prover nodes simultaneously — a network-wide denial of service consistent with "network unable to confirm new transactions."

### Likelihood Explanation
Reaching this code only requires submitting an ordinary Declare transaction with an attacker-crafted (but otherwise valid, size-limited) Sierra program; no special privileges, RNDC-key-equivalent, staking, or p2p roles are needed — matching the CVE's "no authentication required" characteristic. The main uncertainty is whether the third-party Sierra-to-CASM compiler's segmentation strategy can be steered by program structure (e.g., many nested conditional/branch/function constructs) to produce an arbitrarily deep `NestedIntList`, which is plausible given nothing in this repo constrains the compiler's segmentation output before it is consumed recursively.

### Recommendation
Add an explicit depth (and/or node-count) bound check before or during recursive traversal of `NestedIntList`/`bytecode_segment_lengths` in `bytecode_hash_node` (`compiled_class_hash.rs`) and `create_bytecode_segment_structure_inner` (`utils.rs`), returning a validation error instead of recursing when the bound is exceeded — analogous to the `segmentation_depth <= 1` assertion already present in `NestedFeltCounts::new_inner`. Alternatively, convert these functions to explicit iterative (stack-based) traversal so unbounded nesting cannot exhaust the native call stack, and validate the segment tree depth as part of Sierra-to-CASM compilation/declare validation before it is used in hashing or OS re-execution.

### Proof of Concept
1. Construct a Sierra program (within existing `max_contract_bytecode_size`/`max_calldata_length` limits) engineered to compile into a CASM contract class whose compiler-emitted `bytecode_segment_lengths` (`NestedIntList`) has deep nesting (e.g., via many nested branch/function constructs that the compiler segments recursively).
2. Submit this program as the `contract_class` of a `Declare` (V3) transaction to the gateway.
3. Gateway's `SierraCompiler::compile` compiles it and calls `executable_class.hash(&HashVersion::V2)` [10](#0-9) , which recurses through `bytecode_hash_node` [1](#0-0)  to a depth proportional to the crafted nesting, exhausting the stack and aborting the process before any block inclusion/authentication of the class occurs.
4. Any node that later re-executes/re-verifies the Declare transaction (`check_compile_class_hash_v2_declaration`) or performs Starknet OS re-execution (`create_bytecode_segment_structure`) crashes identically, producing a repeatable, network-wide denial of service from a single submitted transaction.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,

        *COMPILED_CLASS_V1,

        l1_handlers_hash,

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
