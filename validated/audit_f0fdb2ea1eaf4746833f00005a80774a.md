Given the evidence gathered, this is the key finding: the "default CU" per top-level BPF instruction is `DEFAULT_INSTRUCTION_COMPUTE_UNIT_LIMIT` = 200,000, which is charged regardless of whether that program CPIs elsewhere. Since compute metering (`ComputeMeter`) is a single shared budget across a whole transaction that decrements for both the outer BPF program's own execution and every CPI it makes (including into `system_program`), the 200,000 CU allocated to a non-builtin top-level instruction already accounts for arbitrary internal CPI cost up to the remaining budget — there is no separate "per-instruction" sub-budget that could be exceeded in isolation while the transaction-level counter still shows headroom. The `core/tests/scheduler_cost_adjustment.rs` test at [1](#0-0)  explicitly demonstrates a top-level BPF Loader v3 instruction CPI-ing into `system_program`, and shows the single, generously-sized default allocation (3,000 CU for builtins) already covers the loader's own cost plus the nested CPI cost with margin — the design is intentionally sized to absorb this.     fn calculate_default_compute_unit_limit(&self, feature_set: &FeatureSet) -> u32 {
        // evaluate if any builtin has migrated with feature_set
        let (num_migrated, num_not_migrated) = self
            .migrating_builtin_feature_counters
            .migrating_builtin
            .iter()
            .enumerate()
            .fold((0, 0), |(migrated, not_migrated), (index, count)| {
                if count.0 > 0 && feature_set.is_active(get_migration_feature_id(index)) {
                    (migrated + count.0, not_migrated)
                } else {
                    (migrated, not_migrated + count.0)
                }
            });

        u32::from(self.num_non_migratable_builtin_instructions.0)
            .saturating_add(u32::from(num_not_migrated))
            .saturating_mul(MAX_BUILTIN_ALLOCATION_COMPUTE_UNIT_LIMIT)
            .saturating_add(
                u32::from(self.num_non_builtin_instructions.0)
                    .saturating_add(u32::from(num_migrated))
                    .saturating_mul(DEFAULT_INSTRUCTION_COMPUTE_UNIT_LIMIT),
            )
    }
