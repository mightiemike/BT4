## Analysis

The Push Chain analog of the Holograph "stuck job" bug lives in the **outbound execution/TSS-broadcast pipeline**, not the inbound one. Push Chain already recognized and patched this exact bug class for **inbound** ballots — via `x/uexecutor/keeper/admin_revert.go`'s `RevertStuckInbound` plus `x/uvalidator/keeper/ballot.go`'s `RecomputeBallotQuorum` — but the equivalent escape hatch does **not exist for outbound** jobs, and the code explicitly documents this asymmetry as intentional.

### Title
Outbound bridging jobs have no escape hatch when TSS-signed broadcast never lands, permanently freezing bridged funds - ([File: x/uexecutor/keeper/ballot_hooks.go], [File: x/uexecutor/keeper/pending_outbound.go], [File: universalClient/tss/txbroadcaster/evm.go])

### Summary
An `OutboundTx` is created with a gas price/limit/fee **fixed once**, at outbound-creation time, from `UniversalCore.getOutboundTxGasAndFees` [1](#0-0) . UVs then TSS-sign and broadcast a transaction using exactly that fixed gas price [2](#0-1) [3](#0-2) . If the destination chain's required gas price rises above this fixed value after signing, the broadcaster keeps retrying the *same* signed transaction indefinitely rather than re-pricing it, per the documented broadcast retry logic [4](#0-3) . The `PendingOutbounds` entry and the ballot for this outbound stay unresolved forever — and the code explicitly states that, unlike inbound, outbound ballot expiry does **not** trigger any cleanup or revert path: "outbound PendingOutbounds entries persist until validators reach consensus... Operators investigate stuck outbounds by correlating each variant's ballot_id with the uvalidator ballot status separately" [5](#0-4) , confirmed by the integration test asserting the entry stays PENDING even with all ballot variants EXPIRED [6](#0-5) .

### Finding Description
This is the exact bug class from the HolographOperator report: a job (here, a Push Chain outbound bridging transaction) is priced at creation time with a gas price the destination chain later exceeds, and no mechanism exists to let the job complete at a different price or to unwind/refund the user once it becomes clear the job is permanently stuck.

Push Chain's designers were aware of this general class of problem for **inbound** stuck jobs and built a full remediation path:
1. `MsgRecomputeBallotQuorum` lets an admin force a stuck `PENDING` ballot to `EXPIRED` when it can no longer reach quorum [7](#0-6) .
2. `MsgRevertStuckInbound` then consumes that `EXPIRED` ballot to synthesize a revert outbound that refunds the user on the source chain [8](#0-7) .

No equivalent message or keeper function exists for **outbound** jobs. Grep across the whole repository shows only `RevertStuckInbound`/`MsgRevertStuckInbound`, never a `RevertStuckOutbound`/`MsgRevertStuckOutbound`. The `BallotHooks` implementation, which is where the inbound auto-cleanup-and-audit-trail logic lives, explicitly skips `OUTBOUND_TX` ballots by design [9](#0-8) .

Meanwhile, the finalization logic that would refund gas or revert bridged funds (`FinalizeOutbound`, `handleFailedOutbound`, `applyGasRefund`) only runs *after* an outbound reaches `Status_OBSERVED` via `VoteOutbound` [10](#0-9)  — i.e., only after UVs successfully observe a mined destination-chain transaction. If the transaction is never mined (fixed gas price too low forever, or indefinitely, during a sustained fee spike as illustrated by the original report's Etherscan data), the outbound never reaches `OBSERVED`, `FinalizeOutbound`/`applyGasRefund` never runs, and the bridged assets that were already burned/locked on Push Chain to create this outbound remain unrecoverable.

### Impact Explanation
Any ordinary user who submits a payload/transaction that results in an outbound bridging transaction is exposed. If the destination-chain gas market moves against the fixed price baked into the outbound at creation time, the outbound job can never be mined, never reaches quorum/`OBSERVED`, and the user's PRC20/native funds already consumed by the bridge-out are permanently frozen with **no on-chain recovery mechanism** — unlike the identical scenario on the inbound side, which the protocol already fixed via `RevertStuckInbound`. This matches the in-scope impact category of "permanent freezing... of user or protocol-controlled funds," reachable purely by an ordinary user's default bridge-out submission plus normal (non-malicious) destination-chain fee-market conditions, with no privileged or malicious-actor assumption required.

### Likelihood Explanation
Gas price spikes on external EVM/SVM chains are a routine, well-documented occurrence (as cited directly in the original report). Any user's outbound created during a low-fee window, followed by a sustained fee increase, triggers this condition with no attacker action needed. The asymmetry between the inbound and outbound recovery paths is an intentional design choice per the code comments, not an edge case — meaning the gap is permanent until remediated, and it will recur every time destination-chain gas conditions outpace a previously-fixed `OutboundTx.GasPrice`.

### Recommendation
Introduce an outbound analog to the inbound escape hatch:
- Extend `BallotHooks`/`RecomputeBallotQuorum` semantics to `OUTBOUND_TX` ballots so a permanently-stuck outbound ballot can be driven to `EXPIRED`.
- Add a `RevertStuckOutbound`/admin (or eventually permissionless, timelocked) message analogous to `RevertStuckInbound` that, for an `EXPIRED` outbound ballot, mints back the PRC20/native asset to the original sender (mirroring `handleFailedOutbound`'s re-mint logic) and refunds any pre-paid gas fee, closing the same gap that Holograph's auditors flagged.
- Alternatively/additionally, support re-signing an outbound with an updated gas price after a configurable timeout so honest UVs can complete the original job instead of only being able to abort it.

### Proof of Concept
1. User submits a payload that results in `BuildOutboundsFromReceipt` creating a `Status_PENDING` `OutboundTx` with `GasPrice` fixed at current market rate [1](#0-0) .
2. UVs TSS-sign and the client broadcasts using that fixed `GasPrice` [3](#0-2) .
3. Destination chain gas price subsequently spikes and stays elevated (e.g., matching the Oct 8→9 Ethereum mainnet example in the original report).
4. The transaction is never mined; `Broadcaster` keeps retrying the same fixed-price signed tx forever per its documented retry semantics [4](#0-3) .
5. `VoteOutbound`/`FinalizeOutbound` never run because no UV observes a mined tx; `PendingOutbounds` entry and ballot remain unresolved indefinitely, confirmed by `TestMultiBallotExpiry_DoesNotRemovePendingOutbound` showing the entry survives ballot expiry [6](#0-5) .
6. Grep confirms no `RevertStuckOutbound`/`MsgRevertStuckOutbound` message exists to unwind this state, unlike the inbound side.

// RecomputeBallotQuorum rebuilds a pending ballot's eligible-voter list and
// voting threshold against the current eligible-voter set, preserving votes
// from voters still eligible and dropping votes from voters no longer eligible.
//
// If the recomputed eligible count is zero, the ballot is marked EXPIRED (no
// path to finalization). Otherwise it stays PENDING with the new parameters;
// downstream UVs must re-vote on the same ballot to trigger finalize+execute
// via the normal flow.
//
// Returns the old/new counts and threshold for the response.
func (k Keeper) RecomputeBallotQuorum(ctx context.Context, ballotID string) (
	oldEligibleCount, newEligibleCount, oldThreshold, newThreshold int64,
	newStatus types.BallotStatus,
	err error,
) {
	ballot, err := k.Ballots.Get(ctx, ballotID)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s not found: %w", ballotID, err)
	}

	if ballot.Status != types.BallotStatus_BALLOT_STATUS_PENDING {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s is not pending (status=%s); only pending ballots can be recomputed", ballotID, ballot.Status.String())
	}

	oldEligibleCount = int64(len(ballot.EligibleVoters))
	oldThreshold = ballot.VotingThreshold

	// Build the current eligible-voter set in the same valoper-bech32 format
	// the ballot already uses. The voting flow (VoteOnInboundBallot/VoteOnOutboundBallot)
	// passes CoreValidatorAddress strings directly into VoteOnBallot, so the
	// stored EligibleVoters list contains valoper bech32 addresses.
	eligibleUVs, err := k.GetEligibleVoters(ctx)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("failed to fetch eligible voters: %w", err)
	}

	newVoters := make([]string, 0, len(eligibleUVs))
	for _, uv := range eligibleUVs {
		if uv.IdentifyInfo == nil || uv.IdentifyInfo.CoreValidatorAddress == "" {
			k.Logger().Warn("recompute: skipping UV with missing identity info")
			continue
		}
		newVoters = append(newVoters, uv.IdentifyInfo.CoreValidatorAddress)
	}
	newEligibleCount = int64(len(newVoters))

	// Zero eligible voters: no path to finalization. Mark EXPIRED.
	if newEligibleCount == 0 {
		if err := k.MarkBallotExpired(ctx, ballotID); err != nil {
			return 0, 0, 0, 0, 0, fmt.Errorf("failed to mark ballot expired on zero-eligible recompute: %w", err)
		}
		k.Logger().Info("ballot recompute: zero eligible voters → marked expired",
			"ballot_id", ballotID,
			"old_eligible", oldEligibleCount,
		)
		return oldEligibleCount, 0, oldThreshold, 0, types.BallotStatus_BALLOT_STATUS_EXPIRED, nil
	}

// RevertStuckInbound creates an INBOUND_REVERT outbound for an inbound whose
// ballot has expired without finalizing. The revert outbound enters the normal
// PendingOutbounds flow; UVs sign it via TSS and broadcast it to the source
// chain, refunding the user.
//
// Strict precondition: the ballot for the supplied inbound must be in EXPIRED
// state. Admin must run MsgRecomputeBallotQuorum first to drive a stuck ballot
// to EXPIRED if it isn't already (recompute auto-expires when no eligible
// voters remain).
//
// Returns the new UTX ID and revert outbound ID for telemetry.
func (k Keeper) RevertStuckInbound(ctx context.Context, inbound types.Inbound) (utxId, outboundId string, err error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Same canonical form as the vote path, so the admin-supplied payload
	// derives the same ballot key / UTX key the votes did.
	inbound.Canonicalize()

	if vErr := inbound.ValidateBasic(); vErr != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, vErr.Error())
	}

	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, fmt.Sprintf("failed to derive ballot key: %s", err))
	}

	ballot, err := k.uvalidatorKeeper.GetBallot(ctx, ballotKey)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrNotFound, fmt.Sprintf("ballot for inbound not found (key=%s): %s", ballotKey, err))
	}

	if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("ballot %s status is %s; admin revert requires EXPIRED (use MsgRecomputeBallotQuorum to drive a stuck pending ballot to EXPIRED)",
				ballotKey, ballot.Status.String()))
	}

	universalTxKey := types.GetInboundUniversalTxKey(inbound)
	if has, hErr := k.HasUniversalTx(ctx, universalTxKey); hErr != nil {
		return "", "", fmt.Errorf("failed to check utx existence: %w", hErr)
	} else if has {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("universal tx %s already exists for this inbound", universalTxKey))
	}

	utx := types.UniversalTx{
		Id:        universalTxKey,
		InboundTx: &inbound,
		PcTx: []*types.PCTx{{
			Status:   "FAILED",
			ErrorMsg: "admin revert: stuck ballot expired",
		}},
	}
	if cErr := k.CreateUniversalTx(ctx, universalTxKey, utx); cErr != nil {
		return "", "", fmt.Errorf("failed to create utx for revert: %w", cErr)
	}

	revertOutbound := k.buildRevertOutbound(sdkCtx, &inbound)
	if revertOutbound == nil {
		return "", "", fmt.Errorf("failed to build revert outbound for inbound %s", universalTxKey)
	}

	if attachErr := k.attachOutboundsToUtx(sdkCtx, universalTxKey, []*types.OutboundTx{revertOutbound}, "admin revert: stuck ballot expired"); attachErr != nil {
		return "", "", fmt.Errorf("failed to attach revert outbound: %w", attachErr)
	}

	k.Logger().Info("admin revert: inbound revert outbound created",
		"utx_id", universalTxKey,
		"outbound_id", revertOutbound.Id,
		"source_chain", inbound.SourceChain,
		"recipient", revertOutbound.Recipient,
		"amount", revertOutbound.Amount,
	)

	return universalTxKey, revertOutbound.Id, nil
}

func (k Keeper) FinalizeOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	// If not observed yet, do nothing
	if outbound.OutboundStatus != types.Status_OBSERVED {
		return nil
	}

	obs := outbound.ObservedTx
	if obs == nil {
		return nil
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Info("finalizing outbound",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"success", obs.Success,
		"dest_chain", outbound.DestinationChain,
		"tx_type", outbound.TxType.String(),
	)

	if !obs.Success {
		return k.handleFailedOutbound(sdkCtx, utxId, outbound, obs)
	}

	return k.handleSuccessfulOutbound(sdkCtx, utxId, outbound, obs)
}
