The `bank_from_snapshot_archives` and `bank_from_snapshot_dir` functions in `runtime/src/snapshot_bank_utils.rs` place the capitalization mismatch check inside a conditional gated by `limit_load_slot_count_from_snapshot.is_none()` — mirroring the reported bug class where a critical post-condition health check is applied only in one branch/condition and silently skipped otherwise.

### Title
Capitalization mismatch check silently skipped when `limit_load_slot_count_from_snapshot` is set - (File: runtime/src/snapshot_bank_utils.rs)

### Summary
`bank_from_snapshot_archives` and `bank_from_snapshot_dir` compute `info.calculated_capitalization` from the reconstructed accounts index and compare it against `bank.capitalization()`. This comparison — the primary defense against a corrupted or maliciously/accidentally mismatched snapshot capitalization — is wrapped in `if limit_load_slot_count_from_snapshot.is_none() { return Err(...) }`, meaning whenever `limit_load_slot_count_from_snapshot` is `Some(_)`, the mismatch is detected internally but the error is never surfaced, and execution proceeds to use the bank as if capitalization were verified.

### Finding Description
In `bank_from_snapshot_archives`: [1](#0-0) 
and identically in `bank_from_snapshot_dir`: [2](#0-1) 

the capitalization check is only enforced in the branch where `limit_load_slot_count_from_snapshot` is `None`. When it is `Some(_)`, the mismatch is computed but the branch is a no-op, and the function returns a `Bank` whose recorded `capitalization()` field disagrees with the capitalization independently calculated from the loaded accounts index (`info.calculated_capitalization`), which is also used to help drive later verification (`verify_snapshot_bank`, called downstream at lines 268 and 450 with `calculated_accounts_lt_hash` derived from the same reconstruction pass). This is analogous to the reported bug class: a critical post-condition validation (`afterWithdrawChecks`) applied only in one branch (`token == tokenA/B`), leaving the other branch (LP token / here, "limited slot count" loads) with an unvalidated invariant.

### Impact Explanation
If the accounts index reconstructed from a snapshot has a capitalization that disagrees with the value embedded in the bank fields — whether due to a corrupted snapshot, a bug elsewhere in the reconstruction path, or (in more severe scenarios) an intentionally crafted incorrect snapshot — the mismatch is silently ignored whenever a node loads via a code path that sets `limit_load_slot_count_from_snapshot`. This can result in the validator running with a bank capitalization/accounts state that is internally inconsistent, producing incorrect balances or hash divergence relative to honest replay, without any error surfaced to the operator.

### Likelihood Explanation
The condition-gated skip is deliberate for the specific documented reason (a partial/limited load naturally changes calculated capitalization), so under normal validator restart flows (`limit_load_slot_count_from_snapshot = None`) the check is enforced correctly. The residual risk is that this parameter is plumbed through ledger-tool and lower-level snapshot-loading APIs, so any caller (including tooling paths that are reachable without direct malicious snapshot crafting) that sets it non-`None` inherits an unconditionally-skipped capitalization safety net for the rest of that run.

### Recommendation
Decouple "acceptable due to partial load" from "silently ignore any and all mismatches." At minimum, log an explicit warning whenever a mismatch is detected but suppressed due to `limit_load_slot_count_from_snapshot`, and consider bounding the acceptable discrepancy (e.g., only suppress if the skipped slots account for the delta) rather than unconditionally accepting an arbitrary capitalization difference.

### Proof of Concept
1. Load a bank from snapshot archives/dir while passing `limit_load_slot_count_from_snapshot = Some(n)`.
2. Arrange (e.g. via a snapshot with an inconsistent capitalization field, reachable through existing `test_bank_from_snapshot_archives_bad_capitalization`-style setup) for `bank.capitalization() != info.calculated_capitalization`.
3. Observe that unlike the `None` case (which returns `SnapshotError::MismatchedCapitalization`, as exercised by the existing test at [3](#0-2) ), no error is returned when `limit_load_slot_count_from_snapshot` is `Some`, and the bank is used downstream unchecked.

    /// Ensure bank_from_snapshot_archives() catches a snapshot with incorrect capitalization.
    #[test]
    fn test_bank_from_snapshot_archives_bad_capitalization() {
        let genesis_config = GenesisConfig::default();
        let bank = Bank::new_for_tests(&genesis_config);
        bank.fill_bank_with_ticks_for_tests();
        bank.set_block_id(Some(Hash::default()));

        // freeze the bank before mucking with capitalization, since
        // freezing also changes capitalization (fees, incinerator, etc).
        bank.freeze();

        let good_capitalization = bank.capitalization();
        let bad_capitalization = good_capitalization + 1;
        bank.set_capitalization_for_tests(bad_capitalization);

        let snapshot_dir = tempfile::TempDir::new().unwrap();
        let snapshot_config =
            snapshot_config_for_tests(&snapshot_dir, &snapshot_dir, &snapshot_dir);
        let full_snapshot_archive_info =
            bank_to_full_snapshot_archive(&snapshot_config, &bank).unwrap();

        let (_tmp_dir, accounts_dir) = create_tmp_accounts_dir_for_tests();
        let error = bank_from_snapshot_archives(
            &[accounts_dir],
            &full_snapshot_archive_info,
            None,
            &snapshot_config,
            &genesis_config,
            &RuntimeConfig::default(),
            None,
            Some(*bank.leader()),
            None,
            false,
            false,
            false,
            ACCOUNTS_DB_CONFIG_FOR_TESTING,
            None,
            Arc::default(),
        )
        .unwrap_err();

        match error {
            SnapshotError::MismatchedCapitalization(expected, calculated) => {
                assert_eq!(expected, bad_capitalization);
                assert_eq!(calculated, good_capitalization);
            }
            _ => {
                panic!("wrong error");
            }
        }
