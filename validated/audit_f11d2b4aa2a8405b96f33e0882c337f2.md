### Title
Permanent loss of bridged funds when an inbound's ballot votes split across `UniversalPayload` formatting variants and only a privileged admin can trigger recovery — ([File: x/uexecutor/keeper/msg_vote_inbound.go])

### Summary
Push Chain's inbound voting path derives the ballot key from a full marshal of the submitted `Inbound` struct, including the UV-supplied `UniversalPayload` sub-fields, but `Inbound.Canonicalize()` only normalizes top-level chain/address/hash fields and never touches the nested payload fields (`To`, `Data`, `GasLimit`, `MaxFeePerGas`, etc.). If honest, non-malicious validators independently decode/format these payload fields slightly differently for the same real cross-chain event, their votes fragment into separate ballot "variants" that individually never reach quorum. When all variants terminate `EXPIRED`, the funds that were already deposited into the external-chain gateway are never minted, and no outbound/refund is created automatically — the only recovery path, `MsgRevertStuckInbound`, requires the `uvalidator` module `Admin` to manually reconstruct the exact original payload off-chain and submit it. This mirrors the `Vault::allocateNewEmissions` bug class: funds are provisionally "allocated" (locked on the source chain, tracked in `PendingInbounds`) but recovery depends entirely on a specific privileged party voluntarily acting, with no permissionless fallback and no deadline-based automatic remediation.

### Finding Description
`VoteInbound` canonicalizes the inbound, then computes both the UTX key and the ballot key from the (still UV-supplied) struct: [1](#0-0) 

`Canonicalize()` normalizes only `SourceChain`, `TxHash`, `Sender`, `AssetAddr`, `Recipient`, `LogIndex`, `Amount`, `RawPayload`, `VerificationData`, and `RevertInstructions.FundRecipient`: [2](#0-1) 

It does **not** normalize the fields inside `UniversalPayload` (`To`, `Value`, `Data`, `GasLimit`, `MaxFeePerGas`, `MaxPriorityFeePerGas`, `Nonce`, `Deadline`). For `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` inbounds, this struct is populated directly by each voting validator (e.g., as constructed in the integration test) and only gets normalized/decoded-from-raw *after* ballot finalization via `NormalizeForTxType`, i.e., strictly after the ballot key has already been computed and voted on: [3](#0-2) 

Since `GetInboundBallotKey` is derived from the full marshaled `Inbound` (including the un-canonicalized payload), any incidental byte-level difference between honest validators' decoding of the same source-chain event (e.g., zero-padded vs. unpadded decimal strings, checksummed vs. lowercase hex addresses embedded in `Data`/`To`, hex-case differences) produces a distinct ballot key. `RecordInboundVote`/`BallotHooks` explicitly document this as the "variant" mechanism: [4](#0-3) 

If validator votes fragment across enough variants that none reaches quorum before ballot expiry, `BallotHooks.afterInboundBallotTerminal` moves the entire audit trail to `ExpiredInbounds` **without ever creating a `UniversalTx`**: [5](#0-4) 

At this point the user's real funds are already locked in the external gateway contract (that is the entire premise of an inbound), but nothing on Push Chain automatically compensates for it. The only remediation is the admin-only `MsgRevertStuckInbound`, which requires the ballot to be `EXPIRED` and requires the admin to supply the exact original `Inbound` payload reconstructed from off-chain logs (the chain does not persist ballot payloads): [6](#0-5) [7](#0-6) 

The `ExpiredInbounds` doc comments repeatedly describe automatic recovery as a "future" feature that does not yet exist: [8](#0-7) 

This is structurally the same flaw as the reported `BabelToken` issue: value is provisionally committed/allocated, but its release depends entirely on a specific party (there, the disabled receiver; here, the admin) choosing to call a gated function, with no automatic or permissionless path and no incentive for that party to notice and act before funds are lost or frozen indefinitely.

### Impact Explanation
An ordinary user submitting a normal cross-chain deposit with a payload (`FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD`) can have their inbound bridging permanently stuck if their transaction's payload encoding happens to be decoded with non-canonical formatting differences by different (fully honest) validators. Real principal (bridged funds already sent to the external gateway) is never minted on Push Chain and no automatic refund/outbound is generated — this is a permanent-freezing-of-user-funds condition unless a privileged admin happens to notice and manually intervenes with the exact original payload bytes, which the chain itself does not retain. This falls within the explicitly in-scope impact "permanent freezing... of user or protocol-controlled funds" reachable via "ordinary user deposits" and "honest validators/honest nodes."

### Likelihood Explanation
The likelihood of ordinary format divergence causing full quorum failure depends on the number of active UVs, the voting threshold, and how deterministic each UV's own decoding/serialization of the numeric/hex payload fields is. It is plausible with a moderately sized validator set (variance grows with validator count and with any independent client implementations), and can also be deliberately amplified by an attacker who crafts calldata/values in the source-chain event that are maximally ambiguous to canonicalize (e.g. non-canonical big-integer string widths, hex casing), increasing the chance no single variant meets quorum. The current recommended remediation, `MsgRevertStuckInbound`, is only usable by the `uvalidator` module admin, and is unreachable to any unprivileged party.

### Recommendation
- Extend `Inbound.Canonicalize()` (or add a payload-specific canonicalizer applied before ballot-key derivation) to normalize `UniversalPayload` sub-fields (numeric strings, hex-address casing/padding, hex-data formatting) so that honest validators observing the same on-chain event always produce byte-identical `Inbound` marshals and a single ballot key.
- Implement the documented "future escape-hatch refund flow" for `ExpiredInbounds` so that after ballot expiry, any account (not only the admin) can trigger an automatic refund outbound using the audit-trail data already stored in `ExpiredInboundEntry`, removing the single point of privileged dependency.

### Proof of Concept
Conceptual reproduction (integration-test style, analogous to `test/integration/uexecutor/pending_inbound_audit_trail_test.go` patterns):
1. Register 4+ UVs so a supermajority threshold is required.
2. Construct the same logical cross-chain deposit event but submit it via `MsgVoteInbound` from different validators with `UniversalPayload.Data`/`To` fields formatted with differing hex casing or differing zero-padding of numeric strings (simulating independent, honest decode-and-format behavior, or a deliberately ambiguous attacker-crafted payload).
3. Observe that `GetInboundBallotKey` produces distinct keys per formatting variant (`x/uexecutor/keeper/msg_vote_inbound.go` lines 60-66), so votes split across multiple `InboundVariant`s in the same `PendingInboundEntry`.
4. Advance blocks past ballot expiry height so all variants reach `BALLOT_STATUS_EXPIRED` without any variant reaching quorum.
5. Confirm via `AllExpiredInbounds` query that the entry is now in `ExpiredInbounds` and that `GetUniversalTx` for the derived UTX key returns not-found — i.e., no UTX/PCTx/outbound was ever created, and the deposited funds remain unminted/unrefunded on Push Chain.
6. Confirm that only `MsgRevertStuckInbound`, signed by `uvalidator Params.Admin`, can create the compensating outbound (`x/uexecutor/keeper/admin_revert.go`), and that no unprivileged/permissionless path exists to recover the funds.

func (k Keeper) VoteInbound(ctx context.Context, universalValidator sdk.ValAddress, inbound types.Inbound) error {
	// Canonicalize first so every derived key + the stored inbound use one
	// representation per logical event.
	inbound.Canonicalize()

	k.Logger().Info("vote inbound received",
		"validator", universalValidator.String(),
		"source_chain", inbound.SourceChain,
		"tx_hash", inbound.TxHash,
		"tx_type", inbound.TxType.String(),
		"sender", inbound.Sender,
	)

	// Check inbound enabled before any state changes
	enabled, err := k.uregistryKeeper.IsChainInboundEnabled(ctx, inbound.SourceChain)
	if err != nil {
		return errors.Wrap(err, "failed to check inbound enabled")
	}
	if !enabled {
		k.Logger().Warn("vote inbound rejected: chain inbound disabled", "source_chain", inbound.SourceChain)
		return fmt.Errorf("inbound is disabled for chain %s", inbound.SourceChain)
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Step 1: Derive UTX key from the original inbound data (source_chain:tx_hash:log_index)
	universalTxKey := types.GetInboundUniversalTxKey(inbound)
	found, err := k.HasUniversalTx(ctx, universalTxKey)
	if err != nil {
		return errors.Wrap(err, "failed to check UniversalTx")
	}
	if found {
		k.Logger().Warn("vote inbound rejected: utx already exists", "utx_key", universalTxKey)
		return fmt.Errorf("universal tx with key %s already exists", universalTxKey)
	}

	// use a temporary context to not commit any ballot state change in case of error
	tmpCtx, commit := sdkCtx.CacheContext()

	// Step 2: Record this validator's vote in the per-utx PendingInbounds entry
	// (variant-aware audit trail). Each unique Inbound payload becomes its own
	// variant; multiple variants per utx_key indicate validator divergence.
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return errors.Wrap(err, "failed to derive inbound ballot key")
	}
	if err := k.RecordInboundVote(tmpCtx, inbound, universalValidator.String(), ballotKey); err != nil {
		return err
	}

func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

func (p *Inbound) NormalizeForTxType() error {
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		// Payload types: recipient is only meaningful when isCEA
		if !p.IsCEA {
			p.Recipient = EvmZeroAddress
		}
		// Always clear universal_payload — whatever the UV sends is ignored.
		// Core validator decodes from raw_payload.
		p.UniversalPayload = nil

		// Decode raw_payload → universal_payload
		if p.RawPayload != "" {
			decoded, err := DecodeRawPayload(p.RawPayload, p.SourceChain)
			if err != nil {
				return fmt.Errorf("failed to decode raw payload: %w", err)
			}
			if decoded == nil {
				return fmt.Errorf("raw_payload decoded to nil for payload tx type")
			}
			p.UniversalPayload = decoded
			p.RawPayload = "" // clear after successful decode to save storage
		}
	default:
		// Non-payload types: payload is not used
		p.UniversalPayload = nil
		p.VerificationData = ""
		p.RawPayload = ""
	}
	return nil
}
