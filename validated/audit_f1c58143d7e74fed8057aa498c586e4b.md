## Finding

### Title
Cairo-Native compilation path lacks the audited-libfuncs restriction, allowing a declared class to reach in-process native code execution unvetted - (File: `crates/apollo_compile_to_native/src/compiler.rs`)

### Summary
The sequencer treats compilation of an attacker-declared Sierra class as a security boundary: the Sierra→CASM compiler enforces an `audited_libfuncs_only` gate that restricts which libfuncs a declared class may use before its bytecode is trusted [1](#0-0) , and this gate defaults to `true` and is explicitly enabled on mainnet and sepolia-alpha [2](#0-1) [3](#0-2) . However, the parallel Sierra→Native compilation path used by Cairo Native execution has no equivalent restriction at all: `SierraToNativeCompiler::compile` invokes the native compiler binary with only output-path and optimization-level arguments, never an allowed/audited libfuncs flag [4](#0-3) , and `SierraCompilationConfig` for native compilation carries no `audited_libfuncs_only`-equivalent field [5](#0-4) .

### Finding Description
Any Sierra class declared through an ordinary `DECLARE` transaction can reach two very different execution engines depending on sequencer configuration: the CASM VM (via `apollo_compile_to_casm`) or Cairo Native, which AOT-compiles the Sierra program to a native shared object and then loads and directly calls into it from within the sequencer/batcher process via `AotContractExecutor` [6](#0-5) . The `audited_libfuncs_only` flag is the sequencer's explicit trust boundary for which libfuncs are considered safe to compile and run: the audited list is the set that has undergone security review, and the CASM path allows operators to enforce it via `--allowed-libfuncs-list-name audited` [1](#0-0) , with a dedicated test asserting the audited list stays in sync with what the compiler ships [7](#0-6) .

The Cairo Native compilation path (`crates/apollo_compile_to_native`), which is invoked from `NativeClassManager` whenever `cairo_native_mode` is enabled for any declared class (subject only to `NativeClassesWhitelist`, which gates class hashes, not libfuncs) [8](#0-7) , never passes any libfunc-allowlist argument to the native compiler binary and never checks the Sierra program's libfunc usage before compiling it to native code that will subsequently execute in-process. This means a class using non-audited (including experimental/pending) libfuncs — which the CASM path can be configured to reject outright — is compiled to native machine code and executed with the full trust of the sequencer/batcher process once Cairo Native is enabled, regardless of whether `audited_libfuncs_only` is set anywhere.

Additionally, even the CASM-side control is inconsistently applied across deployments: the sepolia-integration overlay explicitly sets `audited_libfuncs_only: false` [9](#0-8) , showing this boundary is a config knob that can be (and is) turned off, while the native path offers no equivalent knob to turn on in the first place.

### Impact Explanation
Cairo Native directly loads and executes attacker-influenced compiled code in the sequencer's own process address space [6](#0-5) . Restricting compilation to audited libfuncs exists precisely to bound what such native-compiled code is permitted to do, since libfuncs outside the audited set have not been vetted for safe interaction with the native/host execution model. Bypassing or omitting this restriction on the native path raises the risk that a maliciously crafted but syntactically valid declared class, using an unaudited libfunc, could corrupt sequencer process state, crash the batcher, or otherwise cause execution behavior diverging from the CASM reference semantics — leading to honest-node divergence or denial of block production for any node running Cairo Native with the affected class whitelisted.

### Likelihood Explanation
Declaring a class is a normal, unprivileged, permissionless transaction available to any sender. Reaching this path only requires: (1) the target sequencer to run with Cairo Native enabled (`cairo_native_mode != Off`), and (2) the declared class hash being included in `native_classes_whitelist` (or `All`) [10](#0-9) . Both are legitimate, expected operational configurations documented in the repo's own config schema, not attacker-controlled misconfigurations, making this reachable in supported deployment topologies.

### Recommendation
Add an audited-libfuncs enforcement mechanism to the Sierra→Native compilation path equivalent to the CASM path — either by validating the Sierra program's libfunc usage against the audited list before invoking `apollo_compile_to_native`, or by passing an allowed-libfuncs restriction through to the native compiler binary itself — and make this restriction mandatory (not an optional config flag) for any class hash eligible for `native_classes_whitelist`.

### Proof of Concept
1. Configure a sequencer/batcher with `cairo_native_run_config.cairo_native_mode = LazyCompilation` (or `WaitOnCompilation`) and `native_classes_whitelist = All`, per `crates/apollo_node/resources/config_schema.json` defaults referenced above.
2. Submit an ordinary `DECLARE` (V3) transaction whose Sierra program legitimately passes CASM's stateless validation (contract class size, Sierra version) but uses a libfunc absent from `crates/apollo_compile_to_casm/src/allowed_libfuncs.json` (the audited set) — e.g., one of the `PENDING_LIBFUNCS` entries or another unaudited/experimental libfunc.
3. Once accepted and cached as `CompiledClasses::V1`, `NativeClassManager::set_and_compile` triggers `SierraToNativeCompiler::compile` unconditionally (no libfunc check) in `crates/apollo_compile_to_native/src/compiler.rs`, producing a native shared object from the unaudited Sierra program.
4. Any subsequent invocation of the class runs through `native_entry_point_execution::execute_entry_point_call`, executing the natively-compiled, unaudited code in-process via `AotContractExecutor`, with no libfunc-based safety restriction ever having been applied.

    pub fn compile(
        &self,
        contract_class: ContractClass,
    ) -> Result<AotContractExecutor, CompilationUtilError> {
        let compiler_binary_path = &self.path_to_binary;

        let output_file = NamedTempFile::new()?;
        let output_file_path = output_file.path().to_str().ok_or(
            CompilationUtilError::UnexpectedError("Failed to get output file path".to_owned()),
        )?;
        let optimization_level = self.config.optimization_level.to_string();
        let additional_args = [output_file_path, "--opt-level", &optimization_level];
        let resource_limits = ResourceLimits::new(
            Some(self.config.max_cpu_time),
            self.config.max_file_size,
            Some(self.config.max_memory_usage),
        );
        let _stdout = compile_with_args(
            compiler_binary_path,
            contract_class,
            &additional_args,
            resource_limits,
        )?;

        Ok(AotContractExecutor::from_path(output_file.path())
            .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
            .unwrap())
    }

fn allowed_libfuncs_aligned_to_audited() {
    let libfuncs_list_selector = ListSelector::ListName(BUILTIN_AUDITED_LIBFUNCS_LIST.to_string());
    let expected = lookup_allowed_libfuncs_list(libfuncs_list_selector).unwrap().allowed_libfuncs;

    let actual_str = include_str!("allowed_libfuncs.json");
    let actual = serde_json::from_str::<AllowedLibfuncs>(actual_str).unwrap().allowed_libfuncs;

    let pending_set: HashSet<&str> = PENDING_LIBFUNCS.iter().copied().collect();

    let missing: Vec<_> =
        expected.keys().filter(|k| !actual.contains_key(k)).map(ToString::to_string).collect();
    let extra: Vec<_> = actual
        .keys()
        .filter(|k| !expected.contains_key(k))
        .map(ToString::to_string)
        .filter(|k| !pending_set.contains(k.as_str()))
        .collect();
    let mismatched: Vec<_> = expected
        .iter()
        .filter(|(k, v)| actual.get(k).is_some_and(|av| av != *v))
        .map(|(k, _)| k.to_string())
        .collect();

    assert!(
        missing.is_empty() && extra.is_empty() && mismatched.is_empty(),
        "allowed_libfuncs.json is not aligned with the audited list.\n Missing (in audited but \
         not in json): {missing:?}\n Extra (in json but not in audited): {extra:?}\n Value \
         mismatch: {mismatched:?}"
    );
}

    /// Returns the runnable compiled class for the given class hash, if it exists in class_cache.
    pub fn get_runnable(
        &self,
        class_hash: &ClassHash,
        native_classes_whitelist: &NativeClassesWhitelist,
    ) -> Option<RunnableCompiledClass> {
        let cached_class = self.class_cache.get(class_hash)?;
        if let CompiledClasses::V1(..) = cached_class {
            // When native mode is WaitOnCompilation, all V1 classes should have been
            // compiled to native synchronously. A V1 cache entry indicates a pipeline bug.
            assert_ne!(
                self.cairo_native_mode(),
                CairoNativeMode::WaitOnCompilation,
                "Manager did not wait on native compilation."
            );
        }

        let cached_class = match cached_class {
            CompiledClasses::V1Native(CachedCairoNative::Compiled(native))
                if !native_classes_whitelist.contains(class_hash) =>
            {
                CompiledClasses::into_non_native_class(native)
            }
            CompiledClasses::V1Native(..) | CompiledClasses::V1(..) | CompiledClasses::V0(..) => {
                cached_class
            }
        };

        Some(cached_class.to_runnable())
    }
