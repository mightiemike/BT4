**Rationale for rejection:**

The exploit hypothesis requires that oversized `collection_name`, `uri`, or `description` strings passed through `CreateCollection::new` ( [1](#0-0) ) could overflow "buffer assumptions" in event-root hashing during transaction info construction. This does not hold up structurally:

1. **No fixed-size buffer exists in the hash path.** BCS serializes `String`/`Vec<u8>` fields with ULEB128 length-prefixing plus raw bytes — there's no fixed buffer to overflow. `ContractEventV2::event_data` is a `Vec<u8>` (`serde_bytes`), and `ContractEventV2::size()` only computes `bcs::serialized_size(&self.type_tag) + self.event_data.len()` as a `usize` sanity check at construction time, not a hashing buffer boundary [2](#0-1) .

2. **Event root hashing uses a cryptographic Merkle accumulator over arbitrary-length leaves.** `CryptoHash::hash` on each `ContractEvent` (SHA3-based `BCSCryptoHash`) processes the full BCS-serialized byte stream regardless of length, then `InMemoryEventAccumulator::from_leaves` combines fixed-size (32-byte) hash digests, not the raw variable-length payload [3](#0-2) . There is no scenario where payload length affects the accumulator's node/leaf structure — accumulators always operate on `HashValue` (fixed 32-byte) leaves.

3. **The same recomputation is used everywhere for verification**, and it's fully deterministic: `ensure_match_transaction_info` [4](#0-3) , `verify_events_against_root_hash` in output-list proof verification [5](#0-4) , and `TransactionWithProof::verify` [6](#0-5)  all independently recompute the identical hash from the identical byte stream and must agree — any legitimate long string would deterministically produce the same event root hash on every node, since BCS+SHA3 hashing has no length-dependent truncation or overflow behavior.

4. Separately, at the Move level, `token.move`'s `create_collection` already enforces `MAX_COLLECTION_NAME_LENGTH` / `MAX_URI_LENGTH` bounds [7](#0-6) , and even where unbounded (e.g., `aptos_token_objects` collection creation), Move's gas metering charges per-byte, making truly "unbounded" strings economically self-limiting rather than a state-integrity issue.

No wrong write set, proof node, root, or version binding is identified — the hash computation path is length-agnostic and consistent between execution, storage commit, and proof verification.
