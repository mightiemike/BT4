### Title
Starknet OS `execute_replace_class` accepts undeclared class hashes, diverging from Blockifier's validated `replace_class` syscall — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler in the Blockifier (the sequencer's actual transaction-execution engine) enforces that a class hash must already be declared before a contract's class can be replaced. The Starknet OS (SNOS) — the Cairo program used to re-execute the same transactions and prove/verify the resulting state transition — implements `execute_replace_class` without this check, in both its current and deprecated syscall paths. This asymmetry lets any unprivileged contract call, reachable from a single submitted `INVOKE` transaction, trigger a state update in the OS's re-execution that the Blockifier would never have produced.

### Finding Description
In the Blockifier, `replace_class` validates the target class before mutating storage: [1](#0-0) 

This is confirmed by an existing negative test asserting that replacing with an undeclared class hash fails with `"is not declared"`: [2](#0-1) 

By contrast, the Starknet OS's Cairo implementation of the same syscall performs no such validation. In the current (non-deprecated) execution path, the missing check is explicitly acknowledged by a TODO comment, yet the code proceeds to unconditionally overwrite the contract's class hash in `contract_state_changes`: [3](#0-2) 

The same absence of a declared-class check exists in the deprecated syscall execution path used by the OS for Cairo0-era transactions: [4](#0-3) 

This is directly analogous to the `CollateralManager#commitCollateral` bug: a state-mutating operation that is reachable by an untrusted caller (any contract executing `replace_class`, invokable from any transaction sender) is missing the authorization/validation check that the "trusted" implementation (Blockifier) enforces. Just as Teller's `CollateralManager` allowed anyone to inject unauthorized collateral data because the privileged check was absent, the Starknet OS allows a contract to "commit" an unauthorized (undeclared) class hash into the state diff it computes, because the equivalent guard present in the Blockifier is missing here.

### Impact Explanation
The Starknet OS is the component whose execution is proven and (ultimately) checked against the sequencer's committed state transition. If the Blockifier rejects/reverts a `replace_class` call for an undeclared class hash while the OS silently accepts it and folds it into its own computed state diff, the two engines can produce different state roots for the exact same transaction and same block. This is a textbook **honest-node divergence**: the sequencer (source of truth for what was actually committed) and the OS re-execution (source of truth for what is proven/verified) disagree on the resulting state, specifically on `class_hash` entries in the contract state diff. Depending on how this divergence propagates, it can result in an incorrect/wrong committed root being proven, or a proof failing to match the actually-finalized block, undermining the network's ability to confirm the correctness of new blocks.

### Likelihood Explanation
The path is trivially reachable: any account can submit an `INVOKE` transaction whose contract calls the `replace_class` syscall with an arbitrary, undeclared `class_hash`. No special privileges, staking, or operator/proposer role is required — this is a standard single-transaction, single-message flow through the syscall layer that both the Blockifier and the Starknet OS must handle identically.

### Recommendation
Add the same "class must be declared" validation to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` (i.e., resolve the `TODO(Yoni, 1/1/2026)` before it can be exploited), mirroring the check already performed by the Blockifier's Rust implementation (`syscall_handler.state.get_compiled_class(request.class_hash)?`). Add a regression test in the OS/SNOS test suite (analogous to `test_replace_class` in `deprecated_syscalls_test.rs`) asserting that the OS rejects `replace_class` calls referencing undeclared class hashes, and cross-check that Blockifier and OS behavior remain consistent for this syscall.

### Proof of Concept
1. Deploy a Cairo1 contract exposing a function that invokes the `replace_class` syscall with a caller-supplied `class_hash`.
2. Submit an `INVOKE` transaction from any unprivileged account calling this function with a `class_hash` value that has never been declared (no corresponding `Declare` transaction exists in state).
3. In the Blockifier's execution, `state.get_compiled_class(request.class_hash)` fails, and the call is rejected/reverted (as demonstrated by the existing `test_replace_class` negative-flow test).
4. When the same transaction is re-executed by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`), no declared-class check exists; the OS unconditionally performs `dict_update` to set the new (undeclared) `class_hash` into `contract_state_changes`, producing a state diff/entry that the Blockifier never actually committed.

Note: I was unable to locate/verify the Rust implementation of `SyscallHandlerBase::replace_class` in `syscall_base.rs` in the indexed content (grep found no match for `pub fn replace_class` there), so I could not directly confirm whether the *current* (non-deprecated) Blockifier syscall path performs the identical declared-class check as the deprecated path. The deprecated path's check and corresponding test are confirmed directly from source. Given the current OS path explicitly documents the missing check via a TODO, and the deprecated OS path has an identical gap, the core divergence finding holds regardless of this one unverified detail. A full session with complete repository access would allow verifying `syscall_base.rs` to close this gap in the analysis.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
