## Analog Found

### Title
Unbounded recursion in `sort_json_value` over untrusted deprecated-class ABI JSON causes stack-overflow crash — ([File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs])

### Summary
The CVE describes `jq`'s `jv_object_merge_recursive()` recursing without a depth bound over attacker-controlled JSON, letting a crafted object-merge crash the process via stack overflow. The sequencer has an analogous unbounded-recursion pattern: `sort_json_value` recursively walks an entirely unconstrained `serde_json::Value` (the deprecated contract's `abi` field, which has "no schema definition") with no depth limit, and this function sits directly in the path used to compute the *hinted class hash* for every Cairo-0 (deprecated) declared class.

### Finding Description
`CairoContractDefinition::abi` is declared as `pub abi: serde_json::Value` explicitly because "Contract ABI ... has no schema definition" [1](#0-0) . `compute_cairo_hinted_class_hash` serializes the whole `ContractClass` to a `serde_json::Value` and calls `sort_json_value` on it to normalize key ordering before hashing [2](#0-1) . `sort_json_value` itself is a plain unbounded recursive traversal over `Object`/`Array` variants with no depth counter or limit: [3](#0-2) 

This is invoked from `compute_deprecated_class_hash`, the function that computes the class hash for every declared Cairo-0 class [4](#0-3) . `compute_deprecated_class_hash` is used both when the sequencer/gateway processes a `DeclareV1Transaction` carrying a `DeprecatedContractClass` (whose `abi` field is deserialized straight from the untrusted, attacker-supplied transaction with only an `Option<Vec<ContractClassAbiEntry>>`-shaped best-effort parse that falls back silently to `None` on failure — but the raw `serde_json::Value` used in `compute_cairo_hinted_class_hash` bypasses that typed parsing entirely) and inside the Starknet OS re-execution path, where every full/prover node loading `DeprecatedCompiledClassFact`s recomputes/verifies this hash for state-commitment purposes [5](#0-4) .

Because the recursion walks the raw, unvalidated `abi: serde_json::Value`, an attacker can craft a Cairo-0 declare transaction whose `abi` field is a deeply nested JSON array (e.g. `[[[[...]]]]`), which costs only 2 bytes per nesting level. The gateway's size limits (`max_contract_class_object_size` = 4,089,446 bytes, `max_contract_bytecode_size` = 81,920 bytes) bound total payload size but not nesting *depth* — a ~4MB payload can encode well over a million levels of array nesting, far exceeding any realistic stack depth, causing a stack overflow when `sort_json_value` (and the subsequent `serde_json::from_slice::<CairoContractDefinition>` deserialization, which is also inherently recursive) processes it.

### Impact Explanation
A crafted declare transaction can crash any process that computes the hinted class hash for the malicious deprecated class: the gateway node validating/admitting the declare transaction, and — more critically — any full node or prover performing Starknet OS re-execution of a block that already contains this class (since `compute_deprecated_class_hash`/`compute_cairo_hinted_class_hash` is on the OS's class-hash verification path). A stack-overflow abort in the OS re-execution path can halt block proving/re-execution for all nodes that must process that class, which maps to the "network unable to confirm new transactions" / node-crash-on-single-transaction impact class. This matches the CVSS profile of the source CVE (availability-only impact via unbounded recursion crash) but is reachable purely from an unprivileged declare transaction, not from a malicious operator/peer.

### Likelihood Explanation
The primitive is directly reachable by any account able to submit a `DECLARE` (v1/v2, Cairo-0) transaction — no special privileges required. The `abi` field's lack of a schema, combined with the absence of a depth check in `sort_json_value` (and in the generic `serde_json` recursive deserialization/serialization it feeds), makes constructing a triggering payload straightforward and cheap relative to the declared object-size limits.

### Recommendation
Add an explicit recursion/nesting-depth limit before or during `sort_json_value` traversal (and reject the class if the `abi` JSON exceeds it), or convert the recursive traversal into an iterative, explicit-stack algorithm bounded to a safe maximum depth. Apply the same depth bound to any other unconstrained `serde_json::Value` fields reachable from untrusted deprecated contract classes (e.g., `program.attributes`, `identifiers`, `reference_manager`) before they are parsed/serialized in class-hash computation.

### Proof of Concept
1. Construct a `DeclareV1Transaction`/`DeprecatedContractClass` whose `abi` JSON value is deeply nested arrays, e.g. `[[[[ ... ]]]]` nested ~10^6 times, staying under `max_contract_class_object_size`.
2. Submit the declare transaction to the gateway; `compute_cairo_hinted_class_hash` → `sort_json_value` recurses once per nesting level on the thread's call stack.
3. The recursion depth exceeds the thread stack size, causing a stack overflow and process abort — reproducing the crash mechanism analogous to jq's `jv_object_merge_recursive` unbounded recursion, but on any node that later re-executes/hashes the same declared class (including Starknet OS re-execution of the containing block).

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}
