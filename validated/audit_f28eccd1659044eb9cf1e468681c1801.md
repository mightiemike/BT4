Confirmed: the blockifier's `replace_class` syscall (used during actual sequencer execution) enforces that the target class is declared and is a Cairo1 class before mutating state [1](#0-0) , and the deprecated syscall handler similarly requires the class to be declared by reading it before writing the new class hash [2](#0-1) . However, the Starknet OS's own re-execution implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`) explicitly skips this check, marked by an open TODO, and unconditionally writes the new `class_hash` into the contract's state entry without ever verifying the class was declared [3](#0-2) . The same missing check exists in the deprecated Cairo0 OS path [4](#0-3) .

### Title
Starknet OS `execute_replace_class` omits the declared-class check enforced by the sequencer's blockifier, allowing OS re-execution to diverge from committed sequencer state - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
This is an inconsistency between two implementations of the same state-transition rule, analogous to the Arbitrum `replaceCohort` bug: one code path (blockifier) enforces a validation invariant while the other (the Starknet OS, which is supposed to re-execute and independently verify the same transactions) does not, so the two can disagree on the resulting state after processing the identical transaction.

### Finding Description
The Cairo1 `ReplaceClass` syscall lets a contract change its own class hash. In the sequencer's blockifier, this is only permitted if the target `class_hash` is actually declared — enforced by calling `self.state.get_compiled_class(class_hash)?` before writing the new class hash [1](#0-0) . The deprecated (Cairo0) syscall path performs the same check [2](#0-1) .

In the Starknet OS program, which independently re-executes every transaction to compute/verify the block's state diff and commitments, the equivalent `execute_replace_class` function has a comment stating the check is not yet implemented: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` It then unconditionally builds a `new_state_entry` with the requested `class_hash` and writes it into `contract_state_changes` via `dict_update`, with no read/verification of the class declaration [5](#0-4) . The deprecated Cairo0 OS `execute_replace_class` has the identical gap [6](#0-5) .

This mirrors the structural pattern in the referenced report: one code path (`replaceCohort`) performs a state-mutating "replace" operation without the validation that a companion process in the same system logically requires, producing an inconsistent/divergent result. Here, the "companion process" is the OS re-execution, and the missing validation is the declared-class check.

### Impact Explanation
If a transaction calls `replace_class` with an undeclared class hash, the blockifier used for building the block will reject the transaction (via `SyscallExecutionError`), so such a transaction/class-hash combination should never appear in a committed block under normal sequencer operation. However, because the OS lacks the equivalent guard, any code path in the OS that reaches `execute_replace_class` independently of the same declared-class precondition being enforced elsewhere in the OS could accept a state entry with an undeclared/invalid class hash, producing a state diff/commitment that does not match what a spec-conformant execution should produce. This is a root-cause soundness gap in Starknet OS re-execution: the prover's/OS's local view of correctness for this syscall is weaker than the sequencer's, undermining the guarantee that OS execution independently verifies the sequencer-produced state diff — a wrong committed root / honest-node divergence class of impact if any input reaches this function without the check having been performed upstream.

### Likelihood Explanation
Exploitability depends on whether some other part of the OS pipeline (e.g. a separate class-declared assertion during block-level state diff application, or Cairo1's `syscall_base.rs`-equivalent logic reused by the OS) already guarantees the class is declared before this function runs. This could not be fully confirmed from the indexed code: the OS's `execute_replace_class` is the only OS-side implementation found, and no external validation call was found immediately preceding it in the traced call path (`execute_syscalls` in `execute_syscalls.cairo` dispatches directly to `execute_replace_class` with no additional check) [7](#0-6) . Because the check is explicitly called out as a TODO rather than implemented elsewhere, likelihood should be treated as credible pending confirmation, but the precise reachability of an "undeclared class" state at this point in the OS trace could not be fully verified with the available index.

### Recommendation
Add the same declared-class (and Cairo1-type, matching blockifier's `is_cairo1` check) validation to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring `crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class`, before performing the `dict_update` on `contract_state_changes`. This should read/verify the compiled class for `class_hash` and reject the syscall (consistent with how the blockifier reverts the transaction) if the class is undeclared.

### Proof of Concept
Not independently reproducible from the indexed code alone — the finding is a static code-path comparison between `crates/blockifier/src/execution/syscalls/syscall_base.rs` (`replace_class`, lines 369–378) and `crates/apollo_starknet_os_program/.../syscall_impls.cairo` (`execute_replace_class`, lines 881–920), where the explicit `TODO` comment at line 902 documents the missing check acknowledged by the codebase authors themselves.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
