### Title
Uncaught `TypeError` in `sanitizeHost` on crafted base64 host causing authentication-handler crash (DoS) - (File: packages/apps/shopify-api/lib/utils/shop-validator.ts)

### Summary
`sanitizeHost` validates only that the raw parameter is syntactically valid base64, then blindly decodes it and passes the decoded string into `new URL()` without a try/catch. Since arbitrary bytes (including spaces, control characters, or invalid host code points) can be represented in valid base64, an attacker can craft a `host` value whose decoded form causes the WHATWG URL parser to throw, and that exception propagates uncaught out of `sanitizeHost` into callers such as `validateShopAndHostParams`.

### Finding Description
`sanitizeHost` first checks the incoming string against `base64regex = /^[0-9a-zA-Z+/]+={0,2}$/` [1](#0-0) . This regex only constrains the *encoded* characters, not the decoded content — base64 can encode any arbitrary byte sequence, including spaces, control characters (e.g. `\x00`), or Unicode code points, using only the `[0-9a-zA-Z+/=]` alphabet.

After passing that check, the code immediately does:
```ts
const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);
```
with `decodeHost` being a thin wrapper around `atob` [2](#0-1) . There is no try/catch around this `new URL(...)` call. The WHATWG URL parser rejects "forbidden host code points" (space, control characters, `#`, `%` in certain contexts, etc.) inside the authority component and throws `TypeError: Invalid URL` for such input.

Callers of `sanitizeHost`, e.g. `validateShopAndHostParams` in both the Remix and React Router adapters, call it directly without any surrounding try/catch: `const host = api.utils.sanitizeHost(url.searchParams.get('host')!);` [3](#0-2) [4](#0-3) . This function runs on every embedded-app authentication request, so a thrown `TypeError` here is not caught anywhere in the call chain shown, and will surface as an unhandled exception in the request handler.

The existing test suite for `sanitizeHost` only exercises: non-base64 strings, base64 of valid/invalid hostnames, and tampered base64 suffixes — none of the `INVALID_HOSTS` fixtures decode to a string with forbidden host code points [5](#0-4) , so this uncaught-throw path is untested and unguarded.

### Impact Explanation
An unauthenticated attacker can send a single crafted request with `?host=<base64>` where the base64 decodes to something like `evil host.myshopify.com` (contains a space) or `\x00.myshopify.com` (contains a null byte). This causes `new URL()` to throw inside `sanitizeHost`, and because no caller wraps this in a try/catch, the exception propagates and crashes/500s the request-authentication handler. This is a low-cost, repeatable denial-of-service against the authentication entry point of any embedded app using this library's default `validateShopAndHostParams` flow.

### Likelihood Explanation
Preconditions are minimal: default configuration, an embedded app, and any request reaching `validateShopAndHostParams` (a step in the normal `authenticate.admin()` flow). No secrets, privileges, or non-default configuration are required — only crafting a base64 string, which is trivial for any anonymous client. The attack is fully repeatable per request.

### Recommendation
Wrap the `new URL(...)` call in `sanitizeHost` in a try/catch, treating a parse failure the same as an invalid host (set `sanitizedHost = null`), so malformed decoded content never throws out of the function:
```ts
let sanitizedHost = base64regex.test(host) ? host : null;
if (sanitizedHost) {
  try {
    const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);
    ...
  } catch {
    sanitizedHost = null;
  }
}
```

### Proof of Concept
```ts
import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('sanitizeHost does not throw for base64 decoding to invalid URL authority', () => {
  const shopify = shopifyApi(testConfig());

  const maliciousHost = Buffer.from('evil host.myshopify.com').toString('base64');

  expect(() => shopify.utils.sanitizeHost(maliciousHost)).not.toThrow();
  expect(shopify.utils.sanitizeHost(maliciousHost)).toBeNull();
});
```
Running this against the current implementation throws `TypeError: Invalid URL` from inside `sanitizeHost` instead of returning `null`, confirming the uncaught-exception DoS path.
