### Title
Starknet OS `execute_replace_class` accepts an undeclared/incompatible class hash without validation, causing OS re-execution to diverge from the blockifier's committed state - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The bug class in the external report is: a privileged/state-changing operation (`mobile_open_url` → arbitrary Android intent) is executed on unsanitized, attacker/user-controlled input because the validation step (scheme check) was omitted. The direct analog in this sequencer is the `replace_class` syscall implementation inside the Starknet OS Cairo program, which omits the "class is declared" validation that the equivalent Rust blockifier syscall enforces, before mutating committed contract state.

### Finding Description
In the Rust execution engine (blockifier), `replace_class` explicitly validates that the target `class_hash` is declared and of a compatible Cairo version before mutating storage: [1](#0-0) 
This is exercised and enforced by tests that confirm an undeclared class hash is rejected with "is not declared": [2](#0-1) 

However, the Starknet OS's own Cairo re-implementation of the same syscall (`execute_replace_class`, used during OS re-execution/proving to independently recompute the state transition for a block) explicitly skips this check, with a TODO acknowledging the gap: [3](#0-2) 

Specifically, at line 902 the code comments: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` — and then unconditionally writes the requested `class_hash` into `contract_state_changes` for the calling contract, with no check that the class was ever declared, and no check on Cairo0/Cairo1 compatibility (which the blockifier separately enforces via `is_cairo1`/"Cannot replace V1 class hash with V0 class hash").

The deprecated (Cairo0) syscall path in the OS has the identical gap: [4](#0-3) 

### Impact Explanation
The Starknet OS is the trusted re-execution/proving component that independently recomputes each block's state diff and commits it to the state Patricia trees, ultimately producing the block's committed state root that is proven and posted. Because the OS's `execute_replace_class` accepts any `class_hash` value supplied by a `replace_class` syscall inside a transaction (a contract call any unprivileged transaction sender can trigger from any deployed contract that calls `replace_class`) without verifying it corresponds to a declared class, the OS can commit a `StateEntry` whose `class_hash` is an undeclared, garbage, or version-incompatible value. This causes:
- Divergence between the state root computed by the OS (used for the proven/committed state) and the state actually computed and validated by the blockifier during block execution (which would have rejected the syscall with "is not declared"/"Cannot replace V1 class hash with V0 class hash").
- A wrong committed state root / class-hash-at-address entry can be produced and hashed into the global state commitment, since the contract-class trie / state commitment logic trusts whatever `class_hash` value is present in `contract_state_changes` (see `commitment.cairo`, which computes `get_contract_state_hash` directly from `state_entry.class_hash`).
- This constitutes an honest-node divergence / wrong committed root class of bug, since two components meant to agree on the same state transition (blockifier vs. OS) apply different validation rules for the same syscall, on a path reachable purely by an unprivileged transaction sender invoking `replace_class` from any contract they control.

### Likelihood Explanation
The `replace_class` syscall is reachable directly from a Cairo1/Cairo0 contract's regular `__execute__` entry point via `replace_class_syscall` — no special privileges are required beyond deploying/controlling a contract and issuing an `INVOKE`/account transaction that calls it (as shown in `test_contract.cairo`'s `test_replace_class`). Triggering the OS's un-guarded code path only requires that the transaction reach OS re-execution, which happens for every block. The condition is trivially reachable by any unprivileged sender.

### Recommendation
Add the same declared-class and version-compatibility checks in the Starknet OS `execute_replace_class` (and the deprecated syscall variant) that the blockifier's `syscall_base::replace_class` performs: read/verify the compiled class for `request.class_hash` exists in the contract-class state before writing the new `StateEntry`, and reject/mirror the "Cannot replace V1 class hash with V0 class hash" behavior, so that the OS's state transition matches the blockifier's validated behavior exactly.

### Proof of Concept
1. Declare and deploy a Cairo1 account/contract `A`.
2. From `A`, issue an INVOKE transaction that calls `replace_class_syscall(class_hash=X)` where `X` is an arbitrary undeclared felt (as in `crates/blockifier_test_utils/resources/feature_contracts/cairo1/cairo_steps_test_contract.cairo:201-203`'s `test_replace_class`).
3. In blockifier-based execution, this transaction reverts/fails with "is not declared" (per `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
4. During Starknet OS re-execution of the same block/transaction, `execute_replace_class` in `syscall_impls.cairo:881-920` performs no such check and unconditionally commits `class_hash=X` into `contract_state_changes` for contract `A`, producing a state entry/root inconsistent with what the blockifier computed — a concrete divergence in the committed state root for the same transaction.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
