### Title
Excess Outbound Gas Fee Permanently Stuck When `applyGasRefund` Fallback Fails - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
Push Chain's cross-chain outbound flow escrows a `GasFee` amount for every outbound (funds/gas-and-payload) transaction. When Universal Validators vote that the outbound was observed, `FinalizeOutbound` computes the unused portion (`gasFee - gasFeeUsed`) and attempts to refund it via `applyGasRefund`. If both the swap-refund and the no-swap fallback EVM calls fail, the excess amount is never returned to the user and there is no retry or sweep mechanism — the outbound is finalized in a terminal status with only an error string recorded. This mirrors the external report's "excess value collected but never refunded" bug class, but here the corrupted state is the on-chain `OutboundTx` gas-refund accounting rather than raw ETH.

### Finding Description
`applyGasRefund` in [1](#0-0)  computes `refundAmount = gasFee - gasFeeUsed` once `gasFee > gasFeeUsed`, and attempts:
1. A swap-based refund via `CallUniversalCoreRefundUnusedGas(..., withSwap=true, ...)`.
2. On failure, a fallback no-swap refund via `CallUniversalCoreRefundUnusedGas(..., withSwap=false, ...)`.

If **both** calls return an error, the function sets `refundPcTx.Status = "FAILED"`, records `outbound.RefundSwapError`, and returns without raising an error to its caller: [2](#0-1) 

The caller (`handleSuccessfulOutbound` / `handleFailedOutbound`) then unconditionally calls `k.UpdateOutbound(ctx, utxId, outbound)`, finalizing the outbound's status (`OBSERVED` or `REVERTED`) regardless of whether the refund succeeded: [3](#0-2) 

Because `FinalizeOutbound` only runs once per outbound (triggered from the vote-threshold path removing the entry from `PendingOutbounds`), and no code path in `x/uexecutor/keeper` re-invokes `applyGasRefund` or offers a governance/manual retry for a `RefundSwapError`/`FAILED` `PcRefundExecution`, the excess gas amount that was already escrowed on-chain (deducted from the user's PRC20/gas-token balance when the outbound was created) has no further path back to the user. The only trace left is an error string on an already-finalized `OutboundTx`.

This is directly analogous to the external report's `PythAggregator.updatePrice`: value is collected from the user up front (fee/gasFee), only part of it is legitimately consumed (Pyth's actual fee / actual `gasFeeUsed`), and the leftover portion has a refund code path that can silently fail to return funds, permanently trapping them in protocol-controlled contracts (the `UniversalCore`/`VaultPC` handler) with no user-facing mechanism to recover them.

### Impact Explanation
Falls under the "unauthorized... permanent loss... of user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting ... canonical UniversalTx state" allowed impacts. The excess gas fee a user pre-paid for an outbound is permanently lost/stuck once both refund legs fail, with the loss being silently recorded rather than surfaced for recovery, and no privileged actor is required to trigger the loss — it is a byproduct of ordinary honest-validator finalization of a normal user cross-chain transaction under transient failure conditions of the swap/no-swap refund calls (e.g., slippage/quote staleness for the swap leg, or any transient EVM revert on the `UniversalCore.refundUnusedGas` no-swap leg).

### Likelihood Explanation
Moderate/uncertain. The swap-refund leg can plausibly fail under normal market movement (5% slippage tolerance computed from `GetSwapQuote`, `outbound.go:213-234`), which is a believable unprivileged trigger. However, triggering failure of the **no-swap fallback** as well requires an additional, less common condition (e.g., `UniversalCore` contract-side revert unrelated to price) that I could not fully verify from the indexed code — the `UniversalCore.sol` / `refundUnusedGas` Solidity implementation itself is out of the Go repo's index, so I cannot confirm all conditions under which the fallback can revert. This uncertainty should be resolved by inspecting the `refundUnusedGas` implementation in the EVM contracts (likely in a separate `push-chain-node` contracts repo) before treating this as a high-confidence, easily-repeatable bug.

### Recommendation
Add a durable, retryable "pending refund" record (or an admin/permissionless sweep message) keyed by outbound ID when both refund legs fail in `applyGasRefund`, instead of only setting a terminal `FAILED` status and moving on. At minimum, do not finalize the outbound into `OBSERVED`/`REVERTED` while `PcRefundExecution.Status == "FAILED"` without an explicit, monitored recovery path (similar to how `AbortOutbound` is used for failed re-mints in `handleFailedOutbound`), so stuck excess gas fees can be identified and returned rather than silently absorbed.

### Proof of Concept
Conceptual (Go-level) scenario based on existing test scaffolding in `test/integration/uexecutor/gas_fee_refund_test.go`:
1. A `GAS_AND_PAYLOAD`/`FUNDS` outbound is created with `GasFee = 1000` (escrowed from the user's PRC20 balance).
2. Universal Validators vote via `MsgVoteOutbound` with `gasFeeUsed = 100`, well below `gasFee`, so `refundAmount = 900` should be returned (`outbound.go:194-198`).
3. Simulate/force both `CallUniversalCoreRefundUnusedGas(..., withSwap=true, ...)` and `CallUniversalCoreRefundUnusedGas(..., withSwap=false, ...)` to return errors (e.g., mock `EVMKeeper.DerivedEVMCall` to fail for the `refundUnusedGas` method, as is already stubbed in `x/uexecutor/mocks/mock_evmkeeper.go`).
4. Observe that `FinalizeOutbound` still completes, `outbound.OutboundStatus` becomes `OBSERVED`, `outbound.PcRefundExecution.Status == "FAILED"`, and `outbound.RefundSwapError` is non-empty — with no subsequent code path that revisits or retries this refund.

Full confirmation that the no-swap fallback can independently fail under attacker-unprivileged conditions requires reviewing the Solidity `UniversalCore.refundUnusedGas` implementation, which is outside this repository's indexed scope.

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
