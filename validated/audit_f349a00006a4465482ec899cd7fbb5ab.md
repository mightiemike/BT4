## Title
Signer set weight underflow strands the entire reward-cycle signer set - ([File: stackslib/src/chainstate/stacks/boot/mod.rs])

## Summary
`StacksChainState::make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs` derives each signer's voting `weight` via a plain floor division (`stacked_amt / threshold`) and drops any signer whose weight floors to `0`, with no fallback or "leftover" redistribution. [1](#0-0)  This is structurally the same bug class as the reported subtensor issue: a fixed-point gate (`stacked_amt / threshold`) can drive every participant's share to zero, and nothing restores an ungated/fallback distribution.

## Finding Description
`make_signer_set` builds the Nakamoto signer set for a reward cycle from PoX stacking entries. It aggregates `amount_stacked` per signing key, then for every aggregated signer computes:
```
let weight = u32::try_from(stacked_amt / threshold).expect(...)
if weight == 0 { return None; }
``` [1](#0-0) 
If many distinct signers each stack an amount just under `threshold` (which is fixed per cycle as `total_ustx / reward_slots`, i.e., a fixed-point "share" gate), *every* signer's `stacked_amt / threshold` floors to `0`. There is no floor/remainder ("largest remainder") correction here, unlike the sibling PoX-5 implementation `pox_5_make_signer_set` in `stackslib/src/chainstate/nakamoto/signer_set.rs`, which explicitly documents and fixes this exact degenerate mode: "when more than `reward_slots` distinct signers hold roughly equal stake, every base weight floors to 0, and without the leftover round the entire signer set could be dropped" and hands out leftover slots by largest remainder to guarantee `weight >= 1` for anyone who should get one. [2](#0-1) 

`make_signer_set` in `boot/mod.rs`, by contrast, has no such leftover-round protection: if the filtering yields no `Some(...)` entries at all, this function returns `Some(vec![])` (an empty, non-`None` signer set), since only the "empty input" case returns `None`. [3](#0-2) 

The equality this breaks is the reward-set invariant that *every locked/staked participant with a valid stacking entry contributes non-zero weight to the signer set that governs block approval*. If all weights floor to zero, the signer set used for `NakamotoBlockHeader::compute_voting_weight_threshold`/`verify_signer_signatures` becomes empty or degenerate, even though real STX was locked by real, unprivileged stackers — a minority-triggerable condition since any set of unprivileged users choosing stacking amounts near-equally can produce this outcome without needing a majority of stake.

## Impact Explanation
If the derived signer set ends up empty (or with drastically fewer effective weight units than intended), the total signing weight computed by `reward_set.total_signing_weight()` and used in `NakamotoBlockHeader::verify_signer_signatures`/`compute_voting_weight_threshold` no longer reflects real stacked capital. [4](#0-3)  This can strand block production for the reward cycle (no legitimate signer combination can satisfy the threshold, or worse, a degenerate near-zero total weight trivializes the threshold), producing a minority-triggerable divergence in whether blocks are validly signed — analogous to the subtensor bug where a fixed-point gate collapsed to zero and stranded emission for an entire subnet epoch. This maps to the "High" tier: a minority-triggerable, unprivileged, static reward-set computation divergence that can cause temporary tip disagreement or halted tenure progress bound to one reward cycle.

## Likelihood Explanation
Triggering requires only that unprivileged stackers choose stacking amounts that are roughly equal and below the per-slot `threshold` for that cycle — no majority stake or privileged role is required, only enough participants relative to `reward_slots`. This is plausible in low-participation or fragmented-stacking cycles.

## Recommendation
Apply the same largest-remainder / leftover-slot correction used in `pox_5_make_signer_set` to `make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs`: compute base weights via floor division, then distribute any leftover reward slots (`reward_slots - sum(base_weights)`) one-per-signer in descending remainder order so that no eligible signer set can collapse to all-zero weights when real stake was locked.

## Proof of Concept
Not independently verified by execution — this assessment is based on static code comparison between `make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1073`) and its sibling `pox_5_make_signer_set` (`stackslib/src/chainstate/nakamoto/signer_set.rs:822-891`), which explicitly documents and remediates the identical degenerate floor-to-zero mode. I was unable to fully trace, within the given tool budget, which exact PoX version(s)/epochs invoke `make_signer_set` versus `pox_5_make_signer_set` at runtime (the last `grep_search`/`read_file` calls to confirm call sites and epoch-gating did not complete before the iteration limit), so it is uncertain whether `make_signer_set`'s path is still reachable in the current mainnet-active PoX version or has been fully superseded by the PoX-5 code path. This should be confirmed before treating the finding as exploitable in production.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

    #[cfg_attr(test, mutants::skip)]
    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
