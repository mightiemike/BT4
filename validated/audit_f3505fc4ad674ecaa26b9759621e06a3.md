### Title
Starknet OS `execute_replace_class` omits declared-class validation performed by the Blockifier, enabling honest-node state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `ReplaceClass` syscall is validated inconsistently between the two execution engines that must produce identical state transitions for the same block: the Blockifier (used by the sequencer to build the block) and the Starknet OS Cairo program (used to re-execute and prove/verify the block). The Blockifier rejects `replace_class` when the target `class_hash` is undeclared or not Cairo1, but the OS's `execute_replace_class` performs no such check and unconditionally rewrites the contract's `class_hash` in `contract_state_changes`.

### Finding Description
The Wintermute report is a hint that address/code-binding invariants (which contract code backs a given address) can be exploited if one execution path enforces the binding and another does not. The Starknet OS analog is the class-hash rebinding performed by `replace_class`.

In the Blockifier, `SyscallHandlerBase::replace_class` explicitly validates the class before rebinding the contract's class hash: [1](#0-0) 

This mirrors the deprecated syscall handler, which also reads the compiled class to force a "declared" check before mutating state: [2](#0-1) 

Test coverage confirms the Blockifier reverts the call when the class hash is undeclared ("is not declared") or is a V0/Cairo0 class ("Cannot replace V1 class hash with V0 class hash"): [3](#0-2) 

However, the Starknet OS Cairo implementation of the same syscall, `execute_replace_class`, contains an explicit unresolved TODO acknowledging the missing check, and directly writes the new `class_hash` into `contract_state_changes` with no validation that the class was declared: [4](#0-3) 

The deprecated OS syscall path has the identical gap: [5](#0-4) 

Because the Starknet OS re-executes the same transactions that the Blockifier already executed when producing the block (see the "Starknet OS re-execution" trust boundary), the two paths are supposed to compute identical `CallInfo`/state-diff results for every transaction. Here they do not: for a `replace_class` call targeting an undeclared (or Cairo0) class hash, the Blockifier reverts the call (no class-hash state change, and revert reason recorded), while the OS silently accepts it and writes the state change plus a `RevertLogEntry` as if it succeeded.

### Impact Explanation
This is a correctness/soundness divergence in the exact re-execution path the OS uses to independently derive the state diff and commit the block: any account contract can trigger `replace_class` with a `class_hash` for a class that is not declared on-chain (a single felt controlled entirely by the calling contract/transaction). If Blockifier and Starknet OS disagree on whether this call reverts:
- The state commitment (Patricia tree root) computed via OS re-execution will not match the state actually produced by the Blockifier-driven sequencer, i.e., "wrong committed root" / honest-node divergence, one of the explicitly accepted impact categories.
- A contract's class hash could be set, via OS-side computation, to a class hash that was never declared — meaning subsequent calls to that contract cannot find its compiled class, which is a form of contract bricking/permanent freezing of the affected contract's functionality if the OS-produced diff were ever treated as authoritative, or a divergence that a block/proof-verifying node would flag if it independently checks the OS output against sequencer output.

### Likelihood Explanation
The transaction path to reach `replace_class` requires nothing more than deploying/using any Cairo1 account or contract that invokes the `ReplaceClass` syscall with an attacker-chosen `class_hash` argument — this is directly reachable by any unprivileged transaction sender. No special permissions, mempool/p2p access, or operator/prover privileges are required, satisfying the "reachable from a single submitted transaction" bar.

### Recommendation
Add the same "declared class" (and "Cairo1-only") validation in the Starknet OS's `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that exists in the Blockifier's `SyscallHandlerBase::replace_class`, before performing the `dict_update` on `contract_state_changes`. Resolve the `TODO(Yoni, 1/1/2026)` by reading/verifying the compiled class for `class_hash` (mirroring `get_compiled_class` behavior) and reverting/failing the syscall consistently with the Blockifier when the class is undeclared or of the wrong Cairo version, ensuring bit-for-bit parity between the two execution engines for this syscall.

### Proof of Concept
1. Deploy any Cairo1 contract exposing a function that calls `replace_class_syscall(class_hash)` (e.g., the `test_replace_class` pattern used in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`), passing an arbitrary/undeclared `class_hash` felt, e.g. `felt!(1234_u16)`.
2. Submit this as a normal invoke transaction. The Blockifier-based sequencer execution reverts the inner call (`"is not declared"`), leaving the contract's class hash unchanged, per [6](#0-5) .
3. Feed the same transaction trace through the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`): because no declared-class check exists there, the OS performs `dict_update` unconditionally, setting `contract_state_changes[contract_address].class_hash = 1234` and logging a `CHANGE_CLASS_ENTRY`, per [7](#0-6) .
4. Compare the resulting state diffs/committed roots from the two engines for the same block — they diverge on this contract's class hash, demonstrating the honest-node/root divergence.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
