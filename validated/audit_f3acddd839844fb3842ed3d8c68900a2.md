### Title
Open Redirect via unauthenticated `exitIframe` parameter bypassing origin check in `sanitizeRedirectUrl` - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
The `sanitizeRedirectUrl` helper used to validate destinations for the App Bridge "exit iframe" redirect only checks that the target is not a `file://` URI, contains no whitespace, has no double-slash in its `pathname`, and uses `http`/`https`. It never verifies that the resulting URL's **origin** matches the app's own `domain` (`config.appUrl`). Because an attacker-supplied, fully-qualified `https://` URL is accepted as-is by `new URL(redirectUrl, domain)`, the `domain` argument is effectively ignored whenever the attacker provides an absolute URL, allowing an open redirect to any external host.

### Finding Description
`isSafe()` in `validate-redirect-url.ts` performs these checks on a candidate `redirectUrl`: [1](#0-0) 

Note that `url.pathname` (not the full URL/origin) is what's checked against `INVALID_RELATIVE_URL`, and no comparison is ever made between `url.origin`/`url.hostname` and the trusted `domain` argument. If `redirectUrl` is already an absolute URL such as `https://evil.example.com/`, `new URL(redirectUrl, domain)` resolves to `https://evil.example.com/` regardless of `domain`, and all checks pass (valid protocol, no whitespace, no `///`, single-slash pathname `/`).

This function is reached directly from an **unauthenticated** request: `respondToExitIframeRequest` in `authenticate.ts` reads the `exitIframe` query parameter straight off the incoming request URL and passes it to `renderAppBridge`, which calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)`: [2](#0-1) [3](#0-2) 

This check runs before `validateShopAndHostParams`, before session-token validation, and before any OAuth flow — i.e., it is reachable by any anonymous visitor to `{appUrl}{config.auth.exitIframePath}` with no shop/session context required.

The identical implementation exists in the React Router adapter as well: [4](#0-3) 

This mirrors the report's bug class: a URL/path filter that is easy to satisfy without actually restricting the target to the intended trusted domain, letting an attacker's fully controlled input pass through the "sanitizer" unmodified.

### Impact Explanation
An attacker can craft a link `{appUrl}/auth/exit-iframe?exitIframe=https://attacker.example/phish&shop=<any>` that, when visited (e.g. from within the Shopify Admin iframe or directly), causes the app to render a page executing `window.open("https://attacker.example/phish/", "_top")`. Because this occurs at the top-level (breaking out of the iframe), it can be used for phishing merchants who believe they're being redirected within a legitimate Shopify app flow (e.g. fake OAuth/login pages), token/credential harvesting, or malware delivery — a classic open-redirect abuse chain in an OAuth-adjacent handler.

### Likelihood Explanation
High. The endpoint is unauthenticated by design (it exists specifically to break out of the iframe before authentication completes), requires no session token, no valid shop, and no prior state. The exploit is a single crafted URL.

### Recommendation
In `isSafe()`, in addition to the existing checks, validate that `url.origin` matches the trusted `domain`'s origin (`new URL(domain).origin`) unless the URL is a Shopify-internal relative path handled elsewhere (e.g. `shopify:admin` remote paths, handled separately by `isAdminRemotePath`). Reject absolute URLs whose origin differs from the configured app URL (and from any explicitly-allowed Shopify domains, if intentional).

### Proof of Concept
1. Configure/run any shopify-app-remix (or shopify-app-react-router) app with `appUrl = https://myapp.example.com` and default `auth.exitIframePath` (`/auth/exit-iframe`).
2. As an unauthenticated user, request:
   `GET https://myapp.example.com/auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example%2Fphish&shop=any-shop.myshopify.com`
3. Observe the HTML response contains `<script>window.open("https://attacker.example/phish/", "_top")</script>`, confirming `sanitizeRedirectUrl` accepted the fully external URL and produced an open redirect, as shown by `isSafe`'s lack of origin validation: [5](#0-4)

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}

export function sanitizeRedirectUrl<OptionsArg extends Options>(
  domain: string,
  redirectUrl: unknown,
  options: OptionsArg = {} as OptionsArg,
): SanitizedRedirectUrl<OptionsArg> {
  if (isSafe(domain, redirectUrl, options.requireSSL)) {
    return new URL(redirectUrl, domain) as SanitizedRedirectUrl<OptionsArg>;
  } else if (options.throwOnInvalid === false) {
    return undefined as SanitizedRedirectUrl<OptionsArg>;
  } else {
    throw new ShopifyError('Invalid URL. Refusing to redirect');
  }
}
