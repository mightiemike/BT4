## Analysis: Native Analog Found

The ORDH-1 pattern — "validate the expensive resource affordability at request time, not at execution time" — has a direct analog in Push Chain's gasless `MsgExecutePayload` flow.

### Title
Unbounded, Fee-Exempt `MsgExecutePayload` Execution Lets an Unprivileged Attacker Force Free, Repeated EVM Compute on Every Validating Node - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`MsgExecutePayload` is whitelisted as a **gasless** Cosmos message [1](#0-0) , meaning the Cosmos `DeductFeeDecorator` and `MinGasPriceDecorator` never charge the submitter [2](#0-1) , and `AccountInitDecorator` lets a brand-new, never-funded account submit it for free by short-circuiting the rest of the ante chain [3](#0-2) . The handler (`Keeper.ExecutePayload`) resolves the target UEA, then immediately runs the full EVM call with the attacker-supplied `GasLimit` via `CallUEAExecutePayload`/`DerivedEVMCall`, and only *afterward* checks whether the UEA can actually pay for the gas via `DeductGasFeesFromReceipt` [4](#0-3) .

### Finding Description
Like the GMX order flow (where `executionFee` was validated only when the keeper attempted execution instead of at order creation), Push Chain validates only the *shape* of the payload up front (`NewAbiUniversalPayload`, hex-decode of `verificationData`) [5](#0-4) , and defers the actual affordability/fee check to *after* the costly EVM call has already run:
- `CallUEAExecutePayload` performs a real `DerivedEVMCall` with `gasLimit` parsed directly from the attacker-controlled `universal_payload.GasLimit` string (no documented upper bound beyond "must parse as an integer") [6](#0-5) .
- The chain module **deliberately does not require `Signer == EVM(Owner)`** for `MsgExecutePayload` — "Any account may submit the message" against **any** `UniversalAccountId`, including a UEA the attacker does not own and does not fund [7](#0-6) .
- The only pre-execution balance gate exists solely for the auto-deploy branch of an *undeployed* UEA [8](#0-7) ; for any already-deployed UEA (the common case), there is no balance/affordability check before `CallUEAExecutePayload` executes.
- Fee affordability is only checked in Step 4, via `DeductGasFeesFromReceipt`, strictly after the EVM call has already consumed real compute on every validating node [9](#0-8) .

Because the message is gasless end-to-end and new signer accounts can be minted for free by the ante pipeline, an unprivileged attacker can submit an unbounded stream of `MsgExecutePayload` transactions — each carrying a large `GasLimit`, arbitrary `Data`, and a bogus `VerificationData` — targeting arbitrary deployed UEAs. Every node must execute the full `executeUniversalTx` EVM call (decode payload, run any `To`-contract logic up to the point of signature-check revert, or run to completion if the target happens to be self-authorizing) before the transaction fails, at zero cost to the attacker.

### Impact Explanation
This is a compute/gas-griefing analog to ORDH-1: the network (validators/proposers, i.e. the "keeper" role here) is forced to repeatedly perform real, potentially expensive EVM execution triggered by an attacker who pays nothing — no Cosmos tx fee (gasless whitelist) and no requirement to fund or own the target UEA. This can degrade block production throughput and crowd out legitimate inbound/outbound/vote traffic that shares the same gasless message-processing path, without requiring any privileged actor.

### Likelihood Explanation
High reachability: `MsgExecutePayload` is explicitly open to "any" signer [10](#0-9) , requires no bonded status, no minimum balance (via `AccountInitDecorator`), and no fee. An attacker only needs to generate arbitrary keys and target arbitrary/known deployed UEA addresses (which are deterministic and publicly derivable via the factory).

### Recommendation
Perform affordability/authorization gating **before** dispatching the EVM call, analogous to the GMX fix of validating `executionFee` at order creation:
- Require a minimum-balance or explicit-affordability check on the target UEA (based on declared `GasLimit`/`MaxFeePerGas`) before invoking `CallUEAExecutePayload`, for both deployed and non-deployed UEAs.
- Cap `UniversalPayload.GasLimit` to a sane protocol-defined maximum.
- Consider rate-limiting or requiring a nominal bond/fee from the `Signer` for `MsgExecutePayload` attempts that fail signature verification, so failed/griefing attempts are not entirely free even though successful executions remain gasless to the owner.

### Proof of Concept
1. Attacker generates a new, unfunded Cosmos keypair `S` (free).
2. Attacker picks any deployed `UniversalAccountId` (`owner` derivable from any public UEA), or a UEA with insufficient upc balance to pay gas.
3. Attacker submits `MsgExecutePayload{Signer: S, UniversalAccountId: victimUEA, UniversalPayload: {GasLimit: <large>, Data: <arbitrary>}, VerificationData: <garbage>}` wrapped so it is the sole message in the tx (keeps it gasless per `IsGaslessTx`).
4. `AccountInitDecorator` creates `S` on the fly and lets the tx through the ante chain without any fee [11](#0-10) .
5. `msgServer.ExecutePayload` → `Keeper.ExecutePayload` resolves `victimUEA` (already deployed) and calls `CallUEAExecutePayload` with the attacker's `GasLimit`, executing real EVM work on every node before the UEA contract reverts on signature verification [9](#0-8) .
6. Repeat with new free accounts indefinitely at zero cost to the attacker, while every validating node repeatedly performs the EVM execution.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil

// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}

**File:** x/uexecutor/README.md (L213-218)
```markdown
`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
