## Analysis

The external report's bug class reduces to: **a value that should be validated/sourced from an immutable, previously-recorded record is instead skipped or re-derived from a different, mutable source, so a stored/committed value can silently diverge from what was actually authenticated.**

Applying this to Aptos's proof/commit-integrity surface, I traced several candidates (feature-flag threading in `BlockExecutorConfigFromOnchain`, `assemble_transaction_infos` in `do_ledger_update.rs`, restore/backup write-set replay in `restore_utils.rs`) and found they correctly derive their checkpoint/root fields from `ExecutionOutput`/`StateCheckpointOutput` consistently. The strongest local analog is a **self-documented comparator gap** in `TransactionOutput::ensure_match_transaction_info`.

### Title
`ensure_match_transaction_info` never validates the state/hot-state/position checkpoint hashes against `TransactionInfo` - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by replay/verification tooling to assert that a locally re-executed `TransactionOutput` matches an authenticated, on-chain `TransactionInfo` (the leaf committed in the transaction accumulator). It checks status, gas used, write-set hash, and event-root hash, but — per its own inline TODO — it never checks `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`.

### Finding Description
`ensure_match_transaction_info` compares four fields between the locally computed `TransactionOutput` and the persisted, hash-committed `TransactionInfo`: [1](#0-0) 

It explicitly does **not** compare the checkpoint-hash fields, and the code itself flags this: [2](#0-1) 

These checkpoint hashes are exactly the fields that bind a `TransactionInfo` leaf to the Jellyfish-Merkle/state-summary root at that version — `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and the newly repurposed `position_state_checkpoint_hash` field are all part of `TransactionInfoV1`: [3](#0-2) 

This function is used as the verification oracle in multiple tools that are supposed to catch state-root divergence between local execution and the authenticated ledger: the chunk executor's verify-execution path, `db-tool`'s `replay_on_archive`, `aptos-debugger`, and the CLI. [4](#0-3) 

Because the comparator silently skips the checkpoint-hash fields, any divergence in the locally-computed state/hot-state/position root (e.g., from a JMT computation bug, hot-state materialization bug, or the write-set-to-storage handoff producing a different resulting state than what was originally committed) would **not** be flagged as a mismatch by this function, even though the transaction's declared status, gas, write-set hash, and events all "match."

### Impact Explanation
This is a proof-verification integrity gap: it is exactly the class of bug the state-integrity gate calls out — "wrong accumulator root ... or state proof accepted as valid." A corrupted or incorrectly computed state checkpoint root would pass this check undetected, meaning replay-verification and audit tooling relying on `ensure_match_transaction_info` (e.g., `replay_on_archive`, debugger-based bisection of consensus divergence) could report a clean replay while the actual state root differs from the authenticated one.

### Likelihood Explanation
I was **not able to fully confirm** whether this comparator gates any mandatory, always-on mainnet commit/consensus path, or whether it is invoked only from opt-in verification/debug tooling (`VerifyExecutionMode`, `db-tool replay-on-archive`, CLI/debugger commands). All confirmed call sites I found (`chunk_executor/mod.rs`, `storage/db-tool/src/replay_on_archive.rs`, `aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`) appear to be offline/opt-in verification and forensic tooling rather than the mandatory state-sync/consensus commit path — meaning normal block execution and commit is *not* gated by this function, and nodes would still independently converge/diverge based on their own JMT computation regardless of this check. This significantly limits the "matters on mainnet by default" severity: it would primarily reduce the effectiveness of after-the-fact audits/replay-verification rather than corrupt live committed state itself. I could not, within the available searches, fully trace every call site's exact activation conditions (e.g., is `VerifyExecutionMode` ever mandatory during fast-sync of a fresh node) to rule out a stronger, always-on impact.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present in the expected `TransactionInfo`) against the locally computed values before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, as the existing TODO already recommends, and audit all four call sites to confirm none of them are relied upon as the sole integrity gate for a mandatory sync/commit path.

### Proof of Concept
Not applicable as executable PoC — the flaw is demonstrated directly by the existing TODO comment and the fields omitted from the comparator function; a concrete PoC would require constructing a scenario where local execution produces a different checkpoint hash than the authenticated `TransactionInfo` and confirming which of the four call sites (chunk executor, replay-on-archive, debugger, CLI) would incorrectly report success. I was unable to complete that trace within the available tool budget.

**Caveat:** Given the uncertainty about whether this gap sits on a mandatory mainnet path versus opt-in tooling, confidence in this meeting the "high/critical, matters on mainnet by default" bar is moderate, not high. This is presented as the strongest local analog found, with the stated uncertainty flagged rather than asserted as fact.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
