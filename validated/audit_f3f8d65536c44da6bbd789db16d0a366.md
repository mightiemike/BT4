### Title
Unbounded gzip decompression in `decompress_program` allows a memory-exhaustion DoS via a single Declare V1 RPC request - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
`apollo_rpc`'s `decompress_program` decompresses a user-supplied, base64+gzip-encoded legacy `program` field with no output size limit and no read timeout, unlike the equivalent function in `starknet_api::compression_utils` which explicitly bounds decompressed size. This function is reachable from an unprivileged, unauthenticated RPC caller through `BroadcastedDeclareTransaction::V1`, used by `starknet_estimateFee` / `starknet_simulateTransactions` execution paths on any full/RPC node.

### Finding Description
`decompress_program` reads the entire gzip stream into an unbounded `Vec<u8>` via `decoder.read_to_end(&mut decompressed)`, with a `TODO(dan): add time and size limits.` comment acknowledging the missing guard: [1](#0-0) 

This is called from `user_deprecated_contract_class_to_sn_api`, which converts a user-submitted `DeprecatedContractClass.compressed_program` field directly: [2](#0-1) 

That conversion function is invoked from `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` for the `V1` (legacy Cairo0) declare variant, which is exactly the deserialization path used when handling a client-submitted legacy Declare transaction for fee estimation / simulation: [3](#0-2) 

This is in stark contrast to the properly-fixed analog in `starknet_api::compression_utils::decompress_with_size_limit`, which bounds the decompressor with `.take(max_size + 1)` and errors out via `CompressionError::SizeLimitExceeded` if the limit is exceeded: [4](#0-3) 

The gateway's own declare-transaction ingestion path (`DeprecatedGatewaySierraContractClass::convert_to_sierra_contract_class` and the protobuf `Cairo0Class` conversion) already uses this size-limited decompression, confirming the project is aware of and mitigates this exact bug class elsewhere, but the RPC execution-simulation entry point was missed: [5](#0-4) [6](#0-5) 

### Impact Explanation
A single unauthenticated JSON-RPC caller can submit a `starknet_estimateFee` or `starknet_simulateTransactions` request containing a `BroadcastedDeclareTransaction::V1` whose `contract_class.program` field is a small gzip payload (analogous to the ~100-byte example in the referenced CVE) that decompresses to many gigabytes. Because `decompress_program` places no bound on the decompressed buffer size, this exhausts node memory and can crash the RPC/full node process (`ErrorObjectOwned`/OOM), causing denial of service for that node without requiring any special privileges, only a normal RPC call.

### Likelihood Explanation
High likelihood: no authentication or resource bounds are required, only an RPC call with attacker-controlled `compressed_program` content shaped as a decompression bomb; the code path is a standard fee-estimation/simulation entry point exposed by any full/RPC node running this code.

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` in `decompress_program` (`crates/apollo_rpc/src/v0_8/api/mod.rs:671-682`) with the same size-limited decompression pattern already used in `starknet_api::compression_utils::decompress_with_size_limit` (bound the reader with `.take(max_size)` and reject with an error if the size limit is exceeded), mirroring the fix already applied to the gateway and protobuf class-decoding paths.

### Proof of Concept
1. Craft a `BroadcastedDeclareTransaction::V1` JSON body where `contract_class.program` is a base64-encoded gzip blob that decompresses to several GB (e.g., a repeated-byte payload compressed with `flate2`/`gzip -9`, similar to the ~100-byte-to-GB ratio described in CVE-2026-53524).
2. Submit it via `starknet_estimateFee` or `starknet_simulateTransactions` JSON-RPC call to a node running this code.
3. `TryFrom<BroadcastedDeclareTransaction>` → `user_deprecated_contract_class_to_sn_api` → `decompress_program` decompresses the payload fully into memory with no bound, exhausting RAM and crashing/hanging the node process.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
