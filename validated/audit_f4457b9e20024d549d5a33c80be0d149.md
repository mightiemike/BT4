### Title
`replace_class` syscall in the Starknet OS lacks the declared-class / Cairo-version validation enforced by the blockifier, causing state-transition divergence between block production and OS re-execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
This is a direct analog of the reported bug class: a state-mutating operation reachable by an ordinary (unprivileged) actor writes attacker/user-controlled data into persistent contract state without validating it, because the validation that exists in one code path is missing in another. In the TON report, `upgrade_storage` wrote an unvalidated cell as contract storage. Here, the `replace_class` syscall writes an unvalidated `class_hash` into the contract's `StateEntry.class_hash` field in the Starknet OS (Cairo) implementation, while the equivalent Rust blockifier implementation enforces two checks that the OS is missing.

### Finding Description
Any contract can call the `replace_class` syscall from ordinary (unprivileged) execution to change its own `class_hash` in state. In the blockifier (the component that actually executes transactions when building a block), this is validated in `SyscallHandlerBase::replace_class`: [1](#0-0) 

which (a) requires the class to be declared (`get_compiled_class` errors with `UndeclaredClassHash` otherwise) and (b) forbids replacing with a Cairo0 (V0) class hash via `ForbiddenClassReplacement`, as also exercised in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` (`undeclared_class_hash`, `cairo0_class_hash` tests) and the deprecated syscall path `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807`.

However, the Starknet OS Cairo program — which is used to re-execute the block and independently derive the state commitment/root that is proven and checked against the sequencer's committed state — implements `execute_replace_class` without any such check: [2](#0-1) 

The code explicitly contains the comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` right before it unconditionally overwrites `state_entry.class_hash` with the caller-supplied `class_hash`, with no check that the class is declared and no check preventing a V1→V0 downgrade. The deprecated OS syscall path (`crates/apollo_starknet_os_program/.../deprecated_execute_syscalls.cairo:307-329`) has the identical unguarded pattern.

This mirrors the TON bug precisely: a state-mutation entry point accepts and persists attacker-controlled data (`class_hash`) without validating that it references well-formed/existing state (a declared class), even though the reference/blockifier implementation performs that validation.

### Impact Explanation
The Starknet OS is used for re-execution/verification of committed blocks (state commitment and proof generation). If the OS's `execute_replace_class` accepts a `class_hash` that the blockifier would have rejected (undeclared class, or a Cairo0 class replacing a Cairo1 class), the OS produces a different final state (and thus a different contract-state Merkle root / committed root) than the blockifier that actually executed and committed the block. This is exactly the kind of "wrong committed root" / "honest-node divergence" outcome called out as in-scope: the sequencer's committed state (from blockifier execution, which rejects the tx) diverges from what OS re-execution computes if the same syscall path were reachable there without the guard, or — more directly reachable — it means the OS's independent verification of a block cannot be trusted to catch an invalid `replace_class` value, undermining the guarantee that OS re-execution/proving is a faithful re-derivation of the same state transition performed by the blockifier. Any node or prover relying on the OS's rules alone (rather than the Rust blockifier's stricter rules) would accept/commit a state transition that the production execution path defines as invalid, a form of state-root/committed-state inconsistency between the two independently-maintained implementations of the same protocol rule.

### Likelihood Explanation
`replace_class` is a normal, permissionless syscall usable by any contract via `replace_class_syscall` from an ordinary `__execute__`/external entry point — no privileged sender is required, matching the "unprivileged transaction sender" reachability requirement. The missing check is explicitly flagged by the developers themselves via the TODO comment, confirming the gap is a known, currently-unaddressed omission rather than a hypothetical. The only barrier to full exploitation is confirming this OS code path is actually invoked during production re-execution/proving with attacker-influenced `class_hash` values (this could not be fully verified from the index alone — the wiki notes the OS is used for re-execution and commitment calculation, but I could not trace every caller of this exact Cairo function within the tool budget).

### Recommendation
Add the same two validations enforced in `SyscallHandlerBase::replace_class` (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) to the Starknet OS's `execute_replace_class`/`execute_replace_class` (deprecated) Cairo implementations:
1. Assert the target `class_hash` corresponds to a declared class (via `contract_class_changes` or equivalent OS-side declared-classes tracking) before writing the new `StateEntry`.
2. Reject replacement of a Cairo1 (V1) class with a Cairo0 (V0) class hash, matching `ForbiddenClassReplacement`.

Additionally, add a regression/consistency test that runs the same transaction through both the blockifier and the OS re-execution/flow-test harness (e.g. `starknet_os_flow_tests`) to assert identical rejection/acceptance behavior for `replace_class` edge cases (undeclared class, V1→V0 downgrade), closing the TODO before it can diverge production execution from OS verification.

### Proof of Concept
1. Deploy a Cairo1 contract exposing `replace_class_syscall` (e.g. the `test_replace_class` entry point pattern used in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit an ordinary `invoke` transaction calling that entry point with an undeclared `class_hash` (or a valid Cairo0 class hash).
3. In blockifier execution, the transaction reverts/fails with `StateError::UndeclaredClassHash` or `SyscallExecutionError::ForbiddenClassReplacement` (see `undeclared_class_hash`/`cairo0_class_hash` tests in `syscall_tests/replace_class.rs`), so this state transition is never committed by the sequencer.
4. Trace the equivalent syscall through the Starknet OS Cairo implementation `execute_replace_class` (`syscall_impls.cairo:881-920`): it contains no such check and unconditionally writes the new `StateEntry` with the attacker-supplied `class_hash`, demonstrating that the OS's state-transition function accepts a `class_hash` value that the blockifier's state-transition function rejects — a divergence in the two implementations of the same protocol rule.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
