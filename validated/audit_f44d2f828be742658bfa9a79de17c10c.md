### Title
Panic-induced chain halt via unresolvable `receiver_shard_id()` for delayed `GlobalContractDistribution` receipts across multi-generation resharding - (File: `runtime/runtime/src/congestion_control.rs`)

### Summary
`DelayedReceiptQueueWrapper::receipt_filter_fn` unconditionally `.unwrap()`s the `Result` returned by `Receipt::receiver_shard_id()` while popping delayed receipts. `receiver_shard_id()` can return `Err(EpochError::ShardingError)` for a `GlobalContractDistribution` receipt whose `target_shard` cannot be mapped into the current shard layout. Because non-`V3` (`V0`/`V1`/`V2`) shard layouts only resolve a single resharding generation, a receipt that survives two or more shard splits while sitting in the delayed queue will hit this error path and cause an `unwrap()` panic in every validator/RPC node applying that shard's chunk — a deterministic, transaction-triggered chain halt.

### Finding Description
`receipt_filter_fn` is used by the congestion-control delayed-receipt queue pop loop to skip receipts that "belong" to a sibling shard after resharding: [1](#0-0) 

It calls `receiver_shard_id(&shard_layout)` and immediately unwraps the result. `receiver_shard_id` is fallible specifically for `GlobalContractDistribution` receipts: [2](#0-1) 

When the receipt's `target_shard` is not present in the current layout, it falls back to `ShardLayout::resolve_to_current_shard`. For `V3` layouts this walks the complete, cumulative split history and can jump across arbitrarily many resharding generations: [3](#0-2) 

But for `V0`/`V1`/`V2` layouts, the same API only resolves a single generation via `get_children_shards_ids`: [4](#0-3) 

So if a `GlobalContractDistribution` receipt (created by an ordinary, unprivileged `DeployGlobalContract` action from any account) is pushed to the delayed-receipt queue and remains there across **two or more** resharding events while the shard layout in force is `V0`/`V1`/`V2` (i.e., outside the `DynamicResharding`/V3 path), `resolve_to_current_shard` returns `None` on the second hop, `receiver_shard_id` returns `Err`, and `receipt_filter_fn`'s `.unwrap()` panics. This exact scenario — a stale `GlobalContractDistribution` receipt surviving a double resharding — is explicitly modeled (for the already-mitigated V3 case) in the repository's own regression test: [5](#0-4) 

That test only asserts safety when `ProtocolFeature::DynamicResharding` (V3 layouts) is enabled; the underlying `receipt_filter_fn().unwrap()` call itself is not guarded and remains reachable for the `V0`/`V1`/`V2` layout path used whenever shard splits are driven by static protocol-version resharding rather than dynamic (V3) resharding.

### Impact Explanation
A panic inside `receipt_filter_fn`, which runs during ordinary chunk application (`DelayedReceiptQueueWrapper::pop`), aborts the runtime `apply()` call for every honest node processing that shard's chunk. Because all validators for the shard hit the identical deterministic state, this is a transaction-triggered, network-wide chunk-application halt (denial of service), directly analogous to the null-pointer-dereference DoS in the CVE (an attacker-controlled/crafted input causing an unhandled crash in normal request processing).

### Likelihood Explanation
Triggering requires only: (1) an unprivileged account deploying a global contract (`DeployGlobalContract`, action available to any signer) whose distribution receipt targets a shard that is about to be split, and (2) sufficiently saturating that shard's compute/gas budget across two resharding boundaries so the receipt stays in the delayed queue long enough to accumulate two stale shard-layout generations — a scenario the codebase's own test harness (`test_stale_global_contract_distribution_after_double_resharding`) demonstrates is constructible with ordinary transactions (contract deploy + `burn_gas_raw` calls). The likelihood is gated on resharding still using non-`V3` shard layouts (static protocol-version-driven splits), which is the layout format historically used for production nightshade resharding.

### Recommendation
Make `receipt_filter_fn` handle the `Err` case explicitly (propagate it as a `RuntimeError` instead of panicking), and/or extend the non-V3 `resolve_to_current_shard`/`get_children_shards_ids` implementations to walk multiple resharding generations the same way the V3 split-map implementation does, so stale `GlobalContractDistribution` receipts can always be remapped or safely dropped instead of causing an unrecoverable panic.

### Proof of Concept
1. Configure a shard layout using `V1`/`V2` (static, non-`DynamicResharding`) resharding with at least two scheduled splits of the same lineage shard across two epochs.
2. From an unprivileged account, submit `DeployGlobalContract` targeting the shard that will be split first, producing an outgoing `GlobalContractDistribution` receipt (see `apply_global_contract_distribution_receipt` / `forward_distribution_next_shard` in `runtime/runtime/src/global_contracts.rs:111-142,288-333`).
3. Saturate the shard's compute budget every block (e.g., repeated `burn_gas_raw` calls, as in the existing test) so the distribution receipt is forced into the delayed-receipt queue and remains there through both resharding boundaries — mirroring `test_stale_global_contract_distribution_after_double_resharding` at [6](#0-5)  but with static (V1/V2) resharding config instead of `DynamicReshardingConfig`.
4. Stop saturating and let the delayed queue drain; `DelayedReceiptQueueWrapper::pop` calls `receipt_filter_fn`, which calls `receiver_shard_id` on the stale receipt. Because the layout is not `V3`, `resolve_to_current_shard` fails to walk the second generation, returns `None`, `receiver_shard_id` returns `Err`, and the `.unwrap()` at `runtime/runtime/src/congestion_control.rs:876` panics, aborting chunk application on every node tracking that shard.

    pub fn receiver_shard_id(&self, shard_layout: &ShardLayout) -> Result<ShardId, EpochError> {
        let shard_id = match self.receipt() {
            ReceiptEnum::Action(_)
            | ReceiptEnum::ActionV2(_)
            | ReceiptEnum::Data(_)
            | ReceiptEnum::PromiseYield(_)
            | ReceiptEnum::PromiseYieldV2(_)
            | ReceiptEnum::PromiseResume(_) => {
                shard_layout.account_id_to_shard_id(self.receiver_id())
            }
            ReceiptEnum::GlobalContractDistribution(receipt) => {
                let target_shard = receipt.target_shard();
                if shard_layout.shard_ids().contains(&target_shard) {
                    target_shard
                } else {
                    // The target shard may be from an arbitrarily old layout (the receipt could
                    // have been delayed across multiple resharding events). resolve_to_current_shard
                    // will find a shard descendant in the current layout.
                    let Some(current_shard) = shard_layout.resolve_to_current_shard(target_shard)
                    else {
                        return Err(EpochError::ShardingError(format!(
                            "Shard {target_shard} does not exist in the shard layout or its split history",
                        )));
                    };
                    current_shard
                }
            }
        };
        Ok(shard_id)
    }

    /// Resolve any historical shard ID to a current shard by walking the full
    /// split history in `shards_split_map`. Returns the shard itself if it is
    /// current, or follows the first child at each generation until a current
    /// shard is reached. Returns `None` only if the shard ID is absent from
    /// both the current layout and the split history.
    pub fn resolve_to_current_shard(&self, shard_id: ShardId) -> Option<ShardId> {
        if self.shard_ids.contains(&shard_id) {
            return Some(shard_id);
        }
        let children = self.shards_split_map.get(&shard_id)?;
        self.resolve_to_current_shard(children[0])
    }

    /// Resolve any historical shard ID to a current descendant shard ID.
    /// For V3 layouts this uses the complete `shards_split_map`.
    /// For older layouts it falls back to `get_children_shards_ids` (single generation only).
    pub fn resolve_to_current_shard(&self, shard_id: ShardId) -> Option<ShardId> {
        match self {
            Self::V0(_) | Self::V1(_) | Self::V2(_) => {
                self.get_children_shards_ids(shard_id).map(|c| c[0])
            }
            Self::V3(v3) => v3.resolve_to_current_shard(shard_id),
        }
    }

fn test_stale_global_contract_distribution_after_double_resharding() {
    init_test_logger();

    // The fix only works with V3 shard layouts (dynamic resharding).
    // With static resharding, the shard layout doesn't maintain a full split history.
    if !ProtocolFeature::DynamicResharding.enabled(PROTOCOL_VERSION) {
        return;
    }

    let epoch_length: BlockHeightDelta = 10;
    let base_boundary_accounts = create_account_ids(["user2", "user3"]).to_vec();
    let base_shard_layout = ShardLayout::multi_shard_custom(base_boundary_accounts, 3);
    let deploy_user: AccountId = create_account_id("user0");
    let users = create_account_ids(["user0", "user1", "user2", "user3", "user4", "user5"]).to_vec();
    let validators_spec = create_validators_spec(1, 0);
    let clients = validators_spec_clients(&validators_spec);
    let chunk_producer = clients[0].clone();
    let gas_limit = Gas::from_teragas(300);
    let base_pv = PROTOCOL_VERSION - 1;

    // Configure dynamic resharding to force-split two shards sequentially.
    // The first split targets the shard containing deploy_user (user0), so the
    // GlobalContractDistribution receipt becomes stale after two layout transitions.
    let first_split_shard = base_shard_layout.account_id_to_shard_id(&deploy_user);
    let second_split_shard = base_shard_layout.account_id_to_shard_id(&create_account_id("user4"));
    assert_ne!(first_split_shard, second_split_shard);

    let dynamic_config = DynamicReshardingConfig {
        memory_usage_threshold: u64::MAX,
        min_child_memory_usage: u64::MAX,
        max_number_of_shards: 100,
        min_epochs_between_resharding: 1.try_into().unwrap(),
        force_split_shards: vec![first_split_shard, second_split_shard],
        block_split_shards: vec![],
    };

    let genesis = TestLoopBuilder::new_genesis_builder()
        .protocol_version(base_pv)
        .validators_spec(validators_spec)
        .shard_layout(base_shard_layout.clone())
        .epoch_length(epoch_length)
        .gas_limit(gas_limit)
        .add_user_accounts_simple(&users, Balance::from_near(1_000_000))
        .build();
    let base_epoch_config = TestEpochConfigBuilder::from_genesis(&genesis).build();

    let mut dynamic_epoch_config = base_epoch_config.clone();
    dynamic_epoch_config.shard_layout_config =
        ShardLayoutConfig::Dynamic { dynamic_resharding_config: dynamic_config };

    let epoch_config_store = EpochConfigStore::test(BTreeMap::from([
        (base_pv, Arc::new(base_epoch_config)),
        (base_pv + 1, Arc::new(dynamic_epoch_config)),
    ]));

    let mut env = TestLoopBuilder::new()
        .genesis(genesis)
        .clients(clients)
        .epoch_config_store(epoch_config_store)
        .gc_num_epochs_to_keep(5)
        .build();

    // Step 1: Deploy the test contract on user0's account so we can call burn_gas_raw.
    {
        let node = env.node_for_account(&chunk_producer);
        let tx = node.tx_deploy_test_contract(&deploy_user);
        node.submit_tx(tx);
    }
    env.runner_for_account(&chunk_producer).run_for_number_of_blocks(2);

    // Step 2: Deploy a global contract from user0. This creates a
    // GlobalContractDistribution receipt with target_shard = user0's shard (S_A),
    // which is the shard that will be split in the first resharding.
    {
        let node = env.node_for_account(&chunk_producer);
        let code = ContractCode::new(near_test_contracts::rs_contract().to_vec(), None);
        let tx = node.tx_deploy_global_contract(
            &deploy_user,
            code.code().to_vec(),
            GlobalContractDeployMode::CodeHash,
        );
        node.submit_tx(tx);
    }

    // Step 3: Saturate compute on user0's shard every block so that the
    // GlobalContractDistribution receipt (arriving as incoming) gets pushed to
    // the delayed queue and stays there through both resharding events.
    //
    // Each burn_gas_raw call burns slightly more than half the gas limit, so
    // two local receipts exhaust the chunk's compute budget. We submit 3 per
    // block to ensure at least 2 are processed as local receipts.
    let gas_to_burn = gas_limit.checked_div(2).unwrap().checked_add(Gas::from_gas(1)).unwrap();
    let initial_num_shards = base_shard_layout.num_shards();
    let target_num_shards = initial_num_shards + 2; // after two splits

    let start_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };

    // Keep saturating until both resharding events complete. Dynamic resharding has a
    // 2-epoch proposal-to-activation pipeline, so we need enough epochs for both splits.
    let max_saturation_height = start_height + epoch_length * 12;
    let mut both_splits_done = false;
    for target_height in (start_height + 1)..=max_saturation_height {
        // Submit 3 heavy transactions to saturate this block's compute budget.
        {
            let node = env.node_for_account(&chunk_producer);
            for _ in 0..3 {
                let tx = node.tx_call(
                    &deploy_user,
                    &deploy_user,
                    "burn_gas_raw",
                    gas_to_burn.as_gas().to_le_bytes().to_vec(),
                    Balance::ZERO,
                    gas_limit,
                );
                node.submit_tx(tx);
            }
        }
        env.runner_for_account(&chunk_producer).run_until_head_height(target_height);

        // Check if both resharding events have completed.
        let node = env.node_for_account(&chunk_producer);
        let epoch_id = node.client().chain.chain_store().head().unwrap().epoch_id;
        let current_layout = node.client().epoch_manager.get_shard_layout(&epoch_id).unwrap();
        if current_layout.num_shards() >= target_num_shards {
            both_splits_done = true;
            break;
        }
    }
    assert!(both_splits_done, "both shard splits did not complete within the allotted blocks");

    // Step 4: Stop saturating. Let the delayed queue drain.
    // If the vulnerability exists, processing the stale GlobalContractDistribution
    // receipt will panic in receipt_filter_fn() when receiver_shard_id() fails
    // to remap the old target_shard after two resharding generations.
    let current_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    let drain_end = current_height + epoch_length * 2;
    env.runner_for_account(&chunk_producer).run_until_head_height(drain_end);

    let head_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    assert!(
        head_height >= drain_end,
        "chain stalled at height {}; expected >= {} (likely panicked processing stale receipt)",
        head_height,
        drain_end
    );
}
