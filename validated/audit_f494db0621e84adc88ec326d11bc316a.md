### Title
Slippage bound derived from a manipulable same-pool spot quote enables sandwich extraction on GAS-route PRC20→PC auto-swaps - (File: x/uexecutor/keeper/execute_inbound_gas.go, execute_inbound_gas_and_payload.go, outbound.go, evm.go)

### Summary
Push Chain's fix for the analogous `BondingCurvePool.graduateToken` slippage-protection bug (MNBD1-2) was to compute `minPCOut` from a Uniswap V3 QuoterV2 quote with a 5% band, per `app/upgrades/chain-meta/upgrade.go` feature 4. However, that "protection" is built on the same manipulable primitive the original bug warned about: a spot AMM price fetched immediately before the swap is executed. `GetSwapQuote` (`x/uexecutor/keeper/evm.go`) is a `commit=false` static call to `quoteExactInputSingle` on the exact same pool that `CallPRC20DepositAutoSwap` will trade against in the same message-handling flow, so the reference price itself, not just the execution price, can be pre-manipulated by an unprivileged attacker.

### Finding Description
Three call sites compute `minPCOut` the same way:
- `ExecuteInboundGas` (GAS inbound route) [5](#0-4) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound route) [6](#0-5) 
- `applyGasRefund` (outbound excess-gas refund swap) [7](#0-6) 

Each fetches `quote` via `GetSwapQuote` against the live Uniswap V3 pool state, then sets `minPCOut = quote * 95 / 100`, and immediately calls `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` (which executes `depositPRC20WithAutoSwap`/`refundUnusedGas` against that same pool) within the same Cosmos message execution. Because the quote and the trade both read/write the identical AMM pool state and there is no TWAP, oracle cross-check, or externally-supplied minimum, an attacker who moves the pool's spot price before the validators' finalizing `MsgVoteInbound`/`MsgVoteOutbound` transaction lands (e.g., by front-running with their own swap in the same block) causes the "reference" quote itself to already reflect the manipulated price. The subsequent 5% band only bounds slippage relative to that already-distorted reference, not relative to a fair/undisturbed market price — this is the same class of bug as MNBD1-2 (minOut protection anchored to an on-chain price the attacker controls), just expressed as an insufficient-oracle problem instead of a zero-value minOut.

An attacker can:
1. Observe a pending inbound (GAS or GAS_AND_PAYLOAD) or a pending outbound-refund that will trigger an autoswap, sized so the swap materially moves the pool.
2. Submit a transaction that skews the WPC/PRC20 pool price in the direction that benefits the attacker, timed to land immediately before the validator's vote-finalization tx in the same block.
3. Let the module's `GetSwapQuote` read the now-skewed price and compute `minPCOut` from it.
4. Let `depositPRC20WithAutoSwap` execute against the same skewed pool (within the attacker's manipulated band), then immediately submit a back-run trade to restore the price and capture the difference.

The user (whose bridged funds are being auto-swapped into PC on the UEA) and/or the protocol absorb the sandwiched value — the received PC amount is worse than it would be at a fair market price, even though it nominally satisfies the "5%-slippage-protected" `minPCOut` check.

### Impact Explanation
This falls within the allowed impact of corrupting gas fee/refund accounting and draining user/protocol-controlled funds through the universal execution flow: users bridging via the GAS or GAS_AND_PAYLOAD inbound routes, and users receiving excess-gas refunds on outbound completion, can have value extracted from their auto-swapped amount by an ordinary, unprivileged attacker with no special access — purely through public mempool transaction ordering within a single block, well within the "ordinary user deposits/payloads/contracts" reachability requirement.

### Likelihood Explanation
Moderate-to-high. It requires the attacker to have capital to move the specific WPC/PRC20 pool and correctly time a transaction to land adjacent to the validators' vote-finalization transaction, but no privileged role, validator collusion, or protocol bug beyond normal AMM mechanics is needed. The impact scales with pool liquidity depth and swap size, and repeats every time a GAS/GAS_AND_PAYLOAD inbound or gas refund triggers an autoswap.

### Recommendation
Do not derive `minPCOut` solely from a spot quote fetched from the same pool immediately before the trade executes. Use a manipulation-resistant reference such as a time-weighted average price (TWAP) from the Uniswap V3 pool's oracle observations, or cross-check the spot quote against an independent price source (e.g., chain-meta gas price oracle or a governance-configured floor) before applying the slippage band. Alternatively, widen the effective protection by comparing the spot quote across multiple blocks and rejecting outlier deviations, or route these swaps through mechanisms that are inherently resistant to same-block manipulation.

### Proof of Concept
Conceptual sequence (no exploitation performed, code-level trace only):
1. Attacker monitors the mempool/validator set for an imminent quorum-reaching `MsgVoteInbound` for a GAS or GAS_AND_PAYLOAD inbound with a sizeable `amount` (see `ExecuteInboundGas`, `x/uexecutor/keeper/execute_inbound_gas.go:14-158`).
2. Attacker submits an EVM tx that swaps a large amount of WPC → PRC20 (or vice versa) on the UniversalCore's underlying Uniswap V3 pool, landing in the block immediately before the validators' finalizing vote tx.
3. Once the vote reaches quorum in that block, `ExecuteInboundGas` calls `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`), which reads the now-skewed pool price and returns a `quote` reflecting the attacker's manipulation.
4. `minPCOut := quote * 95 / 100` is computed from this skewed quote (`x/uexecutor/keeper/execute_inbound_gas.go:142-148`), then `CallPRC20DepositAutoSwap` executes the real swap against the same still-skewed pool.
5. Attacker immediately submits a back-run trade to unwind their initial position, capturing the price difference at the expense of the value the user's bridged funds converted into. [1](#0-0)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,

	ueaAddr common.Address,
	amount *big.Int,

		return nil, err

		return nil, err

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err

	if err != nil {
		return nil, err
