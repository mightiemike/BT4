### Title
Vault `accrue` silently no-ops instead of reverting when paused, letting deposit/redeem/borrow/repay proceed on stale interest state - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Each vault contract (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`, and their `local-testing` mirrors) exposes a per-asset `pause-states` bitfield with a dedicated `accrue` flag. `deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan` and `transfer` all begin by calling `(try! (accrue))`, expecting either a freshly-accrued index or a hard failure. When the `accrue` pause flag is set, `accrue` instead returns `(ok { index: idx, lindex: lidx })` with the *old* cached values, explicitly labeled in the code as "PAUSED: Pass-through without reverting."

### Finding Description
`accrue` is defined identically in every vault, e.g.: [1](#0-0) 

The pattern is: read `pause-states`, and if `(get accrue states)` is true, short-circuit with `(ok {index: idx, lindex: lidx})` using the currently stored (potentially stale) `index`/`lindex`, without ever touching `var-get`/`var-set` for `last-update`, `treasury-lp` minting, or index recalculation, and — critically — without returning an error. Every caller of `accrue` (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`, `transfer`) treats the `try!` on this call purely as a "refresh-or-abort" gate: [2](#0-1) [3](#0-2) 

Because `try!` only unwraps `err` and this call is always `ok`, none of these entry points ever actually stop executing when `accrue` is paused — they simply continue with a frozen `index`/`lindex` as if the pause never happened. The DAO's `accrue` pause was clearly intended as a maintenance/circuit-breaker switch (analogous to the market's `set-pause-liquidation`), but its implementation is a value pass-through rather than a revert, so it fails to halt the very operations (`deposit`, `redeem`, `borrow`, `repay`) that depend on the interest/liquidity index being current. This matches the report-class analog explicitly permitted by scope: "a pause that passes through instead of reverting."

Compounding this, `market.clar`'s `accrue-and-cache` calls the vault's `vault-accrue` (which routes to this same `accrue`) and caches whatever it returns for the rest of the block: [4](#0-3) 
So while `accrue` is paused, the market's per-block index cache is silently populated with the stale `index`/`lindex` for that vault, and every operation in `market.clar` that depends on that asset's index (`borrow`, `repay`, `liquidate`, `collateral-add/remove`, health checks) will compute debt/collateral valuations and interest-based accounting using the frozen values rather than failing or reverting.

### Impact Explanation
While the `accrue` pause is active, users can continue to `deposit`/`redeem`/`borrow`/`repay` against a vault whose interest index is frozen. Debt does not accrue interest and liquidity-index growth does not happen for suppliers during the pause window, yet the vault keeps accepting new borrow/repay/deposit/redeem operations that assume a live index. A user can borrow before or during the pause and repay after unpause (or vice versa) while interest that should have accrued during the paused interval is never charged, effectively causing the DAO's maintenance pause to fail its purpose and letting lenders' expected yield be silently skipped for the paused period. This is a temporary freezing/loss of unclaimed yield for suppliers (interest they should have earned is never accounted for during the pause window), which falls under the in-scope "High" impact category (theft/permanent or temporary freezing of unclaimed yield).

### Likelihood Explanation
This requires only the normal, intended DAO action of toggling the `accrue` pause flag (not a compromise) — a legitimate operational scenario (e.g. pausing accrual during an oracle/interest-rate model migration). Once paused, any ordinary user transaction into `deposit`/`redeem`/`borrow`/`repay` on that vault silently proceeds with stale interest data; no special timing, flashloan, or attacker-controlled configuration is needed beyond the pause being active, making the root-cause condition easy to trigger whenever the intended pause switch is used.

### Recommendation
Have `accrue` return an error (e.g. `ERR-PAUSED`) when the `accrue` pause flag is set, and have all callers (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`, `transfer`, and `market.clar`'s `accrue-and-cache`) properly propagate that failure via `try!` instead of silently continuing with stale index/lindex values. Alternatively, if pass-through behavior is intentional for gas/availability reasons, explicitly gate `deposit`/`redeem`/`system-borrow`/`system-repay` on the same `accrue` pause flag so they revert rather than relying on `accrue`'s return value to halt execution.

### Proof of Concept
1. DAO/authorized caller sets the `accrue` bit of `pause-states` to `true` on, e.g., `v0-vault-usdc.clar` (intended as a maintenance pause).
2. A user calls `market.clar`'s `borrow` for USDC; internally this triggers `accrue-and-cache` → `vault-accrue` → vault's `accrue`, which, being paused, returns `(ok {index: idx, lindex: lidx})` with the old, un-refreshed index instead of erroring: [1](#0-0) .
3. `market.clar` caches this stale index in `index-cache` for the block and proceeds to compute `scaled-debt-added`/health checks against it as if it were fresh: [4](#0-3) , [5](#0-4) .
4. The borrow succeeds normally even though the vault is in a "paused" accrual state; interest that should reflect the elapsed time since the last accrual is never charged for as long as the pause remains active, and the borrow/repay cycle completes without the pause ever blocking the transaction.
5. Repeated over the pause window, users effectively borrow/repay/deposit/redeem interest-free (or without the yield growth suppliers are owed), defeating the purpose of the pause and causing temporary loss of unclaimed yield to suppliers.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
