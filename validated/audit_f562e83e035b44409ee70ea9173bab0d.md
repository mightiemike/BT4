### Title
Unbounded, non-deduplicated shop session-ID list in `KVSessionStorage` causes DoS of `findSessionsByShop` / uninstall handling - (File: packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts)

### Summary
`KVSessionStorage.storeSession()` unconditionally appends the session id to a per-shop index list on every call, with no deduplication and no cap, unlike the analogous Redis adapter which checks for existing entries before pushing. This mirrors the root cause of the reported `Voter::_processPendingRemovals()` bug: an array that is only ever appended to and then fully iterated/loaded during a critical operation, without any batching or size limit, leading to unbounded growth and eventual denial of service of that operation.

### Finding Description
`storeSession()` calls `addShopIds(session.shop, [session.id])` on every store, including updates to an already-stored session id: [1](#0-0) 

`addShopIds` blindly concatenates the new id(s) onto the existing list read from KV, with no check for duplicates and no upper bound: [2](#0-1) 

Contrast this with the Redis adapter's equivalent method, which explicitly guards against duplicate insertion: [3](#0-2) 

The unbounded list is later loaded in full and iterated with `Promise.all` in `findSessionsByShop`, which is the analog of `_processPendingRemovals` iterating the full `pendingRemovals[ep]` array with no batching: [4](#0-3) 

`findSessionsByShop` is invoked from `AppInstallations.includes()` and `AppInstallations.delete()`, which are used by the Express package's `APP_UNINSTALLED` webhook handler and by app installation checks — critical authentication/app-lifecycle paths: [5](#0-4) 

Because token refresh, re-authentication, or repeated online-session creation for the same shop all call `storeSession()` repeatedly (often re-storing the *same* session id, e.g. token refresh for an existing online/offline session), the per-shop id list in KV grows without bound and accumulates duplicate entries over the life of an installation. Since `removeShopIds`/`deleteSession` only remove ids that are explicitly deleted, but `addShopIds` keeps duplicating, the list size is asymmetric and monotonically increasing under normal use, without any batch/cap parameter ever being applied.

### Impact Explanation
As the per-shop id array grows, `findSessionsByShop` must fetch and resolve every id (including now-stale duplicates) via `Promise.all`, and `KVNamespace` values have hard size limits. Eventually either the operation times out/becomes computationally expensive, or writes to the shop's index key fail once the serialized array exceeds the KV value size limit, breaking `storeSession`, `deleteSession` (via `removeShopIds`), and `findSessionsByShop`. This directly denies the `APP_UNINSTALLED` webhook handler (`deleteAppInstallationHandler`) and `AppInstallations.includes/delete`, both of which are on the authentication/app-lifecycle critical path, mirroring the reported DoS of `Voter::finalize()`.

### Likelihood Explanation
This requires no privileged/administrative action — it is triggered purely by normal, repeated OAuth/session-storage activity for a single shop (e.g., repeated token refreshes, or multiple staff members creating online sessions), which is entirely within the capability of a single merchant or even automatically over time through normal app usage. No malicious HMAC forgery or elevated access is needed to trigger growth; only sustained normal usage of the app by that shop.

### Recommendation
In `addShopIds` (`packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`), deduplicate ids before writing (mirroring the Redis adapter's `includes` check), and consider capping/pruning stale ids, so the per-shop index cannot grow unbounded and `findSessionsByShop` remains bounded in cost.

### Proof of Concept
1. An app using `KVSessionStorage` performs repeated OAuth/online-session token exchanges for the same shop (normal usage, e.g. session refresh on every embedded app load).
2. Each `storeSession()` call re-adds the session id via `addShopIds`, which appends without checking `shopIds.includes(id)` (unlike `redis.ts`'s `addKeyToShopList`).
3. Over time the `shop:<domain>` KV value accumulates a large, duplicate-laden array of ids.
4. Any subsequent call to `findSessionsByShop(shop)` — invoked by `AppInstallations.includes`/`delete` during install checks or the `APP_UNINSTALLED` webhook — must resolve every id in the bloated array via `Promise.all`, degrading or failing once the KV value size limit or execution time limit is hit, denying app-lifecycle/session operations for that shop.

    const sessionIds = await this.namespace.get<string[]>(
      this.getShopSessionIdsKey(shop),
      {type: 'json'},
    );

    if (!sessionIds) {
      return [];
    }

    return Promise.all(
      sessionIds.map(async (id) => (await this.loadSession(id))!),
    );

  private async addShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
  }

  private async addKeyToShopList(session: Session) {
    const shopKey = session.shop;
    const idKey = this.client.generateFullKey(session.id);
    const idKeysArrayString = await this.client.get(shopKey);

    if (idKeysArrayString) {
      const idKeysArray = JSON.parse(idKeysArrayString);

      if (!idKeysArray.includes(idKey)) {
        idKeysArray.push(idKey);
        await this.client.set(shopKey, JSON.stringify(idKeysArray));
      }
    } else {
      await this.client.set(shopKey, JSON.stringify([idKey]));

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
      );
    }
  }
