Based on my research, I found a genuine analog matching the "pause passes through instead of reverting" pattern named in the scan rules.

### Title
Pausing `accrue` silently returns stale indexes instead of reverting, letting `system-borrow`/`system-repay`/`deposit`/`redeem` mutate state on frozen interest data - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every vault (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) implements `accrue` so that when the `accrue` pause flag is set, the function does not revert - it returns `(ok { index: idx, lindex: lidx })` with the pre-existing (stale) values [1](#0-0) . Every state-mutating entry point (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`) calls `(try! (accrue))` and treats its `ok` result as if a real accrual happened, then proceeds to mutate `principal-scaled`, `total-borrowed`, or `assets` using the (possibly stale) `idx`/`lindex` values [2](#0-1) .

### Finding Description
Each vault's pause map has an independent `accrue` flag distinct from the `deposit`/`borrow`/`repay`/`redeem`/`flashloan` flags [3](#0-2) . If the DAO pauses only `accrue` (leaving borrow/repay/deposit/redeem active), `accrue()` becomes a no-op pass-through that never fails and never updates `index`/`lindex`/`last-update` [4](#0-3) . Downstream callers like `system-borrow` and `system-repay` unconditionally proceed to record new scaled debt using the frozen `idx` [5](#0-4) [6](#0-5) , and `deposit`/`redeem` mint/burn shares using share-price previews that are also derived from the frozen index [7](#0-6) .

The `set-pause-states` function attempts to compensate for this by force-accruing before pausing and by jumping `last-update` forward when unpausing [8](#0-7) , but this compensation only covers the transition edges. While `accrue` remains paused, an unbounded amount of real interest continues to accrue economically (borrowers still hold outstanding debt, lenders' funds are still deployed) but is never captured into `index`/`lindex`, and every `deposit`, `redeem`, `system-borrow`, and `system-repay` call executed during that window mutates `assets`, `principal-scaled`, and `total-borrowed` against the stale, un-accrued state instead of reverting.

### Impact Explanation
Because `accrue` can be paused independently of `deposit`/`redeem`/`borrow`/`repay`, depositors/redeemers/borrowers/repayers who transact during that window get share prices and scaled-debt conversions computed from an index that omits real elapsed-time interest. Depending on the length of the pause and market conditions, this misprices shares minted/burned in `deposit`/`redeem` and misprices new debt recorded in `system-borrow`, causing a temporary freezing/misallocation of unclaimed yield between depositors who transact during vs. after the pause window - this lands on the "temporary freezing of unclaimed yield" impact category.

### Likelihood Explanation
This requires the DAO to pause only the `accrue` flag while leaving other operations active - a configuration that is fully within the intended pause-flag design of `set-pause-states`, so no privileged compromise is needed beyond a normal pause action already exposed in the contract's design surface. Any user calling `deposit`, `redeem`, `system-borrow`, or `system-repay` during that window automatically triggers the mispriced mutation in the same transaction as their action, satisfying a single-transaction analog (health/accrual step silently returning a stale value that is not invalidated before the subsequent mutating call in the same call graph).

### Recommendation
Either make `accrue()` revert with `ERR-PAUSED` when the `accrue` flag is set (so callers cannot proceed with stale indexes), or make `deposit`, `redeem`, `system-borrow`, and `system-repay` also check the `accrue` pause flag explicitly and revert if it is stale/paused, ensuring the same invariant enforced at the transition edges in `set-pause-states` (accrue-before-pause, last-update-jump-on-unpause) is also enforced for every intervening mutating call while paused.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-stx.clar` with `{accrue: true, borrow: false, repay: false, deposit: false, redeem: false, flashloan: false}` - this force-accrues once then freezes `index`/`lindex` [9](#0-8) .
2. Time passes (many blocks); real borrower debt economically grows, but `index`/`lindex` do not move because `accrue()` returns the pass-through `ok` without updating state [4](#0-3) .
3. A user calls `deposit` (not paused): `accrue()` is invoked, returns stale `idx`/`lindex` as `ok`, and `deposit` proceeds to mint shares via `convert-to-shares-preview` using the stale index [10](#0-9) , under-pricing the new depositor relative to true accrued value.
4. Similarly, a borrower calls `system-borrow`, and new scaled debt is recorded via the stale `idx` [2](#0-1) , locking in a scaled-debt value that does not reflect the true economic interest owed for the paused period once the DAO eventually unpauses and jumps `last-update`.

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)

        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
      
      (ok true))))
