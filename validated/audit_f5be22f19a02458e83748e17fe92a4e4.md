### Title
Auto-swap deposits (GAS / GAS_AND_PAYLOAD inbound execution and outbound gas-fee refunds) derive slippage protection from a manipulable same-block spot quote instead of a bounded reference price - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The BendDAO finding is a class of bug where a protocol computes an economically important price/amount with no independent cap or reference bound, so an attacker-influenced input can force a counter-party into an inflated, unfavorable value. Push Chain's inbound `GAS`/`GAS_AND_PAYLOAD` auto-swap path and the outbound excess-gas-refund path both compute the acceptable execution price (`minPCOut`) as a fixed 95% of a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote fetched in the same call sequence as the actual swap, with no TWAP or externally-bounded reference price. Because the quote and the swap are derived from the same manipulable AMM pool state, an unprivileged actor who moves the pool price shortly before the module executes the swap can force user/protocol funds through the swap at that manipulated price while still satisfying the "5% slippage" check, extracting value.

### Finding Description
For `GAS` inbound execution, `k.GetSwapQuote` is called against `UniversalCore`'s Uniswap V3 `QuoterV2` right before `k.CallPRC20DepositAutoSwap` executes the real swap: [1](#0-0) 

The same pattern is repeated for `GAS_AND_PAYLOAD` in `gasAndPayloadDepositAutoSwap`: [2](#0-1) 

And again for outbound excess-gas refunds in `applyGasRefund`: [3](#0-2) 

`GetSwapQuote` performs a non-committing `CallEVM` to `quoteExactInputSingle` with `SqrtPriceLimitX96 = 0` (no price-limit protection) against the pool's *current* state: [4](#0-3) 

In all three call sites, `minPCOut` is computed purely as `quote * 95 / 100` — i.e., a percentage band *around the very quote being read at execution time*, not against a manipulation-resistant reference price (e.g., a TWAP, an oracle price from `x/uregistry`, or a governance-set floor). This is architecturally the same flaw as the BendDAO report: the "acceptable price" bound is derived from the same instantaneous, attacker-influenceable value it is supposed to protect against, so it can never actually cap the loss — it only guarantees the loss won't exceed 5% *of whatever price the attacker has already pushed the pool to*.

Since the `UniversalCore` Uniswap V3 pools (PRC20 gas-token ⇄ WPC) are ordinary on-chain AMM pools, any unprivileged user can trade against them in a preceding transaction within the same block (or in the block immediately before the inbound/outbound is processed) to shift the spot price. When the module's inbound deposit-with-autoswap or outbound gas refund executes immediately afterward, it reads the now-skewed quote, computes `minPCOut` from that skewed quote, and executes the swap — realizing a swap at a price up to 5% (plus the price impact of the module's own swap) worse than the pre-manipulation fair price, while appearing "protected" by slippage tolerance.

### Impact Explanation
This directly threatens user and protocol funds in the universal execution path: depositors using `GAS`/`GAS_AND_PAYLOAD` inbound flows have their deposited gas token unilaterally auto-swapped to PC on their behalf, and the outbound refund flow swaps protocol-custodied gas-token excess back to PC for the sender. In both cases, the swap counter-party is the manipulated AMM pool, so value extracted by the attacker (via classic sandwich/price-manipulation) comes directly out of the depositor's/refund-recipient's expected proceeds, i.e., unauthorized value extraction from user/protocol-controlled funds — matching the "corruption of PRC20/native asset accounting" and "unauthorized... drain" allowed-impact categories. Because these swaps are triggered automatically as part of consensus-approved inbound/outbound processing (not user-chosen, no user-supplied slippage), affected users cannot opt out or set their own protection.

### Likelihood Explanation
Exploitation requires only normal trading capability against the `UniversalCore` Uniswap V3 pools plus the ability to time a trade near the block in which a targeted inbound/outbound is processed — both achievable by an ordinary unprivileged user/searcher, with no reliance on malicious validators, TSS participants, or privileged roles. The impact scales with the pool's liquidity depth and the size of the auto-swapped/refunded amount; shallow pools (likely for many PRC20 gas tokens) make this more practical.

### Recommendation
Do not derive `minPCOut` solely from a spot quote fetched at execution time. Bound the acceptable execution price against an independent, harder-to-manipulate reference (e.g., a time-weighted average price, a registry/oracle-sourced exchange rate maintained in `x/uregistry`, or a maximum allowed deviation from the last several observed chain-meta gas prices), and/or cap the swap size relative to pool liquidity/price-impact so a single-block manipulation cannot materially move the executed price. Consider also allowing/validating a user- or governance-configured minimum acceptable output rather than a fixed 95%-of-spot heuristic.

### Proof of Concept
1. Identify a `UniversalCore` Uniswap V3 pool (PRC20 gas-token/WPC) with modest liquidity.
2. Submit a large swap against the pool to depress the PRC20→WPC price just before (or in the same block ordering window as) an inbound `GAS`/`GAS_AND_PAYLOAD` message (or an outbound observation crossing the 2/3 vote threshold that triggers `applyGasRefund`) is processed.
3. When `GetSwapQuote` is called in `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund`, it returns the depressed quote; `minPCOut = quote * 95/100` reflects the manipulated price, not the fair price.
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap at (or near) the manipulated price, satisfying the "slippage check" while realizing a worse-than-fair price for the depositor/refund recipient.
5. Attacker reverses their initial trade (or simply captures the price-impact spread from the module's swap) to realize profit extracted from the victim's expected proceeds.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
