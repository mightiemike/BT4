### Title
Unbounded, attacker-controlled `GasLimit` in gasless `MsgExecutePayload` enables free-of-cost EVM computation DoS - (File: `x/uexecutor/keeper/msg_execute_payload.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/types/universal_payload.go`)

### Summary
`MsgExecutePayload` mirrors the report's "permissionless route creation with unbounded/unvalidated parameters" pattern: any unprivileged account can submit it for free (it is in the gasless allowlist), supplying an attacker-controlled `UniversalPayload.GasLimit` that is validated only as "a valid non-negative integer" — with no upper bound — and is then passed straight through as the EVM `gasLimit` to a real, state-committing `DerivedEVMCall`.

### Finding Description
`MsgExecutePayload` is in the gasless message allowlist (`app/txpolicy/gasless.go`), so `DeductFeeDecorator` and `MinGasPriceDecorator` skip all Cosmos-level fee/gas-price checks for it [1](#0-0) , and any account may submit it — `Signer` need not equal the UEA owner [2](#0-1) .

`UniversalPayload.ValidateBasic()` only checks that `GasLimit` parses as a non-negative `uint256` string; there is no ceiling relative to the Push Chain block gas limit or any sane per-tx cap [3](#0-2) .

That unbounded value flows directly into `CallUEAExecutePayload`, which parses `universal_payload.GasLimit` into a `*big.Int` and passes it as the explicit `gasLimit` argument to `DerivedEVMCall` with `commit=true` (a real, state-changing EVM transaction) [4](#0-3) . `ExecutePayload` invokes this before any balance/fee check on the actual gas cost — fee deduction (`DeductGasFeesFromReceipt`) happens only *after* the EVM call already executed [5](#0-4) , and that deduction is based on `baseFee * gasUsed`, not on `GasLimit` [6](#0-5) .

Crucially, `DerivedEVMCall` is the Push-chain-specific EVM-call primitive documented as accepting an "explicit `gasLimit`" separate from normal Cosmos SDK gas metering, precisely so its computation isn't constrained by the outer Cosmos tx's declared gas [7](#0-6) . This is analogous to the `ForwarderHashedTimelockERC20.route()` bug: a permissionless entry point accepts an attacker-supplied numeric parameter with no upper bound, and that value is used to drive expensive/blocking protocol state (there, an infinite timelock blocking admin fund recovery; here, an effectively unbounded EVM computation budget executed for free).

### Impact Explanation
An unprivileged attacker can submit `MsgExecutePayload` transactions (paying zero Cosmos fee, since the message is gasless) whose `UniversalPayload.GasLimit` and `Data` are crafted to drive maximal EVM computation per call (e.g. targeting a UEA/contract with an expensive fallback or loop). Because the outer Cosmos tx pays no fee and the EVM gas limit is attacker-controlled with no protocol-level cap, repeated submission can consume disproportionate validator CPU/EVM execution time relative to zero attacker cost — a denial-of-service vector against block processing that is reachable purely through an ordinary unprivileged user's default transaction submission path, matching the in-scope "denial of service ... reachable without privileged control" impact category. The eventual `DeductGasFeesFromReceipt` failure (if the UEA has no funds) only causes the message to return an error/no persisted state change — it does not prevent the EVM computation from having already run.

### Likelihood Explanation
The precondition (an existing UEA, or a UEA auto-deployed via a pre-funded precomputed address, per `ExecutePayload`'s auto-deploy branch [8](#0-7) ) is attacker-achievable with a minimal funding step, and `MsgExecutePayload` requires no special permission or validator bonding — only `ValidateBasic()` and later cryptographic verification inside the UEA contract, which gate fund movement but not gas-limit magnitude. This makes the trigger straightforward for any external, unprivileged account.

### Recommendation
Enforce an explicit protocol-level upper bound on `UniversalPayload.GasLimit` in `ValidateBasic()` (e.g., capped well below the Push Chain block gas limit), reject payloads exceeding it before any EVM call is issued, and/or require a pre-execution balance/affordability check on the UEA before committing the `DerivedEVMCall`, so free (gasless) submissions cannot be used to buy unbounded EVM computation at zero cost.

### Proof of Concept
Not independently executed against a live node in this investigation (no runtime access); the trace above through `msg_execute_payload.go` → `evm.go` → `universal_payload.go`/`fees.go` demonstrates the code path allowing an unbounded, attacker-set `GasLimit` on a gasless, unprivileged message to reach a committing `DerivedEVMCall` before any gas-cost affordability check. Confirming actual resource-exhaustion magnitude would require running a devnet node and submitting `MsgExecutePayload` with a maximal `GasLimit` against a gas-heavy contract.

// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

| Parameter | Purpose |
|---|---|
| `ctx` | SDK context — provides block, gas meter, store access |
| `abi` | Parsed contract ABI for encoding the call |
| `from` | The EVM address that will appear as the tx sender. Can be a derived user address or a module account address. |
| `contract` | Destination contract |
| `value` | Native value to attach (`*big.Int`, may be `nil` or `big.NewInt(0)`) |
| `gasLimit` | Explicit gas limit (`nil` -> use a sensible default). Critical for predictable receipts. |
| `commit` | `true` = real state-changing tx; `false` = simulation / static call |
| `gasless` | `true` = skip gas accounting entirely. Used when the call is initiated by the protocol itself and shouldn't bill any user. |
| `isModuleSender` | `true` = `from` is a Cosmos module account (no private key). The fork's signer logic uses a deterministic synthetic signature instead of requiring a real ECDSA signature. |
| `manualNonce` | If non-`nil`, the caller supplies the nonce explicitly. This is what makes "many EVM calls in one block from the same module" deterministic — see [Manual Nonce Management](#manual-nonce-management). |
| `method` + `args` | Standard ABI-encoded call data |
