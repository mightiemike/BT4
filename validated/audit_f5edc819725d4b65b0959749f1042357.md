### Title
Unbounded `LinkedBlockingQueue` in filter result buffers permits heap-exhaustion DoS via `eth_newFilter` - ([File: framework/src/main/java/org/tron/core/services/jsonrpc/filters/FilterResult.java])

### Finding Description
`FilterResult<T>` declares `protected BlockingQueue<T> result` [1](#0-0) , and both concrete subclasses instantiate it as a no-arg `LinkedBlockingQueue<>()`, which is unbounded (`Integer.MAX_VALUE` capacity) [2](#0-1) [3](#0-2) .

Any unprivileged caller can invoke `eth_newFilter` (`TronJsonRpcImpl.newFilter`) to create a `LogFilterAndResult` matching all logs (empty address/topics) [4](#0-3) . Every subsequent block, `handleLogsFilter` → `processLogFilterEntry` matches logs against the filter and calls `logFilterAndResult.getResult().addAll(localResults)`, which appends unboundedly to the queue as long as the filter is not expired and the caller never drains it via `popAll()`/`eth_getFilterChanges` [5](#0-4) .

The only mitigations in the code are: (1) `maxLogFilterNum` caps the *number* of filters an `eventFilter2Result` map may hold [6](#0-5) , and (2) `EXPIRE_SECONDS` (300s) bounds how long a filter survives before `processLogFilterEntry` evicts it on the next `handleLogsFilter` call [7](#0-6) . Neither of these bounds the size of an individual filter's `result` queue while it is alive. The `logElementCache` is sized (300,000 entries, comment: "300s * tps(1000) * 1 log/tx") only to deduplicate `LogFilterElement` object instances across filters and does not cap the queue length; if actual matched-log volume during a 300s window exceeds that sizing assumption (or if multiple filters simultaneously accumulate elements), the per-filter and aggregate queue memory is not capped anywhere [8](#0-7) .

### Impact Explanation
Because `maxLogFilterNum` can permit many concurrent "match everything" filters (default depends on config, but not `1`) and each filter's queue can grow without limit for up to `EXPIRE_SECONDS` (300s), an attacker can drive memory growth proportional to `maxLogFilterNum × (matched logs in 300s)`. Sustained heap pressure can trigger GC thrashing or `OutOfMemoryError`, potentially causing a full node hosting the JSON-RPC service to become unresponsive or crash, disrupting `eth_*` API availability for all clients relying on that node (including wallets/dApps polling for TRC20 transfer events).

### Likelihood Explanation
`eth_newFilter` is a completely public, unauthenticated JSON-RPC endpoint reachable by anyone with network access to the node; no fee or accounting guard exists for holding a filter open and not draining it. The attack is trivially repeatable (create filter, never call `eth_getFilterChanges`/`eth_getFilterLogs`, repeat up to `maxLogFilterNum`). The actual growth rate is bounded by real on-chain log-emission throughput (not attacker-controlled beyond driving contract calls that emit logs), which somewhat limits the speed of the attack, but does not eliminate the unboundedness of the per-filter queue itself.

### Recommendation
Bound the `result` queue per filter (e.g., construct `LinkedBlockingQueue<>(MAX_QUEUE_SIZE)` and either drop oldest entries or reject/evict the filter with a `removed: true` marker when full), and/or enforce a maximum aggregate element count across all active filters, independent of the `logElementCache` sizing which serves a different purpose (dedup, not a hard cap).

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/jsonrpc/FilterQueueUnboundedTest.java
@Test
public void testFilterQueueGrowsUnboundedWithoutDrain() throws Exception {
  TronJsonRpcImpl jsonRpc = new TronJsonRpcImpl(null, null);
  FilterRequest fr = new FilterRequest(); // matches all logs
  LogFilterAndResult filter = new LogFilterAndResult(fr, 0L, null);
  jsonRpc.getEventFilter2ResultFull().put("attacker-filter", filter);

  // simulate high tps block production for < EXPIRE_SECONDS, never calling popAll()
  for (long blockNum = 1; blockNum <= 1_000_000; blockNum++) {
    List<TransactionInfo> txInfoList =
        Collections.singletonList(buildTxInfoWithLog(new byte[20]));
    LogsFilterCapsule capsule =
        new LogsFilterCapsule(blockNum, "0xabcdef" + blockNum, null, txInfoList, false, false);
    jsonRpc.handleLogsFilter(capsule);
  }

  // Expected (if bounded): queue size capped at some MAX_QUEUE_SIZE.
  // Actual: queue grows to 1,000,000 elements, demonstrating unbounded memory growth.
  Assert.assertTrue("queue should be capped but grew unbounded",
      filter.getResult().size() > 300_000); // exceeds logElementCache's documented 300s*tps sizing
}
```
This demonstrates that `LogFilterAndResult.result` (a `LinkedBlockingQueue`) has no enforced upper bound, allowing memory to grow proportionally to matched-log volume while a filter remains undrained within its 300s expiry window.

  private void processLogFilterEntry(
      Map.Entry<String, LogFilterAndResult> entry,
      Map<String, LogFilterAndResult> eventFilterMap,
      LogsFilterCapsule logsFilterCapsule) {
    LogFilterAndResult logFilterAndResult = entry.getValue();
    if (logFilterAndResult.isExpire()) {
      eventFilterMap.remove(entry.getKey());
      return;
    }

    long blockNumber = logsFilterCapsule.getBlockNumber();
    long fromBlock = logFilterAndResult.getLogFilterWrapper().getFromBlock();
    long toBlock = logFilterAndResult.getLogFilterWrapper().getToBlock();
    if (!(fromBlock <= blockNumber && blockNumber <= toBlock)) {
      return;
    }

    if (logsFilterCapsule.getBloom() != null && !logFilterAndResult.getLogFilterWrapper()
        .getLogFilter().matchBloom(logsFilterCapsule.getBloom())) {
      return;
    }

    LogFilter logFilter = logFilterAndResult.getLogFilterWrapper().getLogFilter();
    List<LogFilterElement> elements =
        LogMatch.matchBlock(logFilter, blockNumber, logsFilterCapsule.getBlockHash(),
            logsFilterCapsule.getTxInfoList(), logsFilterCapsule.isRemoved());

    List<LogFilterElement> localResults = new ArrayList<>(elements.size());
    for (LogFilterElement element : elements) {
      LogFilterElement cachedElement;
      try {
        // compare with hashcode() first, then with equals(). If not exist, put it.
        cachedElement = logElementCache.get(element, () -> element);
      } catch (ExecutionException e) {
        logger.error("Getting/loading LogFilterElement from cache fails", e); // never happen
        cachedElement = element;
      }
      localResults.add(cachedElement);
    }
    logFilterAndResult.getResult().addAll(localResults);
