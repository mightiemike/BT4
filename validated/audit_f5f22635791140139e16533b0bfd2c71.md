### Title
Panic on empty-calldata L1Handler transaction in `l1_handler_message_hash()` - ([File: crates/starknet_api/src/hash.rs])

### Summary
`l1_handler_message_hash()` unconditionally calls `calldata.0.split_first().expect(...)`, assuming an L1Handler transaction's calldata always contains at least the `from_address` element. `L1HandlerTransaction` and its `Calldata` type derive `Deserialize` with no non-empty invariant enforced, so this assumption can be violated by an L1Handler transaction whose calldata is empty, causing a panic analogous to the GTP kernel bug where an unchecked-length assumption on attacker-influenced input led to a crash.

### Finding Description
`l1_handler_message_hash()` computes the L1↔L2 message hash from an `L1HandlerTransaction`'s calldata: [1](#0-0) 

It does:
```rust
let (from_address, payload) =
    calldata.0.split_first().expect("Invalid calldata, expected at least from_address");
``` [2](#0-1) 

This `.expect()` panics if `calldata.0` is empty. Elsewhere in the codebase, the exact same "calldata could be empty" scenario is explicitly acknowledged and defended against with `saturating_sub` in `L1HandlerTransaction::payload_size()`: [3](#0-2) 

The comment there states directly: *"`saturating_sub` guards the empty-calldata case (which would otherwise underflow to `usize::MAX` in release): `L1HandlerTransaction` derives `Deserialize` and `Calldata` has no non-empty invariant."* This confirms that empty-calldata `L1HandlerTransaction` instances are a recognized, reachable state in this codebase — but the guard was only added in one call site (`payload_size`), not in `l1_handler_message_hash`/`calc_msg_hash`.

`calc_msg_hash()` is called on `L1HandlerTransaction` objects produced from scraped L1 events, and is invoked, e.g., when the `L1EventsProvider` logs proposed transactions during block proposal: [4](#0-3) 

It is also used by the RPC layer (`apollo_rpc/src/v0_8/api/api_impl.rs`) when exposing L1-to-L2 message hashes for `L1HandlerTransaction`s already accepted into blocks/state — a code path exercised for every historical or in-flight `L1HandlerTransaction`, without first checking `calldata` is non-empty.

This mirrors the GTP bug class precisely: a helper function is given a length precondition on attacker-influenced data ("payload always contains at least N leading bytes/felts"); the precondition is not enforced upstream (deserialization does not require non-empty calldata), and the helper panics instead of returning an error on the empty case.

### Impact Explanation
If an `L1HandlerTransaction` with empty `calldata` reaches `calc_msg_hash()` — e.g., through deserialization from storage/network/API without an intervening non-empty check, given calldata has "no non-empty invariant" as documented in the codebase itself — the sequencer process panics. A panic in a batcher/L1-events-provider path used during block proposal (`get_txs`) or in the RPC-serving path can crash the node process, causing that node to stop confirming/serving new transactions — i.e., a liveness impact on the affected sequencer node, consistent with "a network unable to confirm new transactions" if triggered broadly (e.g., replicated on all sequencer nodes processing the same malformed input).

### Likelihood Explanation
Likelihood depends on whether any reachable path can construct/deserialize an `L1HandlerTransaction` with empty calldata before it reaches `calc_msg_hash`. The codebase's own comment on `payload_size()` demonstrates this is considered a real, non-hypothetical possibility for `L1HandlerTransaction` given its `Deserialize` derivation and the lack of a non-empty-calldata invariant on `Calldata`. Whether the specific ingestion paths of `apollo_l1_events` or `apollo_rpc` validate calldata length before constructing/hashing such a transaction could not be fully confirmed with the tools available in this session — this is the primary point of uncertainty. A background engineering review of all `L1HandlerTransaction` construction/deserialization sites (L1 event scraping, RPC deserialization, storage read paths) is needed to determine definitively whether an attacker (a malicious/compromised L1 message, or a corrupted/replayed stored transaction) can drive an empty-calldata instance into `calc_msg_hash`.

### Recommendation
Replace the `.expect()` panic in `l1_handler_message_hash()` with a fallible check (return a `StarknetApiError`/`Result`) mirroring the defensive pattern already used in `L1HandlerTransaction::payload_size()`, so that empty calldata is rejected gracefully rather than causing a process panic. Additionally, audit all construction sites of `L1HandlerTransaction`/`ExecutableL1HandlerTransaction` (L1 event scraper, RPC message-from-L1 conversion, storage deserialization) to enforce a non-empty-calldata invariant as early as possible in the pipeline.

### Proof of Concept
Not fully constructible with the available read-only tooling — the exact reachability of an empty-calldata `L1HandlerTransaction` into `calc_msg_hash` (via L1 event scraping, RPC APIs, or storage deserialization bypassing gateway validation) could not be confirmed end-to-end in this session. A concrete PoC requires verifying, in a live/dev environment, whether any deserialization or construction path permits empty `calldata.0` before `calc_msg_hash()` is invoked (e.g., `crates/apollo_l1_events/src/l1_scraper.rs`, `crates/apollo_rpc/src/v0_8/transaction.rs`'s `MessageFromL1 -> L1HandlerTransaction` conversion, or storage-layer deserialization of previously stored transactions).

/// Calculating the message hash of L1 -> L2 message.
/// For more info: <https://docs.starknet.io/documentation/architecture_and_concepts/Network_Architecture/messaging-mechanism/#structure_and_hashing_l1-l2>
pub fn l1_handler_message_hash(
    contract_address: &ContractAddress,
    nonce: Nonce,
    entry_point_selector: &EntryPointSelector,
    calldata: &Calldata,
) -> L1L2MsgHash {
    let (from_address, payload) =
        calldata.0.split_first().expect("Invalid calldata, expected at least from_address");

    let mut encoded = Vec::new();
    encoded.extend(from_address.to_bytes_be());
    encoded.extend(contract_address.0.key().to_bytes_be());
    encoded.extend(nonce.to_bytes_be());
    encoded.extend(entry_point_selector.0.to_bytes_be());
```
