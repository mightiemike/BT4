### Title
`remove_dead_accounts` uses partial/truncated `get_account_data_lens` result without checking completeness, silently corrupting alive-byte/count accounting - (File: accounts-db/src/accounts_db.rs)

### Summary
`AppendVec::get_account_data_lens` can silently return fewer entries than the `sorted_offsets` slice it was given whenever it hits a read/layout condition it can't parse (I/O failure, truncated metadata, or an offset whose data would extend past the current file length), simply `break`-ing out of its loop early. `AccountsDb::remove_dead_accounts` calls this helper and then uses the (possibly truncated) `data_lens` to compute `dead_bytes` and to zip against the full `offsets` list for `mark_accounts_obsolete`, while separately passing the *original, unclipped* `offsets.len()` to `store.remove_accounts(dead_bytes, offsets.len())` — never checking whether `data_lens.len() == offsets.len()`. This is the same bug class as the reported Router issue: a sub-operation can be "partially filled" (fewer results/less output than requested) and the caller treats the call as if it fully succeeded.

### Finding Description
`get_account_data_lens` iterates `sorted_offsets` and pushes one size per offset, but `break`s (returning a short `Vec`) if:
- the buffer read fails, [1](#0-0) 
- `StoredMeta` can't be parsed from what was read, [2](#0-1) 
- or the computed end of the account's data would exceed the storage's current length. [3](#0-2) 

The function's own doc comment promises "for each offset in `sorted_offsets`, get the amount of data stored," implying a 1:1 mapping, but nothing in the return type (`Vec<usize>`) signals truncation to callers. [4](#0-3) 

`AccountsDb::remove_dead_accounts` consumes this result without any length check:
```
let data_lens = store.accounts.get_account_data_lens(&offsets);
let dead_bytes = data_lens
    .iter()
    .map(|len| store.accounts.calculate_stored_size(*len))
    .sum();
let remaining_accounts = store.remove_accounts(dead_bytes, offsets.len());
...
store.obsolete_accounts.write().unwrap().mark_accounts_obsolete(
    offsets.into_iter().zip(data_lens),
    slot_marked_obsolete,
);
``` [5](#0-4) 

If `data_lens` is shorter than `offsets`:
- `dead_bytes` only accounts for the truncated subset of accounts, yet `remove_accounts(dead_bytes, offsets.len())` is told that the **full** `offsets.len()` accounts were removed — decrementing the storage's alive `count` by more than the bytes actually reclaimed reflect. [6](#0-5) 
- `offsets.into_iter().zip(data_lens)` silently drops the tail offsets that lack a corresponding size, so those accounts are never inserted into `obsolete_accounts`, even though they were just logically "removed" from the alive count via `remove_accounts`. [7](#0-6) 

This mirrors the Router bug precisely: a helper (`get_account_data_lens`) can return a partial result instead of the full requested set, and the caller (`remove_dead_accounts`) has no check for "was this call partially filled?" before using the result as if it were complete, propagating an inconsistency into two independently-tracked pieces of state (`alive_bytes`/`count` in `AccountStorageEntry` vs. the `obsolete_accounts` bookkeeping used for hashing/shrink/clean).

### Impact Explanation
An under-reported `dead_bytes` combined with an over-reported removed-account `count` desynchronizes `AccountStorageEntry`'s alive-bytes/alive-count tracking from the actual obsolete-accounts records. This tracking directly feeds `is_candidate_for_shrink`/`alive_bytes_after_shrink` (shrink eligibility and shrink-triggered account rewrite), and the obsolete-accounts list is consulted by `AccountStorageReader`/lattice-hash and snapshot generation to skip dead bytes. [8](#0-7)  A mismatch here can cause a shrink pass to rewrite a storage while retaining or dropping the wrong bytes relative to what the index/hash machinery expects, producing storage/count vs. obsolete-list divergence and, in the worst case, a hash or capitalization mismatch between the live path and a snapshot-restored replica — an honest-node snapshot-vs-replay divergence.

### Likelihood Explanation
`get_account_data_lens` returning a truncated vector requires one of its break conditions to actually trigger for a legitimate offset (I/O read failure, or an offset in `reclaims` whose recorded size no longer fits within `self.len()`). The code path guards against concurrent shrink via `assert!(self.storage.no_shrink_in_progress())` [9](#0-8) , which suggests engineers are aware such races are hazardous, but the assertion only protects against one specific race (shrink running concurrently) and does not address I/O errors or any other path that could feed a stale/oversized offset into this call. I was not able to trace a concrete, always-reachable production trigger for the truncation branch within the indexing/tool available to me, so likelihood is moderate/uncertain rather than proven-common; it depends on hitting an I/O error or an offset/length mismatch that the `no_shrink_in_progress` assert doesn't already rule out.

### Recommendation
Make `get_account_data_lens` return a length-checked result (e.g., `Option<Vec<usize>>`, erroring or panicking if it can't produce an entry for every offset), and have `remove_dead_accounts` assert `data_lens.len() == offsets.len()` before computing `dead_bytes` and before zipping into `mark_accounts_obsolete`, treating a mismatch as a fatal/logged error rather than silently proceeding with a partial mapping.

### Proof of Concept
Not independently reproduced; this analysis is based on static code reading of `AppendVec::get_account_data_lens` [10](#0-9)  and its sole production consumer `AccountsDb::remove_dead_accounts` [11](#0-10) . Existing unit tests only exercise the "well-formed" path (`test_get_account_sizes`, `test_calculate_storage_count_and_alive_bytes_obsolete_account`) and never test what happens when `get_account_data_lens` returns fewer elements than `offsets.len()` is passed into `remove_dead_accounts`, so there is no existing test coverage proving the mismatch is currently detected or handled.     /// for each offset in `sorted_offsets`, get the the amount of data stored in the account.
    pub(crate) fn get_account_data_lens(&self, sorted_offsets: &[usize]) -> Vec<usize> {
        // self.len() is an atomic load, so only do it once
        let self_len = self.len();
        let mut account_sizes = Vec::with_capacity(sorted_offsets.len());
        let mut buffer = [MaybeUninit::<u8>::uninit(); mem::size_of::<StoredMeta>()];
        for &offset in sorted_offsets {
            // SAFETY: `read_into_buffer` will only write to uninitialized memory.
            let Some(bytes_read) = read_into_buffer(
                &self.file,
                self_len as FileSize,
                offset as FileSize,
                unsafe {
                    slice::from_raw_parts_mut(
                        buffer.as_mut_ptr() as *mut u8,
                        mem::size_of::<StoredMeta>(),
                    )
                },
            )
            .ok() else {
                break;
            };
            // SAFETY: we only read the initialized portion.
            let bytes = ValidSlice(unsafe {
                slice::from_raw_parts(buffer.as_ptr() as *const u8, bytes_read)
            });
            let Some((stored_meta, _)) = Self::get_type::<StoredMeta>(bytes, 0) else {
                break;
            };
            let next = Self::next_account_offset(offset, stored_meta);
            if next.offset_to_end_of_data > self_len {
                // data doesn't fit, so don't include
                break;
            }
            account_sizes.push(stored_meta.data_len as usize);
        }
        account_sizes
    }

    fn remove_dead_accounts<'a, I>(
        &'a self,
        reclaims: I,
        mark_accounts_obsolete: MarkAccountsObsolete,
    ) -> IntSet<Slot>
    where
        I: Iterator<Item = &'a (Slot, AccountInfo)>,
    {
        let mut reclaimed_offsets = SlotOffsets::default();

        assert!(self.storage.no_shrink_in_progress());

        let mut dead_slots = IntSet::default();
        let mut new_shrink_candidates = ShrinkCandidates::default();
        let mut measure = Measure::start("remove");
        for (slot, account_info) in reclaims {
            reclaimed_offsets
                .entry(*slot)
                .or_default()
                .insert(account_info.offset());
        }

        self.clean_accounts_stats
            .slots_cleaned
            .fetch_add(reclaimed_offsets.len() as u64, Ordering::Relaxed);

        reclaimed_offsets.into_iter().for_each(|(slot, offsets)| {
            if let Some(store) = self.storage.get_slot_storage_entry(slot) {
                assert_eq!(
                    slot,
                    store.slot(),
                    "AccountsDB::accounts_index corrupted. Storage pointed to: {}, expected: {}, \
                     should only point to one slot",
                    store.slot(),
                    slot
                );

                let remaining_accounts = if offsets.len() == store.count() {
                    // all remaining alive accounts in the storage are being removed, so the entire storage/slot is dead
                    store.remove_accounts(store.alive_bytes(), offsets.len())
                } else {
                    // not all accounts are being removed, so figure out sizes of accounts we are removing and update the alive bytes and alive account count
                    let (remaining_accounts, us) = measure_us!({
                        let mut offsets = offsets.iter().cloned().collect::<Vec<_>>();
                        // sort so offsets are in order. This improves efficiency of loading the accounts.
                        offsets.sort_unstable();
                        let data_lens = store.accounts.get_account_data_lens(&offsets);
                        let dead_bytes = data_lens
                            .iter()
                            .map(|len| store.accounts.calculate_stored_size(*len))
                            .sum();
                        let remaining_accounts = store.remove_accounts(dead_bytes, offsets.len());

                        if let MarkAccountsObsolete::Yes(slot_marked_obsolete) =
                            mark_accounts_obsolete
                        {
                            store
                                .obsolete_accounts
                                .write()
                                .unwrap()
                                .mark_accounts_obsolete(
                                    offsets.into_iter().zip(data_lens),
                                    slot_marked_obsolete,
                                );
                        }
                        remaining_accounts
                    });
                    self.clean_accounts_stats
                        .get_account_sizes_us
                        .fetch_add(us, Ordering::Relaxed);
                    remaining_accounts
                };

                // Check if we have removed all accounts from the storage
                // This may be different from the check above as this
                // can be multithreaded
                if remaining_accounts == 0 {
                    self.dirty_stores.insert(slot, store);
                    dead_slots.insert(slot);
                } else if self.is_shrinking_productive(&store)
                    && self.is_candidate_for_shrink(&store)
                {
                    // Checking that this single storage entry is ready for shrinking,
                    // should be a sufficient indication that the slot is ready to be shrunk
                    // because slots should only have one storage entry, namely the one that was
                    // created by `flush_slot_cache()`.
                    new_shrink_candidates.insert(slot);
                };
            }
        });

#[test_case(8)]
#[test_case(5)]
#[test_case(0)]
fn test_calculate_storage_count_and_alive_bytes_obsolete_account(
    num_accounts_to_mark_obsolete: usize,
) {
    let accounts = AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG);
    accounts.accounts_index.set_startup(Startup::Startup);

    let account_sizes = [1, 5, 10, 50, 100, 500, 1000, 2000];

    // Make sure we have enough accounts to mark obsolete. If this fails, just add more
    // entries to account_sizes
    assert!(account_sizes.len() >= num_accounts_to_mark_obsolete);

    let account_list: Vec<_> = account_sizes
        .into_iter()
        .map(|size| {
            (
                Pubkey::new_unique(),
                AccountSharedData::new(1, size, AccountSharedData::default().owner()),
            )
        })
        .collect();

    let slot0 = 0;
    let storage = accounts.create_store(slot0, 10_000);
    let offsets = storage.accounts.write_accounts(&(slot0, &account_list[..]));

    let offsets = offsets.unwrap().offsets;
    let data_lens = storage.accounts.get_account_data_lens(&offsets);
    let mut offsets: Vec<_> = offsets.into_iter().zip(data_lens).collect();

    // Randomize the accounts that get marked obsolete
    let mut rng = rand::rng();
    offsets.shuffle(&mut rng);

    let (accounts_to_mark_obsolete, accounts_to_keep) =
        offsets.split_at(num_accounts_to_mark_obsolete);

    storage
        .obsolete_accounts
        .write()
        .unwrap()
        .mark_accounts_obsolete(accounts_to_mark_obsolete.iter().cloned(), slot0 + 1);

    let mut reader = crate::append_vec::new_scan_accounts_reader();
    let mut accum = IndexGenerationAccumulator::with_slots_capacity(1);
    accounts.generate_index_for_slot(&mut reader, &mut accum, 0, &storage);
    assert_eq!(
        accum.num_obsolete_accounts_skipped,
        num_accounts_to_mark_obsolete as u64
    );
    assert_eq!(
        accum.storage_info.len(),
        if num_accounts_to_mark_obsolete < account_sizes.len() {
            1
        } else {
            0
        }
    );

    for (slot, value) in accum.storage_info {
        // Sum up the stored size of all non obsolete accounts
        let expected_stored_size: usize = accounts_to_keep
            .iter()
            .map(|(_, data_len)| storage.accounts.calculate_stored_size(*data_len))
            .sum();

        assert_eq!(
            (slot, value.count, value.stored_size),
            (0, accounts_to_keep.len(), expected_stored_size)
        );
    }
    accounts.accounts_index.set_startup(Startup::Normal);
}
