### Title
Chain-selector-keyed blessed/unblessed classification in `CommitPluginCodecV1.Encode` silently reclassifies unblessed merkle roots as blessed when a `ChainSelector` collision occurs - ([File: core/capabilities/ccip/ccipevm/commitcodec.go])

### Summary
`CommitPluginCodecV1.Encode` classifies each `MerkleRootChain` as blessed or unblessed using a `map[cciptypes.ChainSelector]bool` keyed only by `ChainSel`, rather than by the identity of the individual root. If `report.BlessedMerkleRoots` and `report.UnblessedMerkleRoots` both contain an entry with the same `ChainSel` (a legitimate scenario since CCIP supports multiple merkle roots per report, `MaxMerkleRootsPerReport`), the unblessed entry is incorrectly bucketed into the blessed list on encode, and the corruption is preserved (not fixed) by `Decode`, since `Decode` performs the identical chain-selector-only classification against the already-corrupted `commitReport.BlessedMerkleRoots`/`UnblessedMerkleRoots` arrays it receives. This breaks the round-trip/lossless invariant `Decode(Encode(x)) == x` for such inputs.

### Finding Description
In `Encode` (`core/capabilities/ccip/ccipevm/commitcodec.go:30-52`):
```go
isBlessed := make(map[cciptypes.ChainSelector]bool)
for _, root := range report.BlessedMerkleRoots {
    isBlessed[root.ChainSel] = true
}
...
for _, root := range append(report.BlessedMerkleRoots, report.UnblessedMerkleRoots...) {
    ...
    if isBl, ok := isBlessed[root.ChainSel]; ok && isBl {
        blessedMerkleRoots = append(blessedMerkleRoots, imr)
    } else {
        unblessedMerkleRoots = append(unblessedMerkleRoots, imr)
    }
}
``` [1](#0-0) 

The map is keyed purely by `ChainSelector`, not by the merkle root's identity (e.g. `MerkleRoot` hash, `OnRampAddress`, or `SeqNumsRange`). If `report.UnblessedMerkleRoots` contains a root whose `ChainSel` also appears in `report.BlessedMerkleRoots` (a different root for the same source chain, e.g. a second batch/root for the same chain that RMN has not yet blessed), the lookup `isBlessed[root.ChainSel]` returns `true` for that unblessed root too, so it is silently moved into `blessedMerkleRoots`. This mirrors the misclassification logic in `Decode` (`core/capabilities/ccip/ccipevm/commitcodec.go:124-146`), which performs the same chain-selector-only bucketing on the already-corrupted arrays it receives from ABI unpacking, so the corruption is not "self-healing" on decode.

CCIP explicitly supports multiple merkle roots per commit report via config knobs like `MaxMerkleRootsPerReport`, and the ccipsolana codec's own test suite contains an explicit case titled `"both blessed and unblessed merkle roots"` that treats a shared root between the two lists as an error condition — showing this is a recognized cross-codec risk that the EVM codec (`ccipevm/commitcodec.go`) does not guard against, unlike Solana's codec, which errors out (`ccipsolana/commitcodec.go:86-104`). [2](#0-1) 

The EVM codec's own unit test (`ccipevm/commitcodec_test.go:16-138`) never exercises this collision scenario because it generates `ChainSel` values independently via `rand.Uint64()` for the blessed and unblessed lists, so a collision essentially never occurs randomly, masking the bug. [3](#0-2) 

### Impact Explanation
"Blessed" status of a merkle root signals that the root has passed RMN (Risk Management Network) verification. If an unblessed root is silently reclassified as blessed due to a `ChainSelector` collision with a genuinely blessed root in the same report, the resulting on-chain `OffRampCommitReport` (produced by `Encode` and eventually submitted to the `OffRamp` contract) will present that root's messages as RMN-blessed when they were not actually verified. This is a data-integrity/misreporting bug in consensus-critical CCIP commit report encoding: it can cause the on-chain committed report to diverge from the intended semantics of the off-chain-agreed `CommitPluginReport`, and downstream `Execute` plugin logic or contract-level blessing checks could treat unverified messages as blessed, weakening the RMN protection this fields is meant to enforce. It also independently breaks the lossless round-trip invariant relied upon anywhere reports are re-decoded and compared (e.g. `CommitReportsGTETimestamp` consumers).

### Likelihood Explanation
This requires no privileged access — it is triggered purely by the *content* of a `CommitPluginReport` that legitimately can contain two different merkle roots for the same source `ChainSelector`, one blessed and one not, which is plausible whenever `MaxMerkleRootsPerReport` config batches multiple roots and RMN blessing is partial/per-root rather than per-chain. The bug is deterministic given such an input, always reproducible, and not gated by any existing validation in `Encode`.

### Recommendation
Track blessed status per-root (e.g., key the classification map by a composite of `ChainSel + MerkleRoot + SeqNumsRange`, or simply retain the caller's classification by building `blessedMerkleRoots`/`unblessedMerkleRoots` directly from `report.BlessedMerkleRoots` and `report.UnblessedMerkleRoots` respectively instead of merging and reclassifying by chain selector). Add a fuzz/property test asserting `reflect.DeepEqual(x, Decode(Encode(x)))` including cases where the same `ChainSel` appears in both `BlessedMerkleRoots` and `UnblessedMerkleRoots`.

### Proof of Concept
```go
func TestCommitPluginCodecV1_BlessedUnblessedChainSelCollision(t *testing.T) {
    chainSel := cciptypes.ChainSelector(rand.Uint64())
    blessedRoot := cciptypes.MerkleRootChain{
        ChainSel: chainSel,
        OnRampAddress: common.LeftPadBytes(utils.RandomAddress().Bytes(), 32),
        SeqNumsRange: cciptypes.NewSeqNumRange(1, 10),
        MerkleRoot: utils.RandomBytes32(),
    }
    unblessedRoot := cciptypes.MerkleRootChain{
        ChainSel: chainSel, // same ChainSel, different root
        OnRampAddress: common.LeftPadBytes(utils.RandomAddress().Bytes(), 32),
        SeqNumsRange: cciptypes.NewSeqNumRange(11, 20),
        MerkleRoot: utils.RandomBytes32(),
    }
    report := cciptypes.CommitPluginReport{
        BlessedMerkleRoots:   []cciptypes.MerkleRootChain{blessedRoot},
        UnblessedMerkleRoots: []cciptypes.MerkleRootChain{unblessedRoot},
    }
    codec := NewCommitPluginCodecV1()
    encoded, err := codec.Encode(t.Context(), report)
    require.NoError(t, err)
    decoded, err := codec.Decode(t.Context(), encoded)
    require.NoError(t, err)

    // Expectation: unblessedRoot should remain unblessed.
    require.Len(t, decoded.UnblessedMerkleRoots, 1, "unblessed root was incorrectly reclassified as blessed")
    require.Equal(t, unblessedRoot.MerkleRoot, decoded.UnblessedMerkleRoots[0].MerkleRoot)
    // This assertion is expected to FAIL against current code, demonstrating the bug:
    require.True(t, reflect.DeepEqual(report, decoded))
}
```

func (c *CommitPluginCodecV1) Encode(ctx context.Context, report cciptypes.CommitPluginReport) ([]byte, error) {
	isBlessed := make(map[cciptypes.ChainSelector]bool)
	for _, root := range report.BlessedMerkleRoots {
		isBlessed[root.ChainSel] = true
	}

	blessedMerkleRoots := make([]ccip_encoding_utils.InternalMerkleRoot, 0, len(report.BlessedMerkleRoots))
	unblessedMerkleRoots := make([]ccip_encoding_utils.InternalMerkleRoot, 0, len(report.UnblessedMerkleRoots))
	for _, root := range append(report.BlessedMerkleRoots, report.UnblessedMerkleRoots...) {
		imr := ccip_encoding_utils.InternalMerkleRoot{
			SourceChainSelector: uint64(root.ChainSel),
