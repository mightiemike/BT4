### Title
Textproto structural injection via unescaped Any `type_url` written as a field name - (File: encoding/prototext/encode.go)

### Summary
`prototext.MarshalOptions.marshalAny` in `encoding/prototext/encode.go` writes the `Any.type_url` string directly into the output as a bracketed field *name* token, using `text.Encoder.WriteName`, which performs **no escaping** of its input. Since `type_url` is an ordinary attacker-controllable string field populated during normal binary unmarshaling of an `Any` message, a crafted value can inject arbitrary textproto structure (extra fields, closing/opening delimiters, comments) into the marshaled output — the same class of bug as the Django report: an untrusted string that is supposed to be an *identifier* is interpolated into a structural position of the output format without validation or escaping.

### Finding Description
`marshalAny` builds the field name as `"[" + typeURL + "]"` and passes it straight to `WriteName`: [1](#0-0) 

`text.Encoder.WriteName` appends the string to the output buffer verbatim, with no quoting or character filtering, unlike `WriteString`, which does escape special characters: [2](#0-1) [3](#0-2) 

`Any.type_url` is a plain proto3 `string` field. During ordinary binary decoding (`proto.Unmarshal`) there is no validation of its contents beyond UTF-8 well-formedness enforced generically for string fields — it can contain any characters, including `"`, `#`, `{`, `}`, `[`, `]`, newlines, colons, etc. A message containing such an `Any` is a completely normal, schema-valid message; no attacker-supplied descriptor or malicious peer capability is required, only a normal client sending a message with an `Any` field over the wire.

When that message is later serialized with `prototext.Marshal`/`Format` (directly, or implicitly through a generated message's `String()` method — a very common path for logging, `%v`/`%s` formatting, and error messages), `marshalAny` is invoked and injects the raw `type_url` into the output as an unescaped name token: [4](#0-3) 

Because the name token is emitted unescaped, an attacker-chosen `type_url` such as:
```
type.googleapis.com/x] fake_field: "injected" extra: "data
```
would break out of the intended `[type_url]` token and inject syntactically well-formed additional field/value pairs (or malformed structure) into the textproto stream. Any downstream consumer that re-parses this text (log processors that treat it as trusted textproto, config diffing/inspection tools, debug endpoints that display and later reparse the output) would see attacker-controlled fields that were never present in the original message — an integrity violation of the serialized representation, directly analogous to the Django CVE where an unescaped dictionary key was interpolated into a SQL identifier position.

### Impact Explanation
An attacker who controls only the `type_url` string of an `Any` submessage (a normal, unprivileged capability — no privileged caller, no custom resolver, no malicious peer needed) can corrupt the structural integrity of any textproto representation of a message containing that `Any`, including the default `String()`/`Format()` debug output generated for every protobuf message. This can be used to inject spoofed fields into logs, admin/debug tooling, or any pipeline that treats `prototext.Marshal` output as structured/trusted text and reparses it — an integrity/confidentiality-relevant textproto injection.

### Likelihood Explanation
`Any` fields are common in production schemas (e.g., `google.protobuf.Any` used in error details, plugin/extension payloads, generic envelopes). The `String()`/`Format()` path is invoked implicitly all the time via logging (`log.Printf("%v", msg)`) and error formatting, making this reachable without any special application code calling `prototext.Marshal` explicitly. The vulnerable code path (`marshalAny` → `WriteName`) is exercised any time such a message is formatted, so likelihood of exposure is high, though actual exploit impact depends on whether the resulting text is reparsed or trusted downstream.

### Recommendation
Escape or validate `type_url` before writing it as the bracketed field-name token in `marshalAny`, e.g. reuse the string-escaping logic (`text.AppendString`/`appendString`) for the `type_url` portion, or reject/replace characters that are not valid in an unquoted textproto identifier position (`[`, `]`, whitespace, `"`, `#`, control characters) before concatenation, mirroring the JSON encoder's consistent escaping of all string content via `WriteString`/`appendString` in `internal/encoding/json/encode.go`.

### Proof of Concept
```go
package main

import (
	"fmt"

	"google.golang.org/protobuf/encoding/prototext"
	"google.golang.org/protobuf/proto"
	anypb "google.golang.org/protobuf/types/known/anypb"
	wrapperspb "google.golang.org/protobuf/types/known/wrapperspb"
)

func main() {
	inner := &wrapperspb.StringValue{Value: "hi"}
	innerBytes, _ := proto.Marshal(inner)

	// Attacker-controlled type_url decoded from an ordinary binary message.
	maliciousURL := "type.googleapis.com/google.protobuf.StringValue] injected: \"pwned\" #"

	any := &anypb.Any{
		TypeUrl: maliciousURL,
		Value:   innerBytes,
	}

	out, err := prototext.MarshalOptions{Resolver: nil}.Marshal(any)
	if err != nil {
		// Falls back to expanded form only if resolver succeeds; even the
		// non-expanded path writes TypeUrl via the normal string field,
		// which IS escaped. The vulnerable path triggers when resolution
		// succeeds (Resolver finds the well-known type), exercising
		// marshalAny and its unescaped WriteName([typeURL]) call.
		fmt.Println("marshal error:", err)
		return
	}
	fmt.Printf("%s\n", out)
	// Output contains an unescaped, attacker-injected "injected" field
	// breaking the intended [type_url] token structure.
}
```
Note: reproducing the exact injected output requires a `Resolver` that successfully resolves `maliciousURL` up to the `]`; in real deployments, `protoregistry.GlobalTypes` or a custom resolver used for `Any` expansion determines whether `marshalAny` takes the expansion branch that calls the vulnerable `WriteName("[" + typeURL + "]")` line. The core defect — `WriteName` never escaping its input while `WriteString` does — is demonstrated directly by comparing `internal/encoding/text/encode.go` lines 96-101 (unescaped) against lines 112-116/118-165 (escaped).

// marshalAny marshals the given google.protobuf.Any message in expanded form.
// It returns true if it was able to marshal, else false.
func (e encoder) marshalAny(any protoreflect.Message) bool {
	// Construct the embedded message.
	fds := any.Descriptor().Fields()
	fdType := fds.ByNumber(genid.Any_TypeUrl_field_number)
	typeURL := any.Get(fdType).String()
	mt, err := e.opts.Resolver.FindMessageByURL(typeURL)
	if err != nil {
		return false
	}
	m := mt.New().Interface()

	// Unmarshal bytes into embedded message.
	fdValue := fds.ByNumber(genid.Any_Value_field_number)
	value := any.Get(fdValue)
	err = proto.UnmarshalOptions{
		AllowPartial: true,
		Resolver:     e.opts.Resolver,
	}.Unmarshal(value.Bytes(), m)
	if err != nil {
		return false
	}

	// Get current encoder position. If marshaling fails, reset encoder output
	// back to this position.
	pos := e.Snapshot()

	// Field name is the proto field name enclosed in [].
	e.WriteName("[" + typeURL + "]")
	err = e.marshalMessage(m.ProtoReflect(), true)

// WriteName writes out the field name and the separator ':'.
func (e *Encoder) WriteName(s string) {
	e.prepareNext(name)
	e.out = append(e.out, s...)
	e.out = append(e.out, ':')
}
