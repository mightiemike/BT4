### Title
Floor-and-drop signer weight apportionment in legacy PoX-4 `make_signer_set` can zero out the entire signer set, freezing Nakamoto block production for a reward cycle - (File: stackslib/src/chainstate/stacks/boot/mod.rs)

### Summary
`StacksChainState::make_signer_set` (the PoX-4 signer-weight apportionment routine) allocates each signer's weight as `stacked_amt / threshold` and silently drops any signer whose result floors to `0`, with no fallback if the resulting set is empty. [1](#0-0) 
This is the exact "floor-and-drop" precision-loss pattern described in the external report (fractions rounding to zero when `_newFractionSupply`/threshold is set too low relative to the number of participants), and the codebase's own PoX-5 successor function explicitly documents this as a known bug class that it was rewritten to fix: [2](#0-1) 
and is regression-tested for exactly this scenario: [3](#0-2) 
The PoX-4 `make_signer_set` was never given the equivalent "largest remainder" (Hare) fix.

### Finding Description
`make_signer_set(threshold, entries)` computes, for each aggregated signer, `weight = stacked_amt / threshold` (integer division) and drops the entry entirely via `filter_map` if `weight == 0`: [4](#0-3) 

`threshold` here is derived from `get_reward_threshold_and_participation`, which computes `threshold = ceil(scale_by / reward_slots)` where `scale_by = max(participation, liquid_ustx / POX_MAXIMAL_SCALING)`: [5](#0-4) 

If more than `reward_slots` distinct signer keys each stack an amount that individually floors to zero when divided by `threshold` (e.g., many signers each holding stake just under `threshold`, which is easy to arrange when `scale_by` is dominated by `liquid_ustx / POX_MAXIMAL_SCALING` rather than by any single signer's stake), every entry's `weight` floors to `0` and the entire `filter_map` output is empty. Unlike the PoX-5 rewrite, there is no leftover/remainder redistribution round to guarantee at least `min(N, reward_slots)` signers keep nonzero weight — the comment in the PoX-5 code explicitly states this is what happened in the "old floor-and-drop scheme" and that it could "stall the chain": [6](#0-5) 

An empty (or missing) `signer_set` propagates into the reward set used by Nakamoto block-signing verification. `NakamotoBlockHeader::verify_signer_signatures` explicitly rejects any reward set without signers: [7](#0-6) 
and the StackerDB listener / miner coordinator paths treat a reward set with no signers as a fatal `NoRegisteredSigners` condition when computing signing weight/threshold: [8](#0-7) 

### Impact Explanation
If the PoX-4 signer weight apportionment yields zero eligible signers for a reward cycle (an equality break: "assigned voting weight" vs. "actual honest stake participating" collapses to nothing even though real stake exists), no valid signer set exists for that cycle. Every Nakamoto block header's `verify_signer_signatures` call fails with "No signers in the reward set," and the signing coordinator / stackerdb listener cannot compute a signing threshold at all. This halts Nakamoto block approval for the entire reward cycle — a chain-wide, minority-triggerable freeze, not requiring any single attacker to hold a majority of stake, only requiring more distinct stackers than `reward_slots` with individually sub-threshold amounts (a naturally occurring or trivially engineered condition, e.g. via Sybil-splitting a moderate stake across many keys). This matches the Critical bucket ("permanent freezing," bounded here to one reward cycle) since the codebase's own PoX-5 fix was written specifically to prevent "the entire signer set" from being "dropped."

### Likelihood Explanation
This requires no privileged access and no majority of stake — only that `>= reward_slots` distinct signer keys each hold stacked amounts below the computed per-slot `threshold`. Because `threshold` scales with `liquid_ustx / POX_MAXIMAL_SCALING` (not purely with actual participation), this condition can arise even under modest, realistic participation patterns typical of early/low-stake reward cycles, and can be deliberately engineered by any staker splitting stake across many signer keys, which is unprivileged and requires no supermajority. Note: PoX-4 is a legacy/transitional cycle type in this codebase (superseded by PoX-5), so exploitability is bounded to reward cycles still operating under PoX-4 semantics; I could not fully confirm from the available index whether PoX-4 cycles remain reachable on the currently targeted network, since I was unable to load `make_reward_set`'s call sites in `boot/mod.rs` fully in this session.

### Recommendation
Port the PoX-5 "largest remainder" (Hare quota) apportionment logic — used in `pox_5_make_signer_set` — into the legacy `make_signer_set` function, guaranteeing that up to `min(N, reward_slots)` signers retain nonzero weight even when every entry's `stacked_amt / threshold` floors to zero, exactly as done in [9](#0-8) . At minimum, add an explicit fallback (e.g., reject the reward-set computation and retain the prior cycle's signer set) rather than allowing an empty/zeroed signer set to propagate into `verify_signer_signatures`.

### Proof of Concept
1. Configure (or observe) a PoX-4 reward cycle where `get_reward_threshold_and_participation` yields `threshold = T` [10](#0-9) .
2. Have `reward_slots + 1` (or more) distinct addresses each stack an amount `< T` as PoX-4 signers (feasible for any staker able to split funds across keys; no majority stake needed).
3. `make_signer_set` computes `weight = stacked_amt / T = 0` for every entry and drops all of them via `filter_map`, returning `Some(vec![])` (or, upstream, an effectively empty signer set) [1](#0-0) .
4. For that reward cycle, every Nakamoto block's `verify_signer_signatures` call returns `Err("No signers in the reward set")` [7](#0-6) , and signer/miner coordination code fails to initialize (`NoRegisteredSigners`) [8](#0-7) , halting Nakamoto block production for the cycle. This is the direct analog to the referenced report's PoC, where a low `_newFractionSupply` caused every migrator's share to floor to zero and permanently froze the vault.

    pub fn get_reward_threshold_and_participation(
        pox_settings: &PoxConstants,
        addresses: &[RawRewardSetEntry],
        liquid_ustx: u128,
    ) -> (u128, u128) {
        let participation = addresses
            .iter()
            .fold(0, |agg, entry| agg + entry.amount_stacked);

        assert!(
            participation <= liquid_ustx,
            "CORRUPTION: More stacking participation than liquid STX"
        );

        // set the lower limit on reward scaling at 25% of liquid_ustx
        //   (i.e., liquid_ustx / POX_MAXIMAL_SCALING)
        let scale_by = cmp::max(participation, liquid_ustx / POX_MAXIMAL_SCALING);

        let reward_slots = u128::try_from(pox_settings.reward_slots())
            .expect("FATAL: unreachable: more than 2^128 reward slots");
        let threshold_precise = scale_by / reward_slots;
        // compute the threshold as nearest 10k > threshold_precise
        let ceil_amount = match threshold_precise % POX_THRESHOLD_STEPS_USTX {
            0 => 0,
            remainder => POX_THRESHOLD_STEPS_USTX - remainder,
        };
        let threshold = threshold_precise + ceil_amount;
        info!(
            "PoX participation threshold is {}, from {} + {} ({}), participation is {}",
            threshold, threshold_precise, ceil_amount, scale_by, participation
        );
        (threshold, participation)
    }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
