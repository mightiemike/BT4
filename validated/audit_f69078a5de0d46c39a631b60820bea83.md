**Rationale:** The premise requires that an attacker get "a shadow-marked Nakamoto block accepted as parent" through normal chain operation, i.e. a `NakamotoBlockHeader` with the `0x80` high bit set to be admitted into a target node's `nakamoto_block_headers` table via network broadcast. That precondition is unreachable for an unprivileged network participant:

- Any incoming block (pushed, downloaded, or received) is checked in `process_new_nakamoto_block_ext` and is unconditionally dropped as soon as `block.is_shadow_block()` is true, before any other validation runs: [1](#0-0) 
- Shadow blocks are the only category of Nakamoto block whose `is_shadow_block()` header flag is honored; they are documented and implemented as blocks inserted directly into the staging DB as part of a node software/schema upgrade (i.e., a consensus-level SIP process), not something broadcast, mined, or accepted from the p2p network: [2](#0-1) 
- `accept_block` itself branches on `block.is_shadow_block()`, and for that branch it requires the block to *already* be present in staging via `has_shadow_nakamoto_block_with_index_hash`, panicking (`"Unacceptable shadow Nakamoto block"`) if the shadow-specific validation fails — again confirming shadow blocks are pre-seeded, not attacker-submitted: [3](#0-2) 

Because an unprivileged attacker cannot cause any honest node to store a block with the shadow bit set as a legitimate parent (the p2p/relay layer discards such blocks outright, and shadow blocks only exist as pre-inserted, software-defined migration artifacts), the described call sequence in `check_nakamoto_tenure` (`stackslib/src/chainstate/nakamoto/tenure.rs:737-750`) can never observe `is_parent_shadow_block == true` for an attacker-controlled parent while `prev_sn.sortition == false`. The `is_parent_shadow_block` bypass of the `!prev_sn.sortition` rejection is only reachable for genuine shadow tenures created by trusted node-software upgrades, which are out of scope for an unprivileged attacker per the rules (no privileged role, no compromised dependency/node-operator path). The equality `prev_sn.sortition == true` whenever `is_parent_shadow_block == false` therefore still holds for any block an unprivileged attacker can actually get accepted.
