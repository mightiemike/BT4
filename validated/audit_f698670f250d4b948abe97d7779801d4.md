### Title
Fixed 5% slippage swap quote sourced from a manipulable on-chain AMM spot price (Uniswap V3 `Quoter`) allows value extraction from inbound gas-abstraction swaps - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The external report describes LP token valuation relying on a price source (Chainlink/Band oracle) that cannot price the underlying asset, causing reverts. The closest reachable analog in Push Chain's scoped code is not a revert-DoS (that path is already handled gracefully — see below) but a **pricing-integrity** issue in the gas-abstraction auto-swap flow: `ExecuteInboundGas` fetches a swap quote directly from an on-chain AMM `Quoter` contract and applies only a fixed 5% slippage tolerance, with no TWAP or external price-oracle cross-check [1](#0-0) .

### Finding Description
When an inbound `GAS`-type transaction reaches validator quorum, `ExecuteInboundGas` resolves the quoter address, WPC address, and fee tier, then calls `k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)` to get a single spot-price quote, and computes `minPCOut = quote * 95 / 100` before calling `k.CallPRC20DepositAutoSwap` [2](#0-1) . This mirrors the ICHI bug's root cause conceptually inverted: instead of "no oracle exists so the call reverts," here a price *is* obtained, but it is sourced from the same instantaneous AMM pool that the swap itself will execute against, with no robust (TWAP-based or externally-verified) reference price. The quote is fetched and consumed within the same message-execution flow (triggered by the quorum-completing `MsgVoteInbound`), so any unprivileged actor who observes the pending quorum-completing vote transaction in the mempool can front-run it with an ordinary DEX trade against the same WPC/PRC20 pool to move the spot price, then back-run to restore it — a classic sandwich attack. The fixed 5% tolerance is a static bound unrelated to real market conditions and does not protect against pool manipulation within the same block window.

### Impact Explanation
This falls within "corruption of PRC20 or native asset accounting" and "gas fee accounting" invariants in-scope for the universal execution flow. An attacker can extract value from the swapped amount belonging to the depositing user (or from protocol-held liquidity) during the gasless/gas-abstraction auto-swap step, without needing any privileged role — this is a normal DEX trade plus timing around a public mempool event. Funds are not "stolen" outright from custody, but the guaranteed swap output is degraded below fair value by an amount up to the full 5% slippage band (or more, depending on pool depth), which is a material, repeatable value drain reachable by any user submitting ordinary deposits.

### Likelihood Explanation
Likelihood is moderate-to-high in principle: it requires (a) visibility into the mempool for the quorum-completing vote transaction, and (b) sufficient capital/flash-loan access to move the specific WPC/PRC20 pool price within the 5% band. Cosmos SDK block production and validator set composition affect actual front-running feasibility (this is not a strict Ethereum public mempool), which introduces uncertainty about how easily an outside, non-validator attacker can time the sandwich in this specific chain's block-production model. I was not able to fully verify `GetSwapQuote`'s underlying ABI call (which AMM/Quoter version and whether it uses `quoteExactInputSingle` against live reserves) or whether any additional protections exist elsewhere in `evm.go`, since the exact implementation body was not retrieved before the tool budget was exhausted.

### Recommendation
Do not derive `minPCOut` from a single spot-price call to a live AMM `Quoter` that the same execution flow will trade against. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks, or a combination of TWAP plus a maximum single-block deviation check) before computing slippage bounds, or clamp/validate the spot quote against a recent TWAP before accepting it — directly analogous to the ICHI report's own recommendation of using an AMM TWAP as a robust price source.

### Proof of Concept
Conceptual (not fully executable without further verification of `GetSwapQuote`'s exact on-chain call target):
1. Attacker monitors the Push Chain mempool for the third/quorum-completing `MsgVoteInbound` for a pending `TxType_GAS` inbound.
2. Attacker submits a large trade against the same WPC/PRC20 pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`, pushing the spot price down just before the quorum vote lands.
3. The quorum vote executes `ExecuteInboundGas`, which calls `GetSwapQuote` against the now-manipulated pool and computes `minPCOut` from that skewed quote, then executes `CallPRC20DepositAutoSwap` at the manipulated price.
4. Attacker reverses their initial trade, capturing the price difference at the depositing user's (or protocol's) expense.

**Caveat**: Confirming this requires inspecting the full body of `GetSwapQuote`, `GetDefaultFeeTierForToken`, and `CallPRC20DepositAutoSwap` in `x/uexecutor/keeper/evm.go`, which I was unable to fully retrieve in the time available. I recommend a follow-up review of that file, and of how/when `MsgVoteInbound` execution is ordered relative to the underlying AMM pool's state transitions in a block, to confirm the sandwich window actually exists in this chain's specific consensus/mempool model before treating this as fully confirmed.
