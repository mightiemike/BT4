### Title
Global, non-namespaced `requestID` map in HTTP Trigger Gateway handler allows any user to grief/DoS another user's workflow trigger by reusing the same request ID - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The Workflow HTTP Trigger gateway handler tracks in-flight trigger requests in a single map keyed only by the caller-supplied JSON-RPC `id` (`requestID`), with no binding to the workflow, workflow owner, or caller identity. Any unprivileged caller who can invoke `workflows.execute` for *any* workflow can pick the same `requestID` that another, unrelated caller is about to use (or is already using) for a *different* workflow, causing the legitimate request to be rejected outright. This mirrors the zAuction bug class: a shared/global unique-identifier namespace that is *chosen by the untrusted caller* and is not bound to the entity that "owns" the ID, enabling front-running/griefing that terminates someone else's in-flight operation.

### Finding Description
`httpTriggerHandler` stores pending requests in: [1](#0-0) 

`setupCallback` is the function that registers a new pending request and enforces uniqueness purely by the raw `requestID` string: [2](#0-1) 

The only validation applied to `requestID` before it reaches this map is that it is non-empty and does not contain `/`: [3](#0-2) 

Critically, `authorizeRequest` and `checkRateLimit` are scoped to `workflowID`, but the `h.callbacks` map key (`requestID`) is *not* namespaced by `workflowID` or by the authorized caller/key at all: [4](#0-3) 

This means the `requestID` collision domain spans **every workflow and every caller served by this gateway/DON**, not just a single workflow or a single caller's session. If two different, unrelated callers (Alice triggering workflow W1, Mallory triggering workflow W2 that Mallory legitimately has access to) submit requests with the same `id`, whichever request reaches `setupCallback` first "wins" and the second is rejected with `ErrConflict` before ever being dispatched to DON nodes: [5](#0-4) 

The existing test only demonstrates same-caller/same-workflow duplicate-ID rejection, which is intended behavior; it does not test/guard against the cross-workflow/cross-caller collision scenario: [6](#0-5) 

This is directly analogous to the zAuction root cause: a unique action identifier chosen by an untrusted party is used as the sole termination key in a global namespace, instead of being bound to the initiating principal (e.g., `owner+workflowID+requestID`).

### Impact Explanation
An attacker with valid authorization to trigger *any* workflow on the same gateway/DON (an unprivileged, otherwise-legitimate user of the platform — not an operator/node) can:
1. Observe or guess a `requestID` that a victim is likely to use (many client SDKs default to sequential, timestamp-based, or low-entropy IDs), or race a known victim ID.
2. Submit their own `workflows.execute` request with that same `id` first.
3. Cause the victim's genuine trigger call to fail immediately with `ErrConflict` ("requestID has already been used"), before it is ever sent to DON nodes — i.e., silently blocking a legitimate workflow execution (denial of service / griefing), analogous to how Mallory's front-run terminates Bob's ability to complete Alice's offer in the zAuction report.

This affects the gateway's `HandleUserTriggerRequest` path, which is a user/workflow ingestion and capability-routing trust boundary explicitly in scope.

### Likelihood Explanation
Exploitability depends on the entropy/predictability of caller-chosen `requestID` values and on winning a request-ordering race, both of which are realistic in adversarial multi-tenant gateway deployments where the ID space is shared across all workflows/tenants and is entirely attacker-influenceable. No special privilege beyond ordinary trigger-invocation authorization is required.

### Recommendation
Scope the in-flight-request uniqueness key (and the corresponding entry in `h.callbacks`) to the authorized principal, not just the raw caller-supplied `requestID` — e.g., key by `hash(workflowID || workflowOwner || requestID)` or `authorizedKey || requestID`, similar to how the vault handler appears to namespace responses by owner. This ensures one caller's chosen ID cannot collide with, and thereby block, another caller's/workflow's in-flight request.

### Proof of Concept
1. Attacker obtains authorization to trigger Workflow W2 (any workflow they are legitimately allowed to call).
2. Attacker learns/guesses that Victim is about to trigger Workflow W1 with JSON-RPC `id = "X"`.
3. Attacker sends `workflows.execute` for W2 with `id = "X"` slightly before Victim's request arrives at the gateway.
4. `setupCallback` registers `h.callbacks["X"]` for the attacker's request.
5. Victim's legitimate request for W1 with `id = "X"` reaches `setupCallback`, finds `h.callbacks["X"]` already populated, and is rejected via `handleUserError(..., jsonrpc.ErrConflict, "requestID: X has already been used...")` — the victim's workflow trigger never reaches the DON, denying the legitimate operation.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, doneCh)
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
	threshold := (len(h.donConfig.Members)+h.donConfig.F)/2 + 1
	agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
	if err != nil {
		return nil, errors.New("failed to create response aggregator: " + err.Error())
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:           callback,
		requestStartTime:   requestStartTime,
		createdAt:          time.Now(),
		responseAggregator: agg,
		doneCh:             doneCh,
	}
	return doneCh, nil
}
