### Title
Long-running/unbounded RPC account scans permanently pin `ongoing_scan_roots` with no cancellation or timeout, indefinitely blocking `clean_accounts` and causing unbounded storage growth - (File: accounts-db/src/accounts_scan.rs, accounts-db/src/accounts_db.rs)

### Summary
`AccountsDb::scan_accounts` registers every in-flight scan (e.g. an RPC `getProgramAccounts`-style scan) via `ScanGuard::try_new`, which pins the scan's `max_root` into `ScanTracker::ongoing_scan_roots` for the entire duration of the scan and only unpins it in `Drop` when the scan callback finishes iterating [1](#0-0) . `clean_accounts` can never advance its clean root past the minimum pinned root, since `max_clean_root` explicitly clamps the clean root to `min_ongoing_scan_root()` [2](#0-1) . There is no timeout, budget, or cancellation mechanism that forces a stalled or abnormally long-running scan to release its pin — the only way the pin is released is for the scan's `scan_func` closure to finish running to completion.

### Finding Description
`ScanGuard::try_new` inserts the scan's max root into `ongoing_scan_roots` before invoking the user-supplied `scan_func` for every visible account, and the guard is only dropped (thereby decrementing/removing the pinned root) after the entire scan completes [3](#0-2) [4](#0-3) . `scan_accounts` itself has no deadline, cancellation timer, or admission-control limit on scan duration — the only abort mechanism is `ScanConfig`'s `abort` flag, which must be explicitly toggled by the caller and is not driven by any elapsed-time watchdog [5](#0-4) , [6](#0-5) .

Meanwhile, `flush_rooted_accounts_cache_with_clean` and `clean_accounts`/`max_clean_root` are explicitly designed to defer to whatever the *minimum* ongoing scan root is: "If there is a long running scan going on, this could prevent any cleaning based on updates from slots > `max_clean_root`" [7](#0-6) . This is confirmed by the existing regression test `test_scan_flush_accounts_cache_then_clean_drop`, which shows that while a scan is pinned at slot 0, `clean_accounts_for_tests()` cannot purge superseded account versions in slot 1 even though a newer root (slot 2) exists — the stale copy is only reclaimed after the scan is explicitly told to exit [8](#0-7) .

This is precisely the bug class in the reference report: a single long-lived, unprivileged-user-initiated operation (an account scan, analogous to the stuck "deployment request") occupies a shared, singular resource (the minimum clean root) with no cancellation/timeout path to force it to release that resource, and downstream cleanup (`clean_accounts`, analogous to progressing the "deployment") is permanently blocked from operating on anything at or above the pinned slot until the scan naturally terminates.

### Impact Explanation
While the scan is pinned, `clean_accounts` cannot reclaim superseded/zero-lamport account versions rooted at or after the pinned slot [2](#0-1) . Every subsequent write to any account touched during that window accumulates additional stale slot-list entries and additional appendvec storage that cannot be shrunk or cleaned, since `is_candidate_for_shrink`/dead-slot detection in `handle_reclaims` only fires once entries are actually reclaimed [9](#0-8) . The longer (or more numerous) the unbounded scans, the larger the unreclaimed backlog grows, producing disproportionate storage growth and wasted background-cleaner CPU cycles re-scanning the same unreclaimable candidates every `CLEAN_INTERVAL` in `AccountsBackgroundService` [10](#0-9) . In the worst case (a scan that never completes, e.g. due to a slow/blocked consumer of an RPC streaming response, or extremely large account sets under `getProgramAccounts`-style scans), the node's storage footprint grows unboundedly for as long as that single scan is outstanding, with no operator-facing way to cancel it short of restarting the validator.

### Likelihood Explanation
Any code path that invokes `AccountsDb::scan_accounts`/`scan_all_accounts` on behalf of an RPC request is enough to pin a root; `rpc/src/rpc.rs` uses these scan primitives to serve account-scanning RPC methods. A slow consumer, a pathologically large account set, or simply a scan the client keeps alive can keep `ScanGuard` alive far longer than a normal single request, and there is no timeout in `ScanGuard`/`scan_accounts` to force it to give up its pin. This requires only a single long-running scan request from an unprivileged RPC caller — not repeated calls within a tight time budget — so it is not equivalent to the excluded "RPC DoS requiring multiple calls" case.

### Recommendation
Add a bounded lifetime/timeout to `ScanGuard`/`ScanTracker`: track scan start time alongside the pinned root, and have the background accounts service (or a dedicated watchdog) detect scans that have exceeded a maximum duration and force-abort them via `ScanConfig::abort` (or forcibly release the pinned root and mark the scan's results as corrupted, mirroring the existing `removed_bank_ids` mechanism used for fork removal). Alternatively, decouple `max_clean_root` from `min_ongoing_scan_root` after some bounded staleness threshold so clean can still make forward progress on slots far below any live scan, with the scan itself detecting the staleness and re-validating/retrying its results.

### Proof of Concept
1. Start a scan via `AccountsDb::scan_accounts` (as exercised by `setup_scan`/`test_scan_flush_accounts_cache_then_clean_drop`) whose `scan_func` blocks indefinitely on a particular pubkey (simulating a slow/stalled RPC consumer) [11](#0-10) .
2. While the scan is blocked, add new roots and repeatedly write/update accounts and call `flush_accounts_cache`/`clean_accounts_for_tests` — observe that stale versions at/after the pinned root are never reclaimed, as shown by the assertions in `test_scan_flush_accounts_cache_then_clean_drop` [12](#0-11) .
3. Because nothing but the scan's own natural completion (or explicit `exit()`) drops the `ScanGuard`, this state persists for as long as the scan is kept alive, with `uncleaned_pubkeys`/storage continuing to grow via ordinary account activity, demonstrating the unbounded-storage/lack-of-cancellation impact.

    /// Begin a scan: checks the bank hasn't been removed and pins `max_root` in
    /// `ongoing_scan_roots`.
    ///
    /// Returns `None` if the bank has already been removed.
    ///
    /// `max_root_inclusive_fn` is called while holding the `ongoing_scan_roots` write lock.
    pub(crate) fn try_new(
        scan_tracker: &'a ScanTracker,
        scan_bank_id: BankId,
        max_root_inclusive_fn: impl FnOnce() -> Slot,
    ) -> Option<Self> {
        {
            let locked_removed_bank_ids = scan_tracker.removed_bank_ids.lock().unwrap();
            if locked_removed_bank_ids.contains(&scan_bank_id) {
                return None;
            }
        }

        let max_root_inclusive = {
            let mut w_ongoing_scan_roots = scan_tracker
                // This lock is also grabbed by clean_accounts(), so clean
                // has at most cleaned up to the current `max_root` (since
                // clean only happens *after* BankForks::set_root() which sets
                // the `max_root`)
                .ongoing_scan_roots
                .write()
                .unwrap();
            // `max_root()` grabs a lock while
            // the `ongoing_scan_roots` lock is held,
            // make sure inverse doesn't happen to avoid
            // deadlock
            let max_root_inclusive = max_root_inclusive_fn();
            if let Some(min_ongoing_scan_root) =
                ScanTracker::min_ongoing_scan_root_from_btree(&w_ongoing_scan_roots)
                && min_ongoing_scan_root < max_root_inclusive
            {
                let current = max_root_inclusive - min_ongoing_scan_root;
                scan_tracker
                    .max_distance_to_min_scan_slot
                    .fetch_max(current, Ordering::Relaxed);
            }
            *w_ongoing_scan_roots.entry(max_root_inclusive).or_default() += 1;
            max_root_inclusive
        };

        scan_tracker.active_scans.fetch_add(1, Ordering::Relaxed);
        Some(Self {
            scan_tracker,
            max_root: max_root_inclusive,
            scan_bank_id,
        })

impl Drop for ScanGuard<'_> {
    fn drop(&mut self) {
        self.scan_tracker
            .active_scans
            .fetch_sub(1, Ordering::Relaxed);
        let mut ongoing_scan_roots = self.scan_tracker.ongoing_scan_roots.write().unwrap();
        let count = ongoing_scan_roots.get_mut(&self.max_root).unwrap();
        *count -= 1;
        if *count == 0 {
            ongoing_scan_roots.remove(&self.max_root);
        }
    }

    pub(crate) fn scan_accounts<F>(
        &self,
        ancestors: &Ancestors,
        bank_id: BankId,
        mut scan_func: F,
        config: &ScanConfig,
    ) -> ScanResult<()>
    where
        F: FnMut(Option<(&Pubkey, AccountSharedData, Slot)>),
    {
        // Register this scan so that slots needed by the scan are not cleaned out from under us.
        let scan_guard = ScanGuard::try_new(&self.scan_tracker, bank_id, || self.max_root())
            .ok_or(ScanError::SlotRemoved {
                slot: ancestors.max_slot(),
                bank_id,
            })?;

        // If the scan's ancestors are all rooted, drop them and scan roots only
        // Scan Guard max root must be used as the scan guard guarantees that
        // the account state as of max root is persisted in the database
        let max_root_ancestors = Ancestors::from(vec![scan_guard.max_root()]);
        let ancestors = if scan_guard.should_use_ancestors(ancestors) {
            ancestors
        } else {
            &max_root_ancestors
        };

        // Step 1: Pre-scan the cache index to find the newest visible cached version of each
        // pubkey. Hold the Arc<CachedAccount> to keep the data alive even if the cache flushes
        // between now and step 3 (Arc clone is just a refcount bump).
        let cached_pubkeys = self.accounts_cache.cached_pubkeys();
        let mut cached_versions =
            HashMap::with_capacity_and_hasher(cached_pubkeys.len(), PubkeyHasherBuilder::default());
        for pubkey in cached_pubkeys {
            if config.is_aborted() {
                break;
            }

            if let Some((cached_account, slot)) =
                self.accounts_cache.load_latest(&pubkey, ancestors)
            {
                cached_versions.insert(pubkey, (cached_account, slot));
            }
        }

        // Step 2: Scan the accounts_index. For each pubkey, return the newest version found in
        // either the storage or the cache. If both versions are the same, use the cached version
        // to avoid a redundant load from storage.
        // Bound max_root by ancestors.min_slot() so that roots from slots
        // beyond the querying bank's ancestor chain are not visible.
        let mut max_root = scan_guard.max_root();
        if let Some(min) = ancestors.min_slot() {
            max_root = max_root.min(min);
        }
        self.accounts_index.scan_accounts(
            ancestors,
            max_root,
            |pubkey, (account_info, slot)| {
                if let Some((cached_account, cache_slot)) = cached_versions.remove(pubkey)
                    && cache_slot >= slot
                {
                    scan_func(Some((pubkey, cached_account.account.clone(), cache_slot)));
                    return;
                }

                let mut account_accessor =
                    self.get_account_accessor(slot, &account_info.storage_location());

                let account_slot = account_accessor.get_loaded_account(|loaded_account| {
                    (pubkey, loaded_account.take_account(), slot)
                });
                scan_func(account_slot)
            },
            config,
        );

    /// Flush all rooted slots up to `requested_flush_root` with cleaning. Cleaning stores only
    /// the newest version of any given account when flushing multiple rooted slots. This reduces

        &self,

        // based on updates from slots > `max_clean_root`.
        let max_clean_root = self.max_clean_root(requested_flush_root);
        self.flush_rooted_accounts_cache(
            requested_flush_root,
            FlushShouldClean::Yes { max_clean_root },
        )

fn setup_scan(
    db: Arc<AccountsDb>,
    scan_ancestors: Arc<Ancestors>,
    bank_id: BankId,
    stall_key: Pubkey,
) -> ScanTracker {
    let exit = Arc::new(AtomicBool::new(false));
    let exit_ = exit.clone();
    let ready = Arc::new(AtomicBool::new(false));
    let ready_ = ready.clone();

    let t_scan = Builder::new()
        .name("scan".to_string())
        .spawn(move || {
            db.scan_accounts(
                &scan_ancestors,
                bank_id,
                |maybe_account| {
                    ready_.store(true, Ordering::Relaxed);
                    if let Some((pubkey, _, _)) = maybe_account
                        && *pubkey == stall_key
                    {
                        loop {
                            if exit_.load(Ordering::Relaxed) {
                                break;
                            } else {
                                sleep(Duration::from_millis(10));
                            }
                        }
                    }
                },
                &ScanConfig::default(),
            )
            .unwrap();
        })
        .unwrap();

    // Wait for scan to start
    while !ready.load(Ordering::Relaxed) {
        sleep(Duration::from_millis(10));
    }

    ScanTracker { t_scan, exit }
}
