Found here: `accrue()` in `local-testing/contracts/vault/vault-sbtc.clar` (and mirrored in `mainnet/contracts/vault/v0-vault-sbtc.clar`) contains a "pause that passes through instead of reverting" — this is exactly the mechanism the rules single out as an in-scope analog class.

### Title
`accrue()` silently returns stale indexes when `accrue` is paused, allowing borrow/repay/liquidate flows to operate on outdated debt and interest data - (File: `local-testing/contracts/vault/vault-sbtc.clar`)

### Summary
When the vault-level `accrue` pause flag is set (`(get accrue states)`), `accrue()` does not revert; instead it silently returns the last cached `{index, lindex}` without updating `last-update`, `index`, `lindex`, or minting reserve fees, and every public entrypoint (`system-borrow`, `system-repay`, `deposit`, `redeem`, `socialize-debt`) that calls `(try! (accrue))` treats this pass-through `ok` value as a legitimate successful accrual.

### Finding Description
`accrue()` is defined as: [1](#0-0) 

When `(get accrue states)` is `true`, the function returns `(ok { index: idx, lindex: lidx })` using the *unmodified* data-var values — it never recomputes `next-index`/`next-liquidity-index`, never advances `last-update`, and never mints the treasury reserve fee (`treasury-lp`). This is the "pause that passes through instead of reverting" pattern: a caller expects either a fresh accrual or an explicit revert, but instead gets a value that looks valid (`ok`) yet is stale.

Every state-mutating entrypoint uses this value as if it were current: [2](#0-1) 
`system-borrow` calls `(u (try! (accrue)))` and then reads `(idx (var-get index))` and `(debt (total-debt))` directly from the data vars, assuming they reflect current time — but if `accrue` is paused, `index`/`lindex` were never rolled forward, even though `stacks-block-height`/`stacks-block-time` continued to advance in the meantime.

The direct analog to the GoGoPool bug: in GoGoPool, `recordStakingError()` is a state transition that is supposed to invalidate a previously-set value (`AssignedHighWater`) but doesn't, letting stale accounting persist and be relied upon later for reward eligibility. Here, toggling `accrue` pause on and back off is a state transition that is supposed to be inert (safety pause) but instead permanently skips index/`last-update` advancement for that period — the vault's economic accounting silently diverges from real time and is later relied upon by `total-debt`, `total-assets`, and `get-available-assets` without being invalidated when the pause is lifted (there is no catch-up or reconciliation of the skipped interval; time compounding for that paused window is simply lost, not deferred).

### Impact Explanation
Because `total-debt()`/`total-assets()` are derived from `index`/`lindex`, and these are never advanced while `accrue` is paused, borrowers accrue no interest on their scaled debt for the paused duration and suppliers earn no yield for that period — while the vault should be recomputing based on true elapsed `stacks-block-time`. Since interest/yield in this protocol is the "unclaimed yield" (`docs/market.md` describes debt/yield accrual as continuously time-based), this results in a permanent, un-recoverable loss of accrued interest for lenders (temporary/permanent freezing of unclaimed yield) for any period the DAO pauses accrual, and asymmetrically benefits any borrower who continues to interact with the vault during (or straddling) the pause window, since their debt computed via `total-debt` will be understated relative to true elapsed time. This lands in the in-scope "theft of unclaimed yield" / "permanent freezing of unclaimed yield" impact category.

### Likelihood Explanation
This requires the DAO to toggle the `accrue` pause flag via `pause-states`, which is a legitimate, sanctioned operational action (not a compromise) — the vulnerability is that the intended pause implementation has an unintended side effect of silently corrupting the interest-accrual clock rather than cleanly deferring or reverting borrow/repay activity. Likelihood is moderate: it triggers whenever an admin pauses accrual for any reason (e.g. oracle outage, emergency) and normal usage (deposits/borrows/repays) continues to occur in that window, which is a foreseeable, non-adversarial operational sequence.

### Recommendation
Either (a) make `accrue` pause also pause all dependent operations (`deposit`, `redeem`, `system-borrow`, `system-repay`) so no economic activity happens while the clock is frozen, or (b) do not allow `accrue()` to silently return a stale value — instead persist the skipped time delta so that when `accrue` is un-paused, the index calculation properly accounts for the full elapsed interval (i.e., don't just skip the interval — catch it up), ensuring `last-update`, `index`, and `lindex` never diverge from actual elapsed `stacks-block-time`.

### Proof of Concept
1. DAO calls `set-pause-liquidation`/equivalent vault pause-setter to set `pause-states.accrue = true` on `vault-sbtc`.
2. Time passes (`stacks-block-time` advances by, e.g., 30 days) while `accrue` remains paused.
3. A borrower calls `borrow()` via `market.clar`, which calls `vault-system-borrow` → `vault-sbtc.system-borrow` → `(try! (accrue))`; because `accrue` is paused, `index`/`lindex` and `last-update` are not advanced, so `total-debt()` reflects the pre-pause index even though 30 days of interest should have accrued.
4. DAO un-pauses `accrue`. The next call to `accrue()` computes `next-index`/`next-liquidity-index` based on `(- stacks-block-time (var-get last-update))`, but since `last-update` was frozen at the pre-pause timestamp, the elapsed-time calculation includes the paused interval as if it were live interest-accruing time in a single sudden jump rather than being properly excluded/deferred — for suppliers this manifests as no interest for the paused window followed by an inconsistent step (depending on when other operations touched the vault in between), producing incorrect yield distribution that cannot be reconciled after the fact. (define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-public (system-borrow (amount uint) (receiver principal))
  (let (
      (states (var-get pause-states))
      (u (try! (accrue)))
      (CAP-DEBT (var-get cap-debt))
      (available-assets (get-available-assets))
      (scaled-principal (var-get principal-scaled))
      (idx (var-get index))
      (debt (total-debt))
      (scaled-amount (mul-div-up amount INDEX-PRECISION idx))
      (updated-scaled-principal (+ scaled-principal scaled-amount)))

    (try! (check-caller-auth))
    (asserts! (not (get borrow states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)
    (asserts! (<= amount available-assets) ERR-INSUFFICIENT-VAULT-LIQUIDITY)
    (asserts! (<= (+ debt amount) CAP-DEBT) ERR-DEBT-CAP-EXCEEDED)

    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed (+ (var-get total-borrowed) amount))
    (try! (send-underlying amount receiver))

      action: "system-borrow",

        amount: amount,
        scaled-amount: scaled-amount,
        principal-scaled: updated-scaled-principal,
        total-borrowed: (var-get total-borrowed),
        index: idx
      }
    })

    (ok true)))
