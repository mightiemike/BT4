Based on my research, I found a plausible native analog to the Zivoe M‑12 rounding bug in `x/uexecutor/keeper/fees.go`, but I could not fully verify the exploitability because the `feemarketKeeper.GetBaseFee` implementation lives in an external `cosmos/evm` dependency that isn't indexed in this repo, so I can't confirm whether `BaseFee` is ever a non-multiple-of-1e18 `LegacyDec` in practice.

### Title
Truncating division when unwrapping `BaseFee` from 18-decimal `LegacyDec` to upc systematically undercharges gas fees - (File: x/uexecutor/keeper/fees.go)

### Summary
`Keeper.CalculateGasCost` unwraps the feemarket's `LegacyDec` base fee into a whole-upc `*big.Int` via integer division by `1e18`, based on a hard-coded assumption ("baseFee is always a whole number of upc") that is not enforced anywhere in the scoped code. If that assumption doesn't hold for a given block, the truncating `Div` rounds the effective gas price down, and the resulting `gasCost` (billed and burned from the caller in `DeductGasFeesFromReceipt` / `DeductAndBurnFees`) is systematically less than the true cost — a rounding-down bias that, like Zivoe M‑12, always favors the payer at the protocol's expense. [1](#0-0) 

### Finding Description
`CalculateGasCost` takes `baseFee sdkmath.LegacyDec` (18-decimal fixed point) and does:
```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
``` [2](#0-1) 

This is called from `DeductGasFeesFromReceipt`, which multiplies the truncated `effectiveGasPrice` by `gasUsed` to get `gasCost`, and then burns exactly that amount from the recipient's balance via `DeductAndBurnFees`. [3](#0-2) 

The comment explicitly documents an assumption that "the base fee is always a whole number of upc — no fractional upc exists," but this invariant is never validated in the scoped `x/uexecutor` code; it depends entirely on the external feemarket module's `GetBaseFee` (in `cosmos/evm`, outside the audited repo) always returning an exact multiple of `1e18`. `go-ethereum`/`cosmos-sdk` feemarket base-fee adjustment formulas (`baseFee * (1 + gasUsedDelta/gasTarget/denominator)`) are multiplicative on a `LegacyDec` and are not inherently guaranteed to remain integral multiples of 1e18 after repeated block-by-block adjustments, unless the feemarket module specifically re-quantizes its stored value to upc granularity on every update. If it does not, `baseFeeBig.Div` truncates any sub-1-upc remainder every single block, and every `ExecutePayloadV2` call bills less than the true cost — every ordinary user's payload execution triggers this path, so the rounding direction is fixed (always down, always in the caller's favor) and is not something a validator/relayer/admin controls.

This mirrors the Zivoe pattern exactly: an integer division on a systemically important accounting value (APR there, gas price here) truncates in one direction only, with no `require`/guard to catch or reject the rounding error, causing a durable, protocol-side value leak on every affected transaction.

### Impact Explanation
If the assumption is violated, the protocol systematically under-collects gas fees on `ExecutePayloadV2` calls, burning less than the EIP-1559-correct amount every time a fractional-upc base fee occurs. This is a direct "loss of protocol-controlled funds" (gas fee under-collection) reachable by any ordinary unprivileged user simply by executing payloads, matching the in-scope "corruption of ... gas fee accounting" impact category.

### Likelihood Explanation
I could not confirm from the indexed code whether the upstream `cosmos/evm` feemarket keeper enforces base-fee quantization to whole-upc values at every base-fee update (this logic is external to the repos I can search). If the feemarket module does guarantee exact upc quantization on every write (which is plausible, since `1 upc` is the chain's smallest denomination and the base fee is likely stored/rounded in upc units by design), then this finding is not exploitable and the comment's assumption holds by construction elsewhere. Given this uncertainty, I present this as a candidate finding requiring confirmation of the feemarket base-fee quantization invariant, rather than a fully verified vulnerability.

### Recommendation
Add a defensive check in `CalculateGasCost` (or at the point base fee is read) asserting `baseFeeBig` is an exact multiple of `1e18` before truncating (e.g., `require(baseFee.BigInt() % 1e18 == 0)` equivalent), or round the effective gas price up (ceiling) rather than down when unwrapping from `LegacyDec` to whole upc, so the protocol never systematically undercharges gas fees due to a fixed-point-to-integer conversion.

### Proof of Concept
Could not construct a concrete PoC without confirming the upstream feemarket's base-fee update/storage semantics (external `cosmos/evm` dependency, not present in the scoped repo). A verifying PoC would need to: (1) confirm whether `feemarketKeeper.GetBaseFee` can return a `LegacyDec` value that is not an exact multiple of `1e18`, and (2) if so, trigger `ExecutePayloadV2` at such a block and show `gasCost` computed by `CalculateGasCost` is strictly less than `gasUsed * trueBaseFeeInUpc`.

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
