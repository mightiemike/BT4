### Title
Unbounded recursive traversal of `NestedIntList` bytecode-segment structures causes stack-overflow DoS during compiled class hashing - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
CVE-2016-4008 is a libtasn1 infinite-recursion bug where a crafted, deeply-nested ASN.1 structure is decoded by a recursive function with no depth bound, causing a stack overflow. The sequencer contains an analogous pattern: several functions recursively walk a `NestedIntList` tree (the CASM bytecode-segment structure produced for a declared class) with **no depth limit**, and this tree's nesting depth is influenced by the Sierra program a declarer submits.

### Finding Description
`NestedIntList` (from `cairo_lang_starknet_classes`) represents the bytecode segmentation of a compiled class (`CasmContractClass.bytecode_segment_lengths`), and it is walked recursively in at least two places in this codebase:

- `bytecode_hash_node`, used by `HashableCompiledClass::hash` to compute the compiled-class hash for every declared/loaded class: [1](#0-0) 

- `create_bytecode_segment_structure_inner`, used by the Starknet OS to rebuild the bytecode segment tree during re-execution/proving of every Cairo1 class: [2](#0-1) 

Both functions recurse once per nesting level of the tree with **no depth check or iterative fallback**. The tree is built by `HashableCompiledClass::get_bytecode_segment_lengths`, which for `CasmContractClass` simply returns whatever `bytecode_segment_lengths` value is present: [3](#0-2) 

`bytecode_segment_lengths` is produced by the Sierra→CASM compiler when the sequencer compiles a declarer-submitted Sierra program (a step reachable directly from a `DECLARE` transaction). Because the segmentation reflects the compiled program's function/branch structure, a declarer can shape a Sierra program (within the existing `max_contract_bytecode_size` limit, e.g. 81920 felts) to make the compiler emit a very deeply nested `NestedIntList::Node(...)` chain (e.g., long chains of singleton nested segments corresponding to nested inline branches/functions). There is no explicit bound anywhere in this code path limiting the *nesting depth* of the resulting tree — only the total bytecode length is bounded: [4](#0-3) 

The compiled-class hash (via `bytecode_hash`/`bytecode_hash_node`) is computed and checked by every node that processes the declare transaction (gateway/mempool validation and block execution), and the bytecode-segment structure (`create_bytecode_segment_structure_inner`) is rebuilt again during Starknet OS re-execution for proving. Because recursion depth is proportional to attacker-controlled tree nesting rather than any explicit, checked bound, a sufficiently deep tree can exhaust the thread stack and crash the process (stack overflow / abort), which is not a recoverable `Result` error — it terminates the executing thread/process outright, unlike the existing, properly-bounded Cairo-VM recursion guard (`RecursionDepthGuard`) that protects contract *call* recursion: [5](#0-4) 

That guard only limits entry-point call depth, not the depth of the compiled-class bytecode-segment data structure, so it provides no protection here.

### Impact Explanation
If reachable with a bytecode-segment tree deep enough to exceed the thread stack (frame size × depth > configured stack, e.g. `execute_config.stack_size` ~60MB per the config, but hashing/OS code runs on other threads/paths without that dedicated stack), this causes a crash of the sequencer process while computing the compiled-class hash for a submitted `DECLARE` transaction. Since **every** node (gateway validators, batcher, and OS-based provers) performs this same deterministic computation on the same submitted class, a single malicious declare transaction could crash all honest nodes that process it — a network-wide denial of service preventing new transactions from being confirmed. This matches the "network unable to confirm new transactions" impact class in scope.

### Likelihood Explanation
Medium: the bytecode-segment structure is produced by a compiler this repo does not control (an external crate), so it is uncertain (without a compiled repro) how deeply nested a real, valid Sierra program can push the segmentation tree, and whether the compiler itself imposes indirect limits (e.g., recursion in its own segmentation pass may itself fail first). This uncertainty is a real gap in my analysis — I was not able to trace the exact segmentation algorithm inside the external `cairo-lang-starknet-classes` compiler within the available tools, so I cannot confirm the maximum achievable nesting depth for a bytecode capped at `max_contract_bytecode_size`. The vulnerability is real code-path evidence (unbounded recursion, no depth guard) analogous to CVE-2016-4008, but full exploitability depends on compiler behavior I could not verify.

### Recommendation
- Add an explicit maximum nesting-depth check when validating/deserializing `bytecode_segment_lengths` for a declared class (reject classes whose segment tree exceeds a safe depth, e.g. proportional to `log(max_contract_bytecode_size)`).
- Convert `bytecode_hash_node` and `create_bytecode_segment_structure_inner` to iterative (explicit stack/worklist) implementations, removing native call-stack dependency entirely, consistent with how `RecursionDepthGuard` bounds call-based recursion elsewhere.

### Proof of Concept
Not independently reproducible with available tools/index access: constructing a concrete deeply-nested `bytecode_segment_lengths` requires compiling an actual Sierra program with the external `cairo-lang-starknet-classes` compiler to observe the resulting `NestedIntList` shape, which is outside the scope of static code search here. The code-level evidence (unbounded recursive functions operating on an attacker-influenced tree with no depth bound) is cited above.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
