The reported bug class — an address list that grows on every call regardless of whether the entry already exists, with no removal logic — has a direct structural analog in this repo's session storage layer.

## Title
Unbounded Duplicate Growth of Shop Session ID List in `KVSessionStorage.addShopIds()` - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

## Summary
`KVSessionStorage.storeSession()` calls `addShopIds(session.shop, [session.id])` on every store, and `addShopIds` unconditionally appends the session id to the shop's tracking array without checking whether it is already present, unlike the sibling `removeShopIds` method (and unlike the Redis implementation's `addKeyToShopList`, which explicitly checks `includes()` before pushing).

## Finding Description
`storeSession()` writes the session, then always appends the id to the per-shop index array: [1](#0-0) 

`addShopIds` performs no de-duplication before pushing: [2](#0-1) 

Compare this to `removeShopIds`, which correctly filters out entries: [3](#0-2) 

And compare to the equivalent method in the Redis adapter, which guards against duplicates exactly as the report recommends for `setNativePool()`: [4](#0-3) 

Because `storeSession` is invoked by the standard OAuth flow every time a session is created or refreshed for a shop (e.g., re-running install/OAuth, or online-token refresh for the same user), and the same `session.id` is deterministic per shop/user (see offline id derivation and JWT-based online session ids used throughout the OAuth tests), repeated calls for the same shop will keep appending the same id to `shop:<shop>` in the KV namespace without limit.

## Impact Explanation
The `shop:<shop>` KV value backs `findSessionsByShop()`: [5](#0-4) 

An ever-growing duplicate-laden array causes: (1) `findSessionsByShop` to return duplicate `Session` objects, corrupting any consumer that assumes uniqueness (e.g., iterating merchant sessions for token cleanup or webhook dispatch), and (2) unbounded growth of the KV value, which is bound by Cloudflare KV's per-value size limits — repeated re-authentication for a single shop can eventually cause `storeSession`/`addShopIds` to fail once the value exceeds platform limits, effectively denying session storage (and thus authentication) for that shop.

## Likelihood Explanation
Triggering this requires no privilege beyond being able to complete the normal OAuth flow as a single merchant/user — every legitimate `begin`/`callback` cycle or online-token refresh re-invokes `storeSession` with the same id. No forged tokens or elevated access are needed; only repetition of a normal, unauthenticated-until-callback OAuth flow.

## Recommendation
Mirror the Redis adapter's guard: in `addShopIds`, check `if (!shopIds.includes(id))` before pushing each id, and de-duplicate the existing array on read as a safety net. This is the direct analog of the report's fix: not re-adding entries already present in the list.

## Proof of Concept
1. Configure `KVSessionStorage` as the app's session storage.
2. Complete OAuth `begin`/`callback` for `shop-a.myshopify.com`, producing offline session id `offline_shop-a.myshopify.com`; `storeSession` runs, `shop:shop-a.myshopify.com` becomes `["offline_shop-a.myshopify.com"]`.
3. Repeat the OAuth callback (or trigger any code path that re-calls `storeSession` for the same session, such as re-installation or token refresh) N times.
4. Read the `shop:shop-a.myshopify.com` KV key — the array contains the same id repeated N times instead of once, growing linearly and unboundedly with each cycle, and `findSessionsByShop` returns N duplicate `Session` entries.

  private async removeShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(
      key,
      JSON.stringify(shopIds.filter((id) => !ids.includes(id))),
    );
  }

  private async addKeyToShopList(session: Session) {
    const shopKey = session.shop;
    const idKey = this.client.generateFullKey(session.id);
    const idKeysArrayString = await this.client.get(shopKey);

    if (idKeysArrayString) {
      const idKeysArray = JSON.parse(idKeysArrayString);

      if (!idKeysArray.includes(idKey)) {
        idKeysArray.push(idKey);
        await this.client.set(shopKey, JSON.stringify(idKeysArray));
      }
    } else {
      await this.client.set(shopKey, JSON.stringify([idKey]));
    }
  }
