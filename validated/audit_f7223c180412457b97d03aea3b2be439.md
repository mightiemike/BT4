### Title
Panic-inducing `.unwrap()` on `receiver_shard_id()` in `receipt_filter_fn` can halt chunk application when a delayed `GlobalContractDistribution` receipt outlives the shard split history - ([File: runtime/runtime/src/congestion_control.rs])

### Summary
`DelayedReceiptQueueWrapper::receipt_filter_fn` unconditionally unwraps the `Result` returned by `Receipt::receiver_shard_id`, treating a legitimate, recoverable error condition (an unresolvable historical shard id) as an unreachable case. This is the same bug class as CWE-395 (using an exception/None-style signal to detect a failure that should instead be handled): the code assumes the "value" will always be present/`Ok` and panics when it is not, rather than gracefully rejecting or re-queuing the receipt.

### Finding Description
`Receipt::receiver_shard_id` returns `Result<ShardId, EpochError>` [1](#0-0) . For `ReceiptEnum::GlobalContractDistribution`, if the receipt's `target_shard` is not present in the current shard layout, the code calls `shard_layout.resolve_to_current_shard(target_shard)`, and if that returns `None` it explicitly returns `Err(EpochError::ShardingError(...))` [2](#0-1) .

`resolve_to_current_shard` (V3 shard layout) only resolves a shard id if it is either present in the current shard layout or reachable through the `shards_split_map`, which records only splits between consecutive layouts that are *both* version ≥ 3 (`build_shard_split_map` explicitly `break`s the accumulation of history at any V1/V2 boundary) [3](#0-2) [4](#0-3) . Consequently, a `GlobalContractDistribution` receipt whose `target_shard` predates or straddles a shard-layout-version boundary (or otherwise falls outside the recorded split history) causes `receiver_shard_id` to return `Err`, not `Some`/`Ok`.

Despite this documented failure mode, `receipt_filter_fn` — used every time the delayed receipt queue is popped during `Runtime::apply` — does not handle the `Err` case at all: [5](#0-4) 
```rust
fn receipt_filter_fn(&self, receipt: &ReceiptOrStateStoredReceipt) -> bool {
    let shard_layout = self.epoch_info_provider.shard_layout(&self.epoch_id).unwrap();
    let receipt_shard_id = receipt.get_receipt().receiver_shard_id(&shard_layout).unwrap();
    receipt_shard_id == self.shard_id
}
```
This is invoked unconditionally inside `DelayedReceiptQueueWrapper::pop`, which is on the hot path of every chunk apply that drains the delayed-receipt backlog [6](#0-5) , itself called from `Runtime::process_receipts` → `Runtime::apply` [7](#0-6) .

The repository already contains a regression test acknowledging this exact panic vector and stating its mitigation is incomplete for non-V3 (static) resharding history: "The fix only works with V3 shard layouts (dynamic resharding). With static resharding, the shard layout doesn't maintain a full split history" [8](#0-7) , and the same test comments that "If the vulnerability exists, processing the stale GlobalContractDistribution receipt will panic in receipt_filter_fn() ... to remap the old target_shard after two resharding generations" [9](#0-8) .

### Impact Explanation
`GlobalContractDistribution` receipts are produced by any unprivileged account issuing a `DeployGlobalContract` transaction. If that receipt is delayed (e.g. via compute/gas exhaustion, which any account can trigger by saturating a shard's chunk with heavy transactions) and remains in the delayed queue across shard-layout transitions that are not fully captured by `shards_split_map` (e.g. a transition where predecessor layouts are not version-3, or any other case where `resolve_to_current_shard` returns `None`), then on the block where the queue is drained, `receipt_filter_fn`'s `.unwrap()` panics inside `Runtime::apply`. Because `apply` runs deterministically and identically on every validator for that shard, this is not a crash confined to a single node — every honest validator applying that chunk panics at the same point, producing a chain-wide, transaction-triggered halt of chunk production for the affected shard (a liveness failure directly reachable from a single contract-deployer's transaction plus ordinary chunk congestion).

### Likelihood Explanation
Reaching this requires: (1) an account deploying a global contract, (2) engineering the receipt to be delayed long enough to survive shard-layout changes, and (3) the shard-layout transition history not fully tracking the receipt's original target shard (per the code's own acknowledged limitation for non-V3/static resharding history). Items (1) and (2) are attacker-controlled and require only ordinary transactions/gas spending; item (3) depends on the specific resharding/version transition sequence in effect, which I could not fully verify from the available code (in particular, whether the current protocol's resharding pipeline can still produce a V1/V2→V3 boundary or an otherwise history-incomplete transition in production). This is a plausible but conditionally-triggered path, and the codebase's own test comment corroborates that the underlying panic condition is real and only partially mitigated.

### Recommendation
Replace both `.unwrap()` calls in `receipt_filter_fn` with proper error propagation: return `Result<bool, RuntimeError>` (or equivalent) from `receipt_filter_fn`, propagate `EpochError`/`ShardLayoutError` through `pop()` as a `RuntimeError`, and ensure callers handle this by either safely delaying the receipt again or converting it into a defined `RuntimeError` that fails the chunk gracefully rather than panicking. Additionally, extend `build_shard_split_map`/`shards_split_map` (or `ShardLayout::resolve_to_current_shard`) so that shard-split history is preserved across version boundaries, ensuring any historically valid `target_shard` can always be resolved.

### Proof of Concept
Conceptual reproduction (mirrors the existing but incomplete regression test):
1. Deploy a global contract as an unprivileged user, producing a `ReceiptEnum::GlobalContractDistribution` with `target_shard = S_A`.
2. Saturate shard `S_A` with `burn_gas_raw`-style transactions every block so the receipt is pushed into the delayed queue.
3. Trigger shard-layout transitions such that `S_A`'s ancestry is not fully captured by `shards_split_map` (e.g. crossing a shard-layout version boundary, matching the `build_shard_split_map` early-break condition).
4. Let the delayed queue drain: `DelayedReceiptQueueWrapper::pop` calls `receipt_filter_fn`, which calls `receiver_shard_id()` → `Err(EpochError::ShardingError)` → `.unwrap()` panics inside `Runtime::apply`, halting all validators applying that shard's chunk.

This exact scenario is documented (for the fully-mitigated V3-only case) in [10](#0-9) , and the underlying unhandled-error path remains present in [5](#0-4) .

    pub fn receiver_shard_id(&self, shard_layout: &ShardLayout) -> Result<ShardId, EpochError> {
        let shard_id = match self.receipt() {
            ReceiptEnum::Action(_)
            | ReceiptEnum::ActionV2(_)
            | ReceiptEnum::Data(_)
            | ReceiptEnum::PromiseYield(_)
            | ReceiptEnum::PromiseYieldV2(_)
            | ReceiptEnum::PromiseResume(_) => {
                shard_layout.account_id_to_shard_id(self.receiver_id())
            }
            ReceiptEnum::GlobalContractDistribution(receipt) => {
                let target_shard = receipt.target_shard();
                if shard_layout.shard_ids().contains(&target_shard) {
                    target_shard
                } else {
                    // The target shard may be from an arbitrarily old layout (the receipt could
                    // have been delayed across multiple resharding events). resolve_to_current_shard
                    // will find a shard descendant in the current layout.
                    let Some(current_shard) = shard_layout.resolve_to_current_shard(target_shard)
                    else {
                        return Err(EpochError::ShardingError(format!(
                            "Shard {target_shard} does not exist in the shard layout or its split history",
                        )));
                    };
                    current_shard
                }
            }
        };
        Ok(shard_id)
    }

pub fn build_shard_split_map(layout_history: &[ShardLayout]) -> ShardsSplitMapV3 {
    let mut split_history = ShardsSplitMapV3::new();

    for window in layout_history.windows(2) {
        let current_layout = &window[0];
        let prev_layout = &window[1];

        if current_layout.version() < VERSION || prev_layout.version() < VERSION {
            break;
        }

        debug_assert_ne!(current_layout, prev_layout);

        for shard_id in current_layout.shard_ids() {
            match current_layout.try_get_parent_shard_id(shard_id).expect("invalid shard_id") {
                Some(parent_id) if parent_id != shard_id => {
                    split_history.entry(parent_id).or_default().push(shard_id);
                }
                _ => continue,
            }
        }
    }

    split_history
}

    /// Resolve any historical shard ID to a current shard by walking the full
    /// split history in `shards_split_map`. Returns the shard itself if it is
    /// current, or follows the first child at each generation until a current
    /// shard is reached. Returns `None` only if the shard ID is absent from
    /// both the current layout and the split history.
    pub fn resolve_to_current_shard(&self, shard_id: ShardId) -> Option<ShardId> {
        if self.shard_ids.contains(&shard_id) {
            return Some(shard_id);
        }
        let children = self.shards_split_map.get(&shard_id)?;
        self.resolve_to_current_shard(children[0])
    }

    pub(crate) fn pop(
        &mut self,
        trie_update: &mut TrieUpdate,
        config: &RuntimeConfig,
    ) -> Result<Option<ReceiptOrStateStoredReceipt<'_>>, RuntimeError> {
        // While processing receipts, we need to keep track of the gas and bytes
        // even for receipts that may be filtered out due to a resharding event
        loop {
            // Check proof size limit before each receipt is popped.
            if trie_update.trie.check_proof_size_limit_exceed() {
                break;
            }
            let Some(receipt) = self.queue.pop_front(trie_update)? else {
                break;
            };
            let delayed_gas = receipt_congestion_gas(&receipt, &config)?;
            let delayed_bytes = receipt_size(&receipt)? as u64;
            self.removed_delayed_gas =
                self.removed_delayed_gas.checked_add(delayed_gas).ok_or(IntegerOverflowError)?;
            self.removed_delayed_bytes = self
                .removed_delayed_bytes
                .checked_add(delayed_bytes)
                .ok_or(IntegerOverflowError)?;

            // Track gas and bytes for receipt above and return only receipt that belong to the shard.
            if self.receipt_filter_fn(&receipt) {
                return Ok(Some(receipt));
            }
        }
        Ok(None)
    }

fn test_stale_global_contract_distribution_after_double_resharding() {
