### Title
`rlp_execute` payable entry point silently absorbs attached deposit on early-exit / error paths, permanently denying refund to external depositors - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The NEAR wallet contract's `rlp_execute` method is marked `#[payable]` [1](#0-0) , so any `attached_deposit` sent with a call is credited to the contract's balance by the runtime before the method body executes. Several early-exit and error branches in `rlp_execute` / `inner_rlp_execute` return without ever creating a `CallerDeposit` refund promise, so a caller's attached NEAR merges irrecoverably into the wallet's own balance instead of being sent back.

### Finding Description
The contract has an explicit mechanism, `CallerDeposit`, to track and later refund a non-owner caller's attached deposit if the underlying cross-account call fails [2](#0-1) . This refund is only wired into the single "happy path" that reaches `rlp_execute_callback`, where a `PromiseResult::Failed` triggers a transfer back to the depositor [3](#0-2) .

However, multiple earlier exit points never construct or forward a refund promise for the already-collected deposit:

1. **In-flight-transaction guard**: `rlp_execute` checks `self.has_in_flight_tx` and returns an error `ExecuteResponse` immediately, before `attached_deposit()` is even read or any `CallerDeposit` tracking is created [4](#0-3) . Any deposit attached to this call is absorbed by the contract with no path to recovery.

2. **Parsing/validation errors in `inner_rlp_execute`**: `caller_deposit` is computed from the context right after `ExecutionContext::new` [5](#0-4) , but if `parse_rlp_tx_to_action` fails (`Error::User(_)` or other `Error` variants), the function returns `Err(err)` directly, dropping `caller_deposit` without ever using it to schedule a refund [6](#0-5) . Back in `rlp_execute`, the `Err(e)` arm simply converts the error into a value response with no refund promise [7](#0-6) .

3. **Callback-side error branches**: In `address_check_callback` and `nep_141_storage_balance_callback`, several failure branches (registrar call failure, unexpected response, "target is existing named account", "expected function call action") return `PromiseOrValue::Value(...)` directly, even though `caller_deposit` was passed into these callbacks specifically to be refunded on failure [8](#0-7) [9](#0-8) . These branches discard `caller_deposit` without issuing the transfer.

Because NEAR credits `attached_deposit` to the receiver's account balance unconditionally as part of receipt processing (documented in `EconomicsAPI.md`) [10](#0-9) , any deposit sent in these error paths becomes part of the wallet contract's own account balance rather than being returned to the sender who attached it — this is the exact analog of an "unnecessary payable function" swallowing `msg.value` with no path to reclaim it for the original sender.

### Impact Explanation
An external, unprivileged caller (e.g., a relayer paying a NEP-141 storage deposit or a fee on behalf of a wallet owner, as exercised by `test_caller_refunds`) can permanently lose the NEAR they attach to `rlp_execute` whenever the call takes any of the described early-exit/error paths instead of the single instrumented failure path. The lost value is not burned; it becomes indistinguishable from the wallet-owner's own balance, meaning value is moved from the caller to the wallet-owner without consent or compensation — a concrete, unauthorized value transfer/frozen-funds condition for the depositor.

### Likelihood Explanation
This is trivially reachable by any account: simply calling `rlp_execute` with a deposit while another transaction is already in flight (`has_in_flight_tx == true`), or submitting a malformed/invalid RLP transaction (triggering `Error::User`/parsing errors), or hitting one of the callback error branches (e.g., calling with a `target` address that resolves to an existing named account, or an unexpected registrar/NEP-141 response) — none of these require special privileges, malicious validators, or network-level control, only a normal `FunctionCall` with a deposit.

### Recommendation
Ensure every error/early-return branch that can execute after a deposit has already been credited (i.e., anywhere after `attached_deposit()`/`CallerDeposit::new` is computed) refunds the tracked `caller_deposit` via a transfer promise, mirroring the logic already present in `rlp_execute_callback`. Specifically: (1) read/refund deposit-awareness before the `has_in_flight_tx` early return, or refund immediately if rejected while in-flight; (2) in `inner_rlp_execute`'s parsing-error arms, issue a refund promise for `caller_deposit` before returning `Err`; (3) in `address_check_callback` and `nep_141_storage_balance_callback`, refund `caller_deposit` in every branch that returns `PromiseOrValue::Value` instead of chaining to `rlp_execute_callback`.

### Proof of Concept
1. Attacker/observer calls `rlp_execute` on a victim wallet contract with a small deposit attached while a legitimate transaction is already in flight (`has_in_flight_tx == true`), or with a malformed RLP payload that fails to parse.
2. The function returns an `ExecuteResponse` with `success: false` without ever creating a `CallerDeposit` refund promise (see cited code paths).
3. Query the wallet contract's account balance before and after: the attached deposit is now permanently part of the wallet's balance, and the depositing account has no way to recover it (only the wallet's owning key can later spend/move that balance), analogous to `test_caller_refunds` in `sanity.rs` [11](#0-10)  but exercised against the unrefunded branches instead of the instrumented `PromiseResult::Failed` path.

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }
}

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
