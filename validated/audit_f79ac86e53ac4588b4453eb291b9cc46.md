### Title
Stale zToken Price from Uninvalidated Index Cache After `socialize-debt` - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The market's per-block index cache (`index-cache`) is populated by `accrue-and-cache` and is only invalidated by a new `stacks-block-time`. `vault-*.socialize-debt` writes down a vault's `lindex` directly, bypassing the normal `accrue` path, so the write-down never refreshes the cache entry for that vault. Any zToken price resolution or notional evaluation that happens later in the same block reads the stale, pre-write-down `lindex` from the cache instead of the vault's true (reduced) state.

### Finding Description
`accrue-and-cache` caches `{index, lindex}` keyed by `{timestamp: stacks-block-time, aid}` and returns the cached tuple on any subsequent call within the same block, without re-querying the vault: [1](#0-0) 

Every normal vault mutator (`deposit`, `redeem`, `system-borrow`, `system-repay`) calls `(try! (accrue))` first, which is the only path that updates `index`/`lindex` and `last-update` consistently with what the market's cache expects: [2](#0-1) 

`socialize-debt`, however, mutates `lindex` (and `principal-scaled`, `total-borrowed`, `assets`) directly, with no call to `accrue` and no interaction whatsoever with the market's `index-cache`: [3](#0-2) 

The market's zToken price callcode reads the *cached* liquidity index, not the live vault state: [4](#0-3) 

Sequence within a single block:
1. An early transaction (or an earlier step of the same transaction, e.g. a health check, price batch, or another user's position evaluation) calls `accrue-and-cache` for vault `aid`, caching `{timestamp: stacks-block-time, aid}` → `{index, lindex}` (pre-loss values).
2. A liquidation of an undercollateralized position on that same vault triggers `vault-socialize-debt`, which writes down `lindex` in the vault to reflect the realized loss — but this never touches `index-cache`.
3. Later in the same block, a different position holding the corresponding zToken as collateral is evaluated (deposit, borrow, or health check) via `resolve-ztoken` → `get-cached-indexes`, which returns the stale, pre-loss `lindex` from step 1 instead of the vault's true post-loss `lindex`.
4. That position's collateral is over-valued relative to the actual (reduced) backing, letting a user borrow more than the collateral truly supports, or evade liquidation that should have triggered.

### Impact Explanation
The mispriced zToken collateral lets borrowers extract debt backed by assets that no longer exist at that value (the loss was already socialized). This is a direct path to protocol insolvency / theft of funds at rest, since new debt is issued against inflated collateral that cannot be recovered — meeting the Critical impact bar (protocol insolvency / theft of funds).

### Likelihood Explanation
Requires: (a) a vault entering socialize-debt within a block where its `aid`'s index was already cached earlier in that block, and (b) a subsequent zToken-collateral operation for the same vault later in the block. Socialize-debt events are rare (bad-debt events), but an attacker who anticipates or triggers one (e.g., via their own liquidation of a large distressed position) can deliberately sequence their own borrow/deposit transaction later in the same block to exploit the stale cache, making this attacker-triggerable rather than purely incidental.

### Recommendation
Have `socialize-debt` invalidate (delete or update) the corresponding `index-cache` entry for its `aid`/current `stacks-block-time`, or route the write-down through the same `accrue`-and-cache-update path so the cache always reflects the vault's post-loss state within the block.

### Proof of Concept
1. Block N, tx 1: User A's position (holding zSTX collateral) is evaluated for borrow eligibility → `accrue-and-cache` caches `{timestamp: T, aid: STX}` → `{index: I0, lindex: L0}`.
2. Block N, tx 2: A large STX debtor is liquidated with insufficient collateral; the shortfall is socialized via `vault-stx.socialize-debt`, which sets `lindex` to `L1 < L0` in the vault's state directly (no cache touch). [5](#0-4) 
3. Block N, tx 3: User A borrows against their zSTX collateral. `resolve-ztoken` calls `get-cached-indexes` for `aid: STX`, which still returns `L0` (cached in tx 1) instead of the true `L1`. [4](#0-3) 
4. User A's zSTX collateral is valued at `L0` instead of `L1`, letting them borrow more than the collateral is actually worth post-socialization.

  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
