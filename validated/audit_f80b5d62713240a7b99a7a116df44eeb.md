### Title
Empty-but-`Some` Signer Set from `make_signer_set` Yields a Zero Voting-Weight Threshold, Allowing Nakamoto Blocks to be Accepted Without Any Signer Signatures - ([File: stackslib/src/chainstate/stacks/boot/mod.rs, stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`RewardSet::make_signer_set` (the V0/pox-4 reward-set builder) can legitimately return `Some(vec![])` — a non-`None`, but empty, signer list — because it filters out every stacker whose `stacked_amt / threshold` floors to `0`, with no fallback mechanism to guarantee at least one non-zero-weight signer. This differs from the newer `pox_5_make_signer_set` path, which explicitly implements a largest-remainder ("Hare round") to avoid exactly this degenerate all-weights-floor-to-zero case. An empty signer set drives `RewardSet::total_signing_weight()` to `0`, which in turn makes `NakamotoBlockHeader::compute_voting_weight_threshold(0)` return `0`. In `NakamotoBlockHeader::verify_signer_signatures`, a block with an empty `signer_signature` vector then satisfies `total_weight_signed (0) < threshold (0)` as `false`, so the block is accepted as validly signed with zero real signatures.

### Finding Description
`RewardSet::make_signer_set` in [1](#0-0)  computes each signer's weight as `stacked_amt / threshold` and drops (`filter_map` → `None`) any entry whose weight floors to `0`. If every stacker's `stacked_amt` is individually below `threshold`, the resulting `signer_set` vector is empty, yet the function still returns `Some(vec![])` rather than `None`, because the early-return-`None` guard only fires when `entries` itself is empty [2](#0-1) .

Contrast this with the newer pox-5 code path, `pox_5_make_signer_set`, which explicitly recognizes and defends against this exact degenerate case with a largest-remainder ("Hare round") allocation, documented in its own comments as preventing "the entire signer set" from being "dropped" when many stackers individually floor to zero weight [3](#0-2) . The V0 `make_signer_set` used for pox-4 has no equivalent safeguard.

`RewardSet::total_signing_weight()` sums the weights of `self.signers()`; for an empty (but `Some`) vector this correctly, but consequentially, returns `Ok(0)` rather than an error [4](#0-3) .

`NakamotoBlockHeader::verify_signer_signatures` uses this `total_weight` to compute the approval threshold via `compute_voting_weight_threshold`, which for `total_weight = 0` evaluates `(0 * threshold) / 10 + ceil = 0` [5](#0-4) . The verification loop only increments `total_weight_signed` for signatures actually present in `self.signer_signature`; if that vector is empty, `total_weight_signed` stays `0`. The final check `if total_weight_signed < threshold` becomes `0 < 0`, which is `false`, so the function returns `Ok(0)` — the block is treated as validly signed [6](#0-5) .

This mirrors the reported bug class precisely: a "minimum requirement" (`_minimumYeetPoint` derived from a pot that is `0`) collapses to `0` and is trivially satisfied, letting the caller bypass the intended gate — here the gate is "a Nakamoto block must be signed by signers holding sufficient weight," and it collapses to "any block is accepted with zero signatures" when the reward-set weight totals `0`.

### Impact Explanation
If reachable, this breaks the core Nakamoto consensus invariant that block signer authorization is verified against a quorum-weighted threshold. A block accepted with zero real signer signatures is an "invalid block accepted network-wide" scenario — every node computing the same degenerate reward set would independently derive `threshold = 0` and accept the same unsigned block, so this would not by itself cause a chain split (all honest nodes agree), but it would mean the network's Nakamoto block-approval security property (requiring `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`/10 of signer weight) is silently voided for that reward cycle, allowing a single miner/proposer to push blocks without any signer participation.

### Likelihood Explanation
This requires the pox-4/V0 reward-set computation to produce a signer list where every individual stacker's locked amount, though the aggregate list is non-empty, floors to weight `0` under the per-slot `threshold`. Whether the caller that computes `threshold` for `make_signer_set` guards against this (e.g., by ensuring the reward-cycle's minimum stacking amount always exceeds `threshold`) could not be fully confirmed from the available indexed code — the exact call site setting the `threshold` argument passed into `make_signer_set` was not located within the available context. This uncertainty means the likelihood cannot be conclusively rated without further investigation of the caller; it is presented here as a structural asymmetry (missing safeguard present in the newer pox-5 path but absent in the V0 path) rather than a fully proven, exploitable end-to-end path.

### Recommendation
Add a fallback in `RewardSet::make_signer_set` (V0/pox-4 path) analogous to the pox-5 "Hare round": if the naive floor-division apportionment would produce zero total weight (or an empty signer set) despite non-empty stacked entries, guarantee at least one signer receives non-zero weight, or explicitly reject reward-set computation (as `pox_5_compute_and_update_signers` does when `signer_set.is_empty()`) rather than returning `Some(vec![])`. Additionally, `NakamotoBlockHeader::verify_signer_signatures` / `compute_voting_weight_threshold` should treat `total_weight == 0` as an unconditional validation failure rather than deriving a `threshold` of `0`.

### Proof of Concept
1. Construct a pox-4 reward cycle where `RawRewardSetEntry` entries are non-empty (every entry has `signer = Some(..)`), but each individual stacker's `amount_stacked` is `< threshold` (the per-slot amount), while the entries list itself is non-empty.
2. `RewardSet::make_signer_set(threshold, entries)` filters every entry to `weight == 0`, returning `Some(vec![])` (per `stackslib/src/chainstate/stacks/boot/mod.rs` L1051-1071).
3. This empty `Vec<NakamotoSignerEntry>` is stored as the reward cycle's `signers`.
4. `RewardSet::total_signing_weight()` returns `Ok(0)` (`boot/mod.rs` L495-503).
5. A miner proposes a Nakamoto block for this reward cycle with `signer_signature = vec![]` (no signer signed it).
6. `NakamotoBlockHeader::verify_signer_signatures` computes `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, `total_weight_signed = 0` (loop never runs), and the check `0 < 0` is `false`, so the function returns `Ok(0)` — the block passes signer-signature verification with zero actual signer participation (`nakamoto/mod.rs` L1115-1189, L1192-1207).

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
