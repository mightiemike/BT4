### Title
Deprecated (Cairo0) class cache entries bypass declaration re-verification after a state revert, allowing execution of undeclared classes and honest-node state divergence - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-validates that a cached Cairo1 (`V1`/`V1Native`) class is still actually declared in the current chain state before serving it from the process-global `ContractClassManager` cache, but it explicitly skips this re-validation for Cairo0 (`V0`) classes. Because the global class cache is a long-lived, per-process structure that outlives any single block's state (and is never invalidated on `revert_block`), a `V0` entry cached while a class was declared can still be served as valid after that declaration is rolled back (e.g., an L1/L2 reorg reverting the declaring block), letting later transactions use an undeclared class.

### Finding Description
`get_compiled_from_class_manager` first checks the global cache: [1](#0-0) 

For non-`V0` classes, the code deliberately re-checks `self.state_reader.is_declared(class_hash)` because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)". The `V0` branch (`RunnableCompiledClass::V0(_) => {}`) performs no such check and unconditionally trusts the cache hit.

The cache itself (`GlobalContractCache`/`ContractClassManager`) is a process-wide LRU cache keyed only by `ClassHash`, independent of block number or state root: [2](#0-1) 

It is populated whenever `get_compiled_from_class_manager` misses and calls `state_reader.get_compiled_classes` + `set_and_compile`: [3](#0-2) 

Nothing in `revert_block` (storage-level rollback) or elsewhere clears the `ContractClassManager` cache when a block containing a declare transaction is reverted: [4](#0-3) 

Consequently, once a Cairo0 class has been declared and executed at least once (populating the global cache), a subsequent chain reorg that reverts the declaring block leaves the class hash "undeclared" in committed state, yet the sequencer process retains a warm cache entry that is returned without any re-check, unlike the `V1` path. Any later transaction (e.g., a `deploy`/`deploy_account`/library-call referencing that class hash) will be executed as if the class were legitimately declared.

### Impact Explanation
This breaks the invariant that contract code execution must be gated by on-chain declaration. It can lead to:
- Execution and deployment of contracts using undeclared bytecode on nodes that happen to have a warm cache (from before the reorg), while nodes without the cached entry correctly reject the transaction as `UndeclaredClassHash` — producing **honest-node divergence** in execution results, state diffs, and the committed state root/block hash.
- Because the divergence is process/cache-state dependent (whether a given sequencer/full node executed the class before the reorg), different honest nodes can compute different state roots for the same block, undermining consensus safety.

### Likelihood Explanation
Triggering requires: (1) a Cairo0 class declare transaction that gets included and executed (any account can submit this, populating the cache on the executing node), and (2) a subsequent revert of that block (a normal, periodically-occurring operation for L2 sequencers reacting to L1/consensus reorgs) before the class hash is reused by a later legitimate transaction. Both are within the reach of unprivileged transaction senders / the ordinary node operation (not requiring a malicious operator/proposer), matching the "declarer/sender-reachable" and "state reads" categories in scope. The asymmetry with the `V1` code path (which the codebase authors already recognized needs re-validation "for reverted blocks") strongly suggests the `V0` omission is an oversight rather than an intentional safe design.

### Recommendation
Apply the same `is_declared` re-verification for `RunnableCompiledClass::V0` cache hits as is done for `V1`/`V1Native`, or invalidate/scope the `ContractClassManager` global cache on `revert_block` so stale class entries cannot outlive the block that declared them.

### Proof of Concept
1. Submit a `declare` transaction for a Cairo0 class `C` with hash `h`; it is included in block `N` and executed, causing `set_and_compile(h, CompiledClasses::V0(..))` to populate the global `ContractClassManager` cache on the sequencer node.
2. Trigger (or simulate, in a reorg-capable environment) a revert of block `N` via `revert_block`, which rolls back committed state (class `h` is no longer declared) but does not clear the in-memory `ContractClassManager` cache.
3. Submit a transaction (e.g. `deploy_account` or an invoke performing library-call) referencing class hash `h` before it is ever re-declared.
4. Observe that `get_compiled_from_class_manager` returns the cached `V0` entry without calling `is_declared`, so the transaction succeeds and executes/deploys code for a class that is not declared in the current committed state — while a node without the warm cache entry rejects the same transaction with `StateError::UndeclaredClassHash`, producing a state root/behavior divergence between nodes.

#[derive(Clone, Debug)]
pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }
