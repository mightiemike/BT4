## Title
Unbounded iteration over `VotesStore` during `doMaintenance()` enables a cheap Sybil DoS of block processing on every full node - (File: `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
`MaintenanceManager.doMaintenance()` is invoked synchronously on every node as part of block application whenever a block crosses the maintenance-time boundary (`applyBlock`). Inside it, `countVote(votesStore)` performs a full iteration over **every entry** in `VotesStore` — one entry per distinct address that cast a vote since the last maintenance cycle. Because casting a vote via `VoteWitnessContract` (or the TVM `voteWitness` native contract) only requires a trivial amount of frozen TRX (as little as `1 TRX` of `tronPower`), an attacker can cheaply create a large number of accounts, each casting one vote, to inflate `VotesStore` to an arbitrary size before the next maintenance boundary. This mirrors the reported bug class exactly: a cheap, unprivileged, per-user deposit (frozen TRX to vote) inflates an unbounded list that is then iterated in full inside a critical accounting routine, this time within the consensus-critical block-application path rather than inside a single transaction's gas budget.

### Finding Description
`MaintenanceManager.doMaintenance()` calls `countVote(votesStore)`: [1](#0-0) 

This iterates the entire `VotesStore` (a LevelDB-backed store keyed by voter address) with a `DBIterator`, deserializing and processing every `VotesCapsule` entry, then deleting it. `VotesStore` gains one entry per distinct address whenever `VoteWitnessActuator.countVoteAccount` (regular transaction) or `VoteWitnessProcessor.execute` (TVM native contract) is executed: [2](#0-1) 

Casting a vote only requires the voter's account to have positive `tronPower` (frozen balance), which per `VoteWitnessActuator.validate()`/`VoteWitnessProcessor.validate()` is bounded only by `MAX_VOTE_NUMBER` per transaction (30), with **no floor** on the minimum tronPower/frozen amount besides `sum > tronPower` being false — i.e. voting `1 TRX` for one witness is valid: [3](#0-2) 

`doMaintenance()` runs on the block-application hot path via `MaintenanceManager.applyBlock`, executed by every full node (not just SRs) when the block crosses `nextMaintenanceTime`: [4](#0-3) 

Because `VotesStore` is fully drained (`votesStore.delete(next.getKey())`) at the end of every maintenance run, its size resets to zero — but an attacker has the full maintenance interval (default 6 hours) to grow it back to an arbitrarily large size using many low-cost Sybil accounts, each requiring only a small frozen-TRX vote transaction. This is structurally identical to the `distributeDividends` bug class: a cheap per-user action (miniscule LP deposit → here, miniscule TRX freeze + vote) adds an entry to an unbounded list that is later iterated in full by a single, non-batched loop in a critical accounting/consensus routine.

### Impact Explanation
Unlike the original TVM/EVM analog where the unbounded loop is bounded by a per-transaction gas limit (causing a revert), `doMaintenance()` executes as node-internal Java code with no gas or time budget — a sufficiently inflated `VotesStore` can make `countVote` take excessive wall-clock time on every full node processing that block. This can delay or stall block validation network-wide at the maintenance boundary, degrading availability of the network (DoS via protocol implementation) and, in the worst case (if some SR/node instances are slower or resource-constrained than others), risks nodes falling behind or missing block-production slots at the maintenance boundary, since the same code path runs deterministically but the CPU/O(n) I/O time is not accounted for. This is a witness-reward/DoS-relevant analog matching the report's bug class (unbounded iteration over a cheaply-grown, attacker-influenced collection in a periodic reward/dividend-adjacent routine).

### Likelihood Explanation
Reachability requires only ordinary, unprivileged transactions (`VoteWitnessContract` broadcasts, or TVM `voteWitness` calls), each individually valid and cheap (minimal frozen TRX). No special permissions, leaked keys, or malicious peers are needed. The main cost to an attacker is the number of distinct addresses (Sybil accounts) needed and the small TRX amount to freeze per account, both of which are attacker-controlled and can be amortized over the ~6 hour maintenance window.

### Recommendation
- Bound per-cycle processing: cap the number of `VotesStore` entries processed per maintenance run and carry over the remainder to subsequent runs/batches, or process votes incrementally as they arrive instead of accumulating an unbounded backlog for one atomic full-store scan.
- Alternatively, restructure vote accounting to a pull-based/point-in-time delta model (similar to the "dividendsPerShare"/VI mechanism already used for reward computation in `MortgageService`/`RewardViCalService`) so that `doMaintenance()` does not need to iterate all voters, only witnesses.
- Consider introducing a minimum frozen-balance threshold for casting a vote to raise the Sybil cost.

### Proof of Concept
1. Prior to the current maintenance-time boundary, generate N distinct funded accounts (N large, e.g. tens/hundreds of thousands).
2. For each account, broadcast a `FreezeBalanceV2Contract`/`FreezeBalanceContract` freezing a minimal amount (e.g. 1 TRX) to obtain nonzero `tronPower`, then broadcast a `VoteWitnessContract` casting 1 vote for any existing witness. Each of these is accepted by `VoteWitnessActuator.validate()`/`execute()` because `sum` (1 TRX * `TRX_PRECISION`) does not exceed `tronPower`.
3. Each successful vote transaction adds/updates one entry keyed by the voter's address in `VotesStore` (via `VoteWitnessActuator.countVoteAccount`).
4. When the next block crosses `nextMaintenanceTime`, every node calls `MaintenanceManager.applyBlock` → `doMaintenance()` → `countVote(votesStore)`, which must fully iterate and deserialize all N entries before it can complete, delaying that node's block-application step in proportion to N.

  public void applyBlock(BlockCapsule blockCapsule) {
    long blockNum = blockCapsule.getNum();
    long blockTime = blockCapsule.getTimeStamp();
    long nextMaintenanceTime = consensusDelegate.getNextMaintenanceTime();
    boolean flag = consensusDelegate.getNextMaintenanceTime() <= blockTime;
    if (flag) {
      if (blockNum != 1) {
        updateWitnessValue(beforeWitness);
        beforeMaintenanceTime = nextMaintenanceTime;
        doMaintenance();
        updateWitnessValue(currentWitness);
      }
      consensusDelegate.updateNextMaintenanceTime(blockTime);
      if (blockNum != 1) {
        //pbft sr msg
        pbftManager.srPrePrepare(blockCapsule, currentWitness,
            consensusDelegate.getNextMaintenanceTime());
      }
    }
    consensusDelegate.saveStateFlag(flag ? 1 : 0);
    //pbft block msg
    if (blockNum == 1) {
      nextMaintenanceTime = consensusDelegate.getNextMaintenanceTime();
    }
    pbftManager.blockPrePrepare(blockCapsule, nextMaintenanceTime);
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
