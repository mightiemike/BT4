This confirms the key fact needed to resolve the question: the `Rent` value used to validate the fee payer in `validate_fee_payer` / `check_static_account_rent_state_transition` does **not** come from `SysvarCache::get_rent()` at all.

Instead, in `runtime/src/bank.rs`, the `TransactionProcessingEnvironment.rent` field is populated directly from `self.rent_collector.rent.clone()` [1](#0-0) , and this same `environment.rent` is threaded through `load_and_execute_sanitized_transactions` into both `validate_transaction_nonce_and_fee_payer` (which calls `validate_fee_payer`) and `load_transaction` [2](#0-1) . The `SysvarCache`'s `rent` entry (populated via `fill_missing_entries`, consumed via `get_rent()`) is a completely separate code path used only for serving the on-chain `Rent` sysvar to programs via syscalls (`sol_get_sysvar`) [3](#0-2)  and is not consumed anywhere in `validate_fee_payer` or `check_static_account_rent_state_transition`.

Since `bank.rent_collector.rent` is a single, deterministically-updated field on the `Bank` struct (updated during bank creation/feature activation, not something that can independently "drift" from a hypothetical alternate rent source at slot boundaries), and the fee-payer path never touches `SysvarCache::get_rent()`, there is no discrepancy between "cached Rent via `fill_missing_entries`" and "Rent used by `check_static_account_rent_state_transition`" — these are simply not the same code path, so the premise of the question is factually incorrect.

Furthermore, `validate_fee_payer` in `svm/src/account_loader.rs` correctly performs the arithmetic check (`checked_sub(min_balance).checked_sub(fee)`) before debiting, and then calls `check_static_account_rent_state_transition` using the exact same `rent: &Rent` reference passed to the whole `validate_transaction_nonce_and_fee_payer`/`load_transaction` sequence for that same transaction [4](#0-3) . There is no slot-boundary window where a different `Rent` value could be used between the fee-debit and the rent-state check within a single transaction's processing — they use the identical `Rent` struct reference. Existing tests (`test_invalid_rent_state_changes_fee_payer` in `runtime/src/bank/tests.rs`, `test_validate_transaction_fee_payer_insufficient_rent` in `svm/src/transaction_processor.rs`) explicitly cover the exact scenario described (fee payer at rent-exempt minimum, fee debit dropping it below minimum) and confirm `InsufficientFundsForRent` is correctly returned [5](#0-4) [6](#0-5) .

pub fn validate_fee_payer(
    payer_account: &mut AccountSharedData,
    payer_index: IndexOfAccount,
    error_metrics: &mut TransactionErrorMetrics,
    rent: &Rent,
    fee: u64,
    relax_post_exec_min_balance_check: bool,
) -> Result<()> {
    if payer_account.lamports() == 0 {
        error_metrics.account_not_found += 1;
        return Err(TransactionError::AccountNotFound);
    }
    let system_account_kind = get_system_account_kind(payer_account).ok_or_else(|| {
        error_metrics.invalid_account_for_fee += 1;
        TransactionError::InvalidAccountForFee
    })?;
    let min_balance = match system_account_kind {
        SystemAccountKind::System => 0,
        SystemAccountKind::Nonce => {
            // Should we ever allow a fees charge to zero a nonce account's
            // balance. The state MUST be set to uninitialized in that case
            rent.minimum_balance(NonceState::size())
        }
    };

    payer_account
        .lamports()
        .checked_sub(min_balance)
        .and_then(|v| v.checked_sub(fee))
        .ok_or_else(|| {
            error_metrics.insufficient_funds += 1;
            TransactionError::InsufficientFundsForFee
        })?;

    let pre_balance = payer_account.lamports();
    payer_account
        .checked_sub_lamports(fee)
        .map_err(|_| TransactionError::InsufficientFundsForFee)?;
    let post_balance = payer_account.lamports();

    check_static_account_rent_state_transition(
        pre_balance,
        post_balance,
        payer_account.data().len(),
        rent,
        payer_index,
        relax_post_exec_min_balance_check,
    )
}
