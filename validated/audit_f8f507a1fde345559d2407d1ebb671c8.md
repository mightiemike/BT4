## Title
State-integrity verification gap: `TransactionOutput::ensure_match_transaction_info` never checks state-checkpoint hashes, allowing a divergent state root to pass replay/verification - ([File: types/src/transaction/mod.rs])

## Summary
`TransactionOutput::ensure_match_transaction_info` is the invariant that binds a locally-computed execution result to the authenticated `TransactionInfo` stored in the transaction accumulator (used by chunk replay, state-sync verification, the debugger, and `db-tool replay-on-archive`). It checks status, gas, write-set hash, and event-root hash, but explicitly and admittedly skips comparing `state_checkpoint_hash` / `hot_state_checkpoint_hash` / `position_state_checkpoint_hash`. [1](#0-0) 

## Finding Description
`ensure_match_transaction_info` validates that a re-executed `TransactionOutput` matches a signed `TransactionInfo` from the ledger (proof-bearing structure covered by the transaction accumulator). It compares status, gas used, `write_set_hash` vs `state_change_hash`, and `event_root_hash`, but the function's own comment states the state/hot-state/position checkpoint hashes are intentionally left unchecked: [2](#0-1) 

The `state_checkpoint_hash` field is the "root hash of the Sparse Merkle Tree describing the world state at the end of this transaction" and is exactly the field that binds the committed `TransactionInfo` (and therefore the accumulator/root) to a specific world-state value. [3](#0-2) 

Because this comparator omits the checkpoint hash, any consumer relying on `ensure_match_transaction_info` to detect a divergence between locally recomputed state and the authenticated ledger state will not detect it if only the state root diverges while status/gas/write-set/events happen to match (or where the divergence is purely in checkpoint-hash computation logic itself, e.g. a bug in `DoStateCheckpoint`/hot-state/position-state root computation). This directly affects the "replay-verify tooling (e.g. db-tool's `replay_on_archive`)" path called out in the code's own TODO, which is used to validate that historical execution matches the authenticated chain state. [4](#0-3) [5](#0-4) 

## Impact Explanation
This breaks a state-commitment/proof-integrity invariant: an authenticated `TransactionInfo`'s state-checkpoint hash is supposed to bind the ledger to one specific state root, but the verification helper meant to confirm "locally recomputed output equals authenticated info" silently skips checking that binding. Any bug elsewhere that produces an incorrect state/hot-state/position-state root (e.g. in `DoStateCheckpoint`, hot-state materialization, or the new "trading native state roots" position-state summary) would not be caught by this check, and tooling like `replay_on_archive` could report a "successful replay" while the authenticated position/state root has actually diverged from local execution — i.e., a hard-fork-class silent state divergence going undetected by the very tool meant to catch it.

## Likelihood Explanation
This is not itself an attacker-triggerable exploit against a running validator's commit path (the accumulator/consensus signature scheme itself is unaffected), so it does not by itself let an attacker forge state. Its severity comes from being a detection-gap in the ledger-integrity verification tooling: it means an actual state-computation regression (bug) can escape both normal replay verification and the archive-replay checker, extending the "hard-fork-only divergence during commit, replay, restore, or proof verification" impact criterion. The comment in the code itself confirms this is a known, currently-live gap rather than a hypothetical one.

## Recommendation
Extend `ensure_match_transaction_info` to also compare `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, and `position_state_checkpoint_hash()` against the corresponding hashes computed by `DoStateCheckpoint` whenever these are present (i.e., pass them in similarly to `expected_write_set`/`expected_events`), so replay/verification paths (`replay_on_archive`, chunk replayer, debugger) fail loudly on any state-root divergence instead of silently passing.

## Proof of Concept
No PoC is provided because this is a detection-gap in verification tooling rather than a directly exploitable state-corruption primitive; the local code (its own inline TODO) is sufficient to establish the broken invariant: `ensure_match_transaction_info` performs status/gas/write-set/event checks but not checkpoint-hash checks.     pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
