### Title
Hardcoded 5% slippage tolerance on spot-price Uniswap V3 quotes lets an unprivileged attacker sandwich PRC20-auto-swap deposits and gas refunds - ([File: x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
Whenever Push Chain auto-swaps a deposited PRC20 (or a leftover gas-token refund) into native PC, the keeper fetches a spot price from Uniswap V3's `QuoterV2.quoteExactInputSingle` and then hardcodes the acceptable slippage to exactly 5% (`quote * 95 / 100`) before executing the real swap. Because the quote is a single-block spot read (not a TWAP) and the 5% band is a fixed Go constant rather than a value tied to pool depth/config, an unprivileged actor can move the pool price with an ordinary trade immediately before the module's swap executes and capture up to the full 5% band from the user's/protocol's swap, in the same block, with only honest validators and honest nodes involved.

### Finding Description
The pattern is repeated in three swap paths:

1. Inbound GAS deposit auto-swap: [1](#0-0) 
2. Inbound GAS_AND_PAYLOAD deposit auto-swap: [2](#0-1) 
3. Outbound gas-refund auto-swap: [3](#0-2) 

All three call `GetDefaultFeeTierForToken` (dynamic, read from `UniversalCore.defaultFeeTier`) and `GetSwapQuote` (a `CallEVM` with `commit=false` against `QuoterV2.quoteExactInputSingle`, using `SqrtPriceLimitX96 = 0`, i.e. an unbounded spot-price read): [4](#0-3) 

Immediately after obtaining that spot quote, every call site hardcodes the slippage tolerance as a literal 95/100 (5%) rather than deriving it from pool liquidity, trade size, or any governance/config parameter:
```go
// 5% slippage: minPCOut = quote * 95 / 100
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
```
This is the direct structural analog of the external report: a fixed numeric constant is substituted for a value that should reflect the actual, current, pool-specific economics — in the Uniswap V2 report it was the swap fee (997/1000) ignoring the factory's real per-pool fee; here it is the slippage bound ignoring the real, attacker-influenceable pool price/depth. Because `quote` is read and consumed within essentially the same state-transition (no TWAP, no oracle, no multi-block delay), a party who trades against the same Uniswap V3 pool in a preceding transaction of the same block can shift the spot price, causing `GetSwapQuote` to return an already-manipulated number, and the subsequent `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` to execute at that manipulated price while still satisfying the fixed `minPCOut` bound (which is derived from the same manipulated quote). The attacker then reverses the trade after the module's swap lands, extracting value up to the 5% band, funded out of the depositing user's PRC20-to-PC conversion or out of the protocol's/sender's excess-gas refund.

### Impact Explanation
This corrupts native/PRC20 asset accounting reachable purely from an ordinary user's cross-chain deposit (GAS or GAS_AND_PAYLOAD inbound) or from a completed outbound's gas refund — no privileged validator or TSS misbehavior is required, and honest validators voting normally will still trigger the vulnerable auto-swap logic. Depositors receive less native PC than the fair market rate, and the difference is siphoned to whoever sandwiches the swap, i.e. an economic drain of user/protocol-controlled funds reachable through the default deposit path — squarely inside the "corruption of PRC20 or native asset accounting" and "draining ... of user or protocol-controlled funds" impact categories.

### Likelihood Explanation
The trigger requires only: (1) observing a pending inbound deposit or a pending outbound refund (both are on-chain/public once submitted or once quorum votes accumulate), and (2) placing an ordinary trade against the relevant Uniswap V3 pool before the module's swap executes in the block, then reversing it afterward. No special privileges, validator collusion, or TSS compromise are needed — only normal transaction submission by an unprivileged actor, and the value extractable scales with pool illiquidity and deposit size, both of which are attacker-observable in advance.

### Recommendation
Replace the fixed 95/100 constant with a slippage bound derived from a manipulation-resistant reference price (e.g., a TWAP over several blocks, or a bound configured per-pool/per-token based on realistic liquidity depth), and/or cap the maximum single-block price impact allowed for these protocol-initiated swaps. Consider also making the tolerance a governance-controlled parameter per token/pool rather than a hardcoded literal duplicated across `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, and `outbound.go`.

### Proof of Concept
1. User submits a large USDC (or other PRC20-backed) GAS deposit inbound on an EVM source chain; validators vote it to quorum.
2. In the same Push Chain block that will process the final `MsgVoteInbound` (which triggers `ExecuteInboundGas`), attacker submits a transaction that swaps a large amount into/out of the corresponding PRC20/WPC Uniswap V3 pool to move the spot price unfavorably for the upcoming auto-swap.
3. `GetSwapQuote` in [5](#0-4)  returns a quote based on the now-manipulated pool state; `minPCOut` is computed as 95% of that already-bad quote in [6](#0-5) .
4. `CallPRC20DepositAutoSwap` executes at the manipulated price, still satisfying `minPCOut`, so it does not revert.
5. Attacker submits a reversing trade later in the same block, restoring the pool price and pocketing the difference — funded by the value that should have gone to the depositing user.

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
