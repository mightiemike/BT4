Based on my investigation, I've confirmed a concrete analog to the reported bug class. Here is the finding.

### Title
Attacker-controlled `Recipient` field on an isCEA inbound lets gas fees for arbitrary attacker-supplied payload data be billed to a third-party CEA contract that never authorized the call - ([File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go] / [File: x/uexecutor/keeper/execute_inbound_funds_and_payload.go] / [File: x/uexecutor/keeper/fees.go])

### Summary
The original report's bug class is: a struct carries an address field (`Dispute.proposer`) that is never checked against the actual party responsible for the debited action, so an attacker can name an arbitrary victim to be billed. Push Chain's `isCEA` inbound-execution path has the same shape: `Inbound.Recipient` is a free-form, attacker/relayer-controlled field (originating from the source-chain gateway event) that is used, unvalidated against any consent/opt-in record, both as the EVM contract to invoke with attacker-controlled calldata and as the account whose UPC balance is billed for the resulting gas usage.

### Finding Description
When an inbound is marked `IsCEA=true`, `ExecuteInboundFundsAndPayload` / `ExecuteInboundGasAndPayload` treat `utx.InboundTx.Recipient` as the destination to call, with no requirement that the destination contract has registered/opted in to accept module-originated `executeUniversalTx` calls billed to itself: [1](#0-0) 

For a non-UEA recipient that merely has deployed code, the module directly calls `executeUniversalTx` on it as the module account (`ueModuleAccAddress`, a "module sender" call that bypasses UEA signature verification per the documented model) with attacker-controlled `payload` bytes derived straight from `utx.InboundTx.UniversalPayload.Data`: [2](#0-1) [3](#0-2) 

Immediately after, `DeductGasFeesFromReceipt` burns UPC from the same `Recipient` address (`ueaAddr`) based on `receipt.GasUsed` and the attacker-chosen `MaxFeePerGas`/`MaxPriorityFeePerGas` in `UniversalPayload`: [4](#0-3) 

Nowhere in this flow — `ValidateForExecution`, the isCEA branch, or `DeductGasFeesFromReceipt` — is there a check that the `Recipient` contract has registered itself as a valid CEA integrator willing to accept module-driven `executeUniversalTx` calls and their associated gas billing. Integration tests confirm the design explicitly allows the `Recipient` to be picked independently of `Sender`/`Sender`'s UEA, and that gas is deducted straight from that recipient regardless of who initiated the source-chain deposit: [5](#0-4) [6](#0-5) 

Because `Recipient` and `UniversalPayload.Data`/`GasLimit` are all attacker-controlled inputs relayed faithfully by honest validators from a real (but arbitrarily small) source-chain deposit event, an attacker can:
1. Deploy or target any existing on-chain contract at `Recipient` that happens to implement the `executeUniversalTx(sourceChain, ceaAddress, payload, amount, prc20AssetAddr, txId)` selector (the CEA-recipient ABI in `types.ParseRecipientContractABI`) and holds UPC for gas.
2. Trigger a minimal real deposit on any supported source chain naming that `Recipient`.
3. Supply payload `Data` designed to make the callee execute gas-expensive logic.
4. Cause `DeductGasFeesFromReceipt` to burn the victim contract's UPC balance for gas usage the victim never consented to and had no way to reject in advance, since the module call happens unconditionally once quorum is reached.

### Impact Explanation
This is an unauthorized-fund-drain / gas-griefing vector against any CEA-integrated contract's UPC balance: the wrong party (the named `Recipient` contract, not the attacker who triggered execution) is billed for arbitrary attacker-chosen execution cost, directly mirroring the original report's "wrong user can be charged" pattern (unauthorized debit of a party who never authorized the specific charge).

### Likelihood Explanation
The isCEA flow is specifically designed for third-party dApp contracts to receive cross-chain calls, so `Recipient` values pointing at real, funded, code-bearing contracts are common by design — the attacker does not need any privileged role, only the ability to submit a real (even dust-value) deposit on an already-supported source chain naming the victim contract as `Recipient`, which honest validators will relay as-is.

### Recommendation
- Require CEA-recipient contracts to explicitly register/opt in (e.g., via `x/uregistry`) before the module will invoke `executeUniversalTx` on them and bill them for gas, rather than treating any code-bearing address named in `Recipient` as an implicit acceptor.
- Bound or cap the gas cost billable to a CEA recipient per inbound (e.g., relative to the bridged `amount`), and/or let the registered CEA contract declare a maximum gas/fee it is willing to be charged.
- Add regression tests that a `Recipient` contract which has not opted in cannot be called/billed via the isCEA path.

### Proof of Concept
1. A victim team deploys `VictimCEA` implementing the recipient ABI (`executeUniversalTx(...)`) and funds it with UPC to pay for expected legitimate cross-chain calls, per the CEA integration pattern shown in `test/integration/uexecutor/inbound_cea_smart_contract_test.go`.
2. Attacker calls the source-chain gateway contract with a trivial deposit (e.g., 1 unit of a supported asset), setting `recipient = VictimCEA`, `isCEA = true`, and payload `Data` crafted to make `VictimCEA.executeUniversalTx` perform expensive computation (loop, storage writes, etc. within `VictimCEA`'s own logic).
3. Honest validators observe and vote on this real (if economically trivial) event; quorum finalizes it into a `UniversalTx` as shown in `msg_vote_inbound.go`.
4. `ExecuteInboundFundsAndPayload`/`ExecuteInboundGasAndPayload` calls `CallExecuteUniversalTx(ctx, VictimCEA, ...)` then `DeductGasFeesFromReceipt(ctx, ctx, VictimCEA, receipt, payload)`, burning `VictimCEA`'s UPC for the gas the attacker's calldata caused it to consume — for repeated dust-value deposits, this drains `VictimCEA`'s UPC balance without its consent.

// CallExecuteUniversalTx calls executeUniversalTx on a smart-contract recipient.
// This is used for isCEA inbounds whose recipient is a deployed contract (not a UEA).
func (k Keeper) CallExecuteUniversalTx(
	ctx sdk.Context,
	recipientAddr common.Address,
	sourceChain string,
	ceaAddress []byte,
	payload []byte,
	amount *big.Int,
	prc20AssetAddr common.Address,
	txId [32]byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	recipientABI, err := types.ParseRecipientContractABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse recipient contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		recipientABI,
		ueModuleAccAddress,
		recipientAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"executeUniversalTx",
		sourceChain,
		ceaAddress,
		payload,
		amount,
		prc20AssetAddr,
		txId,
	)
}

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

	t.Run("gas fees deducted from smart contract recipient after executeUniversalTx", func(t *testing.T) {
		chainApp, ctx, vals, inbound, coreVals, contractAddr := setupInboundCEASmartContractTest(t, 4)

		// Fund the smart contract with upc so fee deduction can succeed
		contractAccAddr := sdk.AccAddress(contractAddr.Bytes())
