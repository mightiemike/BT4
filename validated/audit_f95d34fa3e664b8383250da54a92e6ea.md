### Title
Floor-division-then-multiply in `BuiltinInstanceLimits::induced_gas_costs` causes systematic undercharging of proving gas in bouncer weight accounting - (File: crates/blockifier/src/bouncer.rs)

### Summary
`BuiltinInstanceLimits::induced_gas_costs` derives a per-primitive **proving-gas cost** by computing `floor(proving_gas / limit)` for each builtin, before that per-unit cost is later multiplied by the transaction's actual usage count in `cairo_primitives_to_gas`. This is the classic "divide before multiply" pattern flagged in the referenced report: pre-dividing truncates the per-unit rate, and the truncation error is then amplified by the usage count, causing the computed total proving gas for a transaction/block to be systematically lower than the mathematically precise `proving_gas * count / limit`.

### Finding Description
`BuiltinInstanceLimits::induced_gas_costs` computes the per-instance proving-gas cost by floor division: [1](#0-0) 

This per-unit cost (`BuiltinGasCosts`) is then used elsewhere as a multiplier against the *count* of primitive usages to compute the total proving gas contributed by a transaction, via `cairo_primitives_to_gas`: [2](#0-1) 

This is precisely the anti-pattern from the referenced report: `cost_per_unit = floor(A / B)` then `total = cost_per_unit * count`, instead of `total = (A * count) / B`. Because `proving_gas / limit` is floored first, and that floored value is then multiplied by `count` (which can be very large, e.g. millions of instances of `range_check`, `bitwise`, etc., per `BuiltinInstanceLimits::default()`), the rounding error of up to `limit - 1` in the per-unit rate gets multiplied by `count`, producing a total proving-gas estimate that is lower than the mathematically precise value by up to `count * (limit-1)/limit` in relative terms — non-trivial when usage is a sizeable fraction of the per-block limit (the exact conditions highlighted in the reference report: "the precision loss becomes more serious at lower discrepancies").

This function is called from `BouncerConfig::builtin_gas_costs()`, which is used in `get_tx_weights` (reachable per-transaction) to compute `proving_gas` bouncer weights: [3](#0-2) [4](#0-3) 

The resulting `proving_gas` bouncer weight is what gates block-fullness checks (`has_room`/`try_update`) against `block_max_capacity.proving_gas`, i.e., the actual per-block proving-resource budget that provers must respect.

### Impact Explanation
Because the bouncer's proving-gas accounting *undercounts* the true resource cost of builtin-heavy transactions (any unprivileged sender can submit transactions that use range_check, bitwise, pedersen, poseidon, ecdsa, ec_op, keccak, add_mod, mul_mod, or blake builtins in arbitrary quantities), a sequencer applying `induced_gas_costs` can pack a block with more proving-gas-heavy transactions than the actual proving-hardware budget (`block_max_capacity.proving_gas`) allows for. This risks producing blocks that exceed the real prover's processing capability, which is a resource/DoS-class impact on block provability — potentially preventing the network from confirming/proving new blocks within the configured proving budget when usage is near (but under) the per-primitive instance limits, a state directly reachable by ordinary transaction senders choosing to maximize builtin usage.

### Likelihood Explanation
This is triggered by an ordinary transaction sender/contract with high natural builtin usage; no special privileges are required. Likelihood of the discrepancy mattering is a function of counts approaching the configured limits (e.g., `pedersen: 2_000_000`, `range_check: 66_666_666`, etc., per `BuiltinInstanceLimits::default`), which are large but achievable across a block's aggregate transaction set. The magnitude of undercounting per primitive is bounded by `count * (limit - 1) / limit`, so it grows with usage; it is a systematic bias (always in the same, favorable-to-cramming direction) rather than a random rounding artifact, making it a consistent latent under-billing of the true proving-gas budget rather than a one-off edge case.

### Recommendation
Avoid pre-computing a floored per-unit `BuiltinGasCosts` rate. Instead:
- Compute the total proving gas contribution for a given primitive directly as `(proving_gas * count) / limit` (multiply before divide), summing numerators across primitives if a combined ceiling/rounding decision is needed, or
- If a stable, cacheable per-unit rate is required for API/consistency reasons, apply a rounding-up (`div_ceil`) at the point where a single per-unit price is unavoidable, and clearly document that the derived `BuiltinGasCosts` is an upper bound, not an exact per-unit price — or better, keep the exact rational (`Ratio<u64>`) form (as is already done for `ResourceCost`/`VmResourceCosts` elsewhere in the codebase, e.g. `resource_cost_to_u128_ratio`) instead of collapsing to an integer `u64` cost per builtin before multiplying by usage counts.

### Proof of Concept
Given `BuiltinInstanceLimits::default()` with `range_check: 66_666_666` and a block proving-gas budget of `6_000_000_000` (as used in the existing regression test `test_induced_builtin_gas_costs_from_default_limits`): [5](#0-4) 

`induced_gas_costs` yields `range_check: 90` (i.e., `floor(6_000_000_000 / 66_666_666) = 90`, whose exact ratio is `90.000000...`, close but not exact in general). For an arbitrary limit/budget pair without such a clean ratio, e.g. `proving_gas = 6_000_000_001`, `limit = 66_666_667`:
- Current implementation: `cost_per_unit = floor(6_000_000_001 / 66_666_667) = 89`; for `count = 66_666_666` (near the limit) usages, `total = 89 * 66_666_666 = 5_933_333_274`.
- Precise calculation: `(6_000_000_001 * 66_666_666) / 66_666_667 ≈ 5_999_999_991`.

The difference (~66.6 million gas units, over 1% of the per-primitive proving-gas budget) demonstrates the same class of precision loss described in the referenced report, here manifesting as under-accounted proving-gas weight in the bouncer rather than under-collected protocol fees.

**Uncertainty note:** I was not able to fully trace how `builtin_gas_costs()` (and thus `induced_gas_costs`) results are cached/reused across the block (e.g., whether it's recomputed per-tx from a fixed `block_max_capacity.proving_gas`, which would make the bias deterministic and block-wide) versus any per-tx adjustment; a Devin session with full repo access should verify the exact call sites and confirm whether this systematic bias is bounded by existing overflow/safety margins elsewhere in the bouncer or fee-charging pipeline before treating this as an exploitable Medium/High finding rather than a benign conservative rounding choice.

```rust
impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),

}
```

```rust
pub fn cairo_primitives_to_gas(
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    // NOTE: 'blake' is currently the only supported opcode, by being included in the
    // builtin_gas_costs.
    cairo_primitives_gas_costs: &BuiltinGasCosts,
) -> GasAmount {
    let cairo_primitives_gas =
        cairo_primitives_counters.iter().fold(0u64, |accumulated_gas, (name, &count)| {
            let cairo_primitive_weight =
                cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap();
            cairo_primitive_weight
                .checked_mul(u64_from_usize(count))
                .and_then(|builtin_gas| accumulated_gas.checked_add(builtin_gas))
                .unwrap_or_else(|| {
                    panic!(
                        "Overflow while converting cairo primitives counters to gas.\nCairo \
                         primitive: {name:?}, Weight: {cairo_primitive_weight}, Count: {count}, \
                         Accumulated gas: {accumulated_gas}"
                    )
                })
        });

    GasAmount(cairo_primitives_gas)
}
```
