The hypothesis requires a downstream verifier to recompute `script_hash` using a *different* hashing scheme than the one used at commit time. In the current codebase, there is only a single deterministic derivation path:

1. `TransactionMetadata::new` computes `script_hash` once as `HashValue::sha3_256_of(s.code())` directly from the raw `Script` payload bytes, and this is the only place the hash is derived from transaction input. [1](#0-0) 

2. `SessionId::txn_meta` (and the other session constructors) simply clone this already-computed `script_hash` from `TransactionMetadata` — they do not independently re-derive it from the script bytes using any alternate scheme. [2](#0-1) 

3. `SessionListener::start` copies this same value verbatim into `NativeTransactionContext.script_hash`, and `native_get_script_hash` returns it unmodified to Move code. [3](#0-2) [4](#0-3) 

4. The replay path (`third_party/move/mono-move/replay-benchmark/src/data.rs`) reconstructs `SessionId` from the transaction's `replay_protector` for entry-function transactions with an explicitly empty `script_hash: vec![]`, which matches the original execution behavior (entry functions have no script hash) rather than diverging from it. [5](#0-4) 

There is no second, competing derivation of `script_hash` anywhere in this codebase that a "downstream verifier" could apply differently — commit-time execution and replay both invoke the identical `sha3_256_of(script_code)` computation, gated by the same deterministic VM logic that all validators/replayers run. The scenario described (a hypothetical future framework upgrade that changes `SessionId::script_hash` derivation) would require an actual protocol/consensus-breaking code change shipped and activated via governance — that is a trusted-operator/hard-fork event requiring explicit chain upgrade, not something an unprivileged transaction, package, API, or bytecode input can trigger on its own. Per the decision standard, "depends on trusted operator mistakes alone" content is excluded, and there is no current divergence in the shipped code for an attacker to exploit today.
