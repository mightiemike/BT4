### Title
Base-fee truncation in `CalculateGasCost` can zero out UEA gas-fee accounting for sub-1-upc base fees - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` in `x/uexecutor/keeper/fees.go` converts the feemarket `LegacyDec` base fee into a whole `upc` amount by doing an integer `Div` by `1e18` [1](#0-0) . This mirrors the analog bug class in the external report: an approximation/derivation that is only accurate for values far from a boundary is applied unconditionally, and for small values the division truncates the meaningful signal to zero, producing a result that silently deviates from the true value by 100%.

### Finding Description
The code comment asserts "the base fee is always a whole number of upc -- no fractional upc exists," and on that assumption does an integer division that discards everything below `1e18` (i.e., any `baseFee < 1` whole `upc`) [2](#0-1) . The feemarket's base fee, however, is a `LegacyDec` maintained by the EIP-1559-style base-fee adjustment mechanism, and there is no code path in this function (or that I was able to verify was enforced upstream) guaranteeing it is always constrained to be an integer multiple of `1e18` in `upc` units. If the effective base fee per gas unit is legitimately sub-1-`upc` (e.g. a fractional gas price such as `0.0005 upc`/gas, which is plausible depending on decimals/config), `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates the value to `0`.

This feeds directly into `effectiveGasPrice := new(big.Int).Set(baseFeeBig)` and then `gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)` [3](#0-2) . When `effectiveGasPrice == 0`, `gasCost` is `0` regardless of `gasUsed`. `DeductGasFeesFromReceipt`, which is called after every UEA-derived EVM execution (`MsgExecutePayload` / inbound execution flow), short-circuits when `gasCost.Sign() <= 0` and returns `nil` without deducting or burning any fee from the recipient's account [4](#0-3) .

The consequence: an attacker (any user submitting `MsgExecutePayload`, which is gasless and permissionless per `app/README.md`) can execute arbitrary EVM code through their UEA and consume real EVM gas without any accounted `upc` fee deduction, whenever the current base fee sits below `1e18` in the `LegacyDec` representation (i.e., below 1 whole `upc` per gas unit).

### Impact Explanation
This corrupts gas-fee accounting for module-originated `DerivedEVMCall` / UEA execution: real EVM computation is performed by the chain but the protocol's own fee-burn invariant (`DeductAndBurnFees`) is silently skipped for a broad, attacker-reachable input range (any state where the network base fee per gas is sub-1-upc), rather than for a genuine "no fee owed" edge case. This is a corruption of gas fee accounting and a potential DoS/resource-exhaustion vector reachable purely through ordinary unprivileged `MsgExecutePayload` submissions (the flow explicitly says gasless messages are exempt from the ante-level fee, so this backend deduction is the only fee-collection point for UEA execution costs) — falling within the "corruption of ... gas fee accounting" and "denial of service ... reachable without privileged control" impact categories.

### Likelihood Explanation
Likelihood depends on whether the feemarket's base fee can, in practice, sit below `1e18` (1 whole `upc`) in `LegacyDec` terms during normal chain operation (e.g., low-congestion periods with a low minimum base fee configured, or during early-network bootstrap with a small starting base fee). I was not able to fully verify, within the available tool budget, the exact default/minimum base-fee parameter value used by this specific feemarket configuration, so I cannot confirm with certainty whether this state is reachable on Push Chain's actual deployed parameters — this is a genuine gap in my verification. If the minimum base fee is configured well above `1e18`, the bug is latent/unreachable; if it can dip below `1e18` (which is a very plausible feemarket parameter, since 1 "whole" `upc` may represent a large real-world value depending on decimals), the issue is trivially and repeatedly triggerable by any user.

### Recommendation
Do not derive the gas price by discarding sub-unit precision via integer division. Perform the full computation in `LegacyDec` (or keep the 1e18 scaling through the multiplication and divide only once at the end with correct rounding), e.g. compute `gasCost = baseFee.MulInt64(int64(gasUsed))` as a `LegacyDec`, then round (ceiling, to match the "user pays at least the accrued cost" property used elsewhere in the codebase, e.g. `Ceil().RoundInt()` in `app/cosmos/min_gas_price.go`) before converting to `big.Int`/`sdkmath.Int`. This avoids collapsing any legitimately fractional (sub-1-`upc`) base fee to zero and keeps gas-fee accounting consistent regardless of the base fee's magnitude.

### Proof of Concept
Conceptual reproduction (exact reachability depends on feemarket parameters, which I could not fully confirm):
1. Set/observe feemarket base fee such that `baseFee.BigInt()` (the `LegacyDec` raw big.Int, scaled by `1e18`) is less than `1e18` — i.e., the real base fee is less than 1 whole `upc` per gas unit.
2. Submit `MsgExecutePayload` causing a UEA-derived EVM call that consumes non-trivial `gasUsed` (e.g. `50000`).
3. In `CalculateGasCost`, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`; `effectiveGasPrice = 0`; `gasCost = 0`.
4. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` — no coins are moved from the recipient account and none are burned via `DeductAndBurnFees`, even though the EVM call consumed real gas resources. [5](#0-4) [6](#0-5)

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
