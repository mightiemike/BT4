### Title
Off-by-One in `apply_delegate_action` Expiry Check Allows Execution at `max_block_height` - (`runtime/runtime/src/actions.rs`)

### Summary

The expiry guard in `apply_delegate_action` uses strict greater-than (`>`) instead of greater-than-or-equal (`>=`). This directly contradicts both the field-level doc comment and the runtime spec, allowing a `DelegateAction` to execute at exactly `block_height == max_block_height` — one block beyond the user's intended authorization window.

### Finding Description

The check at `runtime/runtime/src/actions.rs:435`:

```rust
if apply_state.block_height > delegate_action.max_block_height() {
    result.result = Err(ActionErrorKind::DelegateActionExpired.into());
    return Ok(());
}
```

uses `>` (strictly greater than). This means the action is only rejected when `block_height > max_block_height`, so execution at `block_height == max_block_height` succeeds.

Two authoritative sources in the same repo contradict this:

1. **Field doc comment** in `core/primitives/src/action/delegate.rs:60`:
   > "The maximal height of the block in the blockchain **below which** the given DelegateAction is valid."
   "Below which" means valid only for `block_height < max_block_height`. At `block_height == max_block_height` the action is outside the valid range.

2. **Runtime spec** in `docs/RuntimeSpec/Actions.md:402`:
   > "If the current block is **equal or greater than** `max_block_height`" → `DelegateActionExpired`

The existing test `test_delegate_action` (line 1289–1303) explicitly sets `apply_state.block_height = max_block_height` and asserts `result.result.is_ok()`, confirming the current behavior is intentionally coded this way — but it encodes the wrong invariant. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Impact Explanation

A user who signs a `DelegateAction` with `max_block_height = N` intends the action to be unauthorized at block `N` (per the spec and field comment). A relayer holding that signed action can submit it at block `N` and the runtime will accept and execute it. The user's intended expiry boundary is violated by one block. This constitutes execution of a transaction outside the signer's authorized window — an unauthorized transaction.

The nonce mechanism prevents the same action from being submitted *twice*, but it does not prevent the relayer from submitting it *once* at the boundary block the user believed was already expired.

### Likelihood Explanation

Any relayer (an ordinary, unprivileged network participant) who holds a signed `DelegateAction` can exploit this by timing submission to block `N`. No privileged role, key compromise, or network-level access is required. The entry path is the standard RPC transaction submission flow. [5](#0-4) 

### Recommendation

Change the comparison operator from `>` to `>=`:

```rust
// Before (incorrect):
if apply_state.block_height > delegate_action.max_block_height() {

// After (correct, matches spec):
if apply_state.block_height >= delegate_action.max_block_height() {
```

Update `test_delegate_action` to set `block_height = max_block_height - 1` for the success case, and add a test asserting `DelegateActionExpired` when `block_height == max_block_height`. [1](#0-0) 

### Proof of Concept

The existing test already demonstrates the bug. `test_delegate_action` passes `block_height = max_block_height` and asserts success: [4](#0-3) 

A confirming unit test:

```rust
#[test]
fn test_delegate_action_boundary_off_by_one() {
    // At block_height == max_block_height: spec says EXPIRED, code says OK
    let (action_receipt, signed_delegate_action) = create_delegate_action_receipt();
    let sender_id = signed_delegate_action.delegate_action.sender_id.clone();
    let sender_pub_key = signed_delegate_action.delegate_action.public_key.clone();
    let access_key = AccessKey { nonce: 19000000, permission: AccessKeyPermission::FullAccess };
    let max_height = signed_delegate_action.delegate_action.max_block_height;

    // block_height == max_block_height: should be DelegateActionExpired per spec
    let apply_state = create_apply_state(max_height);
    let mut state_update = setup_account(&sender_id, &sender_pub_key, &access_key);
    let mut result = ActionResult::default();
    apply_delegate_action(
        &mut state_update, &apply_state,
        &VersionedActionReceipt::from(&action_receipt),
        &sender_id, (&signed_delegate_action).into(), &mut result,
    ).unwrap();
    // This assertion FAILS with the current code (action succeeds when it should not):
    assert_eq!(result.result, Err(ActionErrorKind::DelegateActionExpired.into()));

    // block_height == max_block_height + 1: correctly rejected
    let apply_state2 = create_apply_state(max_height + 1);
    let mut state_update2 = setup_account(&sender_id, &sender_pub_key, &access_key);
    let mut result2 = ActionResult::default();
    apply_delegate_action(
        &mut state_update2, &apply_state2,
        &VersionedActionReceipt::from(&action_receipt),
        &sender_id, (&signed_delegate_action).into(), &mut result2,
    ).unwrap();
    assert_eq!(result2.result, Err(ActionErrorKind::DelegateActionExpired.into()));
}
```
