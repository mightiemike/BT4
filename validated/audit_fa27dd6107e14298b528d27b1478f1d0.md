### Title
Uncapped gas limit on `executeUniversalTx` calls to attacker-controlled CEA contracts allows unpaid, unbounded EVM computation on every validating node - (File: `x/uexecutor/keeper/evm.go`)

### Summary
The Blast report's bug class is: calling out to an untrusted, externally-controlled contract lets that contract's owner inflate gas consumption at the caller's expense, because the gas budget for the callback isn't meaningfully bounded/paid-for up front. Push Chain has a structurally identical pattern in its CEA ("contract as recipient") inbound-execution flow: `CallExecuteUniversalTx` calls into an arbitrary, attacker-deployed recipient contract's `executeUniversalTx` method with `gasLimit = nil`, deferring to the EVM fork's "sensible default" instead of a value tied to what the recipient has actually paid for.

### Finding Description
`CallExecuteUniversalTx` in [1](#0-0)  issues a `DerivedEVMCall` to an arbitrary CEA recipient address with `value=big.NewInt(0)` and, critically, `gasLimit=nil`. This differs from the UEA path `CallUEAExecutePayload` at [2](#0-1)  which at least parses and forwards an explicit `gasLimit` taken from `universal_payload.GasLimit`.

Both `ExecuteInboundFundsAndPayload` and `ExecuteInboundGasAndPayload` route `isCEA` inbounds through this nil-gas-limit call, wrapped in a `CacheContext` so that if `DeductGasFeesFromReceipt` subsequently fails (e.g., because the CEA contract holds zero `upc` balance), the EVM state changes are discarded: [3](#0-2) [4](#0-3) .

The regression test explicitly documents this rollback behavior and frames it as the fix for "the recipient cannot consume gas without paying for it": [5](#0-4) . However, that fix only discards *EVM state changes* — it does not, and cannot, undo the actual computational work already performed by the EVM interpreter when honest validators processed the `executeUniversalTx` call. `DeductGasFeesFromReceipt` bills for gas only *after* the call executes and only succeeds if the recipient happens to hold sufficient `upc` balance: [6](#0-5) . Because `CallExecuteUniversalTx`'s `gasLimit` argument is `nil` rather than being capped to some value the attacker has provably funded, a malicious CEA contract can consume up to the fork's default/maximum gas ceiling on every honest full node processing the inbound, and if it deliberately holds zero `upc` balance, the fee-recovery step fails every time, so this computation is never paid for.

### Impact Explanation
An unprivileged attacker can:
1. Deploy a CEA contract on Push Chain whose `executeUniversalTx` implementation performs maximally expensive computation (loops, storage writes, precompile calls) up to whatever the fork's default gas ceiling for a nil `gasLimit` is.
2. Keep that contract's native `upc` balance at zero.
3. Trigger a genuine (even tiny/zero-value) source-chain deposit event pointing at this contract as an `isCEA` recipient. Honest Universal Validators observe and vote this in normally — no malicious validator or relayer is required.
4. Every time quorum finalizes such an inbound, every validating node executes the expensive `executeUniversalTx` call at consensus time, and `DeductGasFeesFromReceipt` fails (insufficient balance) so the fee is never collected — the computation is free to the attacker and costs the network unpaid CPU/gas.

This is a repeatable, unprivileged compute-cost/gas-accounting griefing vector (DoS-adjacent, not network-level) reachable purely through the ordinary inbound-voting → CEA-execution pipeline, matching the "denial of service ... reachable without privileged control" and "corruption of ... gas fee accounting" categories in scope.

### Likelihood Explanation
High reachability: any address can be deployed as a CEA target and any address on a supported external chain can send a qualifying deposit; the flow requires only honest validator observation of a real (attacker's own) on-chain event, no privileged actor. The only friction is whatever the underlying `DerivedEVMCall` fork treats as its "sensible default" gas ceiling when `gasLimit=nil` — but regardless of that concrete value, the code path visibly omits any explicit, funds-anchored cap for this specific call site (in contrast to the UEA path, which at least threads through a caller-declared `GasLimit`).

### Recommendation
Bound `CallExecuteUniversalTx`'s `gasLimit` to a value provably affordable by the CEA recipient before the call executes (e.g., derive it from the recipient's current `upc` balance and current base fee, or require/verify a funded `UniversalPayload.GasLimit`/prepaid gas escrow the same way the UEA path does), rather than passing `nil`. Alternatively, pre-check the recipient's balance against a worst-case gas cost and skip/short-circuit the call if it cannot be paid for, instead of relying solely on post-hoc `CacheContext` rollback of state (which does not reimburse the validator-side compute cost already incurred).

### Proof of Concept
Conceptual PoC (cannot be fully executed without deploying to a live/test node):
1. Deploy `MaliciousCEA.sol` implementing `executeUniversalTx(...)` with an expensive loop/storage-write pattern and no `receive`/fallback that would ever fund itself with `upc`.
2. Submit (or trigger, as the attacker's own source-chain account) a `FUNDS_AND_PAYLOAD` or `GAS_AND_PAYLOAD` inbound with `Recipient = MaliciousCEA address`, `IsCEA = true`, and any minimal `Amount`.
3. Have 2/3+ of honest Universal Validators vote it in exactly as `TestInboundCEASmartContractRecipient`/`TestInboundCEAFundsAndPayload` integration tests do: [7](#0-6) .
4. Observe that `contractReceipt.GasUsed` is high (the EVM call ran to completion) and `DeductGasFeesFromReceipt` returns an "insufficient gas" error, per the pattern already asserted in the existing test at lines 431-441 — proving the call runs (and costs real gas/CPU on all nodes) even though the fee is never collected.
5. Repeat indefinitely at negligible attacker cost.

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
