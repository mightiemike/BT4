### Title
Starknet OS `execute_replace_class` omits declared-class check present in Blockifier, causing OS/Blockifier state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall lets any contract change its own class hash. In `Blockifier` (the sequencer's live transaction-execution engine), this syscall is guarded: it requires the target `class_hash` to already be a declared, compiled class before the state's `class_hash_at` mapping is mutated. The Starknet OS's Cairo implementation of the very same syscall — used to re-execute the block for proof generation — omits this check entirely, as confirmed by an explicit TODO in the code itself. This creates a state mutation path in the OS that Blockifier would reject, causing the OS-computed state to diverge from the state actually committed by the sequencer.

### Finding Description
`Blockifier`'s `replace_class` syscall implementation explicitly requires the class to be declared (and of Cairo1 type) before allowing the mutation: [1](#0-0) 

The deprecated (Cairo0-compatible) Blockifier syscall handler enforces the same declared-class precondition: [2](#0-1) 

However, the Starknet OS's own Cairo re-implementation of `execute_replace_class` (the "current" syscall variant, executed during Starknet OS re-execution/proof generation) performs the `dict_update` on `contract_state_changes` directly, with an explicit acknowledgment that the declared-class check is missing: [3](#0-2) 

The deprecated OS syscall path shows the identical gap — no verification that `class_hash` corresponds to an already-declared class before updating the `StateEntry`: [4](#0-3) 

This is structurally the same bug class as the referenced report: a state-mutating operation reachable from an unprivileged transaction (here, any contract calling `replace_class` with an arbitrary `class_hash`) is permitted by one enforcement path (Blockifier) only after a specific validation (`class_hash` must be declared), but the corresponding/parallel execution path (Starknet OS) applies the mutation unconditionally, skipping that validation.

### Impact Explanation
The Starknet OS re-executes a committed block's transactions to produce the proof attesting the sequencer's state transition is correct. If a transaction calling `replace_class` with an undeclared `class_hash` is included, Blockifier during block building would revert that particular call (an `UndeclaredClassHash`-style error), so the sequencer's authoritative state (and the state root it commits) does not include the class-hash mutation. But when the OS re-executes the same transaction to build the proof, it lacks this check and would apply the class-hash mutation unconditionally, producing a `contract_state_changes` result — and thus a state commitment — that disagrees with what the sequencer actually committed on-chain. This is a state-commitment / honest-node divergence between the sequencer's blockifier execution and its own OS-based proof-generation re-execution, which can manifest as: proof generation failing to match the committed block hash (network unable to finalize/confirm the block), or a contract's class hash being illegitimately overwritten with an undeclared hash in the OS-computed state (an unauthorized account/class state change), both of which fall under "wrong committed root" / "honest-node divergence" impact categories.

### Likelihood Explanation
Any account can trivially craft an `INVOKE` transaction whose Cairo1 contract calls `replace_class(some_undeclared_class_hash)`. No special privileges, timing, or race conditions are required — the divergence is deterministic and reproducible on demand by a single unprivileged transaction sender.

### Recommendation
Add the same declared-class validation to the OS's `execute_replace_class` (both the current syscall in `syscall_impls.cairo` and the deprecated variant in `deprecated_execute_syscalls.cairo`) that Blockifier already performs in `syscall_base.rs::replace_class` and `hint_processor.rs::replace_class` — i.e., read/verify the compiled class for `class_hash` from `contract_class_changes`/declared classes before performing the `dict_update` on `contract_state_changes`, and reject (or otherwise fault) the syscall consistently with Blockifier's behavior when the class is undeclared.

### Proof of Concept
1. Deploy a Cairo1 contract that calls the `replace_class` syscall with a `class_hash` that was never declared on-chain.
2. Submit an `INVOKE` transaction invoking that contract function.
3. Observe that Blockifier (sequencer execution) reverts/rejects the syscall due to the undeclared class check in `syscall_base.rs::replace_class` (crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378).
4. Feed the same block/transaction trace into the Starknet OS re-execution (`execute_replace_class` in `syscall_impls.cairo:881-920`), which lacks the check and unconditionally updates `contract_state_changes`, producing a differing state entry/commitment for that contract address compared to the sequencer's actual committed state.

Note: I was unable to fully trace whether the missing check in the OS is also present in `snos_syscall_executor.rs`/`snos_deprecated_syscall_executor.rs` (the Rust-side OS hint processors, as opposed to the Cairo OS program) due to running out of tool iterations before inspecting those files' `replace_class` implementations; the Cairo-level `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo` evidence and the explicit TODO comment are what substantiate this finding.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
