### Title
Unrecovered panic via malformed Solana-source `DestExecData` in `CalculateMessageMaxGas` causes DoS - ([File: core/capabilities/ccip/ccipsolana/gas_helpers.go])

### Summary
`EstimateProvider.CalculateMessageMaxGas` in `core/capabilities/ccip/ccipsolana/gas_helpers.go` wraps `CalculateMessageMaxGasWithError` and converts any returned error into a `panic(err)`. When the message's source chain is Solana (SVM), the token amount decoding path uses `ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap`, which calls `binary.BigEndian.Uint32(destExecData)` directly without checking that `destExecData` is at least 4 bytes, causing a real Go runtime panic (index out of range) rather than a returned error, for any `DestExecData` payload shorter than 4 bytes.

### Finding Description
The call chain is:
`EstimateProvider.CalculateMessageMaxGas` ( [1](#0-0) ) → `CalculateMessageMaxGasWithError` ( [2](#0-1) ) → `extraDataCodec.DecodeTokenAmountDestExecData` → (via `ExtraDataCodecMap`/`ExtraDataCodecRegistry`, dispatched by `sourceChainSelector`'s family, [3](#0-2) ) → `ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap`: [4](#0-3) 

This implementation performs no length check, unlike the equivalent Aptos implementation which explicitly validates `des.Remaining() != 4` before decoding ( [5](#0-4) ) and the EVM implementation which uses `abiDecodeUint32` that returns a length-insufficient error rather than panicking (as demonstrated in the existing test at [6](#0-5) , which asserts an error string "length insufficient 4 require 32" for a 4-byte-but-still-wrong-sized input in the EVM path).

In Go, `binary.BigEndian.Uint32` on a slice shorter than 4 bytes triggers an unrecovered "index out of range" runtime panic — this is not a `error` value, so the `if err != nil { panic(err) }` pattern at line 34-36 is irrelevant; the panic happens even before `CalculateMessageMaxGasWithError` can return, inside `DecodeDestExecDataToMap` itself. Since `msg.TokenAmounts[i].DestExecData` for a Solana-origin message is populated based on data emitted from the source chain (SVM onRamp), and `EstimateProvider.CalculateMessageMaxGas` is invoked as a non-error-returning interface method (`ccipocr3.EstimateProvider`) during commit/execute plugin gas estimation for OCR report building, a message with a `DestExecData` field of fewer than 4 bytes will crash the calling goroutine with no `recover()` present in this code path.

### Impact Explanation
A panic in `DecodeDestExecDataToMap`/`CalculateMessageMaxGas`, invoked from the CCIP commit/execute OCR plugin's gas-estimation logic, will propagate up the call stack. If not caught by a `recover()` somewhere higher in the OCR runner (which is not present in the reviewed code path), this crashes the goroutine performing OCR report generation, potentially halting commit/execute plugin progress for the affected DON/lane — a denial-of-service of a key node function.

### Likelihood Explanation
The bug is triggerable purely by data-shape (a `DestExecData` byte slice under 4 bytes long) reaching the estimation path for a Solana-sourced token transfer; no privileged access, signing keys, or social engineering is required — only that a CCIP message with a malformed/short `DestExecData` for a token transfer reaches the gas-estimation logic on the destination-chain OCR plugin.

### Recommendation
Add an explicit length check in `ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap` (mirroring the Aptos/EVM implementations) to return an error instead of panicking when `len(destExecData) != 4`, e.g.:
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	if len(destExecData) != 4 {
		return nil, fmt.Errorf("dest exec data invalid length: %d, should be 4 bytes", len(destExecData))
	}
	return map[string]any{
		svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
	}, nil
}
```
Additionally, consider removing the `panic(err)` pattern in `CalculateMessageMaxGas` in favor of returning errors through the `ccipocr3.EstimateProvider` interface, or wrapping calls to it with `recover()` at the OCR plugin boundary as defense-in-depth.

### Proof of Concept
Add a table-driven test in `core/capabilities/ccip/ccipsolana/gas_helpers_test.go` (or `extradatacodec_test.go`) that constructs a `cciptypes.Message` with `Header.SourceChainSelector` set to a Solana chain selector and `TokenAmounts[0].DestExecData` set to byte slices of length 0, 1, 2, and 3. Expected (fixed) behavior: no panic; instead `CalculateMessageMaxGasWithError` should return a descriptive error. Current (vulnerable) behavior: the test will observe a `runtime error: index out of range` panic originating from `binary.BigEndian.Uint32` in `ccipsolana/extradatacodec.go` line 88.

// DecodeDestExecDataToMap reformats bytes into a chain agnostic map[string]interface{} representation for dest exec data
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	des := bcs.NewDeserializer(destExecData)
	if des.Remaining() != 4 {
		return nil, fmt.Errorf("dest exec data invalid length: %d, should be 4 bytes", des.Remaining())
	}

	destGasAmount := des.U32()
	if des.Error() != nil {
		return nil, fmt.Errorf("decode dest gas amount: %w", des.Error())
	}

	return map[string]any{aptosDestExecDataKey: destGasAmount}, nil
}
