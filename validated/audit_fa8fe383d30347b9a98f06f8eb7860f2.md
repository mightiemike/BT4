Based on my investigation, I found a genuine analog: `sanitizeHost`'s regex-only validation lets malformed base64 strings reach the unguarded `atob()` call, which throws regardless of the caller's intent.

### Title
Unhandled `atob()` exception in `sanitizeHost`/`decodeHost` allows request-level DoS of embedded-admin auth handlers via crafted `host` param - (File: packages/apps/shopify-api/lib/utils/shop-validator.ts)

### Summary
`sanitizeHost` is meant to safely validate a user-supplied `host` query parameter and return `null` for invalid input (unless `throwOnInvalid` is explicitly set). However, its character-set-only regex check does not guarantee the string is *decodable* base64, and the subsequent `decodeHost()` call (`atob(host)`) throws a raw, unhandled exception when the string has invalid padding/length, bypassing the intended "return null" contract entirely.

### Finding Description
`sanitizeHost` only validates that the `host` string contains base64-alphabet characters: [1](#0-0) 
This regex (`/^[0-9a-zA-Z+/]+={0,2}$/`) does not enforce that the string length is decodable base64 (e.g. correct length/padding). If the regex passes, the code immediately calls `decodeHost(sanitizedHost)`: [2](#0-1) 
`decodeHost` is a bare `atob(host)` call with no try/catch. `atob` throws a `DOMException`/`SyntaxError` (e.g. "The string to be decoded is not correctly encoded") for many strings that pass the character-set regex but aren't valid base64 (wrong length modulo 4, misplaced padding, etc.), for example a single character like `"a"`.

This exception is not caught anywhere in `sanitizeHost`, so it propagates out of the function even when the caller passed `throwOnInvalid = false` (the default), defeating the function's designed error-handling contract — exactly analogous to `getMultiplier()` reverting from unchecked arithmetic despite being invoked from functions that are supposed to gracefully validate input first.

`sanitizeHost` (with default `throwOnInvalid=false`) is called directly from multiple **unauthenticated** admin-auth entry points without any surrounding try/catch: [3](#0-2) [4](#0-3) 

### Impact Explanation
Any anonymous request to an embedded-admin authentication route (e.g. the app's document-load/authenticate.admin flow) that includes a crafted `host` query parameter (base64-alphabet characters but structurally invalid, e.g. `host=a`) triggers an unhandled exception deep inside a function whose contract is to return `null` for bad input. Since callers such as `validateShopAndHostParams` and `redirectToShopifyOrAppRoot` do not wrap the call in try/catch (they only check the boolean-like return value), this turns a designed "invalid input → graceful redirect/re-render App Bridge" path into an uncaught error, causing that request to fail unexpectedly (500) instead of being handled per the intended validation flow — a functional DoS of the admin authentication handler for that request, reachable pre-authentication by any anonymous actor.

### Likelihood Explanation
High: the `host` param is fully attacker-controlled, unauthenticated, and no code path sanitizes/pre-validates base64 length before invoking `atob`. Triggering it requires a single crafted query string on any embedded-app admin route.

### Recommendation
Wrap the `atob` call in `decodeHost` (or its use in `sanitizeHost`) in a try/catch, returning `null` (or throwing `InvalidHostError` only when `throwOnInvalid` is true) on decode failure, matching the function's documented contract, e.g.:
```ts
export function decodeHost(host: string): string {
  try {
    return atob(host);
  } catch {
    throw new Error('Invalid base64 host value');
  }
}
```
and catch that in `sanitizeHost` to fall through to the existing `sanitizedHost = null` / `throwOnInvalid` handling.

### Proof of Concept
1. Send `GET /?shop=<valid-shop>&host=a&embedded=1` (or any request hitting `validateShopAndHostParams`/`redirectToShopifyOrAppRoot`) to a shopify-app-remix or shopify-app-react-router embedded app.
2. `host=a` passes `base64regex.test('a')` (single alphanumeric char matches `[0-9a-zA-Z+/]+`).
3. `decodeHost('a')` calls `atob('a')`, which throws a `DOMException`/`SyntaxError` because `'a'` is not valid base64 (invalid length).
4. This exception propagates out of `sanitizeHost` uncaught, since no try/catch wraps the `decodeHost` call, producing an unhandled error/500 instead of the intended "invalid host → redirect" behavior — for every request bearing this crafted param.

import {redirect} from '@remix-run/server-runtime';

import type {BasicParams} from '../../../types';

export async function redirectToShopifyOrAppRoot(
  request: Request,
  params: BasicParams,
  responseHeaders?: Headers,
): Promise<never> {
  const {api} = params;
  const url = new URL(request.url);

  const host = api.utils.sanitizeHost(url.searchParams.get('host')!)!;
  const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!)!;

  const redirectUrl = api.config.isEmbeddedApp
    ? await api.auth.getEmbeddedAppUrl({rawRequest: request})
    : `/?shop=${shop}&host=${encodeURIComponent(host)}`;

  throw redirect(redirectUrl, {headers: responseHeaders});
}
