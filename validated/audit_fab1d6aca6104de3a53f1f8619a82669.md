### Title
Unhandled TypeError in `sanitizeHost` instead of `InvalidHostError` when decoded `host` contains forbidden URL host characters - (File: packages/apps/shopify-api/lib/utils/shop-validator.ts)

### Summary
`sanitizeHost` decodes the attacker-supplied `host` query parameter with `atob` and feeds the raw decoded bytes directly into `new URL(\`https://${decodeHost(sanitizedHost)}\`)` without a try/catch. If the decoded bytes contain a forbidden host code point (e.g. `NUL`, space, `\`, `@`, `#`), the WHATWG `URL` constructor throws a `TypeError`, which is not caught anywhere in `sanitizeHost`, `validateShopAndHostParams`, or the wrapping `authenticateAdmin` try/catch (the catch only special-cases `Response` instances and rethrows everything else).

### Finding Description
`validateShopAndHostParams` (packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-shop-and-host-params.ts, when `config.isEmbeddedApp` is true) calls `api.utils.sanitizeHost(url.searchParams.get('host')!)`. [1](#0-0) 

Inside `sanitizeHost`, the raw base64-shaped input is decoded with `decodeHost` (which is a thin wrapper around `atob`), and immediately used as the host portion of a `new URL()` call with no exception handling: [2](#0-1) [3](#0-2) 

The pre-check `base64regex` (`/^[0-9a-zA-Z+/]+={0,2}$/`) only validates the *encoded* string's character set — it does not constrain what bytes `atob` can decode to. Since `atob` treats each base64 group as an arbitrary byte (0–255) and returns them as a binary string, an attacker can base64-encode bytes such as `NUL` (0x00), space, `\`, `@`, or other WHATWG "forbidden host code points." When that decoded string is interpolated into `https://<decoded>` and passed to `new URL()`, the URL parser throws a `TypeError: Invalid URL` per the WHATWG URL spec's forbidden-host-code-point rule.

This exception is not caught inside `sanitizeHost`, so it propagates out of `validateShopAndHostParams`, into `authenticateAdmin`'s try/catch block: [4](#0-3) 

That catch block only handles the case `errorOrResponse instanceof Response` (attaching CORS headers) and otherwise simply rethrows the raw error (line 184), rather than converting it into a clean `InvalidHostError`/redirect like the intended `if (!host) { ... redirectToLoginPath }` path does. The net effect is an unhandled `TypeError` escaping the authentication handler instead of the intended, controlled `InvalidHostError`/redirect-to-login behavior.

### Impact Explanation
A single crafted request causes the auth handler to throw an unhandled `TypeError` instead of returning the expected redirect/`InvalidHostError`. In a Remix/React Router app this manifests as an uncaught loader/action exception (typically surfaced as a 500 response or triggering the framework's default error boundary) for that request. This is a request-scoped denial-of-service/crash of the authentication handler (matches "crash/hang of an auth handler" impact class) rather than a full process crash or cross-tenant compromise — no session forgery, token theft, or bypass of `DESTINATION_ALLOWLIST` enforcement occurs, since the malformed input still fails validation, it just fails via a different code path than intended.

### Likelihood Explanation
No privileged access is required: an anonymous attacker can send `GET /app?shop=valid-shop.myshopify.com&host=<base64-encoded-malicious-bytes>` to any embedded app using `authenticateAdmin` (the `sanitizeHost` call is only reached when `config.isEmbeddedApp` is true). Crafting a base64 string that decodes to a byte sequence containing a forbidden host character (e.g. `NUL`, `\`, or space) is trivial and fully repeatable.

### Recommendation
Wrap the `new URL()` call in `sanitizeHost` in a try/catch, treating any parse failure the same as a failed `hostRegex` match (i.e., setting `sanitizedHost = null` / throwing `InvalidHostError` when `throwOnInvalid` is set) instead of letting the `TypeError` propagate:
```ts
let sanitizedHost = base64regex.test(host) ? host : null;
if (sanitizedHost) {
  try {
    const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);
    // ... existing hostRegex check
  } catch {
    sanitizedHost = null;
  }
}
```

test('sanitizeHost throws unhandled TypeError instead of InvalidHostError for malformed decoded host', () => {
  // base64 encoding of "a\u0000.myshopify.com" (contains NUL byte)
  const maliciousHost = Buffer.from('a\u0000.myshopify.com', 'binary').toString('base64');

  const sanitize = sanitizeHost(config);

  // Expected (desired) behavior: returns null or throws InvalidHostError
  // Actual behavior: throws TypeError: Invalid URL, uncaught by sanitizeHost
  expect(() => sanitize(maliciousHost, true)).not.toThrow(TypeError);
});
