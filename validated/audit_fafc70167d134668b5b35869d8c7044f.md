### Title
Unbounded per-account TRC10 asset map growth causes O(n) bandwidth-accounting cost, enabling DoS-by-spam against `getAccountById`/`getAssetMapV2` consumers - (File: `chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java`)

### Summary
`AccountCapsule` stores a per-account map of every distinct TRC10 asset (token) balance it has ever held, keyed by token ID (`assetV2`) [1](#0-0) . Any user can permissionlessly issue a new TRC10 token via `AssetIssueContract` and permissionlessly send an arbitrary amount of it to any victim address via `TransferAssetContract`, which calls `addAssetAmountV2()` and inserts a brand-new entry into the recipient's `assetV2` map with no cap on the number of distinct tokens a single account may hold [2](#0-1) [3](#0-2) .

### Finding Description
`BandwidthProcessor.updateUsage(AccountCapsule)` iterates over the *entire* `assetV2` map (`accountCapsule.getAssetMapV2()`) plus the free-asset-net-usage map for every call, updating per-asset bandwidth bookkeeping in a `forEach` loop: [4](#0-3) 

This is directly analogous to the Paladin `poolRewards` bug: an attacker-controlled, permissionless mapping (`poolRewards` array of reward tokens ↔ `assetV2` map of TRC10 tokens) is iterated in full by core account-processing logic, with no size limit enforced on how many distinct entries a victim account can accumulate. Just as `poolRewards` grows via anyone calling reward-notify functions, `assetV2` grows via anyone calling `TransferAssetContract` with a freshly issued token — the recipient has no ability to prevent, reject, or clean up unwanted entries.

`updateUsage(AccountCapsule)` is invoked for account queries, e.g. `Wallet.getAccountById()`: [5](#0-4) 

Because `getAssetMapV2()` calls `importAllAsset()` first, which (when asset-optimization is enabled) performs a full DB `prefixQuery` over all asset keys stored for that account address, this operation's cost scales linearly with however many distinct tokens were ever sent to the account: [6](#0-5) [7](#0-6) 

By contrast, other similarly-shaped growth vectors in java-tron are explicitly bounded: witness votes are capped by `MAX_VOTE_NUMBER` (checked in both `VoteWitnessActuator.validate()` and `VoteWitnessProcessor.validate()`) [8](#0-7) [9](#0-8) , and `FrozenSupply` lists in `AssetIssueContract` are capped by `MaxFrozenSupplyNumber` [10](#0-9) . No equivalent cap exists on the number of distinct TRC10 assets an account can be forced to hold.

### Impact Explanation
The impact is bounded compared to the original Paladin finding (which could brick reward claims/transfers/hooks entirely): here the affected functionality is per-account bandwidth/asset bookkeeping and query paths (`Wallet.getAccountById`, asset map exposure through `getAssetMapV2`), not core consensus transaction validation for arbitrary transfers of TRX. The `TransferAssetContract` cost itself is bounded per transaction, but the cumulative effect on the victim's own subsequent `updateUsage()` calls and any API/service that reads `getAssetMapV2()`/`getAllAssets()` grows linearly with attacker-supplied garbage tokens, degrading performance for that specific account's bandwidth accounting and asset-related RPCs (e.g., `GetAccount`, `getaccountnet`) — a resource-exhaustion/griefing vector against a targeted account rather than a network-wide halt.

### Likelihood Explanation
Likelihood is high for the *setup* step: issuing a TRC10 token (`AssetIssueContract`) and sending it to a victim (`TransferAssetContract`) are both fully permissionless operations available to any funded account, and repeating this with many distinct freshly-issued token IDs costs only the standard TRC10 creation fee and bandwidth/fees per transfer — there is no protocol-level rate limit tying the number of distinct assets to anything the recipient controls. However, the resulting DoS is localized (affects the targeted account's own bandwidth-usage recompute and any caller who requests that account's full asset map), not a chain-wide halt, so exploitation impact is comparatively modest and the overall likelihood of it being a *practically damaging* attack is moderate.

### Recommendation
Introduce a maximum number of distinct TRC10 asset entries (`assetV2` keys) an account may hold, enforced at `TransferAssetActuator.validate()`/`execute()` time (rejecting the transfer, or requiring the recipient to have room, once the cap is reached) — mirroring the existing `MAX_VOTE_NUMBER` and `MaxFrozenSupplyNumber` patterns already used elsewhere in the codebase. Alternatively/additionally, ensure `BandwidthProcessor.updateUsage()` and `AccountAssetStore.getAllAssets()` do not need to scan the full per-account asset set on every invocation (e.g., lazy/on-demand computation only for assets actually referenced by the current transaction) to remove the unbounded-loop cost even if the map itself cannot be size-capped.

### Proof of Concept
1. Attacker account A issues N distinct TRC10 tokens via `AssetIssueContract` (permissionless, standard token-creation fee each).
2. Attacker sends 1 unit of each of the N tokens to victim address V via `TransferAssetContract`, which calls `AccountCapsule.addAssetAmountV2()` for each new token id, adding N entries to V's `assetV2` map [3](#0-2) .
3. Any subsequent call to `Wallet.getAccountById(V)` (or any code path calling `BandwidthProcessor.updateUsage(V)` / `getAssetMapV2()`) now iterates all N entries and, if asset-optimization is enabled, performs a full-prefix DB scan over V's assets [5](#0-4) [6](#0-5) , with cost scaling linearly (unbounded) in N, degrading queries/bandwidth-usage recomputation for the targeted account.

  public boolean addAssetAmountV2(byte[] key, long amount,
      DynamicPropertiesStore dynamicPropertiesStore, AssetIssueStore assetIssueStore) {
    importAsset(key);
    boolean disableJavaLangMath = dynamicPropertiesStore.disableJavaLangMath();
    //key is token name
    if (dynamicPropertiesStore.getAllowSameTokenName() == 0) {
      Map<String, Long> assetMap = this.account.getAssetMap();
      AssetIssueCapsule assetIssueCapsule = assetIssueStore.get(key);
      String tokenID = assetIssueCapsule.getId();
      String nameKey = ByteArray.toStr(key);
      Long currentAmount = assetMap.get(nameKey);
      if (currentAmount == null) {
        currentAmount = 0L;
      }
      this.account = this.account.toBuilder()
          .putAsset(nameKey, addExact(currentAmount, amount, disableJavaLangMath))
          .putAssetV2(tokenID, addExact(currentAmount, amount, disableJavaLangMath))
          .build();
    }
    //key is token id
    if (dynamicPropertiesStore.getAllowSameTokenName() == 1) {
      String tokenIDStr = ByteArray.toStr(key);
      Map<String, Long> assetMapV2 = this.account.getAssetV2Map();
      Long currentAmount = assetMapV2.get(tokenIDStr);
      if (currentAmount == null) {
        currentAmount = 0L;
      }
      this.account = this.account.toBuilder()
          .putAssetV2(tokenIDStr, addExact(currentAmount, amount, disableJavaLangMath))
          .build();
    }
    return true;
  }

  public void updateUsage(AccountCapsule accountCapsule) {
    long now = chainBaseManager.getHeadSlot();
    long oldNetUsage = accountCapsule.getNetUsage();
    long latestConsumeTime = accountCapsule.getLatestConsumeTime();
    accountCapsule.setNetUsage(increase(accountCapsule, BANDWIDTH,
            oldNetUsage, 0, latestConsumeTime, now));
    long oldFreeNetUsage = accountCapsule.getFreeNetUsage();
    long latestConsumeFreeTime = accountCapsule.getLatestConsumeFreeTime();
    accountCapsule.setFreeNetUsage(increase(oldFreeNetUsage, 0, latestConsumeFreeTime, now));

    if (chainBaseManager.getDynamicPropertiesStore().getAllowSameTokenName() == 0) {
      Map<String, Long> assetMap = accountCapsule.getAssetMap();
      assetMap.forEach((assetName, balance) -> {
        long oldFreeAssetNetUsage = accountCapsule.getFreeAssetNetUsage(assetName);
        long latestAssetOperationTime = accountCapsule.getLatestAssetOperationTime(assetName);
        accountCapsule.putFreeAssetNetUsage(assetName,
            increase(oldFreeAssetNetUsage, 0, latestAssetOperationTime, now));
      });
    }
    Map<String, Long> assetMapV2 = accountCapsule.getAssetMapV2();
    Map<String, Long> map = new HashMap<>(assetMapV2);
    accountCapsule.getAllFreeAssetNetUsageV2().forEach((k, v) -> {
      if (!map.containsKey(k)) {
        map.put(k, 0L);
      }
    });
    map.forEach((assetName, balance) -> {
      long oldFreeAssetNetUsage = accountCapsule.getFreeAssetNetUsageV2(assetName);
      long latestAssetOperationTime = accountCapsule.getLatestAssetOperationTimeV2(assetName);
      accountCapsule.putFreeAssetNetUsageV2(assetName,
          increase(oldFreeAssetNetUsage, 0, latestAssetOperationTime, now));
    });
  }

  public Map<String, Long> getAllAssets(Protocol.Account account) {
    Map<String, Long> assets = new HashMap<>();
    if (account.getAssetOptimized()) {
      Map<WrappedByteArray, byte[]> map = prefixQuery(account.getAddress().toByteArray());
      map.forEach((k, v) -> {
        byte[] assetID = ByteArray.subArray(k.getBytes(),
                account.getAddress().toByteArray().length, k.getBytes().length);
        assets.put(ByteArray.toStr(assetID), Longs.fromByteArray(v));
      });
    }
    account.getAssetV2Map().forEach((k, v) -> assets.put(k, v));
    return assets;
  }
