### Title
Unprivileged Declare transactions using the hardcoded `'BOOTSTRAP'` sender address bypass signature validation, fee charging and nonce accounting - (File: `crates/starknet_api/src/executable_transaction.rs`)

### Summary
Both the Rust `blockifier`/`starknet_api` execution path and the Cairo Starknet-OS program treat any `DeclareTransaction::V3` whose `sender_address` equals the fixed constant `bootstrap_address()` (the felt encoding of the ASCII string `'BOOTSTRAP'`), with `nonce == 0` and zero effective fee, as a privileged "genesis bootstrap" declare: it skips `__validate_declare__`, skips fee charging, and skips nonce incrementation, writing the class hash directly into `contract_class_changes`. Because `bootstrap_address()` is a public, hardcoded constant rather than a value gated by any L1/administrative authorization check inside the execution/OS layer itself, any ordinary declare transaction sent by an unprivileged party can set this exact `sender_address` and reach the same code path, at any block height — not only at genesis.

### Finding Description
The "control" condition that decides whether a Declare transaction gets the privileged bootstrap treatment is a magic, publicly-known constant compared purely by value, with no accompanying authorization/context check (e.g., "block number == 0" or "declare sent via a dedicated L1/admin channel"): [1](#0-0) 

This is checked in `AccountTransaction::execute_raw`: [2](#0-1) 

The identical bypass condition (`sender_address == 'BOOTSTRAP' and tx_info.nonce == 0 and tx_info.version == 3`) is re-implemented in the Starknet-OS Cairo program, which also skips `check_and_increment_nonce` and the `__validate_declare__` call when it matches: [3](#0-2) 

This mirrors the Camel-Lucene bug class exactly: a control value (here, a magic sender address instead of a magic HTTP header name) that is meant to represent a privileged/internal-only condition ("this is the sequencer bootstrapping a new system") is in fact just a fixed, guessable/known value with no additional authorization boundary preventing an ordinary external transaction sender from supplying it. Just as `QUERY`/`RETURN_LUCENE_DOCS` were not properly namespaced and thus passed straight through the HTTP header filter, `'BOOTSTRAP'` is not namespaced/gated behind any capability check and can be supplied by anyone crafting a `DeclareTransaction::V3`.

The gateway does have a separate, unrelated authorization gate for declares: [4](#0-3) 

Whether the deployed `is_authorized_declarer` allow-list is configured to exclude the bootstrap address after genesis is a deployment/config concern I could not verify from the indexed code — if that allow-list is permissive (or if any path bypasses the gateway, e.g. re-execution/tests), the bypass in `is_bootstrap_declare` / `transaction_impls.cairo` is directly reachable from an ordinary submitted transaction.

### Impact Explanation
An unprivileged transaction sender who can get a Declare V3 transaction with `sender_address = bootstrap_address()`, `nonce = 0`, and no fee accepted into the mempool/executed can:
- Declare any not-yet-declared class hash for free, without running `__validate_declare__` (no signature check) and without paying fees or bumping the (frozen) nonce, which can be repeated indefinitely because the nonce never advances past 0.
- Because declaration is enforced "once per class hash" (`prev_value == 0` in `dict_update`), an attacker can pre-emptively declare/squat any class hash a victim intends to declare later, permanently blocking the victim's legitimate declare of that class (an unauthorized state-write griefing / denial-of-declare against a specific class hash), at zero cost to the attacker.

### Likelihood Explanation
Reachability depends entirely on whether `bootstrap_address()` is excluded from `is_authorized_declarer` (or an equivalent gate) in the production gateway configuration and in all paths that admit transactions into the mempool/execution pipeline (including any re-execution/OS paths that don't go through the RPC gateway's declare-permission check). If that exclusion is missing or incomplete, exploitation requires nothing more than constructing a normal Declare V3 RPC transaction with the known constant sender address — no special access or timing is needed.

### Recommendation
Do not rely solely on a hardcoded sender-address value to gate privileged bootstrap behavior. Restrict the bootstrap declare bypass to an explicit, out-of-band trust boundary (e.g., only permit it for a fixed number of transactions at block 0 / via a dedicated genesis-only code path that ordinary transaction ingestion cannot reach), and ensure `is_authorized_declarer`/gateway configuration unconditionally rejects `bootstrap_address()` as a sender for any block beyond genesis in every deployment. Add symmetric checks in the Starknet-OS Cairo implementation and blockifier so the bypass cannot be reached after the chain has left its bootstrap phase.

### Proof of Concept
1. Craft a `DeclareTransaction::V3` RPC transaction with `sender_address = 0x424f4f545354524150` (`'BOOTSTRAP'`), `nonce = 0`, `signature = []`, and `resource_bounds` set so the effective fee is zero (as done in the test helper `generate_bootstrap_declare`): [5](#0-4) 
2. Set `class_hash`/`compiled_class_hash` to a not-yet-declared, correctly Sierra-derived class hash/CASM pair.
3. Submit the transaction to the gateway. If it is not filtered by `is_authorized_declarer`, `AccountTransaction::execute_raw` will detect `is_bootstrap_declare` and directly declare the class hash, skipping `__validate_declare__`, fee charge, and nonce increment, per: [6](#0-5) 
4. Repeat with new class hashes (nonce remains 0) to declare classes indefinitely for free, or target a class hash a victim is expected to declare to pre-empt/squat it.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }
