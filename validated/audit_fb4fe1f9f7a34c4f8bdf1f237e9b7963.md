Found the critical piece: `collect_execution_results_and_stream_txs` in `crates/apollo_batcher/src/block_builder.rs:708-716` treats **any** `TransactionExecutorResult` error uniformly as a "transaction rejection" — including `TransactionExecutorError::StateError` (an internal/unrecoverable state-access failure, e.g. `StateError::OutOfRangeContractAddress`, storage read failures, etc.), exactly the same way it treats an ordinary execution/validation failure. This is confirmed by the test `transaction_failed_test_expectations` in `crates/apollo_batcher/src/block_builder_test.rs:396-472`, which explicitly feeds `TransactionExecutorError::StateError(StateError::OutOfRangeContractAddress)` into the "transaction failed → excluded from block" path.
