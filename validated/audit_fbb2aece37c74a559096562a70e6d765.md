## Analysis

The Balancer bug pattern here is: a "supermajority/threshold" quantity is computed with a formula that silently drops a necessary rounding/adjustment term, so the coded check ends up weaker than the documented guarantee — letting a sub-threshold minority satisfy a check meant to require a true supermajority. Stacks-core has an exact structural analog in the two independent implementations of the "70% weight" threshold used by the signer set.

### Title
Signer global-state agreement threshold uses floor instead of ceiling, letting sub-70%-weight minorities force signer consensus decisions - (File: libsigner/src/v0/signer_state.rs)

### Summary
`NakamotoBlockHeader::compute_voting_weight_threshold` (the canonical, consensus-critical definition of "70% of signer weight") rounds **up** (`ceil`), guaranteeing that fewer than 70% of weight can never satisfy the check. `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` in `libsigner`, which drive the signer set's soft-consensus decisions (global burn view, global miner view/capitulation, protocol-version adoption, and transaction-replay-set selection), instead compute the threshold with plain integer division (floor), so whenever `total_weight * 7` is not a multiple of 10 the effective bar is strictly below 70%.

### Finding Description
Consensus-critical threshold (rounds up, strict ≥70%): [1](#0-0) 

Signer-set "soft consensus" threshold (rounds down): [2](#0-1) 

`reached_agreement` is the sole gate used by `determine_global_state`, `determine_global_burn_view`, `determine_latest_supported_signer_protocol_version`, and `find_majority_prefix_replay_set` to decide the signer set's agreed-upon burn view, current miner, transaction-replay set, and even the signer protocol version: [3](#0-2) [4](#0-3) 

For any `total_weight` where `total_weight * 7 % 10 != 0`, `reached_agreement` returns `true` at `floor(total_weight*7/10)`, which is strictly less than the `ceil(total_weight*7/10)` figure that the same named constant (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7`, i.e. "70%") produces when used for actual block-signature verification: [5](#0-4) 

Example: with `total_weight = 11`, the block-header threshold requires `ceil(7.7) = 8` (72.7%), while `reached_agreement` accepts `floor(7.7) = 7` (63.6%). A signer coalition holding only ~64% of total weight — well short of the documented 70% supermajority — can force `determine_global_state`/`determine_global_burn_view` to report agreement, causing honest signers to capitulate their local miner viewpoint (`capitulate_viewpoint`) or their transaction-replay set to the minority's view: [6](#0-5) 

This exactly mirrors the Balancer report's root cause: a threshold/ratio calculation that omits the correction term (there: dividing by `rate`; here: rounding up) that a second, more-careful implementation of the *same* nominal formula (`compute_voting_weight_threshold`) does apply, producing two inconsistent notions of "70%" within the same codebase.

### Impact Explanation
This is a minority-triggerable divergence: a coalition below the true 70% supermajority (but above the flooring artifact) can force the `GlobalStateEvaluator` to treat its preferred miner/tenure/burn-view/replay-set as "globally agreed," causing honest signers to capitulate viewpoint (via `capitulate_viewpoint`/`capitulate_miner_view`) to a minority-backed miner or transaction-replay-set. Because capitulation drives which tenure/miner signers will endorse and pre-commit to, this can produce tip disagreement among signers and unnecessary tenure/miner churn, without requiring an actual 70% supermajority as the protocol intends — a High-severity, minority-triggerable signer-consensus divergence bounded to temporary tip/tenure disagreement.

### Likelihood Explanation
No privileged access is required — only ordinary stacked/registered signer weight is needed, and the exploitable gap exists whenever `total_weight * 7` is not a multiple of 10, which is the common case for realistic weight distributions (weights are derived from stacked STX amounts, not multiples of 10/7). No majority is required, only a coalition landing between `floor(total_weight*0.7)` and `ceil(total_weight*0.7)`.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` (and `reached_disagreement`) use the same ceiling-based computation as `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g. reuse that function directly, so all "70%"/"30%" checks in the codebase are computed identically and cannot silently disagree.

### Proof of Concept
1. Construct a signer set whose registered weights sum to `total_weight = 11` (e.g., weights `[2,2,2,2,1,1,1]`).
2. Have signers controlling weight `7` (63.6%) send a `StateMachineUpdateMessage` agreeing on a specific `(burn_block, burn_block_height)` / miner view / replay set.
3. Call `GlobalStateEvaluator::determine_global_burn_view` / `determine_global_state`: `reached_agreement(7)` evaluates `7 >= 11*7/10 = 7` → `true`, so agreement is reported at 63.6% weight.
4. Compare with `NakamotoBlockHeader::compute_voting_weight_threshold(11)` (used for actual block signature verification), which returns `8`, i.e. 72.7% — confirming the same nominal "70%" constant yields two different, inconsistent effective thresholds within the codebase. [7](#0-6)

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Updates the local state machine's viewpoint as necessary based on the global state
    #[allow(clippy::too_many_arguments)]
    pub fn capitulate_viewpoint(
        &mut self,
        stacks_client: &StacksClient,
        signerdb: &mut SignerDb,
        eval: &mut GlobalStateEvaluator,
        local_supported_signer_protocol_version: u64,
        sortition_state: &mut Option<SortitionsView>,
        capitulate_miner_view_timeout: Duration,
        tenure_last_block_proposal_timeout: Duration,
        last_capitulate_miner_view: &mut SystemTime,
    ) {
        // We should do this without waiting for capitulation checks, as protocol version updates are orthogonal to capitulation
        self.update_protocol_version(stacks_client, eval, local_supported_signer_protocol_version);

        if !self.is_capitulation_check_ready(
            signerdb,
            local_supported_signer_protocol_version,
            capitulate_miner_view_timeout,
            last_capitulate_miner_view,
        ) {
            return;
        }
        *last_capitulate_miner_view = SystemTime::now();
        // First, update our parent tenure last block if needed. We may have timed out our view of it.
        // This is a bit of an expensive call (due to call for node tip) so we don't want to do it if
        // the node is advancing with our participation.
        self.update_parent_tenure_last_block(
            stacks_client,
            signerdb,
            local_supported_signer_protocol_version,
            tenure_last_block_proposal_timeout,
        );
        let Ok(local_update) =
            self.try_into_update_message_with_version(local_supported_signer_protocol_version)
        else {
            return;
        };

        // Is there a miner view to which we should capitulate?
        let Some(new_miner) = self.capitulate_miner_view(
            stacks_client,
            eval,
            signerdb,
            &local_update,
            tenure_last_block_proposal_timeout,
        ) else {
            return;
        };

        let (burn_block, burn_block_height) = local_update.content.burn_block_view();
        let current_miner = local_update.content.current_miner();
        let tx_replay_set = local_update.content.tx_replay_set();

        if current_miner != &new_miner {
            info!("Signer State: Capitulating local state machine's current miner viewpoint";
                "current_miner" => ?current_miner,
                "new_miner" => ?new_miner,
                "burn_block" => %burn_block,
                "burn_block_height" => burn_block_height,
                "tx_replay_set" => ?tx_replay_set,
            );
            crate::monitoring::actions::increment_signer_agreement_state_change_reason(
                crate::monitoring::SignerAgreementStateChangeReason::MinerViewUpdate,
            );
            Self::monitor_miner_parent_tenure_update(current_miner, &new_miner);

            *self = Self::Initialized(SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: new_miner.clone().into(),
                active_signer_protocol_version: local_update.active_signer_protocol_version,
                tx_replay_set,
            });
