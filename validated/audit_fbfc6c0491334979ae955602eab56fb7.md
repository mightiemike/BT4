Confirmed: `revertRecipient` (Word 3 of the `sendFunds` gateway event) is fully attacker-controlled — it is emitted by the depositor's own external-chain transaction and decoded verbatim into `payload.RevertFundRecipient` [1](#0-0) , which becomes `Inbound.RevertInstructions.FundRecipient` and later `OutboundTx.RevertInstructions.FundRecipient`, the exact field used as the refund/revert recipient in `applyGasRefund` and `handleFailedOutbound` [2](#0-1) [3](#0-2) .

### Title
Attacker-controlled refund recipient permanently strands excess gas-fee funds with no residual-fund recovery path - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
`applyGasRefund` computes the excess gas fee (`gasFee - gasFeeUsed`) after an outbound is observed and attempts to return it to `outbound.Sender` or, if set, `outbound.RevertInstructions.FundRecipient` via `CallUniversalCoreRefundUnusedGas`, first with a swap-back-to-PC leg and then via a no-swap PRC20 deposit fallback [4](#0-3) . Both delivery legs ultimately transfer value to the same attacker-chosen `recipientAddr`. If that address is a contract crafted to revert on receiving the refund (e.g., no PRC20 receive hook / an always-reverting fallback), both the swap and no-swap `CallUniversalCoreRefundUnusedGas` invocations fail. The code simply records `PcRefundExecution.Status = "FAILED"` and `RefundSwapError`, and returns — there is no retry, no rescue path, and no mechanism analogous to a "rebalance" that reclaims and redistributes the un-deliverable excess gas token.

### Finding Description
`RevertInstructions.FundRecipient` originates from the `revertRecipient` field of the depositor's own `sendFunds` gateway event on the source chain, parsed verbatim with no validation that it is a normal EOA or a contract capable of accepting the refunded token [1](#0-0) . This value flows unchanged into `OutboundTx.RevertInstructions` and is used as the refund/revert target in both `handleFailedOutbound` (bridged-funds revert) and `applyGasRefund` (excess gas refund) [5](#0-4) [4](#0-3) .

`applyGasRefund` tries two delivery mechanisms in sequence — swap-based refund and PRC20 no-swap refund — both of which ultimately push value to the same recipient address the attacker controls. When both calls to `CallUniversalCoreRefundUnusedGas` fail (deterministically, because the recipient contract always reverts on receipt), the function sets `refundPcTx.Status = "FAILED"`, stores `outbound.RefundSwapError`, and returns with no further handling [6](#0-5) . Unlike `handleFailedOutbound`'s bridged-funds path, which calls `AbortOutbound` for manual intervention when the re-mint fails [7](#0-6) , the gas-refund path has no equivalent abort/rescue/retry flow. The `outbound.OutboundStatus` still transitions to `OBSERVED`/`REVERTED` via `UpdateOutbound`, and the excess gas amount is never reattempted, re-routed, or made claimable by any other party — it is permanently unrecoverable, mirroring the SafEth.sol pattern where residual ETH has no mechanism to be harnessed once the primary distribution path fails.

### Impact Explanation
This causes permanent, protocol-side loss of the excess gas-fee funds (a corrupted/unreachable `refundAmount` value) that were reserved for legitimate refund to the outbound's sender. The amount is neither returned to the user nor swept back into protocol funds; it is simply stranded in whatever escrow/holding mechanism `UniversalCore.refundUnusedGas` uses internally, unreachable by any subsequent unprivileged or admin action found in scoped code. This matches the in-scope impact category of "permanent freezing... of user or protocol-controlled funds."

### Likelihood Explanation
The trigger is fully unprivileged and requires only submitting an ordinary bridging transaction with a `revertRecipient` set to a contract deliberately built to reject the refund token (a trivial, always-revert `receive`/`transfer` hook). No validator or admin misbehavior is needed — honest validators voting on the true `gasFeeUsed` value is sufficient. The only variable is the magnitude of the stranded amount, which is attacker-influenced only in that it corresponds to actual over-provisioned gas fee for that outbound (bounded by protocol gas-fee estimation, but nonzero and predictable via `GetOutboundTxGasAndFees`).

### Recommendation
Add a fallback path analogous to `AbortOutbound` in `handleFailedOutbound`: when both the swap and no-swap `CallUniversalCoreRefundUnusedGas` calls fail, do not merely record `FAILED` and drop the funds — instead (a) retry against a safe fallback recipient (e.g., the module/treasury account) when the primary recipient is provably unreceivable, or (b) mark the outbound/refund state as requiring manual/governance sweep, with an explicit on-chain record and message handler (`MsgRescueRefund` or similar) that lets funds be redirected once diagnosed, rather than silently discarding `refundAmount`. Additionally, consider validating or capping refund recipients to addresses known to accept the relevant asset, or performing the transfer in a way that cannot block the outbound's terminal accounting.

### Proof of Concept
1. Attacker submits a normal cross-chain `sendFunds`/gateway deposit on the external chain, setting `revertRecipient` to a contract address `M` whose PRC20 receive logic (or native-token receive fallback) unconditionally reverts.
2. This value is parsed into `payload.RevertFundRecipient` and stored as `Inbound.RevertInstructions.FundRecipient` / propagated to the resulting `OutboundTx.RevertInstructions.FundRecipient` [1](#0-0) .
3. Honest validators observe and vote the real outbound with `gasFeeUsed < gasFee`, producing a positive `refundAmount` in `applyGasRefund` [8](#0-7) .
4. `CallUniversalCoreRefundUnusedGas` with `withSwap=true` reverts because `M` rejects the incoming asset; the swap fallback reason is recorded [9](#0-8) .
5. The no-swap fallback call to `CallUniversalCoreRefundUnusedGas` with `withSwap=false` also reverts for the same reason [10](#0-9) .
6. `refundPcTx.Status = "FAILED"` is stored on `outbound.PcRefundExecution`, `RefundSwapError` is set, and the function returns; `UpdateOutbound` commits the outbound in its terminal state with no further recovery of `refundAmount` [11](#0-10) . The excess gas-fee value is now permanently unreachable.

Note: I was unable to directly inspect the `UniversalCore.refundUnusedGas` Solidity implementation (precompile/contract source) in the indexed codebase to confirm exactly how/where the reverted-transfer funds are held internally; this may be excluded from the index. Starting a full Devin session would allow inspection of that contract to pin down the exact custody location of the stranded funds and confirm no built-in sweep exists there either.

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
