### Title
Unbounded Gzip Decompression (Decompression Bomb) DoS in `decompress_program` - (File: `crates/apollo_rpc/src/v0_8/api/mod.rs`)

### Summary
The Starknet RPC node exposes a `declareTransaction`/simulation path where an unprivileged caller submits a `BroadcastedDeclareV1Transaction` containing a Cairo-0 `DeprecatedContractClass` with a base64+gzip `program` field. The conversion function `user_deprecated_contract_class_to_sn_api` calls `decompress_program`, which decompresses the gzip payload with **no size limit and no time limit**, unlike the equivalent, hardened path in `starknet_api::compression_utils::decode_and_decompress_with_size_limit` used elsewhere in the gateway.

### Finding Description
`decompress_program` in [1](#0-0)  reads the entire decompressed gzip stream into memory via `decoder.read_to_end(&mut decompressed, ...)` with an explicit `// TODO(dan): add time and size limits.` comment acknowledging the gap. This is reached from `user_deprecated_contract_class_to_sn_api`, which is called when converting a `BroadcastedDeclareTransaction::V1` (submitted through RPC, e.g. `simulateTransactions`/`estimateFee`/`addDeclareTransaction`-style flows) into an `ExecutableTransactionInput`: [2](#0-1) .

This contrasts with the properly bounded implementation used in the deprecated-gateway HTTP path, `decode_and_decompress_with_size_limit`, which caps decompressed output using a `.take(max_size + 1)` reader and returns `CompressionError::SizeLimitExceeded` if exceeded: [3](#0-2) . `decompress_program` bypasses this protection entirely, allowing an attacker to submit a small, highly-compressed gzip payload (a "gzip bomb") that expands to an arbitrarily large decompressed size (potentially gigabytes) in memory before any signature, balance, or fee validation of the transaction occurs.

### Impact Explanation
An attacker can submit a specially-crafted, small `BroadcastedDeclareV1Transaction` whose `contract_class.program` decompresses to many gigabytes, causing memory exhaustion / OOM in the RPC-serving node process. Because contract class decompression happens as part of RPC-triggered execution/simulation flows before validation gating, repeated calls can degrade or crash the affected node process, matching the "network unable to confirm new transactions" impact category if this occurs on a sequencer/full node providing RPC services used for transaction submission or fee estimation.

### Likelihood Explanation
Reaching this code path requires only a single crafted RPC call containing a `DECLARE` v1 transaction with an oversized/compressed `program`; no privileged access, no valid signature, and no special node role is required to trigger the decompression before further transaction checks. The only constraints are that the RPC method be reachable (RPC endpoints such as fee estimation/simulation accept `BroadcastedTransaction` inputs per [4](#0-3) ).

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` call in `decompress_program` with a size-limited decompression (e.g., using `.take(max_size)` as done in `decompress_with_size_limit`), and add a hard cap consistent with `DEFAULT_MAX_SIERRA_PROGRAM_SIZE`/`max_sierra_program_size` used elsewhere for gzip-compressed class payloads. Consider also enforcing a decompression time budget.

### Proof of Concept
1. Construct a `DeprecatedContractClass` whose `program` field is a base64-encoded gzip stream that decompresses to several GB (a classic "gzip bomb"; gzip supports extremely high compression ratios for repetitive data).
2. Submit it as `contract_class` inside a `BroadcastedDeclareV1Transaction` to an RPC method that triggers `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` (e.g., a simulate/estimate-fee RPC call), reaching `user_deprecated_contract_class_to_sn_add_api` → `decompress_program`.
3. Observe the node's memory usage grow unbounded as `decoder.read_to_end` attempts to fully materialize the decompressed program before any error/size check occurs, potentially causing an OOM crash of the node process. [1](#0-0) [5](#0-4)

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
