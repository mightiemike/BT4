### Title
OAuth CSRF-state cookie expires after only 60 seconds, causing legitimate authorization flows to fail (DoS of the OAuth callback handler) - ([File: packages/apps/shopify-api/lib/auth/oauth/oauth.ts])

### Summary
The `begin` function of the OAuth flow sets the `STATE_COOKIE_NAME` (`shopify_app_state`) cookie — which carries the CSRF-protection nonce used to validate the subsequent `/auth/callback` request — with a hard-coded expiry of only 60 seconds. [1](#0-0)  If the merchant does not complete the full Shopify OAuth consent screen (login, scope review, 2FA, etc.) within that single minute, the cookie will already be expired by the time the browser is redirected back to the app's callback URL.

### Finding Description
`begin()` generates a nonce and stores it in a short-lived, signed cookie scoped to the callback path:
```
await cookies.setAndSign(STATE_COOKIE_NAME, state, {
  expires: new Date(Date.now() + 60000),
  sameSite: 'lax',
  secure: true,
  path: callbackPath,
});
``` [1](#0-0) 

When `callback()` runs later, it reads this cookie via `cookies.getAndVerify(STATE_COOKIE_NAME)`. If the cookie is missing (e.g., because the browser already expired/discarded it), the flow throws immediately:
```
const stateFromCookie = await cookies.getAndVerify(STATE_COOKIE_NAME);
cookies.deleteCookie(STATE_COOKIE_NAME);
if (!stateFromCookie) {
  throw new ShopifyErrors.CookieNotFound(...);
}
``` [2](#0-1) 

This is functionally the same bug class as the report cited: a fixed timelock/window (`60 seconds` here vs. `adminSettleDebtLockPeriod` there) is assumed to be always sufficient for a real-world, multi-step external process (Shopify's own login/consent/2FA UI, analogous to Lido's 1–5 day withdrawal queue) that the app does not control and that can legitimately exceed the assumed window. A merchant who needs to log into Shopify, pass 2FA, or simply reads the requested scopes before approving can easily take longer than 60 seconds, especially on slower networks/devices.

### Impact Explanation
When the window expires before the callback is hit, `callback()` throws `ShopifyErrors.CookieNotFound`, forcing the merchant to restart the entire installation/authorization flow. This is a denial-of-service of the OAuth callback handler for any single, unprivileged merchant attempting a normal install/re-auth — reachable without any special access, purely by the natural timing of the external Shopify consent process. [3](#0-2) 

### Likelihood Explanation
Likelihood is not negligible: any merchant who pauses on the Shopify consent screen (reviewing scopes, switching staff accounts, completing 2FA, or simply having a slow connection) for more than 60 seconds will trigger the failure. Unlike the original Lido report which requires a rare admin action plus a withdrawal-queue delay, this condition can be triggered unintentionally by ordinary merchant behavior during every single OAuth attempt.

### Recommendation
Increase the `STATE_COOKIE_NAME` cookie expiry to a more realistic window (e.g., 5–10 minutes) to account for the time a merchant may spend on Shopify's login/consent/2FA screens, mirroring the report's recommendation to widen `adminSettleDebtLockPeriod` to account for real-world external process durations beyond the original conservative estimate.

### Proof of Concept
1. Call `shopify.auth.begin(...)` for a shop; observe the `Set-Cookie: shopify_app_state=...; expires=<now+60s>` header. [1](#0-0) 
2. Simulate a merchant taking longer than 60 seconds on Shopify's consent screen (e.g., delay the callback request beyond 60s, or manually expire/delete the cookie as the browser would).
3. Send the callback request with a valid `hmac`/`state`/`code` but without the (now-expired) `shopify_app_state` cookie.
4. Observe `shopify.auth.callback(...)` throws `ShopifyErrors.CookieNotFound`, aborting the OAuth flow and requiring the merchant to restart installation. [2](#0-1)

export function callback(config: ConfigInterface): OAuthCallback {
  return async function callback<T = AdapterHeaders>({
    expiring,
    ...adapterArgs
  }: CallbackParams): Promise<CallbackResponse<T>> {
    throwIfCustomStoreApp(
      config.isCustomStoreApp,
      'Cannot perform OAuth for private apps',
    );

    const log = logger(config);

    const request = await abstractConvertRequest(adapterArgs);

    const query = new URL(
      request.url,
      `${config.hostScheme}://${config.hostName}`,
    ).searchParams;
    const shop = query.get('shop')!;

    const response = {} as NormalizedResponse;
    let userAgent = request.headers['User-Agent'];
    if (Array.isArray(userAgent)) {
      userAgent = userAgent[0];
    }
    if (isbot(userAgent)) {
      logForBot({request, log, func: 'callback'});
      throw new ShopifyErrors.BotActivityDetected(
        'Invalid OAuth callback initiated by bot',
      );
    }

    log.info('Completing OAuth', {shop});

    const cookies = new Cookies(request, response, {
      keys: [config.apiSecretKey],
      secure: true,
    });

    const stateFromCookie = await cookies.getAndVerify(STATE_COOKIE_NAME);
    cookies.deleteCookie(STATE_COOKIE_NAME);
    if (!stateFromCookie) {
      log.error('Could not find OAuth cookie', {shop});

      throw new ShopifyErrors.CookieNotFound(
        `Cannot complete OAuth process. Could not find an OAuth cookie for shop url: ${shop}`,
      );
    }

    const authQuery: AuthQuery = Object.fromEntries(query.entries());
    if (!(await validQuery({config, query: authQuery, stateFromCookie}))) {
      log.error('Invalid OAuth callback', {shop, stateFromCookie});

      throw new ShopifyErrors.InvalidOAuthError('Invalid OAuth callback.');
    }
```
