### Title
Missing authorization on the "BOOTSTRAP" fee-exempt declare path allows any sender to bypass fee, nonce, and signature checks - ([File: crates/blockifier/src/transaction/account_transaction.rs])

### Summary
The blockifier's `AccountTransaction::execute_raw` grants a special, unauthenticated fast-path to any `Declare` transaction whose `sender_address` equals the well-known constant `BOOTSTRAP` address, provided `nonce == 0` and `charge_fee == false`. This path skips nonce/fee pre-validation and the account's `__validate_declare__` entry point entirely. Nothing in the Gateway's admission checks (`check_declare_permissions`) restricts who may set `sender_address` to the bootstrap address or gates this on genesis/block-0 conditions, so any unprivileged transaction submitter can construct such a transaction.

### Finding Description
`DeclareTransaction::is_bootstrap_declare` treats a declare transaction as a "bootstrap declare" purely based on transaction *field values* the sender fully controls — `sender_address == bootstrap_address()`, `nonce == 0`, and the (derived) `charge_fee` flag — not on any real authorization/ownership proof: [1](#0-0) 

When execution reaches `AccountTransaction::execute_raw`, if this predicate is true, the transaction entirely bypasses `perform_pre_validation_stage` (nonce/fee checks) and the account `__validate__` entry point, going straight to declaring the class: [2](#0-1) 

The Starknet OS re-implements the identical bypass logic in Cairo, checking only `sender_address == 'BOOTSTRAP'`, `nonce == 0`, `version == 3`, and `max_possible_fee == 0` — again fields fully controlled by the transaction author, with no signature or account-ownership check performed before declaring the class: [3](#0-2) 

Critically, the Gateway's admission-time authorization check (`check_declare_permissions`) only enforces `block_declare` and an optional `authorized_declarer_accounts` allowlist. It does not special-case or restrict the bootstrap address, and by default `authorized_declarer_accounts` is `None` (unset), meaning **any** address, including the reserved `BOOTSTRAP` address, is accepted: [4](#0-3) [5](#0-4) 

The only other guard is `assert_not_zero(compiled_class_hash)` plus `prev_value == 0` in the dict update, which only prevents re-declaring the *same* class hash twice via this path — it does not prevent an attacker from bootstrap-declaring an arbitrary *new* class hash at any point after genesis.

This is directly analogous to the Pimcore CWE-862 finding: a privileged operation (tag CRUD in Pimcore; fee/validation-exempt class declaration in Starknet) is reachable without any check that the caller is actually entitled to perform it — the "permission" is inferred from a field the caller fully controls rather than a properly authenticated identity/context.

### Impact Explanation
Any unprivileged party can submit an RPC `Declare` transaction with `sender_address = BOOTSTRAP`, `nonce = 0`, and resource bounds tuned so `charge_fee` evaluates false (as demonstrated by `ValidResourceBounds::create_for_testing_no_fee_enforcement()` / `AllResourceBounds::new_unlimited_gas_no_fee_enforcement()` used throughout the test/bootstrap tooling, and mirrored by the OS's `max_possible_fee == 0` condition). Such a transaction:
- Skips `__validate_declare__` (no signature/ownership proof required),
- Skips nonce enforcement and fee charging,
- Still results in a valid, permanent state change: the class is declared and `declared_contracts`/`compiled_class_hashes` are updated,

as shown by the test asserting a state diff purely from the declaration path with zero fee and no nonce bump: [6](#0-5) 

Consequences for a live (post-genesis) network:
- **Unauthorized privileged action**: attackers gain a free, unauthenticated declare channel indefinitely (not limited to bootstrap/genesis), letting them bypass the fee market and declare arbitrary classes at will as long as the specific class hash was not declared this way before.
- **Resource/fee-accounting bypass**: this undermines fee-based DoS protection for the declare transaction type, since the normal compilation/CPU cost of Sierra→CASM (already flagged elsewhere in the gateway as expensive) is incurred without payment.
- **Honest-node divergence risk**: because the Starknet OS re-execution path implements the exact same unauthenticated bypass logic independently in Cairo, any inconsistency between the Rust blockifier's `is_bootstrap_declare` predicate and the OS's Cairo condition (e.g., differing precisely on `charge_fee` vs. `max_possible_fee == 0` derivation) is a source of potential state-root mismatch between block building and OS re-execution.

This satisfies "unauthorized account action" / fee-accounting bypass reachable from a single submitted transaction, meeting the Medium+ severity bar.

### Likelihood Explanation
High likelihood of reachability: the check is purely a function of attacker-controlled transaction fields (`sender_address`, `nonce`, `resource_bounds`) and requires no special network position, no signing key, and no privileged account state. It is reachable through the standard `add_transaction` gateway path exactly like any ordinary declare transaction (`crates/apollo_gateway/src/gateway.rs`'s `add_tx_inner` → `check_declare_permissions` → stateless/stateful validation → mempool). No code found in the reviewed paths restricts this bypass to genesis / block 0, or to a designated bootstrapper identity, beyond the generic (and by-default disabled) `authorized_declarer_accounts` allowlist.

### Recommendation
- Do not infer "bootstrap" privilege from transaction-supplied fields alone. Gate the bootstrap-declare bypass on an explicit, node-side authorization check (e.g., only permitted when `block_number == 0` / chain has no prior blocks, as already reflected in `GenesisStateReader`/`GenesisFixedBlockStateReader`, and/or require the bootstrap declare to originate from a specifically configured/allow-listed key or L1 message rather than a public felt constant).
- In `check_declare_permissions` (`crates/apollo_gateway/src/gateway.rs`), explicitly reject any declare transaction with `sender_address == DeclareTransaction::bootstrap_address()` unless additional node-side context proves this is a legitimate genesis bootstrap flow (e.g., check via the state-sync/genesis reader that no blocks exist yet).
- Ensure the same authorization boundary is enforced consistently in `AccountTransaction::execute_raw` (blockifier) and in the Starknet OS Cairo re-execution to avoid divergence, ideally by tying eligibility to the OS-visible block number being zero rather than solely to `charge_fee`/`max_possible_fee`.
- Add a regression/integration test asserting that a bootstrap-style declare transaction submitted at a non-zero block height (i.e., after genesis) is rejected by the gateway and by execution.

### Proof of Concept
1. Post-genesis, an attacker submits an RPC `Declare` V3 transaction via `add_transaction` with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (the fixed constant `0x424f4f545354524150`),
   - `nonce = Nonce(Felt::ZERO)`,
   - `resource_bounds` set so that `max_possible_fee == 0` (e.g., `ValidResourceBounds::create_for_testing_no_fee_enforcement()`, mirroring `generate_bootstrap_declare()` in `crates/mempool_test_utils/src/starknet_api_test_utils.rs`),
   - `signature = TransactionSignature::default()` (empty/no signature needed),
   - an arbitrary not-yet-declared `class_hash`/`compiled_class_hash` pair for a contract of the attacker's choosing.
2. `check_declare_permissions` passes because `authorized_declarer_accounts` is unset by default and `block_declare` is false.
3. Stateless/stateful validation pass; nonce read for `BOOTSTRAP` returns default `0`.
4. During execution, `AccountTransaction::execute_raw` detects `tx.is_bootstrap_declare(charge_fee=false)` is true and takes the bypass branch, declaring the class without running `__validate_declare__`, without nonce increment, and without fee charge.
5. The class is now declared in state — a free, unauthenticated privileged declaration — repeatable for any number of distinct class hashes not previously declared via this path, at any block height.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

        // Do not run validate or perform any account-related actions for declare transactions that
        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),
                );
                let mut remaining_gas = 0;
                let res = tx.run_execute(state, &mut context, &mut remaining_gas)?;
                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());
            }
        }

    fn check_declare_permissions(
        &self,
        declare_tx: &RpcDeclareTransaction,
    ) -> Result<(), StarknetError> {
        // TODO(noamsp): Return same error as in Python gateway.
        if self.config.static_config.block_declare {
            return Err(StarknetError {
                code: StarknetErrorCode::UnknownErrorCode(
                    "StarknetErrorCode.BLOCKED_TRANSACTION_TYPE".to_string(),
                ),
                message: "Transaction type is temporarily blocked.".to_string(),
            });
        }
        let RpcDeclareTransaction::V3(declare_v3_tx) = declare_tx;
        if !self.config.is_authorized_declarer(&declare_v3_tx.sender_address) {
            return Err(StarknetError {
                code: StarknetErrorCode::KnownErrorCode(
                    KnownStarknetErrorCode::UnauthorizedDeclare,
                ),
                message: format!(
                    "Account address {} is not allowed to declare contracts.",
                    &declare_v3_tx.sender_address
                ),
            });
        }
        Ok(())
    }
