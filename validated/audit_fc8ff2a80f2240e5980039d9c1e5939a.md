# H-10 Analog Analysis for Push Chain

## Title
Instantaneous Uniswap V3 spot-quote used as sole price reference for module-driven PRC20↔WPC auto-swaps and gas refunds enables AMM price manipulation to drain protocol-routed liquidity - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

## Summary
The Plaza Finance bug (H-10) is a case where a protocol-internal ratio (`collateralLevel`) that gates which pricing formula applies is computed from live, attacker-movable state (TVL/supply), letting a user temporarily shift the ratio across a threshold, benefit from the more favorable formula, then reverse the shift. The closest reachable analog in Push Chain is the reliance on a single-block Uniswap V3 **spot** quote (`QuoterV2.quoteExactInputSingle`) as the only price reference used to compute swap floors for PRC20↔WPC conversions performed *by the protocol itself* on a user's behalf, both for inbound gas deposits and for outbound gas refunds.

## Finding Description
`GetSwapQuote` fetches a non-committing quote from `QuoterV2.quoteExactInputSingle`, which reflects the Uniswap V3 pool's current instantaneous price (no TWAP), and this value is used to derive a `minPCOut` slippage floor before immediately executing a real swap in the same call: [1](#0-0) 

This pattern (`GetDefaultFeeTierForToken` → `GetSwapQuote` → `minPCOut = quote * 95/100` → commit swap) is repeated in three independent fund-moving flows:

1. Inbound gas top-up auto-swap: [2](#0-1) 

2. Combined gas+payload auto-swap: [3](#0-2) 

3. Excess-gas refund swap on outbound completion: [4](#0-3) 

In all three, `minPCOut` is only a lower bound derived from the *current* pool price, not a manipulation-resistant reference (e.g., a TWAP or oracle-checked price). Because the quote and the actual swap execution both read the same live pool state, whoever controls that pool state at the moment of execution controls the outcome. An unprivileged actor who is also the depositor/sender can pump the WPC/PRC20 pool price (via ordinary swaps against the Uniswap V3 pool that backs `UniversalCore`) ahead of when their own inbound/outbound is finalized (inbound execution triggers once UV votes cross the ballot threshold; outbound refund triggers once UV votes observe the destination result), hold the manipulated price until that Cosmos-module-driven swap executes, extract an inflated amount of WPC (i.e., native PC) from the pool relative to fair value, and then unwind the manipulation — the exact "manipulate a rate → benefit from a subsequently-computed value → reverse the manipulation" shape as the Plaza `collateralLevel` exploit, except here the value siphoned comes from the WPC/PRC20 liquidity pool routed through `depositPRC20WithAutoSwap` / `refundUnusedGas` rather than from a bond/leverage TVL split.

## Impact Explanation
If exploitable, this allows an unprivileged user to extract value from the WPC/PRC20 pool that backs cross-chain gas top-ups and refunds, beyond what their deposited/refunded amount is fairly worth, at the expense of protocol- or LP-owned liquidity — matching the in-scope impact category of corrupting "PRC20 or native asset accounting, gas fee accounting, refund accounting ... token mapping" via a user-reachable flow with honest validators.

## Likelihood Explanation
Likelihood is constrained by several factors: (1) the actual swap logic and pool reserves live in the external `UniversalCore`/Uniswap V3 Solidity contracts, which are outside this repository's scope and cannot be fully verified here; (2) execution timing is gated by UV ballot finalization (not directly by the attacker), so precise single-block sandwiching is not generally achievable — only sustained (multi-block) price-holding is plausible, which requires capital and is easier to counter-arbitrage by third parties on a liquid pool; (3) the 5% slippage floor bounds losses but does not bound gains from a manipulated favorable price. Given the inability to inspect the actual AMM/pool contract code from this repository, this should be treated as a **design-level pricing weakness** rather than a confirmed, fully-reachable exploit within this repo's scope.

## Recommendation
Replace or supplement instantaneous `quoteExactInputSingle` spot pricing with a manipulation-resistant reference (TWAP over a window, or an external price oracle) for both the auto-swap deposit path and the gas-refund swap path, and/or cap the deviation allowed between the quoted price and a longer-window reference price before committing `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`.

## Proof of Concept
Conceptual (bounded by lack of visibility into `UniversalCore`/pool contract code in this repository):
1. Attacker deposits on a source chain to trigger a Push Chain inbound gas top-up destined to their own UEA.
2. Before/while UVs are voting the inbound to finality, attacker swaps heavily against the WPC/PRC20 Uniswap V3 pool on Push Chain to push the pool price in their favor.
3. When the ballot passes, `ExecuteInboundGas` calls `GetSwapQuote` then `CallPRC20DepositAutoSwap` using the manipulated live price, minting an inflated amount of WPC/PC to the attacker's UEA relative to the PRC20 amount actually bridged.
4. Attacker reverses their initial swap, restoring the pool and keeping the extracted surplus. [5](#0-4) 

Because full confirmation requires the external AMM/`UniversalCore` contract source (not present in this repository), this finding is reported as a scoped-code pricing-input weakness rather than a fully proven exploit chain.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
