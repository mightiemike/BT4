## Analog Vulnerability Found

### Title
Missing declared-class validation in Starknet OS `replace_class` syscall allows blockifier/OS state divergence via undeclared class hashes - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
CVE-2021-41790 involves executing scripts that were never validated/registered in the sanctioned storage location (the Data Dictionary). The Starknet OS (SNOS) contains a directly analogous gap: its `replace_class` syscall handler writes an arbitrary attacker-supplied class hash into contract state **without verifying the class was ever declared**, while the actual sequencer execution engine (blockifier) enforces this check and reverts such transactions.

### Finding Description
The blockifier's `replace_class` syscall implementation explicitly requires the target class to be declared and Cairo1 before permitting the state mutation: [1](#0-0) 

The deprecated (Cairo0) syscall path enforces the same rule: [2](#0-1) 

In contrast, the Starknet OS's `execute_replace_class` (used for re-execution/proving) performs no such check at all — it directly overwrites the contract's `StateEntry.class_hash` with the value supplied in the syscall request, guarded only by an explicit TODO acknowledging the missing check: [3](#0-2) 

The deprecated OS syscall handler has the identical gap, with no declared-class lookup before the state entry is overwritten: [4](#0-3) 

Unlike `library_call` or `deploy`, which must load and execute bytecode for the target class hash (and therefore are naturally constrained by the guessed compiled-class-facts bundle), `replace_class` is a pure state write that requires no code execution from the target class. This means the OS has no incidental mechanism to reject an undeclared class hash for this syscall.

### Impact Explanation
When an attacker submits an INVOKE transaction whose `__execute__` calls `replace_class_syscall(undeclared_class_hash)`:
- The sequencer's blockifier raises `StateError::UndeclaredClassHash`, causing the transaction to be marked REVERTED (fee charged/nonce incremented, but no class-hash state change committed).
- The Starknet OS, when re-executing the identical transaction to produce/verify the proof, applies the class-hash overwrite unconditionally and does not detect any failure, so it does not revert.

This produces a genuine state-transition divergence between the sequencer's committed state (used to build/propose the block) and the OS's independently re-executed state (used to generate the STARK proof / final L1 state commitment). This falls squarely in the "wrong committed root" / "honest-node divergence" impact category: the class hash of an account/contract can end up bound to a value that never went through the Declare pipeline (fee payment, compiled-class-hash validation, Sierra version checks), or the mismatch can cause proof/state-root verification to fail, halting new block confirmation.

### Likelihood Explanation
Triggering the divergence requires only a single ordinary transaction from any account calling the standard, unprivileged `replace_class_syscall` with a class hash that has not been declared — no special permissions, no compromised operator, and no p2p/consensus assumptions are needed. The `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment is direct developer-acknowledged evidence that the check is currently absent.

### Recommendation
Add a declared-class existence check (analogous to the blockifier's `get_compiled_class` call) inside both `execute_replace_class` implementations in the Starknet OS Cairo code, verifying the target class hash corresponds to a class present in the compiled-class-facts bundle (or otherwise provably declared) before the `contract_state_changes` dictionary update is performed, matching the blockifier's semantics exactly (including the V0-class-hash rejection rule).

### Proof of Concept
1. Declare and deploy any test contract exposing `replace_class_syscall` (e.g., `test_replace_class` in `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo`). [5](#0-4) 
2. Submit an INVOKE transaction calling `test_replace_class(undeclared_class_hash)` where `undeclared_class_hash` is any value never declared on-chain.
3. Observe (per existing blockifier unit tests) that the blockifier reverts/rejects this call with "is not declared": [6](#0-5) 
4. Re-execute the same transaction trace through the Starknet OS's `execute_replace_class` (`syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`) and observe it unconditionally writes the undeclared class hash into `contract_state_changes` with no error, producing a state/result diverging from the blockifier's reverted outcome.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.

        key=contract_address,
