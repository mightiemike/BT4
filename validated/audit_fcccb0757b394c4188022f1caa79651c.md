## Finding

State-commitment analog to the ERC4626 report: a value that should participate in an integrity comparison is silently dropped from the comparison, causing an authenticated proof field to diverge from local computation without detection — mirroring how `accPnlPerToken` diverges from the true share price without being caught.

### Title
`replay_on_archive` verification silently ignores authenticated checkpoint-hash fields of `TransactionInfoV1`, allowing committed state-root divergence to go undetected - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole correctness check used by the `db-tool replay_on_archive` `Verifier` to confirm that locally re-executed transactions match the transaction info that was actually committed to the transaction accumulator on mainnet. The function checks status, gas used, write-set hash, and event root hash, but it does not check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — all of which are part of `TransactionInfoV1` and thus part of the accumulator-committed, authenticated ledger state.

### Finding Description
`ensure_match_transaction_info` explicitly compares only four fields — status, gas used, write-set hash, and event root hash — before returning `Ok(())`: [1](#0-0) 

The function's own trailing comment admits the gap: it does not validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`, and states that replay tooling such as `db-tool`'s `replay_on_archive` "can report a successful replay even when the authenticated position state root diverges from local execution": [2](#0-1) 

`db-tool/src/replay_on_archive.rs`'s `Verifier::execute_and_verify` calls this exact function as the only pass/fail gate per transaction: it re-executes each transaction locally via `AptosVMBlockExecutor`, then calls `ensure_match_transaction_info(version, &expected_txn_infos[idx], ...)`, treating an `Ok` result as proof that local execution reproduces mainnet's committed state: [3](#0-2) 

`state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` are all committed, accumulator-hashed fields of `TransactionInfoV1` (they are hashed via `txn_info.hash()` when the accumulator leaf is built): [4](#0-3) [5](#0-4) 

Because these hashes carry the authenticated state Merkle roots (regular state, hot state, and the new native-trading "position" state introduced by `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`TRADING_NATIVE` features), any bug that causes local state-root computation to diverge from what was actually committed on-chain (e.g. a JMT/state-checkpoint construction bug, an ordering bug in `DoStateCheckpoint`, or a position-state summary bug in `commit_native_position`) would be invisible to the archive-replay verification tool, even though the write set, events, gas, and status all "match."

This is the direct analog of the ERC4626 report: there, a quantity needed for one invariant (accurate PnL accounting) was silently entangled with/omitted from another invariant (share-price stability) such that a real divergence was masked by omission rather than caught. Here, a quantity needed for one invariant (accumulator/state-root proof integrity) is omitted from the comparison used by the tool whose entire purpose is to catch that exact class of divergence.

### Impact Explanation
This does not corrupt consensus itself — validators independently compute and vote on state roots via the normal execution/ledger-update pipeline, so a single divergent node cannot force bad state into the accumulator. The impact is on the fallback/last-line defense: the archive replay-verification tool (`db-tool replay_on_archive`), which is precisely the mechanism intended to catch "hard-fork-only divergence during commit, replay, restore" per the task's stated scope. If a state-root-affecting bug exists anywhere in `DoStateCheckpoint`, hot-state, or the new native-trading position-state pipeline, `replay_on_archive` will report full success while the authenticated state root recorded on mainnet is provably wrong, delaying detection of a live consensus-state corruption or hard-fork-worthy bug. Given the code's own comment calls this out as a precondition ("Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`"), the gap is real and unaddressed in current code, and `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`TRANSACTION_INFO_V1` feature flags already exist and can be enabled.

### Likelihood Explanation
Likelihood of the verification gap itself firing is High — it is unconditional (no feature flag guards the missing comparisons; it always skips these fields when `TransactionInfoV1` is in use). The likelihood of an actual underlying state-root bug occurring is independent and not itself proven here, but the missing check means the network's dedicated safety net for that class of bug is broken by design today, once `TRANSACTION_INFO_V1` (and especially `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) is active.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against locally recomputed equivalents whenever they are present in the on-chain `TransactionInfo`, before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`HOT_STATE_ROOT_IN_TXN_INFO` in production, exactly as the existing TODO comment specifies.

### Proof of Concept
Not exploitable as a direct funds-loss PoC; the flaw is demonstrated structurally by code inspection:
1. `TransactionInfoV1` includes `state_checkpoint_hash`, `hot_state_checkpoint_hash`, `position_state_checkpoint_hash`, all folded into `txn_info.hash()` which is what's committed to the transaction accumulator [5](#0-4) .
2. `ensure_match_transaction_info` never reads or compares those three fields [6](#0-5) .
3. `replay_on_archive::Verifier::execute_and_verify` treats `Ok(())` from that function as full verification success and would report zero failed transactions even if the position/hot/state checkpoint hash committed on mainnet differs from what local re-execution computes [7](#0-6) .

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
