### Title
GAS/GAS_AND_PAYLOAD auto-swap minPCOut is derived from a manipulable spot price, enabling sandwich attacks that drain user swap value - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
When `x/uexecutor` processes a `GAS` or `GAS_AND_PAYLOAD` inbound, it auto-swaps the deposited PRC20 for WPC via a Uniswap V3 pool and computes a `minPCOut` slippage bound from `GetSwapQuote`, which reads the pool's current spot price with no TWAP/oracle reference. Because the reference price and the swap execution happen back-to-back using the same manipulable AMM state, an unprivileged attacker who trades against the pool immediately beforehand can move the spot price, causing `minPCOut` to be computed against the already-skewed price. The 5% band only bounds deviation from the attacker's manipulated reference, not from a fair price, so the user's autoswap executes at the manipulated rate while the attacker reverses the trade for profit — the same "no real slippage protection" failure mode as the reported ERC-4626 issue, applied to Push Chain's PRC20→WPC autoswap.

### Finding Description
`GetSwapQuote` (x/uexecutor/keeper/evm.go:502-538) calls `QuoterV2.quoteExactInputSingle` with `commit=false`, reading the live spot price of the configured Uniswap V3 pool for the `prc20/wpc` pair at the moment of execution: [1](#0-0) 

Both `ExecuteInboundGas` (x/uexecutor/keeper/execute_inbound_gas.go:103-153) and `gasAndPayloadDepositAutoSwap` (x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379) then derive `minPCOut` directly from that same quote with a fixed 5% tolerance and immediately execute `CallPRC20DepositAutoSwap` against the same pool: [2](#0-1) [3](#0-2) 

The comment on `CallPRC20DepositAutoSwap` even documents that `fee` and `minPCOut` are "pre-computed by the caller" from the same pool being swapped against, and `deadline` is passed as `0` ("contract uses its default"), removing any additional time-based mitigation: [4](#0-3) 

An inbound's `SourceChain`, `AssetAddr`, `Amount`, and `Recipient` become publicly observable on-chain as soon as the first validator vote creates the pending `UniversalTx` record (before the vote threshold, and hence before the swap, is reached), per the documented lifecycle: [5](#0-4) 

This gives an unprivileged attacker everything needed to sandwich the autoswap: knowledge of the exact swap size and asset ahead of execution, and a manipulable spot-price oracle used as the sole slippage reference. This is the direct analog of the reported bug class: "slippage protection" exists syntactically (a `minPCOut` parameter, a `95/100` factor) but does not protect against price manipulation because the reference price itself is attacker-controllable within the same trust boundary as the swap.

### Impact Explanation
A successful sandwich lets an attacker extract value from every GAS/GAS_AND_PAYLOAD inbound that goes through auto-swap: the user's PRC20 is converted to WPC at a manipulated rate, so the user (and ultimately protocol-controlled PRC20/WPC accounting) receives less WPC than fair value while the attacker captures the difference by reversing their manipulation trade afterward. This falls under "corruption of PRC20 or native asset accounting" and "unauthorized state transitions in universal execution flows" in the allowed impact gate, since it results in a mispriced, protocol-executed conversion of user funds reachable purely from ordinary deposit/inbound flows with no privileged access required.

### Likelihood Explanation
Likelihood depends on the liquidity depth of the specific PRC20/WPC pool and fee tier used for a given token, and on the attacker's ability to get their front-run/back-run trades ordered around the finalizing vote transaction in the same or an adjacent block. For thinly-liquid pools (likely for many bridged PRC20 assets early in the token's life), a modest capital outlay can move the spot price well beyond the 5% band's ability to protect the user, making this readily exploitable; for deep pools it is less profitable but still nonzero.

### Recommendation
Do not derive `minPCOut` solely from a same-block/same-call spot quote of the pool being traded against. Use a manipulation-resistant reference (e.g., a time-weighted average price, an external chain-meta/oracle price already tracked by `x/uexecutor` via `ChainMeta`/gas price voting, or a user/validator-supplied `minPCOut` bound checked against a sanity band) so the slippage check is meaningful even when the attacker can influence the pool immediately before execution. Additionally, set an explicit, short `deadline` instead of `0`/contract-default to reduce the window during which a stale, manipulated quote can be used.

### Proof of Concept
1. Attacker monitors pending inbounds; observes a `GAS_AND_PAYLOAD` or `GAS` inbound for `sourceChain`/`assetAddr` with a sizable `Amount` after the first `MsgVoteInbound` creates the `UniversalTx` (per x/uexecutor/README.md lifecycle).
2. Before/within the block where the last required validator vote lands (triggering `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`), attacker submits a large swap against the same PRC20/WPC Uniswap V3 pool (fee tier from `GetDefaultFeeTierForToken`) to skew the spot price.
3. When the threshold vote executes, `GetSwapQuote` (x/uexecutor/keeper/evm.go:502) returns the skewed price; `minPCOut = quote*95/100` is computed from it and passed to `CallPRC20DepositAutoSwap`, which executes the swap at the skewed rate.
4. Attacker immediately submits a reverse trade to restore the pool price, realizing the extracted value while the inbound's recipient UEA receives WPC valued below fair market price.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
```

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
```

A typical `FUNDS_AND_PAYLOAD` inbound, end to end:

```
1. UV observes a source-chain gateway event.
2. UV submits MsgVoteInbound. The UTX is created the moment the first vote
   arrives, with id = sha256(sourceChain:txHash:logIndex). Only the
   InboundTx field is populated; PcTx and OutboundTx are empty.
   (UTX id is also added to PendingInbounds.)

3. Threshold of UV votes reached. The keeper executes the inbound:
   a. Mints the PRC20 to the recipient's UEA address.
      A new PCTx (deposit) is appended to UTX.PcTx.
   b. Runs the universal payload through the UEA.
      A second PCTx (executeUniversalTx) is appended.
   (UTX id removed from PendingInbounds.)
