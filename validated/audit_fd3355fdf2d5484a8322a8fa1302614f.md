### Title
`sanitizeShop`'s `throwOnInvalid` guard is bypassed by domain-transformation functions, letting `getOfflineId` collapse multiple shops into the literal session id `'offline_null'` - (File: `packages/apps/shopify-api/lib/utils/shop-validator.ts`)

### Summary
`sanitizeShop(config)(shop, true)` is documented/expected to either return a valid shop string or throw `InvalidShopError`, but its `throwOnInvalid` check runs *before* `applyDomainTransformations` is applied, so a custom `transform` function that returns `null` silently bypasses the throw. `getOfflineId`/`getJwtSessionId` then interpolate that `null` into a template literal, producing the fixed string `offline_null`/`<...>_null`, which is used to key the session in storage. Any two shops whose domain matches the transformation regex but whose transform returns `null` collide on the same session-storage id.

### Finding Description
In `applyDomainTransformations` (`packages/apps/shopify-api/lib/utils/domain-transformer.ts:45-47`), a function-based `transform` can return `null`, and this is explicitly tested/supported (`packages/apps/shopify-api/lib/utils/__tests__/domain-transformer.test.ts:121-134`).

In `sanitizeShop` (`packages/apps/shopify-api/lib/utils/shop-validator.ts:39-48`):
```
const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
if (!sanitizedShop && throwOnInvalid) {
  throw new InvalidShopError('Received invalid shop argument');
}
if (sanitizedShop && config.domainTransformations) {
  return applyDomainTransformations(sanitizedShop, config);
}
return sanitizedShop;
```
The `throwOnInvalid` check only validates that the shop matches the built-in regex; it happens *before* `applyDomainTransformations` runs. If the regex matches (so `sanitizedShop` is truthy) but the custom `transform` function returns `null`, `sanitizeShop` returns `null` even though `throwOnInvalid` was `true` and no exception is raised.

`getOfflineId` (`packages/apps/shopify-api/lib/session/session-utils.ts:22-26`) and `getJwtSessionId` (lines 16-20) call `sanitizeShop(config)(shop, true)` and interpolate the result directly into a template literal:
```
return `offline_${sanitizeShop(config)(shop, true)}`;
```
When `sanitizeShop` returns `null`, JavaScript's template-literal coercion turns this into the literal string `'offline_null'` for every shop that falls into the null-returning branch of the transform, regardless of the shop's real identity.

### Impact Explanation
Any two (or more) distinct, legitimately-installed shops whose domains match a configured transformation regex but map to `null` in the custom transform end up sharing the exact same offline (or online, via `getJwtSessionId`) session-storage key. This breaks the tenant-isolation invariant: one shop's authenticated session (including its offline access token) can be looked up, returned, or overwritten by another shop's session flow. This matches Shopify's "cross-tenant session/data access" bounty impact class.

### Likelihood Explanation
Exploitation requires the host app to configure `domainTransformations` with a function-based `transform` that can return `null` for more than one distinct shop name (a real, tested code path per `domain-transformer.test.ts`). Given that precondition, the collision is deterministic and trivially repeatable by any merchant who installs the app on a shop that lands in the null branch — no secrets, forged tokens, or privileged access are needed. The root cause is that the library's `throwOnInvalid` contract silently fails to cover the post-transformation `null` case.

### Recommendation
In `sanitizeShop` (`packages/apps/shopify-api/lib/utils/shop-validator.ts`), re-check the result of `applyDomainTransformations` against `throwOnInvalid` and throw `InvalidShopError` if it returns `null`/falsy, instead of returning it silently. Additionally, `getOfflineId`/`getJwtSessionId` should not rely on unchecked template-literal coercion of a possibly-`null` shop value — they should propagate/throw on `null` rather than silently producing `offline_null`.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts
import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('cross-tenant collision via null-returning transform bypasses throwOnInvalid', () => {
  const shopify = shopifyApi(
    testConfig({
      domainTransformations: [
        {
          match: /^(test-[a-zA-Z0-9-_]+)\.my\.shop\.dev$/,
          transform: () => null, // e.g. developer's "reject test shops" logic
        },
      ],
    }),
  );

  // Both calls use throwOnInvalid = true but do NOT throw:
  const shopA = shopify.utils.sanitizeShop('test-a.my.shop.dev', true);
  const shopB = shopify.utils.sanitizeShop('test-b.my.shop.dev', true);

  expect(shopA).toBeNull();
  expect(shopB).toBeNull();

  const offlineIdA = `offline_${shopA}`;
  const offlineIdB = `offline_${shopB}`;

  // Both distinct shops collide on the same session storage id.
  expect(offlineIdA).toBe('offline_null');
  expect(offlineIdB).toBe('offline_null');
  expect(offlineIdA).toBe(offlineIdB);
});
