### Title
Weak `getTransformationDomains` regex-extraction heuristic silently produces an overly-broad TLD fragment (e.g. bare `com`), widening `sanitizeShop`/`sanitizeHost` allowlists to accept arbitrary attacker domains - (File: packages/apps/shopify-api/lib/utils/domain-transformer.ts)

### Summary
`getTransformationDomains` extracts a "domain" fragment from a `domainTransformations[].match` regex source using the naive pattern `/\\\.([\\.\w-]+)\$?$/`, which is documented as unsupported for alternations/optional-groups/character-classes. For such patterns, instead of failing safe, the heuristic matches the *last* trailing `\.<label>` segment before the string end (e.g. it extracts just `com` out of `\.(dev|staging)\.example\.com$`), and this fragment is pushed unescaped-as-alternative into `domainsRegex.join('|')` used to build `shopUrlRegex`/`hostRegex` in `shop-validator.ts`. Because `com` alone becomes a valid alternative in the suffix group, any single-label `*.com` shop domain (for `sanitizeShop`) or any hostname ending in `.com` (for `sanitizeHost`) is now accepted as valid, defeating the intended domain allowlist.

### Finding Description
`getTransformationDomains` (packages/apps/shopify-api/lib/utils/domain-transformer.ts:90-129) runs `regex.source.match(/\\\.([\\.\w-]+)\$?$/)` to heuristically pull a domain suffix out of a configured transformation's `match` regex. [1](#0-0) 

For a documented-as-unsupported pattern such as `/\.(dev|staging)\.example\.com$/`, the extraction regex cannot match starting at the `\.` before the alternation group (`(dev|staging)`) because `(` is not part of the character class `[\.\w-]`, so that candidate position fails to reach the string end. It also cannot successfully match starting at the `\.` before `example` for the same reason (the following `\.` before `com` breaks the greedy run before the end-of-string anchor can be satisfied). The only position where the pattern can match all the way to the end of the source string is the final `\.com$`, so `domainPattern[1]` resolves to the single label `"com"` — not `example.com`, not `dev.example.com`. This happens silently; the code only logs at `debug` level when the *whole* match fails (`domainPattern` is falsy), but here the match *does* succeed (just against the wrong, dangerously short substring), so no warning is emitted at all. [2](#0-1) 

This bogus `"com"` value is then pushed into `domainsRegex` in `shop-validator.ts` and joined unescaped/unsanitized into the allowlist regex alternation: [3](#0-2) 
`shopUrlRegex` becomes `^[a-zA-Z0-9][a-zA-Z0-9-_]*\.(myshopify\.com|shopify\.com|myshopify\.io|shop\.dev|com)[/]*$`. Any single-label domain ending in `.com` (e.g. `evil-shop.com`) now satisfies this regex and is accepted by `sanitizeShop`.

The same flaw affects `sanitizeHost`, which is even more exploitable because `hostRegex` there is not anchored to a single label at the start: [4](#0-3) 
`hostRegex = /\.(myshopify\.com|shopify\.com|myshopify\.io|spin\.dev|shop\.dev|com)$/` matches **any** hostname ending in `.com` (e.g. `attacker.evil.com`), not just the intended `example.com`/`dev.example.com` transformation target. `sanitizeHost` output feeds `buildEmbeddedAppUrl`, which decodes the (attacker-controlled, base64) `host` query param and constructs a redirect URL `https://${decodedHost}/apps/${config.apiKey}` without further origin restriction beyond `sanitizeHost`'s regex check. [5](#0-4) 

None of the existing protections stop this: `sanitizeShop`/`sanitizeHost` are the actual security boundary being widened, and the bug is in how their allowlist regex is *constructed*, not bypassed by some other check.

### Impact Explanation
Once an app has configured any `domainTransformations` entry whose `match` regex falls into the documented "unsupported" categories (alternation, optional group, character class before the final literal domain), the shop/host domain allowlist silently degrades from a small fixed set of Shopify domains to "anything ending in `.com`" (and analogous broadening for other TLD/segment fragments extracted the same way). This is a `DESTINATION_ALLOWLIST` bypass: `sanitizeHost` accepting arbitrary `.com` hosts enables open-redirect via `getEmbeddedAppUrl`/`buildEmbeddedAppUrl`, and `sanitizeShop` accepting arbitrary `.com` "shops" can let attacker-controlled domains be treated as legitimate shop domains downstream (e.g. OAuth begin/callback shop parameter, webhook shop domain checks) wherever the app relies on `sanitizeShop`/`sanitizeHost` as the trust boundary.

### Likelihood Explanation
Precondition: the app owner must have configured `domainTransformations` with a `match` regex from the "unsupported" category (this is explicitly documented in code comments as producing incorrect extraction, but no code prevents it and no visible warning is logged in the "com"-only case since extraction technically "succeeds"). Given that precondition, the attacker capability is minimal — any unprivileged caller can submit an arbitrary `shop` query param or crafted `host` param to trigger `sanitizeShop`/`sanitizeHost` and the widened allowlist immediately accepts it. Reproducibility is deterministic and does not depend on secrets, timing, or race conditions.

### Recommendation
- Make `getTransformationDomains` fail closed rather than silently extracting an overly generic fragment: validate that the extracted fragment contains at least two labels (i.e., contains a literal `.`) and reject/skip single-label extractions like bare `com`.
- Better: instead of regex-source string heuristics, require `domainTransformations` entries to also specify an explicit `domain` (or `allowedSuffix`) string field for allowlist purposes, decoupled from parsing the `match` regex source.
- Escape/validate any extracted fragment before joining into `domainsRegex` (reject values that aren't a normal `label(\.label)+` domain shape) and log at `warn` (not `debug`) when a transformation is skipped or extraction is ambiguous, so misconfiguration is visible to app owners.

```ts
// packages/apps/shopify-api/lib/utils/__tests__/domain-transformer.test.ts (new case)
import {getTransformationDomains} from '../domain-transformer';
import {sanitizeShop, sanitizeHost} from '../shop-validator';

test('unsupported alternation pattern extracts overly broad "com" fragment', () => {
  const config: any = {
    domainTransformations: [
      {
        match: /\.(dev|staging)\.example\.com$/,
        transform: '$1.internal.example.com',
      },
    ],
    logger: {log: () => {}},
  };

  const domains = getTransformationDomains(config);
  expect(domains).toContain('com'); // BUG: should never allow a bare TLD fragment

  // sanitizeShop now accepts an attacker-chosen .com domain that has
  // nothing to do with example.com
  const shop = sanitizeShop(config)('evil-shop.com', false);
  expect(shop).not.toBeNull(); // BUG: allowlist bypass

  // sanitizeHost is even broader (unanchored at start)
  const host = Buffer.from('attacker.evil.com/admin').toString('base64');
  const result = sanitizeHost(config)(host, false);
  expect(result).not.toBeNull(); // BUG: any *.com host accepted
});
```
Expected (secure) behavior: both `sanitizeShop('evil-shop.com')` and `sanitizeHost(...)` for an arbitrary `*.com` host should return `null`, since neither is `myshopify.com`/`shopify.com`/`myshopify.io`/`shop.dev`/`spin.dev` nor a domain intentionally targeted by the configured transformation (`example.com`/`dev.example.com`/`staging.example.com`).

```typescript
export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
```
