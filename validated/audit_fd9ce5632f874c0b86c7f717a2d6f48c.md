### Title
Replay/consistency check `ensure_match_transaction_info` never validates `position_state_checkpoint_hash` against `TransactionInfo` - (File: types/src/transaction/mod.rs)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function that cross-checks a locally re-executed `TransactionOutput` against the authenticated `TransactionInfo` stored in the ledger accumulator (status, gas, write-set hash, event root). For the new `TransactionInfoV1` native-position feature, the analogous `position_state_checkpoint_hash` field is deliberately left unchecked, with a `TODO(trading-native)` comment acknowledging the gap.

### Finding Description
`ensure_match_transaction_info` validates `state_change_hash` (write-set hash) and `event_root_hash` against `txn_info`, but explicitly does **not** validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`: [1](#0-0) 
This means any consumer that relies on this function as its sole state-root consistency check (e.g. replay/verification tooling such as `db-tool`'s `replay_on_archive`, referenced directly in the comment) will report a transaction as successfully replayed even if the locally computed native-position state root diverges from the authenticated root committed to the transaction accumulator via `TransactionInfoV1`.

The broader native-position pipeline otherwise does enforce this check at the executor layer — `DoStateCheckpoint` compares computed roots against `known_position_state_checkpoints` sourced from committed `TransactionInfo`s during chunk replay: [2](#0-1) 
and `get_state_checkpoint_hashes` enforces `known[idx] == Some(computed_last_checkpoint_hash)`: [3](#0-2) 
So the consensus/commit-time path is protected. The gap is specifically in the standalone `ensure_match_transaction_info` comparator, which is a narrower, separately-invoked consistency check.

### Impact Explanation
If any tool or verification path (replay-verify, debugging/auditing utilities, or future consumers) treats `ensure_match_transaction_info` as a complete "does this output match the committed TransactionInfo" check, it can be misled into believing a replayed transaction's native-position (`TransactionInfoV1`) state is correct when it has actually diverged — masking state-commitment divergence rather than causing it. This is a proof/verification integrity gap (a wrong root being silently accepted as consistent by that specific comparator) rather than a live commit-path bypass, since the actual commit path (`DoStateCheckpoint`) already enforces the check independently.

### Likelihood Explanation
Low likelihood of high/critical mainnet impact today: the `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature flag gating native-position root computation is not confirmed to be enabled on mainnet, and the function's only currently-identified caller context is stated in the comment to be replay-verify tooling, not the consensus commit path (which is independently protected by `DoStateCheckpoint`). The code comment itself flags this as a pre-existing known gap ("Validate the checkpoint hashes here before enabling COMPUTE_TRADING_NATIVE_STATE_ROOTS"), indicating it is an intentionally deferred TODO rather than an active, currently-exploitable divergence.

### Recommendation
Before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (and `HOT_STATE_ROOT_IN_TXN_INFO`) are enabled, extend `ensure_match_transaction_info` to also validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against the corresponding computed values, so any tool relying on this comparator (replay-verify, archival node validation, etc.) cannot silently accept a divergent native-position (or hot-state) root as a valid replay.

### Proof of Concept
Not applicable as an exploit PoC — the finding is a code-level gap identified via static analysis of [4](#0-3) , confirmed by cross-referencing the enforced check that exists at the executor/commit layer [5](#0-4) , showing the gap is isolated to the standalone comparator rather than the commit path itself.

**Caveat**: I could not fully verify (a) whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled anywhere reachable on mainnet, or (b) all current callers of `ensure_match_transaction_info` to confirm whether any of them are relied upon for a security-relevant, unprivileged, mainnet-facing decision (as opposed to internal debugging/replay tooling). Given this uncertainty and that the commit-time enforcement path is independently correct, this finding is reported with reduced confidence relative to a full commit-path bypass, and should be treated as a hardening/defense-in-depth issue pending confirmation of caller context and feature-flag status, rather than a definitive high/critical mainnet exploit.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
