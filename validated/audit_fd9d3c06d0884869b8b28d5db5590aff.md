### Title
Unbounded linear scan of `PendingInbounds` on every ballot-terminal event enables gas-cost blow-up and stuck/DoS'd inbound voting - (File: x/uexecutor/keeper/ballot_hooks.go)

### Summary
The Yeti report describes an ever-growing, never-pruned array (`poolColl.tokens[]`) that is linearly scanned on every `getVC()` call, so gas cost grows unbounded with protocol usage until transactions revert with Out-of-Gas. Push Chain's `x/uexecutor` module has a structurally identical pattern: the `PendingInbounds` collection has no size cap, is driven purely by ordinary/unprivileged user cross-chain deposit activity, and is *fully scanned* (`Walk`) every single time an inbound ballot reaches a terminal state, instead of being looked up by its own key.

### Finding Description
`RecordInboundVote` creates one `PendingInboundEntry` per unique `utx_key` (derived from `source_chain:tx_hash:log_index`) the first time any validator votes on it, and appends an `InboundVariant` per distinct marshaled payload [2](#0-1) . Nothing caps the number of entries in `PendingInbounds` or the number of variants per entry — growth is entirely a function of unprivileged, ordinary deposit submissions on source chains that validators then observe.

When any such ballot reaches a terminal status (PASSED/REJECTED/EXPIRED), `x/uvalidator`'s `MarkBallotExpired`/`MarkBallotFinalized` fire `AfterBallotTerminal`, which in `x/uexecutor` dispatches to `afterInboundBallotTerminal` [3](#0-2) . Because ballot IDs are one-way digests, this handler locates the owning `PendingInboundEntry` by doing a full `k.PendingInbounds.Walk(ctx, nil, ...)` over **every** entry and **every** variant in the entire collection — an O(N·V) operation for a single terminal transition, explicitly acknowledged in the code comment as relying on "the pending set is small and transient" [4](#0-3) .

Critically, this is not confined to `EndBlock`: `ExpireBallotsBeforeHeight` (which calls `MarkBallotExpired` → the same O(N) hook, once per stale ballot) is invoked synchronously from `CreateBallot` [1](#0-0) , and `CreateBallot` is reached from every ordinary `VoteOnBallot` call inside the metered `MsgVoteInbound`/`MsgVoteOutbound` transaction path [5](#0-4) . So an unprivileged user who submits many distinct low-value/garbage-but-well-formed source-chain deposit events (each with a unique `tx_hash`, forcing validators to create distinct `utx_key`/variant entries that never reach quorum before expiring) causes:
1. `PendingInbounds` to grow unbounded over time (analogous to `poolColl.tokens[]` never shrinking).
2. Every subsequent terminal transition (expiry or finalization) of *any* inbound ballot to pay for a full walk of that ever-growing collection, inside a normal, gas-metered validator transaction.
3. Since `CreateBallot` proactively sweeps *all* expired active ballots before creating a new one, a single `MsgVoteInbound`/`MsgVoteOutbound` transaction can trigger many terminal-hook walks in sequence (one per expired ballot), each an independent O(N·V) scan — a multiplicative blow-up.

### Impact Explanation
This matches "denial of service...reachable without privileged control" and material state-machine effects in the Push Chain allowed-impact gate: the cost of ordinary inbound-vote transactions grows unboundedly with cumulative (attacker-inflatable) `PendingInbounds` size, which can push honest validators' `VoteInbound`/`VoteOutbound` transactions toward the block gas limit or cause them to run out of gas / be rejected, stalling the crosschain inbound-voting pipeline for legitimate users' deposits. Because the growth is driven purely by attacker-submitted source-chain events (no privileged party needed) and the cost is paid inside consensus-critical, gas-metered code invoked by every validator vote, this is a genuine repository-specific denial-of-service risk on the universal execution / inbound voting path, not a network-level or external-chain issue.

### Likelihood Explanation
Likelihood is moderate: an attacker needs only to generate many cheap, distinct source-chain transactions (dust deposits, or malformed-but-parseable events different validators might decode differently, creating multiple variants per event) that validators must vote on and that fail to reach quorum, letting the collection accumulate before ballots expire. No validator collusion, admin access, or protocol-level privilege is required — only the ability to originate ordinary cross-chain transactions, which is explicitly in-scope as an "ordinary user deposit" trigger.

### Recommendation
- Add a secondary index/key mapping `ballotID -> utxKey` so `afterInboundBallotTerminal` can do an O(1) lookup instead of walking the entire `PendingInbounds` collection.
- Bound `PendingInbounds` size and/or the number of variants per entry, rejecting or rate-limiting further variant creation once a cap is reached.
- Consider decoupling `ExpireBallotsBeforeHeight`'s sweep from the hot `CreateBallot`/vote path (e.g., move it to `EndBlock` with a bounded per-block work budget) so a single user transaction cannot trigger unbounded cumulative hook work.

### Proof of Concept
1. An attacker (unprivileged) originates N distinct, uniquely-hashed but otherwise well-formed deposit transactions on a supported source chain, none large enough to be economically meaningful, timed so validators' votes never reach the 2/3 quorum before ballot expiry (e.g., by controlling timing/format so votes split across variants).
2. Each triggers `RecordInboundVote`, growing `PendingInbounds` by one entry/variant per unique payload [2](#0-1) .
3. As ballots expire, each terminal transition invokes `afterInboundBallotTerminal`'s full-collection `Walk` [6](#0-5)  inside `MarkBallotExpired`, which is itself invoked in bulk from `ExpireBallotsBeforeHeight` [7](#0-6)  — synchronously inside subsequent honest validators' ordinary `CreateBallot`/`VoteInbound` transactions [1](#0-0) .
4. As N grows, the per-vote-transaction gas cost for honest validators grows correspondingly, eventually threatening out-of-gas failures on legitimate `MsgVoteInbound`/`MsgVoteOutbound` transactions and stalling inbound processing — the same class of unbounded-scan gas exhaustion as the cited Yeti Finance `getVC()`/`poolColl.tokens[]` report.

// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}

	// Close iterator explicitly before mutation phase to release the IAVL snapshot
	iter.Close()

	if len(toExpire) > 0 {
		k.Logger().Debug("expiring stale ballots", "count", len(toExpire), "current_height", currentHeight)
	}

	// Phase 2: expire collected ballots (safe — iterator is closed)
	for _, id := range toExpire {
		if err := k.MarkBallotExpired(ctx, id); err != nil {
			return err
		}
	}

	return nil
}

func (h BallotHooks) afterInboundBallotTerminal(
	ctx context.Context,
	ballotID string,
	status uvalidatortypes.BallotStatus,
) error {
	// Ballot IDs are one-way canonical digests (not reversible), so locate
	// the owning audit-trail entry by scanning PendingInbounds for the
	// variant carrying this ballot ID. The pending set is small and
	// transient, and this hook only fires on terminal transitions.
	var (
		utxKey string
		entry  types.PendingInboundEntry
		found  bool
	)
	err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
		for _, v := range e.Variants {
			if v.BallotId == ballotID {
				utxKey, entry, found = key, e, true
				return true, nil
			}
		}
		return false, nil
	})
	if err != nil {
		return err
	}
