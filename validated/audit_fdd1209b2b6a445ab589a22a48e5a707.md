### Title
Missing length validation causes panic on malformed `DestExecData` in CCIP Solana extra-data decoder - (File: core/capabilities/ccip/ccipsolana/extradatacodec.go)

### Summary
The Solana `ExtraDataDecoder.DecodeDestExecDataToMap` function reads a fixed-size `uint32` directly from an attacker/cross-chain-influenced byte slice without first checking that the slice is at least 4 bytes long. This mirrors the reported ERC1410 bug class (reading fixed-offset data from a variable-length buffer without a length check), except here the unchecked read causes an out-of-bounds slice access panic instead of silently returning adjacent memory content.

### Finding Description
`DecodeDestExecDataToMap` unconditionally calls `binary.BigEndian.Uint32(destExecData)`: [1](#0-0) 

`encoding/binary.BigEndian.Uint32` indexes `b[3]` internally, so if `destExecData` is shorter than 4 bytes this panics with an index-out-of-range error. This is inconsistent with the sibling function in the very same file, `DecodeExtraArgsToMap`, which explicitly validates `len(extraArgs) < 4` before proceeding: [2](#0-1) 

It is also inconsistent with the equivalent EVM implementation, which uses ABI decoding (`abiDecodeUint32` → `UnpackValues`), a path that returns a Go `error` rather than panicking on malformed input: [3](#0-2) 

`DestExecData` (`dest_exec_data` on the wire) is per-token-transfer data that originates from the `CCIPMessageSent` event emitted by the source chain's onramp/token pool, and is propagated end-to-end through CCIP execute reports: [4](#0-3) 

It reaches `DecodeDestExecDataToMap` through multiple execute-plugin code paths, e.g. decoding an on-chain execute report: [5](#0-4) 

and while computing gas estimates for a message: [6](#0-5) 

Because the field is set by the source chain's token pool/onramp contract logic rather than validated for a minimum length before being handed to the destination-chain codec, a source chain component (which is not a privileged Chainlink node/operator) can produce a `DestExecData` value under 4 bytes, causing the decode call on the CCIP OCR3 node to panic.

### Impact Explanation
This is a denial-of-service class issue: a panic inside message/report decoding logic used by the CCIP execute plugin (`Encode`/`Decode`, `Hash`, and gas estimation paths) can disrupt CCIP execute processing for the affected chain family (Solana) on any node running that plugin, potentially crashing the goroutine handling report generation/verification repeatedly for a malformed message, until recovered/filtered elsewhere in the stack. This does not constitute the same "memory disclosure" impact as the original Solidity bug (Go slices are bounds-checked so there is no read into unrelated heap memory), but it shares the same root cause — a fixed-size read performed without validating the source buffer's minimum length — and it produces an availability impact on the CCIP OCR3 node pipeline.

### Likelihood Explanation
`DestExecData` is set upstream by the source-chain token pool contract logic when a token transfer message is created; it is not something the destination chain OCR3 node controls or validates before decoding. If any source-chain token pool implementation (current or future) can emit or be tricked into emitting fewer than 4 bytes for this field (e.g., zero-length exec data for tokens that don't need destination gas overrides), the destination-chain decode path panics. The lack of a length guard here — unlike the length guard present two functions above in the same file — indicates this was an oversight rather than an intentional invariant, making it plausible for this state to arise from a misconfigured or non-standard token pool implementation.

### Recommendation
Add an explicit length check in `DecodeDestExecDataToMap` (mirroring `DecodeExtraArgsToMap`) before calling `binary.BigEndian.Uint32`, returning an error such as `"destExecData too short: %d, should be at least 4 bytes"` when `len(destExecData) < 4`.

### Proof of Concept
Calling `ExtraDataDecoder{}.DecodeDestExecDataToMap(cciptypes.Bytes{})` (or any slice with 0–3 bytes) directly panics: [1](#0-0) 

Any CCIP execute report / message whose `TokenAmounts[i].DestExecData` field is shorter than 4 bytes will trigger this panic when passed through `DecodeTokenAmountDestExecData` in the Solana codec, e.g. via `ExecutePluginCodecV1.Encode`/`Decode` or `EstimateProvider.CalculateMessageMaxGasWithError`.

func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
