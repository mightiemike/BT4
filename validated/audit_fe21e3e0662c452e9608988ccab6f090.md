### Title
Floor-rounded fractional gas-per-unit costs zero out calldata/signature and code fees for small transactions - (File: crates/blockifier/src/fee/resources.rs)

### Summary
`ArchivalDataResources::get_calldata_and_signature_gas_cost` and `ArchivalDataResources::get_code_gas_cost` compute the L1/L2 gas cost of transaction calldata, signature, and declared-class code by multiplying a per-unit `ResourceCost` (a `Ratio<u64>`) by the usage count and truncating with `.to_integer()` (floor), instead of rounding up as is done everywhere else in the fee-accounting code (e.g. `calculate_resource_gas_cost` in `fee_utils.rs` uses `.ceil()`).

### Finding Description
The `deprecated_l2_resource_gas_costs` block used for `GasVectorComputationMode::NoL2Gas` defines fractional per-unit costs less than 1: [1](#0-0) 

- `gas_per_data_felt = 128/1000 = 0.128`
- `gas_per_code_byte = 32/1000 = 0.032`

These values are consumed by `get_archival_data_gas_costs`, which selects `deprecated_l2_resource_gas_costs` for `GasVectorComputationMode::NoL2Gas`: [2](#0-1) 

The actual per-transaction cost computation floors instead of ceiling: [3](#0-2) [4](#0-3) 

Because `.to_integer()` truncates toward zero (unlike `.ceil()` used consistently elsewhere, e.g. `calculate_resource_gas_cost`), any transaction whose `extended_calldata_length + signature_length` is small enough that `0.128 * total_data_size < 1` (i.e., up to 7 felts) is charged **zero** gas for calldata/signature. Likewise a declared class with `code_size < 1/0.032 ≈ 31` (bytes as computed, in words/word-equivalent units) is charged **zero** gas for code storage. [5](#0-4) 

This directly mirrors the reported bug class: a fractional per-unit rate combined with integer/floor division causes legitimate resource usage to be billed as zero, silently losing precision/value in the accounting layer.

### Impact Explanation
This is reachable by any transaction sender submitting a legacy (V0–V2) transaction, or a V3 transaction that resolves to `GasVectorComputationMode::NoL2Gas` (L1Gas-only resource bounds), with minimal calldata/signature or a small declared class. Such a transaction consumes actual storage/computation resources on L1 gas accounting but is charged 0 for that specific gas-vector component, which is a systematic undercharge of the L1 gas fee relative to true resource cost. This is a fee/resource-accounting correctness bug: the sequencer collects less than the versioned-constants-mandated fee for real work performed, letting a sender obtain free or underpriced calldata/signature/code storage bandwidth — a protocol-level fee-revenue loss and unfair/incorrect fee bounds validation (since fee checks and node's committed-fee balance verification are all derived from the same, incorrectly floored gas vector). I could not fully confirm within the available context which client-facing transaction versions realistically hit `NoL2Gas` in the currently supported protocol version set (V0–V2 are declared "deprecated"), which affects the practical exploitability window; a Devin session with full repo/test access would need to confirm which live transaction/resource-bounds combinations still route through `NoL2Gas`.

### Likelihood Explanation
High reachability: no privileged role is required — any external account can submit a transaction with small calldata or declare a small contract class to trigger the zero-cost path. The condition (few felts / few bytes) is trivial to construct deterministically.

### Recommendation
Replace `.to_integer()` with `.ceil().to_integer()` (or an equivalent round-up conversion) in `get_calldata_and_signature_gas_cost`, `get_code_gas_cost`, and `get_client_side_proof_gas_cost` in `crates/blockifier/src/fee/resources.rs`, consistent with `calculate_resource_gas_cost` in `crates/blockifier/src/fee/fee_utils.rs`, so that any nonzero resource usage is billed at least 1 unit of gas rather than being floored to zero.

### Proof of Concept
1. Construct a V0/V1/V2 (or `NoL2Gas`-routed V3) invoke transaction whose `calldata` + `signature` together total ≤ 7 felts (`extended_calldata_length + signature_length ≤ 7`).
2. Compute the archival gas cost via `ArchivalDataResources::get_calldata_and_signature_gas_cost`: `gas_per_data_felt (128/1000) * 7 = 0.896` → `.to_integer()` yields `0`.
3. The resulting `GasVector` component for calldata/signature is `GasAmount(0)`, which flows into `get_fee_by_gas_vector` and is charged `Fee(0)` for that resource despite nonzero calldata/signature actually being transmitted and stored. [6](#0-5) [7](#0-6)

    /// Returns the cost for transaction calldata and transaction signature. Each felt costs a
    /// fixed and configurable amount of gas. This cost represents the cost of storing the
    /// calldata and the signature on L2.
    fn get_calldata_and_signature_gas_cost(
        &self,
        versioned_constants: &VersionedConstants,
        mode: &GasVectorComputationMode,
    ) -> GasVector {
        let archival_gas_costs = versioned_constants.get_archival_data_gas_costs(mode);

        // TODO(Avi, 20/2/2024): Calculate the number of bytes instead of the number of felts.
        let total_data_size = u64_from_usize(self.extended_calldata_length + self.signature_length);
        let gas_amount =
            (archival_gas_costs.gas_per_data_felt * total_data_size).to_integer().into();

        match mode {
            GasVectorComputationMode::All => GasVector::from_l2_gas(gas_amount),
            GasVectorComputationMode::NoL2Gas => GasVector::from_l1_gas(gas_amount),
        }
    }

    ) -> GasVector {
        let archival_gas_costs = versioned_constants.get_archival_data_gas_costs(mode);

            GasVectorComputationMode::All => GasVector::from_l2_gas(gas_amount),
            GasVectorComputationMode::NoL2Gas => GasVector::from_l1_gas(gas_amount),

    }
