### Verdict

#No vulnerability found for this question.

**Reasoning:**

The claimed equality is: `recovered_miner_hash160` (from the block's miner signature) `== leader_key.interpret_nakamoto_signing_key()` (hash160 X committed in the `LeaderKeyRegisterOp` memo referenced by the winning block-commit).

Tracing the actual call path in `validate_normal_against_burnchain`, this equality is enforced **unconditionally**, independent of whether the block contains a tenure-change, a tenure-extend, or neither: [1](#0-0) 

`check_miner_signature(miner_pubkey_hash160)` is called first and always, before `check_tenure_tx()`. The `miner_pubkey_hash160` argument is derived directly from the winning leader key's `interpret_nakamoto_signing_key()`: [2](#0-1) 

`check_miner_signature` itself unconditionally recovers the signer's pubkey hash from the block header signature and rejects any mismatch: [3](#0-2) 

`check_tenure_tx` is a separate, additional check that only validates the tenure-change/tenure-extend transaction's embedded `pubkey_hash` field against the recovered signer — it is a no-op (`Ok(())`) when no tenure tx is present: [4](#0-3) 

Because `check_miner_signature` runs independently and unconditionally as part of `validate_normal_against_burnchain` for every normal Nakamoto block (regardless of tenure-change/tenure-extend/no-tenure-tx), the premise of the question — that `check_tenure_tx`'s branching on `get_tenure_tx_payload()` can be exploited to bypass signature-to-key binding for tenure-extend-only blocks — does not hold. The attacker's block signed by unregistered key Y would fail at `check_miner_signature` before `check_tenure_tx` is even reached, for any transaction content (tenure-change, tenure-extend, or plain block). The unit test at lines 2093–2113 confirms both checks are exercised and independently reject a mismatched key/signature.

No divergence, reward mis-payment, or fork condition is reachable via this path.

    pub(crate) fn check_tenure_tx(&self) -> Result<(), ChainstateError> {
        // If this block has a tenure-change, then verify that the miner public key is the same as
        // the leader key.  This is required for all tenure-change causes.
        let Some(tc_payload) = self.get_tenure_tx_payload() else {
            return Ok(());
        };

        // in all cases, the miner public key must match that of the tenure change
        let recovered_miner_hash160 = self.recover_miner_pubkh()?;
        if tc_payload.pubkey_hash != recovered_miner_hash160 {
            warn!(
                "Invalid tenure-change transaction -- bad miner pubkey hash160";
                "consensus_hash" => %self.header.consensus_hash,
                "stacks_block_hash" => %self.header.block_hash(),
                "stacks_block_id" => %self.header.block_id(),
                "pubkey_hash" => %tc_payload.pubkey_hash,
                "recovered_miner_hash160" => %recovered_miner_hash160
            );
            return Err(ChainstateError::InvalidStacksBlock(
                "Invalid tenure change -- bad miner pubkey hash160".into(),
            ));
        }

        // in all cases, the tenure change's consensus hash must match the block's consensus
        // hash
        if tc_payload.tenure_consensus_hash != self.header.consensus_hash {
