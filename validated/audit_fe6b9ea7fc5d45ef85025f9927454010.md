### Title
Unbounded Gzip Decompression of User-Submitted Legacy Contract Program Enables Zip-Bomb DoS - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
The JSON-RPC v0.8 server accepts legacy (Cairo 0) `DECLARE` transactions whose contract program is delivered as a base64-encoded, gzip-compressed string. When converting the user-supplied `DeprecatedContractClass` into the internal Starknet API type, the server calls `decompress_program`, which decompresses the gzip stream with `GzDecoder::read_to_end` into an unbounded `Vec<u8>` with **no size or time limit**, as explicitly flagged by the code's own `TODO(dan): add time and size limits.` comment. [1](#0-0) 

### Finding Description
`user_deprecated_contract_class_to_sn_api` converts a client-submitted `DeprecatedContractClass` (containing the attacker-controlled `compressed_program` field) into the internal Starknet contract class by calling `decompress_program(&value.compressed_program)`: [2](#0-1) 

```rust
pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}
``` [1](#0-0) 

This is analogous to the Gradio CVE-2024-10569 zip-bomb: an unprivileged, unauthenticated client provides a small compressed payload that expands to an arbitrarily large decompressed size, and the server unconditionally buffers the entire decompressed output in memory before any validation occurs.

Notably, the codebase already recognizes this exact class of bug and has fixed it elsewhere:
- `decompress_with_size_limit` / `decode_and_decompress_with_size_limit` in `starknet_api::compression_utils` caps decompression using `.take(max_size + 1)` and errors with `CompressionError::SizeLimitExceeded` if exceeded. [3](#0-2) 
- The deprecated-gateway transaction path (`apollo_http_server`) and the p2p class converter (`apollo_protobuf`) both use this size-limited helper for Sierra/Cairo-0 programs. [4](#0-3) [5](#0-4) 

However, the JSON-RPC v0.8 API's `decompress_program` (used when converting user-broadcasted legacy Declare transactions) was never migrated to this bounded helper, leaving an unbounded decompression path directly reachable from RPC clients.

### Impact Explanation
A single unauthenticated caller of the JSON-RPC `starknet_addDeclareTransaction` (or any code path constructing a `BroadcastedDeclareTransaction::V1`/legacy declare with a crafted `program` field) can submit a small gzip payload (a few KB) that decompresses to gigabytes of data. Since `decompress_program` reads the entire stream into memory with `read_to_end` before any size check, this causes uncontrolled memory allocation and CPU consumption on the sequencer/RPC node, leading to process OOM/crash — a denial of service that can prevent the node from confirming or serving new transactions. This matches the "network unable to confirm new transactions" impact criterion.

### Likelihood Explanation
High likelihood: the vulnerable function is directly reachable by any external, unauthenticated JSON-RPC client submitting a declare transaction; no special privileges, staking, or prior state are required. The attack payload is trivial to construct (standard gzip bomb) and requires no on-chain fees to trigger, since it can be exercised before/without a costly gateway validation pass that limits size (that stricter path exists only in the separate deprecated-gateway HTTP flow, not in this RPC conversion function).

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` in `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs) with the existing bounded utility `starknet_api::compression_utils::decompress_with_size_limit` / `decode_and_decompress_with_size_limit`, enforcing a maximum decompressed size (and ideally a decompression time budget) consistent with the limits already applied in `apollo_http_server::deprecated_gateway_transaction` and `apollo_protobuf::converters::class`. Reject the request with a client error (not `internal_server_error`) if the limit is exceeded.

### Proof of Concept
1. Craft a legacy Cairo 0 program body of enormous size (e.g., a JSON structure many GB when uncompressed), gzip-compress it (achieving ~1000:1+ ratio), and base64-encode it — a "zip bomb" a few KB in size.
2. Submit this as the `program` field of a `BroadcastedDeclareV1Transaction` (`DeprecatedContractClass`) via the node's JSON-RPC v0.8 `starknet_addDeclareTransaction` (or the equivalent internal RPC->gateway conversion invoking `user_deprecated_contract_class_to_sn_api`).
3. Observe that `decompress_program` unconditionally decompresses the full payload into memory via `read_to_end`, exhausting the node's memory/CPU and crashing or hanging the RPC/sequencer process — before any subsequent validation (e.g. class size checks) can reject it. [2](#0-1) [1](#0-0)

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

/// Decodes the provided data with size limits.
// TODO(dan): consider limiting the time it takes to decompress.
pub fn decode_and_decompress_with_size_limit<T: DeserializeOwned>(
    value: &str,
    max_size: usize,
) -> Result<T, CompressionError> {
    let decoded_data = base64::decode(value)?;
    let decompressed_data = decompress_with_size_limit(decoded_data, max_size)?;
    Ok(serde_json::from_reader(decompressed_data.as_slice())?)
}
