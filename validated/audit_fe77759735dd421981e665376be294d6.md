### Title
Sandwichable spot-price AMM quote in `GetSwapQuote`/`CallPRC20DepositAutoSwap` lets attackers drain the protocol's PRC20⇄WPC liquidity pool during gas-abstraction inbound execution - (File: `x/uexecutor/keeper/evm.go`)

### Summary
The `BathPair` finding describes a class of bug where a contract computes a value (price-per-share) from a live, manipulable balance and then immediately allows an attacker to enter/exit around that computed value for profit, because the balance used for pricing is not protected against last-moment manipulation. Push Chain's gas-abstraction auto-swap path has the same underlying flaw: `GetSwapQuote` reads an **instantaneous spot price** from a Uniswap V3 `QuoterV2` (`quoteExactInputSingle`), and that unprotected quote is used, with only a flat 5% slippage buffer, to authorize a real swap of protocol-held PRC20 for PC via `CallPRC20DepositAutoSwap` / `refundUnusedGas`. Because the quote-then-swap sequence happens inside one deterministic keeper call triggered by an ordinary, mempool-visible `MsgVoteInbound`/`MsgVoteOutbound` transaction, an unprivileged actor can sandwich it exactly like the BathPair `rebalancePair()` front-run.

### Finding Description
`GetSwapQuote` fetches `quoteExactInputSingle` from the Uniswap V3 Quoter with `commit=false` [1](#0-0) , and the returned value is turned into `minPCOut` with a fixed 95% multiplier before the module executes the actual swap via `CallPRC20DepositAutoSwap` [2](#0-1) . The same pattern is repeated for `GAS_AND_PAYLOAD` inbounds in `gasAndPayloadDepositAutoSwap` [3](#0-2)  and for outbound gas refunds in `applyGasRefund` [4](#0-3) .

This quote-then-swap sequence is not a separate off-chain oracle read with TWAP protection — it is a single spot-price read of the live AMM pool state, executed synchronously as part of processing an ordinary `MsgVoteInbound`/`MsgVoteOutbound` transaction. Any unprivileged party can:
1. Watch the mempool for the UV's `MsgVoteInbound`/`MsgVoteOutbound` transaction that will trigger quorum and cause the auto-swap/refund to execute.
2. Submit a higher-gas-price transaction that swaps a large amount through the same PRC20⇄WPC pool immediately before it, pushing the spot price so the resulting `quoteExactInputSingle` output (and thus `minPCOut`) is skewed in the attacker's favor.
3. Let the module's swap execute against the manipulated pool at the inflated/deflated price, extracting real WPC/PC or PRC20 value from the pool relative to fair market price.
4. Reverse their manipulating swap in the same or a following transaction to realize the profit — a classic sandwich, structurally identical to front-running `BathPair.rebalancePair()`: both bugs let an attacker act around a value computed from a balance/price that surges or dips in a way visible and triggerable from the public mempool, with only after-the-fact correction (rebalancing in BathToken, a flat 5% band here).

The 5% slippage tolerance is a fixed band around whatever spot price is observed at execution time; it protects against reverts on ordinary pool drift but not against an attacker who actively manipulates price within that same transaction window, since the "reference" price itself (the quote) is the manipulated value, not an independent anchor.

### Impact Explanation
Each `GAS`/`GAS_AND_PAYLOAD` inbound deposit-auto-swap and each outbound gas-fee refund-with-swap moves real protocol-facing value (PRC20 gas tokens ⇄ PC/WPC) through this unprotected pricing path. Repeated sandwiching across many gas top-ups drains value from the WPC/PRC20 liquidity pool used by `UniversalCore`, corrupting the amount of PC actually credited to users' UEAs or refunded to senders relative to fair value — directly affecting user/protocol-controlled fund accounting, matching the "corruption of PRC20 or native asset accounting" and "stealing/draining ... protocol-controlled funds" impact categories.

### Likelihood Explanation
Any external, unprivileged actor with a wallet and access to the Push Chain mempool can execute this attack whenever a gas-abstraction inbound or an outbound gas refund is about to be finalized — no validator, TSS, or admin privilege is required, and the triggering `MsgVoteInbound`/`MsgVoteOutbound` transactions from honest Universal Validators are, by design, ordinary observable transactions. The likelihood scales with the size and thinness of the PRC20⇄WPC pool and the frequency of gas-abstraction inbounds, which are a routine, user-triggered flow (every gas top-up).

### Recommendation
Do not derive `minPCOut` solely from an instantaneous `quoteExactInputSingle` spot read taken in the same execution window as the swap. Use a time-weighted average price (TWAP) over a meaningful window, or an independent oracle-fed reference price (similar to `ChainMeta`/gas-price oracles already present in the module) to bound acceptable slippage, and/or tighten the slippage band and add a maximum absolute deviation check between the pre-computed quote and pool state immediately before commit. Consider also capping the swap notional per block/per pool to limit the extractable value from any single sandwich.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (or the final vote that will reach 2/3 UV quorum for a `GAS`/`GAS_AND_PAYLOAD` inbound) in the mempool.
2. Attacker submits, with higher priority, a swap transaction against the PRC20/WPC Uniswap V3 pool that shifts the spot price used by `quoteExactInputSingle`.
3. The UV's vote transaction lands next in the same block, triggering `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which calls `GetSwapQuote` (reading the now-manipulated spot price) then `CallPRC20DepositAutoSwap` with `minPCOut = quote * 95%` [5](#0-4) , executing the swap against the skewed pool.
4. Attacker submits a follow-up transaction reversing their initial swap, capturing the price difference extracted from the pool at the protocol's expense. [1](#0-0) [6](#0-5) [4](#0-3)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
