### Title
Outbound gas fee, refund-swap, and inbound gas-abstraction swap calculations consume `gasPriceByChainNamespace` / swap-quote data from `UniversalCore` without ever checking the on-chain freshness timestamp - (File: `x/uexecutor/keeper/gas_fee.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The `UniversalCore` contract exposes `timestampObservedAtByChainNamespace(chainNamespace)` [1](#0-0)  specifically to record when a chain's gas price / chain-height oracle entry was last updated by `setChainMeta`. However, across the entire Go keeper, this getter is never called — a repo-wide search shows it only appears in the ABI definition file, with zero call sites in `x/uexecutor/keeper/*.go`. Every financial computation that reads `gasPriceByChainNamespace`, `getOutboundTxGasAndFees`, or Uniswap swap quotes (`GetSwapQuote`) uses whatever value is currently stored on-chain, with no check on how old that value is.

### Finding Description
`VoteChainMeta` applies a staleness window (`chainMetaVoteStalenessSeconds`) when *aggregating validator votes* before writing to the EVM oracle [2](#0-1) , and refuses to advance the on-chain price if there are zero fresh votes [3](#0-2) . That protects the *write* path: bad validators can't push forged data. But it does nothing to protect the *read/consumption* path — if all Universal Validators for a given external chain stop voting (oracle client crash, RPC outage, chain-specific bug), `entry.LastAppliedChainHeight` and the on-chain `gasPriceByChainNamespace`/`chainHeightByChainNamespace` simply freeze at their last-written value indefinitely. The contract itself tracks exactly when that value was last written, via `timestampObservedAtByChainNamespace` [1](#0-0) , but no Go code path ever reads it before using the associated price.

Concrete consumers of the (potentially stale) gas price:
- `GetOutboundTxGasAndFees` reads `gasToken`, `gasFee`, `gasPrice`, `gasLimit` from `UniversalCore.getOutboundTxGasAndFees` for computing outbound fees, with no freshness gate [4](#0-3) .
- `applyGasRefund` computes `refundAmount = gasFee - gasFeeUsed` and immediately calls `GetSwapQuote`/`CallUniversalCoreRefundUnusedGas` to swap the excess gas token back to native PC and refund the user, using only a fixed 5% slippage bound on top of the (possibly stale-price-derived) quote — no timestamp check anywhere in this flow [5](#0-4) .
- `ExecuteInboundGas`'s auto-swap path (GAS / GAS_AND_PAYLOAD inbound routes) fetches a swap quote and computes `minPCOut = quote * 95/100` before minting/swapping PRC20 for the user, again with no gate on oracle freshness [6](#0-5) .

This is the direct Push Chain analog of the reported bug class: an oracle-fed value (external-chain gas price) is used to compute swap outputs / fee amounts for users, the protocol deliberately chooses not to halt/pool-stop on staleness (mirroring the client's stated rationale in the report), but unlike the report's recommendation, there is no reasonable-timeframe rejection check even though the infrastructure to do one (`timestampObservedAtByChainNamespace`) already exists on-chain and is simply unused.

### Impact Explanation
If the off-chain gas-price oracle for a given external chain stops updating (any of the many chain-specific reasons: RPC failure, chain congestion, universalClient crash, chain reorg confusion) while the source chain's real gas price moves significantly, Push Chain will keep computing outbound gas fees, refund amounts, and inbound auto-swap `minPCOut` values against the frozen price. This can cause: outbound relayer/gas fee undercharging or overcharging (fee accounting corruption), incorrect refund amounts sent back to users during `applyGasRefund` (potential fund loss to the protocol or user shortchanging depending on price direction), and incorrect `minPCOut` slippage bounds on the auto-swap gas-abstraction inbound path, which could let a user (or an exploiting bot depositing when it's advantageous) receive a swap execution priced against stale reference data. This falls within the "corruption of gas fee accounting, refund accounting" and "unauthorized state transitions in universal execution flows" allowed-impact categories, reachable purely from ordinary user inbound/outbound activity without any privileged actor.

### Likelihood Explanation
Triggering requires only that the off-chain gas-price oracle for one external chain goes stale for a sustained period while the associated pool of pending inbounds/outbounds keeps flowing — this is an operational/infrastructure condition rather than an attacker action per se, but it is entirely unprivileged and reachable by ordinary users continuing to submit deposits/outbounds during the outage window; no validator or admin collusion is needed to trigger the miscalculation once the condition exists. Given the acknowledged precedent in the seed report (the vendor explicitly chose not to halt on stale oracle data), and the fact that a purpose-built timestamp getter exists but is unused, this is a real, currently-unmitigated gap rather than a defended invariant.

### Recommendation
Add a staleness check using the already-exposed `timestampObservedAtByChainNamespace` value before consuming `gasPriceByChainNamespace` / `getOutboundTxGasAndFees` outputs in `GetOutboundTxGasAndFees`, `applyGasRefund`, and `ExecuteInboundGas`'s auto-swap step. If the last-observed timestamp exceeds a configurable maximum age, either reject/hold the operation for manual/governance resolution (similar to how `AbortOutbound` is already used elsewhere in this file) or fall back to a safe default fee/quote path, rather than silently computing swap outputs and refund amounts against arbitrarily old data.

### Proof of Concept
Not directly exploitable via a single reproducible transaction — this is a state-staleness condition. Conceptual repro: (1) stop or fail the off-chain `ChainMetaOracle` voting for chain X so `VoteChainMeta` stops receiving fresh votes and `LastAppliedChainHeight`/on-chain price freeze [3](#0-2) ; (2) let real-world gas price for chain X diverge significantly from the frozen value; (3) submit an ordinary inbound (GAS/GAS_AND_PAYLOAD) or trigger an outbound refund during this window; (4) observe that `GetOutboundTxGasAndFees`/`GetSwapQuote`/`applyGasRefund` compute fee/refund/swap amounts from the stale frozen price with no rejection, since `timestampObservedAtByChainNamespace` is never queried anywhere in the call chain (confirmed by repo-wide grep showing zero non-ABI references).

	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
