### Title
Unbounded Growth of Shop-Session-ID Index in `KVSessionStorage` Enables Cheap Merchant-Triggered DoS/Corruption of Session Lookups - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

### Summary
`KVSessionStorage` maintains a per-shop index (`shop:<domain>` key) listing every session id ever stored for that shop. `addShopIds` unconditionally appends new ids to this array with no deduplication, size cap, or expiry pruning. For non-embedded apps, every online OAuth login generates a brand-new `crypto.randomUUID()` session id, so a single authenticated merchant can cheaply and repeatedly trigger the OAuth flow to make this array (and the underlying KV value) grow without bound, eventually causing failures in `findSessionsByShop` and any code that depends on it (including the `APP_UNINSTALLED` webhook cleanup path), mirroring the "cheap spam on one side, expensive/broken execution on the other" pattern described in the report.

### Finding Description
`storeSession` calls `addShopIds`, which reads the current id list for the shop and blindly appends the new session id without checking for duplicates or limiting length: [1](#0-0) 

For online, non-embedded sessions, the session id is a fresh `crypto.randomUUID()` on every OAuth completion (as opposed to a deterministic per-user JWT session id used for embedded apps): [2](#0-1) 

Because the auth callback path calls `sessionStorage.storeSession(session)` on every completed OAuth callback (a normal, unprivileged action any authenticated merchant/user can trigger repeatedly), each such login appends a brand-new, unique id to the shop's index with no cap: [3](#0-2) 

`findSessionsByShop` then reads this entire id list and issues a `Promise.all` of `loadSession` calls for every id ever recorded, including ids for sessions that have long since expired or been deleted (since `addShopIds` never prunes and old/expired sessions are simply not removed from the index unless `deleteSession`/`removeShopIds` is explicitly invoked): [4](#0-3) 

`findSessionsByShop` is a required dependency of `AppInstallations`, which is invoked from the `APP_UNINSTALLED` webhook handler pipeline (an app-uninstall action any merchant can perform for free) to check/clean up sessions for a shop: [5](#0-4) [6](#0-5) 

### Impact Explanation
A single merchant can, at negligible cost (repeatedly completing the online OAuth flow, which requires no special privileges beyond installing/using the app), grow the per-shop index key without bound:
- The KV value backing the shop index can approach/exceed platform value-size limits (e.g., Cloudflare Workers KV values are capped at 25 MiB), eventually causing `storeSession`/`findSessionsByShop` to fail outright for that shop — a denial of service for future logins, session lookups, and the uninstall-cleanup path.
- `loadSession(id)` for ids of sessions that have already expired/been overwritten can return `undefined`; `findSessionsByShop`'s `Promise.all(sessionIds.map(async (id) => (await this.loadSession(id))!))` uses a non-null assertion that does not guard against this, propagating `undefined` entries into the returned `Session[]`. Downstream consumers such as `AppInstallations.includes()` (`session.accessToken`) and `.delete()` will then throw on the phantom `undefined` entries, breaking the uninstall-webhook session cleanup flow for legitimate shops.
- Every login also multiplies the number of KV read operations `findSessionsByShop` performs (one GET per historical id), driving up latency/cost for legitimate operations that share this code path, analogous to the "lose-lose" execution burden described in the report.

### Likelihood Explanation
This requires no special access — any user able to complete the standard, unprivileged OAuth "online" login flow against a non-embedded app (a normal, cheap, and repeatable customer/merchant action) can trigger unbounded appends. No admin privileges, leaked secrets, or MITM conditions are needed; the flaw is purely in the storage adapter's missing deduplication/eviction logic.

### Recommendation
- In `KVSessionStorage.addShopIds`, deduplicate ids before writing back (e.g., use a `Set`) and consider a bounded/rotating index (cap size, evict expired/oldest entries) instead of unconditional appends.
- Prune ids in the shop index whose backing session is expired or missing (verified during `findSessionsByShop`), rather than allowing `loadSession` to return `undefined` into the result array.
- Reconsider using `crypto.randomUUID()` for online-session ids in non-embedded mode, or bound how many concurrent online sessions per shop/user are retained (evicting the oldest instead of growing indefinitely).

### Proof of Concept
1. Deploy an app using `KVSessionStorage` in non-embedded mode.
2. As a merchant/customer, repeatedly complete the online OAuth flow (`/auth?shop=...` → `/auth/callback`) N times — each completion is a normal, cheap, unprivileged action.
3. Observe that the `shop:<domain>` KV entry grows by one unique UUID per login with no dedup, without bound, via `addShopIds`.
4. After sufficiently many iterations, call `findSessionsByShop(shop)` (e.g., indirectly via uninstalling the app, which invokes `AppInstallations.delete`) and observe growing latency/cost, and eventually failures once the KV value size limit is hit or once expired-session ids resolve to `undefined` and break `AppInstallations` logic.

    const sessionIds = await this.namespace.get<string[]>(
      this.getShopSessionIdsKey(shop),
      {type: 'json'},
    );

    if (!sessionIds) {
      return [];
    }

    return Promise.all(
      sessionIds.map(async (id) => (await this.loadSession(id))!),
    );
  }

  private async addShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
  }

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
      );
    }
  }
