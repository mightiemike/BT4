CVE-2016-10211 is a use-after-free in YARA's C-based bison grammar parser (`yr_parser_lookup_loop_variable` in `libyara/grammar.y`), where a loop variable pointer is dangling after being freed but still referenced due to broken scope tracking. This bug class fundamentally depends on manual memory management in C, which does not translate to Go's garbage-collected memory model — protobuf-go has no equivalent manual pointer lifetime management for parser scope/loop variables.

Searching protobuf-go's parser implementations confirms this: the text-format decoder's scope/nesting tracking uses a plain byte slice `openStack []byte` (pushed/popped via `pushOpenStack`/`popOpenStack`) [1](#0-0)  and its push/pop operations are simple slice append/truncate operations with no freed-pointer retention [2](#0-1) . Similarly, the JSON decoder's `openStack []Kind` follows the identical index-based pattern [3](#0-2) . There is no scope-variable lookup mechanism resembling YARA's loop-variable table that stores raw pointers to freed AST/scope nodes, and Go's garbage collector prevents a slice element or struct from being freed while still reachable/referenced, eliminating the underlying UAF primitive. No reachable, unprivileged request path in protobuf-go exhibits the "stale reference to a freed scope entry" pattern required to be a valid analog of this CVE.
