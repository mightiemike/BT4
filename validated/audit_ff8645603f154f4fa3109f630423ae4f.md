Found it. The `accrue` function explicitly implements a "pass through instead of reverting" pattern when paused, exactly matching one of the allowed analog mechanisms. [1](#0-0) 

### Title
`accrue()` pause pass-through freezes index updates while dependent `borrow`/`repay`/`redeem` still execute against stale state - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
`accrue` is documented as "PAUSED: Pass-through without reverting" — when `accrue` is paused it returns `(ok {index: idx, lindex: lidx})` using the *current* stored `index`/`lindex` instead of the values that would result from `next-index`/`next-liquidity-index`, and critically does **not** revert the caller.

### Finding Description
`accrue` reads `pause-states` and, if `accrue` is paused, short-circuits to `(ok { index: idx, lindex: lidx })` [2](#0-1)  — silently skipping the interest/liquidity index update instead of reverting the transaction. Every fund-moving entrypoint (`deposit`, `redeem`, `system-borrow`, `system-repay`) calls `(try! (accrue))` unconditionally as one of its first `let` bindings, and only *afterwards* independently checks its own `pause-states` field (`deposit`, `redeem`, `borrow`, `repay`) via `asserts!` [3](#0-2) [4](#0-3) [5](#0-4) .

Because `accrue` never reverts when paused, an operator pausing only `accrue` (e.g. to freeze interest computation while investigating an oracle/index bug) does not stop `borrow`, `repay`, `redeem`, or `deposit` — those functions have their *own*, independently-controlled pause flags (`borrow`, `repay`, `redeem`, `deposit`) in the same `pause-states` tuple [6](#0-5) . If `index`/`lindex` are frozen (accrue paused) while `borrow`/`repay` remain active, all subsequent debt math (`total-debt`, `mul-div-down scaled-principal idx INDEX-PRECISION`) in `system-borrow`/`system-repay` operates against a stale `idx` that no longer reflects real accrued interest, letting borrowers repay using an index that undercounts owed interest, or letting the vault under/over-value debt relative to actual assets, for as long as `accrue` remains paused while borrow/repay stay open. This is a pass-through-instead-of-reverting design that leaves fund-moving paths reachable using a stale cached value that only the caller controls the invalidation of.

### Impact Explanation
Temporary freezing/mispricing of interest accrual while debt-changing operations (`system-borrow`, `system-repay`) continue unimpeded means a security responder pausing `accrue` alone gets a false sense of safety: the assumption that pausing `accrue` halts financial state changes is false, since `index`/`lindex` staleness directly corrupts debt/interest accounting used by `system-repay`'s `calc-principal-ratio-reduction` and `total-debt`, potentially causing temporary freezing of unclaimed yield/interest owed to depositors (interest that should have accrued is not reflected, and repayments computed off the stale index misallocate principal vs. interest).

### Likelihood Explanation
Requires the DAO/operator to pause only `accrue` (a normal, sanctioned incident-response action per the pause_states design) while leaving `borrow`/`repay` open — a plausible operational scenario given the pause flags are independent booleans rather than a single kill switch, and the code comment itself acknowledges the pass-through as intentional behavior, meaning it will reliably occur any time `accrue` is toggled off without also toggling `borrow`/`repay`.

### Recommendation
Make `accrue`'s paused branch either (a) revert with `ERR-PAUSED` instead of passing through, so callers relying on `try! (accrue)` are also halted, or (b) make `borrow`/`repay`/`redeem`/`deposit` explicitly check `(get accrue states)` in addition to their own flag before proceeding, so debt/interest math is never computed against a period where accrual was known to be stale.

### Proof of Concept
1. DAO calls `set-pause-states` with `{accrue: true, borrow: false, repay: false, ...}` [7](#0-6)  intending to freeze interest logic during an incident.
2. A user calls `system-borrow`; it calls `(try! (accrue))`, which detects `accrue` paused and returns `(ok {index: idx, lindex: lidx})` without updating `index`/`lindex`/`last-update` [8](#0-7) .
3. `system-borrow` proceeds normally (its own `borrow` flag is false) and mints scaled principal against the stale `idx` [9](#0-8) .
4. Later, `system-repay` computes `debt`/`principal-reduction` off the same never-updated `idx`, misallocating principal vs. interest for the entire time `accrue` remains paused [10](#0-9) .

Note: this same pattern is duplicated identically across `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-stx.clar`, and `v0-vault-usdh.clar` .

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
      
      (print {
        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
      
      (ok true))))

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
